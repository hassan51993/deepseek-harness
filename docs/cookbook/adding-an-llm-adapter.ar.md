# دليل عملي: إضافة مهايئ LLM

[English](adding-an-llm-adapter.md) | العربية

كيف توصل مزوّد نماذج جديدًا. والتنفيذان المرجعيان: `packages/llm/llm-deepseek` (HTTP مباشر، وSSE يؤطّره `eventsource-parser`) و`packages/llm/llm-pi-ai` (يلفّ مكتبة LLM). اقرأ أولًا توثيقَ `StreamChunk` في `packages/llm/llm/src/types.ts`، فهو يسجّل أعراف البروتوكول التي تُحقِّق منها المهايئان.

## الصيغة

```ts ignore-check
class MyAdapter extends LlmAdapter {
  async * stream(options: GenerateOptions): AsyncIterable<StreamChunk> { … }
}

export const name = 'llm-myprovider'
export const inject = ['llm']
export const Config: z<Config> = z.object({ apiKey: z.string(), … })

export function apply(ctx: Context, config: Config) {
  ctx.llm.registerAdapter(['my-provider'], new MyAdapter(…))
}
```

والتسجيل قائم على الآثار (فهو آمن مع HMR)؛ ومهايئ واحد لكل مسار مزوّد، فالتكرار يرمي استثناءً، والتسجيل على عدة مسارات إما أن يتم كله أو لا يتم. ويختار `options.provider` المهايئَ، و`options.model` هو معرّف النموذج عند المزوّد، فيستطيع مهايئٌ بدليل ديناميكي أن يخدم نماذج جديدة بلا إعادة ضبط لدورة الحياة. والأسرار أصيلة في cordis: إعداد schemastery مع رجوع إلى البيئة، يُغذّى من cordis.yml عبر `!!js process.env.MY_KEY`. ولا تقرأ ملفات مفاتيح مرتجَلة في الشفرة أبدًا.

## التزامات البروتوكول (العقد الذي تحقّق منه تنفيذان)

- أرسل `usage` **قبل** `finish`؛ ولا ترسل شيئًا بعد `finish`. والطريقة المتينة: خزّن finish وusage مؤقتًا حتى علامة نهاية التدفق عند المزوّد، ثم أفرغهما (فهذا يستوعب المزوّدين الذين يرسلون قطعَ usage وحدها في الذيل).
- وسائط `arguments` في استدعاء الأداة سلاسلُ JSON خام من طرف إلى طرف؛ فبُثّ الشظايا بوصفها `argumentsDelta`. وإن أعاد إليك مزوّدك كائنات محلَّلة، فأعِد تحويلها إلى سلسلة عند `block-end`.
- خصّص فهارس `index` للكتل بترتيب أول ظهور في التدفق؛ وأعِد استعمال الفهرس في كل delta للكتلة نفسها.
- للأخطاء مساران مأذونان لا ثالث لهما: أن ترمي من `stream()` (أعطال النقل والبروتوكول، واستعمل `LlmError` برمز ثابت)، أو أن تُنهي التدفق بـ `finish {kind: 'error' | 'aborted'}` (أعطال المزوّد داخل النطاق). والمستهلكون يعالجون الاثنين؛ فاختر بحسب صنف العطل ووثّق اختيارك.
- احترم `options.signal` (مرّره إلى fetch أو إلى SDK الخاص بك).
- وحقلُ `GenerateOptions` الذي لا يستطيع مزوّدك احترامه (مثل قائمة `stop` عند مزوّد بلا تسلسلات إيقاف): ارمِ `LlmError(..., 'UNSUPPORTED_OPTION')` بدل إسقاطه في صمت.
- وإن اشترط المزوّد معرّفاتِ استجابة أو تواقيعَ أو بياناتٍ أصيلة أخرى في الاستدعاءات اللاحقة، فأرسل أصغرَ إسقاط JSON بلا فقد في `finish.replayState`. وتحقّق منه عند إعادة بناء التاريخ. ولا يمرّره `LlmRuntime` إلا حين يكون مسار المزوّد التاريخي ومسار المزوّد الهدف مملوكين حاليًا لنسخة المهايئ نفسها بعينها؛ ومهايئك هو الذي يقرّر هل تجوز الاستعادة داخل النموذج نفسه أو عبر النماذج أو عبر المزوّدين. ولا تستنتج إعادةَ التشغيل الأصيلة من أسماء المزوّد والنموذج وحدها حين تغيب الحالة.

وتبقى مفاتيح وضع التفكير الخاصة بالمزوّد في `Config` الخاص بالمهايئ. أما بيانات النموذج الوصفية بعينها فتستعمل seam قدرة واحدة محايدة تجاه المزوّدين: نفّذ `resolveModel()` بهوية المزوّد والنموذج وبالحقلين الاختياريين `context` و`reasoning`، ولا تعلن `defaultEffort` مضبوطًا إلا حين يوجد، واحترم `AbortSignal` الاختياري للمحلِّل. ودرجاتُ الاستدلال معرّفات معتمة مرتَّبة يربطها المهايئ بطلبات المزوّد. واحفظ قائمةَ المهايئ المرجعية القابلة للاختيار، بما فيها `off` الذي يعرّفه المهايئ متى دُعم، دون كشف هجاء السلك النهائي ودون قصّ القيم غير المدعومة؛ ولا يلزم أن يساوي المعرّف تمثيلَه على السلك.

## بنية التنفيذ

أبقِ أنواعَ السلك، وتسلسلَ الطلب، وتحليلَ النقل، وترجمةَ القطع، وصنفَ المهايئ مسؤولياتٍ منفصلة؛ و[`llm-deepseek`](../../packages/llm/llm-deepseek/README.ar.md) هو التخطيط المرجعي.

## التحقق

اتبع [سياسة الاختبار في المستودع](../testing.ar.md)، فهي تملك تغطيةَ المهايئات، وفحوصَ المزوّد الحقيقي، ومتطلباتِ المداخل المنشورة.
