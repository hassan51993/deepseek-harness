# فعلي تشغيل يد سجل: مراجعة قراءة حفظ دائم نوع تغيير

[English](reviewing-persistence-type-changes.md) | العربية

## عام وصف

في قد تثبيت اعتماد مساهمة من فحص خروج دليل في تعديل جلسة حفظ دائم نوع إعلان بعد، استخدام هذا تعليم مسار. توفير مزدوج لغة توافق صفة شرح، مجددا استخدام واحد بند أمر تصنيف تغيير و توليد سجل.[سجل مشاركة اعتبار](../persistence-changes/README.ar.md) حل تفسير ملف و تلقائي قاعدة. كل مقارنة مقارنة إدخال كل في فحص خروج دليل في؛ لا حاجة أساس خط فرع أو شبكة شبكة وصول.

## اختياري: فحص تغيير

إذا يحتاج في سجل قبل معاينة، في مستودع أصل دليل تشغيل:

```sh
pnpm --silent run verify-persistence-changes --json
```

إزالة استهلاك JSON وقت استخدام `--silent`: لا فإن pnpm سوف يأخذ دورة الحياة فشل نص إلحاق إلى معيار إخراج. فشل أمر ما زال بـ خروج رمز 1 انتهاء.

قراءة قراءة تقرير إبلاغ في أصل، مسار، تغيير نوع صنف و إصدار اشتراط. يتم مرجع نوع ممكن أثر كثير عدد حدث ملخص؛ فحص كل تلقي أثر أصل. في تاريخ تغطية جديد schema قبل، تحقق سوف فشل. قديم قديم توليد بيان أيضا سوف توجيه يؤدي تحقق فشل؛ سجل أمر سوف تحديث جديد هو. إذا إعادة ترتيب حقل أو ربط دمج نوع فرع بعد `changes` لـ فارغ، تشغيل `pnpm run gen-persistence-catalog` و إعادة فحص. أي جعل نسخ إعلان أو شفرة المصدر موضع إنتاج دليل diff، لم تغيير ملخص أيضا بلا حاجة إضافة جديدة تأكيد سجل.

<a id="acknowledge"></a>
## 1. سجل تغيير

تحرير كتابة يتضمن `en` و `ar` محلي JSON ملف، اثنان من قسم آخر يتضمن `summary`،`compatibility` و `verification` نص. التالي إدخال وصف واحد مرور مرور تحقق خطاف مراجعة حساب حقل من لا بد اختيار تعديل لـ اختياري تغيير. استخدام أنت الذي فعل تغيير واقع استبدال شرح و اختبار دليل؛CLI(أمر سطر واجهة) لن إثبات هذه إعلان.

سوف إدخال حفظ لـ `.artifacts/persistence-change.prose.json`، لا بد يلزم وقت إنشاء هذا يتم تجاهل اختصار دليل:

```json
{
  "en": {
    "summary": "Makes the persisted hook audit decision optional.",
    "compatibility": "Existing records remain valid. Hook execution consumes HookOutput instead of replaying this audit field. Producers still write decisions, and absence does not imply pass.",
    "verification": "pnpm exec vitest run packages/hooks/hook-protocol/tests/events.spec.ts: 10 tests passed."
  },
  "ar": {
    "summary": "سوف حفظ دائم خطاف مراجعة حساب قرار تعديل لـ اختياري.",
    "compatibility": "قد لديه سجل ما زال صالح. خطاف تنفيذ إزالة استهلاك HookOutput، لا إعادة تشغيل هذا مراجعة حساب حقل. كتابة جهة ما زال سجل قرار، ناقص لا بديل جدول pass.",
    "verification": "pnpm exec vitest run packages/hooks/hook-protocol/tests/events.spec.ts:10 عدد اختبار عبر."
  }
}
```

استخدام يوم مدة و وصف صفة قصير اسم استبدال عرض مثال id:

```sh
pnpm --silent run persistence-changes --record 2026-09-11-poc-optional --prose .artifacts/persistence-change.prose.json --json
```

أمر في كتابة قبل تحقق تاريخ و مزدوج لغة شرح، دفع قطع الأكثر منخفض إصدار قرار، و فحص الذي يحتاج رأس جزء إصدار تمرير زيادة. هو توليد سجل مقابل، كامل تغيير بعد schema، اثنان نسخة دليل، آلة جهاز بيان و إعداد مقابل سجل. إيداع قبل مراجعة قراءة شرح و إرجاع `changes`،`roots` و `files`. حذف `--prose` سوف إنشاء لم إتمام مسودة مسودة، تحقق سوف رفض هو جمع، مباشر إلى شرح تكملة متساو.

دفع قطع التزام دوران[ثابت توافق صفة قاعدة](../persistence-changes/README.ar.md#compatibility-rules) ، لن أكثر تعديل شفرة المصدر أو وضع عرض قاعدة. حاجة رفع إصدار وقت، أولا التزام دوران[إضافة جلسة صيغة إصدار](adding-a-session-format-version.ar.md). سجل يجب يتضمن ذلك ذاته `SessionHeader.version` تمرير زيادة تحويل؛ غير متصل تاريخ رفع إصدار لا يستطيع تخويل هو. يوم معتاد تغيير لا إنشاء آخر بند أساس خط.

<a id="verify"></a>
## 2. فحص، إيداع و دفع إرسال

أصل حسب[اختبار سياسة سياسة](../testing.ar.md) اختيار تغيير الذي تابع وحدة سلوك فحص، مجددا تشغيل وثيقة فحص:

```sh
pnpm run doc-sync
```

`doc-sync` فحص حفظ دائم بيان و دليل جديد طازج درجة، كامل تاريخ و مزدوج لغة إعداد مقابل. سجل أمر `ok: true` لا يستطيع بديل هذه فحص، أيضا لا يستطيع بديل الذي تابع وحدة سلوك و ترحيل اختبار.JSON فشل استجابة إبقاء `ok: false`، تشخيص `code` و خروج رمز 1. بنية تحويل تغيير يتضمن مستقر نوع صنف و تدريجي أصل تغيير قبل بعد ملخص، تلقائي تحويل بلا حاجة تحليل وصف نص.

سجل توليد مسؤول ذلك دليل و سجل مزدوج لغة مقابل؛ حزمة README أو أخرى مزدوج لغة صفحة تحرير ما زال التزام دوران معتاد قاعدة إعداد مقابل مسار. مراجعة قراءة و مؤقت تخزين مسبق مدة فرق مختلف، لكن بعد صحيح معتاد إيداع و دفع إرسال. مؤقت تخزين lint، إعداد مقابل، فارغ أبيض hooks، و pre-push Host/Client نوع فحص ما زال يجب تنفيذ.

<a id="competing-records"></a>
## تحديث بعد لم قبول سجل

سجل بعد شفرة المصدر مجددا مرة تغير وقت، مراجعة قراءة توافق صفة شرح، و تحديث جديد نفس بند بعد لم قبول نهاية طرف سجل:

```sh
pnpm --silent run persistence-changes --update 2026-09-11-poc-optional --prose .artifacts/persistence-change.prose.json --json
```

أمر تحديث جديد آلة جهاز إعلان،schema، دليل و إعداد مقابل. لا يوجد `--prose` وقت، هو إبقاء قد لديه شرح. تحديث سوف رفض ابتدائي أساس خط و يتم أخرى سجل اعتماد سجل. دليل ذاته لا يمكن تعرف آخر أي بعض سجل قد نيل مراجعة قراءة قبول: إبقاء قد قبول تاريخ، و إنشاء بعد استمرار.

تجميع صار إنتاج تنافس تنازع نهاية طرف سجل وقت، أصل حسب باق بقية تاريخ تحديث بعد لم قبول سجل، مجددا إعادة تقييم تقدير نهائي فرق مختلف. غير متصل أصل تأكيد بلا حاجة تحديث جديد.[آلية قرار](../../.agents/notes/implemented/process/2026-09-11-persistence-type-history.ar.md) حل تفسير لـ أي إبقاء كامل لقطة و تدريجي أصل قبل دفع.

صريح `--decision` ما زال هو تلقي فحص تأكيد. إذا قد لديه خاصية قيمة نوع حدوث تغير، تحت وجه هذا عدد لذا معنى خطأ تأكيد سوف في كتابة قبل فشل:

```sh
pnpm --silent run persistence-changes --update 2026-09-11-poc-optional --decision same-version --json
```
