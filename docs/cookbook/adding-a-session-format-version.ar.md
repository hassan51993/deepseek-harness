## عام وصف

هذا تعليم مسار وسيط تعريف مثل أي إضافة تحت واحد بنية صفة Session سجل إصدار، معا لا تعديل كتابة قد إصدار بيانات. قراءة قراءة[إصدار و إصدار حالة حق مصدر](../session-format-status.ar.md) ، تحديد مساحة العمل كتابة جهاز و الأكثر جديد قد إصدار صيغة. أمر N يمثل مرور نواة فعلي قد إصدار صيغة،N+1 يمثل هدف إصدار؛ اسم و بيانات وصفية في هذه احتلال موضع رمز يجب استبدال لـ عدد حرف. بدء قبل، طلب دقيق تجهيز متاح مساهمة من مساحة العمل، و قراءة قراءة[حزمة فحص بيان](adding-a-package.ar.md) ،[صيغة مكتبة](../../packages/session/session-format/README.ar.md) و[قد إصدار صيغة قرار](../../.agents/notes/implemented/architecture/2026-08-31-released-session-format-migrations.ar.md).

## 1. اختيار إصدار و إصدار أساس خط

عند header، حدث معلومة غلاف، نواة قلب حدث دلالة أو جدول وجه إعادة بناء حدوث بنية صفة تغيير وقت، رفع رفع صيغة إصدار. عادي حدث إضافة جديدة لا حاجة رفع رفع إصدار؛ التزام دوران[إصدار قاعدة](../../.agents/notes/implemented/architecture/2026-08-10-session-log-version-mechanism.ar.md). منطقة قسم Session صيغة كامل عدد و حزمة إصدار إصدار،SQLite schema إصدار، إسقاط وحدة إصدار و بروتوكول حزمة تركيب طبقة إصدار.

لـ N+1 استخدام مشترك `release/*` تجميع صار أساس خط. أساس خط تغيير إضافة كتابة جهاز،codec،catalog وصل خط، ثابت انتظار ترحيل و تحقق. من هذا أساس خط إنشاء كل عدد مستقل فرعي فرع، و سوف ذلك PR(Pull Request) هدف ضبط لـ إصدار فرع، بينما غير آخر عدد مستقل فرعي فرع. كل فرعي فرع في نفس عدد متبادل مجاور ترحيل حزمة داخل إضافة ذاته بنية تغيير تبديل، تحقق جهاز، مستهلك و اختبار. لا يلزم فقط لـ يمثل مراجعة ترتيب بينما قسم إعداد مقدار خارج إصدار. عبر PR سوف مراجعة بعد فرعي فرع دمج دخول إصدار فرع، و في إصدار قبل تحقق تركيب نتيجة. التزام حراسة إصدار فرع قوي صنع دفع إرسال و حذف حفظ حماية؛ لا يلزم قوي صنع تزامن هذا فرع.

قد إصدار codec و ترحيل دلالة إبقاء تجميد ربط. لا يلزم عبر تعديل قد إصدار ترحيل حافة قدوم تنفيذ جديد بنية صفة وظيفة. فقط لديه N→N+1 ترحيل حافة يمكن في N+1 إصدار قبل قبول دخول تنسيق نفس تغيير؛ إصدار بعد، دخول واحد خطوة بنية صفة تغيير حاجة تحت واحد بند متبادل مجاور ترحيل حافة.

لم إصدار N+1 اختبار تكامل ينبغي استخدام يمكن إسقاط، متبادل متبادل عزل Harness home. في بين إصدار إنتاج N+1 ملف قد علامة لـ هدف كتابة جهاز إصدار، لذلك لاحق مقابل N→N+1 تعديل لن مجددا مرة ترحيل هذا ملف. طلب في كل جديد اختبار home في من لم تغيير تاريخ إدخال إعادة تشغيل؛ أبدا عبر تعديل كتابة قد إيداع بديل حد أو إعادة استخدام حقيقي مستخدم home قدوم إصلاح هذا عدد مشكلة.

تغيير كتابة جهاز قبل، استخدام[عودة ملف أمر](../persistence-changes/historical-formats/README.ar.md#maintenance) إبقاء ذلك كامل حفظ دائم schema، مجددا في `docs/persistence-changes/historical-formats/vN.*` تحت إضافة مزدوج لغة صيغة مشاركة اعتبار. إبقاء كل أكثر مبكر سجل. صيغة تغطية فحص اشتراط منخفض في جديد كتابة جهاز كل كامل عدد إصدار كل لديه مستقل وثيقة؛ حالي توليد دليل فقط تغطية جديد كتابة جهاز.

## 2. إضافة ثابت انتظار ترحيل حافة

حسب وفق حزمة فحص بيان لـ N→N+1 إنشاء مكتبة، بينما غير تركيب إضافة. ثابت انتظار متن تحويل فقط هو الأكثر أول وصل خط هيكل هيكل.[V2 إلى V3 مواصفة](../../packages/session/session-format-v2-to-v3/README.ar.md#v2-to-v3-specification) هو واضح تحويل و إبقاء قاعدة ثابت عرض مثال، بينما لا هو يمكن متابعة توسيع أو نظر لـ ثابت انتظار تحويل ترحيل حافة.

في manifest(بيانات وصفية بيان) في إعلان `dsh.sessionFormatMigration`، يتضمن عدد قيمة `from: N` و `to: N+1`، توجيه خروج مسار، و توجيه خروج ترحيل، مصدر codec، هدف codec، هدف header تحقق جهاز و هدف استعادة جهاز. إعادة استخدام قبل واحد بند ترحيل حافة الذي تابع حزمة توجيه خروج مصدر codec، و اعتماد هذا حزمة؛ لا يلزم نسخ أو إعادة تعريف قد إصدار codec. من جديد حزمة توجيه خروج هدف codec و تحقق جهاز. سوف ترحيل حافة إضافة دخول catalog مباشر اعتماد، و إضافة مساحة العمل TypeScript مسار و مشروع مرجع.

في إضافة جديد ترحيل حافة إعلان معا، سوف[نواة قلب Session نوع](../../packages/core/session/src/types.ts) في `SESSION_FORMAT_VERSION` ضبط لـ N+1، لكن بعد توليد catalog. تحت وجه أمر فقط توليد قد إعلان ترحيل سلسلة؛ هو لن تنفيذ جديد إصدار:

```sh
pnpm run gen-session-format-catalog
```

[توليد جهاز](../../scripts/gen-session-format-catalog.ts) اشتراط من صفر إلى كتابة جهاز إصدار كل واحد خطوة تماما جيد لديه واحد متبادل مجاور ترحيل حزمة، دليل و حزمة اسم مطابقة، متبادل مجاور codec توجيه خروج مطابقة، و إعلان الذي يحتاج اعتماد. هو رفض نقص فتحة، تكرار أو كثير بقية ترحيل حافة، لم معرفة بيانات وصفية عضو، و لم عبر مقابل انتظار اعتماد (peer dependency) إضافة تطوير اعتماد مشترك Session catalog. طلب إصلاح إعلان، بينما غير يد تعديل `generated.ts`.Catalog في بناء وقت ساكن حالة تحديد؛ إضافة تركيب لا نيل قرار تاريخ بيانات هل يمكن قراءة.

## 3. تنفيذ كل نسخة ناتج وحيد احتلال Stage و تحقق

استخدام [Stage واجهة](../../packages/session/session-format/src/types.ts) ، لا يلزم استخدام كامل نسخة ناتج عدد مجموعة إلى عدد مجموعة ترحيل جهاز. غير ممكن تغيير `SessionFormatMigration` إعلان توفير `migrateHeader`،`validateTargetHeader` و `createStage`. كل مرة استدعاء `createStage` كل لـ واحد نسخة مصدر ناتج إنشاء مستقل حالة. حساب عدد جهاز، انتظار معالجة حدث و مرجع خريطة عودة هذا حالة كل؛ مختلف Session بين أبدا مشترك متغير Stage.

تنفيذ `transformEvent(event, context)`،`transformRun(run, context)` و `finish(context)`. عبر `context.emitEvent` أو `context.emitRun` تزامن إخراج؛ مرة استدعاء يمكن إنتاج صفر عدد، واحد أو كثير عدد إخراج. يجعل Stage مباشر إزالة استهلاك codec كل ضيق تجميع run، أو من تكرار بديل `run.expand()`، بينما لا شيء تحويل في بين عدد مجموعة. استدعاء جهة مسؤول ضبط درجة، ترحيل سلسلة أولا انتهاء فوق تنقل Stage، مجددا انتهاء تحت تنقل Stage.

وراثة قطع نقطة هو منطق حدث عدد كمية، لا هو شيء إدارة سطر عدد. فقط لديه في EOF قبل معروف وقت عندئذ عام `headerInheritedEventCount`؛`finish` إرجاع دقيق هدف قطع نقطة. قبل واحد بند تغيير حدث عدد كمية ترحيل حافة ممكن جعل هذا عدد كمية في بنية صنع وقت غير ممكن معرفة. لا بد يلزم وقت من قد تحقق نوع فرعي علامة دفع توجيه هو، و اختبار من كل تلقي دعم حمل تاريخ بديل حد إلى N+1 لديه نوع فرعي كثير قفز استعادة، بينما غير فقط اختبار مباشر N إدخال. أبدا بـ صفر بديل لم معرفة قطع نقطة.

صريح تعريف جديد ترحيل حافة حدث دقيق دخول و تغيير تبديل قاعدة.[V2 إلى V3 مصدر مراجعة حساب](../../packages/session/session-format-v2-to-v3/README.ar.md#source-audit) و [Alpha V0→V1 قاعدة](../../.agents/notes/implemented/architecture/2026-08-31-alpha-historical-unknown-event-refusal.ar.md) قسم آخر مسؤول مقابل قد إصدار ترحيل حافة سياسة، بينما غير جديد ترحيل حافة سياسة. لا يلزم سوف مهمة واحد سياسة دفع واسع إلى كل ترحيل حافة. بنية أو حدث موضع تغير وقت، يجب تصنيف مصدر حدث، تحميل حمل عضو و مرجع، و صريح حكم قطع لا نفاذ واضح بيانات قدرة لا إبقاء صالح.[نفس إصدار إبقاء](../../.agents/notes/implemented/architecture/2026-08-30-retain-ignorable-external-session-events.ar.md) ذاته لا يستطيع إثبات بنية تغيير تبديل أمان. تحقق هدف دلالة، و لـ كل إضافة جديدة يمكن قبول سجل مثال توفير واحد يتم رفض عكس مثال؛ أبدا وضع عرض قديم ترحيل حافة قدوم إخفاء غطاء لا تلقي دعم حمل تحويل.

عبر `sessionFormatCatalog.createRestore(header, { recovery: 'strict', validation: 'current' })` تحقق صارم إطار استعادة، حسب ترتيب نقل دخول كل سطر و استدعاء `finish()`. هذا سوف تنفيذ شيء إدارة حل رمز، كامل ترحيل سلسلة و قد تثبيت حالي Session تحقق. إنتاج بيئة recoverable/transformed سياسة لا يستطيع بديل fixture(اختبار قبل وضع بيانات) و إصدار تحقق الذي يحتاج صارم إطار تحقق. إبقاء قد سجل تاريخ تحقق مثال خارج، لا يلزم إعلان تسمية مصدر تحقق مقارنة ترحيل حافة فعلي تنفيذ أكثر صارم إطار.

## 4. تحديث حالي إصدار مستهلك

تتبع أثر كل حالي إصدار مستهلك، يشمل Session إنشاء و استعادة،JSONL ملف اسم اختيار و إصدار،catalog حالي تحرير رمز جهاز و استعادة جهاز، إسقاط ذاكرة مؤقتة بديل حد هوية، إعادة تشغيل و لقطة عودة واحد تحويل، و TypeScript/Python SDK تسجيل صنع. عند قيمة يمثل حالي إصدار وقت استخدام كتابة جهاز معتاد كمية؛ في قد إصدار codec و تاريخ fixture في إبقاء حرف وجه تاريخ إصدار. عبر كل منها كل من تحديث حالي وثيقة و توليد مشاركة اعتبار.

لا يلزم تلقائي رفع رفع غير متصل إصدار. طلب حزمة تركيب طبقة `sessionFormatVersion` معرف تضمين دخول Session بديل حد؛ خارج طبقة schema إصدار لديه ذاتي ذات يحتوي معنى. إسقاط وحدة حالة إصدار نفس مثال لا يستطيع بديل ذاكرة مؤقتة Session بديل حد هوية.

تحقق قراءة و كتابة اثنان بند مسار. فقط header قائمة عملية لا نيل قراءة متن أو إصدار. تاريخ قراءة فتح يمكن مباشر إرجاع ترحيل بعد داخل تخزين ناتج بينما لا كتابة؛ كتابة فتح يجب أولا تحقق تزامن نشر وحيد نهائي حالي بعد استمرار بديل حد، مجددا سماح إلحاق. مصدر مسار، بايت و inode إبقاء ثابت. الذي اختيار بديل حد عال في حالي إصدار أو بلا فاعلية وقت، لا نيل رجوع إلى قبل بديل.[دقيق تجهيز مرحلة مقطع قرار](../../.agents/notes/implemented/architecture/2026-09-05-read-only-session-migration-preparation.ar.md) مسؤول إصدار وقت ترتيب.

## 5. إنشاء لقطة بعد استمرار بديل حد

قراءة قراءة[لقطة كل حق](../../snapshots/AGENTS.md) و[لقطة مكتبة](../../packages/test-support/session-snapshot/README.ar.md). اختيار يملك بيانات مشهد، بينما غير فقط مرجع هو مهايئ. تنفيذ N+1 بعد، إبقاء كل نسخة تاريخ ملف، و حسب هدف إصدار مواصفة أب فرعي ملف اسم توليد بعد استمرار ملف. أبدا سوف قبل بديل إعادة تسمية لـ هدف ملف اسم، أو فقط تعديل ذلك header.

إذا إعادة تشغيل إدخال ثابت، في كل من فوق تنفيذ بلا مفتاح refresh، مجددا تنفيذ لا كتابة عودة replay. التالي SDK أمر استخدام `text-turn` و مساحة العمل كتابة جهاز إصدار. أولا تنفيذ و وصل دخول N+1، عندئذ قدرة استخدام هو جمع توليد هذا إصدار؛ وظيفة تغيير ينبغي اختيار فعلي تلقي أثر كل من:

```sh
pnpm run test:snapshot:refresh snapshots/sdk/sdk.snapshot.ts -t text-turn
pnpm run test:snapshot snapshots/sdk/sdk.snapshot.ts -t text-turn
```

واحد بدء مراجعة فحص جديد بديل حد، طلب مرافق مع ملف و بروتوكول إخراج. تحقق كل قبل بديل بايت إبقاء نفسه، كما أب فرعي زاوية لون وصل متابعة. اختيار قاعدة اعتماد عدد قيمة الأكثر عال بديل حد، لذلك ينبغي سوف مشترك مرجع تحديث لـ كل من اختيار في أب بديل حد. لا يلزم يأخذ packed تخطيط ترحيل جهاز عند عمل إصدار ترقية جهاز. إذا نموذج transcript(نص سجل) يجب تغير، من مشهد كل من حسب وفق[اختبار سياسة](../testing.ar.md) استخدام الذي يحتاج مزود مفتاح إجراء فوري تسجيل صنع.

عبر `snapshot.yml` `sessionFormat.version` و تلقي دعم حمل `coverage` اسم صريح إبقاء تاريخ سجل مثال؛record و refresh لا تعديل هذه Session fixture. تحديث[لغة مادة سياسة](../../scripts/session-snapshot-corpus-policy.ts) بـ اعتماد حالي بديل حد، معا إبقاء تجمع تركيز مباشر ترحيل حافة، كثير قفز،packed row، إعادة محاولة/فشل و تسليم profile تغطية. فحص لغة مادة و اثنان عدد SDK إسقاط؛ لا يلزم فقط لـ إزالة حذف تحقق فشل بينما دفعة كمية refresh غير متصل مشهد.

## 6. تحقق تجميع صار نتيجة

من مستودع أصل دليل تشغيل. التالي أمر فحص catalog إعلان،Stage تركيب، قد إصدار V2→V3 ترحيل حافة و بديل حد اختيار. هو جمع هو أساس خط فحص؛ يحتاج لـ جديد ترحيل حافة إضافة تجمع تركيز تغطية:

```sh
pnpm run verify-session-format-catalog
pnpm exec vitest run scripts/gen-session-format-catalog.spec.ts packages/session/session-format/tests packages/session/session-format-v2-to-v3/tests packages/session/session-format-catalog/tests
pnpm run test:snapshot scripts/session-snapshot-corpus.corpus.ts
```

تنفيذ جديد ترحيل حافة بعد، سوف ذلك فعلي اختبار مسار إضافة دخول تجمع تركيز Vitest أمر. أصل حسب فعلي diff إضافة تلقي أثر JSONL، إعادة تشغيل، إسقاط و SDK اختبار؛ إصدار Worker مسار تغير وقت أيضا يحتاج بناء ناتج خطر دخان اختبار. اشتراط صارم إطار ترحيل نجاح، هيكل هيكل إبقاء ثابت انتظار، رفض صيغة خطأ و لم معرفة مطلوب حدث، تكرار استعادة تحديد، تزامن Stage حالة مستقل، لديه نوع فرعي كثير قفز قطع نقطة صحيح تأكيد، قبل بديل ثابت كما بلا رجوع. تقرير إبلاغ تأكيد قطع أمر و فشل، لا يلزم دفع قطع كامل اختبار طقم عنصر نتيجة.

تحديث[الذي تابع Agent Note](../../.agents/notes/implemented/architecture/2026-08-31-released-session-format-migrations.ar.md) ، بينما غير إضافة تكرار قرار سجل. إصدار قبل إبقاء[إصدار سجل](../session-format-status.ar.md#updating-the-record) ثابت؛ إصدار بعد، استخدام قد نواة فعلي إصدار دليل تحديث هو. مراجعة حساب متبادل صلة نشط وثب سجل يحل محل علاقة؛ إبقاء مستقل إدارة من، و إبقاء عودة ملف سجل تجميد ربط. واحد بدء تحديث مزدوج لغة متن، عبر مستودع أداة إعادة سجل كل تغيير إعداد مقابل، لكن بعد تشغيل وثيقة فحص:

```sh
pnpm run verify-translation-pairing --write docs/cookbook/adding-a-session-format-version.md
pnpm run test:docs
pnpm run doc-sync
pnpm run lint
git diff --check
```
