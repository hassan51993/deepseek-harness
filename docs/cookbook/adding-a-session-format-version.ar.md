# دليل عملي: إضافة إصدار صيغة لسجل الجلسة

[English](adding-a-session-format-version.md) | العربية

## الملخص

استعمل هذا الدرس لإدخال إصدار الجلسة البنيوي التالي دون إعادة كتابة البيانات المُصدَرة. واقرأ [مرجع الإصدار وحالة النشر](../session-format-status.ar.md) لتعرف كاتبَ نسخة العمل وأحدثَ صيغة مُصدَرة. ولْيكن N تلك الصيغةَ المُصدَرة المتحقَّق منها، وN+1 الهدفَ؛ وضع قيمًا عددية مكان هذين الرمزين في الأسماء والبيانات الوصفية. وابدأ من نسخة عمل مساهِم صالحة، واقرأ [قائمة تحقق الحزمة](adding-a-package.ar.md)، و[مكتبة الصيغ](../../packages/session/session-format/README.ar.md)، و[قرار الصيغ المُصدَرة](../../.agents/notes/implemented/architecture/2026-08-31-released-session-format-migrations.ar.md).

## 1. اختر الإصدار وأساس الإصدار

ارفع الصيغة عند تغيير بنيوي في الترويسات أو مغلّفات الأحداث أو دلالة الأحداث الأساسية أو إعادة بناء السطوح. أما إضافاتُ الأحداث العادية فلا تقتضي رفعًا؛ فاتبع [قاعدة الإصدارات](../../.agents/notes/implemented/architecture/2026-08-10-session-log-version-mechanism.ar.md). وميّز عددَ صيغة الجلسة عن إصدارات نشر الحزم وإصدارات schema في SQLite وإصدارات وحدات الإسقاط وإصدارات مغلّفات البروتوكول.

واستعمل أساسَ دمج مشتركًا `release/*` للإصدار N+1. ويضيف تغييرُ الأساس الكاتبَ والـ codec وتوصيلَ الدليل وترحيلَ الهوية والتحقق. وأنشئ كل فرع ابن مستقل من ذلك الأساس واجعل PR الخاص به يقصد فرعَ الإصدار، لا فرعَ ابن مستقل آخر. ويضيف كل ابن تحويلَه البنيوي ومدقّقاتِه ومستهلكيه واختباراتِه إلى حزمة الترحيل المتجاور نفسها. ولا تخصّص إصدارات إضافية لمجرد تمثيل ترتيب المراجعة. وادمج الأبناء المراجَعين في فرع الإصدار عبر PRs، ثم تحقّق من النتيجة المجتمعة قبل الإصدار. واحترم حمايات الدفع القسري والحذف على فرع الإصدار؛ ولا تزامنه قسرًا.

وتبقى الـ codecs المُصدَرة ودلالاتُ الترحيل مجمَّدة. ولا تعدّل حافةً مُصدَرة لتنفّذ ميزةً بنيوية جديدة. ولا يجوز إلا لحافة N إلى N+1 أن تضم تغييرات منسّقة قبل شحن N+1؛ وبعد الإصدار تحتاج التغييراتُ البنيوية الأخرى الحافةَ المتجاورة التالية.

واستعمل أدلةً منزلية للإطار معزولة وقابلة للإسقاط في اختبار دمج N+1 غير المُصدَر. فملفُّ N+1 المرحلي يحمل إصدارَ الكاتب الهدف أصلًا، فلن يرحّل تعديلٌ لاحق على N إلى N+1 ذلك الملف مرةً أخرى. أعِد التشغيل من مدخلات تاريخية لم تتغير في دليل منزلي اختباري جديد؛ ولا تصلح هذا أبدًا بإعادة كتابة جيل مودَع أو بإعادة استعمال دليل مستخدم حقيقي.

وقبل تغيير الكاتب، استعمل [أمر الأرشفة](../persistence-changes/historical-formats/README.ar.md#maintenance) لتحفظ schema الحفظ الدائم كاملًا له، ثم أضف مرجعَ الصيغة الثنائي اللغة تحت `docs/persistence-changes/historical-formats/vN.*`. واحفظ كل السجلات الأسبق. ويشترط فحصُ تغطية الصيغ أن يكون لكل عدد صحيح دون الكاتب الجديد وثيقتُه هو؛ فالدليلُ المولَّد الحالي لا يغطي سوى الكاتب الجديد.

## 2. أضف حافة هوية

اتبع قائمة تحقق الحزمة لإنشاء مكتبة لـ N إلى N+1، لا إضافةً مركَّبة. وتحويلُ المتن تحويلَ هوية سقالةُ توصيل أولية لا غير. و[مواصفة V2 إلى V3](../../packages/session/session-format-v2-to-v3/README.ar.md#v2-to-v3-specification) مثالٌ ثابت على التحويلات الصريحة وقواعد الحفظ، لا حافةٌ تُوسَّع ولا تحويلُ هوية.

أعلن `dsh.sessionFormatMigration` بـ `from: N` و`to: N+1` عدديَّين، وبمسار تصدير، وبالترحيل المصدَّر وcodec المصدر وcodec الهدف ومدقّق ترويسة الهدف ومستعيد الهدف. وأعِد استعمال codec المصدر الذي تصدّره حزمةُ الحافة السابقة واعتمد عليها؛ ولا تنسخ codec مُصدَرًا ولا تعِد تعريفه. وصدّر codec الهدف والمدقّقات من الحزمة الجديدة. وأضف الحافة اعتماديةً مباشرة للدليل، وأضف مساراتِ TypeScript وإشاراتِ المشاريع في مساحة العمل.

واضبط `SESSION_FORMAT_VERSION` في [أنواع الجلسة الأساسية](../../packages/core/session/src/types.ts) على N+1 مع تصريحات الحافة الجديدة، ثم ولّد الدليل. والأمر التالي لا يولّد إلا السلسلة المعلَنة؛ وهو لا ينفّذ إصدارًا جديدًا:

```sh
pnpm run gen-session-format-catalog
```

ويشترط [المولّد](../../scripts/gen-session-format-catalog.ts) حزمةً متجاورة واحدة بالضبط لكل خطوة من صفر إلى إصدار الكاتب، وتطابقَ أسماء الأدلة والحزم، وتطابقَ تصديرات الـ codecs المتجاورة، والاعتمادياتِ المعلَنة. وهو يرفض الفجوات، والحوافَّ المكرّرة أو الزائدة، والبياناتِ الوصفية المجهولة، ودليلًا لا يتشارك Session عبر الاعتماديات النظيرة واعتماديات التطوير. فأصلح التصريحات بدل تحرير `generated.ts` يدويًا. والدليلُ ساكن عند البناء؛ فلا يجوز أن يقرّر تركيبُ الإضافات قابليةَ قراءة التاريخ.

## 3. نفّذ الأطوار لكل ناتج ونفّذ التحقق

استعمل [واجهات Stage](../../packages/session/session-format/src/types.ts)، لا مرحِّلًا يحوّل مصفوفةً إلى مصفوفة للناتج كله. ويوفّر تصريحُ `SessionFormatMigration` غير القابل للتغيير الدوالَّ `migrateHeader` و`validateTargetHeader` و`createStage`. وكل استدعاء لـ `createStage` ينشئ حالةً مستقلة لناتج مصدر واحد. فاحفظ العدّادات والأحداث المعلّقة وخرائطَ المراجع هناك؛ ولا تتشارك طورًا قابلًا للتغيير بين الجلسات أبدًا.

ونفّذ `transformEvent(event, context)` و`transformRun(run, context)` و`finish(context)`. وأرسل تزامنيًا عبر `context.emitEvent` أو `context.emitRun`؛ وقد ينتج الاستدعاءُ صفرَ مخرجات أو واحدًا أو كثيرًا. ودَع الطورَ يستهلك الجولاتِ المضغوطة التي يملكها الـ codec مباشرةً، أو يمرّ على `run.expand()` بلا تجسيد مصفوفة وسيطة. والمستدعي يملك الجدولة، وتُنهي السلسلةُ الأطوارَ الأعلى قبل الأدنى.

وعامِل القطعَ الموروث عددَ أحداث منطقيًا لا عددَ صفوف فيزيائيًا. ولا تكشف `headerInheritedEventCount` إلا حين يكون معروفًا قبل نهاية الملف؛ و`finish` يعيد القطعَ الهدف بعينه. وقد تجعل حافةٌ سابقة تغيّر العددَ ذلك الرقمَ غيرَ متاح عند البناء. فاشتقّه من علامات البذر المتحقَّق منها عند اللزوم، واختبر الاستعادةَ المبذورة متعددةَ القفزات من كل جيل تاريخي مدعوم حتى N+1، لا من مدخل N المباشر وحده. ولا تضع صفرًا أبدًا مكان قطع مجهول.

وعرّف صراحةً قواعدَ قبول الأحداث وتحويلها في الحافة الجديدة. وتملك [مراجعة مصدر V2 إلى V3](../../packages/session/session-format-v2-to-v3/README.ar.md#source-audit) و[قاعدة V0 إلى V1 في alpha](../../.agents/notes/implemented/architecture/2026-08-31-alpha-historical-unknown-event-refusal.ar.md) سياساتِ تينك الحافتين المُصدَرتين، لا الحافةَ الجديدة. ولا تعمّم أيًّا منهما على كل حافة. وتغييرُ البنية أو مواضع الأحداث يقتضي تصنيفَ أحداث المصدر وأعضاءِ الحمولة والمراجع، والحكمَ صراحةً هل تبقى البيانات المعتمة صالحة. و[الاحتفاظ بالإصدار المساوي](../../.agents/notes/implemented/architecture/2026-08-30-retain-ignorable-external-session-events.ar.md) وحده لا يثبت سلامةَ تحويل بنيوي. فتحقّق من دلالة الهدف، وأعطِ كل حالة مقبولة حديثًا مثالًا مضادًّا يُرفَض؛ ولا توسّع الحوافَّ الأقدم أبدًا لإخفاء تحويل غير مدعوم.

وأثبت الاستعادةَ الصارمة عبر `sessionFormatCatalog.createRestore(header, { recovery: 'strict', validation: 'current' })`، بتغذية الصفوف بالترتيب واستدعاء `finish()`. فهذا يمرّن فكَّ الترميز الفيزيائي والسلسلةَ كاملةً وتحقُّقَ الجلسة الحالي المركَّب. وسياسةُ الإنتاج القابلة للتعافي والتحويل ليست بديلًا عن التحقق الصارم من التجهيزات والنشر. واحفظ استثناءات التحقق التاريخية الموثَّقة بدل ادّعاء تحقق من المصدر أشدَّ مما تجريه الحافةُ فعلًا.

## 4. حدّث مستهلكي الإصدار الحالي

تتبّع كل مستهلك للإصدار الحالي، بما فيه إنشاءُ الجلسة واستعادتها، واختيارُ اسم ملف JSONL ونشرُه، ومرمِّزُ الدليل الحالي ومستعيدُه، وهويةُ جيل ذاكرة الإسقاط المؤقتة، وتوحيدُ إعادة التشغيل واللقطات، وتسجيلاتُ TypeScript وPython SDK. واستعمل ثابتَ الكاتب حيث تعني القيمةُ «الحالي»؛ وأبقِ الإصدارات التاريخية الحرفية في الـ codecs المُصدَرة والتجهيزات التاريخية. وحدّث التوثيقَ الحالي والمراجعَ المولَّدة عبر مالكيها.

ولا ترفع إصدارات غير ذات صلة تلقائيًا. فـ `sessionFormatVersion` في مغلّف الطلب يحدّد جيلَ الجلسة المضمَّن فيه؛ ولإصداره الخارجي معناه هو. وكذلك لا تحل إصداراتُ حالة وحدات الإسقاط محل هوية جيل الجلسة في الذاكرة المؤقتة.

وتحقّق من مسارَي القراءة والكتابة معًا. فالإدراجُ المقصور على الترويسة يجب ألّا يقرأ المتون ولا ينشر. و`open` للقراءة التاريخية قد يعيد الناتجَ المرحَّل في الذاكرة بلا كتابة؛ أما `open` للكتابة فيجب أن يتحقق وينشر الخَلَفَ الحالي النهائي وحده قبل الإلحاق. ويبقى مسارُ المصدر وبايتاته وعقدةُ فهرسته بلا تغيير. ويجب ألّا يؤدي جيلٌ مختار أحدثُ أو غيرُ صالح إلى الرجوع إلى سلف. ويملك [قرار التحضير](../../.agents/notes/implemented/architecture/2026-09-05-read-only-session-migration-preparation.ar.md) توقيتَ النشر.

## 5. أنشئ خلفاء اللقطات

اقرأ [ملكية اللقطات](../../snapshots/AGENTS.md) و[مكتبة اللقطات](../../packages/test-support/session-snapshot/README.ar.md). واختر السيناريو المالك، لا مهايئًا يشير إليه فقط. وبعد تنفيذ N+1، أبقِ كل ملف تاريخي وولّد خلفَه بأسماء ملفات الأب والابن المعيارية لإصدار الهدف. ولا تعِد تسمية سلف إلى اسم ملف الهدف ولا تغيّر ترويسته وحدها أبدًا.

وفي مدخلات إعادة التشغيل التي لم تتغير، استعمل التحديثَ الخالي من المفاتيح على المالك، ثم أعِد التشغيل بلا كتابة راجعة. وأمرا SDK هذان يستعملان `text-turn` وإصدارَ الكاتب في نسخة العمل. فنفّذ N+1 ووصّله قبل استعمالهما لتوليد ذلك الإصدار، واختر المالكَ المتأثر فعلًا في أي ميزة:

```sh
pnpm run test:snapshot:refresh snapshots/sdk/sdk.snapshot.ts -t text-turn
pnpm run test:snapshot snapshots/sdk/sdk.snapshot.ts -t text-turn
```

راجع الجيلَ الجديد والملفاتِ المرافقة للطلب وخرجَ البروتوكول معًا. وتحقّق من بقاء كل سلف مطابقًا بايتًا ببايت ومن بقاء أدوار الآباء والأبناء متصلة. والاختيارُ يأخذ أعلى جيل عدديًا، فحدّث المراجعَ المشتركة إلى الأب المختار للمالك. ولا تستعمل مرحِّلَ التخطيط المحزوم مرقِّيًا للإصدارات. وإن وجب تغييرُ نص محادثة النموذج، فمالكُ السيناريو يسجّل حيًّا وفق [سياسة الاختبار](../testing.ar.md)، بمفتاح المزوّد الذي تشترطه.

وأبقِ الحالاتِ التاريخية المقصودة صريحةً عبر `sessionFormat.version` في `snapshot.yml` وأسماءِ `coverage` المدعومة؛ ولا يمس التسجيلُ ولا التحديث تجهيزاتِ جلساتها. وحدّث [سياسة المدوَّنة](../../scripts/session-snapshot-corpus-policy.ts) للجيل الحالي مع الاحتفاظ بتغطية مركَّزة للحافة المباشرة، والقفزات المتعددة، والصفوف المحزومة، وإعادة المحاولة والفشل، والـ profiles المشحونة. وافحص المدوَّنة وإسقاطَي SDK معًا؛ ولا تحدّث سيناريوهات غير ذات صلة جملةً لمجرد إسكات فشلِ تحقق.

## 6. تحقّق من النتيجة المدمجة

شغّل من جذر المستودع. وهذه الأوامر تفحص تصريحاتِ الدليل وتركيبَ الأطوار والحافةَ المُصدَرة V2 إلى V3 واختيارَ الأجيال. وهي خطُّ أساس؛ فأضف تغطيةً مركَّزة للحافة الجديدة:

```sh
pnpm run verify-session-format-catalog
pnpm exec vitest run scripts/gen-session-format-catalog.spec.ts packages/session/session-format/tests packages/session/session-format-v2-to-v3/tests packages/session/session-format-catalog/tests
pnpm run test:snapshot scripts/session-snapshot-corpus.corpus.ts
```

وبعد تنفيذ الحافة الجديدة، أضف مسارَ اختبارها الفعلي إلى تشغيلة Vitest المركَّزة. وأضف اختباراتِ JSONL وإعادة التشغيل والإسقاط وSDK التي يختارها الفرقُ الفعلي، مع اختبار التحقق السريع لعامل النشر المبني حين يتغيّر ذلك المسار. واشترط نجاحَ الترحيل الصارم، وحفظَ الهوية في الهيكل، ورفضَ الأحداث المشوَّهة والمجهولة المطلوبة، واستعاداتٍ متكررة حتمية، وحالةَ أطوار متزامنة مستقلة، وقطوعًا مبذورة متعددة القفزات، وأسلافًا لم تتغير، وانعدامَ الرجوع. وأبلِغ عن الأوامر والأعطال بعينها، لا عن نتيجة جناح كامل مستنتَجة.

وحدّث [Agent Note المالك](../../.agents/notes/implemented/architecture/2026-08-31-released-session-format-migrations.ar.md) بدل إضافة سجل قرار زائد. وأبقِ [سجل الإصدار](../session-format-status.ar.md#updating-the-record) بلا تغيير حتى النشر؛ وبعده حدّثه بدليل إصدار متحقَّق منه. ودقّق الملاحظاتِ النشطة ذات الصلة بحثًا عن ما حلّ محله؛ واحتفظ بالتبرير المستقل واترك الملاحظات المؤرشفة مجمَّدة. وحدّث النثر الثنائي اللغة معًا، وأعِد تسجيل كل اقتران متغيّر بأداة المستودع، ثم شغّل فحوص التوثيق:

```sh
pnpm run verify-translation-pairing --write docs/cookbook/adding-a-session-format-version.md
pnpm run test:docs
pnpm run doc-sync
pnpm run lint
git diff --check
```
