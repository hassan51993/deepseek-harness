# مرجع تأليف الأدوات

[English](adding-a-tool.md) | العربية

مرجعٌ للعقود التي على الأداة الموجَّهة إلى النموذج استيفاؤها. ولأداة أولى مرتَّبة الخطوات اتبع [بناء أداة](../user/develop/basic/tool.ar.md). و`packages/shell/tool-bash` هو المثال الإنتاجي ذو الحزم الثلاث.

## الصيغة الدنيا

```ts
import { readFile } from 'node:fs/promises'
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'my-tool'
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'read_file',
    description: 'Read a file from disk.',          // what the model sees
    parameters: {
      path: { type: 'string', required: true, description: 'Absolute path' },
      limit: { type: 'number' },                     // optional by default
    },
    output: {
      schema: { type: 'string' },
      render: (_args, value) => [{ type: 'text', text: value }],
    },
    async execute(args, exec) {
      // args is TYPED from the schema: { path: string; limit?: number }
      // exec carries immutable identity + token; signal is the operational field
      return readFile(args.path, { encoding: 'utf8', signal: exec.signal })
    },
  }))
}
```

والتسجيل قائم على الآثار: فتحرير fiber الإضافة يلغي تسجيل الأداة. وتتدفق schemas إلى تجميع توجيه النظام تلقائيًا.

## قواعد عقد ()execute

- **الوسائط مُتحقَّق منها نيابةً عنك.** يتحقق `defineTool` من `arguments` التي يولّدها النموذج مقابل `ParameterSchemaSpec` الموحَّد قبل تشغيل `execute` (الأنواع، والمفاتيح المطلوبة، وقيود القيم الحرفية، واتحاداتُ «واحد بالضبط»، والقيمُ المتداخلة)، فتطابق الوسائطُ داخل `execute` النوعَ `InferArgs`. وعُقد الكائنات الصريحة تعلن `additionalProperties: true | false`؛ ويبقى جذرُ المعاملات الضمني مفتوحًا. ويبقى عليك فحصُ القيود التي لا تعبّر عنها اللغةُ الوصفية يدويًا، مثل السلاسل غير الفارغة أو الأعداد الموجبة أو القواعد العابرة للحقول. وأدواتُ JSON-Schema الخام المسجَّلة مباشرةً تملك التحقق من مدخلاتها.
- **التسجيل يستعير تعريفَك للقراءة فقط.** فالمساهمة المنمَّطة داخل العملية نفسها ليست حدَّ تسلسل؛ فلا تغيّر schema الخاص بها ولا تستبدل استدعاءاتها الراجعة بعد التسجيل. و`schemas()` لا تجسّد إلا الإسقاط الصريح الموجَّه إلى النموذج. ولتبديل أداة تبديلًا حارًّا، حرّر الأثرَ الذي يملكها وسجّل البديل؛ وتبقى الحالةُ القابلة للتغيير داخل إغلاق الاستدعاء الراجع حالةَ إضافة عادية.
- **هوية التنفيذ محمية.** يجسّد الـ registry `arguments` بوصفها JSON منفصلًا بلا فقد في مرور تكراري واحد، ويجمّد تلك القيمة قبل أن تبدأ السياسة، ويسند `exec.token` معتمًا؛ وتبقى `callId` و`name` و`arguments` و`agent` و`token` و`signal` المطلوبة المملوكة للمستدعي، ورمزُ `parent` الاختياري للنقل المحيط، غيرَ قابلة للتغيير طوال التوزيع. و`parent` للهوية وحدها ولا يكشف تنفيذًا خارجيًا حيًّا. وعامِل `args` مدخلًا للقراءة فقط. ولا يتلقى عرضًا قابلًا للتغيير إلا اللافُّ المحيط بالتوزيع، وله أن يستبدل `exec.signal` المطلوبة ويعيدها ليفرض مهلة، لكنه لا يستطيع حذفها.
- **أعلن قيمةَ JSON معيارية واحدة وأعِدها.** يستعمل `output.schema` النوعَ `ValueSchemaSpec` وقد يكون جذرُه كائنًا أو مصفوفةً أو قيمةً مفردة أو null. ولا يعيد `execute` إلا القيمةَ المستنتَجة؛ ويأخذ الـ registry لقطةً منها بوصفها JSON بلا فقد، ويتحقق منها، ويجمّدها، ويمرّرها إلى `output.render(args, value)`. ولا تعِد كتلَ محتوى من المتن، ولا تجعل المستدعين يحلّلون نثرًا لاستخراج المعرّفات والحقول.
- **الرمي أو إعادةُ قيمة غير صالحة تعني `isError`.** فالـ registry يلتقط الرميَ ويحتوي أعطالَ schema والمصيّر ومسقِط البيانات الوصفية وJSON بلا فقد قبل تشغيل المراقبين. وارمِ في أعطال البنية التحتية. ومثّل النتيجةَ الناجحة في المجال بالقيمة المعيارية حتى حين يشرح مصيّرها الأصيل حالةً غير مثالية، مثل خروج عملية برمز غير صفري.
- **احترم `exec.signal`.** وألغِ العمل الجاري حين تُطلَق.
- **أسقِط بيانات البطاقة الدائمة بـ `presentationMeta` (اختياري).** يشتق `output.presentationMeta(args, value)` من القيمة المعيارية نفسها JSON قابلًا لإعادة التشغيل. وتحفظه النواةُ على `tool/result` وتسلّمه إلى `presentResult`، فتنجو البطاقةُ التي تحتاج وقائعَ وقت النتيجة، مثل القطع المطبَّقة في `write` و`edit`، من إعادة التشغيل بلا حفظ القيمة المعيارية. ويُتخطّى المسقِط في توزيعات Code المتداخلة لأن لا بطاقات لها.
- **استعمل `exec.agent` للإشعارات اللاتزامنية.** فـ `agent.inject({ content, source: { kind: 'plugin', plugin: '<name>' } })` يُلحق سياقًا دائمًا يراه **طلبُ النموذج التالي**؛ وهو ليس إيقاظًا (فالوكيل الخامل يبقى خاملًا). واحترس من الوكلاء المحرَّرين (بـ try/catch).

## العمل الطويل

قيّد `run_in_background` بإعداد المنتج، ثم سجّل عبر `ctx.jobs.start({ kind, label, owner: exec.agent, run })`. ويرفض الـ registry استدعاءً أُجهض سلفًا قبل متن المنتج؛ ويتحقق وقتُ التشغيل من الملكية ومن توفّر متحكّم المهام قبل أن يبدأ `run()` العمل، ثم يوفّر المعرّفَ وسياجَ الجلسة وأدواتِ التحكم العامة والإشعاراتِ وتنظيفَ المالك. والفرعُ الخلفي الناجح يعيد مقبضًا معياريًا منمَّطًا مثل `{ kind: 'background', jobId }`؛ ويجوز لمصيّره الأصيل أن يحتفظ بنثر للإنسان مثل `started background job bash-1`، لكن يجب ألّا يحلّل وضعُ PTC ذلك النثر أبدًا لاستخراج المعرّف.

ويوفّر المنتجُ `cancel` تزامنيًا، و`done` لا يُرفَض ويستقر بعد تنظيف الموارد، و`readOutput` اختياريًا يستهلك بتنسيق خرج محدود. والاستدعاءُ المجهَض سلفًا عطلٌ لأن لا مهمة يوجد معرّفها ليستوفي schema الخرج الناجح. وبمجرد أن ينشر `ctx.jobs.start()` المعرّفَ، استعمل إشارةَ إلغاء تملكها المهمة لا `exec.signal`: فإلغاءُ الاستدعاء الخارجي لاحقًا يوقف الانتظار لكنه لا يقتل عملًا منشورًا؛ ويملك ذلك العمرَ `job_kill` وتحريرُ المالك وتفكيكُ الخدمة. ويبقى عملُ المقدمة مقترنًا بـ `exec.signal`. انظر [Agent Note عن وقت تشغيل المهام الخلفية](../../.agents/notes/implemented/architecture/2026-06-20-generic-long-running-tool-runtime.ar.md) و`dsh-tool-bash` لمثال منتج تدفق.

## سياسة التنفيذ والمراقبة

فضّل ألّا تبني سياسةَ النشر داخل الأداة. استعمل `tools/pre-execute` لسياسة السماح والمنع والسؤال القابلة للتوسعة ([مثال بوابة الأذونات](extension-cookbook.ar.md#a-hook-plugin-permission-gate-example))، و`ctx.tools.guard()` لمنع نهائي رتيب لا يستطيع المستمعون اللاحقون نقضه، و`tools/execute` للفّ التوزيع بمهلة أو إعادة محاولة أو جمع قياسات، و`tools/post-execute` لاستبدال محتوى العرض أو القيمة المعادة أو لحجب النتيجة أو لإلحاق سياق يراه النموذج، و`tools/result` لمراقبة النتيجة الموحَّدة غير القابلة للتغيير. واستبدالُ المحتوى يُبقي الوصول البرمجي إلى `value` سليمًا؛ أما سياسةُ السرية فتحجب القيمة أو تستبدلها. ويمكن أيضًا أن يعمل تنفيذُ العزل داخل منفّذ الأداة نفسه؛ ويعرّف [README الخاص بـ `dsh-tools`](../../packages/core/tools/README.ar.md#extension-points) مدخلاتِ كل نقطة امتداد وترتيبَها وقيمَها الراجعة وسلوكَها عند العطل.

## وضع PTC يبلغ أداتك بلا عناء

في [وضع PTC](../../packages/core/tools/README.ar.md)، تتاح كل أداة مسجَّلة ظاهرة بصيغة `await tools.<name>(args)` بلا تكامل إضافي. ويشتق `ToolArgsMap` و`ToolOutputMap` المولَّدان أنواعَ الوسائط والقيم المعيارية الراجعة بعينها من schemas نفسها، وتعود الاستدعاءاتُ إلى خط التنفيذ المعتاد. والاستدعاءُ الناجح يتحلّل إلى قيمة JSON المعيارية النهائية بعد السياسة، لا إلى محتوى أصيل مصيَّر. والاستدعاءُ الفاشل يُرفَض بـ `ToolCallError` الحقيقي؛ ولا تستطيع البرامجُ فحصَ غير `name` و`toolName` و`message` المقروء للإنسان، لا رموزِ الأخطاء الداخلية ولا اتحادِ الأعطال.

وصمّم `output.schema` واجهةً برمجية نافعة: أعِد المقابض والحقول مباشرةً، واسمح بجذور مفردة أو مصفوفات أو null حين تكون هي القيمةَ الصادقة، وأبقِ الشرحَ للإنسان في `output.render`. والقيمُ الوسيطة محلية للتنفيذ، ولا تُحفظ ولا تُقتطع في التوجيه، ولا سقفَ بايتات لها، فتظل حدودُ الاكتساب الصادقة عند المنتج وذاكرةُ العملية مهمّة. ولا يعبر سقفَ الخرج القابل للضبط وخطَّ الانسكاب الموجَّه إلى النموذج إلا سجلاتُ `run_code` الخارجية ونتيجتُها.

## كيف تُصيَّر أداتك في الواجهة

يعيد `output.render` الخاص بأداتك محتوًى موجَّهًا إلى النموذج؛ أما **بطاقتها في الواجهة** فشأنٌ منفصل يُعلَن عبر إسقاطات عرض خالصة وطريقتَي `presentCall` و`presentResult` الاختياريتين. فصمّمها مع القيمة المعيارية. والأداةُ التي لا عرضَ لها في الواجهة ترجع إلى بطاقة عامة (العنوان اسمُ الأداة، والوسائطُ الخام مدخلًا).

وتعيد الطريقتان **نيةَ تصيير موسومة بـ `card`**؛ فاختر نوع البطاقة الذي يطابق ما تفعله أداتك:

- `presentCall(args)` يعيد `ToolCallView` (البطاقةَ المعلَّقة):
  - `{ card: 'generic', title, kind?, rawInput?, content?, locations? }` وهي الافتراضية. اضبط `kind` لأيقونة (`read` أو `search` أو غيرهما)؛ واضبط `locations: [{ path, line? }]` لكل ملف تلمسه أداتك، ليتابع محرّرٌ قادر معك أو يقفز إليه.
  - `{ card: 'terminal', title, description?, cwd? }` حين يكون استدعاؤك أمرَ shell. فـ `title` هو الأمر، و`description` يُصيَّر فوق بطاقة الطرفية. (كما في tool-bash.)
  - `{ card: 'diff', title, diffs, locations? }` حين ينشئ استدعاؤك ملفًّا أو يعدّله. و`diffs: [{ path, oldText, newText }]` (بـ `oldText: null` للملف الجديد) تُصيَّر بطاقةَ فروق سطرية. (كما في `write` و`edit` في tool-fs.)
- و`presentResult(args, { content, isError, meta? })` يعيد البطاقة المكتملة:
  - `generic` يوفّر عنوانًا اختياريًا ومحتوًى.
  - `terminal` يوفّر الخرجَ الخام وبياناتِ خروج اختيارية؛ وتصيّر كل واجهة عرضَها القادر أو البديل.
  - `diff` يوفّر القطعَ المطبَّقة، ويشتقها غالبًا `output.presentationMeta` وتُحمل في `result.meta` المحفوظة لتعيد إعادةُ التشغيل إنتاجَها. وتُبقي أدواتُ التغيير نتيجةَ diff لأن العرضَ المكتمل يحل محل البطاقة المعلَّقة.
  - `read` يوفّر نافذةَ ملف مكتملة معادَ بناؤها من `result.meta` المحفوظة: مسارُ الملف `path`، وإزاحةٌ `offset` تبدأ من 1، والأسطرُ `lines` المعادة (ويحتفظ كلٌّ منها برقم سطره في الملف)، و`totalLines`، وتلميحُ إبراز `lang` اختياري؛ والواجهةُ التي لا تملك قدرة `read` ترجع إلى محتوى النتيجة الخام. ولا عرضَ استدعاء لـ `read`، فحالةُ استدعاء القراءة المعلَّقة تبقى بطاقةً عامة، لأن المحتوى لا يوجد إلا بعد `execute`. (كما في `read` في tool-fs.)
  - `search` يوفّر نتيجةَ اكتشاف معادَ بناؤها من `result.meta` المحفوظة: تطابقاتٌ مجمَّعة بالملف (`shape: 'matches'` في grep) أو قائمةُ مسارات مسطّحة (`shape: 'paths'` في glob)، مع `truncated` و`total` حتى لا تعرض واجهةٌ نتيجةً مقصوصة بوصفها كاملة. ولا يحمل العرضُ نصَّ نتيجة (فالواجهةُ التي لا بطاقةَ بحث لها ترجع إلى محتوى النتيجة الخام)، ولا عرضَ استدعاء لـ `search`، فحالةُ استدعاء الاكتشاف المعلَّقة تبقى بطاقةً عامة، لأن التطابقات لا توجد إلا بعد `execute`. (كما في `grep` و`glob` في tool-fs-search.)
  - `web` يوفّر جلبَ ويب مكتملًا، يميّزه `kind: 'search' | 'fetch'` (مصادرُ البحث المبنيَنة أو ملخصُ الجلب)، مشتقًّا من `result.meta`؛ وهو لا يحمل نصَّ المتن، فالواجهةُ التي لا تملك قدرة `web` ترجع إلى محتوى النتيجة الخام. (كما في `web_search` و`web_fetch` في tool-web.)

وقواعد صارمة تلدغ إن خولفت:

- **النقاء.** فهذه تعمل في البث الحي **وفي إعادة تشغيل سجل الجلسة**، فيجب أن تكون دوالَّ خالصة من `args` (ومن النتيجة): بلا إدخال وإخراج، وبلا قراءة حالة الجلسة، وبلا ساعة ولا عشوائية. وفروقُ diff تُشتق من الوسائط (فـ `write` يستعمل `oldText: null` لأن مصيّرًا وقتَ الاستدعاء لا محتوى ملف سابقًا عنده)؛ ويوفّر مهايئُ الواجهة سياقَ الجلسة لا الأداة. وإن وجدتَ نفسك تريد المحتوى القديم للملف أو دليلَ العمل داخل `presentCall`، فتوقّف: فذلك يخص بياناتِ النتيجة الدائمة أو المهايئ، لا المصيّر.
- **التنسيق الخاص بالواجهة يبقى خارج نتيجة النموذج.** فسورُ ` ```console `، وفرقُ diff، والمسارُ المنسوب: لا شيء منها ينتمي إلى القيمة المعيارية ولا إلى المحتوى الأصيل لمجرد خدمة واجهة. ويملك `output.render` النثرَ الموجَّه إلى النموذج؛ ويملك `presentationMeta` مع مصيّري البطاقات حالةَ الواجهة القابلة لإعادة التشغيل. وعرضُ نتيجة `terminal` يحمل الخرجَ الخام ويضيف المهايئُ أي إطار بديل.
- **`defineTool` يتحقق من مسار العرض تحققًا ليّنًا.** فالوسائطُ المشوَّهة أو المسجَّلة بصيغة أقدم تجعل اللافَّ يعيد `undefined` (بديلًا عامًّا) بدل أن يرمي، فلا يجوز أن يُسقِط العرضُ إعادةَ تشغيل أبدًا.

وتسكن المفرداتُ المحايدة في `dsh-tools`؛ ولا تستورد الأدواتُ نوعَ واجهة ولا نوعَ نقل أبدًا. ويربط مستهلكو هذه الواجهة كلَّ `card` بعرضهم هم. والتصميمُ وسببُه في [Agent Note عن اتحاد نيات التصيير](../../.agents/notes/implemented/architecture/2026-07-02-tool-render-intent-union.ar.md)؛ و`dsh-tool-fs` (generic وdiff) و`dsh-tool-bash` (terminal) هما التنفيذان المرجعيان.

## العرض في عميل Web

لا يستهلك عميلُ Web المدمج `presentCall` ولا `presentResult`. فـ `page` و`follow` في الجلسة ينقلان أحداثَ `tool/call` و`tool/result` خامًّا، بما فيها `result.meta` المحفوظة. وتسجّل إضافةُ Client اسمَ أداتها على السلك في الفتحة المفهرسة `tool.call.toolview`، وتشتق خصائصَ المكوّن من وسائط `ToolCallBlock` ومحتواه وخطئه وبياناته الوصفية و`parentCallId` القائم لتوزيع PTC ووقائعِ مسارات الجلسة. وهي تتحقق من قيم السلك هذه محليًّا وتعيد الصفَّ العام عند مدخل مشوَّه أو غير مدعوم.

واستعمل `output.presentationMeta(args, value)` حين تحتاج بطاقةُ Web قائمة وقائعَ نتيجة مبنيَنة محدودة لا يستطيع المحتوى الموجَّه إلى النموذج حفظَها بلا فقد. ولا تخزّن خصائصَ React ولا بطاقةً مختارة في البيانات الوصفية، ولا تستورد تنفيذَ أداة Host إلى حزمة متصفح، ولا تنشئ registry مصيّرين آخر في Client. وتعريفُ طرق عرض Host وحده لا يضيف بطاقةَ Web متخصصة. ويعرّف [Agent Note عن العرض المشتق في Client](../../.agents/notes/implemented/architecture/2026-08-23-client-derived-tool-presentation.ar.md) الملكيةَ والرجوعَ واشتراطاتِ التكافؤ.
