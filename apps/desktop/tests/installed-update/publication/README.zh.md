# اختبار تحديث فوق نقل و إصدار

[English](README.md) | العربية

## ملخص

فوق نقل اثنان عدد قد تحقق إصدار بينما لا عام نشر إصدار 2، انتظار عملية من بدء قد تثبيت إصدار 1 بعد عندئذ إصدار إصدار 2 ثابت feed. افتراضي أمر فحص محلي شيء مادة، لا قراءة اعتماد أو ربط شبكة. فعلي COS كتابة حاجة آخر سطر نيل نيل شخص عمل تخويل و تحقق.

## قبل رفع شرط

إتمام[عرض تدريب إشارة جنوب](../README.zh.md) في اثنان عدد تثبيت حزمة تحقق. إبقاء عبر `verification/check-*/result.json` عودة تنفيذ و لم تعديل شيء مادة. إصدار أداة سوف عودة تنفيذ و حالي تثبيت حزمة،blockmap،feed و بيان بايت إعادة نواة مقابل. هو أبدا توقيع أو تثبيت أي ملف.

قائم `.env.windows` تحميل جهاز توفير `DSH_DESKTOP_AUTO_UPDATE_ENV=test`،`DOWNLOAD_TEST_ORIGIN=https://download-test.deepseek.com`،`DOWNLOAD_TEST_COS_BUCKET=bj-toc-download-test-1320056602` و `DOWNLOAD_TEST_COS_SECRET_ID` / `DOWNLOAD_TEST_COS_SECRET_KEY`. فقط لديه هذا اثنان عدد فوق نقل سري سري دخول COS عميل؛ أبدا وضع دخول أمر أو سجل. نقل تنفيذ سوف طلب حد في test تخزين دلو و مستقل Windows تحقق استلام مسار داخل.

اثنان دخول صنع فوق نقل عملية مقدار خارج استعلام تخزين دلو إصدار تحكم؛ استعلام نجاح كما حيث غير تفعيل أيضا غير مؤقت توقف حالة قبل، هو رفض كتابة.feed إصدار إعادة استخدام نجاح اثنان دخول صنع فوق نقل عودة تنفيذ، لا تكرار استعلام دلو إعداد أو تحت تحميل تثبيت حزمة.COS وثيقة شرح [`x-cos-forbid-overwrite`](https://cloud.tencent.cn/document/product/436/7749) لا يمكن حفظ حماية فتح بدء إصدار تحكم تخزين دلو في كائن. استعلام يتم رفض فقط معنى طعم حال هذا إعداد لم معرفة، لا يستطيع إثبات فوق نقل يتم رفض.

كل آلة جهاز فقط استخدام واحد إصدار من. محلي `publication.lock` ترتيب حذف مشترك شيء مادة دليل إعادة تراكم عملية، لا حد أخرى آلة جهاز. إصدار 2 إصدار في استبدال قبل فحص قائم إصدار 1 feed؛ هذا قراءة و كتابة لا هو أصل فرعي مقارنة مقارنة و تسليم تبديل عملية. أخرى إصدار من لا نيل تزامن كتابة نفس عدد feed.

## شخص عمل عملية ترتيب

التالي هو انتظار شخص عمل تنفيذ خطوة، لا هو قد إتمام بعيد طرف تحقق استلام. في مستودع أصل دليل استخدام إبقاء بيان، دقيق تأكيد إصدار و مطابقة تحقق حزمة عودة تنفيذ تنفيذ. لا إضافة `--execute` وقت، اثنان عدد أمر كل فقط ضرب طبع محلي حساب تخطيط، لا إرسال طلب:

```powershell
node --import tsx apps/desktop/scripts/publish-installed-update.ts upload-binaries "<run.json>" "<version>" "<verification/result.json>"
node --import tsx apps/desktop/scripts/publish-installed-update.ts publish-feed "<run.json>" "<version>" "<verification/result.json>"
```

1. أولا في محلي فحص اثنان عدد إصدار. كل مرة مفرد وحيد تخويل فوق نقل بعد، إعطاء `upload-binaries` إضافة فوق `--execute`، في تفاعل طرفية إدخال `UPLOAD <version> <run-id>`. فوق نقل تثبيت حزمة و blockmap أبدا إصدار feed. قد وجود كما مطابقة اثنان دخول صنع فقط عودة قراءة، لا تغطية؛ بايت لا رمز قيام أي إيقاف.
2. إبقاء ثابت feed لا وجود. تثبيت إصدار 1 و عبر تثبيت بعد سريع سريع طريقة بدء، تأكيد عرض إصدار و سجل في `workspace-ready`. تخويل أي feed كتابة قبل، أولا إتمام عرض تدريب إشارة جنوب في 404 مشهد. إبقاء إصدار 1 تشغيل.
3. إعطاء إصدار 1 `publish-feed` إضافة فوق `--execute`، إدخال `PUBLISH <version> <run-id>` تخويل إصدار. ذلك اثنان دخول صنع يجب قد وجود و عبر عام شبكة عودة قراءة. ابتدائي feed يجب لا وجود، أو يتضمن تماما متسق إصدار 1 بايت. كامل عودة قراءة feed بعد، في ما زال تشغيل إصدار 1 تطبيق داخل إتمام نفس إصدار مشهد؛ إبقاء دليل، آخر سطر تخويل بعد عندئذ إصدار إصدار 2.
4. استخدام تحت وصف أمر و ذلك دقيق تأكيد تأكيد تخويل إصدار 2 إصدار. توفير أصل تثبيت تطبيق `dsh-update-qualification/<run-id>/journals` دليل. اشتراط بدء دليل و رمز دمج مسبق مدة قديم feed. عملية من مستقل نواة مقابل تثبيت مسار و إصدار 1 ما زال في تشغيل.

```powershell
node --import tsx apps/desktop/scripts/publish-installed-update.ts publish-feed "<run.json>" "<version-2>" "<version-2-verification/result.json>" --journals "<journal-directory>" --execute
```

إصدار و عام شبكة عودة قراءة نجاح بعد، عندئذ متابعة عرض تدريب إشارة جنوب. أداة استخدام ثابت عام شبكة URL، لا إضافة كسر ذاكرة مؤقتة معامل، فوق نقل وقت ضبط `Cache-Control: no-store`، و تحقق إرجاع بايت و ها أمل. اثنان دخول صنع فوق نقل إبقاء كامل عام شبكة عودة قراءة.feed إصدار فقط في بعيد طرف قراءة feed، اشتراط هذا دفعة مرة `publication-records/operation-*` تحت وجود نجاح `upload-binaries` نتيجة، كما ذلك محلي حساب تخطيط تماما مطابقة؛ عودة تنفيذ ناقص، فشل أو لا مطابقة وقت إيقاف إصدار. إصدار نتيجة سجل إعادة استخدام عودة تنفيذ مسار و عودة تنفيذ/حساب تخطيط ها أمل. هذا إثبات هذا قبل توزيع نجاح، لا إثبات غير ممكن تغيير كائن حمل متابعة متاح؛ لا نيل حذف أو استبدال هذه كائن.SDK كتابة لا يوجد تلقائي إعادة محاولة.

## دليل و استعادة

كل مرة عملية إبقاء `publication-records/operation-*`: حساب تخطيط، حمل ختم الوقت مرحلة مقطع، نهائي نتيجة، و ملائم استخدام وقت feed أصل نص. سجل يتضمن يمكن أمان إبقاء طلب ID و متاح HTTP حالة، لا يحتوي أصلي SDK خطأ أو إقرار إثبات رأس. فشل أي إيقاف لاحق كتابة؛ مهلة لا يستطيع إثبات خادم رفض هذا قبل كتابة. إبقاء سجل و بعيد طرف كائن، فحص الأكثر بعد مرحلة مقطع و حقيقي بعيد طرف حالة، آخر سطر تأكيد بعد عندئذ تنفيذ تحت مرة عملية.

حسب دقيق تأكيد API تشخيص `403 AccessDenied`:`GetBucketVersioning`،`GetObject` و `PutObject` حاجة مختلف إذن. اشتراط توسيع حق أو تعديل CDN إعداد قبل، أولا مقابل وفق إبقاء نجاح سجل، و استخدام حالي اعتماد فحص فشل عملية. لا يوجد محاولة تجربة فوق نقل وقت، لا يستطيع يأخذ إضافة جديدة إعداد استعلام فشل تقرير إبلاغ لـ فوق نقل فشل. قراءة نجاح أيضا لا يستطيع إثبات حالي كتابة إذن؛ أولوية مراجعة فحص لا لا بد يلزم إضافة جديدة قبل وضع فحص، بينما لا هو توسيع كبير الأكثر صغير إذن فوق نقل هوية تخويل.

شخص عمل طلب لاحق عملية تحقق قد مطابقة كائن، لا إعادة كتابة هو جمع.`alreadyPublished: true` يمثل نواة مقابل قد وجود هدف feed، لا هو مرة جديد إصدار؛ إصدار وقت استخدام أصل عملية دليل. غير مسبق مدة feed بايت سوف جعل عملية إيقاف، يشمل محاولة تجربة استخدام إصدار 1 استبدال إصدار 2. انهيار انهيار ممكن إبقاء تحت `publication.lock`؛ تأكيد لا يوجد إصدار من تشغيل و إبقاء فشل سجل بعد، عندئذ من عملية من إزالة هذا عدد دقيق تأكيد فارغ دليل. أبدا لـ التفاف مرور نشط وثب إصدار من بينما حذف قفل.

qualification COS إصدار استعلام مجموع قطع توقف وقت لـ 30 ثانية، كائن قراءة و PUT مجموع قطع توقف وقت لـ 15 قسم ساعة. إلى مدة سوف في توقف قاع طبقة HTTP طلب، و في تحرير عملية قفل قبل انتظار طلب إغلاق؛ حمل متابعة نقل لن تأخير طويل وقت حد.

## ملاحظة تطوير

ترتيب اختبار استخدام داخل تخزين تخزين بديل ذات؛ نقل اختبار استخدام بديل HTTP معالج تنفيذ حقيقي SDK تسلسل تحويل. اثنان من متساو لا يستطيع إثبات COS كتابة قد تحقق استلام.2026-09-14، حالي اعتماد قراءة إبقاء test استكشاف إبرة إرجاع HTTP 200 كما SHA-512 مطابقة، بينما `GetBucketVersioning` إرجاع 403؛ لا يوجد محاولة تجربة PUT. آخر مرة 2026-09-11 استكشاف إبرة قد تحقق test فوق نقل، ثابت feed تحديث جديد و updater تحت تحميل.TODO: في لا تقليل ضعيف نطاق الأسماء عزل، كامل صفة فحص و فشل أي توقف قبل رفع تحت مراجعة فحص مقدار خارج دلو إعداد قبل وضع شرط؛ هذا مرة وثيقة تصحيح صحيح و لم تنفيذ إزالة هذا شرط.

مع بعد مرور عملية من تخويل دفعة مرة `installed-update-r5dYNH` في `.desktop-build/qualification/` تحت إبقاء `object-overwrite-probe/result.json` و `binary-upload/result.json`. جديد بناء 49 بايت اختبار كائن نجاح؛ مجددا مرة يحمل منع توقف تغطية معامل PUT نفسه بايت وقت إرجاع `409 FileAlreadyExists`، مصدر محطة و عام شبكة ها أمل إبقاء ثابت. حد تحديد هذا دفعة مرة صاف اثنان دخول صنع قيادة مع بعد استخدام نفسه طلب رأس فوق نقل اثنان عدد توقيع تثبيت حزمة و ذلك blockmap، إعادة نواة مقابل تحقق حزمة عودة تنفيذ، و تحقق الكل أربعة عدد كامل عام شبكة استجابة. سجل يتضمن أربعة مرة نجاح جديد كائن PUT، لا يوجد إعادة محاولة،feed أو إعداد كتابة، استكشاف إبرة إبقاء إبقاء. مقابل مستقل feed URL HEAD مراقبة قياس إرجاع 404. هذا مرة شخص عمل عملية بـ مراقبة قياس إلى كائن درجة منع تغطية سلوك بديل دلو إعداد استعلام؛ فوق جهة عام CLI قبل وضع شرط لم تعديل. هذه عودة تنفيذ إثبات اختبار كائن قد توزيع، لا إثبات feed إصدار، تثبيت بعد بدء أو قد تثبيت إصدار ترقية.
