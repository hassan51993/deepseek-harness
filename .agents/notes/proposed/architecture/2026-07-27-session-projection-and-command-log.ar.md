# Agent Note: جلسة إسقاط و أمر دورة الحياة سجل سجل

Status: proposed

[English](2026-07-27-session-projection-and-command-log.md) | العربية

## مشكلة

ثلاثة عدد في طريق web وظيفة——todo(#497) ،goal(#527) ،plan mode(#587)——كل يلزم من جلسة سجل دفع توجيه حسب جلسة حالة و عرض إلى متصفح عميل، بينما ثلاثة من كل منها إرسال واضح واحد طقم نفس مثال آلية:

- **عميل نواة قلب صنف امتصاص استلام كل واحد مجال.** ثلاثة من كل نحو عميل وقت التشغيل `Session` صنف داخل إضافة خاص حقل، سحب أخذ تحرير ترتيب و حدث switch فرع، و مرور `ConversationSnapshot` إلقاء خروج كل منها قيمة. فقط plan واحد بيت حينئذ إضافة سبعة عدد خاص حقل و ثلاثة طبقة شبكة شريط (طلب إصدار، حدث إصدار، الأكثر جديد نشط قيمة ذاكرة مؤقتة) ؛goal إضافة كتابة revision شبكة شريط خارج إضافة واحد دمج صيغة إعادة أخذ حلقة؛todo إضافة واحد إسقاط (projection) حقل و واحد بند حدث case فرع. مجددا قدوم رقم أربعة عدد مجال، حينئذ يلزم رقم أربعة مرة تعديل نواة قلب صنف.
- **ثلاثة بند أساس خط عبر طريق.** todo تركيب في تاريخ ذيل صفحة `todos` حقل فوق——من **api-proxy داخلي** `backscanTodos` حساب حساب، عمل خدمة طي (fold) منطق إرسال إقامة في تحميل جسم داخل؛plan إضافة واحد مخصص استخدام `session.planMode` واحد عنصر RPC؛goal إضافة `goals.get`. نفس عدد مشكلة، ثلاثة نوع بروتوكول صيغة (wire format).
- **أمر نتيجة غير ممكن استعادة.** `/goal`،`/plan` و ذلك بقية كل مائل عمود أمر كل فقط في `command.execute` RPC استجابة داخل إرجاع نتيجة، بـ واحد بند تحويل لحظة أي زوال composer إشعار عرض في إرسال بدء أمر وسم صفحة فوق. جلسة سجل داخل ماذا أيضا إبقاء لا تحت: تحديث جديد، آخر فتح وسم صفحة، استعادة أو fork كل سوف فقد إسقاط «هذا أمر سبق مرور تشغيل مرور» سجل. مجال*حالة*تغيير هو حمل دائم (goal إيداع `goal/change` بيانات وصفية،plan إيداع `plan/mode`) ، لكن أمر استدعاء ذاته و ذلك ربط نقاش لا هو.

قاع طبقة نقص فتحة هو هيكل بنية صفة: عميل لا يوجد واحد seam يجعل إضافة في جلسة scope داخل مراقبة جلسة حدث و صيانة ذاتي ذات إرسال توليد حالة؛host جانب أيضا لا يوجد موحد واحد طريقة يأخذ سجل إرسال توليد حالة حالي قيمة تسليم إعطاء عميل——بينما هذا حالة تاريخ ممكن قد يتم قسم صفحة ضغط خروج عميل نافذة خارج.

## رفع سجل

أولا قيام أربعة عنصر أساس أساس ضبط تطبيق، بعد كل مجال كل تراجع تحويل لـ صاف مساهمة جهة.

### كل كمية قيمة حدث قاعدة

يحمل حالة سجل حدث يجب يحمل تغيير بعد كامل حالة، أبدا يحمل عار زيادة كمية. ثلاثة عدد مجال الآن حالة قد لكن دمج قاعدة:`todo/write` هو كامل جدول لقطة،`plan/mode` هو واحد كامل قيمة منطقية،`goal/change` بيانات وصفية هو كامل `GoalSnapshot`(أو واحد كل كمية قيمة صاف حذف قبر نصب). هذا قاعدة يجعل كل مجال حالة تحويل نقل بداية نهاية كاف كاف نزيه قيمة (إطار هيكل تدريجي حدث قيادة هو) ، يجعل قيمة في بروتوكول طبقة ذاتي وصف، و يجعل أي مستهلك كل يمكن يأخذ الأكثر قريب دفع إرسال قيمة عند عمل نهائي قيمة——اعتماد seq مقارنة مقارنة نيل نيل فوضى ترتيب تجنب وباء، كما ذاتي شفاء: تسرب إسقاط تحديث سوف يتم تحت مرة تحديث تصحيح صحيح.

### host جانب إسقاط سجل التسجيل (`dsh-session-projection`، جديد حزمة)

واحد خفيف كمية Service Definition حزمة:merge-extensible host حالة و عميل عرض نوع جدول، سجل التسجيل خدمة، و إبرة مقابل حمل دائم حالة و عميل قيمة zod تحقق. قدرة seam زاوية لون مثل تحت: مجال host إضافة توفير إسقاط وحدة، تحميل جسم إزالة استهلاك هذه وحدة، اثنان جانب متبادل لا متبادل تعرف.

مجال تسجيل هو واحد**حالة قيادة حساب حساب وحدة (state-driven computation unit)**——صاف طي، إذا جاف إعلان و اختياري عميل عرض——أبدا هو واحد لا نفاذ واضح getter. قيادة هو هو إطار هيكل مسؤولية (حجز قراءة، ماء موضع خط (watermark) ، ذاكرة مؤقتة، و لاحق فحص نقطة آلية) ، مجال فقط مسؤول حساب حساب. إسقاط خدمة في كل عمل خدمة مجال (جلسة عنوان،plan،goal، إذن،todos) ؛ أمر فقط هو منها واحد بند إطلاق مسار، في هذا اتفاق في لا يوجد أي خاص خاص أرض موضع.

```ts ignore-check
export interface SessionProjectionStateMap {} // host fold states
export interface SessionProjectionMap {}      // client-visible whole values

export interface ProjectionDefinition<K extends keyof SessionProjectionStateMap, S> {
  key: K
  stateSchema: ZodType<S>
  persist?: boolean // host-only units opt in; client-visible units always persist
  /** State for the empty log. */
  init(): S
  /** Pure transition: previous state + one event → next state. The framework drives it; domains hold no subscriptions. */
  apply(state: S, event: SessionEvent): S
  /** Client view; omitted for host-only units. */
  wire?: K extends keyof SessionProjectionMap ? {
    viewSchema: ZodType<SessionProjectionMap[K]>
    view(state: S): SessionProjectionMap[K]
  } : never
  /** State must be plain JSON (persisted-cache precondition); bump to invalidate persisted rows. */
  stateVersion: number
}

declare module 'cordis' {
  interface Context { sessionProjections: SessionProjectionRegistry }
}
```

- `SessionProjectionStateMap` وصف host طي حالة؛`SessionProjectionMap` متابعة بصفة بروتوكول كتلة و React خطاف مرور `import type` مشترك وحيد عميل DTO جدول. وحدة حذف `wire` أي إبقاء host-only. عميل قيمة مثل أي*تصيير*هو slot جسم نظام أمر، دائم بعيد لا عودة إسقاط طبقة إدارة. حالة/عرض تفكيك قسم رؤية[قد تنفيذ حالة و عميل عرض سجل](../../archived/architecture/2026-08-19-session-projection-state-and-client-views.md).
- **host هو إسقاط وحيد حساب حساب أرض نقطة.** إطار هيكل رئيسي حركة قيادة (eager drive) كل قد تسجيل وحدة: كل قد إيداع جلسة حدث كل مرور مرور `apply`؛ مقابل بعض حدث لا شعور نهوض اهتمام وحدة إرجاع نفس عدد حالة مرجع، بينما مرجع لم تغيير (`Object.is`) حينئذ لا إنتاج أي تحت تنقل عمل. عميل من لا طي مجال حدث——هو جمع استلام إلى هو صار صنف قيمة (أساس خط كتلة + تحت نص دفع إرسال لقطة). هذا إزالة حذف مزدوج إعادة تنفيذ وقوع فخ (plan مزدوج حدث طي فقط في host كتابة واحد مرة) ، أيضا إزالة حذف واحد قطع عميل جانب مجال شفرة.
- **حالة دائم بعيد اعتماد حساب حساب نيل خروج، أبدا دخول سجل.** سجل فقط تخزين حدث؛ وحدة حالة إقامة في إطار هيكل حسب جلسة ماء موضع خط ذاكرة مؤقتة داخل (كل وحدة واحد نسخة `{state, observedSeq}`) ، و في لاحق مرحلة مقطع دخول domain-KV تخزين seam فوق**حمل دائم إسقاط ذاكرة مؤقتة (persisted projection cache)**: شكل مثل `(sessionId, key, ver, seq, val)` سطر (`ver` = وحدة `stateVersion`،`seq` = ماء موضع خط،`val` = حالة JSON). واحد سطر دائم بعيد لن هو خطأ، حتى كثير هو قديم قديم——ذلك `seq` دقيق شرح قديم قديم إلى أي. بارد قراءة و نشط قراءة مشترك استخدام نفس طقم قراءة إعداد جهة: أخذ ذاكرة مؤقتة حالة (أو `init()`) ، فقط مقابل تجاوز خروج ذلك ماء موضع خط حدث فعل صحيح نحو `apply`، مجددا مقابل نتيجة فعل `view`. بارد قائمة (عبر الكل workspace صف خروج كل جلسة عنوان) تغيير صار مرة بحث جذب قراءة، حتى كثير خارج إضافة واحد صغير مقطع ذيل جزء إعادة تشغيل؛session-persistence seam في نفس لاحق مرحلة مقطع لـ هذا مقطع ذيل جزء تكملة واحد حسب seq بدء قراءة أصل لغة. كتابة سياسة: عقدة تدفق (مرة عدد/بين فصل، يمكن إعداد) خارج إضافة اثنان عدد قوي صنع نقطة——`turn/end` و detach(من نشط تحويل بارد وقت لحظة). اثنان مرة كتابة بين انهيار انهيار بديل قيمة هو ذيل جزء إعادة تشغيل أكثر طويل واحد بعض، أبدا سوف هو قيمة خروج خطأ.
- مجال إدخال حدث تجميع من مجال ذاتي ذات اختيار:todos فقط طي `todo/write`؛plan طي `plan/mode` خارج إضافة هو ذاتي ذات `/plan` `command/run` سجل (رؤية plan واحد عقدة) ؛goal طي `goal/change` بيانات وصفية؛ جلسة عنوان طي ذلك عنوان حدث (ترتيب حمل تحت خط مخصص ضبط `session/title` لقطة و عميل عنوان لقطة جدول——هذا هو هذا seam استلام تحرير رقم أربعة عدد يد عمل إسقاط).
- تسجيل هو effect(disposer مع fiber مشي): إضافة إزالة بعد ذلك key من لاحق استجابة في إزالة فقد، عميل سوف ذلك قراءة عمل قدرة ناقص——HMR(حار وحدة استبدال) دلالة مع لـ تلقائي صار قيام.key تكرار مباشر throw. مجال إضافة في `ctx.inject(['sessionProjections'], …)` تحت تسجيل، لذلك لا حمل سجل التسجيل headless تجميع تماما لا تلقي أثر.
- هذا حزمة يملك `./invariant`(كل يتم خدمة key كل لديه واحد بند تخزين نشط تسجيل).

### قد تسليم مستهلك:subagent هوية وحدة

سجل التسجيل اثنان موضع قائم قراءة قاعدة قد خدمة في هذا RFC بروتوكول خطة خارج واحد قد تسليم مستهلك:[subagent قائمة مرور إسقاط وحدة قراءة هوية](../../archived/architecture/2026-08-06-subagent-list-identity-projection.md) تسجيل `subagent` وحدة——من `subagent/descriptor` حسب last-wins طي خروج حفظ دائم mode/label هوية——`SubagentRuntime.listChildren` مقابل live child مرور `snapshot()` قراءة (ماء موضع ذاكرة مؤقتة، صفر سجل قراءة) ، مقابل cold child فإن استخدام مرة حفظ دائم كامل قراءة نتيجة استدعاء `restore({}, events, 0)` قراءة. سجل التسجيل اتفاق ثابت: لا يوجد فشل عبر طريق، لا يوجد جديد قراءة قاعدة——وحدة دائم لا رمي خطأ، قيمة نقص مقعد ذاته حينئذ هو إشارة، نقص مقعد مثل أي عرض هو هذا مستهلك ذاتي ذات قرار.

### بروتوكول طبقة: تاريخ ذيل صفحة فوق projections كتلة

```ts ignore-check
// session.history response, tail page only (beforeSeq absent):
{ events, hasMore,
  projections?: { asOfSeq: number, values: Partial<SessionProjectionMap> } }
```

api-proxy تاريخ معالج قطع خروج ذيل صفحة بعد تزامن مرة تاريخ سجل التسجيل——كل مسار لا يوجد واحد `await`، لذلك كل key قيمة و `asOfSeq` بنية صار نفس عدد متسق قطع وجه.`asOfSeq` هو**الأكثر بعد واحد حدث seq**(`session.seq - 1`؛ فارغ سجل لـ `-1`، و `session/subscribed.lastSeq` نفس طقم مفردات) ، لذلك يحمل أساس خط بعد أول عدد تغيير دفع إرسال لقطة في مقارنة مقارنة وقت ثابت صارم إطار أكثر كبير.api-proxy لا يحتفظ أي مجال معرفة تعرف (و `viewFor` موجه إلى `ctx.tools` هو نفس نوع تحميل جسم/مساهمة جهة علاقة).

لا إضافة جديدة RPC طريقة. وقت آلة فوق إعادة دمج هو دقيق: عميل كل واحد حاجة جديد أساس خط وقت لحظة (فتح، إعادة وصل إعادة تزامن، نقص فتحة إصلاح تكملة) هذا قدوم حينئذ يلزم سحب ذيل صفحة، بينما وحيد دائم بعيد لا حاجة أساس خط مسار (loadOlder) تماما جيد هو وحيد نقل `beforeSeq` مسار. لذلك عميل**تماما لا يوجد**مستقل «إعادة أخذ أساس خط» قرار. نافذة محتوى من لا ملء عند إشارة:«نافذة داخل لا يوجد هذا مجال حدث» هذا عدد مشكلة في نافذة داخل من بنية صنع فوق حينئذ لا يمكن عودة جواب، فقط لديه أساس خط قدرة عودة جواب هو.

مع هذا كتلة تحت خط قديم عبر طريق:`session.planMode` و `setPlanMode`(قراءة كتابة اثنان جانب——plan اختيار تعديل مشي معيار أمر عبر طريق، رؤية plan واحد عقدة) ،`goals.get`(قراءة جانب؛ ستة عدد تغيير RPC إبقاء، لكن ذلك استجابة لم يعد تغذية حالة——mux حدث عكس صحيح سوف إلى) ،`todos` تركيب تحميل حقل، و api-proxy داخل `backscanTodos`(نقل دخول todo مجال وحدة، سقوط في `tool-todo`).

### دفع إرسال لقطة و عميل قيمة مستودع (مجال صفر عميل شفرة)

حيث لكن host هو وحيد حساب حساب أرض نقطة، صار صنف قيمة مرور واحد جديد mux لقطة إرسال بلوغ عميل:

```ts ignore-check
// MuxFrame union + schema branch:
{ type: 'session/projection', sessionId, key: string, value: unknown, seq: number }
```

فقط يلزم بعض وحدة حالة مرجع حدوث تغير (فوق نص `Object.is` بوابة باب) ، إطار هيكل حينئذ إرسال خروج هذا لقطة؛`seq` هو إرسال خروج وقت هذا وحدة ماء موضع خط. هذا هو فوري دفع إرسال حالة، أبدا دخول سجل——و tool-view `view` slot نفس وضع حالة: إعادة تشغيل وقت في host إعادة حساب حساب.

عميل كائن طبقة لـ كل جلسة صيانة واحد**عام قيمة مستودع (value store)**:`key → { value, seq }`، من ذيل صفحة projections كتلة بث نوع، من هذا لقطة تحديث، وحيد قاعدة هو **seq عال من فوز**. إعادة وضع أساس خط لا يمكن يأخذ تحديث لقطة نحو تراجع؛ فقد فقد واحد لقطة بديل قيمة فقط هو قديم قديم——إلى تحت واحد لقطة أو أساس خط لـ توقف——أبدا سوف خروج خطأ. لا يوجد `fromEvent`، لا يوجد حسب مجال cell تسجيل، لا يوجد عميل جانب مجال طي——مجال تسليم إسقاط دعم حمل فقط يحتاج**صفر عميل شفرة**(`SessionProjectionMap` merge مرور `/types` خروج فتحة معا خدمة اثنان جانب). مخصص ضبط `session/title` لقطة و manager عنوان لقطة جدول كل استلام تحرير دخول هذا مقابل عام آلية. كل حسب مجال ذاتي صنع شبكة شريط (#587 ثلاثة طبقة،#527 كتابة revision) كل إزالة دمج دخول هذا واحد بند seq قاعدة.

### plan مشي معيار أمر عبر طريق (كامل عرض مثال)

plan mode كامل عرض عرض هذا طقم نمط——إطلاق مسار، تشغيل وجه، إعادة تشغيل وجه، ثلاثة من جاف صاف قسم مغادرة:

- **إطلاق مسار**:web plan فتح صلة مثل أي أخرى أمر واحد مثال مرور `command.execute` إرسال `/plan` / `/plan off`؛ مخصص ضبط `setPlanMode`/`planMode` RPC تحت خط. مستخدم*طلب*يتم حمل دائم سجل لـ هذا أمر `command/run { name: 'plan', args: 'off' | '' }`——بنية تحويل حقل، بلا حاجة تحليل سطر نص.
- **تشغيل وجه**(ثابت):plan-mode خدمة في داخل تخزين داخل إبقاء انتظار تحديد معنى رسم، و في تحت واحد جولة حد سقوط تحت `plan/mode`. بارد بدء وقت خدمة من إعادة تشغيل وجه إعادة بناء ذلك معنى رسم طابور صف («تشغيل حالة لـ فارغ أي بـ إعادة تشغيل حالة لـ دقيق»).
- **إعادة تشغيل وجه**:plan إسقاط وحدة طي**اثنان**نوع حدث——هو ذاتي ذات `command/run` سجل ضبط `wanted`؛`plan/mode` ضبط `active` و صاف حذف `wanted`؛`view` دفع تصدير `{ active, pending: wanted !== null && wanted !== active }`. انتظار تحديد حالة من هذا يصبح صاف إعادة تشغيل كمية:host إعادة بدء قدرة استعادة هو، أخرى وسم صفحة طي نفس مثال حدث (عبر وسم صفحة انتظار تحديد حالة مع لـ تلقائي نيل نيل) ، بارد قراءة عودة جواب `{ active: false, pending: true }` أيضا هو دقيق تأكيد («واحد لم صرف الآن اختيار صحيح انتظار استعادة»).

مجال إدخال حدث تجميع من مجال ذاتي ذات اختيار——هذا عرض مثال سقوط فعلي صحيح هو هذا بند واحد عام قاعدة.«مستخدم طلب مرور X» هو ظهور في إسقاط داخل (plan طي ذاتي ذات أمر سجل) ، أيضا هو فقط ظهور في flow داخل (أمر عقدة عكس صحيح سوف تصيير) ، يخص كل مجال ذاتي ذات دلالة، دائم بعيد لا هو إطار هيكل صلة قطع.

### React:`useProjection`، رقم خمسة عدد إطار هيكل خطاف مقعد موضع

قائم أربعة عدد مقعد موضع كل تركيب لا تحت هذا نسخة حالة (store سجل قاعدة منع توقف عمل خدمة كائن؛inject منع توقف خطاف؛`ConversationSnapshot` جارٍ يتم صاف تراجع).`useProjection` يصبح واحد إطار هيكل مقعد موضع، في ui-renderer(وحيد خطاف صب صنع نقطة) صب صنع، مرور و `useSession` نفسه معيار طقم عنصر عبر طريق (`provideInfo` → SessionProvider → props) إرسال بلوغ:

```ts ignore-check
type UseProjection = {
  <K extends keyof SessionProjectionMap>(key: K): SessionProjectionMap[K] | undefined
  <K extends keyof SessionProjectionMap, S>(
    key: K, selector: (v: SessionProjectionMap[K] | undefined) => S,
    eq?: (a: S, b: S) => boolean): S
}
```

`undefined` موحد واحد يمثل قدرة ناقص (host إضافة لم تركيب، أو بعد بلا أي أساس خط/لقطة يحمل مرور هذا key). قيمة مستودع فقط كشف حسب key عار `{subscribe, getSnapshot}` وجه؛ ذلك بقية تسليم إعطاء حمل تدريجي key ذاكرة مؤقتة `bindSnapshotSelector`——مرجع مستقر صفة صار قيام، لأن واحد key قيمة مرجع فقط في لقطة أو أساس خط سقوط أرض وقت عندئذ تغير. كتابة مسار ثابت: تغيير عودة ضبط إبقاء في inject مشترك وجه (عودة ضبط خروج ذاتي inject، نشط حالة خروج ذاتي `useProjection`).

«خطاف لا نيل اختراق مرور inject» وحيد قائم مخالفة مثال——`DetailsInjected.useSelection`——مع هذا تغيير واحد و استلام تحرير: اختيار في حالة هو إقامة في حديث يوم store داخل عرض حالة، لذلك details تسجيل إعلان مشترك store جملة مقبض، مكون تعديل قراءة `props.useStore(s => s.selection)`؛`useSelection` خروج inject اتفاق.

### سجل في أمر دورة الحياة

اثنان عدد فقط سجل (غير surface، نموذج غير ممكن رؤية) حدث، مرآة مثل `tool/call`/`tool/result` إعداد مقابل:

```ts ignore-check
'command/run':  { commandId: string; name: string; args?: string; source: CommandSource }
'command/done': { commandId: string; kind: 'success' | 'error'; text?: string }
```

host جانب أمر منفذ (`packages/interaction/commands`) في استدعاء معالج قبل إلحاق `command/run`، في تسوية وقت إلحاق `command/done`——في استقبال agent(ذكي جسم) جلسة فوق مباشر مستقل إلحاق، و[دمج صار جولة إزالة](../../implemented/simplification/2026-07-28-remove-synthetic-log-only-turns.ar.md) بعد كل إضافة ذاتي لديه log-only حدث نفس شكل حالة: لا يوجد جولة حزمة لف هو جمع (جولة فقط وصف نموذج حلقة تنفيذ) ، حفظ دائم في معتاد قاعدة فحص نقطة ترتيب فارغ هو جمع،run/done إعداد مقابل من commands حزمة ذاتي ذات invariant مرافق توليد إضافة يأخذ حراسة. تحميل حمل هو بنية تحويل——`name` و افتراضي يحمل `args` قدوم ذاتي محلل ذاتي ذات قطع قسم (`parseCommand` name و rawInput) ، لذلك مستهلك (طي ذاتي ذات أمر سجل إسقاط وحدة، غني أمر بطاقة) دائم بعيد بلا حاجة إعادة تحليل سطر نص. عند تحميل حمل من مرجعي مجال حدث يحتفظ وقت، أمر تعريف سوف ضبط `recordInput: false`؛ هذا وقت `command/run` حذف `args`، بينما لا هو تكرار هذا تحميل حمل.`text` هو معالج أصل مثال نتيجة——و `tool/result.content` نفس صفة جودة واقع بيانات، لا هو عرض (إصدار صيغة مثل أي تحرير ترتيب ما زال من عميل في تصيير وقت حساب حساب، ممتلئ كاف «عرض دائم لا دخول سجل» هذا بند أحمر خط). تفكير يجعل نموذج معرفة طريق نتيجة مجال إبقاء قائم سلوك (plan جانب أبيض،goal حقن)——ذلك هو مجال ذاتي ذات قرار، إبقاء ثابت.

من في قد إيداع حدث سوف في mux تدفق فوق واسع بث، تحديث جديد بعد ما زال في، كثير وسم صفحة تزامن،fork/استعادة بعد يمكن أيضا أصل هذا ثلاثة عنصر أمر مع لـ الكل تلقائي نيل نيل.`command.execute` RPC تراجع تحويل لـ دقيق دخول حكم تحديد——`{ matched, commandId? }`: هذا سطر هل مطابقة أمر في، و أمر في وقت جديد صب إعداد مقابل id، إرسال بدء أمر عميل حسب هذا يأخذ ذاتي ذات طلب و دورة الحياة حدث إنتاج خروج flow عقدة صلة ربط بدء قدوم. مرة صفة إشعار عبر طريق (`runDetached` → `noticeFor`) حينئذ هذا تحت خط.

عميل flow بناء جهاز إضافة جديدة واحد عام أمر عقدة (run/done حسب `commandId` إعداد مقابل؛ عبر نافذة مقتطع وقت و أداة إعداد مقابل نفس مثال لين تخفيض). تصيير مشي واحد جديد keyed slot `'conversation.chat.commandview'`،key = أمر اسم،**التقاط قاع = عام أمر بطاقة**(صفر تسجيل يكفي استخدام——من قبل إشعار نص الآن حمل دائم أرض تصيير في flow داخل). مجال يلزم ترقية عرض، فقط يحتاج تسجيل واحد سطر مكون، أخذ مادة في `command/run` بنية تحويل حقل و ذاتي ذات إسقاط قيمة (`useProjection`)——و toolview حل تفرق بعد أداة سطر نفس شكل حالة.

## تسليم خطة

أساس أساس ضبط تطبيق أولا سطر؛ ثلاثة عدد في طريق PR(Pull Request) أصل مثال لا حركة، انتظار أساس مقعد سقوط أرض بعد إعادة مقابل وصل (هو جمع ترحيل خريطة أي إشارة جنوب):

1. **host أساس مقعد**:`dsh-session-projection`(وحدة اتفاق، رئيسي حركة قيادة، ماء موضع خط ذاكرة مؤقتة)+ api-proxy projections كتلة + `session/projection` دفع إرسال لقطة. صفر مجال تسجيل أيضا يمكن دمج دخول (هذا وقت كتلة و لقطة مباشر نقص مقعد).
2. **عميل أساس مقعد**: عام قيمة مستودع + `useProjection` مقعد موضع؛ تحت خط حسب مجال cell آلية، و في عنوان وحدة تسجيل بعد واحد و تحت خط `session/title` لقطة و عنوان لقطة جدول. لقطة شكل حالة اعتماد 1(في هذا قبل fixture(اختبار قبل وضع بيانات) تغذية دمج صار لقطة).
3. **أمر عبر طريق**: اثنان عدد حدث، منفذ سقوط سجل، عام عقدة + keyed slot، إشعار عبر طريق تحت خط،`{matched, commandId?}` دقيق دخول. و 1 و سطر.
4. **مجال إعادة مقابل وصل**(في 1+2 بعد): أولا todo(وحدة دخول `tool-todo`، حذف إسقاط تركيب تحميل حقل) ، مجددا plan(مزدوج حدث وحدة،RPC تحت خط، فتح صلة تعديل إرسال `/plan`) ، الأكثر بعد goal(`goal/change` وحدة، حذف إسقاط `goals.get`، يأخذ ستة عدد `Session` طريقة نقل دخول مجال إضافة inject).
5. **حمل دائم إسقاط ذاكرة مؤقتة**(لاحق مرحلة مقطع، انتظار domain-KV تخزين seam حينئذ خيط بعد):`(sessionId, key, ver, seq, val)` سطر، حمل turn/end و detach قوي صنع نقطة عقدة تدفق كتابة، و حفظ دائم جانب توفير بارد ذيل جزء إعادة تشغيل استخدام حسب seq بدء قراءة أصل لغة.

## تجهيز اختيار خطة

**مخصص ضبط واحد `session.projections` RPC**——غير مقبول: أساس خط تحديث جديد وقت لحظة و ذيل صفحة سحب أخذ دقيق إعادة دمج، مفرد وحيد واحد عنصر RPC فقط سوف تبديل قدوم ثاني مرة نحو إرجاع، ثاني عدد انتظار ضبط و seq، و واحد عميل «أي وقت إعادة أخذ» قرار——بينما تركيب تحميل تصميم يأخذ هذا عدد قرار كامل حذف إسقاط.

**لا نفاذ واضح `get(agent)` مزود اتفاق**——مرفوض: حساب حساب نموذج إخفاء في مجال داخلي وقت، إطار هيكل دائم بعيد لا يمكن لـ حالة فعل فحص نقطة، لا يمكن خدمة بارد جلسة (لا يوجد agent، لا يوجد قد تحميل سجل——`get` بلا موضع يمكن ركض) ، أيضا لا يمكن من سجل في مقطع متابعة حساب. تسجيل `(init, apply, view)` وحدة يأخذ قيادة حق تسليم إعطاء إطار هيكل، مجال فقط إبقاء صاف عدد تعلم؛ لديه host جانب سلوك يحتاج طلب مجال، ذلك خدمة حجز قراءة وفق قديم ذاتي حمل، و إسقاط وحدة متبادل لا جر وصل.

**لـ plan انتظار تحديد معنى رسم مخصص ضبط فقط فوري تراكم إضافة خطاف (`live?(agent, base)`)**——غير مقبول: هو وجود وحيد إدارة من هو مستخدم plan *اختيار*لا في سجل داخل. يجعل اختيار مشي معيار أمر عبر طريق بعد،`command/run` فوق حساب، انتظار تحديد حالة يصبح صاف إعادة تشغيل كمية، إسقاط متابعة من صاف طي و اختياري عميل عرض بنية صار.

**يأخذ تسجيل API تسمية لـ `registerFold`**——قد يتم وحدة اتفاق يحل محل: تسجيل كائن مثل اليوم تأكيد فعلي هو واحد طي، لكن هذا مستودع داخل `fold*` مخصص إشارة صاف `(events) => state` مساعد مساعدة دالة، بينما هذا سجل التسجيل استقبال هو حمل key، حمل schema، حمل إصدار وحدة. إسقاط ما زال هو حدث تتبع مصدر في إشارة تسمية قراءة نموذج زاوية لون فن لغة،#587 Note عنوان و #497 تقييم نقاش أيضا كل قد في استخدام هو.

**عميل جانب طي (حمل `fromEvent` حسب مجال إسقاط cell)**——مرفوض: واحد حالما plan وحدة يلزم طي اثنان نوع حدث، عميل cell حينئذ يجب في متصفح داخل تكرار لحظة host حالة تحويل نقل منطق——نفس عدد طي كتابة اثنان مرة، كل منها عرض تحويل. دفع إرسال صار صنف قيمة (عنوان لقطة أولا مثال عام تحويل) حفظ إقامة وحيد حساب حساب أرض نقطة، و يأخذ عميل بسيط تحويل لـ واحد من seq يأخذ حراسة عام قيمة مستودع؛ مجال صفر عميل شفرة.

**مقابل سجل ذيل جزء محدود عكس نحو مسح (absorber إعلان).**غير مقبول: قائم تنفيذ متساو لا دعم حمل هو، هو فقط خدمة في «كل حدث كل يحمل كامل طي حالة» مجال، بينما حمل دائم إسقاط ذاكرة مؤقتة بـ موحد واحد طريقة تغطية نفس بارد قراءة يحتاج طلب (ذاكرة مؤقتة سطر إضافة صحيح نحو ذيل جزء إعادة تشغيل——و عميل أساس خط و تتبع لحاق، و قسم صفحة تحميل هو نفس طقم إعداد جهة). فقط لديه عند ظهور فحص نقطة آلية خدمة لا حقيقي بارد قراءة مسار وقت عندئذ إعادة اقتراح.

**`invalidate` صيغة cell(علامة قذر، لقاء مجال حدث حينئذ إعادة أخذ)**——غير مقبول: هو وجود فقط لـ ترصد انتظار زيادة كمية حدث. كل كمية قيمة قاعدة يجعل كل مجال كل هو last-wins؛goal إعادة أخذ حلقة، دمج منطق، قديم قديم قراءة شبكة شريط مع لـ الكل إزالة فقد.

**يأخذ سجل التسجيل تعليق إلى `ctx.apiProxy` اسم تحت**——غير مقبول: جلسة إسقاط و غير web مخصص تابع (TUI،ACP(Agent Client Protocol) ،headless كل هو لم قدوم مستهلك) ، كما مجال حزمة لا نيل اعتماد apiproxy حزمة. مستقل seam أيضا ترتيب حمل حذف إسقاط #587 من api-proxy إشارة نحو plan حزمة type-only استيراد حافة.

**ثاني ورقة عميل DTO نوع جدول**——غير مقبول:`SessionProjectionMap` ما زال هو بروتوكول و UI مشترك وحيد عميل مفردات.`SessionProjectionStateMap` لا هو آخر ورقة عميل عرض جدول؛ هو وصف host طي حالة، جعل داخلي حالة يمكن مختلف في إرسال نحو عميل قيمة.

**استخدام حدث واسع بث استلام تجميع، بديل سجل التسجيل مرة تاريخ**——غير مقبول: مختلف خطوة مستمع إعطاء لا خروج ذلك عدد مفرد واحد تزامن قطع وجه، بينما صحيح هو هو يجعل `asOfSeq` يصبح أفقي عبر كل key متسق لقطة؛ سجل التسجيل عندئذ هو هذا مستودع تحمل وصل مساهمة عبر سطر شكل حالة (`ctx.tools`، نص التوجيه قطعة مقطع،slot).

**مخصص ضبط `plan/select` اختيار حدث (استخدام بنية تحويل مجال حدث بديل طي أمر سجل)**——غير مقبول، تعديل استخدام أمر عبر طريق:`command/run` بنية تحويل `{name, args}` قد سجل اختيار،`/plan` لغة قاعدة و ذلك طي منطق نفس إقامة واحد إضافة (مجال داخل اقتران دمج، غير عبر مجال) ، أيضا قليل واحد نوع حدث نوع. معالج يجب في أي ممكن فشل مسار قبل استدعاء `set()`، جعل قد دخول سجل طلب و تشغيل وجه غير ممكن قدرة قسم تقاطع——هذا هو مجال داخلي ترتيب قيد، وثيقة كتابة في معالج موضع.

**إبقاء `setPlanMode` مخصص استخدام RPC**——غير مقبول:plan اختيار حينئذ هو واحد بند عادي مستخدم أمر؛ أمر عبر طريق إعطاء هو حمل دائم سجل،flow تصيير، كثير وسم صفحة مرئي صفة و دقيق دخول دلالة، لا حاجة مخصص ضبط بروتوكول طريقة.Web UI تفاعل مكون (واحد فتح صلة) في داخلي تجميع خروج أمر سطر يكفي.

**يجعل تغيير RPC استجابة تغذية cell حالة**——غير مقبول: قد إيداع mux حدث أي لحظة وصول، يحمل نفس عدد كل كمية قيمة خارج إضافة seq؛ «استجابة تغذية حالة» صحيح هو عند أول إجبار خروج #527 كتابة revision شبكة شريط أصل مصدر.

## تحقق استلام معيار

- مجال إضافة يأخذ حسب جلسة سجل إرسال توليد حالة إرسال بلوغ React، فقط يحتاج كتابة: كل كمية قيمة حدث إعلان، مرة host جانب وحدة `register`، ذاتي ذات ذلك نسخة `SessionProjectionMap` merge، و inject عودة ضبط——صفر عميل جانب شفرة، لا تعديل عميل `Session` صنف،`ConversationSnapshot`،api-proxy أو أي بروتوكول schema ملف.
- تاريخ ذيل صفحة يحمل `projections`، ذلك `asOfSeq` انتظار في نافذة ذيل جزء seq؛loadOlder صفحة دائم لا يحمل؛ لم تركيب سجل التسجيل نشر وفق معتاد إرجاع لا حمل هذا كتلة تاريخ، عميل يأخذ كل key نظر لـ نقص مقعد.
- قديم قديم أساس خط لا يستطيع تغطية تحديث `session/projection` لقطة، إعادة وضع لقطة أيضا لا يستطيع يجعل قيمة مستودع قلب تراجع (اثنان بند مسار كل فعل seq عال من فوز اختبار).
- في واحد وسم صفحة تنفيذ مائل عمود أمر، تحديث جديد بعد، في ثاني عدد وسم صفحة فوق، استعادة بعد كل في flow في تصيير خروج حمل دائم عقدة؛ لم تسجيل أمر تصيير عام بطاقة؛ أمر نتيجة composer إشعار مسار تام قاع إزالة.
- `useProjection` مرور معيار props طقم عنصر مقاومة بلوغ مكون؛ لا يوجد أي خطاف اختراق مرور inject اتفاق (يشمل `useSelection`).
- جلسة عنوان تركيب ركوب هذا مقابل عام آلية (أساس خط كتلة + إسقاط لقطة) ؛ مخصص ضبط `session/title` لقطة و عميل عنوان لقطة جدول تام قاع إزالة.

## ريح خطر

- **كل كمية قيمة قاعدة هو تحمل إعادة بنية**: لم قدوم بعض عدد مجال إذا فقط تسجيل عار زيادة كمية، حينئذ لا يمكن سند ذلك الأكثر جديد حدث خدمة مستهلك، أيضا سوف يجعل ذاتي ذات وحدة تكرار مختلط تحويل. مؤقت حل: هذا قاعدة كتابة واضح في هذا Note و إسقاط حزمة README داخل؛ وحدة اتفاق يجعل كامل حالة في كل مرة تحويل نقل موضع كل هو صريح.
- **وحدة تزامن سجل قاعدة**:`init`/`apply`/`view` واحد حالما await حينئذ سوف تمزيق شق متسق صفة قطع وجه. سجل التسجيل في وثيقة في تقديم واضح هذا بند سجل قاعدة،invariant إعداد طقم في يمكن سطر نطاق داخل تأكيد تزامن صفة؛ ذلك بقية من مراجعة يأخذ صلة.
- **سجل التسجيل فوري زيادة حذف لا فعل دفع إرسال**: جلسة في طريق تحميل أو إزالة مجال إضافة سوف تغيير مفتاح تجميع، لكن لن إطلاق أي جلسة حدث، أيضا لن دفع أي لقطة؛ فتح حال عميل يحتفظ قديم قديم key مباشر إلى تحت مرة ذيل صفحة سحب أخذ (إعادة وصل، نقص فتحة إصلاح تكملة، فتح). قبول لـ فقط تطوير مدة (HMR) قديم قديم وقت نافذة——يوم بعد يمكن في تغيير تدفق فوق إضافة واحد سجل التسجيل تغيير دفع إرسال، اتفاق لا تلقي أثر.
- **مشغول مشغول جلسة فوق رئيسي حركة قيادة فتح إلغاء**: كل قد إيداع حدث كل يلزم مرور كل قد تسجيل وحدة `apply`. حسب بنية صنع، وحدة تدريجي حدث فتح إلغاء جدا منخفض (كل كمية قيمة قاعدة) ، لا مطابقة حدث إرجاع نفس مرجع، كما قد تسجيل مجال عدد كمية جدا صغير؛ إذا حق ظهور حار نقطة مسار، يمكن إضافة حسب وحدة حدث نوع مسبق مرور ترشيح، اتفاق ثابت.
- **إسقاط تحميل حمل تمدد انتفاخ**: كل ذيل صفحة يحمل كل قد تسجيل key. تحميل حمل هو UI كمية درجة حالة كل كمية قيمة (واحد ورقة todo بيان، واحد نسخة goal لقطة) ؛ سوف قدوم إذا بعض مجال قيمة جدا كبير، يمكن في طلب فوق إضافة تدريجي key opt-out أو كسول صفة key، نموذج ذاته لا استخدام تعديل.
- **أمر سجل جسم كمية**: كل بند مائل عمود أمر اثنان عدد فقط سجل حدث؛ حد أعلى من شخص طرق أمر تردد معدل قرار، متبادل مقابل قسم قطعة جسم كمية يمكن تجاهل اختصار لا حساب.
- **إعادة مقابل وصل إرجاع عمل**: ثلاثة عدد لم دمج دخول PR يلزم تغيير أساس إلى نقل حركة بعد أرض أساس فوق. هذا هو أساس أساس ضبط تطبيق أولا سطر حيث تحديد بديل قيمة.
