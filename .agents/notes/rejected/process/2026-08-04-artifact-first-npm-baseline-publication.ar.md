# Agent Note: بـ ناتج لـ أولا NPM أساس خط إصدار

Status: rejected — superseded by 2026-08-10-npm-release-sequences: numbered versions and pack→protected publish shipped; timestamp versions were not adopted

[English](2026-08-04-artifact-first-npm-baseline-publication.md) | العربية

## مشكلة

monorepo في يمكن تشغيل شفرة المصدر و لا يستطيع إثبات إصدار بعد حزمة يمكن تشغيل.workspace link،TypeScript paths،tsx شفرة المصدر تحميل و عمل شجرة داخل ناقص إبقاء `lib/` كل ممكن تكملة فوق إصدار tarball في ناقص ملف أو اعتماد. أي جعل قائم بناء ناتج اختبار استخدام عادي Node، هو ما زال مباشر قراءة عمل شجرة في `lib/`، لا يوجد تحقق `package.json#files` نهائي اختيار في ماذا، أيضا لا يوجد تحقق حزمة إدارة جهاز تثبيت بعد ملف تخطيط. مرة تطوير نمط صحيح معتاد تنفيذ لذلك ممكن إصدار لـ نقص قليل bundle chunk، إعلان ملف، إعداد أو مورد حزمة.

إصدار كثير عدد متبادل متبادل اعتماد `@deepseek-ai` حزمة أيضا سوف إنتاج تجميع دمج متسق صفة مشكلة. إذا نص برمجي كل pack واحد حزمة حينئذ قيام أي publish، ذلك ما لاحق pack أو تحقق فشل وقت، سجل التسجيل في قد وجود لا يمكن بصفة كامل أساس خط استخدام قبل نصف مجموعة إصدار.npm سجل التسجيل لا يوجد عبر حزمة أمر خدمة، لذلك هذا داخل «مرة صفة إصدار» لا يستطيع تحمل وعد أصل فرعي إيداع، فقط قدرة تحمل وعد في أي بعيد طرف كتابة قبل كامل توليد و تحقق إصدار تجميع دمج، مجددا من واحد يمكن استعادة تحرير ترتيب أمر إصدار هذا عدد غير ممكن تغيير تجميع دمج.

حالي أساس خط أيضا حاجة شخص عمل في هذا آلة إتمام إصدار إرسال توليد، إقرار إثبات،pack، إصدار و إعادة محاولة. لاحق GitHub Actions سير العمل يجب إعادة استخدام نفس طقم إصدار حزمة و تحقق منطق، لا يستطيع في دفعة دقيق إصدار بعد إعادة بناء آخر مجموعة لم مرور مستهلك اختبار tarball.

## رفع سجل

إصدار مسار بـ واحد غير ممكن تغيير release bundle(إصدار حزمة تجميع دمج) لـ حد.pack مرحلة مقطع من واحد تحديد Git commit بناء الكل هدف حزمة، توليد الكل tarball، فحص tarball محتوى، و عبر تثبيت بعد اختبار تكامل؛publish مرحلة مقطع فقط قراءة هذا مجموعة tarball و ذلك manifest(بيانات وصفية بيان) ، منع توقف إعادة بناء أو إعادة pack.

هدف تجميع دمج فقط يتضمن `packages/*/*/package.json` و `apps/*/package.json` في تسمية لـ `@deepseek-ai/*` workspace حزمة. أصل مشروع،`website/`،vendor،Python و native workspace لا يخص هذا NPM أساس خط. اكتشاف آلية يجب رفض تكرار حزمة اسم، مختلف أساس أساس إصدار، معنى خارج `private` إصدار حالة و تجميع دمج في لم معرفة حزمة، بينما لا هو صيانة آخر نسخة يد عمل حزمة اسم قائمة.

مسبق إصدار إصدار من حزمة مستقر أساس أساس إصدار، أمر بدء وقت دقيق إلى ثانية UTC ختم الوقت و هدف commit 10 موضع قصير SHA مجموعة صار:`<base>-<YYYYMMDDHHmmss>-<short-commit>`.dist-tag من أساس أساس إصدار إرسال توليد لـ `dev-<base>`. مثال مثل، أساس أساس إصدار `0.0.1`، وقت `2026-08-04T00:32:00Z` و commit `909292dd7b` توليد إصدار `0.0.1-20260804003200-909292dd7b` و tag `dev-0.0.1`. نفس release bundle إعادة محاولة يجب امتداد استخدام أصل إصدار و manifest؛ إعادة pack سوف حسب جديد أمر بدء وقت توليد جديد إصدار.

pack مرحلة مقطع حسب التالي ترتيب تنفيذ:

1. سوف ref تحليل صار غير ممكن تغيير commit، أخذ تجميع UTC ختم الوقت، من هذا commit أصل manifest إرسال توليد إصدار، و عرض commit، ختم الوقت، إصدار،tag، سجل التسجيل و إخراج مسار.`pack` و `release` هذا وقت كل سوف في مرتفع ثمين عملية بدء قبل انتظار Enter؛ تلقائي تحويل متاح `--yes` قفز مرور هذا تأكيد.
2. في عزل detached worktree في تثبيت frozen lockfile، و في مؤقت تخزين قبل تشغيل شفرة المصدر manifest إصدار قيد؛ استدعاء جهة عمل شجرة في لم إيداع ملف و قديم بناء إخراج لا نيل مشاركة و إصدار.
3. سوف كل هدف manifest مؤقت تخزين لـ إرسال توليد إصدار، إزالة إصدار وقت `private` علامة، و يأخذ `dependencies`،`devDependencies`،`optionalDependencies` و `peerDependencies` في داخلي workspace اعتماد الكل تعديل كتابة لـ نفس دقيق إصدار.
4. كامل بناء هدف commit، مجددا تشغيل publint و قد بناء حزمة ثابت صيغة.
5. لـ هدف تجميع دمج في كل حزمة تنفيذ pack، لكن لا تنفيذ أي سجل التسجيل كتابة.
6. فحص tarball داخل package manifest، ملف بيان، داخلي اعتماد إصدار، حزمة اسم و إصدار، و رفض ناقص، تكرار أو مقدار خارج tarball.
7. توليد يتضمن commit، إصدار،tag، سجل التسجيل، كل حزمة tarball مسار،SHA-256 و npm integrity release manifest و تحقق و ملف.
8. من محلي tarball تثبيت واحد عزل مستهلك، تشغيل حالي تنفيذ قد لديه تثبيت حالة ناتج استكشاف قياس، و سوف هذه استكشاف قياس توسيع لـ تحت نص تعريف كامل ناتج مستو وجه اختبار تكامل مستطيل دفعة.
9. فقط عند كامل تجميع دمج عبر وقت إخراج واحد يمكن مباشر تنفيذ publish أمر؛pack أمر ذاته بداية نهاية إبقاء بلا بعيد طرف كتابة.

محلي `release` أمر تركيب pack و publish. هو أولا عبر فوق وصف pack تأكيد تحديد مسبق مدة ختم الوقت و إصدار، مجددا في pack نجاح بعد انتظار ثاني مرة Enter، مع بعد إصدار نفس manifest؛`release --yes` قفز مرور اثنان مرة تأكيد. مستقل `pack` و `publish --manifest` ما زال هو CI قسم job و قطع نقطة استعادة استخدام أساس أساس عملية.

## حالي تنفيذ حد

قد إيداع pack أمر تنفيذ ثابت commit مؤقت تخزين، داخلي اعتماد دقيق ثابت تحويل، ساكن حالة و tarball payload فحص، غير ممكن تغيير manifest، و يأخذ كل إصدار tarball كل بصفة محلي قمة طبقة اعتماد عزل npm تثبيت. هو في إخراج publish أمر قبل، استخدام عادي Node تشغيل تثبيت بعد `dsh --version` و `dsh --dump-default-config` مدخل، مجددا في POSIX PTY في بدء تثبيت بعد افتراضي TUI، انتظار ذلك `main-session-` حينئذ خيط إشارة، و عبر `/exit` خروج.Publish دعم حمل حسب integrity استعادة، سوف فقط قراءة سجل التسجيل تحقق و إقرار إثبات هوية فحص قسم مغادرة، و بـ كامل بعيد طرف integrity و dist-tag تحقق انتهاء.

PR(Pull Request) CI لن استدعاء pack أمر؛ تثبيت حالة مدخل استكشاف قياس يخص محلي إصدار فحص، بينما لا هو دمج بوابة. تجنب اعتماد CI تنفيذ، أخرى كل bin و عام وقت التشغيل مدخل حزمة ذاتي لديه استكشاف قياس،workflow artifact نقل تمرير و تلقي حفظ حماية publish job ما زال يخص رفع سجل نطاق.

## إصدار payload اتفاق

إصدار حزمة فقط يحمل مستهلك حاجة بناء ناتج.`package.json#files` منع توقف يتضمن `src` و `lib/types/**/*.d.ts.map`؛tarball محتوى بوابة أيضا يلزم مستقل تأكيد لا وجود أي `package/src/**` و `package/**/*.d.ts.map`، تجنب تجنب manifest pattern أو pack سلوك التفاف مرور ساكن حالة قيد. وقت التشغيل JS، إعلان ملف `.d.ts`، إعداد، مورد،worker ملف و bundle حركة حالة chunk يجب حسب فعلي مدخل إغلاق حزمة استلام متساو.

شفرة المصدر manifest يمكن إبقاء `exports["./src/*"]`، توفير هذا مستودع شفرة المصدر مستو وجه تحليل استخدام؛ هذا export لا بديل جدول شفرة المصدر سوف دخول إصدار payload، أيضا لا يخص قد إصدار حزمة مستهلك اتفاق. ساكن حالة بوابة يجب قسم آخر فحص شفرة المصدر مستو وجه و إصدار payload، لا يستطيع عبر حذف source export قدوم إخفاء غطاء خطأ workspace تحليل، أيضا لا يستطيع عبر إصدار `src` قدوم إصلاح تكملة ناقص بناء ناتج.

كل tarball يجب لا يحتوي `workspace:` specifier، و كما كل إشارة نحو هذا مرة إصدار تجميع دمج داخلي اعتماد و مقابل انتظار اعتماد (peer dependency) كل يجب دقيق انتظار في هذا مرة إرسال توليد إصدار، منع توقف استخدام `^`،`~` أو أخرى semver نطاق عبر تجاوز commit أساس خط. حذف واضح فقط توفير شفرة المصدر مستو وجه استخدام `exports["./src/*"]`،package manifest في إعلان كل مستهلك مدخل كل يجب إشارة نحو tarball داخل وجود ملف؛ حركة حالة import، وقت التشغيل تجميع وصل مسار و غير export مورد لا يستطيع فقط اعتماد manifest فحص، يجب من تثبيت بعد تنفيذ تغطية.

## ناتج مستو وجه اختبار تكامل

اختبار تكامل في الكل tarball توليد بعد، أي publish قبل تشغيل. هو في monorepo خارج إنشاء واحد كل جديد مؤقت مشروع، عبر هذا مرة release manifest في محلي `.tgz` ملف تثبيت إعلان اعتماد إغلاق حزمة، و من تثبيت دليل تنفيذ. اختبار يجب استخدام عادي Node و حزمة إدارة جهاز توليد `node_modules`؛ منع توقف tsx،tsconfig paths،workspace link، مستودع شفرة المصدر مسار، عمل شجرة `lib/` و قد إصدار سجل التسجيل في نفس إصدار حزمة مشاركة و تحليل. اختبار أيضا يلزم تأكيد صلة مفتاح وحدة و bin حقيقي مسار يقع في مؤقت مستهلك داخل.

تثبيت استخدام هذا مرة إصدار اختيار عميل سلوك. سجل التسجيل فوق نقل يجب استخدام `npm` CLI(أمر سطر واجهة) ، بـ ممتلئ كاف خاص سجل التسجيل فقط قبول npm عميل سياسة؛ بناء تحرير ترتيب ما زال يمكن استخدام pnpm.tarball اختبار لا نيل أولا يأخذ هذه حزمة إصدار إلى حقيقي سجل التسجيل، أيضا لا نيل في اختبار بعد إعادة pack.

اختبار حتى قليل تغطية التالي تنفيذ وجه:

- `@deepseek-ai/dsh` تثبيت بعد `dsh --version` و `dsh --dump-default-config` في عادي Node تحت نجاح، قسم آخر تغطية ساكن حالة CLI مدخل و واحد حركة حالة نمط مدخل.
- تثبيت بعد افتراضي `dsh` في PTY في إتمام مرة بلا مفتاح TUI بدء، وصول حيث تحديد ready إشارة بعد من اختبار تلقي تحكم خروج. هذا بند مسار يجب تحميل حقيقي TUI حركة حالة chunk، لذلك نقص قليل صنف يشبه `lib/tui-*.js` إصدار ملف سوف جعل بوابة فشل.
- كل أخرى قد إصدار `bin` كل تعريف واحد لن وصول حقيقي خدمة أو تعديل مستخدم حالة حزمة درجة خطر دخان أمر. مختلف CLI لا قوي صنع مشترك استخدام `--help`؛ اختبار يجب تشغيل ذلك حقيقي تثبيت مدخل و فحص اتفاق خروج أو ready إشارة.
- Node توافق عام وقت التشغيل مدخل من تثبيت دليل تحميل؛ متصفح،worker أو يجب من مضيف بروتوكول قيادة مدخل استخدام مقابل عزل fixture(اختبار قبل وضع بيانات) ، لكن إدخال ما زال فقط قدرة هو هذا مرة tarball.

هذه اختبار تحقق يمكن تنفيذ صفة، لا بديل اختبار وحدة، لقطة، حقيقي API e2e أو publint. اختبار fixture ينبغي إعادة استخدام قائم built-bin و PTY مشهد سلوك تأكيد، لكن يجب يأخذ مدخل تعديل لـ tarball تثبيت نتيجة؛ مباشر تشغيل عمل شجرة `lib/bin.js` اختبار لا يستطيع حساب عمل هذا بوابة.

## إصدار و استعادة

publish أمر أولا تحقق release manifest، كل محلي تحقق و، هدف سجل التسجيل،`npm ping` و `npm whoami`، مجددا حسب تحديد ترتيب فوق نقل tarball. أمر فقط قبول pack مرحلة مقطع توليد manifest، لا قبول workspace دليل بصفة إصدار إدخال. افتراضي سجل التسجيل لـ `https://registry.npm.harnessment.com/`، كل مرة publish كل صريح نقل دخول سجل التسجيل و إرسال توليد tag، تجنب تجنب مستخدم درجة `.npmrc` تغيير هدف.

npm لا توفير كثير حزمة أصل فرعي أمر خدمة، فوق نقل ما زال سوف تدريجي حزمة حدوث. تحرير ترتيب جهاز عبر قوة انتظار استعادة تقليص صغير فشل وجه: إذا بعيد طرف لا وجود `<name>@<version>` حينئذ فوق نقل؛ إذا قد وجود كما integrity و release manifest نفسه حينئذ قفز مرور؛ إذا قد وجود لكن محتوى مختلف حينئذ قيام أي فشل.dist-tag فحص فقط قراءة tag خريطة، لا تحليل افتراضي tag إشارة نحو إصدار، لذلك أي جعل غير متصل tag إشارة نحو إصدار قد لا وجود، أيضا لن منع قطع استعادة. إتمام بعد يجب تدريجي حزمة تأكيد إصدار integrity و dist-tag كل إشارة نحو هذا مرة إصدار، فقط لديه كامل تجميع دمج عبر نهائي تحقق، سير العمل عندئذ تقرير إبلاغ إصدار نجاح.

إذا pack،tarball فحص أو تثبيت بعد اختبار تكامل فشل، سجل التسجيل يجب إبقاء صفر كتابة. إذا publish في جزء فوق نقل بعد فشل، عملية من استخدام نفس release manifest إعادة ركض publish أمر قدوم استعادة، لا نيل إعادة pack و توليد آخر عدد ختم الوقت إصدار قدوم بديل بديل استعادة. إصلاح شفرة أو تغيير بناء إدخال بعد حاجة مختلف tarball وقت، عندئذ إعادة تنفيذ كامل pack و اختبار.

## GitHub Actions تجميع صار

GitHub Actions قسم لـ بلا اعتماد pack-and-test job و تلقي حفظ حماية publish job. قبل من فحص خروج دقيق commit، استدعاء و محلي نفسه pack مدخل، تشغيل tarball مستهلك اختبار، و فوق نقل كامل release bundle بصفة سير العمل ناتج. بعد من اعتماد قبل من نجاح، من سير العمل ناتج تحت تحميل bundle، إعادة تحقق manifest و تحقق و، مجددا استدعاء نفس عدد publish مدخل؛ هو لا يستطيع فحص خروج بعد إعادة بناء.

PR و عادي push يمكن تشغيل بلا اعتماد pack-and-test إشارة، من بينما في دمج قبل اكتشاف payload ارتداد. فعلي خاص سجل التسجيل إصدار أولا عبر `workflow_dispatch` توفير، إدخال فقط يشمل هدف ref؛UTC ختم الوقت من pack job توليد، أساس أساس إصدار، قصير SHA،tag، سجل التسجيل و حزمة بيان كل من مستودع حالة أو تلقي إصدار تحكم إعداد إرسال توليد. مستقر إصدار إطلاق طريقة لا في هذا أساس خط رفع سجل نطاق داخل.

سجل التسجيل token فقط حقن publish job، و من تلقي حفظ حماية GitHub Environment تحكم شخص عمل دفعة دقيق، سماح فرع أو tag و تزامن.pack-and-test job لا نيل قراءة إصدار اعتماد. سير العمل ناتج إبقاء مدة يمكن مقارنة قصير، لكن publish job يجب استخدام نفس workflow run توليد bundle، لا يستطيع حسب رقم الإصدار من لا تلقي معلومة مهمة موضع بحث بحث tarball.

## اعتبار مرور بديل خطة

**من workspace مباشر تمرير عودة publish.** لا اعتماد، لأن أمر سوف يأخذ pack و سجل التسجيل كتابة تسليم خطأ، لا يمكن في رقم مرة كتابة قبل إثبات كامل تجميع دمج كامل، أيضا سعة سهل يجعل workspace تحليل و استدعاء جهة عمل شجرة حالة أثر إصدار نتيجة.

**فقط اختبار عمل شجرة في بناء بعد `lib/`.** لا اعتماد، لأن هذا تحقق هو بناء شجرة، لا هو `package.json#files` اختيار خروج tarball. عمل شجرة في وجود بينما tarball في تسرب إسقاط حركة حالة chunk صحيح هو هذا رفع سجل يجب التقاط فشل.

**فقط تشغيل `dsh --help`.** لا اعتماد، لأن Commander يمكن في تحميل TUI،Web أو headless حركة حالة مدخل قبل إخراج مساعدة و خروج. هو لا يمكن إثبات افتراضي إنتاج بدء مسار كامل.

**يأخذ `src` و إعلان خريطة واحد بدء إصدار بـ خفض منخفض تسرب ملف ريح خطر.** لا اعتماد، لأن شفرة المصدر مستو وجه لا هو إنتاج وقت التشغيل بعد تجهيز مسار؛ توسيع كبير payload سوف إخفاء غطاء bundle إغلاق حزمة خطأ، و يأخذ محلي ضبط تجربة ناتج تغيير صار بلا معنى إصدار اتفاق.

**اشتراط حق صحيح عبر حزمة أصل فرعي إصدار.** لا اعتماد، لأن npm سجل التسجيل لا يوجد متبادل ينبغي أمر خدمة. غير ممكن تغيير release bundle، إصدار قبل كل كمية تحقق،integrity مقارنة مقابل و قوة انتظار استعادة توفير يمكن تنفيذ حد، معا واضح إبقاء جزء فوق نقل قصير مؤقت مرئي حد.

**في دفعة دقيق بعد من إصدار job إعادة بناء.** لا اعتماد، لأن اختبار عبر tarball و فعلي فوق نقل tarball سوف لم يعد أداة لديه محتوى هوية. سير العمل ناتج و تحقق و يجب يأخذ اختبار إدخال مباشر نقل إعطاء إصدار خطوة.

## تحقق استلام معيار

- واحد pack مدخل من تحديد commit اكتشاف `packages/*/*` و `apps/*` الكل هدف حزمة، بـ UTC ثانية درجة ختم الوقت و قصير commit توليد و عرض إصدار، مجددا انتظار Enter؛ هو في أي سجل التسجيل كتابة قبل توليد كامل release bundle، و إخراج واحد يمكن نسخ publish أمر؛`release` في pack بعد مجددا مرة انتظار،`--yes` قفز مرور اثنان مرة تأكيد.
- ساكن حالة manifest بوابة و tarball محتوى بوابة كل رفض إصدار `src` و `.d.ts.map`، معا إبقاء شفرة المصدر manifest في `exports["./src/*"]`.
- release bundle سجل كامل حزمة تجميع دمج،commit، إرسال توليد إصدار،tag، سجل التسجيل و تدريجي tarball integrity؛ كل داخلي اعتماد كل دقيق ثابت تحويل إلى هذا إصدار،publish فقط إزالة استهلاك هذا bundle، أبدا إعادة بناء.
- واحد عزل اختبار تكامل من محلي tarball تثبيت مستهلك، و استخدام عادي Node بدء تثبيت بعد افتراضي `dsh` TUI؛ حذف مهمة واحد الذي يحتاج حركة حالة chunk سوف جعل هذا اختبار مستقر فشل.
- كل قد إصدار bin و ملائم استخدام عام وقت التشغيل مدخل كل لديه tarball تثبيت بعد تنفيذ تغطية، كما تحليل مسار إثبات لا يوجد رجوع إلى monorepo.
- publish يمكن في جزء نجاح بعد استخدام نفس manifest أمان إعادة ركض؛ نفسه integrity يتم قفز مرور، مختلف integrity يتم رفض، نهائي تحقق اشتراط كل إصدار و tag متسق.
- GitHub Actions بلا اعتماد job توليد و اختبار bundle، تلقي حفظ حماية job فوق نقل تماما نفسه bundle، إصدار token فقط وجود في بعد من.

## ريح خطر

كل كمية pack، تثبيت و بدء سوف زيادة CI وقت و سير العمل ناتج جسم تراكم. تنفيذ ينبغي ذاكرة مؤقتة خارجي اعتماد و pnpm store، لكن لا نيل ذاكرة مؤقتة أو إعادة استخدام هدف حزمة قد تثبيت workspace إخراج؛ و سطر تنفيذ أمان مستهلك probe يمكن خفض منخفض وقت تأخير.

يأخذ كل tarball كل تثبيت لـ مؤقت مشروع قمة طبقة اعتماد ممكن إخفاء غطاء لم إعلان داخلي اعتماد. اختبار توليد جهاز ينبغي حسب يتم قياس تطبيق إعلان صيغة تمرير عودة إغلاق حزمة تثبيت، و ربط دمج قائم اعتماد بوابة؛ مقابل اعتماد وجه وصل قريب كل تجميع `@deepseek-ai/dsh`، ما زال يحتاج اعتماد اعتماد package manifest و ساكن حالة رسم فحص اكتشاف لم إعلان حافة.

مختلف منصة optional dependency،native addon،PTY و متصفح مدخل ممكن حاجة منصة مخصص تابع probe. رقم واحد مرحلة مقطع حتى قليل في إصدار الذي استخدام Linux runner و واحد محلي macOS مسار فوق تغطية رئيسي `dsh` بدء، لاحق مستطيل دفعة حسب فعلي إصدار منصة توسيع؛ لا يستطيع استخدام قفز مرور لا مستقر probe طريقة يأخذ إنتاج مسار نقل خروج بوابة.

استعادة آلية لا يستطيع إزالة حذف npm جزء مرئي صفة. إصدار فشل خلال، سجل التسجيل ممكن قصير مؤقت يحتوي لديه هذا مرة إصدار واحد جزء حزمة؛ عملية من و تلقائي تحويل يجب بـ نهائي bundle تحقق نتيجة بينما غير مفرد عدد `npm publish` نجاح بصفة أساس خط متاح إشارة.
