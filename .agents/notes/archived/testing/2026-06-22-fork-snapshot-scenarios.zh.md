# Agent Note: سجل fork و خلط دمج spawn+fork لقطة مشهد

Status: implemented
Archived: 2026-07-26

[English](2026-06-22-fork-snapshot-scenarios.md) | العربية

## مشكلة

[seed حد Agent Note(agent قرار سجل)](2026-06-22-fork-child-replay-seed-boundary.md) يجعل fork فرعي بند إعادة وضع قدرة كاف صحيح تأكيد توجيه:`dsh-llm-replay` أصل حسب حفظ دائم `seedLength` حد موضع و ذلك بعد حدث إرسال توليد فرعي بند نص برمجي، لذلك fork فرعي بند وراثة أب بادئة لن بصفة فرعي بند ذاته نموذج استدعاء إعادة وضع. لكن سقوط أرض وقت**لا يوجد سجل صيغة fork مشهد**——slice فقط من `llm-replay` اختبار وحدة (دمج صار فرعي بند fixture(اختبار قبل وضع بيانات)) و حفظ دائم نحو إرجاع اختبار تغطية. كامل transcript(نص سجل) لقطة طبقة——سوف بدء حقيقي `acp-agent` و إعادة وضع طرف إلى طرف تضمين طقم transcript ذلك ورقة شبكة——فقط لديه spawn فرعي بند (`subagent-spawn`،`subagent-multi`). إذا fork توجيه ارتداد لا يوجد يجعل اختبار وحدة تغيير أحمر، هو ما زال سوف هروب مرور مخصص لـ التقاط transcript ارتداد بينما بناء هذا واحد طبقة.

جدول بلوغ fork مشهد الذي يحتاج لقطة أساس أساس ضبط تطبيق قد حينئذ موضع: اثنان عدد عملية داخل خلفية كل في `cordis.yml` / `cordis.snapshot.yml` في بـ اثنان عدد موجه إلى نموذج أداة وصل دخول (`subagent` → spawn،`subagent_fork` → fork) ،harness سوف استلام تجميع كل فرعي جلسة سجل، إعادة تشغيل حسب `seedLength` لـ مفتاح تحويل إرسال كل فرعي جلسة fixture. نقص قليل هو واحد*قد سجل مشهد*قدوم قيادة fork فرعي جلسة مشي تمام هذا بند مسار.

## قرار

إبرة مقابل حقيقي API سجل اثنان عدد مشهد، متساو في افتراضي بوابة في بـ بلا مفتاح طريقة إعادة تشغيل:

- **`subagent-fork`**: أب جلسة إتمام واحد جولة بـ بناء قيام واحد واقع، لكن بعد عبر `subagent_fork` تفويض إرسال واحد فرعي مهمة.fork فرعي جلسة وراثة محادثة (ذلك سجل يحمل غير صفر `seedLength`) ، لذلك يمكن من أب جلسة سياق في عمل جواب. هذا هو تجمع تركيز ارتداد حراسة حماية: فرعي جلسة fixture `seedLength` حينئذ هو إعادة تشغيل قطع قطعة الذي اعتماد حد، قدوم ذاتي حقيقي fork سجل بينما غير يد عمل دمج صار.
- **`subagent-mixed`**——أب بند إتمام واحد جولة، مع بعد في نفس transcript في عبر `subagent` تفويض حمل مرة (كل جديد spawn فرعي بند،`seedLength` لـ 0) ، مجددا عبر `subagent_fork` تفويض حمل مرة (fork فرعي بند،`seedLength` غير صفر). هذا هو seed حد و تدريجي جلسة إعادة وضع Agent Note كل نقطة اسم بصفة لم قدوم إضافة جديدة بند spawn+fork خلط دمج مشهد: واحد نسخة transcript تغطية اثنان نوع نقل طريقة و slice اثنان عدد فرع (`seedLength` لـ 0 = بلا عملية،`seedLength > 0` = قطع قص وراثة بادئة) ، اثنان عدد فرعي بند حسب `createdAt` ترتيب صف لـ أولا spawn، بعد fork.

### لـ ماذا حاجة واحد قد إتمام رقم واحد جولة

fork خلفية استخدام أب بند**قد إعداد مستو كامل جولة بادئة**لـ فرعي بند توفير seed. أب بند إذا في رقم واحد جولة حينئذ تنفيذ fork، لا يوجد قد إتمام جولة يمكن توفير وراثة، لذلك seed لـ فارغ (≡ كل جديد spawn،`seedLength` لـ 0)——هذا لن تغطية slice. لذلك، اثنان عدد مشهد كل استخدام مزدوج نص التوجيه إدخال: رقم واحد نص التوجيه إتمام واحد جولة (بناء قيام قليلا بعد اشتراط فرعي بند عودة ذاكرة codeword) ، ثاني عدد نص التوجيه تفويض حمل fork. فرعي بند transcript في عودة ذاكرة خروج codeword فقط هو نموذج سلوك مرفق حمل نتيجة؛ تحمل تحميل صلة مفتاح قيد ناتج هو فرعي بند fixture في سجل، من إعادة وضع slice إزالة استهلاك `seedLength`.

## عاقبة

- fork توجيه قطع قطعة الآن من كل transcript طبقة حراسة حماية، بينما لا فقط فقط هو اختبار وحدة. إزالة `slice(seedLength)`(إعادة تشغيل كامل فرعي جلسة سجل) سوف يجعل**اثنان عدد**جديد مشهد تغيير أحمر——fork فرعي جلسة استلام إلى هو أب جلسة سجل قسم قطعة بينما غير ذاتي ذات——إثبات حراسة حماية تأكيد فعلي توليد فاعلية (مشهد سقوط أرض وقت قد تحقق أحمر→أخضر).
- `subagent-mixed` هو رقم واحد في نفس عدد transcript في قيادة اثنان نوع*مختلف* subagent خلفية لقطة مشهد، معا تغطية عبر spawn و fork فرعي جلسة تدريجي جلسة إعادة تشغيل مفتاح تحكم.
- عملية خارج (ACP(Agent Client Protocol))subagent إعادة تشغيل شكل مختلف (كل فرعي جلسة هو مستقل عملية، لديه ذاتي ذات إعادة تشغيل) ، ما زال بـ `TODO(acp-subagent-replay)` تتبع أثر——هذا نص مشهد فقط حد عملية داخل.
- إعادة تسجيل صنع (`pnpm run test:snapshot:record`) سوف من حقيقي API إعادة توليد الكل أربعة عدد fork/spawn fixture؛ اثنان عدد جديد مشهد في بلا مفتاح وقت تلقائي قفز مرور، و كل قد تسجيل صنع مشهد متسق.
