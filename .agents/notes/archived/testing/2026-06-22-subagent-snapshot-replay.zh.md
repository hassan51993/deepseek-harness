# Agent Note: تضمين طقم agent تدريجي جلسة لقطة إعادة تشغيل

Status: implemented
Archived: 2026-09-04

[English](2026-06-22-subagent-snapshot-replay.md) | العربية

## مشكلة

لقطة طبقة (`pnpm run test:snapshot`) سوف بدء حقيقي `acp-agent` عملية فرعية، عبر [`dsh-llm-replay`](../../../../packages/test-support/llm-replay) إعادة تشغيل قد سجل جلسة، و سوف مواصفة تحويل بعد تلقائي تحويل بروتوكول إخراج + إعادة حفظ دائم جلسة سجل و قد إيداع مسبق مدة إخراج إجراء diff. كبير كثير عدد مشهد عبر هذا بند حقيقي عملية حد اختبار تجميع بعد خلفية سلوك.

هذا طبقة الأكثر أول لـ كل عملية فقط لديه واحد جلسة بينما بناء، هذا واحد زائف ضبط صلب تحرير رمز في اثنان موضع:

- **`dsh-llm-replay` لا يوجد فعل أي مفتاح تحكم.** هو استخدام واحد عام تنقل علامة، سوف رقم N مرة `llm/stream` استدعاء مقابل إلى مفرد واحد تسجيل صنع تسلسل رقم N بند. عند أب agent(ذكي جسم) و واحد عملية داخل subagent في نفس عدد سياق فوق معا تدفق صيغة إخراج وقت، استدعاء تسليم خطأ، مفرد واحد تنقل علامة سوف يأخذ فرعي agent نص برمجي إرسال إعطاء أب agent(عكس لـ أيضا لكن).
- **harness فقط استلام تجميع واحد نسخة سجل.** `findSessionLog` مرة تاريخ sessions أصل دليل، إرجاع بحث إلى رقم واحد `.jsonl`.subagent بصفة ثاني عدد `Session` تشغيل و يملك ذاتي ذات سجل، لذلك فرعي agent transcript(نص سجل) يتم ساكن صامت إسقاط.

هذا حينئذ هو [subagent seam Agent Note](../feature/2026-06-21-subagent-capability-seam.zh.md) في عبر `TODO(subagent-snapshots)` دفع متأخر عمل: عملية داخل خلفية سقوط أرض وقت قد لديه وحدة + e2e تغطية، لكن في هذا طقم أساس أساس ضبط تطبيق سقوط أرض قبل، كامل transcript لقطة طبقة لا يمكن جدول بلوغ تضمين طقم agent شكل حالة.

## قرار

إعادة تشغيل حسب**استدعاء جهة جلسة**مفتاح تحكم،harness استلام تجميع**كل**جلسة سجل.

### 1. استدعاء جهة جلسة id مرفق حال في نموذج طلب فوق

`GenerateOptions` إضافة جديدة اختياري حقل `sessionId`، في طلب تجميع وقت من `agent.session.id` منح قيمة. مهايئ تجاهل اختصار هو؛`llm/stream` مستمع استخدام هو حسب إرسال بدء جلسة توجيه. ذلك نوع لـ `Branded<'SessionId'>`(قدوم ذاتي `dsh-brand`) بينما غير `dsh-session` `SessionId`، لأن بعد من الذي في حزمة استيراد `dsh-llm` `Message`، عكس نحو استيراد سوف شكل صار حلقة. اثنان عدد نوع انتظار قيمة، لذلك جلسة id منح قيمة بلا حاجة نوع تحويل. سوف brand نقل إلى واحد مخصص استخدام ids حزمة يخص مستقل عمل، لأن هو سوف أثر كل id استيراد.

### 2. إعادة تشغيل حسب أول مرة استدعاء ترتيب سوف نشط وثب جلسة ربط إلى تسجيل صنع نص برمجي

تضمين طقم مشهد تسجيل صنع كثير عدد زاوية لون:parent استخدام `session[.vN].jsonl`، كل subagent child استخدام `session.<ordinal>[.vN].jsonl`.V0 حذف `.v0`، صحيح generation استخدام صغير كتابة `.vN`،harness لـ كل زاوية لون اختيار عدد قيمة الأكثر عال ملف.`dsh-llm-replay` تحميل هذا عدد اختيار تحديد تجميع دمج، و لـ كل تسجيل صنع Session إرسال توليد واحد نسخة نص برمجي.Primary نص برمجي بداية نهاية أولا ربط؛child نص برمجي حسب header `createdAt` ربط،timestamp نفسه وقت من recorded id قرار فوز. حفظ دائم اكتشاف آخر خارج حسب `createdAt` قسم إعداد child fixture ordinal.

نشط وثب جلسة id كل مرة تشغيل كل هو كل جديد مع آلة قيمة، دائم بعيد لا انتظار في تسجيل صنع وقت id، لذلك نشط وثب جلسة لا يمكن عبر id متبادل انتظار ربط إلى نص برمجي. أخذ بينما بديل لـ هو**أول مرة استدعاء ترتيب**ربط: رقم واحد إرسال بدء أي نموذج استدعاء نشط وثب جلسة إقرار قيادة رقم واحد نسخة لديه ترتيب نص برمجي (أي أب جلسة:`createdAt` الأكثر مبكر، كما لا بد لكن الأكثر أولا تدفق صيغة إخراج، لأن هو يجب أولا تشغيل واحد جولة عندئذ قدرة تفويض إرسال) ، تحت واحد جديد نشط وثب جلسة إقرار قيادة تحت واحد نسخة نص برمجي، اعتماد هذا صنف دفع. هذا بعد كل جلسة مستقل دفع دخول ذاتي ذات تنقل علامة.

هذا نوع طريقة حسب من في استدعاء مفتاح تحكم، بينما غير حسب عام استدعاء ترتيب. لذلك أي جعل subagent سوف قدوم تزامن أو في خلفية تشغيل (عام تنقل علامة سوف توجيه يؤدي تسليم خطأ) ، هو ما زال صحيح تأكيد. لا يحمل `sessionId` استدعاء (مباشر في اختبار وحدة في استدعاء `stream()`) يتم نظر لـ واحد مجهول اسم جلسة، ربط إلى رئيسي نص برمجي، لذلك مفرد جلسة مسار و قديم سلوك تدريجي بايت متسق. نشط وثب جلسة عدد كثير في تسجيل صنع نص برمجي عدد وقت سوف واضح تقرير خطأ (ظهور لم تسجيل صنع subagent) ، أبدا سوف ساكن صامت خطأ توجيه.

فرعي fixture(اختبار قبل وضع بيانات) حسب `createdAt` ترتيب ترتيب، في أخ أخ جلسة صارم إطار ترتيب تنفيذ وقت و استدعاء ترتيب متسق.id قرار فوز قاعدة فقط لأجل يجعل أقصى طرف حال حال تحت ختم الوقت اندفاع مفاجئ نيل نيل تحديد ترتيب. تزامن أو خلفية فرعي جلسة يجب جذب دخول صريح أول مرة استدعاء ترتيب رقم، بينما غير اعتماد ختم الوقت.

## سبق اعتبار بديل خطة

سبق اعتبار لكن مرفوض خطة هو:**سوف أب فرعي سجل حسب استدعاء ترتيب دمج**لـ واحد نسخة عام نص برمجي (فقط في عملية داخل subagent تنفيذ صارم إطار تضمين طقم——أب agent منع سد انتظار فرعي agent——وقت عندئذ صحيح تأكيد). مقابل تزامن تنفيذ نموذج بينما قول أكثر بسيط مفرد، لكن سوف «أب منع سد في فرعي» هذا واحد ثابت صيغة ثابت تحويل دخول ذهاب؛ لم قدوم إذا جذب دخول خلفية/تزامن subagent حينئذ سوف بطلان. تدريجي جلسة مفتاح تحكم فإن لن.

### 3. harness استلام تجميع كل سجل، رئيسي جلسة أولوية

`harvestSessionLogs` سوف في كل حفظ دائم Session دليل تحت تمرير عودة اختيار عدد قيمة الأكثر عال مواصفة generation، تحليل كل منها header، و حسب primary أولوية ترتيب ترتيب: قمة طبقة Session(بلا `parentSession`) في قبل، كل child حسب `createdAt` رفع ترتيب ترتيب صف.`RunResult.sessionLogs` يتضمن كثير نسخة سجل؛record و refresh سوف يأخذ كل نسخة حالي إخراج كتابة `session[.vN].jsonl` أو `session.<ordinal>[.vN].jsonl`، لـ ما زال إنتاج زاوية لون إبقاء قديم generation، و يأخذ اختيار تحديد الأكثر عال replay إدخال و جديد طازج حالي إخراج فعل diff.normalizer قد دعم حمل كثير عدد Session id و سوف طي أي تنقل مغادرة UUID، لذلك بلا حاجة تعديل normalizer.

### 4. مشهد

إضافة جديدة اثنان عدد تضمين طقم مشهد، متساو مقابل حقيقي API تسجيل صنع:

- **`subagent-spawn-in-process`**: أب agent عبر `subagent` أداة سوف واحد فرعي مهمة تفويض إرسال إعطاء واحد جديد spawn فرعي agent(2 عدد جلسة).
- **`subagent-multi`**: أب agent تفويض إرسال اثنان عدد فرعي مهمة، كل منها تسليم إعطاء ذاتي ذات spawn فرعي agent(3 عدد جلسة) ، بـ ثلاثة نسخة مستقل تدريجي جلسة نص برمجي و نفس أب agent تحت اثنان عدد فرعي جلسة `createdAt` ترتيب ترتيب قدوم ضغط قياس تدريجي جلسة مفتاح تحكم.

اثنان من متساو في افتراضي بوابة في بـ keyless طريقة إعادة تشغيل.
