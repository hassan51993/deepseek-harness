# Agent Note: يجعل تلقي دعم حمل منصة اختبار تجمع تركيز دلالة

Status: implemented
Archived: 2026-09-04

[English](2026-07-22-cross-platform-test-fixtures.md) | العربية

## مشكلة

اختبار وحدة و نسبة التغطية اختبار طقم عنصر سوف في Windows،macOS و Linux فوق تشغيل، لكن منصة غير متصل سلوك ممكن يتم منصة خاص لديه fixture(اختبار قبل وضع بيانات) إخفاء غطاء. حرف وجه POSIX مسار في Windows فوق سوف تغيير صار متبادل مقابل في مشغل مسار؛ حمل رئيسي آلة اسم `file:` URI في Windows فوق ممكن هو صالح UNC مسار؛ عملية فرعية إدارة طريق إغلاق أو حدث حلقة ضبط درجة في مختلف مضيف فوق مستقر وقت نقطة أيضا لا متسق.FIFO، يمكن تنفيذ نمط موضع و دليل بحث إذن موضع انتظار فقط وجود في POSIX نظام الملفات حالة، في Windows فوق لا يوجد يمكن مباشر بنية صنع fixture.

يأخذ fixture لغة قاعدة عند صار منتج سلوك، يلزم ما سوف خطأ تقرير ارتداد، يلزم ما سوف حث جعل إنتاج شفرة جذب دخول مسح ذهاب أصلي مسار دلالة عودة واحد تحويل.

## قرار

اختبار منصة غير متصل سلوك وقت، استخدام مضيف `node:path` و `node:url` API بنية صنع قطعا مقابل مسار و `file:` URI، مجددا أصل حسب اتفاق اشتراط تأكيد أصلي قطعا مقابل إخراج أو مستقر مساحة العمل متبادل مقابل إخراج. بلا فاعلية URI fixture استخدام واحد نوع في كل تلقي دعم حمل منصة فوق كل سوف يتم `fileURLToPath()` رفض تحرير رمز شكل صيغة.

نقل لذا عائق اختبار سوف حقن اتصال رسالة كتابة جهاز، و نقل دخول و حقيقي Node تدفق نفسه مختلف خطوة كتابة عودة ضبط خطأ. إنتاج كتابة جهاز ما زال سوف يأخذ قسم لقطة رسالة كتابة عملية فرعية stdin. هذا نوع طريقة يجعل حقيقي عملية فرعية إبقاء تخزين نشط، جعل اختبار بلا حاجة لمس و منصة خاص لديه إدارة طريق جملة مقبض، أيضا قدرة تحديد صفة أرض منطقة قسم نقل لذا عائق و عملية خروج.

لغة خادم مورد تنظيف سوف إنهاء كامل شجرة بعد بديل عملية شجرة:POSIX استخدام سالب عدد عملية مجموعة ID،Windows تزامن تنفيذ `taskkill /T /F`.Windows فقط سوف تجاهل اختصار taskkill إرجاع «عملية شجرة قد لا وجود» حالة؛ أمر تنفيذ فشل، إذن خطأ و أخرى إنهاء عملية شجرة فشل ما زال يخص مورد تنظيف فشل. فقط قراءة مزود استعلام فقط في اختيار تحديد حوض تحويل نقل في هذا مرة استعلام بدء قبل أو تنفيذ خلال بطلان وقت إعادة محاولة مرة؛ خادم ما زال تخزين نشط وقت إرجاع خطأ لن إطلاق إعادة محاولة. طرفية اختبار سوف انتظار يمكن مراقبة تصيير إخراج، لا زائف ضبط مرة حدث حلقة جولة تحويل قد كاف كاف.

مقابل في حق صحيح فقط وجود في POSIX أصل لغة، اختبار فقط في هذا حالة استخدام فوق ترتيب حذف Windows. متبادل مجاور عبر منصة حالة استخدام ما زال سوف ثابت رفض غير عادي ملف، غير ممكن استخدام أمر و لا يمكن وصول عمل دليل سلوك.Windows فوق تلقي دعم حمل مسار ما زال تلقي تدريجي ملف نسبة التغطية بوابة قيد، لن مع اختبار ملف واحد بدء ترتيب حذف.

## سبق اعتبار بديل خطة

**سوف كل مسار و URI عودة واحد تحويل لـ POSIX نص.**هذا سوف جعل تأكيد إبقاء متسق، لكن أيضا سوف تغيير صحيح تأكيد Windows سلوك: خارجي مسار هو أصلي قطعا مقابل مسار،UNC ملف URI صالح، بينما كما قد إعداد رئيسي دليل سوف حسب وفق مضيف مسار قاعدة تحليل.

**تشغيل رأسي عملية فرعية إدارة طريق داخلي حالة، مباشر حتى كتابة فشل.**CRT وصف رمز و libuv جملة مقبض في مختلف مضيف و Node إصدار فوق كل حق مختلف، لذلك هذا نوع فعل قاعدة اختبار هو لم وثيقة تحويل fixture آلية، بينما غير اتصال كتابة فشل اتفاق.

**في Windows فوق قفز مرور كامل اختبار ملف أو حزمة.**مرور عرض ترتيب حذف سوف إخفاء تلقي دعم حمل سلوك. فقط ترتيب حذف لا يمكن في Windows فوق بنية صنع متبادل ينبغي حالة مفرد بند fixture؛ متبادل صلة اتفاق ما زال إبقاء تغطية.

## عاقبة

يمكن نقل غرس fixture حاجة أكثر صريح أرض بنية صنع، لأن مسبق مدة مسار يلزم من مشترك أصلي معتاد كمية إرسال توليد، نقل لذا عائق فإن عبر ضيق ضيق كتابة جهاز خطاف حقن. فقط ملائم لأجل خاص تحديد منصة ترتيب حذف بند يجب إعداد لديه متبادل مجاور عبر منصة تأكيد، بـ متابعة تغطية متبادل ينبغي منتج سلوك. بروتوكول درجة أفضل أنيق صلة توقف فشل بعد،Windows فوق مورد تنظيف اعتماد مضيف `taskkill` أمر؛ أمر تزامن تنفيذ نجاح وقت، يمكن تأكيد حفظ dispose(مورد تحرير) في لديه حد وقت داخل إتمام، و تأكيد حفظ تنظيف إرجاع قبل يكفي مراقبة إلى بعد بديل عملية خروج؛ إذا عملية شجرة إنهاء فشل، مورد تحرير منطق ما زال قدرة مراقبة إلى هذا فشل.
