# Agent Note: إسقاط ذاكرة مؤقتة تعديل لـ كل جلسة ملف

Status: implemented
Archived: 2026-09-04

[English](2026-08-19-projection-cache-per-session-files.md) | العربية

## Problem

حمل دائم إسقاط ذاكرة مؤقتة سبق هو مفرد عدد عام `session_projcache.json`——تخزين أصل دليل تحت واحد ملف داخل `sessions` جدول. كل مرة عقدة تدفق فحص نقطة كل سوف إعادة كتابة يتضمن كل جلسة سطر كامل ملف، كتابة وضع كبير مع جلسة عدد كمية زيادة طويل؛ كما واحد شاذ شكل ملف سوف يجعل كامل ذاكرة مؤقتة واحد بدء بطلان.

## Decision

ذاكرة مؤقتة فتح اعتماد إضافة جديدة `per-record` تخطيط `session_projcache` تخزين مجال: كل جلسة واحد حمل إصدار ختم وثيقة، يقع في `<root>/session_projcache/sessions/<id>.json`، وسيط جودة عودة تخزين مكدس كل——`storage` / `storage-json` / `storage-domain` و ذاكرة مؤقتة واحد بدء سقوط في مشترك base تركيب إعداد داخل، ذاكرة مؤقتة إعادة تغيير عودة صاف خالص مجال مستهلك. كل مع مرفق كما أساس في base profile كل إبقاء تفعيل ذاكرة مؤقتة، لذلك جلسة إنتاج جهة سوف سجل فحص نقطة، لا أخذ قرار في حالي تطبيق هل توفير قائمة واجهة؛ لا استخدام base تركيب حزمة `sdk-minimal` لا في هذا تركيب إعداد نطاق داخل. ذاكرة مؤقتة أبدا استشارة استفسار حفظ دائم طبقة: لا يوجد `locate`، لا اعتماد تركيب هو أي عدد خلفية.

قراءة كتابة مشترك نفس نسخة متسق حالة: كل مرة قراءة (`cachedSnapshot`) كل هو مقابل مجال داخل تخزين جدول تزامن فحص بحث (صفر I/O) ؛ كل مرة كتابة ترتيب دخول هذا مجال مفرد بند كتابة سلسلة، أولا سقوط قرص نجاح عندئذ تعديل داخل تخزين——لم يعد لديه سقوط بعد في عقدة تدفق كتابة مباشر قراءة مغناطيس قرص. ذاكرة مؤقتة إبقاء ذلك بقية الكل مسؤولية: فحص نقطة طي، كتابة سياسة (turn/end + dispose قوي صنع نقطة،count/interval عقدة تدفق) ،fail-soft حفظ دائم و قائمة قراءة.`cachedSnapshot(meta)` هو تزامن. ذاكرة مؤقتة لا تشغيل بارد إعادة طي مرحلة سلم (ذلك حاجة قراءة جلسة سجل، يخص حفظ دائم طبقة مسؤولية) ؛ حاجة حفظ إثبات بارد لقطة مستهلك ذاتي سطر من سجل إعادة طي.json خلفية بـ فقط تابع رئيسي إذن (`0o700`) إنشاء ذاتي ذات دليل شجرة.

## Consequences

- كل جلسة كتابة عزل: كل مرة عقدة تدفق كتابة فقط استبدال هذا جلسة صغير وثيقة، إزالة حذف عام كتابة وضع كبير. مجال كتابة سلسلة سوف كتابة سلسلة سطر تحويل، جديد قطع وجه أبدا سوف أولا في قديم قطع وجه سقوط قرص؛ مجال إغلاق وقت سوف ترتيب فارغ في طريق كتابة.
- قائمة قراءة هو تزامن داخل تخزين قراءة؛ لا يوجد سجل وثيقة جلسة فقط هو نقص قليل إسقاط صف.
- ACP،headless،SDK و Web جلسة كل سوف إصدار ذاكرة مؤقتة سطر، توفير لاحق مستهلك استخدام. تأكيد حفظ سجل قيادة أولا حمل دائم صفة شاشة عائق ممكن حسب ذاكرة مؤقتة عقدة عزف flush قد تغطية بادئة، و تفكيك قسم أصل هذا سوف دمج شيء إدارة JSONL سطر؛ كل profile تسجيل صنع لقطة سوف إعادة pack منطق حدث تدفق، لذلك ذاكرة مؤقتة وقت ترتيب لن قرار fixture تخطيط.
- per-record عقد نحو يأخذ لذا عائق نطاق تقليص صغير إلى مفرد سجل: شاذ شكل أو مرور مدة إصدار وثيقة في فتح وقت قراءة عمل"بلا هذا سجل"، مفرد عدد تالف ملف لن سحب انهيار كامل ذاكرة مؤقتة؛ فحص نقطة schema ترقية حسب جلسة إسقاط مرور مدة سطر، بينما لا هو رفض كامل مجال.
- json خلفية فقط في قطعة رفع وقت لا يوجد اكتشاف أي جديد تخطيط وثيقة مسار، قديم وحدة اسم مطابقة، كما ذلك إصدار لـ حالي إصدار أو قد إعلان توافق إصدار وقت، عندئذ من قديم كامل وحدة ذاكرة مؤقتة جذب توجيه per-record دليل شجرة. قبول تجميع دمج خارج إصدار إبقاء ثابت، جديد مجال لـ فارغ؛ تخزين أبدا يأخذ مجال owner لم دفعة دقيق إصدار تعديل علامة لـ حالي إصدار. فقط يلزم وجود مهمة معنى جديد وثيقة مسار، أي جعل ملف غير ممكن قراءة أو إصدار قديم قديم، أيضا سوف مقابل كامل وحدة منع استخدام جذب توجيه؛ ناقص جلسة سطر من سجل إعادة طي.[عبر إصدار قراءة توافق قرار](2026-09-02-projcache-cross-version-read-compat.ar.md) هو إصدار سياسة مرجعي شرح.
- `session_projcache` مجال استخدام إصدار 7، و إعلان إصدار 3 حتى 6 في بنية فوق توافق. قبل بديل identity نقص قليل Session `formatVersion`، لذلك لا يستطيع بث نوع حالي إسقاط و سوف عودة سقوط بارد طي؛ حالي فحص نقطة سوف استخدام كامل identity إعادة كتابة هو جمع. صيغة مطابقة بعد، ناقص lineage حقل عودة واحد تحويل لـ unseeded هوية،seeded استدعاء جهة سوف رفض هذا هوية و عودة سقوط بارد طي. ما زال عبر لا مرور schema تحقق سجل سوف يتم تجهيز نسخة و قفز مرور؛ لاحق كل مرة كتابة كل استخدام إصدار 7.
- ذاكرة مؤقتة سجل ما زال ربط نفس سجل دورة الحياة: تخزين `{createdAt, cwd, isSeeded, inheritedEventCount}` هوية منع توقف يتم إعادة بناء id أو لا مطابقة وراثة بادئة خطأ توجيه.

## Alternatives considered

- **إبقاء عام sessions جدول.** إبقاء مرة تحميل صيغة قائمة، لكن إبقاء حث صار هذا تعديل عام كتابة وضع كبير و مفرد ملف انفجار انفجار نصف مسار.
- **ذاكرة مؤقتة ذاتي حمل كل جلسة ملف**(`<root>/<session-id>/projection_cache.json`، هذا تعديل رقم واحد إصدار). تجربة مرور و في مراجعة في رجوع: ذاكرة مؤقتة يد فرك وسيط جودة——مسار، حسب مسار كتابة سلسلة، في طريق تتبع أثر، فقط تابع رئيسي ملف إذن، و sqlite بلا مسار خاص حكم——بينما كما هو قائمة قراءة كل مرة استدعاء كل مباشر قراءة مغناطيس قرص، كتابة لكن في عقدة تدفق، قراءة كتابة دائم لا متسق.
- **مرور `sessionPersistence.locate(meta)` تحليل مسار**(ملف وضع في جلسة سجل جانب). لم اعتماد: ذاكرة مؤقتة نيل من سجل artifact مسار"تخمين"سجل جانب حافة (`dirname` + ثابت ملف اسم) ، يأخذ ذاكرة مؤقتة اقتران دمج إلى حفظ دائم خدمة و خلفية تخطيط.
- **يأخذ `per-record` فعل صار قائم وحدة واحد نوع نمط بينما غير مستقل وحدة صنف.** لم اعتماد: اثنان نوع تخطيط حالة نموذج هذا جودة مختلف——`single` داخل تخزين مرجعي، كامل ملف إصدار؛`per-record` بلا حالة (دليل أي حالة،`loadAll` إعادة مسح دليل شجرة)——الذي بـ هو جمع هو نفس خلفية تحت اثنان عدد صغير نوع مستقل صنف، سجل مفتاح فعل مسار أمان تحقق بينما غير تحرير رمز.
- **عبر لم إعلان وحدة إصدار نسخ قديم قيمة.** لم اعتماد:json خلفية لا معرفة طريق مجال سجل schema، أيضا لا يمكن دفع توجيه جلسة lineage حقل. فقط لديه عند مجال في `compatibleVersions` في واضح صف خروج قديم إصدار، كما حالي schema قبول هذا قيمة وقت، خلفية عندئذ نسخ قديم سجل؛ لا فإن سجل إبقاء ثابت و قراءة عمل لا وجود.
