# Agent Note: مرور من مباشر mdast مصير زيادة كمية تدفق صيغة Markdown

Status: implemented
Archived: 2026-09-04

[English](2026-08-06-web-markdown-incremental-ast-renderer.md) | العربية

## Problem

`MarkdownText` في كل مرة تدفق صيغة إصدار وقت كل إعادة تحليل كامل قد تراكم تراكم عودة تكرار:react-markdown صاف نص API كل مرة تصيير كل جديد بناء unified processor,و مقابل كل نص ركض تمام micromark → mdast → hast → React,لذلك كل chunk رئيسي خط مسار عمل كمية مع عودة تكرار طويل درجة خط صفة زيادة طويل,كامل تدفق تراكم حساب صار هذا مع لـ اثنان مرة زيادة طويل. قائم مؤقت حل يد مقطع (لقطة درجة دمج، عزل تدفق صيغة ذيل جزء، محيط شريط plain ذراع) قيد هو هذا نسخة عمل ركض كثير تردد كثيف، موجة و كثير واسع,من لم قيد كل مرة إعادة تحليل كثير قليل نص. إصلاح هو حاجة AST درجة إدخال——تجميد ربط قد تحديد نوع كتلة، فقط إعادة تحليل مصدر نص ذيل جزء——هذا هو صاف نص غلاف تركيب في بنية فوق لا يمكن جدول بلوغ.

## Decision

`MarkdownText` مباشر تصيير mdast,و في تدفق صيغة خلال زيادة كمية تحليل:

- **لغة قاعدة**([parse.ts](../../../../packages/client/ui-primitives/src/markdown/parse.ts)):`parseGfm`(تدفق صيغة ذراع و `extractMarkdownPlainText`) و `parseGfmWithMath`(تحديد مسودة ذراع) بـ يتم استبدال remark إضافة الذي حزمة تركيب نفس مجموعة micromark توسيع استدعاء `mdast-util-from-markdown`,لذلك كل موضع كتلة حد تماما متسق.`mathCompatibility`(أصل `remarkMathCompatibility`) الآن مباشر توجيه خروج ذلك micromark توسيع.
- **زيادة كمية تحليل**([incremental.ts](../../../../packages/client/ui-primitives/src/markdown/incremental.ts)):CommonMark كتلة تحليل حسب سطر دفع دخول,إلحاق نص فقط سوف إعادة تشكيل تحليل قبل امتداد.`IncrementalMarkdownParser` إبقاء نهاية ذيل اثنان عدد كتلة لا مستقر (الأكثر بعد واحد كتلة هو قبل امتداد;قلب عدد ثاني كتلة هو أمان وفرة كمية),تجميد ربط ذلك قبل كل كتلة,فقط من الأكثر بعد واحد تجميد ربط كتلة `position.end.offset` بدء إعادة تحليل مصدر ذيل جزء——استخدام هو محلل ذاتي ذات انحراف نقل كمية,لا يوجد أي ذاتي صنع مصدر مسح. كل مصدر منطقة بين في كامل تدفق في تحليل O(1) مرة بينما غير كل chunk مرة;مفرد عدد ضخم نوع كتلة (لم إغلاق دمج محيط شريط) تراجع تحويل لـ قديم كل كمية إعادة تحليل صار هذا,لن أكثر فرق. غير إلحاق إدخال في تمرير زيادة generation تحت إعادة وضع حالة.
- **تصيير**([render.tsx](../../../../packages/client/ui-primitives/src/markdown/render.tsx) ،[katex.tsx](../../../../packages/client/ui-primitives/src/markdown/katex.tsx)): واحد مقابل mdast عقدة نوع switch يحل محل remark-rehype + react-markdown,تدريجي بايت تكرار لحظة يتم استبدال إدارة خط DOM——جدول إطار مقابل متساو تصيير لـ `text-align` مثال صيغة، ضيق تجميع قائمة مقطع سقوط حل حزمة، مهمة قائمة صنف اسم و تكرار اختيار إطار فارغ إطار، قدم ملاحظة منطقة (ذلك صفحة داخل مرساة نقطة هذا حينئذ يتم بروتوكول أبيض اسم مفرد خفض لـ صاف نص) ، حرف وجه raw HTML، سوف و حرف وجه HTML نص متبادل مجاور إظهار شكل قسم فصل تبديل سطر,و rehype-katex ثلاثة ذراع سعة خطأ سلسلة,KaTeX HTML مرور متصفح ذاتي حمل `DOMParser` خريطة لـ React(بلا حزمة لف عنصر عنصر,أول/نهاية فرعي عنصر عنصر margin قاعدة ما زال قدرة أثر في `.katex-display`;React 18 سوف يأخذ `.katex-mathml` فرعي شجرة وضع دخول HTML نطاق الأسماء,و يتم استبدال إدارة خط تماما متسق——قائم حد,لا في هذا مقابل انتظار صفة اتفاق نطاق داخل,مقابل تحمل تحمل نظر شعور تصيير `.katex-html` ذراع غير ممكن رؤية). تجميد ربط كتلة ذاكرة مؤقتة ذلك React عنصر عنصر و إبقاء مصدر انحراف نقل key,عبر مرور تجميد ربط حد وقت مشي reconcile بينما غير إعادة تركيب;`MarkdownText` قد memo تحويل.

DOM من `tests/fixtures/markdown-dom` تثبيت ميت:fixture تسجيل صنع ذاتي استبدال قبل react-markdown تنفيذ,جديد مصير يجب في فارغ أبيض قاعدة كامل تسلسل تحويل جهاز تحت تكرار الآن.fixture فرق مختلف أي مستخدم مرئي markdown مثال صيغة تغيير,يجب حسب هذا مراجعة,أبدا قدرة لـ إعادة بنية بينما إعادة تسجيل.`tests/markdown-incremental.spec.tsx` تحمل تحميل انتظار قيمة صفة صفة جودة——بـ 1/3/7/16 بايت قسم كتلة,في كل إلحاق بادئة موضع,معتاد إقامة مكون DOM كل انتظار في كل جديد تركيب——خارج إضافة تجميد ربط حد DOM عقدة نفس صفة و إعادة وضع سلوك.

هذا دفع قلب[مساعدة يد Markdown Note](../feature/2026-07-23-web-assistant-markdown.zh.md) في يتم مرفوض تجهيز اختيار ("صيانة واحد ذاتي تعريف React walker"): زيادة كمية يحتاج طلب هو عند وقت لا وجود جديد دليل,walker أمان حساس شعور فرع (URL أبيض اسم مفرد، صورة سياسة، كسول صفة HTML) هذا حينئذ هو منتج ذاتي لديه دالة,بينما هذا اعتماد لم يعد حذف نقص ذاتي لديه شفرة——هو منع سد هيكل بنية. هذا Note غير ممكن معلومة إخراج سياسة و مصير اختيار نوع ثابت.

## Alternatives considered

**إبقاء react-markdown,يأخذ مصدر نص قطع صار تدريجي مقطع `<ReactMarkdown>` نسخة.** مصير صفر ذاتي لديه صار هذا,لكن كل لقطة مقابل ذيل جزء تحليل اثنان مرة (حد فحص قياس + تصيير),تحديد مسودة عدد تعلم ما زال يلزم كل كمية إعادة تحليل,hast بناء و تدريجي تصيير processor اعتماد قديم وجود,كما كتلة عبر مرور تجميد ربط حد وقت سوف إعادة تركيب——عنصر عنصر شجرة لا يمكن عبر نسخة ذاكرة مؤقتة.

**استخدام `mdast-util-to-hast` + `hast-util-to-jsx-runtime` تصيير ذاكرة مؤقتة mdast.** أبيض أخذ فوق تنقل عقدة خريطة,لكن كل لقطة إبقاء hast في بين طبقة,و لـ واحد خريطة وجه صغير، غلاف إغلاق، كما قد يتم fixture تثبيت ميت إدارة خط جذب دخول اثنان عدد جديد مباشر اعتماد.

**استخدام `hast-util-from-html-isomorphic` تحليل KaTeX إخراج (rehype-katex فعل قاعدة).** لـ تحليل يمكن معلومة، مفردات تلقي حد KaTeX إخراج يأخذ أساس في parse5 HTML محلل سحب دخول bundle,بينما متصفح ذاتي حمل `DOMParser`(حمل مواصفة SVG/MathML خاصية ضبط كامل) تحليل نتيجة تماما نفسه.

## Consequences

تدفق صيغة كل chunk عمل كمية الآن تتبع مع لا مستقر ذيل جزء بينما غير كامل عودة تكرار,react-markdown،remark-gfm،remark-math،rehype-katex،unified و hast سلسلة خروج متصفح bundle(`mdast-util-math` و `micromark-util-sanitize-uri` يصبح مباشر اعتماد;اثنان من أصل هذا حينئذ هو نقل تمرير اعتماد). حزمة ذاتي لديه نحو 25 عدد عقدة خريطة، ذلك اختبار و KaTeX DOM تحويل——بديل قيمة من تجميد ربط ذلك إخراج fixture اتفاق مقابل اندفاع. اثنان عدد سلوك انحراف فرق,متساو في تحديد مسودة كل كمية تحليل موضع ذاتي شفاء: تعريف سقوط في تجميد ربط حد آخر جانب مرجع صيغة رابط أو قدم ملاحظة في تدفق صيغة خلال تصيير لـ حرف وجه نص;عند قدم ملاحظة تعريف أولا تجميد ربط بينما مرجع كتلة ما زال لا مستقر وقت,قدم ملاحظة مرجع ممكن وميض عودة حرف وجه نص. هذا وحدة و KaTeX تحويل زائف تحديد متصفح DOM(`DOMParser`),هذا عدد client-only حزمة هذا حينئذ مثل هذا.
