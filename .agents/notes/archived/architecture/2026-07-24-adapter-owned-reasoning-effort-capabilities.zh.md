# Agent Note: مهايئ يحتفظ دفع إدارة قوي درجة قدرة

Status: implemented
Archived: 2026-09-04

[English](2026-07-24-adapter-owned-reasoning-effort-capabilities.md) | العربية

## مشكلة

دفع إدارة قوي درجة مرور ذهاب فقط قدرة في مهايئ في إعداد، لذلك محادثة لا يمكن في كثير مرة طلب بين اكتشاف أو أكثر تعديل الذي اختيار نموذج دعم حمل انتظار درجة. إذا سوف بعض عدد مهايئ انتظار درجة ربط دمج نوع رفع رفع إلى `dsh-llm`، كل مزود و نموذج كل يجب اعتماد واحد طقم ذاته ممكن و لا دعم حمل اسم؛ إذا تعديل استخدام مزود خاص لديه options كائن،agent loop(ذكي جسم حلقة) أيضا لا يمكن تحقق نهائي توليد فاعلية طلب، أيضا لا يمكن عبر حفظ دائم سجل دقيق تأكيد إعادة بناء هذا طلب.

## قرار

`dsh-llm` استخدام لا نفاذ واضح صنف لوحة نوع `ReasoningEffortId` يمثل دفع إدارة قوي درجة. من مهايئ يحتفظ مفرد مرة `resolveModel(provider, model, signal?)` استعلام إرجاع `LlmResolvedModelInfo`، منها يتضمن تأكيد قطع نموذج هوية و اختياري سياق و دفع إدارة بيانات وصفية.`LlmRuntime.resolveModelInfo()` سوف تحقق هذا تجمع دمج نتيجة، و إرجاع و مهايئ داخلي حالة قسم مغادرة قيمة فرعي هذا.`reasoning.efforts` وجود وقت، هو يتضمن عرض بيانات وصفية غير فارغ لديه ترتيب ID قائمة، و يمكن إشارة تحديد واحد من إعداد تحديد قيمة افتراضية. نواة قلب اشتراط صريح إشارة تحديد أو إعداد إشارة تحديد دفع إدارة قوي درجة و قائمة في بعض عدد ID تماما متسق، كما أبدا تلقائي ضبط كامل أو لـ قيمة توفير آخر اسم.

`LlmCallConfig` و `GenerateOptions` يحمل اختياري دفع إدارة قوي درجة.agent loop في نشط وثب جولة إشارة تحكم تحت دقيق تجهيز `agent/request` معالجة إتمام بعد إعداد، مجددا كتابة `request/header`، لذلك قيمة افتراضية و حركة حالة تغيير فقط لديه يصبح حفظ دائم واقع بعد عندئذ مقابل نموذج مرئي. دقيق تجهيز إتمام استدعاء في مختلف خطوة تأكيد قطع نموذج تحليل، طلب رأس حمل دائم سجل و قسم إرسال كل مسار إبقاء نفس بند تأكيد قطع مهايئ تسجيل؛ مباشر استدعاء `LlmRuntime.stream()` وقت، أيضا سوف في انتظار تحليل قبل التقاط نهائي مهايئ تسجيل. لا يوجد قد تسجيل مهايئ توجيه سوف إبقاء أصل تحديد إعداد، جعل `llm/stream` في بين عنصر يمكن وصل إدارة و قصير مسار هذا طلب؛ إذا ما زال لم نيل إلى معالجة، نهائي توزيع سوف رفض هذا توجيه. استعادة بعد agent loop فقط في ابتدائي مزود/نموذج توجيه لم تغيير وقت إبقاء سجل في سجل دفع إدارة قوي درجة؛ إذا توجيه حدوث تغير، فإن إسقاط فوق واحد نموذج لا نفاذ واضح ID.

عند نشر سياسة سماح تفكير اعتبار وقت، أصلي DeepSeek مهايئ إعلان `off`،`low`،`high` و `max`، افتراضي استخدام إعداد إشارة تحديد دفع إدارة قوي درجة، إذا لم إعداد فإن استخدام `high`. من مهايئ يحتفظ `off` خريطة لـ `thinking.type: disabled`، كما لا حمل `reasoning_effort`؛`low`،`high` و `max` سوف تفعيل تفكير اعتبار و يحمل كل منها نفس اسم رسمي جهة بروتوكول قوي درجة قيمة. إعداد لـ `thinking: disabled` نشر فقط إعلان `off`، و سوف في مزود I/O قبل رفض تفعيل تفكير اعتبار محاولة تجربة.pi-ai مهايئ أصل مثال إصدار كل تأكيد قطع نموذج `getSupportedThinkingLevels()` نتيجة، منها يشمل `off`؛profile لم إشارة تحديد قيمة افتراضية وقت إبقاء مزود افتراضي سلوك، و سوف مزود بروتوكول قيمة خريطة إبقاء في pi-ai داخلي. حسب وفق pi-ai ذاته API اشتراط، ذلك عام تدفق خيار عبر حذف `reasoning` قدوم يمثل `off`.

## تجهيز اختيار خطة

**في نواة قلب في تعريف pi-ai `ThinkingLevel` ربط دمج نوع.** غير مقبول:pi-ai حالي مواصفة اسم يخص مهايئ تنفيذ دقيق عقدة؛ لم قدوم مزود يمكن كشف مختلف معرف رمز، بينما بلا حاجة لـ هذا إصدار جديد نواة قلب إصدار.

**يحمل بلا نوع قيد مزود options كائن.** غير مقبول:agent loop حيث لا يمكن تحقق اختيار تحديد قيمة، أيضا لا يمكن في طلب رأس في كتابة مستقر كما و مزود غير متصل واقع.

**تلقائي ضبط كامل لا دعم حمل انتظار درجة.** غير مقبول: ساكن صامت استبدال سوف توجيه يؤدي مستخدم اختيار تحديد تحكم بند و سجل سجل طلب معنى رسم لا متسق، أيضا سوف إخفاء غطاء قديم قديم نشر إعداد.

**سوف كل مهايئ مواصفة تحويل لـ نواة قلب يحتفظ انتظار درجة قائمة، أو إزالة `off`.** غير مقبول: اختياري قيمة تجميع دمج يخص تأكيد قطع نموذج قدرة. عميل يمكن تصيير بعض عدد مهايئ `off` خيار، بينما بلا حاجة اشتراط كل مهايئ كل كشف هذا خيار.

## أثر

عميل فقط يحتاج استعلام مرة تأكيد قطع توجيه، يكفي تصيير ذلك هوية، سياق سعة كمية و من مهايئ يحتفظ دفع إدارة خيار، بينما بلا حاجة حل عام قطعة رفع أو ذاتي سطر دمج صار `off`. مهايئ إعداد ما زال هو نشر قيمة افتراضية و سياسة ملكية جهة،`agent/request` فإن يمكن في هذا سياسة نطاق داخل لـ كل خطوة استبدال فعلي توليد فاعلية دفع إدارة قوي درجة. تأكيد قطع هوية، سياق أو دفع إدارة بيانات وصفية بلا فاعلية وقت، قسم آخر رمي خروج `INVALID_MODEL_INFO`،`INVALID_MODEL_CONTEXT` أو `INVALID_MODEL_REASONING`؛ صريح إشارة تحديد أو إعداد إشارة تحديد قيمة لا تلقي دعم حمل وقت، سوف في مزود I/O قبل رمي خروج `UNSUPPORTED_REASONING_EFFORT`.

تأكيد قطع نموذج بيانات وصفية تجمع دمج استعلام اعتماد مختلف خطوة طريقة، و كما مقابل في من مرجعي دليل دعم حمل مهايئ ممكن فشل. اختياري إشارة بنية صار استدعاء جهة إلغاء حد؛ مختلف خطوة مهايئ يجب في إشارة في توقف بعد سريع سرعة إتمام تسوية، جعل agent loop مورد تحرير بلوغ إلى تماما توقف مستقر. بلا مفتاح خدمة، مهايئ،agent loop، جلسة و طلب رأس اختبار لـ تحقق، قيمة افتراضية تحليل، حركة حالة تغيير، سجل سجل، استعادة سلوك،HMR(حار وحدة استبدال) خلال تسجيل كل حق و إلغاء توفير ارتداد حفظ عائق؛ يمكن تشغيل لقطة قفل تحديد فعلي تجميع طلب رأس في قد تحليل دفع إدارة قوي درجة، فقط في لديه مفتاح وقت تشغيل مهايئ اختبار فإن تغطية مزود تسلسل تحويل.
