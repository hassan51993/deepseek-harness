# Agent Note: تفكيك قسم جلسة إسقاط حالة و عميل عرض

Status: implemented
Archived: 2026-09-04

[English](2026-08-19-session-projection-state-and-client-views.md) | العربية

## مشكلة

إسقاط سجل التسجيل سوف حفظ دائم كل وحدة داخلي طي حالة، لكن لا يوجد وقت التشغيل schema؛ و هذا معا،`SessionProjectionMap` وصف هو `view` إرجاع عميل قيمة. هذا جعل استعادة خروج حالة لم مرور تحقق، أيضا يجعل نفس ورقة نوع جدول نظر يشبه معا وصف اثنان نوع ممكن مختلف قيمة.host مستهلك أيضا حاجة قراءة حالي طي حالة، لكن لا ينبغي لـ هذا تسلسل تحويل الكل قد تسجيل عميل عرض، أيضا لا ينبغي يأخذ داخلي حالة كشف إلى عميل بروتوكول.

## قرار

`SessionProjectionStateMap` هو host طي حالة merge-extensible نوع جدول. كل `ProjectionDefinition` key كل يخص هذا جدول و توفير `stateSchema`؛ ذاكرة مؤقتة سطر فقط لديه عبر تحقق بعد عندئذ قدرة لـ طي توفير ابتدائي حالة.`SessionProjectionMap` إبقاء أصل لديه اسم و دلالة، متابعة بصفة وحيد عميل مرئي كل كمية قيمة نوع جدول، لذلك `title: string | null` انتظار قائم عميل بيانات بنية إبقاء ثابت.

إذا واحد وحدة key أيضا وجود في `SessionProjectionMap`، هذا وحدة حينئذ توفير `wire.viewSchema` و `wire.view`. كل وحدة حالة كل سوف كتابة فحص نقطة——client-visible و host-only واحد نظر نفس لب؛`persist` اختيار بند قد إزالة، أي وحدة كل لا يستطيع صامت صامت قفز مرور حفظ دائم ذاكرة مؤقتة. لقطة API فقط قطعة رفع حمل `wire` تعريف، لذلك تسرب نقل تلقي جمهور علامة أيضا لا يمكن يجعل داخلي حالة دخول API تحميل حمل.host شفرة عبر `stateOf(session, key)` قراءة واحد نسخة حالي حالة؛ إرجاع هو استعارة استخدام مرجع، لا نيل تعديل.

## نتيجة

إسقاط حالة و عميل قيمة قسم آخر نيل نيل نوع و تحقق، معا لا جذب دخول ثاني طقم عميل DTO مفردات. وحدة يمكن إبقاء أكثر وفير غني host حالة، و كشف ضيق تجميع أو توافق قائم بنية عميل قيمة. شاذ شكل ذاكرة مؤقتة حالة لا يستطيع لـ `viewCheckpoint` توفير بيانات؛ استعادة سوف رفض شاذ شكل حالة، و من ذاكرة مؤقتة قائم كل كمية قراءة رجوع من سجل إعادة بناء.host مستهلك يمكن استخدام نفس طقم زيادة كمية طي استبدال خاص سجل مسح، بينما تحميل جسم لقطة لا يمكن قطعة رفع host-only حالة.

أصلي [session-projection رفع سجل](../../proposed/architecture/2026-07-27-session-projection-and-command-log.zh.md) قد سجل هذا مرة تفكيك قسم. قائم [subagent هوية إسقاط](2026-08-06-subagent-list-identity-projection.zh.md) و[إسقاط تحويل token استخدام كمية](2026-07-29-projected-token-usage-and-request-context.zh.md) قرار ما زال صالح؛ منها مجال طي نقل دخول حالة جدول، لا تغيير موجه إلى مستخدم قيمة.

## اعتبار مرور بديل خطة

- **يأخذ قائم نوع جدول تعديل اسم لـ حالة جدول، مجددا جذب دخول جديد عميل نوع جدول**——لا إعطاء اعتماد، لأن هذا سوف تغيير قد تأكيد قيام عميل نوع اسم، و توجيه يؤدي لا لا بد يلزم عميل تحميل حمل ترحيل.
- **متابعة استخدام واحد ورقة نوع جدول معا وصف حالة و عميل قيمة**——لا إعطاء اعتماد، لأن هذا مثال لا يمكن دقيق تأكيد جدول بلوغ أكثر وفير غني طي حالة و إبقاء توافق عميل قيمة.
- **host-only وحدة حسب يحتاج اختيار حفظ دائم**——لا إعطاء اعتماد:`persist` علامة سجل سوف يجعل وحدة صامت صامت قفز مرور حفظ دائم ذاكرة مؤقتة، بينما حذف تحت (كل جلسة واحد سطر صغير سجل) دائم بعيد لا قيمة نيل هذا نوع لا مقابل تسمية أو هو حمل قدوم stateVersion صعب حيرة. كل وحدة حالة موحد واحد كتابة فحص نقطة.
- **يجعل `stateOf` إرجاع حالة فرعي هذا**——لا إعطاء اعتماد، لأن كل مرة host قراءة كل تغلب ضخم سوف زيادة عمل، لكن لا يوجد حفظ حماية أي حد؛ هذا طريقة لـ نفس عملية نوع تحويل استدعاء جهة واضح قاعدة تحديد فقط قراءة استعارة استخدام مرجع معنى خدمة.
