# Agent Note: جلسة محتوى بحث عبر openAt never بـ opt-in طريقة تسليم

Status: implemented
Archived: 2026-09-04

[English](2026-08-13-session-content-search-opt-in.md) | العربية

## مشكلة

تسليم bundle قبل بـ تفعيل حالة تركيب SQLite جلسة استعلام مزود كل نص بحث جذب (`openAt: first-search`) ، لذلك كل افتراضي نشر كل يحمل واحد إرسال توليد FTS بحث جذب،Web جانب حافة شريط توفير محتوى بحث. واحد نشر هل حاجة هذا بحث جذب——هو node:sqlite استيراد، كل مرة بحث مصدر مقابل حساب و إرسال توليد تخزين——هو نشر ذاته اختيار، منتج افتراضي لا يحمل هو تسليم؛ موجه إلى نموذج بحث أداة هذا قبل قد هو opt-in كما لم تركيب (رؤية[غير افتراضي تسليم قرار](../feature/2026-08-02-session-search-not-shipped-default.ar.md)).

عبر إزالة إضافة سطر قدوم إغلاق هذا قدرة غير ممكن سطر.`ApiProxyService` سوف `sessionQuery` إعلان لـ مطلوب حقن، لا يوجد هذا مزود وقت كامل مضيف API شبكة صلة إبقاء لم تحميل،Web GUI لا يمكن بدء. جلسة سجل توجيه خروج عبر `ctx.sessionQuery.traceSession` تتبع أثر فرعي بديل إدارة بعد بديل، فرعي بديل إدارة قسم تقاطع أيضا عبر نفس دم حافة تتبع أثر تحليل ذلك Workspace——اثنان من كل حاجة اختياري خدمة حراسة حماية إضافة واحد بديل دم حافة مصدر، تعديل وجه كبير نحو توسيع كبير ثلاثة ضعف، معا جعل دقيق قراءة في كل أرض جهة إزالة فقد.

## قرار

محتوى بحث في مزود موضع قوي صنع إغلاق.`openAt: 'never'` هو `@deepseek-ai/dsh-session-query-sqlite` رقم ثلاثة عدد فتح مرحلة مقطع:`searchSessions` و `searchEvents` في أي طلب مواصفة تحويل قبل حينئذ بـ نوع تحويل `SESSION_QUERY_SEARCH_DISABLED` شفرة فشل،node:sqlite أبدا سوف يتم استيراد أو فتح، أيضا لا تشغيل أي مصدر مراقبة أو مقابل حساب.`ctx.sessionQuery` فوق وراثة الكل دقيق قراءة، مرور ترشيح و تتبع أثر إبقاء متاح، لذلك جلسة توجيه خروج، قسم تقاطع Workspace وراثة و عنوان قراءة لا تلقي أثر.

`SESSION_QUERY_SEARCH_DISABLED` إضافة دخول غلاف إغلاق `SessionQueryErrorCode` تصنيف،`tool-session-query` خدمة حد سوف هو خريطة لـ نموذج أمان رسالة `session search is disabled in this deployment`.

base bundle في `session-query-sqlite` سطر فوق ضبط `openAt: never`،web bundle إعادة وصف إبقاء هذا قيمة؛ تفعيل محتوى بحث فقط يحتاج في لاحق patch طبقة استخدام واحد سطر تغطية `openAt`(`first-search` أو `startup`) ، عبر معتاد معا إعداد واحد حمل دائم `path`. مضيف `session.search` طرف نقطة امتداد قائم خطأ مسار تقرير إبلاغ مزود فشل،Web جانب حافة شريط إبقاء ذلك قائم تخفيض: محلي عنوان/مساحة العمل مطابقة إضافة محتوى بحث غير ممكن استخدام تلميح.CLI توافق صفة اختبار ثابت تسليم `openAt: never` سطر، بينما Web e2e قدم يد هيكل إبقاء محتوى بحث تفعيل——ذلك نوع فرعي جلسة مشهد عبر محتوى بحث تنقل، هذه تشغيل أيضا هو opt-in مسار تركيب إعداد درجة تغطية.

## سبق اعتبار بديل خطة

- **إزالة إضافة سطر**(في base patch في `disabled: true`)——مرفوض:api-gateway مطلوب `sessionQuery` حقن سوف جعل كامل مضيف API إبقاء لم تحميل، بينما يأخذ هذا حقن تعديل لـ اختياري حاجة حراسة حماية إضافة فوق جلسة توجيه خروج و قسم تقاطع تحليل في header مرة تاريخ دم حافة رجوع.
- **في مستهلك موضع إغلاق**(مضيف `session.search` طرف نقطة أو جانب حافة شريط)——مرفوض: قوي صنع ينبغي من فعل خروج قرار عملية تنفيذ؛opt-in نموذج أداة أو أي أخرى مستهلك ما زال سوف لمس بلوغ بحث جذب.
- **في `openAt` جانب زيادة مستقل نشر ذلك فتح صلة**——مرفوض: فتح مرحلة مقطع قد يملك"SQLite أي وقت بدء"هذا واحد محور؛`never` تأخير امتداد نفس أصل محور، بينما لا هو زيادة واحد ممكن و لـ تناقض درع ثاني عدد دوران زر.

## نتيجة

- افتراضي نشر لا تشغيل أي إرسال توليد بحث جذب: لا يوجد node:sqlite استيراد أو فعلي تحقق صفة SQLite بدء تحذير إبلاغ، لا يوجد مقابل حساب عمل، مغناطيس قرص فوق لا يوجد إرسال توليد قاعدة بيانات. جانب حافة شريط بحث فقط مطابقة جلسة عنوان و مساحة العمل اسم.
- افتراضي حالة تحت بحث فشل هو نوع تحويل كما مستقر، استدعاء جهة يمكن يأخذ نشر اختيار و بحث جذب لذا عائق (`SESSION_QUERY_INDEX_FAILED`) منطقة قسم فتح.
- إعادة تفعيل محتوى بحث هو تدريجي نشر إعداد بينما غير شفرة تعديل، و أصل مثال استعادة كامل FTS سلوك.
- تركيب بحث أداة لكن لم تغطية `openAt` تركيب، كل مرة بحث استدعاء كل سوف نيل إلى نموذج أمان قد منع استخدام رسالة؛ تفعيل أداة معنى طعم حال معا تفعيل بحث جذب.
