# Agent Note: أساس في prompt rpcId محلي إيداع عودة إظهار

Status: implemented
Archived: 2026-09-04

[English](2026-08-26-local-submission-echoes.md) | العربية

## مشكلة

كثير رسم prompt في عميل تسلسل تحويل إضافة host admission فوق يلزم زهرة عدد ثانية،durable `user/message` في هذا قبل لا وجود، جلسة في هذا خلال ماذا كل لا عرض:composer تجميد ربط لـ فقط قراءة، رسالة في كامل بند خط الإنتاج انتهاء بعد عندئذ ظهور، مستخدم لا يمكن حكم قطع إيداع هل قد بدء (#3003).durable event لا يمكن رفع قبل،Model-visible ⟺ logged اشتراط `user/message` فقط قدرة في الكل مرفق عنصر حفظ دائم بعد سقوط قرص، لذلك مرئي إيداع يجب و durable إيداع حل اقتران.

## قرار

**Session كائن يحتفظ عميل محلي إيداع عودة إظهار، استخدام prompt قائم `requestId`/`rpcId` صلة ربط.**`session.beginSubmission` في استدعاء جهة تسلسل تحويل أي محتوى قبل، تزامن يأخذ `{requestId, text, images: previews}` كتابة `SessionSnapshot.pendingSubmissions` و قلب تحويل `promptAttempted`؛ نفس عدد `requestId` مع prompt RPC إرسال خروج. لا يوجد جديد صلة ربط id، لا يوجد wire نوع تعديل، أيضا لا يوجد session log تعديل:host هذا حينئذ يأخذ prompt `requestId` كتابة دخول durable user source `rpcId`،queue إسقاط الآن يأخذ هو بصفة `SessionQueuedItem.rpcId` يحمل، تغطية سقوط دخول inbox بينما غير log prompt(تشغيل في turn إيداع).

**تراجع راحة من مراقبة قيادة و تأخير متأخر واحد لقطة؛ عرض ذهاب إعادة هو تصيير مدة إعلان صيغة قاعدة.**Session في حمل ذلك rpcId durable `user/message` أو queue occurrence وصول وقت (append، نافذة تثبيت أو control frame) علامة عودة إظهار لـ قد مراقبة، و في واحد حركة رسم لقطة بعد إزالة، متأخر في أولا تسجيل جلسة تجميع لقطة.ChatView مستقل أرض إخفاء rpcId ظهور في قد تصيير user/steering عقدة أو queue سطر في عودة إظهار، لذلك بلا نقاش store تحديث ترتيب مثل أي، كل مرة تصيير في عودة إظهار و durable تماما لديه واحد مرئي. حمل معرف prompt فشل،`abandon()` أو إلغاء تدمير جعل عودة إظهار قيام أي حسب failed تراجع راحة؛ أولا إلى settlement توليد فاعلية.

**طابور صف عملية اشتراط مراقبة إلى Host هوية.**ترتيب طابور عودة إظهار عرض إرسال حالة، و في صحيح صيغة طابور صف سطر نفسه موضع عرض منع استخدام تحرير، حذف و إدراج كلام حسب زر. طي بعد طابور صف في عنوان شريط إبقاء هذا حالة. مفرد وحيد prompt تأكيد لا يحمل طابور صف بند هوية، لذلك فقط لديه صلة ربط Host طابور صف سطر وصول بعد عندئذ تفعيل ملائم استخدام عملية. هذا جعل مؤقت بطيء تلقي إدارة حالة مرئي، معا تجنب تجنب يأخذ محلي طلب id عند عمل يمكن تعديل Host طابور صف بند.

**Composer مرح مراقبة إيداع.**Enter في واحد machine أمر خدمة داخل صاف فارغ مسودة مسودة،occurrence جدول و سحب إلغاء تاريخ،phase إبقاء `plain`؛ إرسال بصفة detached attempt تشغيل، سماح تزامن إرسال، وحيد تجميد ربط in-flight مجرى فقط إبقاء إعطاء أمر. كثير عدد detached إرسال فشل وقت، فقط يلزم composer لـ فارغ أو ما زال هو فوق مرة تلقائي أيضا أصل محتوى، حينئذ حسب إيداع ترتيب دمج أيضا أصل؛ مستخدم تحرير بعد إيقاف هذا واحد جولة تلقائي أيضا أصل. مسودة مسودة صورة من detached attempt يحتفظ إلى عودة إظهار تراجع راحة، لذلك صورة مغادرة فتح rail بعد إلغاء تدمير Session scope ما زال قدرة تحرير هو جمع. عودة إظهار بـ observed تراجع راحة وقت،`HistoricalImageCache.seed` يأخذ كل معاينة URL تعليق إلى admitted مرجع اسم تحت. ذاكرة مؤقتة تزامن عام معاينة URL، معا قراءة durable مرفق عنصر؛ قراءة إتمام بعد استخدام مواصفة تحويل URL استبدال معاينة، و حسب كل منها دورة الحياة سحب إلغاء اثنان عدد URL. مباشر subagent continuation لا تسجيل عودة إظهار، لأن هو transport سوف قسم إعداد آخر عدد RPC id، بينما كما لا دعم حمل صورة إدخال.

عميل صورة تحرير رمز من تزامن قسم كتلة `btoa` حلقة تبديل صار `FileReader.readAsDataURL`(أصلي تحرير رمز).browser→host نقل ما زال هو واحد base64 JSON كامل حزمة؛#2885 باق بقية نقل تعديل صنع لا في هذا قرار نطاق داخل.

## عاقبة

عادي نص و صورة prompt نقر إيداع بعد سوف في عند لقطة عرض رسالة و يجعل composer سقوط قاع،admission وقت آلة ثابت. افتراضي إرسال لم يعد تجميد ربط composer، إرسال خلال يمكن متابعة إدخال و إيداع؛machine `submitting` مرحلة مقطع فقط لأجل أمر إيداع.RPC استجابة فقد فقد لكن admission قد نجاح prompt عبر مراقبة تأكيد نتيجة، لن تكرار إرسال. صورة في durable بايت إرجاع قبل عرض محلي معاينة، مع بعد عرض host حفظ إصدار، في بين لا يوجد تحميل احتلال موضع.

## تحقق

Session client spec تغطية تزامن إدراج دخول،requestId نفاذ نقل،event،queue و نافذة مراقبة،queue و durable معا مراقبة وقت فقط تراجع راحة مرة، تأخير لقطة إزالة،abandon و إلغاء تدمير.Machine و shell spec تغطية مرح مراقبة إيداع، تزامن detached settlement، كثير عدد فشل حسب إيداع ترتيب أيضا أصل، صورة صاف إرسال إلغاء، و صورة مع scope إلغاء تدمير بينما تحرير.ChatView spec تغطية تدفق ذيل تصيير، و عودة إظهار ما زال في snapshot وقت حسب عقدة و طابور صف ذهاب إعادة.Host control spec تغطية queue rpcId إسقاط؛ ذاكرة مؤقتة و مرفق عنصر spec تغطية seed أول لقطة عرض، مواصفة تحويل استبدال و URL سحب إلغاء.connection fixture عودة إظهار `requestId`،`fresh-round-trip` recorded-session snapshot في durable admission قبل سجل محلي عودة إظهار.

## اعتبار مرور بديل خطة

**إضافة جديدة `clientSubmissionId` اختراق اختراق wire و user source.**مرفوض:`requestId` قد طرف إلى طرف وجود (`user-rpc` source عضو) ، ثاني عدد id سوف تكرار صلة ربط و مستو أبيض لمس اصطدام wire تحقق.

**حدث دخول مكتبة وقت تزامن إزالة عودة إظهار.**مرفوض: جلسة تجميع حسب حركة رسم لقطة إصدار، تزامن إزالة سوف يجعل رسالة فارغ واحد لقطة.steering طابور صف مرآة مثل تاريخ فوق قبول هذا عدد تنافس حالة؛ عودة إظهار مسار استخدام تصيير مدة ذهاب إعادة إضافة تأخير لقطة تراجع راحة إزالة حذف هو.

**يأخذ عودة إظهار بصفة دمج صار عقدة مشي جلسة assembler.**مرفوض:assembler فقط من durable session event قيادة، عميل مخصص تابع عقدة kind سوف يأخذ إغلاق دمج `ConversationNode` ربط دمج توسيع دخول كل target `assertNever`؛`PartialAssistant` صيغة جانب مسار حالة رمز دمج قائم أولا مثال.

**إبقاء composer تجميد ربط، فقط إضافة عودة إظهار.**مرفوض:issue تحقق استلام اشتراط وصل متابعة و تزامن إيداع، تجميد ربط composer سوف إعادة جذب دخول عودة إظهار هذا يلزم إزالة حذف بطاقة توقف شعور.
