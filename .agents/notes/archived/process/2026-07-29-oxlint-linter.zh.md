# Agent Note: استخدام Oxlint بصفة مستودع linter

Status: implemented
Archived: 2026-09-04

[English](2026-07-29-oxlint-linter.md) | العربية

## مشكلة

مستودع ذاتي لديه شفرة المصدر حاجة نوع شعور معرفة TypeScript صحيح تأكيد صفة قاعدة، متسق صيغة، و ملف داخل تكرار منطق فحص.ESLint عبر JavaScript محلل، مشروع خدمة و كثير عدد إضافة توفير هذه فحص، لكن في محلي ترحيل أساس خط فوق، مرة بلا مشكلة lint تشغيل نحو يحتاج 1 قسم ساعة، و كما حاجة 8 GiB Node كومة،CI نتيجة ذاكرة مؤقتة و مفرد وحيد ضبط أفضل ESLint تزامن درجة.

لا يستطيع بـ رفع عال تشغيل سرعة درجة لـ من فقد فقد قاعدة. ترحيل يجب إبقاء صارم إطار نوع فحص مسبق ضبط، مستودع تغطية إعداد، داخل ربط كبح صنع إشارة أمر،@stylistic إصلاح،SonarJS فحص،host/client TypeScript عزل و vendor ترتيب حذف قاعدة.

## قرار

أصل دليل [`.oxlintrc.json`](../../../../.oxlintrc.json) هو مستودع نوع شعور معرفة lint إعداد مرجعي مصدر. لا تحميل مشروع [`.oxlintrc.staged.json`](../../../../.oxlintrc.staged.json) إعداد وراثة ذلك شفرة المصدر قاعدة، لـ محدود pre-commit مسار منع استخدام نوع قسم تحليل، و إعادة قبول دخول نوع شعور معرفة خلفية لا يمكن قسم تحليل لكن يحتاج إبقاء TypeGraph fixture(اختبار قبل وضع بيانات).`lint` و `lint:fix` حزمة نص برمجي، بوابة مجدول،CI و lefthook عبر [`scripts/run-oxlint.ts`](../../../../scripts/run-oxlint.ts) استدعاء Oxlint؛[فقط استخدام Oxlint إصلاح سير العمل](2026-08-09-oxlint-only-fix-workflow.zh.md) مسؤول كثير جولة إضافة إصلاح، و يحل محل مفرد وحيد صيغة تحويل رجوع مسار.

`options.typeAware` تفعيل `oxlint-tsgolint`. ذلك خلفية حسب ملف اكتشاف TypeScript مشروع: حزمة شفرة المصدر استخدام كل منها حزمة مشروع،host اختبار و شبكة محطة شفرة المصدر استخدام `tsconfig.host.json`،client اختبار و `scripts/client-bundle-purity.spec.ts` استخدام `tsconfig.client.json`. لا يحتوي برنامج أصل حل قرار خطة أبدا سوف يتم مسطح مستو تحويل.Oxlint `--tsconfig` تغطية بند سوف أثر استيراد تحليل، لكن نوع شعور معرفة lint سوف تجاهل اختصار هو، لذلك هذا مستودع لا ضبط هذا خيار. هذا إعداد صريح تحميل دخول ترحيل بعد صارم إطار نوع فحص قاعدة و مستودع تغطية إعداد، بينما لا تفعيل محتوى ممكن حدوث تغير Oxlint عرض عام صنف آخر.`typescript/no-unnecessary-condition` ما زال من Oxlint nursery قاعدة تجميع في تفعيل، لأن هو في ترحيل قبل حينئذ هو مستودع قوي صنع تنفيذ قاعدة.

Oxlint JavaScript إضافة توافق طبقة تشغيل `@stylistic/eslint-plugin` و `eslint-plugin-sonarjs`، من بينما متابعة قوي صنع تنفيذ قائم صيغة و ملف داخل تكرار منطق قاعدة. توافق طبقة سوف تقرير إبلاغ `@stylistic` مخالفة قاعدة و تنفيذ ذلك أمان إصلاح؛`max-len` ما زال فقط لأجل تحقق. ذاتي لديه شفرة المصدر في كبح صنع إشارة أمر استخدام `oxlint-*` إشارة أمر و `typescript/*` نطاق الأسماء، لم استخدام إشارة أمر ما زال بصفة تحذير إبلاغ تقرير إبلاغ؛vendor شفرة المصدر إبقاء ذلك فوق تنقل إشارة أمر، لأن Oxlint سوف ترتيب حذف `vendor/**`.

CI لا استعادة أو حفظ lint نتيجة ذاكرة مؤقتة.`DSH_OXLINT_THREADS` جعل مشترك تشغيل جهاز سوف نفس حد أعلى نقل إعطاء Oxlint `--threads` خيار و نوع شعور معرفة خلفية `GOMAXPROCS` بيئة متغير؛ عادي محلي تشغيل مقابل اثنان من متساو اعتماد قيمة افتراضية.Pre-commit تشغيل لا تحميل مشروع Oxlint تحقق، تطبيق حمل مرة محدود إعادة محاولة أمان إصلاح، قبول فقط يحتوي قد تجاهل اختصار ملف ملف اختيار، و عبر lefthook إعادة مؤقت تخزين نتيجة. عام مشترك `lint` و CI سوف أولا دقيق تجهيز توليد إعلان، و إبقاء كامل نوع شعور معرفة قاعدة.

## تحقق

حل قرار اثنان موضع قسم تحليل جهاز فرق مختلف بعد، ترحيل بعد إعداد تقرير إبلاغ و ترحيل قبل متسق ذاتي لديه شفرة المصدر بلا مشكلة أساس خط: إزالة واحد بند زائد بقية اختبار تأكيد، بينما `tsc` اشتراط واحد موضع بنية صفة نوع تحويل استخدام ضيق نطاق Oxlint كبح صنع إشارة أمر. بـ قد حذف ESLint إعداد دقيق blob لـ أساس دقيق إجراء مرة صفة مراجعة نواة في إتمام قاعدة اسم خريطة بعد تأكيد: شفرة المصدر لـ 88 بند مقابل 88 بند، عرض مثال لـ 87 بند مقابل 87 بند، اختبار لـ 83 بند مقابل 83 بند. قد إيداع إشارة نقش قفل تحديد هذه مرور مراجعة نواة Oxlint قاعدة إعداد و كامل تغطية بنية؛ هو حيث لا تنفيذ قد حذف إعداد، أيضا لا قبول دخول لاحق فوق تنقل مسبق ضبط تغيير. مقابل `typescript-eslint@8.61.0` تقييم تقدير أيضا تأكيد،`strictTypeChecked` و لم تفعيل `@typescript-eslint/no-empty-function`؛ قد حذف، فقط لأجل اختبار `off` بند لا بدء أثر.

يمكن تنفيذ اتفاق اختبار اشتراط حزمة،host و client مشروع إنتاج نوع شعور معرفة تشخيص، تأكيد client مخصص استخدام نص برمجي الذي استخدام مشروع، رفض لم مطابقة رجوع قسم تحليل، و فحص تحقق Stylistic،SonarJS و nursery توافق مسار. هو جمع أيضا قفل تحديد مؤقت تخزين إعداد لا تحميل مشروع وراثة سلوك و TypeGraph fixture تغطية، لم استخدام كبح صنع إشارة أمر تقرير إبلاغ سلوك، فقط اختيار قد تجاهل اختصار مؤقت تخزين ملف حال حال، كامل Stylistic قاعدة تجميع، و استلام جمع بعد نهائي صيغة تحويل بايت. تشغيل جهاز اختبار قفل تحديد اثنان بند عمل خط مسار تحكم، نوع فحص فإن تأكيد ترحيل جذب إرسال شفرة المصدر تعديل لا يوجد كسر تالف TypeScript برنامج.

## اعتبار مرور بديل خطة

**في كل مستودع نطاق داخل معا تشغيل اثنان عدد linter.** كل صحيح تأكيد صفة قاعدة متساو يمكن عبر Oxlint أصلي قاعدة،nursery قاعدة أو JavaScript إضافة توافق طبقة نيل نيل. في كل مستودع نطاق تفعيل ESLint رجوع سوف إبقاء مقارنة بطيء مشروع خدمة ابتدائي تحويل و اثنان طقم صحيح تأكيد صفة إعداد، لكن لن زيادة أي فحص.

**استخدام مفرد وحيد صيغة تحويل جهاز.** ترحيل إبقاء ضيق نطاق ESLint مسار، لأن عند وقت إقرار لـ توافق طبقة لا يمكن تنفيذ إصلاح. قفل تحديد إصدار أداة سلسلة إثبات قدرة كاف تنفيذ نفسه إصلاح بعد،[فقط استخدام Oxlint إصلاح سير العمل](2026-08-09-oxlint-only-fix-workflow.zh.md) بـ مرة محدود إعادة محاولة يحل محل هذا جزء قرار.

**إزالة بعد بلا أصلي تنفيذ @stylistic أو SonarJS قاعدة.** هذا سوف إزالة اعتماد، لكن أيضا سوف تقليل ضعيف آلة آلة جودة كمية اتفاق. توافق طبقة سوف إبقاء هذه قاعدة، مباشر إلى قدرة كاف عبر مفرد وحيد قرار تقييم تقدير أصلي بديل قاعدة.

**ترحيل خلال استخدام Oxfmt استبدال @stylistic.** صيغة تحويل جهاز ترحيل سوف إنتاج تجاوز خروج lint جذب محرك حد إخراج تغير، و حمل قدوم كل مستودع صيغة diff. إبقاء قائم قاعدة يمكن جعل هذا مرة تغيير سهل في مراجعة، و يجعل صيغة تحويل جهاز اختيار إبقاء مستقل.

## نتيجة

محلي ترحيل قياس كمية عرض، لا استخدام نتيجة ذاكرة مؤقتة وقت، مرة بلا مشكلة نوع شعور معرفة lint تشغيل من نحو 61 ثانية تقليص قصير حتى نحو 8 ثانية. تأكيد قطع مقارنة مثال بسبب رئيسي آلة بينما مختلف، لا بنية صار صفة قدرة حفظ إثبات.

نوع شعور معرفة تشخيص الآن قدوم ذاتي عبر `oxlint-tsgolint` ربط ربط TypeScript Go قسم تحليل جهاز، لذلك أي جعل `tsc` قبول نفس برنامج، حد مشهد تحت نوع دفع قطع أيضا ممكن و typescript-eslint مختلف.lint و نوع فحص ما زال هو اثنان بند متبادل متبادل مستقل لا بد يلزم دليل.

JavaScript إضافة توافق API و مؤقت تخزين إعداد هو حاجة صيانة مقدار خارج حد. كل مرة إيداع يأخذ نوع شعور معرفة تشخيص إبقاء إعطاء عام مشترك lint و CI، و تجنب تجنب اعتماد توليد إعلان. كل مستودع تحقق، إصلاح، نوع شعور معرفة قسم تحليل، ذاكرة مؤقتة سياسة سياسة، عمل خط مسار تحكم و داخل ربط إشارة أمر ما زال من Oxlint مسؤول.
