# Agent Note: PR إلى Issue حالة فقط نحو قبل إلقاء إطلاق

Status: implemented
Archived: 2026-08-10

[English](2026-08-04-forward-only-pr-issue-status.md) | العربية

## مشكلة

Issue Project حالة يمثل عمل الذي موضع مرحلة مقطع، نفس مستودع داخل دقيق مطابقة حل قرار نوع صلة مفتاح حرف مرجع فإن بناء قيام مرجعي PR(Pull Request) إلى Issue علاقة. إذا فقط سماح قد موضع في `Ready` Issue دفع دخول دورة الحياة، أي جعل تنفيذ قد واضح بدء، موضع في `Inbox` أو `Backlog` Issue ما زال سوف توقف إبقاء في أصل حالة. فقط لديه PR بيانات وصفية في أخرى جهة وجه متساو صالح وقت عندئذ إلقاء إطلاق عمل مرحلة مقطع، أيضا سوف يأخذ سياسة سياسة دمج قاعدة صفة و يمكن مراقبة إلى عمل حالة خلط لـ واحد حديث.

## قرار

PR حدث و PR مراجعة حدث سوف يأخذ حالي PR مرحلة مقطع إلقاء إطلاق إلى نفس مستودع داخل من حل قرار نوع صلة مفتاح حرف دقيق مرجع كل Issue. مسودة مسودة PR، أو حيث لا يوجد مراجعة طلب أيضا لا يوجد قد إيداع مراجعة غير مسودة مسودة PR، هدف حالة لـ `In progress`. أداة تجهيز فوق وصف مهمة واحد صنف مراجعة نشط حركة غير مسودة مسودة PR، هدف حالة لـ `In review`.

نشط وثب حالة اعتماد مرة لـ `Inbox`،`Backlog`،`Ready`،`In progress` و `In review`. فقط لديه هدف حالة في هذا ترتيب في يقع في حالي حالة بعد وقت، إلقاء إطلاق عندئذ سوف كتابة. إلقاء إطلاق لن يأخذ Issue حالة نحو بعد نقل حركة، لن تعديل `Done` أو `No action`، أيضا لن يأخذ لا يوجد Project حالة Issue إضافة دخول Project. دورة الحياة مسار مستقل في PR بيانات وصفية تحقق؛ آخر سطر تنفيذ مطلوب PR سياسة سياسة فحص متابعة قوي صنع سقوط فعلي وسم، مرجع و أولوية درجة متسق صفة.

هذا بند إلقاء إطلاق لحظة معنى إبقاء مفرد نحو. هو لن من Issue عكس فحص صلة ربط PR، أيضا لن إضافة تحديد وقت مقابل حساب مهمة.PR حدث هو دفع دخول دورة الحياة مصدر.Issue إدارة اختبار سوف تحقق صاف دالة تنفيذ حالة تحويل قرار، و كما هذا اختبار سوف في `check-all`،`ci-primary` و `ci-static` بوابة في تشغيل.

## تحقق

`.github/issue-management/policy.test.mjs` تغطية من كل أكثر مبكر نشط وثب حالة دفع دخول، منطقة قسم مسودة مسودة و مراجعة حالة، مستقل في بيانات وصفية سياسة سياسة، و منع توقف حالة قلب تراجع أو تعديل نهاية حالة.`scripts/run-gates.ts` مسؤول في قمة طبقة محلي بوابة نمط و CI بوابة نمط في تنفيذ هذا بند مخصص بند سياسة سياسة اختبار.

## اعتبار مرور بديل خطة

**فقط سماح من `Ready` حالة دفع دخول.** هذا نوع خطة إبقاء شخص عمل قبل وضع شرط، لكن حل قرار نوع PR قد إثبات تنفيذ بدء بعد، ما زال سوف يجعل موضع في `Inbox` و `Backlog` بند إبقاء قديم قديم حالة.

**زيادة مزدوج نحو أو تحديد وقت مقابل حساب.** من Issue حدث عكس فحص PR، أو تحديد مدة مسح Project، يمكن إصلاح أكثر كثير تاريخ متروك إبقاء حالة؛ لكن هذا سوف إضافة جديدة واحد بند عكس نحو مرجعي حالة تحديث مسار، و زيادة دورة مدة صفة API عمل كمية، تجاوز خروج الذي يحتاج PR قيادة دورة الحياة نطاق.

**بـ كامل PR بيانات وصفية بصفة إلقاء إطلاق قبل رفع.** وسم، مرجع و أولوية درجة ما زال يجب قوي صنع سقوط فعلي، لكن بيانات وصفية نقص وقوع و لا يستطيع لا تحديد عمل فعلي موضع في تنفيذ أو مراجعة مرحلة مقطع.

**PR تحويل لـ مسودة مسودة أو فقد ذهاب مراجعة شخص وقت سوف حالة نحو بعد نقل حركة.** هذا سوف يجعل مؤقت PR حالة تغطية قد مراقبة إلى أكثر اعتماد بعد عمل مرحلة مقطع، أيضا سوف جعل حالة كل حق أكثر تكرار مختلط. لذلك، إلقاء إطلاق إبقاء مفرد ضبط.

## عاقبة

- PR حدث سوف تلقائي تصحيح صحيح من هذا PR حل قرار لكن ما زال توقف إبقاء في `Inbox`،`Backlog` أو `Ready` Issue.
- إذا Issue إنشاء في الأكثر بعد واحد متبادل صلة PR حدث بعد، فإن يجب انتظار لاحق PR حدث أو شخص عمل تحديث حالة، لأن نظام لن عكس نحو فحص بحث أو تحديد وقت مسح.
- أي جعل وجود تاريخ مراجعة نشط حركة، مسودة مسودة PR ما زال إبقاء `In progress`؛ فقط لديه غير مسودة مسودة PR عندئذ سوف بـ `In review` لـ هدف حالة.
- نهاية حالة و ترتيب في أكثر اعتماد بعد نشط وثب حالة لن قلب تراجع.
- مطلوب سياسة سياسة فحص ما زال سوف كشف PR بيانات وصفية خطأ، بينما لن لذلك منع توقف دورة الحياة إلقاء إطلاق.
