# Agent Note: doc-sync مشي بوابة مجدول

Status: implemented
Archived: 2026-07-26

[English](2026-07-21-doc-sync-through-gate-scheduler.md) | العربية

## مشكلة

`pnpm run doc-sync` أصل هذا هو يأخذ 24 عدد `pnpm run` فرعي أمر استخدام `&&` سلسلة بدء قدوم سلسلة. كل واحد حلقة كل يلزم أولا دفع مرة كامل pnpm حزمة تركيب طبقة بدء (workspace تحليل، نص برمجي فحص بحث،tsx بدء) عندئذ جولة إلى نص برمجي هذا جسم؛ في تطوير آلة فوق فعلي قياس،24 عدد نص برمجي هذا جسم دمج حساب نحو 34 ثانية يكفي ركض تمام، بينما سلسلة صيغة شكل استهلاك وقت نحو 3 قسم ساعة، كما حزمة تركيب طبقة توقف توقف في محلي مغناطيس قرص فوق نفس مثال تكرار الآن، لذلك كل موضع تطوير من و كل بند CI عربة طريق كل في دفع هذا قلم فتح إلغاء، و غير فقط لديه شبكة شبكة نظام الملفات فوق فحص خروج تلقي أثر. هذا بند سلسلة أيضا هو سلسلة سطر تنفيذ، كل إدارة كل عضو بوابة فقط قراءة كما متبادل متبادل مستقل؛ هو أيضا في صامت صامت انحراف مغادرة [scripts/run-gates.ts](../../../../scripts/run-gates.ts): وقت التشغيل API دليل سقوط أرض وقت `verify-cordis-api` إضافة دخول سلسلة، لكن من لم إضافة دخول `docSyncLeafGates`، توجيه يؤدي CI من لم يأخذ صلة هذا دليل جديد طازج درجة.

## قرار

`package.json` في `doc-sync` تفويض حمل إعطاء قائم محدود مجدول——`tsx scripts/run-gates.ts doc-sync`——و كل `check:ci:*` نص برمجي فعل قاعدة متسق ([و سطر بوابة ضبط درجة](2026-07-06-parallel-pre-push-gates.md) ،[حالي CI توسيع اندفاع](2026-07-22-evidence-based-larger-hosted-runners.md)).`doc-sync` نمط تماما جيد توسيع لـ `docSyncLeafGates()`، جعل `run-gates.ts` داخل ورقة فرعي قائمة يصبح عضو تجميع دمج وحيد حق مصدر. محلي نمط يأخذ افتراضي تزامن حد أعلى ضبط لـ أربعة عدد worker، لأن كثير عدد وثيقة بوابة كل منها يلزم بناء كامل `ts.Program`؛`DSH_GATE_CONCURRENCY` ما زال يمكن تغطية.

`docSyncLeafGates` يتضمن `verify-cordis-api`، لذلك متبادل صلة محلي وثيقة فحص و CI سوف نفس أخرى توليد وثيقة واحد بدء يأخذ صلة توليد وقت التشغيل API دليل.

## اعتبار مرور بديل خطة

- **إبقاء `&&` سلسلة، فقط تكملة ناقص ورقة فرعي**——قدرة إصلاح جيد اليوم يوم عائم نقل، لكن إبقاء اثنان نسخة أيضا سوف مجددا عائم نقل عضو قائمة، أيضا إبقاء 24 مرة سلسلة سطر pnpm حزمة تركيب طبقة بدء.
- **مخصص باب `scripts/doc-sync.ts` في مفرد عملية داخل import كل تحقق وحدة**——وصل كل بوابة tsx بدء أيضا قدرة حذف إسقاط، لكن حاجة يأخذ الكل 24 عدد نص برمجي من import أي تنفيذ تعديل صنع صار يمكن استدعاء مدخل، أيضا سوف فقد ذهاب مجدول حسب بوابة حساب وقت، عزل و فشل قسم مجموعة؛ بينما مجدول قد تجنب تجنب حزمة تركيب طبقة بدء عندئذ هو فتح إلغاء كبير رأس.
- **استخدام shell حلقة ركض `tsx scripts/*.ts`**——بـ منخفض صار هذا تجنب فتح pnpm حزمة تركيب طبقة بدء، لكن في CI قد استخدام مجدول جانب حافة زيادة ثاني طقم تنفيذ مفردات، كما لا يوجد هو أي ضبط درجة و تقرير إبلاغ قدرة.

## نتيجة

مرة `pnpm run doc-sync` صار هذا من 24 مرة حزمة تركيب طبقة بدء إضافة الكل عضو لـ و، تغيير لـ مرة حزمة تركيب طبقة بدء إضافة عضو بوابة في الأكثر بطيء اعتماد سلسلة. إضافة جديدة وثيقة بوابة فقط يحتاج في `docSyncLeafGates` تعديل واحد موضع (خارج إضافة package script ذاته بـ سهل يد عمل مفرد وحيد تشغيل) ؛`package.json` إبقاء كل `verify-*` نص برمجي بصفة يد عمل تشغيل مفرد عدد بوابة مفردات. مجدول إخراج حسب بوابة حساب وقت،doc-sync تغيير بطيء وقت قدرة مباشر إشارة نحو احتلال كبير رأس بوابة.`pnpm run doc-sync` إخراج من تدريجي أمر ترتيب إخراج تغيير لـ مجدول تسليم خطأ إخراج؛ تحليل هذا إخراج أداة يجب بـ `run-gates:` ملخص سلوك دقيق.
