# Agent Note: في Linux runner فوق استخدام Wine تشغيل Windows منع قطع بوابة

Status: implemented
Archived: 2026-08-08

[English](2026-07-27-wine-windows-gates-experiment.md) | العربية

## مشكلة

Pull request Windows عبر طريق غاية في تحقق اثنان عدد منع قطع صفة win32 جدول وجه، أي workspace بناء و إنتاج محطة نقطة. هذا عبر طريق هذا قبل تشغيل في حمل إدارة `windows-2025` فوق، هو مطلوب مستطيل دفعة في الأكثر بطيء عمل عمل: استهلاك وقت 7–9 قسم ساعة، بينما Linux عمل عمل استهلاك وقت 1.5–2.5 قسم ساعة، لذلك Windows VM بدء، دقيق تجهيز و نظام الملفات فتح إلغاء رئيسي توجيه كل pull request صلة مفتاح مسار.

فعلي تحقق عودة جواب مشكلة هو: واحد منصة عادي Linux runner قدرة لا بـ Linux عمل عمل جدار ساعة وقت لـ هذه منع قطع جدول وجه إنتاج خروج انتظار فاعلية win32 إشارة، يجعل pull request مسار فوق تماما لا يوجد Windows VM؟

## قرار

[ci.yml](../../../../.github/workflows/ci.yml) في مطلوب pull request `windows` عمل عمل (`windows node 24 / wine blocking`) في `ubuntu-latest` فوق عبر Wine استخدام حقيقي Windows اثنان دخول صنع تشغيل منع قطع بوابة أمر: تحقق و تحقق مرور win-x64 Node.js تنفيذ `tsc -b`،`tsdown` و VitePress إنتاج بناء، لذلك أداة سلسلة win32 فرع——عكس مائل عمود مسار معالجة،`CreateProcess` إرسال توليد دلالة،`@esbuild/win32-x64` PE تحميل، و rolldown/rollup MSVC `.node` إضافة——كل حق صحيح تنفيذ.master `serial-windows` عمل عمل أصل غلاف لا حركة: كامل أصلي داخل نواة بيان، يشمل هذا عبر طريق لا تشغيل مراقبة صفة يمكن نقل غرس صفة بوابة، ما زال في كل مرة master push وقت في حقيقي `windows-2025` فوق تنفيذ.

اعتماد في Linux فوق أصلي تثبيت،`supportedArchitectures` توسيع إلى win32-x64، جعل Windows منصة حزمة شيء تحويل دخول نفس عدد store؛ عبر مباشر استدعاء كل أداة JavaScript مدخل التفاف فتح cmd-shim طبقة، هذا صحيح هو `run-gates` نهائي إرسال توليد ذلك بعض عملية.`nodeLinker: hoisted` هو تحمل إعادة، لا هو ريح إطار مشكلة: واحد مستقل أصل نوع إبقاء pnpm افتراضي isolated تخطيط——يشمل في Linux مسبق أخذ store فوق وفي فعلي أرض استخدام Windows pnpm مغادرة خط إعادة تركيب——بينما Wine تحت Windows Node اعتماد لكن لا يمكن اختراق مرور isolated رمز رقم رابط سلسلة تحليل `@esbuild/win32-x64` أو تحميل koffi مسبق تحرير ترجمة ناتج، في أي مستودع بوابة تشغيل قبل حينئذ فشل. مسطح مستو حقيقي ملف تخطيط عندئذ يجعل بوابة تغيير نيل يمكن بلوغ؛ هذا عبر طريق قبول هذا أصل نوع تحقق و ثابت، معا واضح وضع ترك ذلك «Windows pnpm تثبيت اعتماد شجرة» هدف (تثبيت عقد نحو في هذا ما زال من Linux جانب تحقق).

هذا عبر طريق اعتماد أربعة عدد عمود عمود يأخذ جدار ساعة وقت إبقاء في و Linux CI عمل عمل متبادل عند ماء مستو:master تحديث جديد pnpm store ذاكرة مؤقتة (فقط استعادة، و Linux عمل عمل نفس مفتاح) ،Wine توفير إعطاء (apt تثبيت،Windows Node تحت تحميل،`wineboot`) و `pnpm install` تزامن تشغيل، اثنان عدد منع قطع جدول وجه تزامن تشغيل——و `run-gates` في أصلي Windows فوق إعطاء هو جمع شكل حالة نفسه——و حسب runner مرآة مثل لـ مفتاح apt عودة ملف ذاكرة مؤقتة، من master `wine apt cache` عمل عمل بث نوع، جعل كل pull request كل قدرة من افتراضي فرع أثر مجال استعادة.

بوابة منطق تجميع في في واحد نص برمجي داخل،[scripts/wine-windows-gates.sh](../../../../scripts/wine-windows-gates.sh):ci.yml عمل عمل فقط توفير إعطاء runner حالة (ذاكرة مؤقتة،apt Wine) لكن بعد استدعاء هو، اختياري محلي بوابة `pnpm run check:windows-wine` في تركيب لديه Wine تطوير آلة فوق تشغيل نفس عدد نص برمجي——مفرد واحد تنفيذ، لذلك محلي تكرار الآن أحمر لون CI عبر طريق لا حاجة في بيئة بين فعل أي تحويل ترجمة. هذا محلي بوابة هو تشخيص أداة بينما غير مثال سطر فحص: فقط في ترتيب فحص معروف Windows متبادل صلة فشل وقت تشغيل؛ يوم معتاد win32 إشارة عودة CI كل،[dsh-pre-push-checks](../../../skills/dsh-pre-push-checks/SKILL.md) أيضا من لا اختيار هو. نص برمجي من لا تعديل عمل شجرة: يأخذ قد تتبع أثر ملف و لم تتبع أثر لكن لم تجاهل اختصار ملف لقطة دخول واحد مؤقت دليل، فقط مقابل لقطة تطبيق إضافة Wine خاص لديه pnpm تغطية، و في ذلك داخل مقابل حال مشترك store تثبيت؛Wine prefix و تحقق و تحقق مرور Windows Node zip حمل دائم تخزين وضع في `.cache/wine-windows/` تحت، محلي إعادة ركض قفز مرور توفير إعطاء،nodejs.org غير ممكن بلوغ وقت رجوع إلى الأكثر جديد قد ذاكرة مؤقتة zip.

خمسة بند بيئة قيد تشكيل صنع CI و محلي تنفيذ، كل بند كل بـ مرة أحمر لون تشغيل يتم اكتشاف:Ubuntu `wine64` حزمة ذاته لا نحو PATH وضع أي شرق غرب (يلزم تركيب `wine` مجدول) ؛Wine تحت Node لا يمكن يأخذ stdio وصل إلى استدعاء جهة إدارة طريق فوق (جذب توجيه مدة `Socket open EBADF`——كل استدعاء كل مرور ملف في تحويل stdio) ؛Wine لا مقابل pnpm isolated تخطيط Unix رمز رقم رابط فعل realpath(أي فوق نص hoisted تخطيط) ؛macOS Wine أيضا سوف يأخذ hoisted workspace رابط كشف لـ عادي دليل، لذلك client اختبار تجمع دمج سوف قبول دخول كل حزمة ذاتي ذات CSS وحدة إعلان، بينما لا اعتماد project-reference realpath؛Wine لا يمكن إنشاء Windows رمز رقم رابط (VitePress `linkVue` تقرير `ENOTSUP`——`vue` رابط في بوابة قبل من مضيف جانب فرش جيد).

## فعلي قياس نتيجة

2026-07-27 فعلي قياس، حار ذاكرة مؤقتة،pull request إطلاق، معيار 2 نواة `ubuntu-latest`: طرف إلى طرف 2 قسم 46 ثانية——دقيق تجهيز و ذاكرة مؤقتة استعادة نحو 17 ثانية، تزامن تثبيت+توفير إعطاء 33 ثانية، تزامن بوابة 110 ثانية——مقابل وفق Linux CI عمل عمل 1.5–2.5 قسم ساعة و يتم استبدال `windows-2025` عمل عمل 7–9 قسم ساعة. بارد ذاكرة مؤقتة نحو كثير دفع واحد قسم ساعة. فعلي تحقق خلال تعريف مرور 8 نواة أساس دقيق اختبار عمل عمل، لكن هو من لم مغادرة فتح تلقي حد `dsh-ubuntu-*` حوض طابور صف؛ معيار runner عدد حرف قد بلوغ علامة، لذا لا استخدام أكثر كبير آلة جهاز.

## اعتبار مرور بديل خطة

**إبقاء حمل إدارة `windows-2025` pull request عمل عمل (الآن حالة).** ذلك إشارة لا يوجد مشكلة، مشكلة فقط في تأخير متأخر: لـ اثنان بند بناء أمر زهرة 7–9 قسم ساعة، هو مطلوب مستطيل دفعة في الأكثر بطيء عمل عمل. هو بصفة master سلسلة سطر مشاركة وفق تخزين متابعة——في ذلك داخل كامل صفة مقارنة تأخير متأخر أكثر إعادة يلزم.

**في Linux runner داخل استخدام QEMU/KVM ركض كامل Windows عميل مستخدم آلة.** حقيقي NT داخل نواة، حفظ حق درجة كامل، يشمل كبير صغير كتابة لا حساس شعور NTFS و ConPTY——لكن أول عدد بوابة تشغيل قبل يلزم زهرة عدد عشرة قسم ساعة تحت تحميل مرآة مثل و فعل بلا شخص قيمة حراسة تثبيت (أخ أخ فعلي تحقق فرع `exp/kvm-windows-ci` فعلي قياس طرف إلى طرف 40 قسم 19 ثانية). فقط لديه إعداد فوق سوف ضغط ضغط Actions ذاكرة مؤقتة ميزانية مغناطيس قرص مرآة مثل ذاكرة مؤقتة عندئذ يمكن إلقاء دخول استخدام.

**في Wine تحت من Windows pnpm تنفيذ تثبيت.** نفس تفكير قاعدة أكثر عال حفظ حق درجة تغيير جسم: يأخذ MinGit و pnpm وضع دخول prefix، استخدام Linux مسبق أخذ ملء ملء store، مجددا من Windows Node تشغيل `pnpm install --offline`، يجعل تثبيت عقد نحو ذاته بـ win32 هوية تنفيذ. هو وصول تثبيت لكن لا وصول بوابة——Wine شبكة شبكة لا يمكن مباشر وصول registry، كما isolated `node_modules` تخطيط أي سهل في جاف صاف مغادرة خط تثبيت بعد أيضا إحباط فشل Windows منصة حزمة تحليل. هذا عبر طريق تضحية قربان هذا نسخة حفظ حق درجة (hoisted تخطيط،Linux جانب تثبيت) قدوم تبديل أخذ بوابة يمكن بلوغ؛ اثنان نسخة سجل هو نفس قطع قرار متبادل تكملة اثنان نصف.

**Linux فوق نظام الملفات دلالة عبر طريق (casefold ext4، ملف اسم lint).** بـ قريب صفر صار هذا التقاط الأكثر عال تردد Windows لذا عائق صنف آخر، لكن مقابل win32 اثنان دخول صنع ماذا أيضا إثبات لا. بصفة أخ أخ فعلي تحقق فرع `exp/casefold-windows-ci` استكشاف؛ و هذا عبر طريق متبادل تكملة بينما غير تنافس تنازع.

**Windows حاوية.** غير ممكن سطر:Windows حاوية اشتراط Windows مضيف داخل نواة؛ حمل إدارة Linux runner لا يمكن تشغيل.

**قطع إسقاط Windows عبر طريق.** قد مرفوض——win32 هو واحد انتظار منتج هدف: أساس في koffi DACL و حمل دائم نطاق الأسماء وحدة، أساس في ConPTY PTY جلسة، و Windows مسار سياسة كل مع `packages/` تسليم.

## عاقبة

كل pull request Windows قطع قرار الآن كل قدرة في Linux عمل عمل استهلاك وقت نطاق داخل، فائدة استخدام تجنب استهلاك معيار runner سعة كمية نيل خروج،pull request صلة مفتاح مسار فوق لم يعد لديه أي Windows VM قسم إعداد؛`all checks passed` إزالة استهلاك ما زال هو أصل قدوم `windows` عمل عمل id.

هذا قلم تسليم سهل بديل قيمة:Wine في كبير صغير كتابة حساس شعور ext4 لـ فوق إعادة تنفيذ Win32——NTFS كبير صغير كتابة لا حساس شعور، حقيقي DACL،ConPTY و انهيار انهيار حمل دائم صفة دلالة في هذا كل لم يتم إثبات، كما مراقبة صفة يمكن نقل غرس صفة بيان (duplication،publint،node-next نوع،win32 فوق قد بناء حزمة ثابت كمية) تماما لم يعد في pull request فوق تشغيل. هذا واحد قطع متساو من master `serial-windows` مشاركة وفق مسؤول تحقق:Wine أخضر مصباح pull request ما زال ممكن في أصلي داخل نواة master تشغيل فوق فشل، مشروع قبول هذا نوع فشل ممكن في دمج بعد عندئذ ظهور. هذا عبر طريق أيضا سوف Wine خاص لديه فرق مختلف ثابت تحويل لـ دائم دائم عمل عمل بنية——ملف في تحويل stdio، مضيف جانب `vue` رابط،hoisted تخطيط——لذلك لم قدوم اعتماد isolated تخطيط دلالة أو عملية داخل رمز رقم رابط إنشاء أداة سلسلة تغيير سوف أولا في هذا داخل بـ Wine فشل بينما غير منتج فشل شكل صيغة طفو الآن، قسم تشخيص يجب مثل هذا عودة صنف. إذا Wine أحمر مصباح في بلا منتج سبب حال حال تحت عكس تكرار ظهور، سجل في سجل تراجع مسار هو يأخذ `windows` عمل عمل أيضا أصل لـ git تاريخ في حفظ Wine قبل `windows-2025` تعريف.
