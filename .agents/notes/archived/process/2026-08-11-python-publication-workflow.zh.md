## مشكلة

Python SDK من واحد منصة غير متصل عميل wheel حزمة و خمسة عدد أصلي وقت التشغيل wheel حزمة مجموعة صار، هو جمع يجب استخدام نفس إصدار، و بصفة واحد مجموعة يمكن تثبيت.public PyPI فوق نقل سوف قيام أي عام حزمة بيانات وصفية و ملف، لا يمكن استبدال قد فوق نقل نفس اسم ملف؛ إذا دقيق إصدار وقت التشغيل اعتماد بعد لم وصول، أيضا سوف إنتاج مؤقت وقت غير ممكن استخدام SDK. خاص مستودع حاجة في لا نحو خارج إصدار أي ناتج حال حال تحت، تنفيذ كامل أصلي بناء و تحقق مسار.

## قرار

GitHub `Release (Python)` سير العمل لـ ضبط `publish=false` يد حركة تشغيل توفير بلا اعتماد تحقق. هذا تشغيل سوف لـ الكل خمسة عدد هدف استدعاء أصلي wheel حزمة بناء جهاز، في Python 3.10 و 3.14 فوق تثبيت Linux إرسال سطر تجميع دمج، تحت تحميل الذي نيل ستة نسخة ناتج، تحقق ذلك دقيق ملف اسم و حزمة بيانات وصفية، تنفيذ PyPI افتراضي مفرد ملف كبير صغير حد، سجل SHA-256 ها أمل، و إبقاء واحد نسخة تجميع مجموع مرشح إرسال سطر إصدار. هذه عمل عمل فقط لديه مستودع قراءة إذن، لا يوجد سجل التسجيل اعتماد أو OIDC إذن،dry-run تشغيل لا يمكن دخول أي إصدار عمل عمل.

ضبط `publish=true` وقت، تشغيل يجب في خاص تلقائي تحويل مستودع استخدام `python-v<repository-version>` وسم، سوف هذا مستودع `github.repository` و ذلك مستودع درجة `PYPI_PUBLISHER_REPOSITORY` متغير مطابقة، بحث إلى `PUBLIC_PYPI_RELEASE_ENABLED=true`، و قسم آخر نيل نيل GitHub `pypi-runtime` و `pypi` بيئة مقابل وقت التشغيل و SDK إصدار دفعة دقيق. فقط قراءة عام مرآة مثل توفير حزمة بيانات وصفية URL، لكن لا تشغيل إصدار Actions. فقط لديه اثنان عدد إصدار عمل عمل نيل نيل `id-token: write`؛PyPI Trusted Publishing سوف يأخذ خاص مستودع هوية تبديل صار قصير مدة مشروع اعتماد، لذلك مستودع لا حفظ PyPI token.

إصدار مرور مسار استخدام نفس مرة سير العمل تشغيل في توليد و فحص مرور تجميع مجموع ناتج. كل إصدار عمل عمل كل سوف في اختيار فوق نقل ملف قبل تحقق إبقاء `SHA256SUMS`. واحد وقت التشغيل عمل عمل أولا فوق نقل الكل خمسة عدد منصة wheel حزمة، مجددا من اعتماد هو عمل عمل فوق نقل SDK wheel حزمة، لأن PyPI فوق نقل لا هو أصل فرعي عملية، بينما SDK سوف يأخذ وقت التشغيل توزيع حزمة ثابت إلى تماما نفسه إصدار. اثنان عدد عمل عمل كل لن فحص خروج شفرة المصدر، أيضا لن إعادة بناء wheel حزمة. سوف هو جمع تفكيك فتح بعد،GitHub فشل عمل عمل إعادة محاولة يمكن في SDK فوق نقل فشل وقت متابعة تنفيذ، بينما لن محاولة تجربة استبدال غير ممكن تغيير وقت التشغيل ملف.

اثنان عدد إصدار action كل سوف منع استخدام عام attestation.action ما زال استخدام Trusted Publishing إجراء هوية إقرار إثبات، معا لا فوق نقل سوف كشف كشف خاص إصدار مستودع بينما غير عام شفرة المصدر مرآة مثل provenance.

مستودع إصدار يمكن هو مستقر إصدار، أيضا يمكن استخدام تلقي دعم حمل مسبق إصدار كتابة قاعدة. وسم إبقاء مستودع كتابة قاعدة،wheel حزمة ملف اسم، بيانات وصفية، اعتماد إصدار ثابت و ناتج فحص بحث فإن استخدام مواصفة تحويل PEP 440 كتابة قاعدة.

وقت التشغيل حزمة `platforms.json` هو أصلي wheel حزمة وسم و يمكن تنفيذ ملف اسم واقع مصدر. مستودع إرسال سطر بناء جهاز و عزل Hatch بناء خطاف سوف قسم آخر تحقق و تحميل هذا ملف.GitHub Actions و GitLab CI مقابل وقت التشغيل يمكن تنفيذ ملف و ذلك مطلوب spawn helper استدعاء نفس عدد مستودع ذاتي لديه macOS نشر هدف فحص، لذلك wheel حزمة في كل Mach-O ملف كل يجب رمز دمج إعلان منصة وسم.

اثنان عدد Python بناء نظام اعتماد كل ثابت استخدام Hatchling 1.30.1. تحت واحد متاح Hatchling إصدار سوف توليد Core Metadata 2.5، بينما ثابت استخدام Twine 6.2.0 تحقق جهاز سوف رفض هذا إصدار؛ دقيق ثابت بناء جهاز بعد، محلي،GitHub و GitLab إخراج سوف إبقاء متسق، مباشر إلى تحقق أداة سلسلة دعم حمل هذا بيانات وصفية إصدار.

## اعتبار مرور بديل خطة

**استخدام TestPyPI عرض تدريب.** TestPyPI هو عام بحث جذب، فوق نقل سوف في مستودع فتح وضع قبل كشف حزمة اسم، بيانات وصفية و wheel حزمة محتوى. بلا اعتماد تجميع مجموع ناتج و قائم خاص GitLab حزمة سجل التسجيل يمكن تغطية تحقق و فوق نقل بروتوكول عرض تدريب، بينما لن صنع صار هذا نوع كشف كشف.

**استخدام طويل مدة PyPI API token.** حفظ token سوف يجعل غير متصل سير العمل خطوة وصل لمس يمكن إعادة استخدام مفتاح، و حاجة شخص عمل جولة تبديل.Trusted Publishing يأخذ اعتماد حد إلى قد تسجيل تسجيل مستودع، سير العمل و بيئة، و كما فقط لـ كل تلقي حفظ حماية إصدار عمل عمل توليد اعتماد.

**في إصدار عمل عمل في إعادة بناء.** ثاني مرة بناء ممكن و عبر أصلي خطر دخان اختبار مرشح ناتج مختلف. إصدار مرور مسار تحت تحميل و استخدام نفس دفعة قد إبقاء ملف، كما لا فحص خروج أي شفرة المصدر.

**أولا فوق نقل SDK، مجددا فوق نقل وقت التشغيل تحميل جسم.** إذا لاحق فوق نقل فشل،SDK سوف أولا عام، بينما ذلك دقيق اعتماد ما زال غير ممكن استخدام. وقت التشغيل أولوية ترتيب جعل جزء فشل لن إنتاج إشارة نحو ناقص ملف يمكن تثبيت عميل.

**من عام مرآة مثل إصدار.** عام مرآة مثل هو فقط قراءة شفرة المصدر إسقاط، لا تشغيل إصدار Actions. سوف PyPI Publisher ربط إلى هذا مرآة مثل بعد، لا يوجد عمل سالب تحميل قدرة كاف توفير قد تسجيل تسجيل OIDC هوية.

**إصدار عام attestation.** action افتراضي سلوك سوف يجعل Trusted Publisher مستودع هوية يمكن عام تحقق. هذا provenance معرف خاص تلقائي تحويل مستودع بينما غير حزمة عام شفرة المصدر مرآة مثل، لذلك إصدار عمل عمل سوف ذلك منع استخدام.

## عاقبة

كامل مرشح إرسال سطر إصدار و عام إصدار كل من خاص تلقائي تحويل مستودع تشغيل. اختيار `publish=true` بعد، فقط لديه إصدار مستودع متغير، إصدار فتح صلة و وسم كل قدرة معرف مرة متعمد عام إصدار، سير العمل عندئذ سوف دخول تلقي حفظ حماية إصدار عمل عمل، لا فإن سوف رفع قبل فشل. مرآة مثل شفرة لن نسخ هذه خاص مستودع ضبط، لذلك فقط قراءة عام مرآة مثل لا يمكن ممتلئ كاف تخويل فحص.

خاص تلقائي تحويل مستودع owner و مستودع اسم، سير العمل ملف اسم و كل عمل عمل بيئة (وقت التشغيل استخدام `pypi-runtime`،SDK استخدام `pypi`) كل هو Trusted Publisher هوية واحد جزء. شفرة المصدر مستودع تحويل نقل، سير العمل تعديل اسم أو بيئة تعديل اسم بعد، يجب تحديث تلقي أثر PyPI Publisher؛ مستودع هوية تغير وقت أيضا يجب تحديث إصدار مستودع متغير. فقط قراءة عام مرآة مثل حدوث تغير وقت، حاجة تعديل هو حزمة بيانات وصفية URL، بينما لا هو إصدار هوية.

اثنان عدد توزيع مشروع بين PyPI إصدار ما زال لا هو أصل فرعي عملية. وقت التشغيل أولوية ترتيب سوف تقليص صغير مرئي فشل حالة؛ مستقل إصدار عمل عمل و تحقق و تحقق فإن يجعل فشل SDK فوق نقل قدرة كاف من مرور مرور فحص دقيق ملف متابعة تنفيذ، و كما أبدا استبدال قد فوق نقل نفس اسم ملف.

منع استخدام عام attestation سوف وضع ترك فوق نقل هوية عام سري رمز تعلم provenance.Trusted Publishing ما زال سوف إقرار إثبات كل مرة فوق نقل، بينما إبقاء تجميع مجموع ناتج سوف في خاص إصدار سير العمل داخلي حفظ مرور مرور فحص wheel حزمة ها أمل.

ترقية Hatchling وقت، يجب أولا استخدام إصدار خط الإنتاج ثابت Twine إصدار تحقق ذلك توليد Core Metadata إصدار، مجددا معا تعديل اثنان عدد حزمة بناء اعتماد.
