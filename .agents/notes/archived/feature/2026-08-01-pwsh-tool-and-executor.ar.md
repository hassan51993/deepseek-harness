# Agent Note: PowerShell منفذ و pwsh أداة

Status: implemented
Archived: 2026-09-04

[English](2026-08-01-pwsh-tool-and-executor.md) | العربية

## مشكلة

harness في كل منصة فقط قول واحد نوع shell جهة قول:`bash`.Windows رئيسي آلة فقط قدرة عبر WSL أو Git-Bash وسادة قطعة تشغيل هو، بينما تسليم `dsh-bash-local` منفذ فقط حد POSIX(صلب تحرير رمز `bash`، عملية مجموعة دلالة هو POSIX ).Windows مسار خط رسم——يجعل رئيسي آلة افتراضي `pwsh`، بعد مجددا فعل pwsh TUI/GUI تصيير——لا يوجد تنفيذ أساس أساس: حيث لا يوجد bash منفذ seam PowerShell تنفيذ، أيضا لا يوجد تعليم نموذج PowerShell جهة قول موجه إلى نموذج أداة.bash أداة أيضا كبير في Windows أولوية رسم مثل صارم إطار الذي يحتاج——خاصة ذلك حمل دائم PTY توأم توليد هو `pwsh` أداة حتى اليوم ما زال لا خلف سالب bash شكل حالة جدول وجه. الأكثر أول الأكثر صغير رسم مثل أيضا لا يوجد خلفية مهمة و صندوق رملي ترقية: خلفية مع [parity قرار](2026-08-02-pwsh-tool-bash-parity.ar.md) إلى قدوم، صندوق رملي وجه (رفض تصيير إضافة `sandbox_permissions` ترقية) مع [Windows ACL sandbox قرار](2026-08-08-windows-acl-restricted-token-sandbox.ar.md) إلى قدوم——الأكثر صغير أداة عند أول حسب danger-full-access Windows وضع حالة قطع قص، هذا واحد قبل رفع في sandbox PR(Pull Request) في Windows فوق إعادة تفعيل عزل و مراجعة دفعة وقت نهاية ربط.

## قرار

في `packages/shell/` تحت إضافة جديدة اثنان عدد حزمة:

- **`@deepseek-ai/dsh-pwsh-local`** —— `ctx.shell` منفذ seam محلي تنفيذ، أساس في `ctx.subprocess`، تدريجي استدعاء مرآة مثل `dsh-bash-local`:`resolve()` من إعداد افتراضي تحويل و ضبط حد أعلى،`run()` عبر واحد deadline دمج دمج إعداد مشبك أخذ مهلة و استدعاء جهة إشارة،`start()` إرجاع إزالة استهلاك صيغة خلفية جملة مقبض، ذلك عملية ملكية في subprocess خدمة. أمر نص بصفة مفرد عدد argv معامل نقل إعطاء `pwsh -NoLogo -NoProfile -NonInteractive -Command`، من PowerShell تحليل، لا وجود shell جذب رقم طبقة. يمكن تنفيذ ملف تحليل (`resolvePwshPath`) هو `(configured, env, platform)` صاف دالة: أولا صريح إعداد، مجددا في Windows فوق استكشاف قياس PowerShell 7 تثبيت موضع،PATH بند (تقشير مغادرة جذب رقم) و Windows PowerShell 5.1، لا فإن إرجاع عار أمر اسم `pwsh`، تسليم من عملية بدء وقت حسب PATH تحليل.
- **`@deepseek-ai/dsh-tool-pwsh`** —— أساس في `ctx.shell` موجه إلى نموذج أداة، اتفاق هو PowerShell جهة قول، تدريجي استدعاء مرآة مثل `dsh-tool-bash`: مرور عام مهمة وقت التشغيل تنفيذ قبل منصة و `run_in_background`، مرور مشترك [`dsh-shell-env`](../feature/2026-08-02-pwsh-tool-bash-parity.ar.md) سجل التسجيل إدارة `DSH_*` بيئة،bash marker/قطع قطع تصيير آلية (جاف صاف خروج لا إنتاج marker) ، و——ذاتي Windows ACL sandbox قرار بـ قدوم——صندوق رملي رفض تصيير و `sandbox_permissions` ترقية وجه، خارج إضافة أداة وصف في Windows مخصص تابع ConstrainedLanguage و تسمية إدارة طريق اتفاق.parity قرار يحل محل هذا Agent Note الأكثر صغير رسم مثل أداة وصف.

Windows vitest نسبة التغطية لحظة معنى لا تابع هذا مرة تعديل: مستودع Windows CI عبر طريق مسؤول بناء/ساكن حالة بوابة، وحدة تغطية في Linux فوق تشغيل، اثنان عدد حزمة طقم عنصر في ذلك داخل بـ حقيقي `pwsh` تشغيل (GitHub حمل إدارة runner مسبق تركيب) أو ناقص وقت ذاتي سطر قفز مرور.vitest `windowsUnsupportedPackages` ترتيب حذف من `packages/shell/*` استلام ضيق لـ حق صحيح حاجة bash حزمة، جعل pwsh طقم عنصر أيضا قدرة في Windows تطوير آلة فوق أصلي تشغيل.

هذا قرار بعد مسار خط رسم——يجعل Windows رئيسي آلة افتراضي `pwsh`(إغلاق bash) و pwsh TUI/GUI تصيير——قد آخر سطر سجل لـ [Windows افتراضي pwsh قرار](2026-08-01-windows-pwsh-default.ar.md).

## تجهيز اختيار خطة

**إعطاء `dsh-bash-local` زيادة pwsh نمط.** مرفوض: منفذ هوية حينئذ هو هو spawn shell؛ في واحد حزمة داخل سد ثاني نوع جهة قول سوف قلب ضعف إعداد وجه (`shell` فتح صلة) و اختبار مستطيل دفعة، كما اثنان نوع جهة قول غريب ميل (Windows فوق إشارة معلومة، جذب رقم مجال) ينبغي كل منها عودة دخول ذاتي ذات حزمة وثيقة.

**إعطاء `dsh-tool-bash` زيادة جهة قول معامل.** مرفوض: نموذج مرئي اتفاق ذاته حينئذ هو جهة قول (مسار، متغير، خروج واقع كل مختلف) ، لذلك جهة قول معامل يلزم ما يجعل schema مع شرط تغير، يلزم ما إجبار واحد أداة تعليم اثنان نوع جهة قول؛ مستقل توأم توليد يجعل نموذج اتفاق إبقاء صدق فعلي——و بـ مرآة مثل بينما غير مشترك تنفيذ طريقة يحمل مشترك جدول وجه (خلفية، صندوق رملي، تصيير).

**الآن حينئذ وصل دخول تسليم CLI(أمر سطر واجهة) تركيب.** مرفوض: في Windows افتراضي قرار سقوط أرض قبل يأخذ `tool-pwsh` + `pwsh-local` تعليق دخول `base.cordis.yml` سوف تغيير تسليم بيان؛ هذا تعديل تسليم قدرة و وصل خط نقطة (`apps/cli` اعتماد،tsconfig عمل مسار) ، لا تبديل أي افتراضي.

## عاقبة

- bash منفذ seam لديه ثاني عدد،Windows أصلي تنفيذ، طلب/مواصفة اتفاق متسق، لذلك `tool-pwsh` خارج موجه إلى نموذج مستهلك (خطاف جسر، عملية داخل إضافة) بلا حاجة جهة قول وسادة قطعة يكفي تشغيل PowerShell.
- `tool-pwsh` هو نموذج مرئي Windows أولوية shell أداة: في قبل منصة، خلفية و صندوق رملي تحويل عمل فوق و bash أداة سلوك يمكن متبادل تبديل——يشمل مرور `ctx.approval` نفس جولة `sandbox_permissions` ترقية——نص التوجيه إشارة توجيه دقيق قديم وصف marker اتفاق، صندوق رملي رفض/ترقية مفردات، و ConstrainedLanguage و تسمية إدارة طريق حد.
- Windows دلالة في منصة فرق مختلف موضع مختلف: قوي صنع إنهاء تقرير إبلاغ خروج رمز 1 كما بلا إشارة (لذلك `signal`/`killed` حالة معلومة فقط حد POSIX) ،PowerShell إخراج CRLF، اختبار فعل عودة واحد تحويل.
- CLI زيادة اثنان عدد workspace اعتماد و اثنان عدد tsconfig عمل مسار، لكن لا تركيب مهمة واحد إضافة——تركيب قرار إبقاء إعطاء Windows افتراضي رفع سجل.
