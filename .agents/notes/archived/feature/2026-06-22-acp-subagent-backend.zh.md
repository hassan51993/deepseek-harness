# Agent Note: ACP subagent خلفية (عملية خارج تفويض إرسال)

Status: implemented
Archived: 2026-09-04

[English](2026-06-22-acp-subagent-backend.md) | العربية

## مشكلة

subagent seam([seam Agent Note](2026-06-21-subagent-capability-seam.zh.md)) تصميم جعل كثير عدد خلفية يمكن حسب اسم مشترك تخزين في `ctx.subagents`. عملية داخل خلفية (`-spawn`/`-fork`) سوف فرعي agent(ذكي جسم) بصفة ثاني عدد `Agent` تشغيل في نفس عدد Cordis سياق في: فتح إلغاء منخفض، لكن فرعي agent و أب agent مشترك عملية، نموذج عميل و أداة.seam نواة قلب معنى معنى في في معا دعم حمل عبر بروتوكول وصول عملية خارج فرعي agent، بـ إثبات هذا سحب كائن يمكن عبر عملية حد ملائم استخدام. هذا Agent Note إضافة رقم واحد هذا صنف خلفية: واحد ACP(Agent Client Protocol) عميل.

## قرار

`@deepseek-ai/dsh-subagent-acp` تسجيل واحد `SubagentProvider`، سوف كل فرعي agent تشغيل في واحد عبر spawn بدء عملية فرعية في، و بـ ACP *عميل*هوية قيادة هو. هو هو قائم خدمة طرف جسر وصل `@deepseek-ai/dsh-acp`(ACP *agent*) جهة نحو عكس تحويل توأم توليد جسم: جسر وصل ينبغي جواب `initialize`/`newSession`/`prompt`؛ هذا خلفية استدعاء هو جمع و تنفيذ `Client` عودة ضبط (`sessionUpdate`،`requestPermission`). سوف إعداد spawn أمر إشارة نحو `acp-agent` عرض مثال، يكفي يجعل harness و ذاته عملية عبر معلومة.

### كل مرة تشغيل بدء كل جديد عملية

كل مرة `start` كل spawn واحد جديد عملية فرعية، تشغيل تماما جيد واحد ACP جلسة (`initialize` → `newSession` → `prompt`) ،`dispose` قتل ميت عملية فرعية و انتظار ذلك خروج. هذا هو الأكثر بسيط مفرد دورة الحياة، و عملية داخل «كل مرة تشغيل واحد فرعي agent» شكل متسق.

### الأكثر صغير تحويل عميل وتد

عميل لا إعلان أي اختياري قدرة (بلا `fs`، بلا `terminal`): فرعي agent في ذاتي ذات عملية في ذاتي سطر معالجة ملف/طرفية وصول.`session/update` إشعار يتم إزالة استهلاك: خلفية سوف `agent_message_chunk` نص تراكم تراكم لـ نتيجة إخراج، تجاهل اختصار ذلك بقية محتوى (تفكير اعتبار، أداة استدعاء بطاقة) ، لذلك فقط كشف فرعي agent نهائي عودة جواب.`session/request_permission` من إعداد سياسة تلقائي ينبغي جواب (`reject` رفض كل تلميح،`allow` عبر رقم واحد يمثل سماح خيار دفعة دقيق)——لا نحو شخص صنف كشف أي إذن تلميح. سوف `fs`/`terminal` بديل إدارة عودة أب عملية (مشترك مساحة العمل نمط) ما زال لـ لاحق عمل، مثل seam Agent Note الذي وصف.

### بلا بدء وقت قدرة

مزود `capabilities` الكل لـ `false`. عملية خارج فرعي agent لا يمكن التزام حراسة أب agent `maxDepth`(هو بلا حق وصول `parent.options.subagentDepth`) أو `toolFilter`(هو يملك ذاتي ذات أداة سجل التسجيل) ، هذا مرحلة مقطع أيضا لم تنفيذ `outputSchema`. إذا طلب حاجة منها أي واحد بند، خدمة في `start` تشغيل قبل أي رفض. خلفية فقط حقن `subagents`(بينما غير `ctx.agents`) ؛ هو من `request.parent` قراءة وحيد محتوى هو جلسة header cwd(رؤية تحت جهة مساحة العمل تحليل)——محادثة سياق، عميق درجة و أداة حالة كل لن عبر تجاوز عملية حد.

### مساحة العمل cwd تحليل

عملية فرعية عمل دليل قدوم ذاتي صريح تحليل، أبدا استخدام harness عملية cwd: إذا قد إعداد نشر `cwd` تغطية، فإن متبادل مقابل في بدء دليل سوف ذلك تحويل لـ قطعا مقابل مسار و في تحميل وقت تحقق؛ لا فإن استخدام أب جلسة header cwd و في بدء وقت تحقق؛ إذا اثنان من كل لا وجود، فإن في spawn أي عملية قبل صدى مضيء رفض. واحد ACP خدمة طرف عملية سوف خدمة قدوم ذاتي كثير عدد مساحة العمل جلسة، لذلك `process.cwd()` لا يستطيع بديل بديل جلسة مساحة العمل——قديم خفي صيغة رجوع سوف يجعل عملية فرعية في خدمة طرف بدء دليل في تشغيل. مرشح مسار يجب هو harness يمكن دخول قطعا مقابل دليل (اشتراط `X_OK`؛ فقط `statSync().isDirectory()` سوف قبول mode-600 دليل، بينما spawn سوف بسبب EACCES فشل) ؛ تحليل خروج نفس مسار معا استخدام عمل عملية فرعية cwd و ACP `session/new` مساحة العمل.

### StopReason خريطة

ACP `StopReason` → harness `SubagentStopReason`:`end_turn`→`completed`،`max_tokens`→`max-tokens`،`refusal`→`refusal`،`cancelled`→`aborted`،`max_turn_requests`→`error`(بلا مقابل انتظار دلالة، مهمة لم إتمام) ، لم معرفة→`error`.spawn،initialize و جلسة إنشاء فشل سوف في مزود ذاتي لديه تنظيف بعد، إصدار قبل رفض `start()`؛ إصدار بعد prompt/RPC/نقل فشل سوف يأخذ `result` تحديد لـ `error`(محلي إلغاء بعد لـ `aborted`) ، بينما `result` في فرعي agent درجة آخر فشل وقت أبدا reject. غير إتمام نتيجة و دورة الحياة فشل فقط سوف مرفق إضافة[عملية خارج تشخيص قرار](2026-08-21-out-of-process-subagent-minimal-diagnostics.zh.md) تعريف محدود provider stage، خشن حبة درجة category، إغلاق تجميع إذن قرار و قد مراقبة قياس عملية واقع؛ أصلي ACP خطأ و stderr ما زال فقط إبقاء في Host.

### أمان: صاف غسل عملية فرعية بيئة

فرعي agent هو مستقل عملية، لذلك سوف وراثة بيئة متغير. شكل مثل سند إثبات بيئة متغير (`/KEY|PASSWORD|SECRET|TOKEN/i`) افتراضي لا تحويل إرسال——أب harness ذاته مفتاح لا نيل خفي صيغة تسرب كشف إلى spawn بدء عملية في (و bash منفذ اعتماد سياسة نفسه). فرعي agent ذاتي ذات سند إثبات (هو حاجة نموذج مفتاح) عبر `config.env` صريح توفير، في صاف غسل بعد تراكم إضافة، لذلك متعمد نقل دخول `DEEPSEEK_API_KEY` نيل بـ إبقاء، بينما أحيانا لكن وجود `AWS_SECRET_ACCESS_KEY` فإن لن. عملية فرعية stderr وراثة إلى أب عملية stderr(تشخيص معلومة ذاتي لكن طفو الآن) ؛spawn درجة آخر `error` حدث (مثل أمر لا وجود وقت ENOENT) يتم التقاط و و ACP قيادة تنافس سرعة، لذلك خطأ أمر نتيجة لـ `error` بينما غير بـ لم معالجة خطأ انهيار انهيار أب عملية.

## اختبار

- **بلا حاجة مفتاح وحدة/اختبار تكامل:** واحد نص برمجي تحويل ACP عملية فرعية عبر حقيقي stdio اختبار نص التوجيه إدخال/إخراج مسار، كل stop-reason خريطة، إشارة و dispose إلغاء (يشمل pre-abort، جلسة قبل تنافس حالة و إدارة طريق قطع شق مشهد) ، اثنان نوع إذن سياسة، يتم تجاهل اختصار غير رسالة تحديث، أمر ناقص وقت تنظيف، مزود إعادة تحميل و نطاق الأسماء توجيه خروج.
- **بلا حاجة مفتاح Loader تركيب اختبار:** فقط لأجل اختبار cordis.yml عبر حقيقي Loader بدء stdio تطبيق، و حذف خلفية `cwd`؛ نص برمجي تحويل نموذج تفويض إرسال مرة، نص برمجي تحويل عملية فرعية فإن إثبات هو في أب جلسة مساحة العمل في تشغيل، كما ACP أيضا مقابل خارج عام نشر هذا مساحة العمل، من بينما طرف إلى طرف تغطية cwd وراثة فرع.
- **حاجة مفتاح e2e اختبار:** خلفية spawn حقيقي ACP عرض مثال؛ ذلك نموذج عودة جواب `PONG`، كتابة `proof.txt`، أب عملية تحقق هذا ملف.
- **بلا مفتاح لقطة:** ACP عرض مثال عبر Loader دعم حمل إعادة تشغيل بدء حقيقي مزود و نص برمجي تحويل عملية فرعية، ثابت قبل منصة و مرة صفة خلفية تشخيص، معا إبقاء عملية فرعية، إذن قرار، جزء إخراج و تنظيف دورة الحياة تحديد.
- **لقطة نقص فتحة:** كل ACP فرعي agent ما زال يملك ذاتي ذات إعادة تشغيل جلسة؛`TODO(acp-subagent-replay)` متابعة تتبع أثر أب عملية مقابل إعادة تشغيل في فرعي harness إعادة تشغيل، بينما لا هو تشخيص مشهد استخدام نص برمجي تحويل بروتوكول عملية فرعية.

## سبق اعتبار بديل خطة

### لـ أي متابعة استخدام SDK 0.25.1؟

خلفية فقط حاجة `ClientSideConnection`،`ndJsonStream`،`PROTOCOL_VERSION` و عميل بروتوكول نوع،0.25.1 الكل دعم حمل.0.28 fluent API حاجة في ACP طبقة معا ترحيل عميل و خدمة طرف اتصال صنف، لكن لن تعديل حسن هذا خلفية، لذلك ترقية بصفة مستقل تغيير إبقاء.

### لـ أي لا استخدام حمل دائم عملية فرعية؟

حمل دائم عملية حوض (عبر تشغيل إعادة استخدام حار عملية فرعية) هو واحد بند صفة قدرة أفضل تحويل، دفع متأخر إلى لاحق عمل. هو زيادة جلسة دورة الحياة و انهيار انهيار استعادة تكرار مختلط درجة، هذا مرحلة مقطع لا حاجة؛ كل مرة `start` spawn كل جديد عملية فرعية و عملية داخل «كل مرة تشغيل واحد فرعي agent» شكل متسق.

## عاقبة

كل مرة تشغيل كل يلزم دفع خروج واحد كل جديد عملية فرعية بديل قيمة (spawn + `initialize` + `newSession`). أب عملية فقط كشف فرعي agent نهائي عودة جواب:`session/update` في تفكير اعتبار و أداة استدعاء بطاقة يتم إزالة استهلاك بعد إسقاط، إذن تلميح من لا وصول شخص صنف——من إعداد سياسة ينبغي جواب. عملية فرعية بيئة افتراضي مرور مرور سند إثبات صاف غسل، لذلك ذلك ذاته نموذج مفتاح يحتاج عبر `config.env` صريح توفير.
