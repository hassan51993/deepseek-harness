# Agent Note: إصدار تحويل GUI فرح استقبال جذب توجيه

Status: implemented
Archived: 2026-08-22

[English](2026-07-30-versioned-gui-welcome-onboarding.md) | العربية

## مشكلة

GUI اعتماد جذب توجيه من DeepSeek مخصص استخدام حينئذ خيط حالة فحص بدء، لكن داخلي اختبار إشعار ملائم لأجل كل موضع مستخدم، أي جعل اعتماد قد إعداد، أيضا يجب أولا في مزود ضبط عرض. إذا يأخذ اثنان من بصفة مستقل طفو طبقة معالجة، كثير عدد محادثة إطار ممكن معا ظهور؛ فقط تخزين في عملية داخل إغلاق علامة حيث لا يمكن منطقة قسم إشعار قد إتمام تأكيد أيضا هو نافذة في تأكيد قبل قد إغلاق، أيضا لا يمكن في نص سجل متعمد إصلاح حجز بعد إعادة عرض مرة إشعار.

## قرار

**ضبط خارج قشرة تنسيق ضبط لديه ترتيب خطوة.** `settings.onboarding` ما زال هو أصل أثر مجال list، لكن `ui-settings` سوف يأخذ منها كل بند id و ترتيب إسقاط إلى واحد تنسيق ضبط جهاز في، و كما فقط تركيب رقم واحد لم إتمام خطوة. حالي تسجيل جهة سوف استلام إلى `complete()` و `openSection(id)`؛ كل حق تحويل نقل قبل، لن تركيب لاحق خطوة.`ui-settings-models` الآن بـ ترتيب `-100` تسجيل استعادة بعد فرح استقبال إعلان، بـ ترتيب `0` تسجيل DeepSeek شرط صيغة اعتماد خطوة؛ اثنان من حالي مشترك استخدام عرض من[مشترك استخدام نابض نافذة جذب توجيه قرار](2026-08-13-shared-modal-product-onboarding.zh.md) يحتفظ.

**منتج فرح استقبال خطوة حسب إصدار إدارة و عودة وظيفة إضافة كل.** هذا إعلان سبق من[إزالة أول مرة بدء داخل قياس إعلان](../simplification/2026-08-13-remove-first-run-beta-notice.zh.md) تاريخ قرار إزالة، الآن بـ جديد اختبار مرحلة مقطع نص سجل استعادة في `ui-settings-models` في.`ui-settings-general` ما زال لا تسجيل أي جذب توجيه خطوة؛ يحتفظ حالي اثنان عدد خطوة إضافة أيضا يحتفظ نص سجل،store و مشترك استخدام نابض نافذة.

**حفظ دائم `ui-onboarding` قسم عقدة يحتفظ تأكيد حالة.** مضيف طرف في user-settings seam في تسجيل هو، تخزين دخول حالي `$DSH_HOME/settings.yaml`؛ حالي فرح استقبال store عبر قائم عام settings API قراءة كتابة منها `welcomeNoticeVersion`.connection إضافة عبر `ctx.connection.isLoopback` موحد واحد إصدار حالي صفحة هل استخدام loopback authority؛hostname حكم تحديد إبقاء في connection حزمة داخل، أخرى عميل إضافة فقط إزالة استهلاك خدمة حالة، بينما لا استيراد ذلك تنفيذ.API Proxy في يمكن إعداد مزود namespace خارج، عبر غلاف إغلاق سماح قائمة كشف هذا واحد منتج namespace، معا لن يأخذ هو تغيير نظر لـ نموذج دليل بطلان حدث.

**مرئي جذب توجيه استخدام نفس عدد نابض نافذة عقد نحو.** حالي اثنان عدد خطوة كل عبر body portal نفس عدد `OnboardingModal` تصيير، كما فقط في نابض نافذة مرئي خلال يأخذ تحت طبقة تطبيق أصل عقدة ضبط لـ inert. خطوة تحميل خاص واقع وقت، خارج قشرة لا تصيير أي حزمة تركيب. واضح عملية سوف نقل تسليم تنسيق ضبط جهاز كل حق؛Escape و نقر حجب غطاء كل لن تأكيد أو قفز مرور خطوة.

## سبق اعتبار بديل خطة

**متصفح محلي تخزين**: لا إعطاء اعتماد، لأن تأكيد حالة سوف تتبع مع بعض عدد متصفح profile، بينما لا هو `$DSH_HOME`؛ كل جديد Harness profile ممكن خطأ وراثة هذا قبل تأكيد حالة، خارجي profile تحرير أيضا لا يوجد مرجعي تحديث تدفق. لذلك، غير loopback رجوع إبقاء لـ عملية داخل حالة، بينما لا هو متصفح profile حالة.

**في `ui-settings-general` في مجددا زيادة واحد مستقل نموذج حالة نافذة**: لا إعطاء اعتماد، لأن فرح استقبال إشعار و اعتماد حينئذ خيط حالة معا لـ حق وقت،list تسجيل جهة ما زال سوف كومة تراكم. إعلان و تصيير هذا list خارج قشرة ينبغي عند يحتفظ لديه ترتيب كل حق.

**في تصيير أو نافذة إغلاق وقت حفظ دائم**: لا إعطاء اعتماد، لأن نظر رؤية إشعار لا انتظار في تأكيد، نافذة إغلاق حدث أيضا لا يمكن يمكن اعتماد إرسال بلوغ. فقط لديه صريح إيداع «متابعة» عندئذ قدرة منع توقف إشعار في تحت مرة بدء وقت مجددا مرة عرض.

**عام عام ضبط كشف علامة سجل**: لا إعطاء اعتماد، لأن واحد منتج namespace لا كاف بـ إثبات ينبغي عند توسيع كبير كل settings تسجيل جهة عام إعداد وجه. هذا API Proxy إبقاء صريح غلاف إغلاق سماح قائمة.

## عاقبة

كل جديد profile سوف أولا يرى حالي اختبار مرحلة مقطع إعلان؛ عند لا يوجد أي متاح مزود وقت، مجددا يرى شرط صيغة DeepSeek مفتاح نابض نافذة. تحديد نحو store و React اختبار ثابت دقيق إصدار تأكيد، تنسيق ضبط جهاز ترتيب، شرط صيغة نقل تسليم، مشترك استخدام نابض نافذة سلوك و HMR تنظيف. حقيقي Chromium مشهد سوف في عزل harness بيت دليل تحت بدء قد إصدار Web تركيب، تحقق اثنان عدد نابض نافذة، عبر قائم اعتماد حد كتابة مفتاح، و فحص secret لم دخول DOM،ARIA أو متصفح تحكم منصة.
