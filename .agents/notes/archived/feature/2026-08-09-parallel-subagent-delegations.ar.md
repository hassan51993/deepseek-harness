# Agent Note: و سطر subagent تفويض إرسال

Status: implemented
Archived: 2026-09-04

[English](2026-08-09-parallel-subagent-delegations.md) | العربية

## مشكلة

تفكير يلزم مروحة خروج نموذج سوف يأخذ كثير عدد `subagent` استدعاء دمج دخول نفس بند assistant رسالة: هذا عدد دفعة مرة ذاته حينئذ هو و سطر معنى رسم. تفويض إرسال أداة هذا قبل لا يوجد إعلان `isConcurrencySafe` تصنيف جهاز، حسب أمان جانب أصل فإن تصميم مجدول ([و سطر أداة استدعاء Agent Note](2026-07-10-parallel-tool-call-execution.ar.md)) سهل يأخذ كل قبل منصة تفويض إرسال كل عند عمل وحيد احتلال شاشة عائق:GUI داخل عرض تسعة ورقة بطاقة، لكن فقط لديه واحد فرعي agent(ذكي جسم) في تشغيل، ذلك بقية ثمانية عدد يلزم في هو كامل تشغيل خلال ترتيب في ذلك بعد انتظار.

الأكثر أول حفظ حراسة قيام ساحة (واحد عنصر تصنيف جهاز لا يمكن إثبات نفس درجة تفويض إرسال مساحة العمل فاعلية نتيجة متبادل لا متبادل تسليم) قد لم يعد حفظ حماية أي شرق غرب:`run_in_background: true` و يمكن متابعة تفويض إرسال هذا قدوم حينئذ سوف و ذلك بعد كل استدعاء إعادة تراكم تنفيذ، يشمل كتابة؛`dsh-workflow-worker-thread` أيضا مبكر قد عبر نفس مثال `ctx.subagents.start()` مزود في مشترك مساحة العمل فوق تزامن تشغيل فرعي agent، عدد كمية يمكن بلوغ ذلك تزامن حد أعلى. فقط لديه قبل منصة شكل يتم سلسلة سطر تحويل.

## قرار

`dsh-tool-subagent` لـ كل نوع استدعاء شكل (قبل منصة، مرة صفة خلفية، يمكن متابعة) كل إعلان `isConcurrencySafe: () => true`، لذلك نفس assistant خطوة في نفس درجة تفويض إرسال سوف في حلقة تمرير حوض تحت إعادة تراكم تنفيذ، حد أعلى لـ `maxParallelToolCalls`، نتيجة ما زال حسب نموذج ترتيب إيداع.

هذا إعلان في بنية فوق ممتلئ كاف مجدول أمان اتفاق: فرعي agent في ذاتي ذات جلسة في عمل، تشغيل أبدا تغيير أب جلسة (بدء وقت إلحاق `sandbox/mode`،`approval/policy`،`subagent/descriptor` فقط سقوط في فرعي agent ذاتي ذات سجل داخل) ، أداة يأخذ إخراج إرجاع إعطاء حلقة، من حلقة حسب ترتيب إيداع. مرة صفة خلفية شكل مقابل أب درجة يملك حالة وحيد كتابة هو عبر `tasks.start` تسجيل واحد Task——هذا هو مرة تزامن، يمكن تسليم تبديل إدراج دخول، ممتلئ كاف هو مجدول Agent Note في مشترك حالة بند بند، بينما غير أكثر قوي «بلا تغيير» صفة جودة. مزود seam اشتراط إبرة مقابل مختلف فرعي agent تزامن بدء و يمكن متابعة دقيق تجهيز قسم آخر عزل عملية نطاق جزء حالة، إلغاء، تسوية و تنظيف. داخل وضع مزود ممتلئ كاف هذا بند اتفاق:spawn و fork في كل مرة بدء بين لا إبقاء متغير حالة،fork فقط قراءة أب درجة قد إتمام جولة بادئة، عملية خارج مزود حسب كل مرة تشغيل قسم إعداد حالة، متابعة تنفيذ إدارة جهاز فإن لـ كل مرة دقيق تجهيز مسبق إبقاء وحيد فرعي agent هوية و قفل.

تنسيق ضبط نفس درجة مساحة العمل فاعلية نتيجة هو نموذج مسؤولية، منتج مقابل خلفية، يمكن متابعة و سير العمل فرعي agent قد أخذ أخذ نفس مثال قيام ساحة. نفس صنف harness فعل قاعدة متسق:Claude Code Task أداة بلا شرط تزامن أمان (حد أعلى 10) ؛oh-my-pi task أداة افتراضي عودة دخول ذلك يمكن إعادة تراكم `shared` صنف آخر؛opencode task أداة في ذلك SDK تحت لا ضبط حد أعلى أرض تشغيل؛Codex فإن يأخذ تفويض إرسال فعل صار مختلف خطوة spawn/wait معلومة صندوق، التفاف فتح هذا عدد مشكلة.

سعة كمية تحكم ما زال إبقاء في مجدول Agent Note الذي تحديد موضع:`maxParallelToolCalls` حد مفرد عدد خطوة في لم تسوية أداة استدعاء عدد كمية——بسبب بينما أيضا حد تزامن تشغيل قبل منصة فرعي agent عدد كمية——بينما خلفية و يمكن متابعة استدعاء في بدء وقت أي تسوية و تحرير حوض موضع، هو جمع إبقاء تحت تشغيل فرعي agent لا تلقي هذا حد أعلى قيد.LLM(كبير لغة نموذج) مزود مسؤول ذاته سعة كمية تحكم.

## اختبار

حزمة اختبار ثابت اثنان نوع استدعاء شكل تصنيف جهاز. واحد باب تحكم اختبار مباشر قيادة سجل التسجيل، ذلك اثنان عدد فرعي agent كل منها منع سد، مباشر إلى اثنان من كل قد بدء، بـ هذا إثبات هذا إعلان الذي اعتماد ذلك واحد نصف: أداة جسم و مزود بدء مسار قدرة سعة تحمل تزامن توزيع——هذا بند مكدس في أي إخفاء سلسلة سطر تحويل كل سوف صنع صار ميت قفل، بينما لا هو ساكن صامت عبر. واحد يمكن متابعة باب تحكم اختبار يجعل اثنان بند مزود دقيق تجهيز توقف في نفس عدد await فوق، في إصدار قبل إلغاء منها واحد استدعاء جهة، و إثبات قد إلغاء فرعي agent لن إبقاء تحت agent أو حمل دائم جلسة، بينما ذلك نفس درجة فإن وصول inbox قبول حالة و مستقل حفظ دائم. آخر نصف (تصنيف حق صحيح إنتاج إعادة تراكم تنفيذ) من تصنيف جهاز pin اختبار و تحت وصف لقطة مسؤول.

شخص عمل تحرير كتابة `subagent-parallel` لقطة ثابت تجميع بعد تطبيق transcript(نص سجل): واحد بند assistant رسالة يحمل اثنان عدد subagent استدعاء، أب درجة سجل سجل لـ `tool/call, tool/call, tool/result, tool/result`(سلسلة سطر تنفيذ سوف يجعل استدعاء/نتيجة صار مقابل تسليم خطأ ظهور) ، اثنان عدد فرعي agent كل منها بصفة مستقل جلسة إتمام. منها توأم توليد تفويض إرسال لحظة معنى فعل صار تماما نفسه:`dsh-llm-replay` حسب أول مرة استدعاء ترتيب ربط فرعي نص برمجي،harvester حسب `createdAt` مقابل فرعي agent ترتيب ترتيب، اثنان من في تزامن فرعي agent بين كل لا أداة تحديد صفة (أي `XXX(concurrent-subagents)` علامة) ، لذلك فقط لديه يمكن متبادل تبديل توأم توليد تفويض إرسال عندئذ قدرة تحديد صفة إعادة تشغيل.

## تجهيز اختيار خطة

**إبقاء تفويض إرسال وحيد احتلال.** الآن حالة لا يوجد حفظ حماية أي شرق غرب: خلفية و سير العمل فرعي agent هذا قدوم حينئذ يمكن حمل حال كتابة ذاتي من إعادة تراكم، سلسلة سطر تحويل قبل منصة شكل فقط سوف زيادة تأخير متأخر، أيضا مخالفة خلف نموذج صريح جدول بلوغ دفعة كمية معنى رسم.

**استخدام إدخال حساس شعور تصنيف جهاز.** هذا استدعاء معامل فقط لديه ذاتي من نص وصف و نص التوجيه؛ منها لا يوجد أي محتوى قدرة منطقة قسم أمان تفويض إرسال و لا أمان تفويض إرسال، لذلك شرط صيغة تصنيف جهاز فقط سوف تدفق في شكل صيغة.

**حسب Codex ريح إطار إعادة تصميم لـ مختلف خطوة spawn/wait.** يمكن متابعة فرعي agent إضافة فوق `send_message` قد توفير مختلف خطوة عبر طريق؛ محيط التفاف معلومة صندوق إعادة بناء قبل منصة اتفاق، انتظار في لـ حل قرار واحد بند إعلان حينئذ قدرة إصلاح ضبط درجة مشكلة، إسقاط واحد بند متاح تزامن نتيجة مسار.

**حسب نسخة توفير `concurrencySafe` إعداد فتح صلة.** لا يوجد مستهلك حاجة سلسلة سطر نشر:`maxParallelToolCalls: 1` قد قدرة استعادة عام سلسلة سطر تنفيذ، نفس صنف harness أولا مثال أيضا افتراضي تفويض إرسال تزامن أمان.

## أثر

نفس درجة فرعي agent ممكن في مشترك مساحة العمل أو خارجي مورد فوق حدوث تنافس حالة؛ هذا بند تنسيق ضبط من نموذج مسؤول، صحيح مثل نموذج مقابل أخرى كل إعادة تراكم فرعي agent قد تحمل تحمل ذلك مثال. تزامن فرعي agent أيضا سوف تنازع استخدام LLM مزود إعداد مقدار؛`maxParallelToolCalls` فقط حد لم تسوية استدعاء، لا حد خلفية أو يمكن متابعة استدعاء إبقاء تحت تشغيل فرعي agent.

نفس بند رسالة في اثنان عدد مرة صفة خلفية تفويض إرسال حسب توزيع تنافس حالة ترتيب نيل نيل كل منها نموذج مرئي job id(`subagent-<n>`). هذه id قد يتم سجل، لذلك إعادة تشغيل ما زال صالح؛ لكن حاجة منطقة قسم خلفية فرعي agent لقطة مشهد سوف وراثة و توأم توليد فرعي جلسة نفسه تحديد صفة قيد.

لديه ترتيب إيداع ممكن يجعل سريع سرعة فرعي agent نتيجة ترتيب في أكثر مبكر مؤقت بطيء نفس درجة بعد انتظار، هذا هو[مجدول Agent Note](2026-07-10-parallel-tool-call-execution.ar.md) قد قبول أخذ ترك؛ فوري واجهة ما زال سوف عرض كل فرعي agent كل منها دخول درجة.

استخدام مختلف نص التوجيه تزامن فرعي agent لقطة مشهد ما زال حاجة إعادة تشغيل harness دعم حمل (تحديد صفة فرعي نص برمجي ربط و استلام تجميع ترتيب ترتيب) ؛ في هذا قبل، هذا صنف مشهد يجب استخدام يمكن متبادل تبديل توأم توليد تفويض إرسال.
