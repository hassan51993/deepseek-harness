# Agent Note: DeepSeek رسمي جهة أول مرة استخدام اعتماد إعداد

Status: implemented
Archived: 2026-09-04

[English](2026-07-30-deepseek-onboarding-credential-setup.md) | العربية

## مشكلة

[web إعداد مستو وجه](../architecture/2026-07-30-web-config-plane.zh.md) يجعل مزود ضبط و اعتماد يمكن فوري تحرير، لكن أول مرة استخدام مستخدم ما زال سوف دخول فارغ أبيض محادثة Hero؛ عند مع منتج توفير `deepseek-official` توجيه نقص قليل اعتماد وقت، واجهة لا يوجد إعطاء خروج يمكن أخذ أخذ عملية شرح.Models صفحة قدرة إصلاح هذا حالة، لكن اشتراط مستخدم ذاتي سطر اكتشاف هذا عدد مدخل سوف تقليل ضعيف أول مرة استخدام جذب توجيه. واجهة لا نيل خلط خلط اعتماد ناقص و مهايئ ناقص: متصفح يمكن لـ قائم اعتماد مرجع تخزين دخول قيمة، لكن لا يمكن حركة حالة تركيب `llm-deepseek` Cordis إضافة.

## قرار

**Models و أول مرة استخدام جذب توجيه مشترك نفس عدد حينئذ خيط حالة إسقاط.**`ui-settings-models` صيانة واحد store، يأخذ `llm/listProviders`،`llm/listConfigurableProviders`، مشترك settings describe مرآة مثل يحتفظ قد انفصال حساس namespace views و دفعة كمية استدعاء `credentials/describe` ربط وصل لـ نفس نسخة حالة. أول مرة استخدام إسقاط اختيار أخذ من `llm-deepseek` namespace و فارغ settings path يحتفظ `deepseek-official` يمكن إعداد مزود بند، قراءة توليد فاعلية `apiKeyEnv`، و فحص مقابل اعتماد وصف رمز. نفس provider id لكن لا يوجد مطابقة يمكن إعداد مزود إعلان تخزين نشط توجيه، في أول مرة استخدام جذب توجيه في نظر لـ مهايئ ناقص. عبر عملية بيئة توفير اعتماد إذا قد إعداد، فإن حكم تحديد لـ حينئذ خيط و إبقاء فقط قراءة. لاحق [settings describe مرآة مثل قرار](../architecture/2026-08-17-settings-describe-mirror.zh.md) يحتفظ هذا مرة settings قراءة و ذلك بطلان ترتيب.

**ضبط خارج قشرة فقط مساهمة ترتيب ترتيب، لا يحتفظ مزود سياسة.** `ui-settings` إعلان واحد أصل أثر مجال `settings.onboarding` list slot، و في حالي واجهة لـ فارغ أبيض Hero وقت، كل مرة فقط تركيب واحد لديه ترتيب خطوة. حالي تسجيل جهة سوف استلام إلى `complete()` و خاص `openSection(id)` عودة ضبط؛ إتمام حالي خطوة بعد، كل حق تحويل تسليم إعطاء تحت واحد بند.`ui-settings-models` عبر `slots.inject()` تسجيل DeepSeek خطوة، ترتيب في هو قبل فرح استقبال إعلان و Models قسم منطقة، لذلك كل مساهمة كل تتبع مع نفس عدد client Cordis إضافة دورة الحياة، اثنان عدد نابض نافذة أيضا لا يمكن كومة تراكم. هو جمع مشترك استخدام عرض من[مشترك استخدام نابض نافذة جذب توجيه قرار](2026-08-13-shared-modal-product-onboarding.zh.md) يحتفظ.

**أول مرة استخدام نابض نافذة سطر داخل تصيير قائم اعتماد تحرير جهاز.** مهايئ قد تركيب كما موضع في نشط وثب حالة، ذلك مرجع يمكن تحليل، يمكن كتابة لكن بعد لم إعداد وقت،`ProviderEditor` سوف بـ فقط اعتماد نمط تصيير في مشترك استخدام جذب توجيه نابض نافذة في. نفس عدد مكون كل حق مسؤول سري رمز إدخال إطار، تحقق،`credentials.set({ref, value})`، كتابة فشل معالجة و كتابة بعد تحديث جديد؛ فقط اعتماد نمط لن إرسال خروج مزود settings تغيير.«قليلا بعد إعداد» فقط إتمام تنسيق ضبط جهاز حالي هذا واحد جولة. مهايئ ناقص وقت ما زال قفز مرور، لأن متصفح لا يستطيع تركيب ناقص Cordis إضافة.

**غير ممكن استخدام حالة لن احتلال إقامة منتج.** يمكن إعداد مزود بند ناقص، توجيه لا نشط وثب، ابتدائي ربط وصل فشل، نشر فقط قراءة أو ضبط/اعتماد قدرة لا يمكن تحليل وقت، كل سوف مباشر إتمام بينما لا تصيير هذا خطوة، لأن أول مرة استخدام جذب توجيه لا يمكن إصلاح هذه حالة.Models صفحة ما زال هو نشر تشخيص و إعادة محاولة واجهة.«قليلا بعد إعداد» فقط سوف إتمام تنسيق ضبط جهاز حالي هذا مرة نقص قليل اعتماد خطوة، لا كتابة أي إتمام حالة. ضبط، اعتماد، مزود توسيع اندفاع و اتصال بطلان حدث كل سوف تحديث جديد مشترك ربط وصل، لذلك خارجي اعتماد تحديث بلا حاجة إعادة تحميل صفحة يكفي إتمام قد فتح خطوة.

## سبق اعتبار بديل خطة

**لـ أول مرة استخدام جذب توجيه مفرد ضبط store و حينئذ خيط حالة RPC استدعاء تسلسل**: لا إعطاء اعتماد، لأن هذا سوف في Models صفحة خارج، مجددا بناء قيام واحد طقم عميل حل تفسير، لأجل حكم تحديد مزود هوية، ضبط مسار،secret مجرى موضع مرافق مع معلومة، اعتماد مرجع و بطلان حدث ترتيب.

**في أول مرة استخدام جذب توجيه في مفرد وحيد تنفيذ API key جدول مفرد**: لا إعطاء اعتماد، لأن هذا سوف نسخ Models تحرير جهاز secret مسودة مسودة، تحقق، خطأ و قد إعداد حالة استلام جمع. نابض نافذة تعديل لـ بـ تلقي حد نمط تصيير قائم `ProviderEditor`.

**يأخذ API key كتابة مزود ضبط**: لا إعطاء اعتماد، لأن حرف وجه كمية secret سوف دخول ضبط تغيير مسار، بينما كامل قسم عقدة استبدال لا يمكن أمان إعادة بناء انفصال حساس قيمة. اعتماد تخزين قد هو منتج seam، و قدرة قيام أي إرسال خروج بطلان حدث.

**`llm-deepseek` ناقص وقت ما زال عرض طفو طبقة**: لا إعطاء اعتماد، لأن متصفح تنقل لا يوجد أي تلقي دعم حمل عملية يمكن تركيب ناقص Cordis إضافة.

## عاقبة

لديه ترتيب مسار من منتج إعلان صفحة بدء، بلا حاجة إعادة بدء يكفي دخول سطر داخل مفتاح جدول مفرد: بلا مفتاح متصفح اختبار في عزل harness بيت دليل تحت بدء حقيقي Web تركيب، تأكيد إعلان بعد من مشترك استخدام نابض نافذة يأخذ توليد مفتاح تخزين دخول هذا دليل `.credentials.yaml`، تحقق مفتاح لم دخول DOM،ARIA أو متصفح تحكم منصة إخراج، و تأكيد عادي Models صفحة تقرير إبلاغ قد إعداد. كامل بلا مفتاح Web إعادة تشغيل أيضا ثابت نفس id غير ممكن إعداد إعادة تشغيل توجيه لن منع سد غير متصل مسار. صاف حينئذ خيط حالة اختبار و React اختبار ثابت تحويل تلقي إدارة ملف اعتماد و عملية بيئة اعتماد، مزود و قدرة ناقص، إلغاء، خارجي بطلان و تنسيق ضبط جهاز نقل تسليم. هذا مسار مباشر وراثة إعداد مستو وجه قد سجل أساس أساس حد، لن آخر إضافة نطاق جزء آلة سري تخزين، انفصال حساس أو ضبط استبدال تغيير عبر خطة.
