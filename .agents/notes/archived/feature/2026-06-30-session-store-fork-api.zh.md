# Agent Note: SessionStore fork API

Status: implemented
Archived: 2026-09-04

[English](2026-06-30-session-store-fork-api.md) | العربية

## مشكلة

حدث تتبع مصدر جلسة سجل قد أداة تجهيز fork الذي يحتاج أصل لغة: إنشاء واحد حمل لديه نوع فرعي حدث بادئة جديد جلسة، لكن بعد مثل إعادة تشغيل واحد مثال من هذا نوع فرعي سجل دفع توجيه نموذج تاريخ. هذا عدد أصل لغة متعمد إبقاء قاع طبقة:`ctx.sessions.create(id, { seed, meta })` قبول أي دمج قاعدة نوع فرعي، لكن معتاد قاعدة نشط وثب جلسة فرع حاجة محيط التفاف التالي مشكلة صنع تحديد سياسة: أي بعض بادئة يمكن يتم نسخ، فرعي جلسة ينبغي ضرب فوق أي بعض بيانات وصفية، و خطأ مثل أي تصنيف.

دلالة فوق ريح خطر في في fork حد. واحد دمج قاعدة مستخدم مرئي fork نوع فرعي يجب وصل متابعة، و في نشط وثب جولة خارج انتهاء. إذا في تنفيذ مرور مسار في fork، سوف نسخ واحد لم إغلاق `turn/start`، ممكن أيضا لديه واحد لم إغلاق `step/start`، و ممكن معلق فارغ أداة استدعاء. هذا مخالفة عكس تنفيذ و مزود transcript(نص سجل) ثابت صيغة، و كما سوف إنشاء واحد مقطع خطأ توجيه صفة فرعي تاريخ——نظر بدء قدوم فرعي جلسة مشاركة و أب جلسة في واحد بعد لم إتمام جولة. قد إغلاق جولة بعد مستقل سياق و من إضافة مسؤول كتابة صاف سجل حدث هو مستقر كما يمكن fork تاريخ. قائم [subagent seam](2026-06-21-subagent-capability-seam.zh.md) متعمد حل قرار هو آخر عدد مشكلة: أداة إطلاق subagent fork عبر معتاد حدوث في أب جولة ما زال فتح وقت، لذلك `dsh-subagent-fork-in-process` سوف سوف نوع فرعي قطع قص إلى أب جلسة الأكثر بعد واحد قد إتمام جولة بادئة. عام جلسة fork لا ينبغي ساكن صامت قطع قص؛ هو ينبغي عند يلزم ما في طلب حد موضع fork، يلزم ما رفض طلب.

## قرار

`dsh-session` مباشر مسؤول `ctx.sessions` فوق معتاد قاعدة نشط وثب جلسة fork. لا ضبط مستقل `dsh-session-fork` حزمة، أيضا لا ضبط `ctx.sessionFork` خدمة: هذا API لا يوجد مستقل خلفية، حدث مفردات، دورة الحياة أو حفظ دائم سلوك، كل حفظ دائم عمل كل تفويض حمل إعطاء قائم جلسة تخزين و حفظ دائم خلفية.

store كشف واحد عملية:

```ts ignore-check
type SessionForkSource = Session | SessionId

class SessionStore extends Service {
  fork(source: SessionForkSource, boundary?: SessionSeq, childSessionId?: SessionId): Session
}
```

`boundary` هو يلزم نسخ إلى صنف لوحة تحويل مصدر حدث `seq`(يحتوي هذا ترتيب رقم). حذف وقت افتراضي لـ مصدر جلسة حالي الأكثر بعد واحد حدث؛ مقابل فارغ مصدر جلسة حذف `boundary` فإن إنشاء واحد فارغ فرعي جلسة.fork خاص لديه تحقق سوف فحص طلب حد وجود، و تأكيد الذي اختيار بادئة الأكثر قريب جولة حد لا هو لم مطابقة `turn/start`. لذلك، الذي اختيار بادئة يمكن انتهاء في `turn/end` أو أكثر متأخر مستقل حدث، مع بعد يتم عميق نسخ صدفة إلى فرعي جلسة نوع فرعي في. فرعي جلسة وراثة مصدر جلسة `cwd`، سوف `parentSession` ضبط لـ مصدر جلسة id، ضبط logical `isSeeded: true`، و يأخذ نسخ بادئة طويل درجة مفرد وحيد بصفة `inheritedEventCount` نقل دخول. حذف `childSessionId` وقت،`SessionStore` استخدام ذلك قائم id سياسة توليد واحد.

فارغ بادئة يمكن يتم fork؛ أي غير فارغ حد كل يجب هو يقع في فتح وضع جولة خارج كما أمان، قد وجود ترتيب رقم. نوع تحويل خطأ منطقة قسم مصدر ناقص، كائن قديم قديم، فرعي id تكرار، حد بلا فاعلية و بادئة انتهاء في تنفيذ مرور مسار في انتظار حال حال. أكثر واسع عام سجل تحقق و انهيار انهيار استعادة ما زال من ذلك قائم مسؤول جهة معالجة.

### Host و متصفح ملائم إعداد

Host `session.fork` RPC قبول `atSeq`، و سوف ذلك نظر لـ الذي يحتاج جولة داخل مرساة نقطة، بينما غير store في يتضمن هذا ترتيب رقم أمان حد. هو اختيار هذا مرساة نقطة موضع أو ذلك بعد أول عدد `turn/end`؛ مرساة نقطة حذف أو تجاوز مرور نهاية ذيل وقت، اختيار الأكثر بعد واحد قد إتمام جولة. إذا مرساة نقطة قد في سجل في، لكن من هذا مرساة نقطة بدء بحث لا إلى مطابقة `turn/end`، فإن إرجاع `fork-unavailable`، أبدا رجوع إلى أكثر مبكر جولة، لذلك رسالة عملية لن ساكن صامت متروك تسرب الذي نقر رسالة.

Host عبر agent(ذكي جسم) سجل التسجيل، بـ اختيار تحديد نوع فرعي و جدول نظام إنشاء فرعي جلسة؛ إصدار قبل setup سوف أولا تثبيت سجل في الأكثر جديد مزود، نموذج و دفع إدارة (reasoning) هدف، فرعي جلسة عندئذ قدرة تشغيل. مع بعد،Host سوف فرعي جلسة مرفق إضافة إلى مصدر Workspace. إذا مرفق إضافة فشل، فإن إرجاع `workspace-attach-failed` و قد إصدار فرعي جلسة id؛ عميل أولا سوف هذا فرعي جلسة مقابل حساب إلى ملخص قائمة، مجددا نحو استدعاء جهة تقرير إبلاغ خطأ.Session سطر عملية استخدام الأكثر بعد واحد قد إتمام جولة، رسالة عملية فإن توفير ذلك حدث seq؛ اثنان من كل سوف في نجاح بعد فتح فرعي جلسة، توسيع جدول نظام بعد يمكن في مصدر جلسة تحت يرى هو.

## سبق اعتبار بديل خطة

**مستقل `ctx.sessionFork` خدمة.** مقارنة مبكر واحد إصدار تكرار بديل سبق يأخذ هو بصفة مستقل خدمة تسليم؛ هو مرور درجة طقم استخدام قدرة seam نمط. شفرة لا يوجد يمكن استبدال خلفية، لا يوجد مقدار خارج حدث وجه، لا يوجد مستقل كل حق دورة الحياة، أيضا لا يوجد تجاوز خروج `ctx.sessions.create({ seed, meta })` حفظ دائم سلوك. إبقاء مستقل حزمة سوف إجبار جعل استدعاء جهة لـ في جلسة تخزين أصل لغة لـ فوق تنفيذ واحد طبقة سياسة بينما ذهاب اكتشاف و تثبيت ثاني عدد خدمة.

**اثنان عدد دالة:`snapshot()` إضافة `fork()`.** هذا إبقاء واحد يمكن إعادة استخدام نوع فرعي/بيانات وصفية حساب حساب، لكن وحيد دعم حمل مستهلك سوف قيام أي إنشاء جلسة. هو أيضا جعل API نظر بدء قدوم مقارنة مستخدم فعلي حاجة أداة جسم عملية أكثر سحب كائن. مفرد واحد `fork()` إضافة صريح `boundary` جعل API إبقاء مباشر، معا ما زال دعم حمل مقابل أولا قبل وقت نقطة fork.

**ساكن صامت قطع قص لم إغلاق جولة إلى الأكثر بعد واحد قد إتمام حد.** هذا مقابل `dsh-subagent-fork-in-process` هو صحيح تأكيد——تفويض حمل عبر معتاد في أب جولة ما زال فتح وقت بدء، فرعي جلسة ينبغي فقط وراثة قد إتمام بادئة. لكن مقابل معتاد قاعدة مستخدم/جلسة فرع بينما قول هو خطأ، لأن هو إخفاء طلب fork نقطة فعلي فوق لا هو دمج قاعدة حد هذا واحد واقع، و كما ساكن صامت إسقاط أب جولة ذيل جزء.

## عاقبة

عام API إبقاء دقيق بسيط كما سهل في اكتشاف: نشط وثب جلسة فرع هو `ctx.sessions` واحد جزء، ضيق مجاور `create({ seed })`، بينما غير واحد مستقل خدمة أو واحد مقابل اثنان خطوة مساعد مساعدة دالة. حفظ دائم متابعة عبر قائم `session/created` و `session/flush` سلوك تشغيل عمل:fork خروج فرعي جلسة إنشاء وقت سهل حمل لديه نوع فرعي حدث، لذلك JSONL خلفية فقط يحتاج حفظ دائم هذا نوع فرعي مرة، و إبقاء logical `parentSession`/`isSeeded` و مفرد وحيد دقيق cut(تحرير رمز لـ v0 شيء إدارة `seedLength`).

هذا قرار ترتيب حذف ACP(Agent Client Protocol)`session/fork`، مقابل لم تحميل قد حفظ دائم جلسة تنفيذ fork، موجه إلى نموذج أداة، و subagent إعادة بنية. إذا لم قدوم إضافة ACP طريقة، ينبغي في أداة تجهيز بروتوكول و لقطة تغطية بعد عندئذ إعلان دعم حمل هذا قدرة؛ هذا Agent Note لا إضافة أي ACP بروتوكول سلوك، لذلك لا حاجة ACP لقطة.fork فرعي جلسة إعادة تشغيل ما زال من قائم[نوع فرعي حد اختبار Agent Note](../testing/2026-06-22-fork-child-replay-seed-boundary.zh.md) تغطية؛store،Host، تحميل جسم و عميل مخصص بند اختبار ثابت حد و مقابل حساب اتفاق، حقيقي Chromium مشهد فإن ثابت تجميع بعد رسالة عملية و جدول نظام شجرة.
