# Agent Note: في Windows فوق دعم حمل TUI

Status: implemented
Archived: 2026-08-04

[English](2026-07-20-windows-tui-support.md) | العربية

## مشكلة

كل شاشة TUI سوف أصلي إدخال،ANSI تصيير، طرفية مقياس قياس تغيير حدث و طرفية استعادة تفويض حمل إعطاء pi-tui `ProcessTerminal`. هذا اعتماد قد تنفيذ أصلي Windows تحكم منصة مسار، لكن مستودع حقيقي عملية خطر دخان اختبار هذا قبل استخدام Python في فقط ملائم لأجل POSIX `pty` و `termios` وحدة. إذا في Windows فوق قفز مرور هذا اختبار، هذا بند تلقي دعم حمل منتج مسار سهل سوف نقص قليل إبرة مقابل بدء، إدخال، تفاعل، فشل تقرير إبلاغ و طرفية استعادة اختبار نسبة التغطية.

TUI منصة عقد نحو يجب بـ تسليم إعطاء مستخدم وقت التشغيل لـ دقيق، بينما لا هو أخذ قرار في بعض عدد اختبار قيادة برنامج يمكن نقل غرس صفة. فقط لديه منتج وجود لا تلقي دعم حمل وقت التشغيل اعتماد، أو قد إثبات فعلي وجود دلالة نقص فتحة وقت، ترتيب حذف بعض عدد منصة عندئذ لديه اعتماد حسب.

## قرار

[`@deepseek-ai/dsh-tui`](../../../../packages/ui/tui/README.md) في Windows،macOS و Linux فوق متساو دعم حمل تفاعل صيغة طرفية. منتج متابعة استخدام pi-tui `ProcessTerminal`؛ في Windows فوق، هو سوف في دخول أصلي نمط بعد تفعيل وهمي محاكاة طرفية إدخال، و تجنب فتح فقط ملائم لأجل Unix `SIGWINCH` تحديث جديد.DeepSeek Harness لا زيادة منصة رفض منطق، أيضا لا اعتماد وظيفة تلقي حد Windows نمط.

حقيقي Loader خطر دخان اختبار أصل حسب مضيف اختيار أصلي زائف طرفية حد.macOS و Linux متابعة استخدام Python POSIX PTY قيادة،Windows فإن استخدام `node-pty` و ConPTY. اثنان نوع قيادة استقبال نفسه بدء أمر، بيئة، طرفية مقياس قياس، بـ علامة لـ إطلاق شرط إدخال حركة عمل، مهلة، مسبق مدة خروج رمز و إخراج تأكيد؛3 عدد خطر دخان مشهد كل سوف في كل تلقي دعم حمل منصة فوق تشغيل.

`node-pty` هو examples مساحة العمل فقط توفير اختبار استخدام اعتماد. هذا اعتماد مرور مراجعة أصلي تثبيت نص برمجي في `pnpm-workspace.yaml` في صريح تفعيل؛ إنتاج TUI حزمة (package) لن إضافة جديدة اعتماد أو عملية فرعية طبقة.

## سبق اعتبار بديل خطة

- **إعلان TUI لا دعم حمل Windows**: غير مقبول، لأن ثابت إصدار طرفية وقت التشغيل قد صريح تنفيذ Windows تحكم منصة إدخال، كما harness لا يوجد فقط ملائم لأجل POSIX إنتاج اعتماد. فقط عبر وثيقة ترتيب حذف Windows، انتظار في لـ نقل حينئذ اختبار harness نقص فتحة بينما ترك ترك قائم منتج مسار.
- **عبر MSYS،Cygwin أو WSL تشغيل POSIX قيادة**: غير مقبول، لأن هذا سوف اختبار توافق بيئة، بينما لا هو مستخدم فعلي تشغيل أصلي Windows تحكم منصة مسار.
- **في كل مضيف فوق استخدام `node-pty`**: غير مقبول، لأن قائم POSIX قيادة قد لـ macOS و Linux توفير الذي يحتاج حد؛ استبدال هذا قيادة سوف توسيع كبير وقت التشغيل تغيير نطاق، لكن لن إعطاء هذا اثنان عدد مضيف حمل قدوم تعديل دخول. حسب منصة اختيار قيادة، فقط في Windows فوق تفعيل `node-pty` وقت التشغيل مسار، معا مشترك نفس نسخة مشهد عقد نحو.
- **اعتماد مصير اختبار وحدة و دلالة طرفية لقطة**: غير مقبول، لأن نموذج محاكاة طرفية لا يمكن إثبات Loader بدء، حقيقي أصلي إدخال، عملية خروج أو عملية نظام حد فوق طرفية استعادة.

## عاقبة

- Windows ناتج lane تنفيذ بدء، نص برمجي تحويل تفاعل، إعداد استعادة فشل و طرفية استعادة مشهد، هذا طقم اختبار لن في أي تلقي دعم حمل منصة فوق قفز مرور.
- Windows عملية درجة تحقق اعتماد ConPTY و ثابت إصدار `node-pty`؛ تغيير هذا اعتماد أو سماح تنفيذ تثبيت نص برمجي وقت، يجب إجراء أصلي حد مراجعة.
- اثنان نوع PTY قيادة داخلي تنفيذ يمكن مختلف، لكن مشترك إدخال و تأكيد سوف جعل ذلك يمكن مراقبة قياس TUI عقد نحو إبقاء متسق.
- Windows دعم حمل نطاق بـ مستودع تسليم Node و pi-tui إصدار لـ حد؛ لا تلقي دعم حمل قديم إصدار Windows تحكم منصة بيئة لن نيل نيل توافق طبقة.
