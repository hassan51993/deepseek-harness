# Agent Note: plan mode——سجل إلى سجل تدريجي agent جلسة نمط

Status: implemented
Archived: 2026-07-26

[English](2026-07-07-plan-mode.md) | العربية

> **قد يحل محل مفردات (2026-07-22):**[سوف أداة اسم جلسة نمط استلام جمع لـ plan mode](../simplification/2026-07-22-plan-specific-collaboration-state.md) قد سوف هذا قلم تسجيل في عام `dsh-mode`،`mode/set`، تعريف map و `ctx.modes` تصميم، استبدال لـ حالي plan مخصص استخدام `dsh-plan-mode`،`plan/mode`،`{ section }` و `ctx.planMode` عقد نحو. تحت نص مراجعة، حد، يمكن إعادة بناء صفة و صندوق رملي صحيح تسليم صفة قرار ما زال صالح؛ عام API عرض مثال فإن بصفة هذا مرة بسيط تحويل الذي إزالة تاريخ تصميم إبقاء تحت قدوم.

> **قد يحل محل ACP(Agent Client Protocol) خريطة:**[ACP بصفة فقط موجه إلى تلقائي تحويل بروتوكول](../simplification/2026-07-23-acp-automation-only-protocol.md) إزالة تحت نص الذي وصف اختيار جهاز، إعداد خيار و elicitation خريطة. موجه إلى شخص صنف واجهة ما زال يمكن استخدام plan mode.

## مشكلة

هذا مرة تغيير قبل،harness لا يمكن حمل دائم أرض يجعل بعض عدد agent(ذكي جسم) اعتماد وحيد خاص عمل وضع حالة.Plan mode اشتراط agent في قاعدة تخطيط إشارة جذب تحت استكشاف و تصميم، إنتاج خروج يمكن توفير مراجعة ناتج، عبر مرور واضح مراجعة دفعة حد، و في استعادة و fork بعد أيضا أصل هذا حالة، معا لا يستطيع يجعل نموذج مرئي طلب انحراف مغادرة جلسة سجل.

قائم توسيع seam قد توفير دورة حافة آلية:[`system-prompt/assemble`](../../../../packages/core/system-prompt/README.md) لـ كل خطوة تشكيل صنع إشارة جذب، قد إرسال طلب فإن سجل في `request/header*` حدث في (مشاركة رؤية[يمكن إعادة بناء صفة](../../implemented/architecture/2026-07-05-reconstructable-requests.md)) ؛[`ctx.userInteraction`](../../../../packages/ui/user-interaction/README.md) تحمل تحميل مراجعة دفعة مشكلة و تصحيح صحيح عكس تغذية (مشاركة رؤية [ask-user أولا مثال](../../implemented/feature/2026-06-25-ask-user-question.md)) ؛`SessionEventMap` تحمل تحميل تدريجي agent حمل دائم واقع (مشاركة رؤية [`todo/write` أولا مثال](../../implemented/feature/2026-06-29-todo-write-tool.md)). نقص قليل هو سوف هذه seam وصل في واحد بدء أداة اسم جلسة حالة، معا ما زال يجعل مستقل صندوق رملي محور و مراجعة دفعة محور مسؤول تنفيذ قيد.

## قرار

تسليم بند هو **plan mode**. هو بصفة أول عدد**جلسة نمط**إصدار، أي واحد أداة اسم، سجل إلى سجل كما تدريجي agent توليد فاعلية تنسيق عمل حالة: نمط تعريف هو من نشر إعداد، توفير نموذج فحص نظر إشارة جذب؛ مقابل بعض عدد agent توليد فاعلية نمط فإن هو من ذلك سجل طي خروج جلسة حالة. نمط بنية صار واحد بند محور، قوي صنع قيد دوران زر——صندوق رملي نمط و مراجعة دفعة سياسة——بنية صار أخرى محور؛ هو جمع من لا متبادل متبادل قراءة كتابة، هذا و Codex سوف Plan/Default تنسيق عمل مسبق ضبط نفس صندوق رملي و مراجعة دفعة ضبط قسم فتح فعل قاعدة متسق. جديد منتج حزمة (package)`@deepseek-ai/dsh-mode` يقع في `packages/mode/mode/`، يملك حدث مفردات، دقيق بسيط `ctx.modes` خدمة و الكل مستمع؛ حلقة بلا حاجة تعديل.`plan` هو وحيد مطلوب تعريف؛ اعتماد نمط شكل حالة مفردات، هو لـ بـ بعد زيادة ثاني نوع نمط وقت بلا حاجة إعادة تسمية حمل دائم حدث نوع، بينما لا هو لأن حالي أيضا سوف إصدار أخرى نمط.

هذا حالة هو `SessionEventMap` واحد عضو:**`mode/set`** هو فقط سجل سجل، لا دخول surface حدث، يحمل أداة لديه كامل قيمة استبدال دلالة `{ mode: string }`؛ آخر لديه صاف دالة `foldMode(events)` إرجاع توليد فاعلية نمط، أي الأكثر بعد واحد `mode/set`، لا يوجد هذا حدث وقت فإن إرجاع افتراضي نمط. من في[سجل هو واقع عبر طريق](../../implemented/architecture/2026-06-30-event-domain-semantics.md) ، استعادة،fork و ضغط بلا حاجة مقدار خارج آلية يكفي أيضا أصل نمط،UI فإن من `session/event` قراءة نمط تبديل. افتراضي نمط يمثل لا وجود نمط إشارة جذب، أي لا يوجد مقطع سقوط، مرور ترشيح أو بوابة. تحميل `dsh-mode` بعد، كل نوع نمط ما زال سوف مساهمة نفس عدد مستقر `exit_plan_mode` schema؛ هذا بند ثابت صار هذا تجنب تجنب نمط حد موضع أداة دليل اهتزاز حركة.

نمط كل خارج إظهار سلوك كل هو لين قيد:`mode:policy` نص التوجيه مقطع سقوط تصيير حالي تعريف إشارة جذب، بينما `exit_plan_mode` في كل نوع نمط تحت كل إبقاء في قد تسجيل أداة دليل في، فقط عند طي نمط لا هو `plan` وقت عندئذ في تنفيذ مرحلة مقطع رفض. لذلك، تحويل فقط سوف في تحت واحد خطوة تغيير يمكن عودة بسبب `request/header` في توجيه النظام جزء، من بينما في لا تغيير Native schema أو Code Mode SDK حال حال تحت متابعة ممتلئ كاف[يمكن إعادة بناء صفة](../../implemented/architecture/2026-07-05-reconstructable-requests.md). نمط متعمد لا قوي صنع تنفيذ أي قيد: لا يوجد تنفيذ بوابة، لا مرور ترشيح أداة، أيضا لا لمس و صندوق رملي أو مراجعة دفعة دوران زر. إذا مستخدم أمل نظر قاعدة تخطيط خلال وجود صلب صفة فقط قراءة تحت حد، يمكن في نمط اختيار جهاز جانب تبديل صندوق رملي نمط خيار؛ اثنان من أولا بعد ترتيب مهمة معنى، أي واحد بند محور كل لن إزعاج حركة آخر بند محور. نفس مثال أيضا لا وجود تدريجي نمط أداة سماح/رفض بيان؛ نمط سماح أي بعض أداة يخص فرعي أثر مشكلة، في أداة تعريف قدرة كاف إعلان ذاته فرعي أثر قبل مؤقت مؤقت معالجة (رؤية[تأجيل عمل](#deferred)). نمط فقط اعتماد اعتماد ذلك مقطع سقوط إشارة جذب و خروج مراجعة قدوم قيد سلوك.

نموذج عبر **`exit_plan_mode`** أداة مغادرة فتح plan mode. ذلك وحيد معامل هو plan نص، لذلك يمكن من سجل إعادة بناء plan؛ هذا أداة ذاتي سطر عبر مستخدم تفاعل seam إتمام مراجعة: مشكلة مساعد مساعدة تفصيل حال يحمل تأكيد قطع plan، و توفير خيار و ذاتي من نص عبر طريق، بينما لا هو فقط لديه واحد بند عار إذن. مراجعة دفعة عبر بعد، سجل إلى سجل نمط قطع عودة افتراضي نمط؛ رفض فإن يصبح يحمل مستخدم تدريجي حرف عكس تغذية تصحيح صحيح خطأ، يجعل نموذج قدرة امتداد واضح جهة نحو متابعة قاعدة تخطيط. مستخدم يمكن من مهمة معنى واجهة عبر `ctx.modes.set()` تبديل نمط؛ تبديل سوف في تحت واحد جولة حد تطبيق (جلسة حدث كل غلاف إغلاق في جولة داخل) ، كما فقط لديه نموذج مرئي حالة تأكيد فعلي تغير وقت عندئذ نحو نموذج شرح وصف مرة.

## عال طبقة API

### مرة طرف إلى طرف plan-mode جلسة

مستخدم عبر ACP نمط اختيار جهاز أو طرفية مدخل في `/plan [message]` سوف جلسة تبديل إلى plan mode؛ من تحت واحد خطوة بدء، كل طلب كل يحمل قد إعداد plan إشارة جذب مقطع سقوط. إذا إعطاء خروج اختياري رسالة، نفس أمر أيضا سوف يأخذ هو إيداع إلى تلقي أثر خطوة في.`exit_plan_mode` schema في افتراضي نمط تحت قد وجود، و سوف إبقاء تدريجي بايت ثابت.

نموذج إجراء استكشاف و تصميم؛ مقطع سقوط في إشارة جذب سوف يجعل هو يأخذ تغيير دفع متأخر إلى plan في. صندوق رملي و مراجعة دفعة دوران زر إبقاء مستخدم ضبط قيمة ثابت؛ أمل نظر قاعدة تخطيط خلال من داخل نواة قوي صنع فقط قراءة نشر جهة (أو مستخدم) ، يمكن يأخذ plan mode و مستقل صندوق رملي نمط خيار إعداد دمج استخدام.

دقيق تجهيز حينئذ خيط بعد، نموذج استدعاء `exit_plan_mode`، و يأخذ plan markdown بصفة معامل؛ مراجعة مشكلة سوف هذا مقطع تأكيد قطع markdown بصفة مساعد مساعدة تفصيل حال، مستخدم يمكن دفعة دقيق، أيضا يمكن اشتراط متابعة قاعدة تخطيط و ذاتي من ملء كتابة عكس تغذية.Native استدعاء أيضا سوف تصيير plan بطاقة؛Code Mode تضمين طقم توزيع لا يوجد Native بطاقة، لذلك مراجعة تفصيل حال هو مشترك استخدام عرض واجهة.

دفعة دقيق بعد، أداة يأخذ سجل إلى سجل نمط قطع عودة افتراضي نمط: تحت واحد خطوة سوف إزالة plan مقطع سقوط، لكن إبقاء نفس عدد أداة دليل (تغير بعد header قد سجل إلى سجل) ، هذا بعد تنفيذ تتبع أثر هذا حينئذ من `todo_write` مسؤول. اشتراط متابعة قاعدة تخطيط وقت، نموذج سوف استلام إلى يحمل مستخدم عكس تغذية نص تصحيح صحيح خطأ، مع بعد تعديل و مجددا مرة عرض.

### نشر إعداد

نمط تعريف هو مرور مرور تحقق إضافة Config؛ اعتماد وفق مستودع اتفاق، هو يمكن عبر `cordis.yml` تعديل، بلا حاجة تحرير شفرة. نشر يجب توفير كامل `plan` مقطع سقوط؛ هذا حزمة لا داخل وضع أي نموذج إشارة أمر. أخرى نمط استخدام نفس نسخة إعداد map:

```yaml
- id: mode
  name: '@deepseek-ai/dsh-mode'
  config:
    modes:
      plan:
        section: |
          You are in plan mode: explore and design, then present the
          plan for approval through exit_plan_mode.
```

تعريف دقيق شكل حالة هو `{ section }`؛ منها متعمد لا توفير تدريجي نمط أداة بيان أو قوي صنع قيد حقل (رؤية[معتاد رؤية مشكلة](#faq)). تعريف اسم استخدام صغير كتابة مائل عمود أمر فرعي تجميع `/^[a-z][a-z0-9_-]*$/u`؛`default` هو إبقاء بند (يمثل لا يوجد سياسة) ، لا يستطيع استخدام عمل مفتاح. اسم بلا فاعلية أو وجود لم معرفة تعريف مفتاح——يشمل `tools` بيان أو `access` حد أعلى——سوف في تحميل وقت تحقق فشل؛ لم معرفة نمط اسم فإن سوف في استدعاء `set()` وقت كبير صوت فشل.

### في طرفية في

طرفية مدخل عبر إضافة ذاتي لديه أمر سجل التسجيل (`@deepseek-ai/dsh-commands`) ، لـ كل قد إعداد تعريف نيل نيل واحد بند دخول أمر:`dsh-mode` لـ مطلوب تعريف تسجيل `/plan [message]`، مثال مثل أيضا سوف تسجيل `/review [message]`(عند إعداد `review` وقت). كل بند أمر كل سجل ذلك أداة اسم تبديل؛ غير فارغ اختياري رسالة سوف ذهاب حذف أول ذيل فارغ أبيض و نقل إعطاء `agent.steer()`، بعد من سوف يأخذ رسالة وضع دخول تشغيل في agent تحت واحد خطوة، أو تفويض حمل إعطاء `send()` بـ فتح بدء جديد فارغ خامل جولة. أمر اسم و نتيجة لن دخول نموذج تاريخ؛ هذا بند صريح رسالة فإن سوف بصفة الذي اختيار نمط تحت عادي مستخدم رسالة سجل إلى سجل. دمج صار `default` بند لا مساهمة أمر. خروج مراجعة بلا حاجة جديد آلية يكفي مباشر في طرفية في تلميح: هو هو عادي مستخدم تفاعل مشكلة، لذلك سوف دخول تركيب بعد مستخدم تفاعل مزود تلميح طابور صف، و `ask_user_question` استخدام طابور صف نفسه.

### عبر ACP

نمط اختيار جهاز هو هذا حزمة مقابل خارج واجهة:`session/new`/`session/load` سوف عبر إبلاغ `availableModes`/`currentModeId`، ذلك قيمة قدوم ذاتي `ctx.modes`(عبر `ctx.get` آلة سوف صيغة إزالة استهلاك، امتداد استخدام `tool-bash` نمط) ؛`session/set_mode` استدعاء `set()` و مرح مراقبة إشعار `current_mode_update`(انتظار توليد فاعلية نمط حينئذ هو مستخدم اختيار، سجل إلى سجل `mode/set` سوف في حد موضع تتبع دخول) ؛`session/event` مستمع فإن سوف في كل مرة قد سجل تبديل مختلف في الأكثر قريب مرة قد إرسال قيمة وقت مجددا مرة إشعار. خروج أداة إعادة استخدام مستخدم تفاعل ACP مزود elicitation مسار؛ ذلك ACP خريطة سوف يحمل مراجعة `detail`، لأن Code Mode تضمين طقم توزيع لا يوجد Native plan بطاقة، بينما Native استدعاء أيضا يمكن مقدار خارج تدفق صيغة نقل هذا بطاقة. صندوق رملي نمط، مراجعة دفعة سياسة و نموذج انتظار مفرد بند بيئة دوران زر لا هو نمط، ينبغي عودة دخول `session/set_config_option`(رؤية[معتاد رؤية مشكلة](#faq)).

### موجه إلى agent إنشاء جهة

`ctx.modes` هو كامل برنامج تحويل واجهة:`list()` إرجاع قد إعداد تعريف و توفير اختيار جهاز استخدام دمج صار `default` بند؛`get(agent)` إرجاع طي نمط و ممكن وجود انتظار توليد فاعلية معنى رسم؛`set(agent, mode)` فإن أصل حسب `list()` مفردات تحقق اسم، و سجل سوف في حد تطبيق معنى رسم.`default` بداية نهاية هو صالح هدف، لذلك خروج نمط و دخول نمط استخدام نفس مرة استدعاء. إنشاء وقت لا يوجد نمط خيار؛ استدعاء جهة في أول عدد جولة قبل عبر `set()` اختيار نمط، مع بعد بـ نفسه طريقة تحديث كتابة. نظام أيضا لا توفير يمكن حجز قراءة فوري `agent/*` مرآة مثل:UI اعتماد وفق[حدث مجال دلالة](../../implemented/architecture/2026-06-30-event-domain-semantics.md) قراءة `mode/set`، هذا حدث قدوم ذاتي `session/event`.

## تفصيل دقيق تصميم

### مفردات

```text
'mode/set': { mode: string }        // SessionEventMap merge in dsh-mode: log-only, non-surface,
                                    // whole-value replace — the last one in the log wins
DEFAULT_MODE = 'default'            // the fold of a log with no mode/set; reserved, not definable
```

تحميل حمل لا يحمل سبب/تتبع مصدر حقل: أداة قيادة تبديل في سجل في ضيق مجاور ذلك `tool/call`، مستخدم تبديل فإن يقع في جولة حد، لذلك سبب حينئذ في سجل متبادل مجاور موضع. هذا و[يمكن إعادة بناء صفة Agent Note](../architecture/2026-07-05-reconstructable-requests.md) إبرة مقابل طلب رأس واقع الذي عمل «سرد وصف حقل يمكن إرسال توليد» قرار نفسه (إجراء في `env/state` حدث لـ الذي بـ يحمل `source`، صحيح هو لأن ذلك عائم نقل تغيير جسم في سجل متبادل مجاور موضع لا يوجد سبب؛ اثنان من شكل صار مقابل وفق، و لا اندفاع مفاجئ). نمط اسم هو إعداد إعلان مفردات، لا هو لا نفاذ واضح عبر حد id، لذلك ما زال استخدام عار نص (لا استخدام `Branded<B>`).

### إعداد و تحليل خطوة

```text
interface ModeDefinition { section: string }                    // prompt text — a mode's whole vocabulary
interface ModeConfig { modes: Record<string, ModeDefinition> }  // plan is required and owns its complete prompt
resolveConfig(config): ResolvedModes                            // explicit resolve (the dsh-bash template), fail-loud:
                                                                // missing plan, 'default', blank sections, and unknown keys rejected
```

مفرد حقل شكل حالة هو متعمد اعتماد الأكثر بسيط تصميم، و غير نهائي مفردات: تدريجي أداة سياسة صيانة درجة سوف بـ أداة تعريف في فرعي أثر بيانات وصفية شكل صيغة ارتداد (رؤية[تأجيل عمل](#deferred)) ، في هذا موضع قراءة، بينما لا هو من كل نوع نمط إعادة إعلان؛ هذا صيانة درجة إلى قدوم وقت، إعداد شكل حالة لا ينبغي حاجة ترحيل.

### طي، خدمة و تحديث كتابة

`foldMode(events)` هو صاف دالة (توجيه خروج توفير إعادة بناء جهة و اختبار استخدام) ، مباشر طي فقط إلحاق جلسة سجل؛`mode/set` لا هو surface عقدة، لذلك ضغط لا يمكن حجب حجب هو.`set(agent, mode)` أصل حسب `list()` مفردات تحقق اسم، أي قد إعداد تعريف إضافة فوق إبقاء `default`؛ بعد من لا يستطيع استخدام عمل إعداد مفتاح، لكن بداية نهاية يمكن بصفة `set()` هدف. هدف و انتظار توليد فاعلية نمط نفسه (لا يوجد انتظار توليد فاعلية نمط وقت فإن و حالي نمط نفسه) وقت، هذا طريقة إسقاط بلا عملية؛ ذلك بقية حال حال سوف يأخذ `{ mode, narrate }` سجل إلى `WeakMap` انتظار توليد فاعلية معنى رسم مجرى في. هو لا يستطيع قيام أي إلحاق، لأن[كل جلسة حدث كل غلاف إغلاق في جولة داخل](../../implemented/architecture/2026-06-15-turn-enclosure-invariant.md) ، بينما فارغ خامل agent لا يوجد فتح جولة.

حلقة اعتراض قطع seam فوق مرور مرور لذا عائق عزل مستمع (مشاركة رؤية[منع صد نمط](../../../../docs/defensive-patterns.md): سياسة إضافة لا نيل منع سد نص التوجيه أو جولة) سوف يأخذ انتظار توليد فاعلية معنى رسم تحديث كتابة لـ واحد بند `mode/set` إلحاق:`agent/prompt-submit` في للتو فتح جولة في، أول مرة تجميع قبل إطلاق؛`agent/turn-continuation` فإن في عادي خطوة إغلاق بعد، لاحق خطوة بدء قبل إطلاق. تلقائي طلب استعادة سوف التفاف مرور continuation، لذلك، قبل وضع `agent/request-error` حزمة تركيب جهاز سوف أولا تفويض حمل إعطاء تركيب بعد سياسة و مختلف خطوة تراجع تجنب، فقط في waterfall إرجاع حلقة قبل تحديث كتابة `retry` قرار؛effect أثر مجال دورة الحياة حراسة حماية سوف كبح صنع في إضافة مورد تحرير بعد عندئذ استعادة قد التقاط حزمة تركيب جهاز. ثلاثة بند مسار كل يقع في أداة تنفيذ و سجل إصدار خارج (إيداع بعد `session/event` مراقبة جهاز فقط مسؤول مراقبة) ، لذلك كل خطوة كل في ذلك تجميع الذي طي خروج نمط تحت تشغيل. تحديث كتابة نمط و الأكثر بعد واحد `request/header` موضع طي نتيجة مختلف وقت، تحديث كتابة سوف في نفس لقطة في إلحاق واحد بند دمج بعد `context/message` إشعار («مستخدم قد سوف هذا جلسة تبديل إلى plan mode.») ؛ موجه إلى مستخدم سرد وصف حال شكل صف في[معتاد رؤية مشكلة](#faq) في.

### لين طبقة: حساب حساب نيل خروج مقطع سقوط و مستقر خروج schema

قد تسجيل نص التوجيه مقطع سقوط من `AssembleContext.agent` قراءة استدعاء agent نمط، و تحليل لـ حالي تعريف إشارة جذب أو `''`. حلقة تدريجي خطوة تصيير، و في تصيير بعد header حدوث تغير وقت سجل كامل `request/header`، لذلك دخول أو مغادرة فتح نمط متساو يمكن عودة بسبب. هذا مقطع سقوط في كل نوع نمط داخل إبقاء ساكن حالة،plan ذاته فإن بـ رسالة و أداة معامل إبقاء في محادثة في؛ بلا حاجة لـ عبر ضغط إبقاء حالة، بينما في كل طلب في إعادة حقن مستقل plan حالة ([قائم خطة](#prior-art) اعتماد إنجاز قاعدة) ، عبث زيادة نص التوجيه اهتزاز حركة.

إشارة جذب مساهمة لـ `{ name: 'mode:policy', order: 50, text: context => … }`: ترتيب في شخص ضبط (0) بعد، أداة إشارة جذب (100–199) قبل، و في افتراضي نمط أو لا يوجد agent تجميع في لـ فارغ.`exit_plan_mode` فقط عبر `ctx.tools` تسجيل مرة كما من لا مرور ترشيح، لذلك نمط تبديل خلال Native schema و Code Mode توليد SDK إبقاء تدريجي بايت نفسه؛ لم نشر `dsh-mode` بيئة فإن لا يوجد هذا بند ربط. نظام لا تسجيل `tools/pre-execute` مستمع: نمط لا ضبط أي بوابة، خروج أداة ذاته طي نمط فحص سوف رفض plan خارج استدعاء. خروج مراجعة هو واحد حمل خيار و عكس تغذية مشكلة، لا هو إذن، لذلك يقع في أداة عبر مستخدم تفاعل seam تنفيذ مرور مسار داخل.

### `exit_plan_mode`

`defineTool` لديه واحد لا بد ملء `plan: string` معامل.Native تنفيذ سوف يأخذ هو سجل في عادي `tool/call` في؛Code Mode في تنفيذ قبل سجل خارج طبقة `run_code` شفرة المصدر، و في توزيع تسوية بعد يأخذ مواصفة تحويل تضمين طقم معامل إلحاق إلى `tool/code-dispatch`.`execute` سوف رفض لا يوجد agent استدعاء (امتداد استخدام [`todo_write` أولا مثال](../../implemented/feature/2026-06-29-todo-write-tool.md)) و طي نمط لا هو `plan` استدعاء، و في استفسار سؤال مراجعة شخص قبل رفض فارغ plan أو لا يحتوي عنوان plan؛ مع بعد، هو عبر `ctx.userInteraction.ask()` إرسال بدء مرة مفرد اختيار مراجعة، ذلك `detail` هو تأكيد قطع plan، و فتح وضع ذاتي من نص عكس تغذية، توفير مستخدم دفعة دقيق أو اشتراط متابعة قاعدة تخطيط. فقط لديه تماما جيد اختيار واحد `Approve` عندئذ يمثل نفس معنى، أخرى أي شكل حالة كل حسب فشل إغلاق معالجة. دفعة دقيق سوف سجل واحد بند سوف في حد توليد فاعلية كما لا سرد وصف معنى رسم، لأجل تبديل إلى `default`، و إرجاع بسيط قصير تأكيد. نشر إشارة جذب اشتراط نموذج يأخذ هذا مرة استدعاء بصفة عودة تكرار في وحيد كما الأكثر بعد مرة أداة استدعاء؛ إذا نموذج مخالفة عكس هذا قاعدة، وقت التشغيل ما زال سوف يجعل هذا دفعة مرة باق بقية جزء إبقاء plan إشارة جذب، تحت واحد خطوة عندئذ سجل تغير بعد header، منها إزالة إشارة جذب بينما أداة schema إبقاء ثابت. كل لم نيل دفعة دقيق نتيجة كل سوف إرجاع تصحيح صحيح صفة `isError`، و يجعل نمط إبقاء في `plan`.

ذلك[تصيير معنى رسم](../../implemented/architecture/2026-07-02-tool-render-intent-union.md) في تصميم لـ أول حينئذ قد تحديد:`presentCall` هو `generic` بطاقة، بـ plan أول عدد عنوان تسمية، بـ plan markdown بصفة محتوى، آخر إعداد واحد ورقة `generic` نتيجة بطاقة.Native مدخل سوف في مشكلة قبل عرض هذا بطاقة؛Code Mode تضمين طقم توزيع لن إنتاج Native استدعاء بطاقة حدث، لذلك مستخدم تفاعل `detail` سوف في كل مزود فوق مستقل يحمل نفس نسخة plan. نظام آلة سوف صيغة إزالة استهلاك هذا seam(`ctx.get('userInteraction')`) ، الذي بـ `dsh-mode` في لا يوجد هو وقت ما زال يمكن تركيب، و تخفيض لـ[معتاد رؤية مشكلة](#faq) في تحديد يد حركة خروج طريقة.

### اعتماد و واجهة

`dsh-mode` هو واحد منتج حزمة، بينما لا هو من ثلاثة عدد حزمة مجموعة صار قدرة seam(رؤية[اعتبار مرور بديل خطة](#alternatives-considered)): هو مقابل انتظار اعتماد `cordis`،`dsh-session`،`dsh-agent`،`dsh-tools` و `dsh-system-prompt`، حقن `['tools', 'systemPrompt']`، و في تنفيذ وقت آلة سوف صيغة قراءة `ctx.userInteraction`(إشارة نحو `dsh-user-interaction` فقط نوع مقابل انتظار اعتماد حافة) ؛ ذلك فقط لديه UI جانب حافة أيضا هو اختياري فقط نوع مقابل انتظار اعتماد (تدريجي تعريف دخول أمر استخدام `dsh-commands`). حذف `ctx.modes` استدعاء واجهة خارج، كل محتوى كل عبر مستمع مشاركة و، لذلك إزالة هذا حزمة سوف مستو مستقر إزالة نمط، بينما لن كسر تالف مستهلك. طرفية مدخل بلا حاجة نمط مخصص استخدام شفرة: تركيب أمر سجل التسجيل بعد،`dsh-mode` سوف ذاتي سطر تسجيل كل تعريف أمر (إشارة نحو `dsh-commands` اختياري فقط نوع مقابل انتظار اعتماد حافة) ، خروج مراجعة فإن استخدام تركيب بعد مستخدم تفاعل مزود تلميح طابور صف.[عال طبقة API](#over-acp) قد تحديد ACP بروتوكول خريطة؛ في حزمة علاقة فوق، جسر وصل طبقة مقابل `dsh-mode` اعتماد فقط نوع مقابل انتظار اعتماد حافة و آلة سوف صيغة قراءة خدمة، الذي بـ لا يحتوي هذا إضافة جسر وصل طبقة سلوك و حالي تماما نفسه.

### قد سجل مشهد و harness عملية

`input.json` إضافة جديدة واحد نوع خطوة عملية `{ "op": "setMode", "modeId": "plan" }`، عبر حقيقي `session/set_mode` RPC قيادة، و إعداد لديه نص برمجي تحويل `elicitationAnswers` طابور صف.`plan-mode` مشهد في رقم 1 عدد جولة قبل دخول plan، في مستقل إعداد صندوق رملي تحت تشغيل حقيقي `cat`، عبر `exit_plan_mode` عرض plan، استقبال نص برمجي تحويل مراجعة دفعة، لكن بعد في تحت واحد خطوة تحرير. أول عدد `request/header` يتضمن كامل، مستقر أداة تجميع و قد إعداد نمط مقطع سقوط؛ دفعة دقيق بعد تغير header سوف إبقاء تدريجي بايت نفسه أداة schema، فقط إزالة هذا مقطع سقوط.`plan-mode-reject` ثابت تصحيح صحيح صفة ذاتي من نص عكس تغذية و لم تغير plan حالة. اثنان نسخة سجل كل في Seatbelt أو bwrap تحت إعادة تشغيل مضيف أمر؛ خلفية خاص لديه صندوق رملي رفض ما زال إبقاء في bash أداة وحدة طبقة.

### آلة آلة استلام ذيل

نظام لا إعلان جديد Cordis حدث (`mode/set` عبر `session/event` نقل تمرير، مستمع مرفق حال إلى قائم waterfall) ، لذلك حدث دليل ثابت. نفس تغيير إعادة توليد التالي محتوى: حفظ دائم سجل دليل (`mode/set`) ، خدمة دليل (`ctx.modes`،JSDoc كامل) ، إعداد دليل (`ModeConfig`) ، أداة دليل (`exit_plan_mode`) ، إنتاج جهة/مستهلك map و وثيقة رسم، و وحدة رسم. مستودع وصل خط يشمل: أصل tsconfig `paths` بند، جديد حزمة مجموعة README و[حزمة بحث جذب](../../../../packages/README.md) في واحد سطر (إضافة جديدة قمة طبقة حزمة مجموعة صحيح هو هذا جدول الذي تسمية متعمد عملية) ،`architecture.md` في مرور مرور ميزانية فحص `ctx.modes` قدرة خدمة سطر، و فعلي تشغيل يد سجل مقابل سطر ترقية.

## تأجيل عمل

التالي كل بند كل حاجة مستقل قرار: عبر تحويل إرسال إنشاء وقت نمط خيار تنفيذ subagent نمط وراثة (من في لا يوجد مستهلك بينما إزالة، سوف مع أول عدد مستهلك ارتداد) ؛`plan` خارج مسبق ضبط نمط (فقط قراءة، قبول تحرير) ؛ إذا انتظار توليد فاعلية معنى رسم فقد فقد يتم إثبات هو حقيقي مشكلة، فإن جذب دخول فارغ خامل سجل أصل لغة؛ و الأكثر إعادة يلزم**في أداة تعريف فوق ذاتي سطر إعلان فرعي أثر**، أي تدريجي أداة فقط قراءة/تغيير تصنيف (MCP `ToolAnnotations` مفردات——`readOnlyHint`/`destructiveHint`——هو ذاتي لكن نموذج لوح، منها مقابل غير ممكن معلومة تلميح تحذير إبلاغ معنى طعم حال أيضا يحتاج منطقة قسم معلومة مهمة طبقة درجة). عام تدريجي نمط أداة سياسة صحيح في انتظار هذا واحد بند: هذا Agent Note الأكثر أول إصدار مرور مؤقت تدريجي نمط اسم سماح بيان، و في إصدار قبل إزالة؛ يد عمل صيانة بيان خطأ أرض جدول بلوغ فرعي أثر مشكلة، يجب تتبع أثر نشر الذي تركيب كل أداة، كما سوف مع أداة زيادة بينما بلا صوت فاسد تحويل. لذلك، حسب نمط حد أداة متاح صفة (و تدريجي أداة `ask` سياسة) سوف بصفة قد إعلان فرعي أثر مستهلك ارتداد، بينما أول بند إزالة استهلاك يحتاج طلب حينئذ هو ذلك إعادة بدء إطلاق شرط.

ACP تلقائي تحويل تركيب لا تركيب plan mode أو مشكلة أداة. موجه إلى شخص صنف تركيب يملك plan اختيار و مراجعة؛ تجمع تركيز plan-mode اختبار و تفاعل واجهة لقطة سوف ثابت ذلك قد سجل حالة، إشارة جذب، مراجعة و مستقر أداة schema.

## معتاد رؤية مشكلة

التالي محتوى توضيح صاف اختيار تحديد تصميم سلوك؛ تعرض مرفوض تصميم رؤية[اعتبار مرور بديل خطة](#alternatives-considered) ، قد قبول بديل قيمة رؤية[عاقبة](#consequences).

**مستخدم تبديل نمط بعد أي وقت توليد فاعلية؟** في تحت واحد تجميع قبل حد توليد فاعلية:`agent/prompt-submit` تغطية أول عدد خطوة،`agent/turn-continuation` تغطية عادي لاحق خطوة، تركيب سياسة بعد `agent/request-error` إعادة محاولة قرار تغطية تلقائي استعادة. لذلك، في طلب أو إعادة محاولة تراجع تجنب إجراء خلال اختيار نمط سوف تشكيل صنع تحت مرة نموذج طلب. هذا حينئذ هو[قائم خطة](#prior-art) في كل بند منتج كل اعتماد «تطبيق في لاحق طلب» دلالة.

**أي وقت نحو نموذج شرح وصف نمط تغير؟** فقط عند نموذج مرئي حالة تأكيد فعلي تغير وقت: تحديث كتابة سوف يأخذ للتو تحديث كتابة نمط و الأكثر بعد واحد `request/header` موضع طي نتيجة إجراء مقارنة مقارنة، و دمج شرح وصف مرة. صاف تغير لـ صفر تبديل تسلسل (أولا دخول plan، مجددا في حد قبل قطع عودة) لن إنتاج سرد وصف؛ أداة قيادة خروج فقط عبر ذاته أداة نتيجة سرد وصف؛ أول عدد جولة قبل ضبط نمط أيضا لا سرد وصف، لأن هذا مقطع سقوط ذاته حينئذ هو حالة شرح. هذا أصل فإن قدوم ذاتي إجراء في env-state رفع سجل حد سرد وصف: إذا نص التوجيه جدول طبقة صامت لكن تبديل،transcript(نص سجل) ما زال سوف اعتماد حسب header قد لم يعد أداة تجهيز حالة إجراء نقاش وصف.

**استعادة وقت، إعداد قد لم يعد تعريف طي خروج نمط سوف كيف مثال؟** حالي إعداد لم يعد تعريف طي نمط اسم سوف في لا إشعار حال حال تحت جدول الآن لـ افتراضي نمط، لذلك جلسة حيث لن نيل نيل بديل قيد، أيضا لن تغيير نيل غير ممكن استخدام.`set()` كبير صوت تحقق فقط تغطية كتابة مسار؛ استعادة بعد سجل بـ عند وقت بحث إلى إعداد لـ دقيق.

**إذا نشر لا يوجد تركيب مستخدم تفاعل مزود، سوف كيف مثال؟** Plan mode ما زال أمان، لكن فقط قدرة يد حركة خروج:`ctx.userInteraction.ask()` سوف رمي خروج `NO_PROVIDER`(seam لا وجود وقت جدا حتى لا يمكن تحليل إلى هذا خدمة) ، أداة إرجاع تصحيح صحيح صفة `isError`، خروج طريقة تخفيض لـ من مستخدم تبديل نمط، أبدا سوف في لم مرور مراجعة وقت خروج. نمط مقطع سقوط سوف اشتراط نموذج عبر `exit_plan_mode` عرض plan، و في فشل وقت تعديل استخدام عادي نص استفسار سؤال مستخدم، لذلك نموذج سوف متابعة عرض، بينما لن توقف ركود.

**لـ أي لا يوجد تدريجي نمط أداة سماح بيان؟** لأن «أي بعض أداة في قاعدة تخطيط نمط تحت أمان» هو كل أداة ذاته خاصية (أي فرعي أثر) ، لا هو نمط خاصية. تدريجي نمط اسم بيان سوف في خطأ ملكية موضع إعادة إعلان هذا واقع، يجب قطعة رفع نشر الذي تركيب كل أداة (يشمل MCP خادم) ، كما سوف مع أداة إلى قدوم بينما بلا صوت فاسد تحويل. في أداة تعريف إعلان ذلك فرعي أثر قبل (رؤية[تأجيل عمل](#deferred) ، منها عودة ملف يتم إزالة مؤقت سماح بيان و ذلك إعادة بدء إطلاق شرط) ، نمط فقط عبر ذاته مقطع سقوط و خروج مراجعة قيد سلوك؛ من هذا إنتاج كشف وجه يخص قد قبول بديل قيمة (رؤية[عاقبة](#consequences)).

**subagent هل وراثة أب درجة نمط؟** fork فرعي درجة يمكن مباشر وراثة، لأن أب درجة `mode/set` يقع في نوع فرعي بادئة في.spawn فرعي درجة من افتراضي نمط بدء؛ إنشاء وقت نمط خيار و subagent مزود تلقائي تحويل إرسال واحد و تأجيل (رؤية[تأجيل عمل](#deferred)).

**plan mode و صندوق رملي فقط قراءة نمط لديه أي علاقة؟** اثنان من هو متبادل لا وصل لمس مستقل محور: نمط هو تنسيق عمل وضع حالة (`mode/set` طي) ، صندوق رملي نمط هو قوي صنع قيد دوران زر (`bash/sandbox-mode` طي، مشاركة رؤية[صندوق رملي Agent Note](2026-07-06-sandbox.md)).Plan mode حيث لا قراءة أيضا لا حد صندوق رملي نمط، و Codex سوف Plan/Default مسبق ضبط نفس صندوق رملي و مراجعة دفعة ضبط قسم فتح فعل قاعدة تماما متسق. أمل نظر قاعدة تخطيط خلال من داخل نواة قوي صنع فقط قراءة مستخدم حاجة معا ضبط اثنان من: بـ مهمة معنى ترتيب تبديل نمط اختيار جهاز و صندوق رملي نمط خيار؛ كل مرة تبديل فقط تغيير ذاته طي نتيجة، لذلك اثنان من متبادل لا جاف إزعاج، أيضا لا وجود ممكن انهيار انهيار أيضا أصل خطوة. سجل سوف يأخذ كل بند محور عودة بسبب إلى كل منها حدث: تنسيق عمل وضع حالة مقابل `mode/set`، عزل قيد مقابل `bash/sandbox-mode`.

**لـ أي صندوق رملي نمط، مراجعة دفعة سياسة أو نموذج ذاته لا يخص نمط؟** هو جمع هو مستقل في تنسيق عمل حالة مفرد بند بيئة دوران زر. قد تراجع دور ACP خريطة سجل في[فقط موجه إلى تلقائي تحويل بروتوكول قرار](../simplification/2026-07-23-acp-automation-only-protocol.md) في. لم قدوم نمط تعريف يمكن ربط ربط بيئة واقع (في تركيب موضع عبر `ctx.envState` تطبيق) ، يجعل Codex ريح إطار مسبق ضبط ما زال هو واحد نوع نمط؛ لكن يأخذ مراجعة دفعة سياسة دمج دمج دخول نمط عام فكرة ذاته خطة قد في[اعتبار مرور بديل خطة](#alternatives-considered) في تعرض مرفوض.

## قائم خطة

مقابل قد إصدار plan mode(Claude Code،Cursor،Copilot،OpenCode،Gemini CLI،Cline،Windsurf،Codex) ضبط بحث جدول واضح، كل منتج كل يتضمن نفس مثال خمسة عدد جزء: منخفض إذن أداة سياسة،plan ناتج، مراجعة دفعة وقت لحظة، تنفيذ حالة تبديل، و[مشكلة](#problem) الذي اعتماد حمل دائم حالة.

فقط يلزم منتج عام نمط واجهة، هذا واجهة حينئذ واحد تحديد هو بيان، أبدا هو قيمة منطقية:Claude Code اختيار جهاز توفير `plan`، جانب حافة هو `acceptEdits`(آخر لديه تلقائي دخول plan نمط) ؛Codex فإن يأخذ `Plan` و `Default` و صف عام لـ تنسيق عمل نمط مسبق ضبط، معا يجعل مراجعة دفعة و صندوق رملي ضبط إبقاء مستقل.ACP نقل طبقة لا عام هذا بند موجه إلى شخص صنف تحكم.

من نشر يملك عرض مثال نص التوجيه استعارة تمييز أداة صفة سلوك، بينما غير منتج خاص لديه آلية. هو استعارة تمييز Codex التالي فعل قاعدة: أي جعل استلام إلى دعاء جعل صيغة تنفيذ لغة أيضا إبقاء في plan mode؛ رفع سؤال قبل أولا استكشاف؛ منطقة قسم مستودع واقع و من مستخدم قرار اختيار؛ يجعل plan كامل تغطية API، بيانات تدفق، فشل، اختبار و زائف ضبط، من بينما كاف بـ عمل خروج قرار. هو أيضا استعارة تمييز Claude Code التالي فعل قاعدة: منع توقف تغيير و إيداع؛ أولوية امتداد استخدام قائم نمط؛ فقط إبرة مقابل يحتاج طلب أو خطة اختيار رفع سؤال؛ عبر خروج أداة إتمام قاعدة تخطيط، بينما لا في عادي نص في طلب مراجعة دفعة. هو متعمد حذف Codex بروتوكول وسم، و Claude plan ملف أو قسم مرحلة مقطع subagent آلية، لأن هذه يخص كل منها وقت التشغيل، بينما غير هذا إضافة عقد نحو.

يأخذ نمط إبقاء إعطاء اتفاق توليد حالة عرض ينبغي تجنب تجنب فشل شكل.Pi ريح إطار نمط توسيع سوف تنازع انتزاع واحد بعد كتابة تغطية عام نشط وثب أداة بيان، فقط اعتماد نص التوجيه نص قوي صنع «فقط قراءة»(نموذج وهم شعور استدعاء واحد ما زال قد تسجيل أداة وقت، هذا استدعاء سوف فعلي تنفيذ) ، و في كل طلب في إعادة حقن plan حالة بـ عبر مرور ضغط. هذا داخل عبر تدريجي agent طي حالة، و ضغط لا يمكن حجب حجب فقط سجل سجل، غير surface حدث، من بنية فوق إزالة حذف لديه تنازع اقتراح عام بيان و تكرار حقن رقعة. متبادل مقارنة لـ تحت، فقط اعتماد نص التوجيه شكل يتم متعمد إبقاء:Codex Plan صحيح هو مثل هذا تنفيذ، هذا أيضا هو نمط محور يمكن و قوي صنع قيد محور ذاتي من تركيب سبب. حاجة صلب صفة تحت حد نشر سوف يأخذ نمط و مستقل صندوق رملي دوران زر إعداد مقابل، بينما لا هو يجعل نمط يحمل ذاته قوي صنع قيد (رؤية[معتاد رؤية مشكلة](#faq)).

## اعتبار مرور بديل خطة

**بـ إذن نمط بصفة نواة قلب عام فكرة (Claude Code شكل).** استخدام واحد `permissionMode` دمج دمج مراجعة دفعة سياسة و أداة سياسة. هذا تصميم في، هو جمع هو عودة مختلف كل من مسؤول اثنان بند محور: مراجعة دفعة seam يملك «من عودة جواب هذا عدد مشكلة» ، نمط يملك «نموذج نيل نيل ماذا واجهة».ACP سوف اثنان من بناء نموذج لـ متبادل صلة لكن لديه منطقة آخر عام فكرة (نمط بـ بعد يمكن اختيار مراجعة دفعة سياسة؛ دورة وقت هو نمط تعريف زيادة حقل، بينما لا هو دمج اثنان من).

**من ثلاثة عدد حزمة مجموعة صار قدرة seam.** واجهة/تنفيذ/مستهلك ملائم دمج يمكن استبدال خلفية؛ نمط متغير جزء هو إعداد قيمة، بينما لا هو تنفيذ. تفكيك قسم سوف صنع صنع واحد فارغ تنفيذ حزمة، و مراجعة دفعة seam و [`todo/`](../../implemented/feature/2026-06-29-todo-write-tool.md) عمل خروج «لا يلزم مرور مبكر تفكيك قسم» قرار نفسه.

**من حلقة يملك نمط حالة.** اعتماد حسب قائم قاعدة (استخدام إضافة، بينما لا تعديل حلقة) إعطاء بـ مرفوض: هذا وظيفة الذي يحتاج كل خطاف——تجميع، تنفيذ قبل معالجة، جولة حد، جلسة حدث——كل قد هو لديه وثيقة سجل seam، تعديل حلقة فقط سوف زيادة اقتران دمج، آخر بلا استلام فائدة.

**حمل افتراضي رفض بوابة تدريجي نمط أداة سماح بيان (أول عدد إصدار شكل).** قد في إصدار قبل إزالة. يد عمل صيانة اسم بيان سوف تدريجي نمط إعادة إعلان واحد بند تدريجي أداة واقع (أي ذلك فرعي أثر): هو يجب قطعة رفع نشر الذي تركيب كل أداة، يشمل MCP خادم و لم قدوم تسجيل بند، و سوف مع أداة زيادة بينما بلا صوت فاسد تحويل (إضافة جديدة فقط قراءة أداة وقت، في لديه شخص تحرير كل نوع نمط قبل كل سوف يتم منع توقف؛ تحرير كتابة سالب تحمل سقوط في حل نمط شخص ذات فوق، بينما لا هو حل أداة شخص ذات فوق). هو أيضا مرور درجة تحمل وعد: هذا بيان نظر يشبه أمان حد، لكن shell خارج أي قدرة ذلك فعلي كل لا وجود هذا نوع حقيقي حد. عام صيانة درجة قد توقف وضع إلى فرعي أثر ذاتي إعلان (رؤية[تأجيل عمل](#deferred)) ؛ من هذا إنتاج عاقبة——plan mode فقط توفير إشارة جذب، أيضا حينئذ هو هذا بوابة واحد درجة سد تكملة Pi نقص فتحة——هو متعمد قبول، و حساب دخول[عاقبة](#consequences).

**نمط فوق `access` صندوق رملي حد أعلى (ثاني عدد إصدار شكل).** نفس مثال قد في إصدار قبل إزالة.`ModeDefinition.access` سوف يأخذ bash seam تدريجي استدعاء صندوق رملي تحليل حد في نمط إعلان حد أعلى داخل (واحد `bash/resolve-mode` waterfall إضافة فوق أخذ مرحلة سلم الأكثر صغير قيمة مستمع؛ حراسة حماية سوف في منفذ لا يمكن تطبيق إضافة قيد وقت إخفاء bash، و في نمط في طريق رفض رفع رفع إذن). حالة ما زال إبقاء صحيح تسليم، لأن حد أعلى من لا كتابة صندوق رملي دوران زر؛ لكن اثنان بند محور و لا صحيح تسليم: دخول plan سوف تغيير صندوق رملي فعلي قوي صنع تنفيذ محتوى، يأخذ تنسيق عمل وضع حالة و قوي صنع قيد درجة آخر دمج دمج بدء قدوم، مخالفة خلف مراجعة نهائي بلوغ صار Codex شكل قسم مغادرة طريقة (Plan/Default مسبق ضبط من لا لمس و صندوق رملي أو مراجعة دفعة ضبط). هذا نوع دمج دمج لديه واحد بند مستخدم مرئي عرض حالة: قاعدة تخطيط خلال يأخذ صندوق رملي خيار تبديل لـ `workspace-write` لن إنتاج أي فاعلية نتيجة. حد أعلى،waterfall و mode→bash اعتماد حافة مع بعد واحد و إزالة؛ نشر يمكن يأخذ نمط و مستقل صندوق رملي نمط خيار إعداد دمج استخدام، من بينما في قاعدة تخطيط خلال من داخل نواة قوي صنع فقط قراءة. بـ بعد أيضا يمكن إعادة جذب دخول نمط إطلاق مسبق ضبط (نمط تعريف ربط ربط بناء اقتراح دوران زر قيمة، و بصفة عادي دوران زر تبديل إضافة بـ تطبيق) ، بينما بلا حاجة مجددا مرة دمج دمج اثنان بند محور.

**فقط وجود في وقت التشغيل نمط (فقط في UI أو جسر وصل طبقة محلي وجود، لا سجل سجل).** استعادة و fork سوف صامت لكن فقد فقد نمط، نمط جذب بدء header زيادة كمية في سجل في أيضا لا يوجد يمكن عودة بسبب سبب. سجل إلى سجل حالة يجعل نمط بلا حاجة مقدار خارج آلية يكفي مراجعة حساب و أيضا أصل.

**يأخذ نمط تبديل بصفة `context/message` و عبر `agent.inject()` كتابة.** هذا مثال يمكن إعادة استخدام قائم جولة غلاف إغلاق مسار، لكن سوف يأخذ سياسة حالة وضع دخول نموذج transcript؛ نموذج بلا حاجة يتم إبلاغ معرفة اثنان مرة (مقطع سقوط قد إبلاغ إبلاغ هو) ، بينما فقط سجل سجل واقع لا ينبغي احتلال استخدام surface.

**plan ملف تخزين (`.plans/` دليل).** هذا سوف لـ سجل قد بـ يمكن إعادة تشغيل طريقة تحمل تحميل محتوى إنشاء ثاني عدد حمل دائم ملكية موضع؛ حاجة ملف نشر يمكن إضافة واحد كتابة ملف أداة. نفس واقع فقط ينبغي لديه واحد ملكية موضع.

**استخدام قيمة منطقية `planMode` يحل محل أداة اسم نمط.** مقابل مستودع قد تتبع أثر واجهة بينما قول مرور في ضيق ضيق:ACP عبر إبلاغ هو نمط بيان، قد إصدار اختيار جهاز أيضا لا فقط ملء دخول plan(رؤية[قائم خطة](#prior-art)) ؛ بـ بعد مجددا عام تحويل سوف إعادة تسمية حمل دائم حدث مفردات. نص شكل حالة آلية الآن لا إنتاج مقدار خارج صار هذا؛ فقط لديه `plan` بصفة تعريف إصدار.

**أداة سياسة مكدس خدمة (مقابل Pi دفعة تقييم تكملة إنقاذ خطة).** الآن حينئذ لـ أداة سياسة بناء قيام مخصص استخدام تركيب خدمة لـ وقت مرور مبكر: هذا تنفيذ لا تنفيذ حسب نمط حد أداة مرور ترشيح، لم قدوم فرعي أثر سياسة يمكن عبر قائم حمل حراسة حماية تنفيذ seam تركيب. فقط لديه قد إعلان أداة فرعي أثر إنتاج أداة جسم تركيب يحتاج طلب بعد، عندئذ ينبغي صحيح صيغة بناء قيام هذا خدمة.

**عبر مراجعة دفعة seam تنفيذ خروج مراجعة دفعة (واحد `{ kind: 'ask' }` بوابة قرار).** الأكثر أول مسودة سجل رفع خروج هذا خطة؛ عند وقت مراجعة دفعة seam هو وحيد صحيح في سقوط أرض استفسار سؤال آلية، الذي بـ إظهار نيل ذاتي لكن، لكن هو يأخذ مراجعة وضع دخول إذن موضع. هذا seam نتيجة مفردات متعمد غلاف إغلاق كما فقط توفير مفرد مرة استخدام (`allowed-once`/`rejected`) ، لذلك رفض لا يمكن يحمل عكس تغذية، دفعة دقيق أيضا دائم بعيد لا يمكن زيادة خيار (مثال مثل «دفعة دقيق و قبول تحرير»). خروج وقت لحظة هو واحد مشكلة، بينما غير إذن؛ مستخدم تفاعل seam لـ ذلك توفير خيار و ذاتي من نص عبر طريق، رفض عكس تغذية أيضا سوف تدريجي حرف نقل إعطاء نموذج. مراجعة دفعة seam ما زال ملائم دمج حق صحيح إذن بوابة (صندوق رملي رفع رفع إذن) ، سجل التسجيل `ask` مفردات أيضا متابعة توفير أمل نظر في هذا موضع ضبط استفسار سؤال نشر استخدام.

**استخدام عادي نص أو steering(في طريق جذب توجيه) خروج، بينما لا استخدام أداة.** هذا مثال حيث لا يوجد ناتج، أيضا لا يوجد مراجعة دفعة وقت لحظة. أداة معامل ذاته حينئذ هو يمكن توفير مراجعة plan، بينما مراجعة مشكلة سوف يأخذ بنية تحويل هو/لا اختيار مرفق حال إلى تأكيد قطع تحويل فوق و تسليم إعطاء شخص صنف.

## عاقبة

التالي حفظ إثبات الآن قد من وحدة، بروتوكول، لقطة و حقيقي API اختبار طبقة ثابت:

- توليد فاعلية نمط هو جلسة سجل صاف دالة: استعادة و fork بلا حاجة مقدار خارج آلية يكفي أيضا أصل هو؛ تحت واحد تغير خطوة في، واحد بند `mode/set` بعد سوف ظهور مطابقة كامل `request/header`.
- مستخدم قيادة تبديل سوف في تحت واحد حد تماما جيد سرد وصف مرة، صاف تغير لـ صفر تبديل تسلسل لن إنتاج سرد وصف؛ أداة قيادة خروج فقط عبر ذاته أداة نتيجة سرد وصف.
- افتراضي نمط تحت، إضافة لا مساهمة نمط مقطع سقوط، لكن سوف مساهمة مستقر `exit_plan_mode` schema؛ لم نشر `dsh-mode` بيئة لا يوجد هذا بند ربط.
- افتراضي،plan و ذاتي تعريف نمط بين تحويل وقت،Native أداة schema و Code Mode SDK إبقاء تدريجي بايت نفسه؛ فقط لديه قد إعداد إشارة جذب مقطع سقوط حدوث تغير.
- Plan mode لا تغيير قوي صنع قيد محور فوق أي محتوى: أداة تجميع، صندوق رملي نمط، إذن رفع رفع و مراجعة دفعة سياسة في plan و افتراضي نمط تحت جدول الآن تماما نفسه؛ نشر عبر يأخذ نمط و مستقل صندوق رملي/مراجعة دفعة دوران زر إعداد دمج استخدام قدوم قوي تحويل قاعدة تخطيط.
- نمط تعريف يمكن عبر `cordis.yml` تعديل، بلا حاجة تحرير شفرة؛ منها يجب توفير كامل plan إشارة أمر. ناقص plan إعداد، تعريف شاذ شكل و لم معرفة مفتاح سوف في تحميل وقت فشل، لم معرفة نمط اسم سوف في `set()` وقت فشل.
- `exit_plan_mode` بداية نهاية عبر إبلاغ، في plan خارج سوف رفض؛ دفعة دقيق بعد فقط إزالة plan إشارة جذب، و عبر تصحيح صحيح صفة `isError` يحمل متابعة قاعدة تخطيط عكس تغذية؛ كل موجه إلى شخص صنف واجهة كل من ذلك مستخدم تفاعل مزود تحمل تحميل مراجعة.
- مع وظيفة سقوط أرض واحد و تسليم وثيقة استلام ذيل يشمل:README، إعادة توليد دليل (حفظ دائم سجل، إعداد،Cordis خدمة، أداة) ، حزمة بحث جذب و هيكل بنية سطر، و فعلي تشغيل يد سجل في مقابل سطر.

قد قبول بديل قيمة مثل تحت: في agent فارغ خامل وقت ضبط انتظار توليد فاعلية مستخدم تبديل، إذا عملية في تحت واحد جولة قبل خروج، حينئذ سوف فقد فقد (UI سوف إعادة تطبيق؛ إذا فعلي ممارسة في ظهور مشكلة، فارغ خامل سجل أصل لغة حينئذ هو هروب توليد فتحة). نمط تحويل سوف تغيير ترتيب 50 موضع توجيه النظام، لذلك من هذا موضع بدء ذاكرة مؤقتة مسار أيضا سوف تغير، لكن أداة schema و Code Mode SDK لم يعد اهتزاز حركة.**نمط فقط اعتماد اعتماد إشارة جذب قيد سلوك**: تجاهل اختصار هذا مقطع سقوط نموذج يمكن في plan خلال تنفيذ تغيير؛ مراجعة وقت لحظة، جلسة سجل و مستقل صندوق رملي، مراجعة دفعة و نظام الملفات سياسة مشترك نفس بنية صار قيد حد. قوي تحويل قاعدة تخطيط معنى طعم حال ضبط هذه دوران زر، بينما لا هو توسيع كبير نمط مسؤولية؛ يتم إزالة قوي صنع قيد شكل و ذلك فرعي أثر إعلان إعادة بدء إطلاق شرط ما زال سجل في[اعتبار مرور بديل خطة](#alternatives-considered) و[تأجيل عمل](#deferred) في. موجه إلى شخص صنف واجهة يملك plan اختيار جهاز و مراجعة تفاعل؛ACP تلقائي تحويل نقل طبقة اثنان من كل لا تحمل تحميل.
