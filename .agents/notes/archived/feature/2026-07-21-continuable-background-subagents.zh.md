# Agent Note: يمكن متابعة خلفية subagent

هذا سجل قد من[يمكن متابعة subagent](2026-07-28-continuable-subagent-conversations.zh.md) يحل محل——بعد من بـ واحد حمل دائم Session إضافة حتى كثير واحد عملية داخل Activation(إقامة إبقاء مدة) استبدال ذلك أساس في Task activation نموذج، توجيه، إلغاء و حمل دائم صفة دلالة. ذلك خدمة وضع وضع و مزود وظيفة سياسة هذا قبل قد من[سوف subagent تحكم دمج إلى subagent خدمة](../simplification/2026-07-26-merge-subagent-control-service.zh.md) و[بـ معنى رسم تسمية subagent متابعة تنفيذ عملية](../simplification/2026-07-27-intent-named-subagent-continuation-operations.zh.md) يحل محل. فقط حمل دائم child جلسة و descriptor تصميم اعتماد حسب ما زال صالح.

## مشكلة

subagent أداة سوف كل مرة تفويض إرسال نظر لـ واحد وحيد احتلال `SubagentRun`: قبل منصة استدعاء و خلفية Task استلام تجميع نتيجة بعد dispose(مورد تحرير) هذا run. هذا نوع كل حق علاقة قدرة كاف حد تخزين نشط child agent(ذكي جسم) عدد كمية، و تحرير ذلك أثر مجال خدمة، مستمع و مزود مورد. حفظ دائم child جلسة ممكن متابعة وجود، لكن parent نقص قليل حفظ دائم دليل و أداة مسار، لا يمكن اكتشاف هذا child و لـ ذلك بدء آخر جولة.

Task،run و child جلسة أداة لديه مختلف دورة الحياة. واحد Task يمثل واحد جولة خلفية تنفيذ، و كما فقط لديه واحد نهاية حالة نتيجة. واحد `SubagentRun` يملك child مرة تنشيط. واحد حفظ دائم child جلسة يمكن يتضمن كثير عدد من parent أو مستخدم إرسال بدء جولة. متابعة تنفيذ يجب إبقاء تدريجي run dispose اتفاق، بينما لا يستطيع يأخذ كل تاريخ child agent كل إبقاء في داخل تخزين في.

## قرار

واحد يمكن متابعة خلفية subagent، هو من واحد نظام صف Task دعم دعم قصير مدة تنشيط مشترك نفس مجموعة صار حفظ دائم child جلسة.child session id،transcript(نص سجل) ، جدول نظام و إعلان تركيب إعداد متساو إبقاء في حفظ دائم تخزين في. كل مرة ابتدائي تنشيط أو استعادة تنشيط كل سوف إنشاء جديد Task،`AgentHandle` و `SubagentRun`، قيادة واحد جولة، استلام تجميع نتيجة، و في Task دخول نهاية حالة قبل dispose هذا run.

Task نتيجة و إلغاء حد يخص child تنشيط، لا يخص لـ هذا تنشيط توفير رقم واحد بند رسالة استدعاء جهة.Task وصول أصل حسب parent session id تخويل، بينما Task سجل التسجيل ما زال إبقاء حالي تخزين نشط دقيق parent Agent نسخة، لأجل إشعار و مورد تنظيف. لذلك، فقط يلزم parent ما زال هو وقت التشغيل owner،parent رسالة و مستخدم رسالة سهل سوف مشترك نفس عدد تنشيط نتيجة:

```text
durable child Session
  activation 1: Task 1 -> SubagentRun -> AgentHandle -> dispose
  activation 2: Task 2 -> SubagentRun -> AgentHandle -> dispose
  activation 3: Task 3 -> SubagentRun -> AgentHandle -> dispose
```

قبل منصة تفويض إرسال إبقاء مرة صفة سلوك. متابعة تنفيذ تغطية خلفية عملية داخل spawn و fork child. كل `tool-subagent` نسخة كل سوف اختيار `backgroundMode: 'one-shot' | 'continuable'`؛ إعداد لـ يمكن متابعة نمط وقت، الذي تركيب مزود يجب أداة تجهيز `resume` وظيفة، بينما يمكن استعادة مزود ما زال يمكن اعتماد مرة صفة خلفية سياسة. في تحت وصف ACP(Agent Client Protocol) لاحق عمل إتمام قبل،ACP child ما زال إبقاء مرة صفة سلوك.

`ctx.subagents` هو وحيد عام خدمة. عادي `start` لا شعور معرفة child تجميع دمج،Activation و حفظ دائم: هو تحقق مزود وظيفة، تحليل مرة صفة وصف رمز، توزيع واحد run، مراقبة run دورة الحياة، و إرجاع من يحتفظ جهة مسؤول run. حقن داخلي متابعة تنفيذ إدارة جهاز مسؤول إدارة مستقر child id، يمكن متابعة وصف رمز حفظ دائم و فحص بحث،Activation دورة الحياة، و عبر `startContinuable` و `followup` إجراء توجيه؛ إدارة جهاز ذاتي سطر تركيب child قبل، مزود عبر خاص إغلاق حزمة توفير دقيق تجهيز بيانات. حسب مزود ربط `@deepseek-ai/dsh-tool-subagent` إضافة و موجه إلى مستخدم مهايئ استدعاء هذه معنى رسم عملية قدوم معالجة يمكن متابعة خلفية عمل؛ قبل منصة و مرة صفة خلفية تفويض إرسال استخدام عادي `start`. عام تسمية نموذج أداة هو `@deepseek-ai/dsh-tool-subagent-control` في اختياري خفيف كمية مهايئ، هو هل وجود لن قرار هل بدء يمكن متابعة عمل.parent إلى child قطعة رفع، مرة صفة/يمكن متابعة نمط مشترك وصف رمز هوية و `list_agents` يخص[حفظ دائم subagent دليل](2026-07-22-durable-subagent-catalog-and-list-agents.zh.md).

### Task و إلغاء كل حق

ابتدائي خلفية تفويض إرسال طلب `ctx.subagents` بدء child و تسجيل ذلك Task. يمكن متابعة مزود فقط لديه في تأكيد هذا مرة تنشيط نهائي جلسة حالة قد حفظ دائم بعد، عندئذ سوف إرجاع نجاح run نتيجة.Task تسوية مسار انتظار هذا نتيجة، عبر متابعة تنفيذ إدارة جهاز تسوية مسار استدعاء `run.dispose()`، لكن بعد عندئذ سجل `JobOutcome`؛`job_kill` في توقف نشط وثب run، ذلك تسوية مسار ما زال سوف dispose هذا run. لذلك، نهاية حالة Task سوف إبقاء تحت حفظ دائم child جلسة، لكن لن إبقاء تحت تخزين نشط child agent. مطلوب حمل دائم صفة فحص نقطة إذا لا يوجد قد تثبيت مستمع أو مهمة واحد مستمع فشل،run سوف بـ مستقر رمز خطأ `DURABILITY_FAILED` رفض، و سوف فحص نقطة فشل إبقاء لـ فشل سبب؛ إدارة جهاز سوف سجل فشل Task، ذلك تفصيل حال شرح الأكثر جديد حالة لم تأكيد قد حفظ دائم، لذلك استعادة وقت ممكن غير ممكن استخدام أو قد قديم قديم.

لاحق كل جولة كل سوف إنشاء آخر عدد Task. هذا جولة producer يحتفظ تنفيذ مورد فقط خدمة في هذا مرة تنشيط، لا يخص child جلسة. هو فقط سوف وصول مرة نهاية حالة، فقط إنتاج واحد نتيجة، أيضا لن إعادة فتح.Task سجل التسجيل في حالي تسجيل ذلك عدد تخزين نشط parent agent نسخة ما زال هو ذلك owner:dispose هذا نسخة سوف إلغاء، انتظار و إزالة ذلك Task.Task API سوف تخويل session id و هذا owner مطابقة استدعاء جهة، لكن id نفسه بديل نسخة لن يصبح إشعار أو مورد تنظيف هدف. هذا واحد تصميم إبقاء `settleRun()` اتفاق، و جعل Task الذي يملك تخزين نشط child عدد كمية تلقي تزامن عمل كمية حد، بينما لا هو مع تاريخ جلسة عدد كمية زيادة طويل.

مستخدم واجهة مهايئ فتح child جلسة وقت، فقط قراءة حفظ دائم transcript، لن فقط لـ عرض بينما استعادة agent. مستخدم إدخال عبر متابعة تنفيذ إدارة جهاز، بدء أو إضافة دخول و parent إدخال نفسه Task تنشيط. من مستخدم بدء Task سوف إبقاء حالي تحميل دقيق parent Agent بصفة إشعار هدف،`job_output` ما زال هو وحيد نتيجة مسار. فقط يلزم Task بعد لم علامة لـ قد تقرير إبلاغ، قائم إتمام مستمع الأكثر كثير حقن واحد بند رئيسي حركة إشعار؛`kill`، نهاية حالة قراءة أو نهاية حالة انتظار كل ممكن سوف ذلك علامة لـ قد تقرير إبلاغ، و كبح صنع هذا بند إشعار. لذلك، فقط سماح في هذا parent نسخة إبقاء تخزين نشط وقت إجراء مستخدم تفاعل. يمكن مقارنة parent تخزين نشط أكثر دائم، و سوف ربط نقاش صريح دمج عودة ذهاب مستخدم ذاتي لديه جلسة يخص[تفاعل صيغة side session](../../proposed/feature/2026-07-08-interactive-side-sessions.zh.md) ، لا يخص هذا واحد من Task يحتفظ دورة الحياة.

إذا لا يوجد مرفق إضافة مهمة تحكم جهاز،`JobRegistry.start()` سوف رفض producer. لذلك، قبول child إدخال مستخدم واجهة مهايئ يجب مرفق إضافة مهمة تحكم جهاز، أو تشغيل في تحميل `@deepseek-ai/dsh-tool-jobs` نشر في؛ فقط تحميل Task خدمة و لا كاف كاف. هذا بند اعتماد هو parent و مستخدم بدء تنشيط مشترك استخدام Task نتيجة، إلغاء و إشعار مسار الذي دفع خروج بديل قيمة.

إلغاء بداية نهاية أثر في حالي كامل تنشيط. إذا مستخدم رسالة و parent رسالة قد إضافة دخول نفس عدد جولة، مهمة واحد استدعاء جهة إرسال بدء إلغاء كل سوف في توقف هذا جولة،dispose ذلك run، و سوف مقابل Task تسوية لـ `killed`؛ هذه رسالة لا يوجد مستقل نتيجة أو إلغاء حق.`followup()` اشتراط استدعاء جهة توفير إشارة؛ إذا في خط steering صحيح في انتظار طلب دقيق دخول وقت هذا إشارة يتم في توقف، تنشيط ذاتي لديه controller سوف يتم في توقف، بـ سهل مزود إسقاط انتظار معالجة رسالة، و كما هذا استدعاء فقط في فرعي agent تماما توقف مستقر بعد تسوية. إذا حاجة مستقل إلغاء، لاحق رسالة يجب آخر بدء جولة، بينما لا يستطيع إضافة دخول حالي جولة.

من حفظ دائم تخزين استعادة Task سوف في فحص بحث وصف رمز أو انتظار أي مزود عملية قبل، إنشاء من هذا مرة تنشيط يحتفظ `AbortController`؛ وصف رمز فحص بحث، مباشر parent تمييز حق و وصف رمز عودة و كل في هذا Task producer داخلي تنفيذ، لذلك نفس إشارة تغطية هو جمع، ذلك فشل سوف سوف هذا Task تسوية لـ `failed`. مقابل في لا قبول إشارة حفظ دائم استدعاء، يمكن يجعل قاع طبقة I/O تنفيذ تمام انتهاء؛ لكن متابعة تنفيذ إدارة جهاز يجب في كل مرة هذا صنف await إرجاع بعد إعادة فحص إلغاء حالة، مثل قد إلغاء، بعد لا نيل بدء أو إصدار أي child عمل. في Agent إصدار قبل استلام إلى في توقف إشارة وقت، مزود يجب أولا تراجع ذلك إنشاء أمر خدمة و بلوغ إلى تماما توقف مستقر حالة، لكن بعد عندئذ يجعل استعادة استدعاء بـ رفض انتهاء.Agent إصدار بعد، مزود يجب إزالة حذف إنشاء خلال نقل تسليم إلغاء إشارة وقت تنافس حالة، في إرجاع قبل سوف نفس إشارة مرفق إضافة إلى تخزين نشط run؛ بعد إلغاء سوف إيقاف child جولة. أي جعل مزود استعادة استدعاء بعد لم إرجاع `SubagentRun`،`job_kill` و مقابل تأكيد قطع owner نسخة dispose ما زال عبر هذا بند مسار توليد فاعلية.Task تسوية سوف انتظار تراجع أو run dispose إتمام، فقط لديه في تنشيط تماما توقف مستقر بعد عندئذ سجل `killed`.

### نشط وثب run صلة ربط

متابعة تنفيذ إدارة جهاز في عملية داخل صيانة child session id إلى حالي Task صلة ربط، و في مزود إصدار بعد سوف run ملء دخول هذا صلة ربط. هو سوف في انتظار مزود start أو resume قبل تثبيت Task صلة ربط، ملء دخول إرجاع run، و كما فقط في run dispose إتمام كما Task نهاية حالة إصدار بعد عندئذ إزالة هذا صلة ربط. هذا صلة ربط فقط لأجل يجعل parent إرسال جهة و مستخدم إرسال جهة بحث إلى نفس مرة تنشيط؛ هو لا هو حفظ دائم child دليل، عام `ManagedSubagent`، دقيق دخول مسبق إبقاء أو run حالة آلة.

مقابل في يمكن متابعة child ابتدائي تنشيط، متابعة تنفيذ إدارة جهاز سوف في إنشاء Task قبل قسم إعداد مستقر child session id، و سوف ذلك بصفة `SubagentProviderStartRequest.continuation` نقل تمرير؛ عملية داخل spawn و fork سوف إصدار هذا واحد تأكيد قطع id، بينما لا هو في داخلي آخر سطر قسم إعداد. عادي `SubagentStartRequest` لا يحتوي continuation حقل. خلفية أداة إرجاع مواصفة `{ kind: 'background', jobId, subagentId }`، تصيير لـ `started subagent <childId> as job <jobId>`.child id في كثير مرة تنشيط في بداية نهاية إشارة بديل نفس عدد حفظ دائم محادثة،Job id فإن فقط إشارة بديل حالي تنشيط. ابتدائي Task فشل، أو عملية في child أول مرة flush قبل خروج، كل ممكن إبقاء تحت واحد **unmaterialized child**: استدعاء جهة يحتفظ child id، لكن لا وجود حفظ دائم header و وصف رمز. لاحق حسب id عملية سوف تقرير إبلاغ هذا id غير ممكن استخدام (قد بدء Task سوف حمل حال هذا تفصيل حال فشل) ، حفظ دائم قطعة رفع أيضا لن صف خروج هو.

كل يمكن متابعة child جولة كل عبر هذا بند من Task دعم دعم مسار دقيق دخول. غير نهاية حالة Task هو وحيد تلقي دعم حمل تخزين نشط تنشيط؛ لا وجود تنشيط وقت، ذلك run قد يتم dispose، حفظ دائم child يمكن استعادة. في توجيه أي حسب id عملية قبل، متابعة تنفيذ إدارة جهاز سوف تزامن سوف ذاته صلة ربط و `ctx.agents.get(childId)` مقارنة مقارنة. إذا سجل التسجيل في Agent لا يوجد صلة ربط، أو من هو و الذي صلة ربط `run.localAgent` مختلف، حينئذ يخص كل حق اندفاع مفاجئ: إدارة جهاز سوف فشل، بينما لن وصل إدارة idle Agent أو مرفق إضافة لم تلقي تتبع أثر جولة. اثنان من متساو لا وجود وقت، يمكن من حفظ دائم تخزين استعادة؛ إذا فحص بعد أيضا لديه تنافس تنازع جهة إصدار، ما زال سوف في Agent سجل التسجيل اندفاع مفاجئ حد فوق فشل.

نظام اعتماد حسب Task صلة ربط إجراء توجيه. تشغيل في Task عبر run اختياري كما توفير تأكيد دلالة `SubagentRun.steer` وظيفة استقبال في خط رسالة.Task لا وجود وقت، نظام إنشاء جديد Task، و من حفظ دائم تخزين استعادة child. عملية داخل spawn و fork سوف أولا تزامن اشتراط child موضع في `running` حالة، و رفض قد إيداع بنية تحويل التقاط child؛ مع بعد استدعاء `Agent.steer()`، انتظار هذا رسالة مخصص تابع دقيق دخول عودة تنفيذ. افتراضي حلقة سوف لـ كل steering مشروع توفير واحد نسخة ملكية في هذا رسالة عودة تنفيذ؛ فقط لديه في `agent/step` و مختلف خطوة نص التوجيه تجميع نجاح بعد، نظام إلحاق هذا رسالة، التقاط غير ممكن تغيير طلب تاريخ و إيداع `step/start`، عودة تنفيذ عندئذ سوف تحليل لـ `admitted`. إنهاء نوع جولة سياسة، إلغاء و dispose(مورد تحرير) سوف سوف انتظار معالجة عودة تنفيذ تحليل لـ `rejected`. غير إنهاء نوع جولة إغلاق يمكن يأخذ انتظار معالجة steering حمل دخول لاحق ترتيب طابور جولة، لكن لن تأكيد ذلك دقيق دخول. مزود يجب في استدعاء `Agent.steer()` قبل فحص تخزين نشط حالة، تجنب تجنب ذلك idle مسار في مراقبة إلى run خارج بدء جولة. إذا فحص بحث صلة ربط بعد، طلب نيل دقيق قبل،Task تسوية أو إنهاء سياسة معدل أولا إتمام،`steer()` سوف رفض،`send_message` سوف تقرير إبلاغ رسالة لم إرسال بلوغ، بينما كما هذا مرة استدعاء لن تعديل استخدام من حفظ دائم تخزين استعادة مسار؛ في Task نهاية حالة إصدار بعد إعادة محاولة، عندئذ ممكن بدء تحت مرة تنشيط.

متابعة تنفيذ إدارة جهاز لن سلسلة سطر تحويل اثنان عدد عبر ذلك خارجي مسار معا تنازع انتزاع قد إيقاف child استدعاء جهة، أيضا لن لـ نتيجة إنتاج و dispose بين مرحلة مقطع مفرد وحيد بناء قيام settling حالة. في producer أول مرة await قبل تزامن تثبيت صلة ربط، جعل هذا عملية داخل كل child فقط دقيق دخول مرة تنشيط——resume تحميل خلال تنافس تنازع `followup` سوف مراقبة إلى انتظار معالجة تنشيط و صريح فشل——بينما التفاف فتح هذا صلة ربط إصدار ما زال سوف في Agent سجل التسجيل نفسه جلسة اندفاع مفاجئ حد فوق فشل. إرسال أيضا ممكن بسبب و بدء، إلغاء، إتمام أو تنظيف حدوث تنافس حالة بينما فشل. هذه حد هو واضح، بينما غير إخفاء في أكثر كبير دورة الحياة سحب كائن بعد.

### موجه إلى نموذج `send_message`

نموذج نيل نيل واحد من `SubagentRuntime.sendMessage()` دعم دعم عام `send_message(agent_id, message)` أداة. تأكيد قطع في خط sender فقط قدرة إشارة تحديد ذلك مباشر parent أو مباشر يمكن متابعة child؛ خدمة مسؤول متبادل مجاور علاقة فحص، بارد استعادة، ثابت Steer ضبط درجة، و حفظ دائم `{ kind: 'agent-message', senderSessionId }` مصدر معلومة. إلغاء فقط مسؤول inbox قبول قبل عمل. مستخدم مهايئ إبقاء قسم مغادرة، لأن متصفح تحرير كتابة إدخال يحمل مستخدم مصدر معلومة و طلب هوية، بينما لا هو Agent إذن. هذا أداة يقع في مفرد وحيد تحميل `@deepseek-ai/dsh-tool-subagent-control` حزمة في، لذلك حسب مزود ربط `@deepseek-ai/dsh-tool-subagent` نسخة يمكن متابعة لـ spawn،fork أو ACP تسجيل مختلف تفويض إرسال أداة، بينما لن تكرار تسجيل عام تحكم أداة.

- إذا child وجود تشغيل في Task و دعم حمل في خط رسالة، خدمة سوف استدعاء `run.steer(message, source)` و إرجاع قائم job id؛ هو لن إنشاء جديد Task.
- إذا child لا يوجد تشغيل في Task،`send_message` سوف إنشاء جديد Task، استخدام هذا رسالة من حفظ دائم تخزين استعادة جلسة، و إرجاع جديد job id.
- إذا نشط وثب مزود لا يمكن استقبال في خط رسالة، حمل تأكيد دلالة steering في دقيق دخول تنافس حالة في فشل، أو Task صلة ربط خارج وجود تخزين نشط child،`send_message` سوف فشل، بينما لن ساكن صامت بدء، استعادة أو وصل إدارة لم تلقي تتبع أثر جولة.

خدمة نتيجة سوف توجيه معرف لـ `steered` و يحمل قائم job id، أو معرف لـ `started` و يحمل جديد job id. فشل نتيجة سوف واضح شرح رسالة لم إرسال بلوغ. موجه إلى نموذج أداة سوف عرض هذه فرق مختلف، يجعل استدعاء جهة قدرة كاف مراقبة من وقت ترتيب قرار فعلي توجيه.

إرسال إلى قائم run رسالة لا يوجد مستقل نتيجة، ذلك فاعلية نتيجة جسم الآن حالي Task نهائي نتيجة في. بدء لاحق جولة أداة لديه جديد Task نتيجة، و استخدام قائم `job_output` قراءة مسار.subagent طبقة لن مجددا حقن ثاني نسخة إتمام إشعار.

مستخدم إدخال استخدام نفس عدد `followup` عملية.UI يمكن عرض child transcript و حالي Task حالة، إلغاء عملية فإن بـ قد تحميل parent بصفة استدعاء جهة وصول Task خدمة. أداة schema و UI مهايئ إزالة استهلاك نفس عدد خدمة اتفاق، لا بناء قيام ذاك هذا مستقل تنفيذ مسار.

### حفظ دائم child handle و من حفظ دائم تخزين استعادة

متابعة تنفيذ إدارة جهاز في إنشاء Task قبل، عبر seam `snapshotSubagentDescriptor()`(أساس في [`snapshotJsonValue`](../../../../packages/util/values/src/index.ts) بناء) مقابل كل بند وصف رمز إدخال بناء قيام لقطة؛ هذا واحد حد و Agent رسالة قائم قسم مغادرة صيغة بلا ضرر JSON حد متسق. أثر في child أثر مجال setup contribution——من عملية داخل قيادة قبل وضع تثبيت مرة صفة `agent/prompt-submit` مستمع——سوف في تحت تنقل prompt admission قدرة كاف منع توقف طلب أو رمي خروج استثناء قبل إلحاق واحد مقابل نموذج إخفاء `subagent/descriptor` حدث.admission نيل دقيق بعد عندئذ سوف فتح بدء child ابتدائي جولة؛admission يتم رفض وقت، وصف رمز سوف بصفة جولة قبل فقط سجل واقع إبقاء، و من هذا activation نهائي مطلوب فحص نقطة حفظ دائم. هذا حدث لا يحمل `surfaceOp`، لا دخول نموذج تاريخ، و في ضغط استبدال surface تاريخ وقت متابعة إبقاء. فقط لديه في تحميل معروف child id مقابل child جلسة بعد، قدرة في ذلك دقيق `inheritedEventCount` موضع أو بعد نيل إلى تلقي دعم حمل وصف رمز، من بينما منع توقف fork seed تسرب كشف أصل أولا وصف رمز، كما جلسة header سوف استدعاء جهة معرف لـ مباشر parent وقت، هذا id عندئذ يمكن استعادة.

إصدار تحويل وصف رمز يمكن متابعة فرع ([descriptor.ts](../../../../packages/subagent/subagent/src/descriptor.ts) في `SUBAGENT_DESCRIPTOR_VERSION`) يحمل `mode: 'continuable'`،subagent مزود اسم، قد تحليل child `agentOptions.provider` و `agentOptions.model`، و اختياري `persona` و `toolFilter`. هو لن مقابل يمكن عبر إعلان دمج توسيع `AgentOptions` كائن بناء قيام لقطة: و هذا غير متصل توسيع قيمة لن فقط بسبب لا يمكن يمثل لـ JSON بينما توجيه يؤدي متابعة تنفيذ فشل. وصف رمز سوف خاص معنى حذف `subagentDepth`؛ من حفظ دائم تخزين استعادة وقت، نظام اعتماد حفظ دائم header في `delegationDepth`، بينما لا أصل حسب وصف رمز إعادة بناء عميق درجة.`outputSchema` يخص مفرد مرة تنشيط نتيجة اتفاق، لا يخص حفظ دائم child تركيب إعداد.child header ما زال هو child id،`cwd`،`parentSession`،`isSeeded` و `delegationDepth` مرجعي معلومة؛ يحتوي متن حفظ دائم metadata يملك دقيق `inheritedEventCount`،child transcript فإن مسؤول حفظ fork seed و لاحق تاريخ.[`delegationDepthOf()`](../../../../packages/subagent/subagent/src/index.ts) سوف في header قيمة و وقت التشغيل قيمة في أخذ الأكثر كبير قيمة، لذلك إعادة بناء بعد وقت التشغيل خيار يمكن إضافة عميق حفظ دائم قيمة، لكن أبدا قدرة خفض منخفض هو، استعادة بعد child لا يمكن إعادة نيل نيل قمة طبقة تفويض إرسال ميزانية.

من حفظ دائم تخزين استعادة لا يستطيع اعتماد `SubagentRun` اختياري طريقة، لأن هذا run قد يتم dispose، و كما عملية إعادة بدء بعد لن إبقاء.run يمثل مرة يمكن dispose تنشيط، فقط كشف أثر في حالي تنشيط عملية.`SubagentRun.steer?()` هذا واحد اسم واضح إشارة بديل توفير تأكيد دلالة كما فقط ملائم لأجل في خط رسالة وظيفة، بـ تجنب هذا وظيفة و خدمة تحرير ترتيب أو موجه إلى نموذج أداة خلط خلط.

داخلي متابعة تنفيذ إدارة جهاز استعادة مسار سوف تحميل معروف child جلسة، عودة و ذلك وصف رمز، أصل حسب حفظ دائم `parentSession` تمييز حق، و في ذلك إنشاء Task داخلي تشغيل. هو عبر خاص خدمة إغلاق حزمة نقل تمرير تماما تحليل `SubagentProviderResumeRequest`، منها يتضمن من Task يحتفظ إلغاء إشارة؛ هذا إغلاق حزمة فقط مسؤول في فحص مزود وظيفة بعد إجراء توزيع، و تنفيذ `start` الذي استخدام عادي run دورة الحياة مراقبة. اختيار في `SubagentProvider.resume?()` مسؤول نقل متبادل صلة إعادة بناء (عملية داخل: في حالي تحميل parent أثر مجال تحت تنفيذ `parent.ctx.agents.resume`) ، و إرجاع واحد جديد run. مزود هل وجود هذا طريقة ذاته حينئذ هو متابعة تنفيذ وظيفة، بلا حاجة مقدار خارج وظيفة علامة سجل.`SubagentRuntime.followup()` في صلة ربط run `steer?()` عملية و هذا حفظ دائم استعادة مسار بين فعل خروج اختيار. خاص مزود توزيع و مزود ذاته كل لن قطعة رفع حفظ دائم child أو صلة ربط Task.

خلفية أداة سوف في استدعاء `JobRegistry.start()` قبل تحقق وصف رمز إدخال و بناء قيام لقطة. تزامن تحقق فشل سوف رفض أداة استدعاء، كما لن إنشاء Task. حذف هذا خارج، أداة سوف قيام أي إرجاع child id و Job id، لا انتظار child إصدار أو وصف رمز حفظ دائم إتمام. عملية داخل يمكن متابعة مزود سوف في child دخول idle بعد، قراءة نتيجة قبل تنفيذ نهائي `SessionStore.flush()`؛ إرجاع `true` يمثل حتى قليل لديه واحد حمل دائم صفة مستمع مشاركة و، إرجاع `false` يمثل مطلوب فحص نقطة فشل، بينما رفض فإن يحمل مستمع فشل. هذا عملية سوف في child ما زال تخزين نشط وقت إعادة محاولة حلقة في فشل فحص نقطة. إذا نهائي تأكيد فشل، مزود سوف رفض بينما لا إرجاع لم مرور تأكيد إخراج، متابعة تنفيذ إدارة جهاز سوف dispose هذا run، قد إنشاء Task سوف تسوية لـ `failed`، ذلك تفصيل حال يتضمن حمل دائم صفة تشخيص. نهائي تأكيد خلال حدوث إلغاء وقت، بعد لم إصدار تنشيط نتيجة من إلغاء عملية وصل إدارة؛ أي جعل child جولة قد سجل لـ إتمام، أو بعد فحص نقطة فشل، أيضا لا يستطيع يحل محل Task `killed` نتيجة. قبل منصة مرة صفة تشغيل ما زال إبقاء حلقة فقط كل قوة تنفيذ فحص نقطة سلوك. عملية داخل spawn و fork سوف في حالي قد تحميل parent أثر مجال تحت إعادة بناء تركيب إعداد. استعادة fork وقت فقط تحميل child ذاتي ذات حفظ دائم transcript، منها قد يتضمن ابتدائي إنشاء وقت التقاط قد إتمام جولة بادئة؛ نظام أبدا سوف مجددا مرة fork parent تحديث بعد تاريخ. استعادة parent لن قيام أي استعادة ذلك child.

### نتيجة و إشعار كل حق

كل مرة يمكن متابعة child تنشيط كل تماما جيد يملك واحد Task و واحد `JobOutcome`، بلا نقاش رقم واحد بند رسالة من parent أيضا هو مستخدم توفير. فقط يلزم Task بعد لم علامة لـ قد تقرير إبلاغ، عام Task تقرير إبلاغ اتفاق الأكثر كثير سوف نحو إبقاء parent owner حقن واحد بند رئيسي حركة إتمام إشعار؛ قراءة، انتظار و إلغاء كل ممكن كبح صنع هذا إشعار. إرسال إلى تشغيل في تنشيط رسالة سوف إضافة دخول هذا تنشيط، لن إنشاء ثاني عدد Task أو ثاني نسخة نتيجة.child transcript هو موجه إلى مستخدم تفصيل دقيق سجل؛Task إخراج هو موجه إلى parent نهائي نتيجة.

Task سجل و نشط وثب run صلة ربط كل يقع في عملية داخل. حفظ دائم جعل child جلسة يمكن في إعادة بدء بعد استعادة، لكن لن استعادة في قطع Task، ذلك نتيجة أو إشعار. حفظ دائم Task استعادة يخص آخر عدد مشكلة.

## قد اعتبار بديل خطة

**في Task تسوية بعد إبقاء كل خلفية child.** هذا هو Codex ريح إطار معتاد إقامة جلسة نموذج: إرسال لاحق رسالة صار هذا مقارنة منخفض، لكن تاريخ child سوف حمل متابعة احتلال استخدام agent أثر مجال، جلسة داخل تخزين، مستمع و مزود مورد، مباشر حتى صريح معتاد إقامة عدد كمية حد أعلى أو تصفية استبعاد سياسة سوف ذلك إزالة. تدريجي تنشيط dispose استخدام حفظ دائم بصفة متابعة تنفيذ حد، معا إبقاء حالي مورد حد أعلى.

**سماح مستخدم جولة لا استخدام Task.** parent رسالة إضافة دخول هذا صنف جولة بعد، لا يوجد مقابل Task نتيجة أو إتمام إشعار؛UI إلغاء مقابل parent الذي إرسال رسالة أثر أيضا لا واضح. يجعل كل مرة تنشيط كل يملك واحد Task، يمكن جعل إتمام و إلغاء يصبح child جولة خاصية، بينما لا هو ابتدائي استدعاء جهة خاصية.

**في child جلسة كامل دورة الحياة داخل إعادة استخدام واحد Task.** نهاية حالة Task لا يمكن ذاتي لكن أرض مجددا مرة دخول تشغيل حالة، واحد نتيجة أيضا لا يمكن يمثل كثير عدد جولة. كل مرة تنشيط إنشاء جديد Task يمكن إبقاء عام Task اتفاق.

**لـ كل بند رسالة إنشاء Task.** إرسال إلى قائم run رسالة سوف إضافة دخول قد لديه جولة، لا إنتاج مستقل نهائي نتيجة؛ لـ هذا صنف رسالة إنشاء Task، سوف تكرار حالي Task، أو تقرير إبلاغ واحد هو و لا يملك نتيجة. فقط لديه بدء جديد تنشيط رسالة عندئذ سوف إنشاء Task.

**تفكيك قسم `send_message` و `follow_up`.** اثنان عدد مستقل إلقاء تمرير عملية سوف نحو نموذج كشف تنفيذ حالة فرق مختلف، لكن لا يمكن إزالة حذف child قد إيقاف وقت تنافس حالة. مفرد واحد عملية اعتماد Claude Code نموذج: نحو تشغيل في عمل إرسال رسالة، أو استعادة واحد من جديد Task دعم دعم دورة الحياة.

**في قد dispose run فوق إبقاء `resume?()`.** إذا فقط لـ استدعاء `resume()` بينما إبقاء قد dispose `SubagentRun`، قديم run سوف معا ملء عند حفظ دائم child handle، بينما كما عملية إعادة بدء بعد لا يمكن إعادة بناء هذا كائن. من خدمة توزيع، مزود إعادة بناء، يمكن واضح جدول بلوغ حفظ دائم حد.

**سوف تحكم تحرير ترتيب وضع في `SubagentRuntime` فوق.** هذا واحد خدمة وضع وضع خطة أي[خدمة دمج قرار](../simplification/2026-07-26-merge-subagent-control-service.zh.md) ؛[معنى رسم عملية دقيق تحويل](../simplification/2026-07-27-intent-named-subagent-continuation-operations.zh.md) سوف مزود start/resume توزيع إعادة استخدام حد في خدمة داخلي، معا سوف اختياري Task و حفظ دائم عمل عزل في حقن داخلي إدارة جهاز في.

**زيادة صريح تنشيط مرحلة مقطع.** عام `starting`/`running`/`settling` حالة يمكن دقيق تأكيد وصف دقيق دخول و تنظيف، لكن سوف جذب دخول تنفيذ ذاته و لا حاجة دورة الحياة بروتوكول. تزامن تثبيت صلة ربط بلا حاجة كشف هذه مرحلة مقطع، يكفي إزالة حذف عملية داخل تكرار cold resume.

- `packages/subagent/tool-subagent/tests/tool-subagent.spec.ts` تغطية إعداد خلفية توجيه: يمكن متابعة نمط اشتراط مزود يمكن استعادة، و في لا اشتراط `send_message` حال حال تحت إرجاع اثنان عدد id؛ أي جعل مزود يمكن استعادة، مرة صفة نمط ما زال إبقاء عادي Task تأكيد رسالة؛ هو أيضا ثابت Task خدمة تجميع صار و موجه إلى نموذج Task تحكم أداة.
- بلا مفتاح SDK لقطة مشهد [`subagent-continuable`](../../../../snapshots/sdk/subagent-continuable/) ثابت نموذج مرئي transcript: مزدوج id تأكيد رسالة، نهائي حمل دائم صفة تأكيد فشل (هذا فشل عبر `job_output` عرض، كما لا يتضمن لم مرور تأكيد child إخراج) ، و مرة `send_message` لاحق عملية——ذلك قد بدء Task سوف حمل حال «id غير ممكن استخدام» فشل.

## أثر

- كل مرة إتمام تسوية بعد لاحق جولة كل حاجة تحمل تحمل حفظ دائم تحميل و أثر مجال setup صار هذا؛ بصفة تسليم تبديل، تخزين نشط child عدد كمية تلقي تزامن عمل كمية حد، بينما لا هو مع تاريخ جلسة عدد كمية زيادة طويل. حفظ دائم غير ممكن استخدام أو تخزين تركيب إعداد لا يمكن إعادة بناء وقت، يمكن متابعة child إنشاء سوف واضح فشل.
- اثنان عدد استدعاء جهة ما زال ممكن عبر متابعة تنفيذ إدارة جهاز خارجي مسار تنازع انتزاع قد إيقاف child.Agent سجل التسجيل سوف منع توقف نفسه جلسة تكرار إصدار؛ فشل Task سوف فشل، كما ذلك رسالة لن إرسال بلوغ. رسالة أيضا ممكن و إلغاء، نهاية حالة حالة إصدار أو run dispose حدوث تنافس حالة. دقيق دخول لا تحمل وعد أصل فرعي أو تماما جيد تنفيذ مرة؛ في عملية داخل تزامن تثبيت صلة ربط بلا حاجة عام دورة الحياة حالة آلة، يكفي عبر `followup` إزالة حذف تكرار cold resume.
- عبر عادي Agent API قيادة يمكن متابعة child سوف التفاف مرور ذلك Task صلة ربط.`ctx.subagents` سوف سوف هذا تخزين نشط child نظر لـ كل حق اندفاع مفاجئ و رفض؛ مهايئ يجب في لا تحميل Agent حال حال تحت عرض حفظ دائم transcript، و عبر `SubagentRuntime.followup()` إيداع مستخدم إدخال.
- نشط وثب run صلة ربط فقط قدرة تنسيق ضبط واحد وقت التشغيل. كثير عدد عملية معا استعادة وقت لن سلسلة سطر تحويل؛ هذا صنف نشر حاجة حفظ دائم طبقة إيجار نحو أو compare-and-set عملية.
- مستخدم تفاعل اشتراط بصفة owner ذلك عدد دقيق parent Agent نسخة إبقاء تخزين نشط، لأن dispose owner سوف إلغاء و إزالة ذلك Task. مستخدم تفاعل أيضا اشتراط مرفق إضافة مهمة تحكم جهاز. إذا يلزم مفرد وحيد و child تفاعل، لاحق يجب سوف Task وصول كل حق و حفظ دائم إشعار هدف قسم مغادرة.
- خلفية أداة سوف في child إصدار و وصف رمز حفظ دائم قبل إرجاع child id و Job id. بدء فشل، نهائي حمل دائم صفة تأكيد فشل، أو عملية في child أول مرة flush قبل خروج، كل سوف جعل Task فشل، و ممكن إبقاء تحت unmaterialized أو قديم قديم child id؛ حسب id تحكم عملية سوف سوف ناقص حالة تقرير إبلاغ لـ غير ممكن استخدام، بينما لن تتبع تتبع تعديل أداة تأكيد رسالة.
- سوف صريح تركيب حقل حفظ دائم إلى child سجل بعد، ذلك بلا ضرر JSON و توافق صفة اتفاق سهل يصبح استعادة اتفاق واحد جزء. لاحق مثل يحتاج دعم حمل أخرى تركيب إعداد إدخال، يجب واضح أكثر تعديل وصف رمز إصدار، لا يستطيع خفي صيغة حفظ دائم يمكن عبر إعلان دمج توسيع `AgentOptions` حقل.
- Task سجل و نشط وثب run صلة ربط يقع في عملية داخل، بينما child جلسة أداة لديه حمل دائم صفة. إعادة بدء سوف استعادة جلسة، لكن لن استعادة إجراء في عمل أو ذلك Task إشعار.
