# Agent Note: عبر sessionStats إسقاط توفير كل جلسة موحد حساب بند عدد حرف

Status: implemented
Archived: 2026-09-04

[English](2026-08-12-full-session-turn-step-counts.md) | العربية

## مشكلة

Web حديث يوم موحد حساب بند كل غير token عدد حرف كل طي حساب ذاتي `StatsLine` قد تحميل جلسة نافذة (`deriveStats` مرة تاريخ `chat.legacy.nodes`):«N جولة · M خطوة» حساب عدد،LLM و أداة جدار ساعة وقت،TTFT/ابتلاع إخراج مستو متساو قيمة. تاريخ حسب كل صفحة 50 بند رسالة قسم صفحة، لذلك كل نقطة مرة «تحميل أكثر مبكر» نافذة تغيير كبير، كل عدد حرف مع لـ زيادة طويل——7 جولة · 44 خطوة في قلب واحد صفحة بعد تغيير صار 10 جولة · 89 خطوة،LLM وقت طويل نفس مثال تسلق رفع. منتج مسبق مدة هو و عميل تحميل كثير قليل تاريخ غير متصل كل جلسة عدد حرف. نفس موحد حساب بند داخل token حساب هدف مبكر قد اعتماد صحيح تأكيد هيكل بنية: حمل دائم `tokenUsage` إسقاط.

## قرار

جديد دالة إضافة `@deepseek-ai/dsh-session-stats` في `ctx.sessionProjections` فوق تسجيل `sessionStats` إسقاط وحدة، بصفة web-app bundle سطر تركيب. قيمة يحمل موحد حساب بند كامل غير token عدد حرف تجميع——`{ turns, steps, llmMs, toolMs, ttftMs, ttftSteps, decodeMs, decodeTokens }`، حقل اسم و نافذة طي واحد واحد مقابل بـ سهل كامل جسم متبادل تبديل.`steps` موحد حساب `step/end` حدث،`turns` موحد حساب يحتوي حتى قليل واحد بند هذا حدث مختلف turn(turn رقم مفرد ضبط تمرير زيادة، واحد `lastTurn` مجرى يكفي) ؛`llmMs` تراكم إضافة `step/start` → `assistant/message`؛TTFT سجل كل خطوة أول عدد غير فارغ delta chunk(في خطوة داخل `llm/retry` بعد إبقاء، و نافذة `resetForRetry` مقابل متساو) ؛ حل رمز وقت طويل تغطية أول token → قد تجميع رسالة، فقط موحد حساب فوق تقرير usage خطوة؛`toolMs` حسب callId إعداد مقابل `tool/call` → `tool/result`، لم حل قرار استدعاء في `turn/end` وقت إسقاط. أول token يسمى كلمة `isTokenDelta` نقل دخول `@deepseek-ai/dsh-llm/message`(و ذلك حكم آخر `StreamChunk` نوع نفس موضع) ،Host طي و عميل حساب وقت بحث جذب مشترك استخدام نفس تنفيذ؛client-runtime تحويل إرسال توجيه خروج. إلقاء تمرير تماما إعادة استخدام قائم إسقاط شق——history ذيل صفحة كتلة،`session/projection` دفع إرسال لقطة، قائمة سطر——apiproxy،wire schema و عميل وقت التشغيل صفر تعديل.`StatsLine` قراءة `useProjection('sessionStats')`، مفتاح لـ undefined(لم تركيب هذا وحدة تركيب إعداد) وقت كامل جسم رجوع إلى نافذة طي. عميل connection fixture حسب ذلك «مرآة مثل كل قد تركيب مفتاح» قائم سجل قاعدة بـ `sessionStatsOf` مستو سطر تنفيذ هذا طي.

حساب عدد حدث اختيار `step/end` بينما غير `assistant/message`، مصدر في مراجعة مباشر شعور خطة (حسب رسالة حساب عدد) وقت اكتشاف اثنان عدد صحيح تأكيد صفة مشكلة:

1. max-tokens خطوة سوف إلحاق واحد بند فقط لـ تحمل تحميل usage بينما وجود فارغ محتوى `assistant/message`، هو من لا دخول surface؛ حسب رسالة حساب عدد سوف يأخذ transcript فوق نظر لا إلى خطوة حساب دخول ذهاب.
2. يتم إلغاء خطوة في رسالة تجميع قبل حينئذ في توقف (تماما لا يوجد `assistant/message`) ، لكن عميل سوف دمج صار مرئي interrupted assistant عقدة؛ حسب رسالة حساب عدد سوف صامت صامت فقد إسقاط معتاد رؤية إلغاء خطوة.

`step/end` مقابل كل دخول خطوة في حلقة `finally` في تماما جيد إلحاق مرة، لذلك إتمام، فشل، إلغاء،max-tokens خطوة كل تماما جيد سقوط واحد بند——كما حساب عدد في خطوة تسوية وقت دفع دخول، و نافذة طي حساب دفع دخول وقت آلة نفسه، مباشر بث مدة سلوك لا حدوث تغير.

## تجهيز اختيار خطة

**موحد حساب `assistant/message` حدث.** بسبب فوق وصف اثنان عدد صحيح تأكيد صفة نقص وقوع مرفوض (كثير حساب usage مضيف رسالة، قليل حساب يتم إلغاء خطوة).

**موحد حساب `step/start` حدث.** تغطية انتظار قيمة (هو أولا في كل بند `step/end`) ، لكن حساب عدد سوف في خطوة بدء بينما غير تسوية وقت دفع دخول——واحد لا يوجد استلام فائدة مرئي مباشر بث مدة سلوك تغير؛`step/end` `finally` موضع إعطاء خروج نفس انتظار كامل صفة.

**يأخذ وحدة تسجيل دخول `core/agent-loop`(حدث إنتاج جهة).** حلقة هو منتج رئيسي جاف؛ يأخذ UI قراءة نموذج وضع دخول ذهاب سوف إعطاء كل تركيب إعداد إضافة فوق session-projection اعتماد، مخالفة عكس «استخدام إضافة بينما غير تعديل حلقة» و «افتراضي تركيب لا حمل اختياري بند».

**يأخذ وحدة تسجيل دخول `token-meter`(طي نفس دفعة حدث قائم وحدة).** جولة/خطوة حساب عدد لا هو token درجة كمية؛ كل إسقاط مفتاح كل إقامة في يملك ذلك مجال حزمة داخل.

**في عميل طي كل كمية سجل.** عميل حسب تصميم فقط يحتفظ قسم صفحة نافذة؛ إسقاط RFC «لا في عميل طي» قاعدة صحيح هو لـ يجعل عدد حرف في قسم صفحة، ضغط و بارد قراءة بين تخزين نشط.

**جدار ساعة وقت،TTFT و ابتلاع إخراج إبقاء نافذة فتحة مسار، حل قراءة لـ «شاشة ستار فوق لديه ماذا».** مرفوض: نفس مثال قسم صفحة مشكلة واحد مثال سقوط في LLM وقت طويل فوق، كما كل كمية حساب عدد و نافذة وقت خلط في واحد بند موحد حساب بند داخل قراءة بدء قدوم هو واحد طقم ذاتي متبادل تناقض درع عدد حرف. إسقاط يحمل كامل تجميع دمج، نافذة طي تخفيض لـ بلا وحدة وقت رجوع.

## عاقبة

موحد حساب بند من رقم واحد ذيل صفحة بدء حينئذ عرض كل سجل عدد حرف؛ قلب صفحة لم يعد تغيير أي قسم مجموعة. و قديم نافذة دلالة قد تعريف حافة حافة فرق مختلف سجل في حزمة README في: لم إنتاج مرئي إخراج خطوة (في محتوى قبل فشل) ما زال حساب دخول؛ يتم انهيار انهيار ضرب قطع خطوة في إعادة تحميل، استعادة لـ ذلك تكملة كتابة دمج صار `step/end` بعد حساب دخول (`interruptedTurnClosers`) ؛ يتم إلغاء خطوة حساب عدد لكن لا حساب وقت (لا يوجد تجميع خروج رسالة) ؛max-tokens usage مضيف رسالة مساهمة surface فوق نظر لا إلى نموذج وقت. كل web ذيل صفحة و قائمة سطر كثير يحمل واحد صغير مفتاح، كما وحدة داخلي حالة في خطوة حد و أول token chunk موضع تغير، تغيير تدفق كل خطوة سوف كثير إرسال بضعة لقطة قيمة نفسه دفع إرسال؛TUI و headless تركيب إعداد لا توفير `sessionStats` مفتاح، ذلك إزالة استهلاك من رجوع نافذة طي. اثنان عدد سبق يأخذ موحد حساب بند عند عمل قد تحميل نافذة استكشاف إبرة تحليل e2e(`chat-scroll-contract`،`complex-history.perf`) تعديل لـ موحد حساب قد تركيب رسالة تدفق سطر/turn-tail صفحة قدم.`stats-paged-history` web مشهد بارد نوع واحد نسخة 28 جولة سجل، تثبيت إقامة كامل بند موحد حساب بند في لا كامل ذيل صفحة فوق أي قراءة خروج كل كمية عدد حرف، كما «تحميل أكثر مبكر» قبل بعد ثابت.
