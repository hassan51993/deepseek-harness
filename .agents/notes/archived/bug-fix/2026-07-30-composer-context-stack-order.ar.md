# Agent Note: Composer سياق كومة مكدس ترتيب

Status: implemented
Archived: 2026-09-04

[English](2026-07-30-composer-context-stack-order.md) | العربية

## مشكلة

Goal،Todo و Queue مستقل تسجيل إلى نفس عدد `conversation.input.dock` قائمة، لكن كل منها تسجيل ترتيب و بين مسافة قاعدة لا يوجد تحرير رمز تركيب مستطيل دفعة. لذلك، مصير سوف Todo وضع في Queue و Goal قبل، بينما Queue و Goal كل حمل لديه لأجل composer حد سالب خارج حافة مسافة. ثلاثة من معا ظهور وقت،Queue و Goal متبادل وصل،Goal و composer متبادل وصل، قلب قلب تصميم طبقة درجة.

## قرار

[Todo أولوية مقابل متساو قرار](2026-08-02-todo-first-composer-context-order.ar.md) قاعدة تحديد حالي رفع ترتيب ترتيب صف. هذا سجل إبقاء محيط التفاف هذا ترتيب كومة مكدس اتفاق: عدد قيمة بين فصل جعل لم قدوم بند يمكن إعلان مسبق مدة موضع، لا لا بد اعتماد إضافة تنشيط ترتيب؛composer bar يقع في قائمة بعد.

`ConversationRoot` مسؤول مستقل سياق بطاقة بين 6px بين مسافة.Goal هو واحد ورقة مستقل 752×36px بطاقة، طي بعد Todo هو واحد ورقة مستقل 752×44px بطاقة.Queue هو نهاية طرف dock بند: ذلك 776px حزمة تركيب طبقة يتضمن نفسه 752px وجه لوح صف، و نقص ذهاب مشترك بين مسافة و أداة اسم 5px تخطيط إعادة تراكم كمية، لذلك بعد تصيير composer بطاقة فقط تغطية Queue حافة حافة. فارغ بند تصيير لـ null، لا احتلال استخدام بين مسافة.

ترتيب و إعادة تراكم هو اثنان بند مستقل اتفاق. تسجيل ترتيب تعريف دلالة طبقة درجة،stack فوق CSS متغير تعريف مشترك بضعة أي. نظام لا يستطيع فقط بسبب Queue هو الأكثر بعد واحد مرئي بند، حينئذ دفع قطع هو يمكن و composer إعادة تراكم، لأن لا يوجد Queue وقت،Goal أو Todo ممكن يصبح الأكثر بعد واحد مرئي سياق بطاقة، بينما هو جمع يجب و composer إبقاء بين فصل.

## تحقق

تسجيل اختبار ثابت ثلاثة عدد ترتيب قيمة. بلا مفتاح Queue متصفح مشهد معا تصيير Todo،Goal و Queue، ثابت هو جمع بلا عائق عائق ترتيب، و فحص ذلك مرئي بطاقة حافة حافة؛ قسم آخر إبرة مقابل Goal و Queue مشهد تغطية كل منها مستقل حالة.

## اعتبار مرور بديل خطة

**Goal و Queue قسم آخر إبقاء مستقل سالب خارج حافة مسافة.** غير مقبول، لأن تلقي أثر متبادل مجاور بند سوف مع slot ترتيب تغير؛ حذف غير دلالة ترتيب أيضا ثابت، لا فإن نطاق جزء خارج حافة مسافة لا يمكن جدول بلوغ سماح أي واحد نوع علاقة.

**في `ConversationRoot` في قسم آخر تصيير كل معروف dock id.** غير مقبول، لأن هذا سوف يأخذ يمكن توسيع قائمة slot تغيير صار صلب تحرير رمز مكون بيان، و إجبار جعل owner في كل إضافة جديدة واحد تسجيل جهة وقت مع لـ تعديل.

**يجعل الأكثر بعد واحد dock بند و composer متبادل وصل.** غير مقبول، لأن Goal و Todo هو مستقل بطاقة؛Goal أو Todo نقص مقعد وقت تركيب لا نيل تغيير باق بقية بطاقة واجهة دلالة.

## عاقبة

كل وجود تركيب تحت نظر شعور طبقة درجة كل إبقاء مستقر،Queue هو وحيد و composer متبادل وصل سياق واجهة. جديد input-dock إضافة يجب متبادل مقابل في Todo `0`،Goal `10` و Queue `20` اختيار ترتيب؛ إذا بند يقع في Queue بعد، أيضا يجب واضح قرار من أي عدد واجهة مسؤول composer حد.
