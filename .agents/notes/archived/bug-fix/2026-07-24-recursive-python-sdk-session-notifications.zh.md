# Agent Note: Python SDK تمرير عودة جلسة إشعار

Status: implemented

## مشكلة

Python SDK مرور ذهاب عبر سوف كل بند إشعار payload و أصل جلسة ID مباشر مقارنة مقارنة قدوم مرور ترشيح جولة إشعار. مباشر فرعي agent دورة الحياة إشعار بسبب parent ID إشارة نحو أصل جلسة بينما قدرة كاف عبر، لكن حفيد درجة دورة الحياة إشعار و كل بعد بديل `session.event` كل سوف يتم رفض.JSON-RPC خادم ما زال سوف إرسال خروج هذه إشعار، لذلك هو جمع سوف كومة تراكم في قاع طبقة عام طابور صف في، بينما عال طبقة إزالة استهلاك من سوف فقد فقد تضمين طقم مسار أثر علاقة و انتهاء حالة.

## قرار

`HarnessClient` سوف في توزيع إشعار قبل، سجل كل بند صالح `subagent.started` الذي يتضمن child-to-parent(فرعي إلى أب) علاقة. لاحق `subagent.finished` سوف اعتماد حسب ذاته غير ممكن تغيير parent ID توجيه، لكن لن تعديل كتابة حالي أصل أولا علاقة، لذلك قديم run أي جعل في ذلك child ID قد يتم إعادة استخدام بعد عندئذ انتهاء، أيضا لا يمكن تغطية بديل هو جديد جلسة. أخرى جلسة إشعار سوف امتداد عميل دورة الحياة داخل حفظ أصل أولا علاقة رسم عودة تتبع ذاته session ID، حكم قطع هو جمع هل يخص طلب أصل جلسة. هذا علاقة رسم سوف عبر وصل متابعة حجز قراءة إبقاء، لذلك بعض عدد بعد بديل أي جعل في مرة `Session.run()` انتهاء بعد ما زال تخزين متابعة، في لاحق جولة في إرسال خروج إشعار وقت ما زال قدرة صحيح تأكيد ملكية؛ عميل بدء جديد وقت التشغيل عملية وقت سوف إعادة وضع علاقة رسم.

`Session.run()` عبر `TurnResult.notifications` و `on_notification` توفير قد اكتشاف جلسة شجرة كامل إشعار تدفق. فقط لديه `sessionId` انتظار في طلب أصل جلسة `session.event` عندئذ سوف دخول `TurnResult.events` أو مشاركة و نهائي عودة تكرار إعادة بناء. لذلك استدعاء جهة قدرة كاف مراقبة بعد بديل حدث، معا فرعي جلسة عودة تكرار لن تغطية أصل جلسة عودة تكرار.

## اعتبار مرور بديل خطة

**في كل بند JSON-RPC إشعار في إضافة دخول أصل جلسة ID.** خادم قد توفير دقيق مباشر أب فرعي علاقة؛ في خط مسار بروتوكول في تكرار نقل تمرير أصل أولا علاقة، سوف إجبار جعل كل إنتاج من تحمل تحمل عميل حجز قراءة حالة مسؤولية.

**يأخذ subagent حد لـ واحد طبقة.** نشر يمكن ضبط `maxDepth: 1`، لكن يجعل SDK اعتماد هذا سياسة، سوف مقابل دمج قاعدة تمرير عودة تركيب إنتاج ساكن صامت خطأ تقرير.

**فقط حجز قراءة بعد بديل دورة الحياة إشعار.** هذا يمكن إصلاح علاقة و انتهاء حالة فوق تقرير، لكن بعد بديل جلسة حدث ما زال سوف كومة تراكم في عام طابور صف في، عودة ضبط يرى جلسة شجرة أيضا لا كامل.

**في JSON-RPC خط مسار فوق عام و بحث جذب كل subagent run ID.** عند عميل يجب صلة ربط نفس child اثنان عدد تزامن نتيجة وقت، دقيق run هوية جدا لديه قيمة قيمة؛ لكن جلسة شجرة توجيه قد يملك مرجعي start علاقة و كل بند إنهاء إشعار في غير ممكن تغيير parent. لا يوجد لا بد يلزم لـ هذا واحد ملكية قرار توسيع بروتوكول.

## عاقبة

عال طبقة مستهلك سوف حسب بروتوكول نقل ترتيب استلام إلى تضمين طقم دورة الحياة و جلسة إشعار، معا أصل جولة نتيجة إبقاء أصل لديه عودة تكرار دلالة. عميل سوف لـ كل قد مراقبة إلى فرعي جلسة إبقاء واحد بند حالي أب علاقة، مباشر إلى وقت التشغيل إعادة بدء؛ أصل أولا عودة تتبع قدرة كاف أمان معالجة حلقة، غير متصل جلسة إشعار ما زال يمكن من عام طابور صف نيل أخذ. بلا مفتاح Python اختبار تغطية اثنان طبقة تفويض إرسال، أصل عودة تكرار عزل، جلسة شجرة إشعار لا كومة تراكم، عبر حجز قراءة إعادة استخدام أصل أولا علاقة، و قديم run فوضى ترتيب انتهاء إعادة استخدام child ID.
