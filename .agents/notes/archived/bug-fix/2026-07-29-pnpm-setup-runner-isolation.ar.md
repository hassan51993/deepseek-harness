# Agent Note: حسب GitHub Actions runner عزل pnpm ضبط

Status: implemented
Archived: 2026-09-04

[English](2026-07-29-pnpm-setup-runner-isolation.md) | العربية

## مشكلة

`pnpm/action-setup@v4` تثبيت هدف دليل افتراضي لـ `~/setup-pnpm`، و سوف في ضبط خلال استبدال هذا دليل. ذاتي حمل إدارة CI لذا عائق تبديل في نفس عدد VM مستخدم تحت تشغيل ستة عدد GitHub Actions runner خدمة، لذلك تزامن عمل عمل سوف مشترك استخدام نفس هدف دليل. في تكرار الآن تشغيل في، ثلاثة عدد عمل عمل في 73 جزء ثانية داخل دخول pnpm ضبط؛ منها واحد ضبط مرور مسار حذف آخر عدد عملية حالي عمل دليل، توجيه يؤدي اثنان عدد عمل عمل في Node `uv_cwd` ابتدائي تحويل مرحلة مقطع فشل. تبديل إلى آخر منصة runner إعادة محاولة بعد عبر، شرح هذا لذا عائق أخذ قرار في وقت ترتيب، و غير مستودع اختبار ارتداد.

## قرار

[رئيسي CI سير العمل](../../../../.github/workflows/ci.yml) و [CI master سير العمل](../../../../.github/workflows/ci-master.yml) في كل**غير Windows** `pnpm/action-setup` خطوة كل ضبط `dest: ${{ runner.temp }}/setup-pnpm-${{ github.run_id }}-${{ github.run_attempt }}`. كل runner خدمة وحيد احتلال ذاتي ذات مؤقت دليل، لذلك واحد ضبط مرور مسار لا يمكن استبدال آخر عدد runner تثبيت دليل؛run/attempt بعد لاحقة أيضا قدرة منع توقف نفس runner فوق ترتيب عمل عمل بسبب ناقص إبقاء قفل تحديد `pnpm.exe` بينما فشل.Windows أصلي عمل عمل و [python SDK exe بناء](../../../../.github/workflows/build-exe-for-python-sdk.yml) في `setup-pnpm-js-${{ github.run_id }}-${{ github.run_attempt }}-${{ github.job }}` تحت استخدام مستقل pnpm يمكن تنفيذ ملف (غير `standalone: true`، دليل ذاته بدء قسم مغادرة أثر):run/attempt/job بعد لاحقة يجعل كل مرة عمل عمل كل استخدام كل جديد دليل، أي جعل ترتيب عمل عمل سقوط إلى نفس ذاتي حمل إدارة runner، كما قبل واحد عمل عمل إبقاء تحت يتم قفل تحديد @reflink أصلي وحدة. حمل دائم store إعادة استخدام ما زال من `PNPM_CONFIG_STORE_DIR` مستقل معالجة، التزام دوران [pnpm إعداد قرار](../process/2026-07-26-pnpm-action-setup-for-symmetric-ci-caching.ar.md).

[سير العمل ارتداد اختبار](../../../../scripts/ci-workflow.spec.ts) سوف بحث خروج `ci.yml`،`ci-master.yml` و `build-exe-for-python-sdk.yml` في كل `pnpm/action-setup` خطوة، و رفض نقص قليل runner مخصص تابع هدف دليل خطوة. هذا يمكن تأكيد حفظ لاحق إضافة جديدة عمل عمل أيضا موضع في نفس عزل حد داخل.

## سبق اعتبار بديل خطة

**سلسلة سطر تنفيذ لذا عائق تبديل عمل عمل.** مرفوض: هذا سوف تضحية قربان من ستة عدد runner مجموعة صار حوض الذي أداة تجهيز مسبق مدة و سطر قدرة، و يأخذ action داخلي دليل اندفاع مفاجئ تغيير صار أصل هذا متبادل متبادل مستقل عمل عمل بين طابور صف انتظار.

**لـ كل runner خدمة قسم إعداد مستقل Unix مستخدم.** هذا نفس مثال قدرة كاف عزل `HOME`، لكن سوف يأخذ هذا ثابت كمية تحويل نقل إلى خارجي VM إعداد في، و جعل لحظة معنى مشترك حمل دائم pnpm store كل حق تغيير نيل تكرار مختلط. سير العمل قد نيل نيل runner مخصص تابع مؤقت دليل.

**إعادة محاولة فشل ضبط خطوة.** مرفوض: إعادة محاولة فقط قدرة خفض منخفض مراقبة قياس إلى اندفاع مفاجئ حدوث معدل؛ آخر عدد تزامن ضبط مرور مسار ما زال ممكن مجددا مرة حذف نفس عدد مشترك دليل.

## عاقبة

pnpm يمكن تنفيذ ملف اعتماد مؤقت تثبيت، و حسب runner عزل؛ حزمة تحت تحميل ما زال استخدام قد إعداد حمل دائم أو ذاكرة مؤقتة store. حمل إدارة عمل عمل استخدام نفسه صريح هدف دليل، لا تغيير ذاكرة مؤقتة سياسة سياسة. سير العمل في كل ضبط خطوة لذلك زيادة ثلاثة سطر إعداد؛ فقط لديه في pnpm إعداد متعمد تعديل استخدام آخر نوع عزل آلية وقت، عندئذ حاجة تحديث ارتداد اختبار.
