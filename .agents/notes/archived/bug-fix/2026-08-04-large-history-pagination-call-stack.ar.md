# Agent Note: كبير قاعدة نموذج تاريخ سجل تتبع مصدر معلومة عبر مسح معالجة، لا فعل معامل توسيع

Status: implemented
Archived: 2026-08-22

[English](2026-08-04-large-history-pagination-call-stack.md) | العربية

## مشكلة

واحد بند قد تحديد مسودة assistant رسالة يمكن عبر `sourceEventSeqs` مرجع عدد عشرة ألف عدد تدفق صيغة قسم قطعة. تاريخ سجل قسم صفحة استخدام `Math.min(event.seq, ...sourceEventSeqs)` فحص بحث رسالة مجموعة أول عدد حدث، لذلك، صالح جلسة ممكن تجاوز خروج JavaScript جذب محرك دالة معامل عدد كمية حد أعلى، توجيه يؤدي `session.history` بـ HTTP 500 فشل.

## قرار

قسم صفحة منطق تدريجي بند مسح `sourceEventSeqs`، كل مرة استخدام واحد عنصر عنصر تحديث الأكثر مبكر ترتيب رقم. هذا حساب قاعدة تكرار مختلط درجة متبادل مقابل تتبع مصدر معلومة قاعدة نموذج ما زال لـ خط صفة، و إبقاء قائم صفحة حد: صفحة بدء نقطة يقع في ذلك الذي يحتوي الأكثر مبكر رسالة كل قد سجل مصدر قبل.

ارتداد اختبار سوف رفض بـ كثير عدد معامل استدعاء أخذ الأكثر صغير قيمة فعل قاعدة، و تحقق كل تتبع مصدر حدث كل سوف و ذلك قد تحديد مسودة رسالة إبقاء في نفس صفحة في. هذا حيث تغطية لذا عائق آلية، أيضا تجنب تجنب افتراضي اختبار طقم عنصر قسم إعداد إنتاج قاعدة نموذج قسم قطعة تدفق.

## اعتبار مرور بديل خطة

- **رفع عال JavaScript مكدس أو معامل حد أعلى**: غير مقبول، لأن هذا حد أعلى أخذ قرار في جذب محرك و نشر بيئة، بينما كما عدد مجموعة توسيع ما زال سوف يجعل صالح تاريخ سجل تلقي صنع في غير متصل وقت التشغيل حد أعلى.
- **في قسم صفحة وقت قطع قطع `sourceEventSeqs`**: غير مقبول، لأن هذا ممكن سوف من رسالة في بين قطع قسم صفحة، كسر تالف إعادة تشغيل قسم مجموعة.
- **في مزود حد حد تدفق صيغة قسم قطعة عدد كمية**: غير مقبول، لأن مزود ممكن سوف دمج إدارة أرض إنتاج طويل تدفق، بينما قسم صفحة يجب معالجة كل واحد نوع صالح جلسة يمثل.

## عاقبة

- كبير نوع تتبع مصدر عدد مجموعة لم يعد فقط بسبب طويل درجة بينما جعل تاريخ سجل قسم صفحة رمي خروج استثناء.
- قسم صفحة دلالة و بروتوكول استجابة إبقاء ثابت.
- هذا قرار لا حد تاريخ سجل صفحة بايت كبير صغير، أيضا لا حد متصفح إعادة تشغيل هذا صفحة فتح إلغاء؛ هذا اثنان بند صفة قدرة مشكلة ما زال و خدمة طرف استدعاء مكدس لذا عائق قسم فتح معالجة.
