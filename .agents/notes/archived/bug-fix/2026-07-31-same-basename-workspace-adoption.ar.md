# Agent Note: وصل قبول basename نفسه Workspace

Status: implemented
Archived: 2026-09-04

[English](2026-07-31-same-basename-workspace-adoption.md) | العربية

## مشكلة

Workspace هوية من ذلك مستقر id و مواصفة دليل مسار تحديد، عنوان فإن هو متغير عرض بيانات وصفية. لكن بينما، فقط يلزم جديد مواصفة مسار حسب دليل اسم إرسال توليد خروج عنوان و آخر عدد Workspace نفسه، سجل التسجيل حينئذ سوف رفض هذا مسار. لذلك،`/a/xx` و `/b/xx` انتظار معتاد رؤية دليل تخطيط لا يمكن معا ظهور في Web UI في، كل إدارة[مجال تصميم](../../proposed/architecture/2026-07-24-domain-kv-storage-and-workspace.ar.md) مبكر قد سماح عنوان تكرار، بينما كما كل بند عميل عملية كل عبر id تحديد موضع Workspace.

## قرار

`ctx.workspaceRegistry.create(path, title?)` فقط بـ مواصفة مسار بصفة وحيد صفة مفتاح. تكرار نقل دخول نفس مسار ما زال إبقاء قوة انتظار، و إبقاء قد تسجيل عنوان. مختلف مواصفة مسار سوف إنشاء مختلف Workspace سجل، كما يمكن مشترك استخدام عنوان؛ لم توفير عنوان وقت، كل بند سجل من نهائي مسار مقطع إرسال توليد عنوان، هذا مسار مقطع لـ فارغ وقت رجوع إلى أصل مسار تجميع كتابة.[Workspace تماما حد تحديد مسار قرار](2026-09-03-fully-qualified-workspace-paths.ar.md) مسؤول قاعدة تحديد مسار دقيق دخول و عنوان رجوع.

Host `workspace.create({ path })` وصل قبول مدخل امتداد استخدام هذا قاعدة.Workspace إدارة جهاز، اختيار جهاز، قسم مجموعة شجرة، اختيار، إعادة تسمية، حذف و Session إنشاء ما زال استخدام `WorkspaceId`، لذلك نفسه وسم حيث لن دمج سجل، أيضا لن يأخذ عملية إشارة نحو أخرى سجل. حاجة منطقة قسم نفسه وسم وقت، جانب حافة شريط معلق توقف تفصيل حال بطاقة سوف عرض كل منها مواصفة مسار.

صريح تسمية ما زال اعتماد أكثر صارم إطار قاعدة.`workspace.rename` ما زال سوف رفض قد تسجيل عنوان، أداة جسم رؤية[يد حركة Workspace تسمية](../feature/2026-07-25-session-list-browsing-and-manual-order.ar.md). هذا حيث منع توقف مستخدم رئيسي حركة جذب دخول آخر عدد صعب بـ منطقة قسم وسم، أيضا سماح قائم دليل اسم صنع صار إعادة اسم. مسار وصل قبول قاعدة فقط يحل محل [Workspace منتج تدفق](../feature/2026-07-25-workspace-ui-product-flow.ar.md) و[أصلي دليل اختيار جهاز](../feature/2026-07-27-native-workspace-directory-picker.ar.md) في عنوان اندفاع مفاجئ بند بند.

حفظ دائم schema لم تغيير:Workspace سجل هذا حينئذ قسم آخر تخزين id،path و title، جذب توجيه ابتدائي تحويل يمكن إرسال توليد خروج نفسه basename، بدء تحقق فحص هو تكرار مسار بينما غير تكرار عنوان.

## تحقق

Workspace سجل التسجيل و Host API اختبار سوف في مختلف أب دليل تحت إنشاء اثنان عدد نهاية درجة اسم نفسه حقيقي دليل، و تأكيد ذلك id و مسار متبادل لا نفسه، كما حفظ دائم ترتيب صحيح تأكيد. اختيار جهاز مكون سوف نفسه وسم تصيير لـ حسب id منطقة قسم مستقل بند. بلا مفتاح Web متصفح مشهد عبر تركيب بينما صار دليل مسار وصل قبول هذا اثنان عدد دليل، و مراقبة إلى اثنان عدد Workspace متساو قد تسجيل كما إتمام تصيير.

## اعتبار مرور بديل خطة

**إبقاء عنوان وحيد، و رفض ثاني عدد دليل.** عرض وسم ما زال سوف معنى خارج ملء عند هوية مفتاح، عادي كثير أصل دليل تخطيط ما زال لا يمكن تسجيل.

**تلقائي لـ اندفاع مفاجئ عنوان إضافة بعد لاحقة.** مثل `xx (2)` هذا مثال توليد وسم سوف لم يعد هو من دليل إرسال توليد عنوان؛ نظام أيضا حاجة صنع تحديد عبر حذف و إعادة تحميل إبقاء مستقر قسم إعداد قاعدة، و كما فقط لـ إخفاء غطاء هوية حكم تحديد خطأ بينما زيادة حالة.

**سوف كامل مسار استخدام عمل كل Workspace عنوان.** هذا سوف إزالة حذف اندفاع مفاجئ، لكن جعل رئيسي تنقل وسم لا لا بد يلزم أرض مرور طويل. كامل مسار ما زال يمكن في معلق توقف تفصيل حال في فحص نظر، بينما بسيط نظيف basename ما زال لديه قيمة قيمة.

**أيضا سماح صريح إعادة تسمية عملية إنتاج إعادة اسم.** سجل التسجيل دعم حمل هذا نوع حالة، لكن هذا عملية هذا حينئذ هو واضح اشتراط مستخدم اختيار عرض اسم. إبقاء اندفاع مفاجئ استجابة يمكن صيانة حمل قائم تسمية منع حماية، معا لا منع توقف من نظام الملفات اختيار أخذ مسار.

## عاقبة

اثنان عدد Workspace سطر ممكن عرض نفسه مرئي عنوان.id مسؤول هوية، لذلك اثنان سطر ما زال يمكن مستقل اختيار و عملية؛ مستخدم يمكن فحص نظر مسار أو إعادة تسمية مهمة واحد سطر بـ عمل منطقة قسم. صريح إعادة تسمية لا يستطيع اعتماد آخر عدد سطر حالي استخدام عنوان، أي جعل هذا عنوان مصدر ذاتي basename نفسه دليل وصل قبول. بلا حاجة تخزين ترحيل أو توافق مسار.
