# Agent Note: Workspace تماما حد تحديد مسار

Status: implemented
Archived: 2026-09-04

[English](2026-09-03-fully-qualified-workspace-paths.md) | العربية

## مشكلة

Workspace مسار هوية يجب في لا اعتماد عملية حالة حال حال تحت إشارة نحو وحيد دليل.POSIX متبادل مقابل مسار،`C:work` انتظار Windows مشغل متبادل مقابل مسار، و `\\work` انتظار Windows حالي مشغل أصل متبادل مقابل مسار، ممكن اعتماد حسب مضيف cwd أو مشغل إبقاء حالي دليل إتمام تحليل. يأخذ هذه تجميع كتابة نقل إعطاء `realpath`، سوف في مضيف حالة تغير وقت تسجيل مختلف دليل. نظام الملفات أصل دليل basename أيضا لـ فارغ، ممكن إنتاج فارغ افتراضي Workspace عنوان.

متصفح أمان متبادل مقابل مسار اتصال أيضا حاجة مفرد وحيد معالجة Windows مشغل أصل. إزالة `C:\\` ذيل جزء فصل رمز سوف نيل إلى `C:`، من بينما يأخذ قطعا مقابل مسار تغيير صار مشغل متبادل مقابل مسار.

## قرار

`WorkspaceRegistry.create()` و `resolveByPath()` سوف في استدعاء `realpath` قبل رفض لا هو تماما حد تحديد شكل صيغة مسار.POSIX اشتراط قطعا مقابل مسار.Windows اشتراط `win32.isAbsolute(path)`، كما تحليل خروج أصل حيث لا هو `\\` أيضا لا هو `/`؛ هذا قاعدة قبول مشغل حد تحديد مسار و UNC مسار، معا بلا حاجة صيانة ثاني طقم مسار لغة قاعدة يكفي رفض حالي مشغل أصل تجميع كتابة و مشغل متبادل مقابل تجميع كتابة.

مواصفة مسار متابعة بصفة سجل التسجيل هوية. افتراضي عنوان استخدام نهائي مسار مقطع؛ هذا مسار مقطع لـ فارغ وقت، فإن استخدام `node:path` تحليل خروج أصل. هذا قاعدة دقيق تحويل[وصل قبول basename نفسه Workspace](2026-07-31-same-basename-workspace-adoption.ar.md) يملك عرض قاعدة، لكن لن اشتراط عنوان وحيد.

متصفح أمان `resolveWorkspacePath()` سوف أولا أصل حسب Workspace تجميع كتابة اختيار قسم فصل رمز، مجددا إزالة ذيل جزء فصل رمز. استخدام عكس مائل عمود مشغل و UNC مسار إبقاء `\\`، استخدام صحيح مائل عمود مشغل مسار إبقاء `/`، و مشغل أصل اتصال وقت بداية نهاية إبقاء خطر رقم بعد قسم فصل رمز.

## اعتبار مرور بديل خطة

**اعتماد حسب مضيف cwd تحليل متبادل مقابل مسار.** غير مقبول، لأن Workspace هوية سوف اعتماد استدعاء جهة لم توفير، بعيد مسار عميل لا يمكن مراقبة عملية حالة.

**اعتماد حسب آخر عدد قد تخزين Workspace تحليل متبادل مقابل مسار.** غير مقبول، لأن create و lookup طلب لا يوجد إشارة تحديد هذا نوع مرساة نقطة، تخمين قياس مرساة نقطة سوف يجعل نفس مسار تجميع كتابة إشارة نحو مختلف سجل.

**صيانة لأجل مشغل و UNC لغة قاعدة صحيح فإن جدول بلوغ صيغة.** غير مقبول، لأن `node:path.win32` قد تحليل أصل و قطعا مقابل مسار؛ ثاني طقم لغة قاعدة ممكن في قسم فصل رمز تغيير جسم و UNC أصل فوق حدوث انحراف فرق.

**لـ نظام الملفات أصل دليل استخدام فارغ عنوان.** غير مقبول، لأن عنوان هو Workspace رئيسي يلزم وسم. أصل مسار تجميع كتابة بسيط قصير، مستقر، و كما قد يمكن منطقة قسم مشغل و UNC أصل.

## عاقبة

استدعاء جهة يجب إيداع تماما حد تحديد Workspace مسار. بلا فاعلية مسار تجميع كتابة سوف في نظام الملفات وصول قبل فشل، بينما لا وجود تماما حد تحديد مسار ما زال إرجاع أصلي نظام الملفات خطأ.Windows مشغل أصل و UNC أصل متابعة بصفة صالح هوية، و أداة لديه غير فارغ افتراضي عنوان؛UNC share أصل استخدام share اسم بصفة نهائي مسار مقطع.

Workspace متبادل مقابل مسار اتصال سوف إبقاء Workspace أصل في قد لديه قسم فصل رمز ريح إطار. اختبار وحدة تغطية POSIX أصل، مشغل أصل،UNC أصل، يتم رفض مشغل متبادل مقابل مسار و حالي مشغل أصل مسار، و اثنان نوع Windows قسم فصل رمز ريح إطار.
