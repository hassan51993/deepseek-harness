# Agent Note: تفكيك قسم نظام الملفات seam——مزود نص تغيير عملية و `dsh-fs-observation-policy` إضافة

Status: implemented

[English](2026-06-26-fsspec-style-fs-seam.md) | العربية

## مشكلة

[نظام الملفات قدرة seam](../../archived/architecture/2026-06-17-filesystem-capability-seam.md) في نظام الملفات قدرة هدف قبل يجعل واحد سحب كائن `FileSystem` خدمة معا مسؤول اثنان بند مختلف عمل:

1. **مزود عملية**——تحليل هدف،stat/إصدار بيانات وصفية، نص قراءة/تدفق صيغة قراءة، أصل فرعي كتابة، و تلقي حفظ حماية حرف وجه تحرير.
2. **موجه إلى agent(ذكي جسم) سياسة**——سطر نافذة، حرف وجه تحرير دلالة، و قراءة بعد كتابة/تحرير مراقبة قياس حالة.

هذا توجيه يؤدي كل لم قدوم خلفية كل يلزم إعادة تنفيذ موجه إلى نموذج قراءة دلالة و مراقبة قياس سياسة.`readPage` إرجاع حمل سطر رقم سطر و عرض بيانات وصفية؛ أساس أساس خدمة حسب owner تخزين ملف حالة، و منطقة قسم `full` و `partial` قراءة. هذه هو لديه استخدام سياسة، لكن هو جمع لا هو نظام الملفات مزود أصل لغة. حرف وجه نص تغيير فإن مختلف: إصدار حراسة حماية، حرف وجه مطابقة، اختلاف معنى فحص قياس و أصل فرعي إعادة كتابة يجب إبقاء في مزود تغيير حد داخل، لكن حالي `applyEdit` تسمية و ذلك دورة محيط seam سوف هذا واحد مزود عملية ربط إلى قديم قراءة بعد تحرير سياسة شكل حالة فوق.

هذا أيضا صنع صار واحد حقيقي مستخدم تجربة ميت عشوائي نفس: نافذة تحويل قراءة سجل `view: partial`، بينما partial عرض لا يمكن تخويل `edit`. واحد نموذج قراءة كبير ملف رقم 100-150 سطر، إذا تفكير تحرير رقم 120 سطر، حينئذ يجب أولا نيل أخذ مرة `full` قراءة، بينما مقابل في تجاوز مرور قراءة حد أعلى ملف هذا ممكن فعل لا إلى. حرف وجه تحرير فعلي فوق فقط حاجة جديد طازج درجة: يتم مطابقة بايت ما زال قدوم ذاتي نموذج الذي قراءة ذلك عدد إصدار يكفي.

قديم Agent Note قد دفع متأخر مستقل `@deepseek-ai/dsh-fs-observation-policy` حزمة. هذا قرار بناء هذا طبقة، جعل `ctx.fs` إبقاء وصل قريب fsspec ريح إطار تخزين أصل لغة (`info`/`cat`/`open`) ، لكن لا يأخذ هو تغيير صار كامل fsspec.

## قرار

سوف مكدس تفكيك لـ أربعة طبقة:

```text
tool          dsh-tool-fs       model-facing schemas + read windowing + text rendering; the EXECUTOR (reads/writes/edits via ctx.fs, dispatches the fs/* events)
policy        dsh-fs-observation-policy  observed-state + read-before-edit + write/edit freshness, contributed through the fs/* event gate (no service)
provider contract dsh-fs            ctx.fs: text IO + atomic mutation primitives (optional version guard)
provider      dsh-fs-local      local implementation of ctx.fs
```

`dsh-tool-fs` إبقاء نفسه موجه إلى نموذج `read`/`write`/`edit` schema. هو هو منفذ: حقن `fs`(لا هو سياسة خدمة) و مباشر وصول `ctx.fs`، يملك قراءة نافذة تحويل منطق، و توزيع `fs/*` حدث بـ سهل `dsh-fs-observation-policy` إجراء باب تحكم و سجل.

هذا Agent Note قرار أربعة طبقة تفكيك قسم، مزود اتفاق و جديد طازج درجة سياسة. مع بعد،[حدث بوابة Agent Note](../architecture/2026-06-26-file-context-as-event-gate.ar.md) دقيق تحويل أداة↔سياسة اقتران دمج:`dsh-fs-observation-policy` هو عبر `fs/*` حدث مشاركة و بوابة إضافة، بينما غير `ctx.fileContext` طريقة خدمة، لذلك أداة لن في طريقة طبقة و ذلك اقتران دمج؛ قراءة نافذة و fs I/O يقع في `dsh-tool-fs`. هذا نص وصف قد سقوط أرض حدث بوابة شكل حالة؛ مزود إصدار حراسة حماية اختياري (حذف أي بلا شرط عار مزود).

## مزود اتفاق

`@deepseek-ai/dsh-fs` استلام تقليص لـ مزود نص IO إضافة تلقي حفظ حماية نص تغيير:

```ts ignore-check
abstract resolve(path: string, opts?: { cwd?: string; signal?: AbortSignal }): Promise<FsTarget>
abstract stat(target: FsTarget, signal?: AbortSignal): Promise<FsInfo | undefined>
abstract readText(target: FsTarget, signal?: AbortSignal): Promise<string>
abstract streamText(target: FsTarget, signal?: AbortSignal): Promise<AsyncIterable<string>>
abstract writeText(target: FsTarget, content: string, expected: FsWriteIntent, signal?: AbortSignal): Promise<FsWriteOutcome>
abstract editText(target: FsTarget, edit: FsEditRequest, expected: { version: FsVersion }, signal?: AbortSignal): Promise<FsEditOutcome>

interface FsInfo {
  version: FsVersion
  type: 'file' | 'directory' | 'other'
  size?: number
}

type FsWriteIntent =
  | { kind: 'createIfAbsent' }
  | { kind: 'replaceIfVersion'; version: FsVersion }
```

`stat` إرجاع بيانات وصفية بينما غير محتوى.`version` هو جديد طازج درجة أمر لوحة؛`type` يجعل منفذ في قراءة قبل رفض دليل/خاص خاص ملف؛`size` يجعل `read` أداة بلا حاجة عبر فشل استكشاف قياس يكفي اختيار `readText` أيضا هو `streamText`.`undefined` يمثل هدف لا وجود.

`readText` قراءة كامل عادي نص ملف.`streamText` بـ نفسه نص دلالة تدفق صيغة قراءة كبير ملف. اثنان عدد مزود أصل لغة مسؤول عادي ملف فحص،UTF-8 حل رمز، اثنان دخول صنع/NUL رفض و `FS_NOT_TEXT`؛ سياسة طبقة من لا معالجة أصلي بايت، أيضا لا إعادة تنفيذ عبر قسم قطعة حل رمز.`readText` هو صغير ملف/مباشر كل ملف أصل لغة، بينما موجه إلى نموذج كبير ملف قراءة استخدام `streamText`.

`writeText` عبر مؤقت ملف + rename تنفيذ أصل فرعي كتابة، و حمل لديه صريح كتابة مدة نظر.`createIfAbsent` إنشاء لا وجود هدف، مقابل قد وجود هدف بـ `FS_NOT_OBSERVED` رفض؛ هذا هو owner لا يوجد أولا قبل قراءة وقت استخدام مسار.`replaceIfVersion` فقط في هدف بـ مراقبة قياس إلى إصدار وجود وقت استبدال؛ هدف لا وجود أو إصدار لا مطابقة وقت رمي خروج `FS_STALE_VERSION`.

`editText` هو مزود درجة آخر تلقي حفظ حماية نص تغيير. تفعيل حراسة حماية وقت، هو أول أولا تحقق هدف ما زال بـ `expected.version` وجود، لكن بعد قراءة حالي نص، تطبيق حرف وجه استبدال و أصل فرعي كتابة. قديم قديم فحص يجب في حرف وجه مطابقة قبل حدوث، هذا مثال أساس في قديم قراءة تحرير سوف تقرير إبلاغ `FS_STALE_VERSION`، بينما لا هو مقابل تحديث محتوى إجراء مطابقة بعد تقرير إبلاغ `FS_EDIT_NOT_FOUND` أو `FS_AMBIGUOUS_EDIT`. سوف هذا أصل لغة إبقاء في مزود اتفاق فوق، إبقاء خلفية محلي قفل تحديد قدرة، أيضا يجعل لم قدوم بعيد مسار خلفية قدرة كاف تنفيذ أصلي compare-and-edit، بينما بلا حاجة سياسة طبقة سحب أخذ كامل ملف.

هذا هو واحد*نص تخزين* seam، لحظة معنى مقارنة بايت درجة fsspec(`cat`/`open` إرجاع أصلي بايت) عال نصف عدد طبقة مرة.UTF-8 حل رمز، اثنان دخول صنع/NUL رفض، تلقي حفظ حماية كل ملف كتابة و تلقي حفظ حماية حرف وجه نص تحرير كل في مزود داخل إتمام، لذلك سياسة طبقة من لا وصل لمس أصلي بايت، لا إعادة تنفيذ عبر قسم قطعة حل رمز، أيضا لا سوف قديم قديم فحص و تغيير قرب حد منطقة قسم مغادرة. موجه إلى نموذج عام فكرة ما زال لا تحت غرق إلى مزود: سطر نافذة، حمل سطر رقم سطر، تصيير صفحة قدم، مراقبة قياس حالة تخزين كل لن تسرب تسرب تحت ذهاب.

من `dsh-fs` حذف:`readPage`،`FsExpectation`،`FsView`،`FsStateSource`،`FsReadRequest`،`FsTextLine`، سطر/نافذة معتاد كمية،`formatReadBody` و observed-state `WeakMap`.`applyEdit` من أكثر ضيق مزود أصل لغة `editText` يحل محل، ذلك اتفاق هو حمل إصدار حراسة حماية حرف وجه نص تغيير، بينما غير سياسة طبقة قراءة تخويل.`FS_PARTIAL_OBSERVATION` رمز خطأ أيضا من `FsErrorCode` تصنيف جسم نظام في إزالة: جديد طازج درجة تخويل لا يوجد جزء/كامل لـ قسم، لذلك لا يوجد أي مسار سوف رمي خروج هو.`FsTargetKey` و `FsVersion` حسب قائم[صنف لوحة تحويل id Agent Note](../../archived/architecture/2026-06-20-branded-ids.md) يصبح صنف لوحة تحويل لا نفاذ واضح id.

## سياسة اتفاق

`@deepseek-ai/dsh-fs-observation-policy` هو إضافة، بينما غير خدمة: هو لا تسجيل أي `ctx.*` مفتاح، أيضا لا حقن أي محتوى. هو يملك لا ينبغي يقع في `FileSystem` مزود أساس صنف فوق كتابة/تحرير جديد طازج درجة سياسة و observed state(لا فإن صندوق رملي/بعيد مسار خلفية سوف وراثة لا هذا من ذلك تحمل تحميل موجه إلى نموذج مراقبة سياسة). هو عبر منفذ قسم إرسال `fs/*` حدث بوابة مساهمة هذا سياسة.

مراقبة قياس حالة بـ `WeakMap<owner, Map<targetKey, FsVersion>>` شكل صيغة تخزين وضع في هذا. عند كما فقط عند owner قراءة، كتابة أو تحرير مرور هذا هدف وقت، بند عندئذ وجود (كل مرة نجاح كل سوف إرسال خروج `fs/observed`) ، لذلك بند وجود*ذاته حينئذ هو*أولا قبل مراقبة قياس سجل——لا يوجد مفرد وحيد `hasRead` علامة سجل.owner من لا نفاذ واضح حدث actor(`{ agent?: { session? } }`) بنية تحويل إرسال توليد، هذا شكل حالة تعريف في `dsh-fs-observation-policy` في بينما غير `dsh-fs` في.

هذا إضافة قرار ثلاثة عدد `fs/*` حدث:

- `fs/write-intent`——بلا أولا قبل مراقبة قياس ⇒ `{ kind: 'createIfAbsent' }`(فقط لديه جديد ملف يمكن أعمى إنشاء) ؛ لديه أولا قبل مراقبة قياس ⇒ `{ kind: 'replaceIfVersion', version: vObserved }`(قد لديه ملف فقط في ذاتي مراقبة قياس بـ قدوم لم تغيير وقت عندئذ استبدال). مفرد مجرى قرار؛ لا استدعاء `next()`.
- `fs/edit-intent`——اشتراط owner لديه أولا قبل مراقبة قياس (لا فإن `FS_NOT_OBSERVED`) ؛ إرجاع `{ version: vObserved }` بصفة CAS أساس أساس. هو لا تنفيذ حرف وجه استبدال——هو تخويل و توفير إصدار، مزود تغيير قرب حد منطقة مسؤول تطبيق حراسة حماية، لذلك أساس في نفس مراقبة قياس إصدار تزامن تحرير ما زال هو واحد نجاح، آخر عدد بسبب إصدار قديم قديم بينما فشل.
- `fs/observed`——في نجاح قراءة/كتابة/تحرير بعد، لـ هذا owner+target سجل `{ version }`. تزامن، فقط فرعي أثر `WeakMap.set`.

هذا إضافة لا فعل أي نظام الملفات I/O:«أنت هل مراقبة قياس مرور هذا ملف؟» هو مرة `WeakMap` فحص بحث، بينما «أنت قراءة إصدار هل ما زال هو حالي إصدار؟» في `ctx.fs.editText`/`writeText` داخلي، و تنفيذ تغيير نفسه أصل فرعي قفل في قرار——إضافة فقط توفير `vObserved` بصفة أساس أساس.

## أداة اتفاق

`dsh-tool-fs` إبقاء نفسه schema و نص التوجيه جدول وجه.`read` ما زال كشف `file_path`،`offset` و `limit`؛`write` و `edit` ثابت. هو هو منفذ: تحقق نموذج معامل، عبر `ctx.fs` مباشر قراءة/كتابة/تحرير، يملك سطر نافذة تحويل و نتيجة تصيير (`N: text`، صفحة قدم،`<path>/<content>` غلاف تركيب) ، و توزيع `fs/*` حدث.

كل تغيير عملية أولا توزيع ذلك intent waterfall(شلال نشر صيغة حدث) ، حمل لديه `undefined` عار مزود قيمة افتراضية، لكن بعد استدعاء `ctx.fs`، مجددا إرسال خروج `fs/observed`. مثال مثل `write` تنفيذ `ctx.waterfall('fs/write-intent', target, exec, () => undefined)` → `ctx.fs.writeText(target, content, intent)` → `ctx.emit('fs/observed', …)`.`read` أولا stat مرة، لكن بعد قراءة/تدفق صيغة قراءة، بناء نافذة، الأكثر بعد إرسال خروج `fs/observed`. سوف `exec` بصفة actor نقل تمرير، يجعل `dsh-fs-observation-policy` بلا حاجة أداة عميق دخول سياسة يكفي إرسال توليد owner.

من في سياسة عبر حمل لديه `undefined` قيمة افتراضية حدث مساهمة،`dsh-tool-fs` لا و `dsh-fs-observation-policy` إنتاج طريقة اقتران دمج: في إضافة نقص مقعد وقت، كل intent waterfall كل سقوط إلى `undefined`(بلا شرط عار مزود كتابة/تحرير) ،`fs/observed` لا يوجد مستمع. تحميل إضافة بعد يكفي تراكم إضافة قراءة بعد كتابة/تحرير سياسة.

## تزامن حد

عملية داخل تحديث هو أمان: محلي خلفية إبقاء قائم حسب هدف تغيير قفل، لذلك إصدار فحص-لكن بعد-rename هو سلسلة سطر تحويل، فشل تحديث سوف يرى `FS_STALE_VERSION`.

عملية داخل إنشاء من نفس عدد حسب هدف تغيير قفل حفظ حماية: اثنان عدد استدعاء من بـ `createIfAbsent` تنافس تنازع وقت سلسلة سطر تحويل، واحد إنشاء نجاح، آخر عدد يرى هدف قد وجود و استلام إلى `FS_NOT_OBSERVED`. عبر عملية إنشاء فقط لـ كل قوة بينما لـ؛ محلي stat-then-rename حراسة حماية لا يمكن في كل لم قدوم خلفية فوق توفير يمكن نقل غرس ترتيب هو إنشاء حفظ إثبات.

عبر عملية كتابة هو كل قوة بينما لـ جديد طازج درجة إضافة أصل فرعي استبدال:`mtime:size` عبر معتاد قدرة التقاط تحرير جهاز حفظ، لكن ممكن فحص قياس لا إلى نفس tick داخل كبير صغير نفسه كتابة؛ أصل فرعي temp+rename منع توقف ملف تمزيق شق لكن لا يستطيع منع توقف كل فقد فقد تحديث.

## يحل محل

هذا Agent Note دفع قلب[نظام الملفات قدرة seam](../../archived/architecture/2026-06-17-filesystem-capability-seam.md) في اثنان بند قرار، و استلام ضيق رقم ثلاثة بند:

- قراءة بعد كتابة/تحرير سياسة من `ctx.fs` نقل خروج، دخول `dsh-fs-observation-policy` إضافة (عبر `fs/*` حدث باب تحكم).
- نص قراءة لم يعد إرجاع خلفية تحرير رقم سطر سجل أو `full`/`partial` عرض؛ تخويل أساس في إصدار جديد طازج درجة، لذلك نافذة تحويل قراءة في ملف لم تغيير وقت يكفي تخويل تحرير.
- حرف وجه تحرير لم يعد يقع في قديم `applyEdit` API بعد (هذا API خلط دمج خلفية تغيير و seam يملك مراقبة قياس سياسة). هو بصفة `editText` إبقاء لـ مزود أصل لغة، لأن إصدار حراسة حماية + حرف وجه مطابقة + أصل فرعي إعادة كتابة يجب إبقاء في مزود تغيير قرب حد منطقة داخل.

إبقاء محتوى:Service Definition / Service Provider / Consumer سجل قاعدة، مستهلك لا استيراد خلفية قاعدة، خلفية تعريف target/version/display بيانات وصفية، أصل فرعي محلي كتابة، و مشترك `FsError` تصنيف جسم نظام.

## تحقق

`dsh-fs` دقيق كشف `resolve`/`stat`/`readText`/`streamText`/`writeText`/`editText`(`stat` إرجاع `FsInfo | undefined`،`writeText` قبول `FsWriteIntent`) ، قد حذف نوع/أصل لغة لم يعد وجود؛`dsh-fs-local` لا يتضمن سطر، عرض أو `formatReadBody` منطق؛ موجه إلى نموذج schema إبقاء تدريجي بايت ثابت. اختبار ثابت التالي سلوك: نافذة تحويل قراءة تخويل مقابل لم تغيير ملف لاحق تحرير؛ أساس في قديم قديم قراءة تحرير في محاولة تجربة حرف وجه مطابقة قبل تقرير إبلاغ `FS_STALE_VERSION`؛ إصدار CAS سلوك نيل بـ إبقاء؛ مراقبة قياس اتفاق صار قيام (`read` أداة قراءة سجل مراقبة قياس حالة؛ مباشر `ctx.fs` قراءة لا سجل) ؛`dsh-fs-observation-policy` أداة لديه HMR(حار وحدة استبدال)/dispose(مورد تحرير) اختبار تغطية.

## لاحق توسيع

بعد قدوم،[لـ نظام الملفات seam إضافة مباشر دليل قائمة](../../archived/architecture/2026-07-03-filesystem-directory-listing-seam.md) دخول واحد خطوة توسيع هذا seam. هذا لاحق عمل مفرد وحيد سجل، جعل هذا نص متابعة وصف الأكثر أول سقوط أرض fsspec ريح إطار تعديل صنع.

## سبق اعتبار بديل خطة

- **بايت درجة fsspec(`cat`/`open` إرجاع أصلي بايت)**: مرفوض. هذا seam لحظة معنى تحديد موضع لـ نص تخزين، مقارنة بايت درجة عال نصف عدد طبقة مرة، هذا مثال UTF-8 حل رمز، اثنان دخول صنع/NUL رفض و تلقي حفظ حماية نص تغيير فقط في مزود تنفيذ مرة، سياسة طبقة من لا وصل لمس أصلي بايت، أيضا لا سوف قديم قديم فحص و تغيير قرب حد منطقة قسم مغادرة.
- **أداة جسم `ctx.fileContext` طريقة خدمة**——هذا Agent Note الأكثر أول سياسة شكل حالة؛[حدث بوابة Agent Note](../architecture/2026-06-26-file-context-as-event-gate.ar.md) سوف ذلك إعادة فعل لـ بوابة إضافة، جعل أداة دائم بعيد لن في طريقة طبقة و سياسة اقتران دمج.
- **في مزود إبقاء `readPage` و `full`/`partial` عرض تخويل**:«يحل محل» واحد عقدة الذي عكس تحويل إعادة بنية قبل شكل. عرض كامل صفة لا هو تحرير أمان الذي يحتاج، إصدار جديد طازج درجة عندئذ هو؛ بينما عرض قاعدة جعل تجاوز مرور قراءة حد أعلى كبير ملف لا يمكن تحرير.

## عاقبة

- إضافة جديدة رقم أربعة عدد fs حزمة و واحد جديد إضافة طبقة. هذا هو متعمد لـ لـ: هو هو هذا قبل دفع متأخر سياسة طبقة، بينما غير ثاني عدد سحب كائن خلفية اتفاق.
- مباشر استخدام `ctx.fs` سوف التفاف مرور سياسة: مباشر `ctx.fs.readText` لا إرسال خروج `fs/observed`، لذلك في افتراضي سياسة تحت، لاحق `edit` سوف بـ `FS_NOT_OBSERVED` رفض، مباشر إلى عبر `read` أداة قراءة هذا ملف. هذا واحد فشل هو صريح كما لديه وثيقة سجل.
- كبير ملف سطر نافذة تحويل من خلفية نقل حتى `dsh-tool-fs` في `read` أداة؛ نص حل رمز و اثنان دخول صنع رفض إبقاء في `ctx.fs.streamText` في، لذلك هذا فقط هو نافذة تحويل منطق ترحيل، بينما غير ثاني طقم نص IO تنفيذ.
- سوف `editText` إبقاء في مزود اتفاق فوق معنى طعم حال كل خلفية كل يجب تنفيذ حرف وجه استبدال اتفاق. هذا هو متعمد لـ لـ: هذا عملية لا هو صاف تخزين، لكن قديم قديم حراسة حماية + حرف وجه مطابقة + أصل فرعي إعادة كتابة هو يجب إبقاء في واحد بدء وحدة، بـ تأكيد حفظ صحيح تأكيد خطأ عودة بسبب و تزامن سلوك. هذا اتفاق ينبغي إبقاء ضيق كما فقط حد نص، بـ سهل لم قدوم خلفية يمكن أصلي تنفيذ أو عبر كل ملف إعادة كتابة تنفيذ.
- جديد طازج درجة سماح في نافذة تحويل قراءة بعد إجراء كل ملف `write`. هذا مقارنة قديم عرض فحص أكثر ضعيف، لكن تجنب تجنب كبير ملف لا يمكن تحرير مشكلة؛ نص التوجيه جذب توجيه ما زال لا حث تشجيع أعمى هدف كل ملف استبدال.
