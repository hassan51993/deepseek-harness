# Agent Note: فتح كبير نوع Session مطلوب CI صفة قدرة gate

Status: implemented

[English](2026-09-04-session-open-performance-gate.md) | العربية

## مشكلة

Session format v2 دفع خروج تغيير اثنان بند صار هذا مع نموذج إخراج زيادة طويل مسار:JSONL backend ترحيل تزامن نشر released-v0 log،Client fold كل قد تسوية عودة تكرار في تضمين دخول ضيق تجميع stream. اثنان بند مسار كل لا يوجد يمكن تنفيذ صفة قدرة فحص، لذلك أول مرة فتح في 127,400 حدث دمج صار log فوق من نحو 35 ms زيادة طويل إلى نحو 5 s(في 575,000 chunk حقيقي log فوق من نحو 0.3 s زيادة طويل إلى 26 s، ذروة قيمة RSS 2.7 GB، و في 512 MB كومة حد تحت استهلاك كل كومة) ،Client fold أيضا مع تدفق صيغة delta عدد بينما لا هو ضيق تجميع سجل عدد خط صفة زيادة طويل، هذه تراجع تحويل لم يتم ملاحظة شعور أرض دخول master.

فقط قياس `SessionPersistence.open()` لا يستطيع مستقر جدول بلوغ مستخدم أو Host انتظار نتيجة. عمل يمكن في `open()`،`SessionHandle.read()`،Session restore و projection بين نقل حركة، بينما أول مرة تاريخ صفحة و بارد Agent استعادة أيضا يتضمن هذه عملية لـ فوق مستقل تحرير ترتيب. عملية انتهاء وقت لم مرور GC مرة `heapUsed` أخذ مثال أيضا لا يستطيع منطقة قسم ما زال يتم Session يحتفظ بيانات و يمكن عودة استلام ترحيل مؤقت كائن.

## قرار

Linux pull request تشغيل مطلوب `node 24 / benchmarks` job، تنفيذ `pnpm run check:ci:bench` → `pnpm run test:bench`. خاص `@deepseek-ai/dsh-benchmarks` workspace يملك benchmark مخصص تابع اعتماد. هذا أمر أولا بناء workspace library و `benchmarks/.dsh-build/` تحت مخصص استخدام worker، مجددا استدعاء `vitest.bench.config.ts`.[معيار حمل إدارة تشغيل جهاز قرار](2026-09-06-standard-hosted-benchmark-runner.ar.md) يملك تشغيل جهاز اختيار و خارج طبقة job مهلة. هذا job مفرد وحيد تشغيل benchmark lane؛Vitest تدريجي ملف تشغيل، فقط مسؤول دقيق تجهيز إدخال، بدء قياس كمية عملية فرعية، تجميع مجموع نتيجة و تنفيذ ميزانية تأكيد. كل بند يتم حساب وقت Node CPU مسار كل بـ صاف Node تنفيذ تحرير ترجمة بعد JavaScript، و إزالة `NODE_OPTIONS` كما لا تحميل TypeScript runtime؛workspace عار استيراد لذلك من `benchmarks/node_modules` عبر package exports تحليل إلى بناء بعد `lib/` مدخل.

مطلوب صفة قدرة gate يقع في قمة طبقة `benchmarks/`، حسب يتم قياس مستخدم مسار بينما غير package ملكية مجموعة نسج.Host ملف استخدام `*.bench.ts`،Client وجه ملف استخدام `*.bench.client.ts`، مشهد مخصص تابع worker و fixture إبقاء في مقابل benchmark جانب كما لا حمل benchmark بعد لاحقة. حزمة داخل `.perf.ts` ملف ما زال هو غير بوابة تشخيص؛`scripts/` مسؤول تحرير ترتيب بينما لا تحمل تحميل benchmark case.

Session benchmark استخدام ثابت معامل دمج صار released-v0 إدخال:200 جولة، كل جولة 500 عدد text delta و 125 عدد reasoning delta، مشترك 127,400 عدد منطق حدث. إدخال استخدام Zstandard، و ثابت logical rows قسم مجموعة و frame تفكيك قسم، جعل كل مرة تشغيل معالجة نفسه حدث، بايت و frame قسم نشر. كل دمج صار turn أولا بدء step، مجددا إلحاق user surface إدخال، جعل V2-to-V3 migration قدرة مسبق إبقاء تلقي حفظ حماية system head بينما لا إعادة ترتيب تاريخ.fixture مباشر بنية صنع released-v0 physical rows، لا اعتماد حالي runtime تاريخ encoder؛ ضغط و كل يتم قياس قراءة و migration مدخل ما زال استخدام إنتاج شفرة. إدخال في حساب وقت قبل كتابة كل مثال هذا وحيد احتلال مؤقت دليل؛benchmark لا استخدام تسجيل صنع Session.

كل Session endpoint كل إبرة مقابل مستخدم دورة الحياة في اثنان عدد وقت نقطة تشغيل.`first-open` الأكثر أول فقط لديه released V0 generation، يتضمن migration؛ فقط قراءة إزالة استهلاك من لا إصدار بعد استمرار ملف، يمكن كتابة Agent resume عندئذ سوف إصدار. اختبار دقيق تجهيز مرحلة مقطع في حساب وقت خارج عبر نفس طقم إنتاج migration توليد مرة `post-upgrade-reopen`، مجددا يأخذ لم تعديل V0 قبل بديل و قد إصدار حالي generation بعد استمرار واحد بدء نسخ إلى كل مثال هذا دليل.Reopen مثال هذا استخدام كل جديد عملية، لذلك قياس كمية مستخدم ترقية إتمام بعد مغناطيس قرص مجددا مرة فتح، لا يتضمن migration أو عملية داخل cache.

كل access kind و endpoint مثال هذا كل في كل جديد، قد تحرير ترجمة Node عملية فرعية في تشغيل. وحدة تحميل،Host خدمة ابتدائي تحويل و fixture دقيق تجهيز في قياس كمية بدء قبل إتمام؛ قياس كمية عملية لا تنفيذ مقدار خارج مسبق حار تحليل. صحيح معتاد كومة نمط تشغيل خمسة عدد مستقل مثال هذا، تقرير إبلاغ الكل مثال هذا و الأكثر صغير قيمة، في موضع عدد و الأكثر كبير قيمة، و بـ في موضع عدد تنفيذ كل وصول حالة مستقل ثابت ميزانية. آخر عدد عملية فرعية استخدام ثابت 128 MB old-space حد أعلى تشغيل نفس مسار، فقط حكم قطع قدرة لا إتمام؛ منخفض كومة حد جذب بدء مقدار خارج GC لا دخول صحيح معتاد وقت أساس خط.

هذا lane يتضمن ثلاثة عدد مستقل Session فتح benchmark، و إبقاء Client fold benchmark:

| Benchmark | يتم قياس مسار | وقت إشارة علامة |
|---|---|---|
| مرحلة مقطع تشريح وجه | قسم آخر لـ first open و post-upgrade reopen تنفيذ حقيقي persistence open،handle read،Session restore و projection | `openMs`،`readMs`،`sessionRestoreMs`،`projectionMs` كل منها استخدام ثابت ميزانية؛ فقط قراءة migration عودة دخول first-open `openMs`؛ بعد استمرار تحرير رمز،verify و publish يخص يمكن كتابة Agent resume |
| أول شاشة تاريخ | اثنان نوع access kind قسم آخر مرور Host Session history controller قراءة إلى أول عدد قسم صفحة snapshot | First open و reopen كل لديه واحد طرف إلى طرف ميزانية؛ متساو يتضمن source stat، قراءة،Session restore،projection، قسم صفحة و snapshot بنية صنع،first open أيضا يتضمن migration؛ اثنان من كل لا يتضمن Gateway شبكة نقل،Client fold أو متصفح paint |
| Agent resume | مقابل اثنان نوع access kind قسم آخر استدعاء `ctx.agents.resume()`، مباشر إلى Agent إنشاء،setup، إصدار و loop بدء إتمام | First open و reopen كل لديه واحد طرف إلى طرف ميزانية؛ اثنان بند مسار كل لا و أول شاشة تاريخ سلسلة سطر، أيضا لا اعتماد هو إبقاء تحت cache |
| Client fold | كبير صغير اثنان عدد v2 history window مرور حقيقي `ConversationNodeAssembler` و الكل Chat Definition fold | كبير نافذة قطعا مقابل وقت و متبادل مقابل صغير نافذة تقليص وضع مقارنة كل منها استخدام ثابت ميزانية |

مرحلة مقطع تشريح وجه صريح استدعاء كل طبقة صحيح صيغة مدخل، لا نسخ decode،migration،restore أو projection حساب قاعدة. أول شاشة تاريخ و Agent resume قسم آخر بـ جديد first-open و reopen أصل دليل تشغيل حقيقي فوق طبقة مدخل، لذلك مكون بيانات لا خطر ملء طرف إلى طرف نتيجة، واحد مشهد أيضا لن إعطاء آخر عدد مشهد مسبق حار عملية أو Session cache. أربعة مرحلة مقطع لـ و فقط لأجل حل تفسير صار هذا؛ أول شاشة و Agent resume طرف إلى طرف وقت كل منها من خارج طبقة وقت ساعة مباشر قياس كمية.

صحيح معتاد كومة نمط في Host ابتدائي تحويل إتمام كما Session بعد لم وصول وقت تنفيذ ثابت اثنان جولة صريح GC، سجل بدء نقطة داخل تخزين؛ عملية حساب وقت انتهاء بعد، في هذا مشهد اشتراط طويل مدة كائن ما زال واضح يمكن بلوغ وقت مجددا مرة تنفيذ نفس مثال GC، مجددا سجل نهاية نقطة داخل تخزين.Agent resume مشهد في نهاية نقطة إبقاء Agent،Session، كامل events و صحيح معتاد خدمة cache، هو `heapUsed` زيادة كمية هو معتاد إقامة Session داخل تخزين ميزانية رئيسي إشارة علامة. كل مشهد معا تقرير إبلاغ `external`،`arrayBuffers`،GC بعد RSS و `process.resourceUsage().maxRSS`؛128 MB نمط متابعة منع توقف لحظة وقت قسم إعداد ذروة قيمة يتم نهاية نقطة GC إخفاء. صريح GC وقت لا حساب دخول عملية وقت.

واحد لا حساب وقت صغير نوع fixture قبل وضع حالة استخدام تحقق حالي migration، رسالة إبقاء،V0 بايت ثابت و بعد استمرار مجددا مرة فتح.Worker فشل وقت إبقاء stderr أول ذيل كل عشرة سطر أو يؤدي أمر كومة خطأ، جعل دقيق تجهيز مرحلة مقطع رفض و ميزانية تجاوز حد يمكن منطقة قسم. حساب وقت صفة قدرة حالة استخدام لا تكرار وظيفة اختبار محتوى تأكيد، فقط اشتراط هدف استدعاء إتمام و وصول مقابل يمكن مراقبة نهاية نقطة.Client fold benchmark متابعة استخدام حقيقي `ConversationNodeAssembler` و الكل Chat Definition، اشتراط كبير نافذة قطعا مقابل وقت و متبادل مقابل صغير نافذة تقليص وضع مقارنة متساو منخفض في ثابت ميزانية.

ميزانية حسب كل قياس كمية نهاية نقطة قسم آخر تدقيق دقيق. اثنان مرة Node 24.19 x64 CI تشغيل في موضع عدد الأكثر كبير متبادل فرق 5.2%؛ ذلك CPU سري تجميع نوع جدار ساعة وقت هو Node 24.18 arm64 مشاركة اعتبار تشغيل 1.95–2.06 ضعف. حذف حالي generation `open` و first-open Agent resume خارج، شفرة المصدر معتاد كمية سجل مشاركة اعتبار آلة جهاز فوق مسبق مدة استهلاك وقت؛`ciTimeBudget()` سوف ذلك ركوب بـ فعلي قياس 2 ضعف CI وقت نظام عدد و 1.25 ضعف موجة حركة بقية كمية. حالي generation `open` استخدام معيار تشغيل جهاز مباشر قياس نيل 50 ms مسبق مدة قيمة، فقط ركوب بـ 1.25 ضعف بقية كمية، نحو فوق أخذ كامل نيل إلى 63 ms ميزانية.First-open Agent resume استخدام مرور مراجعة فحص 562 ms حمل إدارة حد أعلى.GC بعد زيادة كمية كومة و Client fold تقليص وضع ميزانية لا يخص جدار ساعة وقت، لذلك فقط استخدام 1.25 ضعف بقية كمية.128 MB إتمام صفة فحص ما زال هو مستقل لحظة وقت قسم إعداد حد. من هذا نيل إلى first-open وقت حد أعلى، تلقي حد كومة فحص و Client fold حد أعلى كل سوف رفض معروف تراجع تحويل. مشاركة اعتبار ثابت لـ PR #3533 دمج نتيجة، فقط لأجل تدقيق دقيق و مراجعة ميزانية؛CI لا checkout أو تنفيذ تاريخ مستودع. ميزانية هو شفرة المصدر في تلقي مراجعة معتاد كمية، لا من بيئة متغير تغطية.

## تدقيق دقيق دليل

مقارنة مقارنة حسب مستخدم دورة الحياة صحيح تسليم، بينما لا هو حسب ناتج يمثل صحيح تسليم. اثنان نوع تنفيذ first open كل استقبال تماما نفسه ثابت V0 بايت.Reopen وقت، كل نوع تنفيذ كل في كل جديد عملية في قراءة ذاتي ذات إقرار تحديد حالي صيغة: مكدس قبل مشاركة اعتبار إصدار ما زال قراءة V0،V2 تنفيذ فإن قراءة هو قد إصدار V2 بعد استمرار. هذا داخل متعمد مقارنة مقارنة نفس مستخدم لاحق فتح تجربة، بينما لا هو يجعل اثنان عدد codec معالجة نفس نوع بيانات بنية.

نفس منصة Node 24 مشاركة اعتبار آلة جهاز فوق خمسة مرة مثال هذا في موضع عدد بنية صار صحيح عكس مثال:

| Access kind | تنفيذ | أربعة مرحلة مقطع مجموع وقت | أول شاشة تاريخ | Agent resume | Agent GC بعد زيادة كمية كومة | 128 MB old space |
|---|---|---:|---:|---:|---:|---|
| First open | مكدس قبل مشاركة اعتبار إصدار | 249.0 ms | 253.8 ms | 100.7 ms | 26.1 MB | إتمام |
| First open | تكرار snapshot تراجع تحويل تنفيذ | 4,197.5 ms | 4,284.8 ms | 4,197.9 ms | 4.4 MB | كومة استهلاك كل |
| Post-upgrade reopen | مكدس قبل مشاركة اعتبار إصدار | 251.1 ms | 253.8 ms | 100.7 ms | 26.1 MB | إتمام |
| Post-upgrade reopen | تكرار snapshot تراجع تحويل تنفيذ | 49.2 ms | 50.4 ms | 43.8 ms | 4.5 MB | إتمام |

مكدس قبل تنفيذ بـ V0 بصفة حالي صيغة، لذلك first open لا تغيير مغناطيس قرص يمثل؛ هو أصلي V0 أول شاشة تاريخ و Agent resume قياس كمية معا ملائم لأجل اثنان عدد دورة الحياة سطر.

PR #3640 معيار مزدوج CPU تشغيل (run 34023970384, job 101461539961) استخدام Node 24.20.0 x64 و Ubuntu مرآة مثل `20260831.293.1`. حالي generation `open` خمسة مرة مثال هذا لـ 49.2،47.4،49.1،48.6 و 48.1 ms: في موضع عدد 48.6 ms، الأكثر كبير قيمة 49.2 ms. أخذ كامل بعد 50 ms CI مسبق مدة قيمة إعطاء خروج 63 ms حد أعلى، لا تكرار ركوب بـ 2 ضعف آلة جهاز نظام عدد. سجل علامة واضح اثنان عدد متاح CPU، لكن لم سجل نوع رقم؛ هو لا يمكن منطقة قسم صلب عنصر تغير و Node إصدار تغير أثر. هذا هو طرف نقطة مخصص تابع تشغيل جهاز تدقيق دقيق، لا هو تطبيق أفضل تحويل أو مشاركة اعتبار آلة جهاز جديد قياس كمية دليل. أخرى كل بند benchmark متساو عبر قائم ميزانية. تحديد صفة صحيح عكس مثال في تاريخ 30 ms حد أعلى تحت رفض فعلي قياس في موضع عدد، في 63 ms تحت قبول هو، رفض دمج صار 75 ms reopen في موضع عدد، و بـ لم تغيير 550 ms حد أعلى رفض دمج صار 4,000 ms أول مرة فتح استهلاك وقت. هذه صحيح عكس مثال تحقق ميزانية تنفيذ، لا بديل جدول قياس نيل جديد تراجع تحويل.

مرة بارد verifier تحزيم ضبط كامل إزالة وقت التشغيل workspace وحدة تحميل، لم تغيير هذه ميزانية أو قياس كمية نهاية نقطة. في macOS arm64،Node 24.18.0 فوق،verifier تحزيم قبل مقابل نفس نسخة 127,400-event fixture أول مرة writable resume استهلاك وقت لـ 164.2،162.4،159.7،149.3،167.7 ms(في موضع عدد 162.4 ms). عبر workspace build تحزيم verifier بعد لـ 119.8،120.9،121.9،122.3،121.8 ms(في موضع عدد 121.8 ms، خفض منخفض 25%).Retained heap إبقاء 5.4 MB؛peak RSS في موضع عدد من 144.9 تغيير لـ 143.7 MB.Reopen في موضع عدد لـ 27.5 و 27.1 ms، يتضمن 128 MB completion check الكل 16 بند Session حالة استخدام عبر.CPU profile سوف قديم verifier جزء صار هذا عودة بسبب في وحدة تحليل و تحرير ترجمة. عزل package built-worker اختبار في قديم worker فوق بسبب لا يمكن تحليل workspace import بينما فشل، في تحزيم بعد worker فوق عبر، معا تحقق خطأ event count سوف يتم رفض. هذه محلي نتيجة لا يستطيع إثبات Linux runner استهلاك وقت؛ هذه حالة استخدام استخدام 450 ms CI حد أعلى.

حمل إدارة تشغيل (run 34265057987, job 102192211510) يتضمن قد تحزيم verifier،first-open Agent-resume مثال هذا لـ 454.2،454.8،455.4،457.8 و 459.8 ms: في موضع عدد 455.4 ms، تجاوز مرور 450 ms. شفرة انتظار قيمة قبل مرة تشغيل (run 34263062688, job 102185561214) تقرير إبلاغ 436.2 ms في موضع عدد؛ اثنان عدد head بين فقط لديه طلب تاريخ مزدوج لغة README و ذلك إعداد مقابل سجل مختلف. مرور مراجعة فحص حد أعلى لـ 562 ms، أي `floor(450 × 1.25)`، زيادة 24.89%، مقارنة مراقبة قياس إلى 455.4 ms في موضع عدد عال 23.4%. خمسة مرة جديد عملية M4 Pro / Node 24.19 مثال هذا نطاق لـ 150.07–158.22 ms، في موضع عدد لـ 152.57 ms. مرة محدود رئيسي خط مسار profile لم اكتشاف واضح إظهار صغير نوع أفضل تحويل؛ هو لا يتضمن verifier خط مسار CPU، أيضا لا يستطيع إثبات حمل إدارة استهلاك وقت تغير سبب. مقابل وفق في 450 ms تحت رفض قد سجل في موضع عدد، في 562 ms تحت قبول هذا قيمة، و رفض 600 ms.Verifier تحزيم أفضل تحويل، عمل سالب تحميل، أخرى وقت ميزانية، مشترك تقليص وضع و داخل تخزين حد متساو إبقاء ثابت.

## اعتبار مرور بديل خطة

**كل مرة CI checkout تاريخ إيداع و فعل متبادل مقابل مقارنة مقارنة.** رفض: تاريخ checkout حاجة مستقل تثبيت، قديم إصدار و حالي إصدار أيضا ممكن يأخذ عمل وضع في مختلف API مرحلة مقطع، زيادة وقت، اعتماد و واجهة عائم نقل. ثابت workload و مرور صحيح عكس مثال تدقيق دقيق ساكن حالة ميزانية أكثر سعة سهل تكرار الآن و مراجعة.

**فقط قياس من V0 first open.** رفض:migration هو مرة صفة ترقية صار هذا، لا يستطيع منع توقف دخول مستقر حالي generation بعد لاحق فتح حدوث تراجع تحويل. اثنان نوع access kind حاجة مستقل قياس كمية و ميزانية.

**فقط قياس أربعة عدد مكون مرحلة مقطع.** رفض: مكون قياس كمية سهل في تحديد موضع، لكن سوف متروك تسرب source stat، تحرير ترتيب، قسم صفحة و snapshot بنية صنع، أيضا لا يستطيع إثبات أول شاشة مسار كامل جسم ما زال متاح كما كاف كاف سريع.

**فقط قياس أول شاشة أو Agent resume مجموع وقت.** رفض: طرف إلى طرف عدد حرف قدرة حفظ حماية نتيجة، لكن لا يستطيع إشارة خروج تراجع تحويل قدوم ذاتي تخزين، قراءة،Session restore أيضا هو projection؛ أربعة مرحلة مقطع ميزانية إبقاء يمكن عملية عودة بسبب.

**في إنتاج تنفيذ داخلي إضافة دقيق حبة درجة حساب وقت وتد.** رفض: هذه وتد سوف توسيع كبير إنتاج واجهة و يجعل benchmark و تنفيذ دقيق عقدة اقتران دمج. اختبار فقط استخدام قائم خدمة و كائن حد؛ لا يمكن من هذه حد حل تفسير صار هذا إبقاء في طرف إلى طرف نتيجة في.

**من TypeScript شفرة المصدر تشغيل يتم قياس worker.** رفض: شفرة المصدر loader سوف تغيير وحدة تحليل و بدء سلوك، و جعل تضمين طقم worker اختيار فقط ملائم لأجل شفرة المصدر بدء مسار.Vitest ما زال يمكن بصفة لا حساب وقت تحرير ترتيب طبقة؛ كل يتم حساب وقت worker كل مثل صاف Node مستهلك واحد مثال تنفيذ بناء ناتج.

**فقط استخدام وقت ميزانية أو فقط نظر GC بعد داخل تخزين.** رفض: وقت لا يمكن اكتشاف داخل تخزين تراجع تحويل، نهاية نقطة تخزين نشط داخل تخزين أيضا نظر لا إلى ترحيل خلال لحظة وقت انفجار إرسال. صحيح معتاد كومة GC بعد زيادة كمية و تلقي حد كومة إتمام صفة قسم آخر تغطية اثنان صنف ريح خطر.

**استخدام حقيقي تسجيل صنع لغة مادة فعل benchmark.** رفض: لغة مادة fixture حسب سياسة إبقاء صغير جسم كمية، تسجيل صنع مادة مادة لا نيل يصبح benchmark إدخال، كما ذلك إعادة تسجيل صنع سوف ساكن صامت نقل حركة workload.

**يأخذ benchmark وضع دخول قائم gate تجمع دمج في تشغيل.** رفض: تجمع دمج في واحد runner فوق تزامن تشغيل كل gate، جدار ساعة قياس كمية سوف وراثة مجاور إقامة CPU سالب تحميل.

**يأخذ كل عبر حزمة gate وضع في واحد مشاركة و منتج package تحت.** رفض:Session فتح عبر تجاوز persistence،migration،projection،Host history و Agent resume؛ مهمة اختيار واحد مشاركة و جهة كل سوف شكل صار خطأ توجيه صفة ملكية و فقط لـ benchmark زيادة package اعتماد. مستودع درجة دليل يملك تجميع صار مستخدم مسار، حزمة داخل تشخيص ما زال إبقاء في مقابل تنفيذ جانب.

**يأخذ benchmark case وضع في `scripts/` تحت.** رفض:scripts يملك أمر، توليد جهاز و تحرير ترتيب، بينما benchmark case يملك حمل نوع اختبار ملف،worker،fixture، ميزانية و دورة الحياة تنظيف. لم قدوم تقرير إبلاغ أو تدقيق دقيق أمر يمكن إزالة استهلاك `benchmarks/`، لا حاجة يأخذ case نقل دخول منها.

## عاقبة

كل pull request كثير دفع خروج واحد مطلوب Linux job؛ هذا job Session جزء تشغيل كثير عدد قصير دورة الحياة عملية فرعية، بـ تبديل أخذ بارد cache، مستقل V8 heap، واضح GC حالة و يمكن عودة بسبب فشل. مستودع درجة benchmark دليل قبول متعمد عبر حزمة اختبار اعتماد، بينما لا تعديل منتج package manifest. ثابت Zstandard workload معا تغطية حدث قاعدة نموذج و frame توسيع اندفاع؛first-open قياس كمية حفظ حماية مرة صفة ترقية تجربة،reopen قياس كمية منع توقف لاحق فتح تراجع تحويل، أربعة مرحلة مقطع ميزانية تحديد موضع صار هذا ملكية، أول شاشة ميزانية حفظ حماية مستخدم مرئي انتظار،Agent resume ميزانية و GC بعد زيادة كمية حفظ حماية كامل بارد استعادة و معتاد إقامة داخل تخزين،128 MB نمط حفظ حماية لحظة وقت قسم إعداد حد أعلى.

Session و Node-fold مشهد لا قياس كمية شبكة نقل، متصفح تصيير أو حقيقي تسجيل صنع Session، أيضا لا هو حمل متابعة صفة قدرة اتجاه اتجاه نظام.[قبل طرف صفة قدرة ميزانية](2026-09-06-frontend-performance-budgets.ar.md) يملك متصفح سير العمل قياس كمية.Node أو runner تغير حاجة استخدام نفس workload إعادة أخذ مثال و مراجعة ميزانية؛ تعديل عمل خدمة تنفيذ وقت لا نيل ترتيب حمل وضع عرض ميزانية بينما لا توفير جديد صحيح عكس مثال بيانات.
