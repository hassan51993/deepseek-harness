# Agent Note: coverage طقم عنصر داخل حمل إدارة مرآة مثل زائف ضبط

Status: implemented

[English](2026-09-10-hosted-image-test-assumptions.md) | العربية

## مشكلة

[لذا عائق تبديل دعم مسار](../process/2026-09-09-blacksmith-failover-leg.ar.md) سوف يأخذ هذا طقم اختبار ركض في هذا مستودع لا يملك حوض فوق——Blacksmith مؤقت مرآة مثل، و ذاتي لديه `vm-backup` و `dsh-win-ci` تجهيز استخدام حوض. في حمل إدارة مرآة مثل فوق،coverage كل عبر طريق فشل قدوم ذاتي حالة استخدام من لم نقطة واضح مضيف خاصية: مضيف هل توفير متاح مستخدم درجة systemd scope، قرار يتم mock PTY خروج سوف و أي نوع containment تنافس تنازع؛ تلقي إدارة scope في ACP تفكيك إزالة وقت تقرير إبلاغ إشارة فشل؛ قراءة طرف يتم انتزاع احتلال وقت سوف يأخذ غير قاعدة UTF-8 ناقص بقية حالة استخدام زائف تحديد لـ مستقل قسم كتلة كتابة دمج صار واحد قسم كتلة؛ و Windows Server مرآة مثل مباشر رفض `CoCreateInstance(CLSID_FileOpenDialog)`.

## قرار

هذه حالة استخدام واضح إعلان كل منها اعتماد مضيف خاصية.

`packages/subprocess/subprocess-local/tests/local.spec.ts` في نموذج محاكاة PTY خروج حالة استخدام واضح اختيار fallback containment. لا تحقق منصة اختيار حالة استخدام استخدام `internals = { platform: 'darwin' }`. طرفية تحرير دورة الحياة حالة استخدام لا ضبط منصة، و يجعل `probeLinuxNative` إرجاع false، بـ تحقق مضيف افتراضي منصة اختيار، معا تجنب تجنب بدء حقيقي Linux scope. اثنان نوع أمان ترتيب كل تجنب تجنب نموذج محاكاة خروج و scope bootstrap تنافس تنازع. منصة ثابت وقت مجددا mock استكشاف إبرة يخص زائد بقية، لأن ثابت منصة سوف التفاف مرور هذا استكشاف إبرة.

`disposal contains a spawn-failure rejection that races teardown` تأكيد تسوية عقد نحو، بينما لا هو هذا ساحة تنافس تنازع بعض واحد جهة نيل فوز: قد إصدار ذلك pre-exec فشل bootstrap بـ هذا فشل reject، أولا توقف إقامة bootstrap teardown فإن بـ يتم طلب `SIGTERM` تسوية. فقط لديه Linux scope سوف سجل إيقاف هذا واحد دعم، لأن win32 job owner سوف يأخذ يتم إلغاء بدء تحويل صار rejection،fallback بدء جهاز فإن بسبب دليل ناقص بينما reject.

`plugin-config dispose graces reach the real ACP run` إعداد 5000ms dispose عرض حد. هذا حالة استخدام mock حسب تصميم حيث رفض stdin EOF أيضا رفض `SIGTERM`، لذلك حالة استخدام سوف انتظار ممتلئ اثنان عدد عرض حد (نحو 10s) ، و ذاتي حمل 30s حالة استخدام ميزانية، عال في محلي مفرد قياس مدخل منح إعطاء 5000ms قيمة افتراضية. اعتماد هذه عرض حد وقت ما زال سوف حدوث scope إشارة فشل، زيادة عرض حد لا يستطيع إثبات إنهاء اكتمل.[مباشر عملية توقف مستقر قرار](../bug-fix/2026-09-12-linux-scope-direct-kill-settlement.ar.md) قاعدة تحديد fallback kill نجاح أو مستقل إثبات مباشر عملية لا وجود بعد الذي يحتاج عملية حدث و جديد أخذ نيل scope دليل.

`packages/experimental/ptc-runtime-python/tests/runtime.spec.ts` اثنان عدد غير قاعدة UTF-8 ناقص بقية حالة استخدام كل استخدام `time.sleep(0.001)` تحكم كتابة عقدة عزف:`os.sched_yield()` سوف يجعل يتم انتزاع احتلال قراءة طرف يأخذ كثير مرة كتابة دمج صار واحد قسم كتلة، بينما يتم حزمة لف `Buffer.concat` قياس كمية صحيح هو هذا قسم كتلة (في صحيح تأكيد تنفيذ تحت، حمل إدارة مرآة مثل قياس نيل 2563، تجاوز مرور 2048 حد). اثنان عدد حالة استخدام تحميل حمل كل إبقاء في هذا حد لـ فوق——`0xFF` حالة استخدام 3200 بايت،CESU-8 حالة استخدام 1100 عدد `ED A0 80` تسلسل (3300 أصلي بايت، تجاوز مرور حسب أصلي بايت حساب استهلاك سوف لمس و 3072 بايت ميزانية)——لذلك قليل حساب ما زال سوف في 2048 لـ فوق إطلاق flush. اثنان من كل منها حمل لديه 20s حالة استخدام ميزانية، سعة قبول حمل عقدة عزف كتابة و حل تفسير جهاز بدء.

`packages/experimental/ptc-runtime-python/tests/stray-fragments.spec.ts` أصلي إخراج قسم كتلة غلاف تخزين اختبار إبقاء حقيقي Python عملية فرعية، لكن يأخذ stdout قراءة تفكيك صار مفرد بايت حدث. عملية نظام إدارة طريق دمج لا يمكن حفظ إثبات بلوغ إلى غلاف تخزين واحد كتلة الذي يحتاج 1024 عدد قطعة مقطع:run 34465259316 الكل تأكيد عبر، لكن لم تغطية هذا فرع. يمكن تحكم قراءة تغطية عكس تكرار غلاف تخزين و نهاية ذيل تبديل سطر دمج؛ دقيق إخراج و نسخ مجموع كمية حد أعلى فحص قياس بايت فقد فقد و بادئة عكس تكرار نسخ.

Linux coverage عبر طريق منح إعطاء `DSH_COVERAGE_TEST_TIMEOUT_MS: '90000'`، و Windows coverage عبر طريق متسق، لأن عند هذا عبر طريق قسم منطقة،worker و نفس درجة بوابة مشترك استخدام واحد مضيف وقت،`subprocess-local` و `bash-sandbox` موضع وضع حالة استخدام سوف تجاوز مرور 5000ms قيمة افتراضية.

Windows ملف مشبك محادثة إطار خطر دخان اختبار تعديل لـ عبر PowerShell استكشاف قياس `CoCreateInstance(CLSID_FileOpenDialog)`، بينما لم يعد حسب `process.platform` قسم تدفق. عودة جواب `CLASS_E_CLASSNOTAVAILABLE`(0x80040111) مرآة مثل سوف ركض جاف صاف رفض حالة استخدام و قفز مرور حقيقي محادثة إطار حالة استخدام، لذلك `win32-dialog.ts` في لا يوجد يمكن فتح محادثة إطار مضيف فوق ما زال حفظ لديه ملف نسبة التغطية. هذا تنشيط مرور مسار رمي خروج أي استثناء كل حسب رفض حل قراءة، لذلك بسبب ذلك هو سبب استكشاف قياس فشل مضيف فقط سوف فقد ذهاب حقيقي محادثة إطار حالة استخدام؛ تماما لا يمكن تشغيل استكشاف قياس فإن إبقاء win32 زائف ضبط.

## تجهيز اختيار خطة

**يأخذ coverage عبر طريق ترتيب حذف خروج حمل إدارة دعم مسار.** مرفوض: هذا دعم مسار معنى معنى حينئذ هو يأخذ نفس طقم اختبار ركض في آخر عدد حوض فوق، بينما هذه فشل نقطة خروج هو حقيقي مضيف اعتماد، لا هو واحد هذا حوض لا يمكن دعم دعم طقم عنصر.

**فقط رفع عال عبر طريق كل حالة استخدام ميزانية.** مرفوض: أكثر عرض ميزانية تغيير لا ذلك بعض صار هذا أو سلوك تحديد حالة استخدام——يتم trap ACP عملية فرعية ما زال سوف انتظار ممتلئ اثنان عدد عرض حد، يتم دمج قراءة طرف ما زال سوف رفع عال قياس نيل ذروة قيمة.

**معا ثابت منصة و mock استكشاف إبرة.** بسبب زائد بقية بينما مرفوض: ثابت منصة سوف في أصلي استكشاف إبرة يتم استدعاء قبل اختيار fallback. تحقق مضيف افتراضي منصة اختيار اختبار فإن لا ضبط منصة، و تحكم استكشاف إبرة نتيجة.

**تقليل نقص غير قاعدة UTF-8 تحميل حمل بـ يجعل حالة استخدام أكثر سريع.** مرفوض: منخفض في 2048 حد بعد، تأكيد مجددا أيضا لا يمكن لـ هو الذي نقطة اسم قليل حساب بينما فشل، انتظار في يجعل هذا ارتداد فقد ذهاب حراسة حماية.

## عاقبة

تثبيت ميت اختيار fixture تجنب تجنب غير مسبق مدة containment اختيار:`linux-scope` و win32-job اثنان بند مسار ما زال من كل منها مخصص استخدام حالة استخدام تغطية، بينما لا هو مرور من هذه حالة استخدام مقاومة بلوغ.ACP موضع وضع حالة استخدام كل مرة تشغيل نحو 10s جدار ساعة، كل ناقص بقية حالة استخدام نحو 3.5s، أيضا يحتاج إضافة فوق مضيف ضبط درجة و أصلي تنظيف مقدار خارج فتح إلغاء. حمل إدارة مرآة مثل دليل:run 34449848541 في هذه حالة استخدام فوق فشل،run 34457655892 في هذا تعديل إضافة 90000ms عبر طريق ميزانية تحت تحويل أخضر،`windows node 24 / coverage` في وصل متابعة خمسة مرة حمل إدارة تشغيل في لـ أخضر، منها استكشاف إبرة تقرير إبلاغ رفض (`clsid-probe=refused`).
