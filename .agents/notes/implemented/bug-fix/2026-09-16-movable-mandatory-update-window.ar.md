# Agent Note: يمكن نقل حركة قوي أكثر نافذة

Status: implemented

[English](2026-09-16-movable-mandatory-update-window.md) | العربية

## Problem

Windows قوي أكثر صفحة أصل أولا استخدام و منتج نافذة انتظار كبير بلا حافة إطار نموذج حالة تغطية طبقة. نموذج حالة نافذة منع استخدام أب نافذة، لذلك لا يمكن استخدام أب نافذة أصلي عنوان شريط نقل حركة أو الأكثر كبير تحويل نافذة. تغطية طبقة إغلاق عملية أيضا يتم اعتراض قطع، واجهة فوق لا يوجد متاح خروج تحكم عنصر.

## Decision

في Windows فوق، قوي أكثر سياسة استخدام مستقل أصلي لديه حافة إطار نموذج حالة نافذة، دعم حمل نقل حركة، ضبط كامل كبير صغير و الأكثر كبير تحويل. سياسة منع سد خلال أب نافذة ما زال غير ممكن عملية. إغلاق نموذج حالة نافذة سوف طلب تطبيق صحيح معتاد خروج، لن إلغاء سياسة و استعادة منتج نافذة. أخرى منصة إبقاء قائم تغطية طبقة عرض.[قوي أكثر قرار](../feature/2026-09-11-desktop-mandatory-update-client.ar.md) ما زال مسؤول سياسة و تثبيت تخويل.

## Alternatives considered

**إبقاء تغطية كامل محتوى منطقة مجال نافذة و إضافة سحب حركة منطقة مجال.** سحب حركة منطقة مجال فقط قدرة بين وصل نقل حركة يتم منع استخدام أب نافذة، أيضا لا يمكن استعادة أصلي الأكثر كبير تحويل و إغلاق تحكم عنصر.

**سماح إغلاق وقت مباشر إلغاء سياسة صفحة.** هذا مثال سوف في لم أخذ نيل جديد بلا حاجة قوي أكثر استجابة وقت كشف يتم منع سد منتج نافذة.

## Consequences

Windows مستخدم يمكن نقل حركة أو الأكثر كبير تحويل تحديث نافذة، أيضا يمكن عبر إغلاق حسب زر خروج تطبيق. نموذج حالة منع سد و ثاني مرة تثبيت دفعة دقيق إبقاء ثابت. تثبيت جهاز وصل إدارة خروج وقت، قشرة سوف في Electron إغلاق نافذة قبل تحرير نموذج حالة نافذة، تجنب تجنب إغلاق اعتراض قطع منع توقف تثبيت.Windows فوق أصلي حافة إطار يحل محل حجب غطاء كامل محتوى منطقة مجال تغطية طبقة؛ معتاد قاعدة تحديث نابض نافذة ما زال استخدام أصل لديه تغطية طبقة.
