# Agent Note: لا استخدام ثابت طويل درجة غير حمل إدارة عرض قراءة Win32 اختيار جهاز مسار

Status: implemented

[English](2026-08-31-win32-picker-path-string-read.md) | العربية

## Problem

Win32 اختيار جهاز حاجة حل رمز `IShellItem::GetDisplayName` قسم إعداد NUL ربط ذيل UTF-16 نص، و عبر `CoTaskMemFree` تحرير هو. ثابت طويل درجة خارجي ArrayBuffer زيادة وقت التشغيل اشتراط و يد عمل إنهاء رمز مسح، لكن لا يستطيع توفير فعلي قسم إعداد كبير صغير.

## Decision

`readUtf16` سوف أصلي عنوان تخزين دخول إشارة إبرة عرض درجة مؤقت اندفاع منطقة، مجددا تسليم إعطاء عام `koffi.decode(buffer, 'str16')`. عام حل رمز حاجة إشارة إبرة متغير، بينما غير مباشر نقل دخول نص عنوان. مقتطعة طويل درجة أخذ ذاتي `koffi.sizeof('void *')`؛Koffi 3 استخدام BigInt يمثل أصلي عنوان. حل رمز خلال قسم إعداد يجب إبقاء صالح كما بـ NUL ربط ذيل. تحويل نجاح بعد، أصلي عنوان ما زال يمكن تسليم إعطاء `CoTaskMemFree`؛ إذا حل رمز رمي خطأ، نص لن يتم تحرير.

## Alternatives considered

**خارجي عرض إضافة يد عمل مسح.** هذا اشتراط وقت التشغيل دعم حمل خارجي مؤقت اندفاع منطقة، و تكرار تنفيذ Koffi نص تحويل. ثابت عرض و تمرير زيادة قسم كتلة كل لا يمكن تحديد أصلي قسم إعداد كبير صغير.

**نص نوع خروج مشاركة.** `_Out_ str16 *` إرجاع نص، لكن فقد فقد صريح COM تحرير الذي يحتاج إشارة إبرة. داخل وضع `str16!` استخدام CRT قسم إعداد جهاز تحرير، بينما غير COM قسم إعداد جهاز.

**ذاتي تعريف يمكن تحرير نوع.** Koffi يمكن تحرير نوع يمكن استدعاء `CoTaskMemFree`، لكن صريح تحويل بلا حاجة تسجيل أصلي نوع، حينئذ قدرة سوف عنوان و تحرير إبقاء في نفس استدعاء نقطة.

## Consequences

حقيقي Koffi اختبار استخدام تخزين نشط UTF-16 مؤقت اندفاع منطقة تنفيذ إنتاج نتيجة مسار تحويل، شمول غطاء U+5F00، بديل إدارة مقابل،NUL إنهاء و تجاوز مرور 32 KiB نص. مستقل أربعة بايت و ثمانية بايت BigInt حالة استخدام تحقق إشارة إبرة إبقاء كامل، و تحرير أصلي عنوان. اختبار يحتفظ مؤقت اندفاع منطقة في تزامن قراءة خلال إبقاء تخزين نشط؛ أصلي حل مرجع قبل سوف فحص إشارة إبرة بايت. هذا قبل مسح قرار إبقاء في[عودة ملف سجل](../../archived/bug-fix/2026-08-23-win32-utf16-nul-truncation.md) في.
