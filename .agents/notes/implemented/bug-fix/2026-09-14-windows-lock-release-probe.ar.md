# Agent Note: Windows قفل في تنافس تنازع استكشاف قياس قبل تحرير

Status: implemented

[English](2026-09-14-windows-lock-release-probe.md) | العربية

## مشكلة

Windows وحيد احتلال إنشاء ملف وقت، إذا آخر كتابة جهة يحتفظ قفل، ممكن تقرير إبلاغ `EPERM`. حمل قفل جهة ممكن في تنافس تنازع من تنفيذ `lstat` قبل حذف قفل، لذلك بعد مراقبة إلى قفل لا وجود، و لا يستطيع إثبات إنشاء فشل مصدر في حمل متابعة إذن حد.profile وحدة رجوع تنافس تنازع اختبار كشف هذا واحد تنافس حالة.

## قرار

`withFileLock` في كل مرة Windows نيل أخذ قفل مرور مسار في سماح مقابل لا يمكن تأكيد قفل وجود `EPERM` إعادة محاولة مرة، امتداد استخدام قائم تراجع تجنب و قطع توقف وقت. تأكيد وجود تنافس تنازع ما زال صحيح معتاد انتظار. ثاني مرة لا يمكن تأكيد قفل وجود إذن فشل سوف إعادة رمي خروج، كما فقط لديه وحيد احتلال إنشاء نجاح بعد عندئذ سوف تشغيل تلقي حفظ حماية عملية.

## اعتبار مرور بديل خطة

مقابل كل إذن خطأ واحد مباشر إعادة محاولة إلى مهلة سوف إخفاء غطاء حمل متابعة إذن فشل. اشتراط قفل في بعد استكشاف قياس وقت ما زال وجود سوف رفض دمج قاعدة تحرير تنافس حالة. تأخير متأخر اختبار في حمل قفل جهة تحرير فقط تغيير وقت ترتيب، لا يمكن إصلاح كتابة بروتوكول.

## عاقبة

Windows حمل متابعة إذن فشل ممكن في مرة تراجع تجنب بعد عندئذ تقرير إبلاغ.POSIX سلوك ثابت.atomic-write اختبار قوي صنع في استكشاف قياس قبل تحرير قفل، و تحقق نجاح نيل أخذ قفل و حمل متابعة إذن فشل؛profile اختبار تغطية حقيقي تنافس تنازع كتابة جهة. قائم اعتماد تسجيل قلم تسجيل ما زال مسؤول كتابة سلسلة سطر تحويل قرار، لن يتم هذا نيل أخذ قفل قاعدة يحل محل.
