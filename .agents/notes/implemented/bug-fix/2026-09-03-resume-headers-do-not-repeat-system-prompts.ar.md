# Agent Note: Resume header لا تكرار توجيه النظام

Status: implemented

[English](2026-09-03-resume-headers-do-not-repeat-system-prompts.md) | العربية

## مشكلة

fork Session سوف يأخذ مصدر جلسة تاريخ نسخ إلى فرعي جلسة. أي جعل system حقل و قبل واحد بند يتم نسخ header تماما نفسه، فرعي جلسة رقم واحد نموذج طلب ما زال سوف سجل واحد بند reason لـ `resume` `request/header`.Chat يأخذ كل بند resume header كل نظر عمل جديد عرض نقطة، لذلك متابعة fork سوف عرض ثاني سطر`توجيه النظام`، يجعل شخص خطأ بـ لـ توجيه النظام يتم حقن اثنان مرة. مزود طلب فعلي ما زال فقط يحمل مرة system حقل؛ تكرار فقط وجود في Chat عرض في.

## قرار

حفظ دائم resume header سجل دقيق إعادة بناء Session الذي يحتاج طلب حد.Chat سوف يأخذ كامل header و قبل واحد بند قد تحميل Request Prompt مقارنة مقارنة، فقط في ابتدائي طلب، صريح رسالة تسلسل بدء نقطة أو حقيقي system حقل تغير وقت عرض غير فارغ توجيه النظام. محتوى لم تغيير resume لا إنشاء مرئي تكرار سطر.

جزء تاريخ نافذة ممكن بـ غير ابتدائي header فتح رأس، بسبب نقص قليل قبل ترتيب header بينما لا يمكن مقارنة مقارنة.Chat سوف حفظ حراسة تصيير هذا توجيه النظام. إذا prepend مع بعد تكملة دخول نفسه قبل ترتيب header، قائم request-prompt Node سوف تحويل لـ إخفاء بينما لا هو يتم سحب عودة؛ ذلك key و صفحة دورة الحياة داخل anchor إبقاء مستقر. مختلف system حقل ما زال مرئي.

Trajectory سوف عرض كل واحد بند طلب header و ذلك تغير تصنيف.Chat عرض لن تغيير مزود طلب،Session event أو إعادة بناء سلوك.

## اعتبار مرور بديل خطة

**من Session log حذف لم تغير resume header.** مرفوض:resume هو حقيقي طلب حد، إزالة بعد دقيق إعادة بناء سوف اعتماد حمل دائم سجل لم سجل عملية تاريخ.

**فقط مقابل fork Session فعل خاص خاص معالجة.** مرفوض: عادي عملية استعادة أداة لديه نفسه عرض دلالة، طلب header قد يتضمن يمكن مباشر مقارنة مقارنة system حقل.

**يأخذ تكرار سطر إبقاء لـ دورة الحياة علامة.** مرفوض:`توجيه النظام`وصف نموذج مرئي طلب محتوى، استخدام هو علامة loop إعادة بدء سوف خطأ داكن عرض مجددا مرة حقن نص التوجيه. طلب دورة الحياة دليل ما زال يمكن في Trajectory في عرض.

## عاقبة

متابعة fork أو في system حقل لم تغيير وقت استعادة عملية، حالي رسالة تسلسل فقط إبقاء واحد سطر مرئي`توجيه النظام`. صريح تسلسل بدء نقطة و حقيقي system تغير ما زال سوف تكرار هذا سطر. جزء نافذة بدء أول يمكن عرض حفظ حراسة سطر، و في أكثر مبكر تاريخ تحميل بعد سوف ذلك إخفاء، معا إبقاء نفس عدد قد شيء تحويل Node.

وحدة ارتداد تغطية ابتدائي طلب، صريح تسلسل، لم تغير resume،system تغير و prepend مشهد.Web تسجيل صنع جلسة مشهد يتضمن واحد بند لم تغير resume header، و تأكيد مستقر بعد Chat فقط تصيير واحد`توجيه النظام`تحكم عنصر.
