# Agent Note: من حمل دائم Inbox حالة استعادة Web Queue

Status: implemented

[English](2026-08-17-durable-web-queue-recovery.md) | العربية

## مشكلة

Inbox قبول رسالة وقت سوف سجل مواصفة تحويل `agent/inbox/spliced` حدث، لكن Web Queue استخدام آخر نسخة عبر قطعة رفع live Agent بناء mux أساس خط.Host عملية إعادة بدء بعد، حفظ دائم عادي Session سوف إبقاء بارد حالة، مباشر إلى بعض بند عملية حاجة ذلك Agent، لذلك live-only أساس خط سوف متروك تسرب ما زال وجود في حمل دائم سجل في قد قبول انتظار معالجة رسالة.

فقط إصلاح إعادة وصل منطق ما زال سوف إبقاء اثنان طقم استعادة تنفيذ: واحد طقم لأجل live Inbox، آخر طقم لأجل Web بارد قراءة. صحيح تأكيد كل من هو Inbox مجال، بينما جلسة إسقاط إطار هيكل قد توفير live قيادة، بارد طي، إعادة وصل أساس خط و ذاكرة مؤقتة استعادة.

## قرار

تركيب Session projection registry وقت،`AgentLoop` في خدمة تنشيط وقت تسجيل معيار `inbox` إسقاط، جعل بارد Session بلا حاجة live Agent يكفي قراءة.[Inbox إقرار قيادة دورة الحياة](../architecture/2026-07-31-claimed-pre-step-inbox-lifecycle.zh.md) تعريف splice مواصفة تحويل، رسالة وحيد صفة،live إشعار و حمل دائم إعادة بناء. إسقاط مشترك استخدام واحد نسخة schema و `InboxState` تعريف؛ رسالة قيمة اعتماد قائم نوع تحويل `UserMessage` اتفاق، بينما لا زيادة ثاني طقم وقت التشغيل رسالة تحقق جهاز.

سجل التسجيل في `Session.append()` إرجاع قبل طي قد إيداع splice؛ كل Agent `ReactLoopInbox` أمر facade كل قراءة نفس نسخة live حالة، بينما لا آخر سطر صيانة طي حالة.

عام جلسة إسقاط نقل طبقة هو وحيد Web نقل. هو إرسال seq أكثر عال `session/projection` قيمة، في كل مرة `session.follow` بدء بداية لقطة في يتضمن كامل values كتلة، طي قد قسم مغادرة بارد سجل، و في ذاكرة مؤقتة صالح وقت استخدام إسقاط ذاكرة مؤقتة. نظام لا وجود Host يملك `queue` إسقاط،placement مفردات،handoff قائمة، مخصص استخدام queue لقطة أو قطعة رفع live Agent إعادة وصل منطق.

مقابل قد حينئذ خيط Host generation تزامن حجز قراءة سوف أولا إسقاط كل إبقاء إسقاط قيمة و ذلك ماء موضع، مجددا تحديث جديد استعلام و إعادة فتح control stream، منها أيضا يشمل عملية محلي control baseline في لا يوجد صف خروج بارد Session. أول مرة control stream سوف انتظار generation حينئذ خيط؛baseline لن أولا في قديم حالة تنظيف وصول، مجددا يتم مقارنة متأخر Cordis `connection/reset` إشعار صاف حذف.Observable face إبقاء ذاته معرف و حجز قراءة. مقارنة مبكر generation list طلب لا يستطيع إصدار قيمة أو جعل حالي طلب انتهاء، لذلك جديد generation تاريخ و list قيمة يمكن بناء قيام مقارنة منخفض حمل دائم seq، بينما لن يتم بعد لم حفظ دائم حالة حجب إقامة. نفس generation داخل، كل استلام إلى baseline كل التزام دوران مقارنة عال seq أولوية، لذلك تأخير متأخر وصول control baseline لا يستطيع حذف أو تغطية مقارنة جديد list أو history قيمة.

عميل Session binding في عام تدريجي جلسة إسقاط تخزين في إبقاء `inbox`، لن يأخذ هو نسخ دخول `SessionSnapshot`.QueueDock مباشر قراءة `next-turn`.ChatView مباشر قراءة مستخدم مصدر `next-step` رسالة، و تجاهل اختصار حقن سياق. إقرار قيادة عملية عبر حمل دائم splice إزالة انتظار معالجة قيمة؛ لاحق `user/message` من عادي جلسة إسقاط تصيير.

`session.updateQueue` في تعديل Inbox قبل عبر مشترك Agent محلل تحليل عادي بارد Session. لذلك، استعادة خروج انتظار معالجة سطر في إعادة بدء بعد ما زال يمكن تحرير، إزالة أو steering، بينما subagent ownership إبقاء و أخرى Agent عملية نفسه fence.

نظام لا يوجد جذب دخول جديد جلسة حدث أو مغناطيس قرص صيغة. قائم splice تدفق ما زال هو حمل دائم حق مصدر.

## تحقق

Host إسقاط تغطية سوف قراءة يتضمن انتظار معالجة إدخال قد قسم مغادرة حمل دائم Session، في `session.follow` بدء بداية لقطة في إرجاع `values.inbox`، و إثبات لا حاجة live Agent. بارد عملية تغطية إثبات `session.updateQueue` سوف استعادة Session و إلحاق حمل دائم حذف splice.

عميل تغطية ثابت عام Inbox إسقاط إلقاء تمرير، إعادة وصل وقت تنظيف متروك تسرب بارد Session قديم قيمة، أساس خط اثنان نوع وصول ترتيب، مرور مدة list طلب نتيجة،Session نسخة تحويل قبل إبقاء seq أكثر عال قيمة، و `SessionSnapshot` لا يحتوي queue حالة.UI تغطية ثابت QueueDock مباشر تصيير `next-turn`، و ChatView تصيير مستخدم مصدر `next-step`. بلا مفتاح Web fixture سوف فتح واحد نسخة بارد حمل دائم Session، و في إعادة بدء بعد مراقبة ذلك انتظار معالجة سطر.

## اعتبار مرور بديل خطة

**يأخذ بارد Session إضافة دخول قديم queue إعادة وصل حلقة.** غير مقبول، لأن هذا سوف تكرار إسقاط سجل التسجيل بارد طي، و يجعل فوري دفع إرسال، تاريخ، ذاكرة مؤقتة و إعادة وصل متابعة استخدام مختلف تنفيذ.

**في Session Controller تسجيل Web مخصص تابع `queue` إسقاط.** غير مقبول، لأن انتظار معالجة إدخال يخص Inbox.placement سطر و handoff قائمة سوف فقط لـ واحد عميل جذب دخول ثاني طقم مجال نموذج.

**في كل بند splice حدث في حفظ كامل Inbox لقطة.** غير مقبول، لأن حمل دائم حدث هو مواصفة تحويل تغيير، لا هو تكرار تجمع دمج. تجمع دمج إعادة بناء و checkpoint يخص إسقاط إطار هيكل.

**في عميل أصل حسب أصلي جلسة حدث إعادة بناء Inbox.** غير مقبول، لأن قسم صفحة ممكن حذف بناء قيام حالي حالة إدراج دخول حدث، كل عميل أيضا سوف تكرار تنفيذ splice دلالة.

**فتح mux تدفق وقت استعادة كل بارد Agent.** غير مقبول، لأن عرض حمل دائم حالة لا ينبغي إصدار وقت التشغيل مورد، تركيب preset أو بدء دورة الحياة عمل.

## عاقبة

انتظار معالجة Queue و steering إدخال يمكن في Host عملية إعادة بدء بعد استعادة، بينما بلا حاجة استعادة Agent.live Inbox قراءة، بارد تاريخ، إعادة وصل و إسقاط ذاكرة مؤقتة استخدام نفس نسخة مجال يملك طي و سجل التسجيل حالة. عملية استعادة خروج سطر وقت سوف استعادة ذلك عادي Agent، من بينما إبقاء preset تركيب و كل حق فحص.

عميل استقبال أصلي اثنان قائمة Inbox قيمة، و ذاتي سطر قرار واجهة عرض أي بعض رسالة. إسقاط حالة إصدار سوف في ذلك تسلسل تحويل حالة أو طي دلالة تغير وقت جعل ذاكرة مؤقتة سطر بطلان.
