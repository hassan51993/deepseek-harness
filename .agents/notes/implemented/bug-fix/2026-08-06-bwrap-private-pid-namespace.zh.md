# Agent Note: سوف bwrap و مضيف PID نطاق الأسماء عزل

Status: implemented

[English](2026-08-06-bwrap-private-pid-namespace.md) | العربية

## مشكلة

bwrap خلفية تركيب كل جديد `/proc`، لكن إبقاء مضيف PID نطاق الأسماء. لذلك، تلقي قيد أمر يمكن يرى مضيف عملية، و امتداد `/proc/<pid>/root`،`/proc/<pid>/fd`،`/proc/<pid>/cwd` انتظار procfs سحر قاعدة رابط دخول مضيف عملية تركيب عرض. عند وصول تحكم سماح تتبع مع منها بعض بند رابط وقت، هذا مسار سهل يمكن تجاوز مرور profile مقابل مضيف أصل دليل فقط قراءة ربط تركيب، و `workspace-write` allow-list. مضيف ptrace حد لديه وقت سوف منع قطع هذا مسار، لكن هذا صنف أخذ قرار في نشر بيئة إذن و لا بنية صار قيد حد.

الأكثر أول[صندوق رملي قرار](../feature/2026-07-06-sandbox.zh.md) متعمد صيانة حمل عملية مرئي صفة ثابت، لأن `SandboxMode` تحمل وعد هو ملف أثر، بينما لا هو واحد عام صفة عملية عزل. مقابل bwrap بينما قول،procfs سحر قاعدة رابط جعل مضيف عملية مرئي صفة يصبح ملف أثر حد واحد جزء، لذلك هذا اختيار لا يمكن صيانة حمل هذه نمط تحمل وعد حد.

## قرار

كل bwrap profile كل استخدام `--unshare-pid`، و لـ هذا خاص نطاق الأسماء تركيب `/proc`. تلقي قيد أمر يمكن مراقبة و تحكم ذاتي ذات بعد بديل عملية، لكن مضيف عملية و ذلك procfs سحر قاعدة رابط لن ظهور.Bubblewrap توفير هذا نطاق الأسماء PID 1 عملية، لأجل عودة استلام بعد بديل عملية.

bwrap وظيفة استكشاف قياس و فعلي حزمة تركيب استخدام نفس عدد profile builder. لذلك، لا يمكن إنشاء PID نطاق الأسماء مضيف سوف في اختيار مرحلة مقطع رفض bwrap و رجوع إلى Landlock، بينما لا هو يجعل مقارنة ضعيف استكشاف قياس عبر، مع بعد عندئذ فشل.

هذا هو bwrap خلفية ثابت صيغة، لا هو `SandboxMode` جديد تحمل وعد.Landlock و Seatbelt ما زال إبقاء عملية مرئي صفة ثابت، كما لا يوجد خلفية حد شبكة شبكة وصول.

## سبق اعتبار بديل خطة

- **في إبقاء مضيف عملية مرئي صفة معا شاشة حجب جزء procfs رابط.** كل عملية بند كل سوف حركة حالة تغير، فقط تغطية `root` ما زال سوف إبقاء تحت يمكن عبر `fd`،`cwd`،`exe` و لم قدوم سحر قاعدة رابط إجراء انتظار فاعلية تجاوز حد مسار. منع توقف قائمة لا يمكن بناء قيام هذا حد.
- **اعتماد ptrace و procfs كل حق فحص.** ذلك سلوك أخذ قرار في داخل نواة ضبط، حاوية إعداد، عملية اعتماد، و عملية هل يمكن تحويل تخزين. نفس مستخدم عملية ممكن ما زال يمكن وصول، لذلك هذه فحص فقط يخص رأسي عميق منع صد، لا يستطيع يحل محل من profile بناء قيام مرجعي حد.
- **تماما إزالة `/proc`.** معتاد قاعدة عملية أداة و بعد بديل عملية إدارة اعتماد procfs. خاص PID نطاق الأسماء إعداد دمج مقابل procfs، حيث قدرة إبقاء هذه آلية، أيضا لن كشف مضيف عملية.

## تحقق

profile اختبار وحدة ثابت اثنان عدد تلقي قيد نمط متساو إلغاء مشترك PID نطاق الأسماء. حقيقي bwrap اختبار تحقق: اثنان عدد نمط تقرير إبلاغ PID نطاق الأسماء معرف كل و harness مختلف، رفض عبر `/proc/1/root` كتابة، تأكيد حفظ مضيف هدف ملف ما زال لا وجود، معا ما زال سماح أمر مراقبة، إنهاء و انتظار ذاتي ذات بعد بديل عملية.

## عاقبة

- تلقي bwrap قيد أمر لا يمكن مجددا فحص مضيف عملية أو نحو ذلك إرسال إشارة، يشمل نفس مستخدم عملية.
- `read-only` و `workspace-write` بلا حاجة مجددا اعتماد مضيف procfs وصول سياسة قدوم منع توقف التفاف مرور تركيب profile.
- لا يمكن استخدام PID نطاق الأسماء مضيف سوف عبر قائم فشل إغلاق مرحلة سلم، اختيار تحت واحد تلقي دعم حمل Linux خلفية.
- هذا مرة تغيير هو داخل نواة قيد حفظ إثبات، لا هو نموذج مرئي إخراج، بروتوكول أو transcript(نص سجل) محتوى؛ لذلك، حقيقي خلفية e2e هو تجميع تطبيق تحقق استلام مسار، بلا حاجة تعديل لقطة.
