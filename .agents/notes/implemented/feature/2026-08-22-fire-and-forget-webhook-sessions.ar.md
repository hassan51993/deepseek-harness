# Agent Note: Fire-and-forget webhook Session

Status: implemented

[English](2026-08-22-fire-and-forget-webhook-sessions.md) | العربية

## Problem

خارجي مستودع حدث حاجة بدء عادي DSH عمل، معا لا يستطيع يجعل كل مزود مهايئ كل إدارة حل Agent preset،Workspace مرفق إضافة، عنوان، إذن و عودة ضبط teardown.GitHub pull request تغيير لـ ready for review هو رقم واحد استخدام طريق: توقيع حدث يمكن إنشاء واحد مراجعة Session، مستخدم قدرة في مستودع Workspace تحت تصفح هو.

إذا يأخذ هو تغيير صار حمل دائم تلقائي تحويل جذب محرك، حينئذ سوف في Session جانب جذب دخول ثاني طقم دورة الحياة: تسليم سجل، تنفيذ حالة، إعادة محاولة و ذهاب إعادة سياسة، انهيار انهيار استعادة، و HTTP قبول، نص التوجيه وصل قبول،Agent idle أو نموذج إخراج في بحث فعلا أي عدد يمثل إتمام. الذي طلب قدرة لا حاجة منها أي يحتوي معنى.

## Decision

`@deepseek-ai/dsh-webhook` يملك فقط لديه اثنان عدد عملية Host runtime: قاعدة عبر `register()` تسجيل، قد تحقق هوية مزود مهايئ استدعاء `dispatch()`. كل مطابقة عودة ضبط كل بصفة مهمة معنى تلقي معلومة مهمة شفرة مستقل تشغيل، و إرجاع `null` أو واحد أساس في Workspace Session طلب.dispatch سوف في عودة ضبط تسوية قبل إرجاع، بينما effect disposer فقط في توقف و ترتيب فارغ ذاتي ذات يملك استدعاء.

runtime لا تخزين مزود تسليم أو تنفيذ سجل. هو لا إعادة محاولة، لا ذهاب إعادة، لا استعادة عودة ضبط عمل، لا مراقبة Agent حالة، أيضا لا استلام تجميع نتيجة. تكرار تسليم ممكن إنشاء آخر عدد Session.`WebhookDeliveryId` ما زال يمكن توفير متعمد عبر ذاتي لديه حالة تنفيذ قوة انتظار صفة قاعدة استخدام.

## Provider adapters

هوية تحقق يخص مزود مهايئ.`@deepseek-ai/dsh-webhook-github` سوف في حقن WebServer فوق تسجيل واحد بند دقيق توجيه، حد لم تعديل UTF-8 body، لـ كل مرة طلب تحليل مفتاح مرجع، في تحليل قبل تحقق `X-Hub-Signature-256`، و يأخذ توقيع بلا ضرر JSON كائن تسليم إعطاء runtime.`202` فقط يمثل قد تحقق داخل تخزين توزيع؛ هو أولا في قاعدة مطابقة، خارجي استدعاء و Session إنشاء.

عادي Web تركيب إبقاء ذلك UI/API WebServer مستقل.GitHub عرض مثال سوف يأخذ آخر عدد WebServer و ذلك مهايئ تركيب إلى فقط عزل `webServer` group في، لذلك عكس نحو بديل إدارة يمكن كشف webhook طرف فتحة، بينما لا كشف `/api`،WebSocket أو قبل طرف ملف.

Patch تحميل سوف يأخذ إدراج دخول سطر في متبادل مقابل إضافة اسم مرساة تحديد إلى patch ملف. بسبب بينما نفس عدد `./github-ready-review-rule.mjs` بند حيث متاح في تطوير بيئة `--patch` overlay، أيضا متاح في دائم دائم profile patch، بينما بلا حاجة يأخذ قاعدة تعديل صار لين عنصر حزمة.

## Session creation

قاعدة نتيجة سوف إشارة تحديد محلي Workspace مسار، عنوان، نص نص التوجيه،agent preset،permission preset، و اختياري واضح مزود/نموذج توجيه و إخراج حد أعلى. لا يوجد واضح توجيه وقت،runtime سوف لقطة يتضمن دفع إدارة قوي درجة كامل فوري افتراضي اختيار، مباشر إلى أول عدد طلب سجل ذلك حمل دائم header.runtime سوف في تغيير حالة قبل تحقق preset، تحليل أو إنشاء مواصفة Workspace، بـ هذا مسار بصفة Session cwd إنشاء Agent، في إصدار قبل تركيب preset، و في وصل قبول نص التوجيه قبل مرفق إضافة Session.

ابتدائي follow-up هو عادي حمل دائم user-role رسالة، و يحمل webhook مزود، مصدر، تسليم و قاعدة مصدر معلومة. هو inbox إدراج دخول هو webhook عملية الأكثر بعد حد. بعد عمل من عادي Session persistence و Agent دورة الحياة يملك؛runtime حيث لا تنفيذ خاص خاص flush، أيضا لا انتظار جولة.

## Alternatives considered

**حفظ دائم تسليم و تنفيذ حالة.** مرفوض، لأن `pending`،`admitted`،`running` و `settled` حاجة حالي قدرة لا يوجد مستهلك إعادة محاولة، ذهاب إعادة، انهيار انهيار و إتمام دلالة.

**في Session إنشاء بعد مجددا نحو GitHub تأكيد.** مرفوض، لأن مهمة معنى قاعدة ممكن استدعاء خارجي نظام و تجاوز مرور مزود HTTP وقت نافذة؛ صالح تسليم لا ينبغي يأخذ نقل متاح صفة و لاحق قاعدة عمل اقتران دمج.

**في رئيسي WebServer فوق تسجيل توجيه.** مرفوض، لأن عملية من حاجة كشف webhook مدخل بينما مختلف وقت كشف متصفح API. عزل ثاني عدد نسخة سوف إعادة استخدام قائم HTTP وحدة، بينما لن إنشاء آخر طقم خادم تنفيذ.

**يأخذ قاعدة حد لـ إعلان صيغة يسمى كلمة لغة.** مرفوض، لأن برنامج تحويل قاعدة واضح حاجة مهمة معنى خارجي استدعاء. تلقي معلومة مهمة Cordis إضافة قد توفير الذي يحتاج إذن و دورة الحياة.

**يجعل كل مهايئ مباشر إنشاء Session.** مرفوض، لأن Workspace،preset، إذن، عنوان،rollback و مصدر معلومة منطق سوف تفرق نشر إلى كل مزود حزمة.

## Verification

حزمة درجة اختبار ثابت مستقل عودة ضبط تنفيذ،fire-and-forget HTTP وقت ترتيب، إلغاء و ساكن توقف حالة تحرير، طلب تحقق، نص التوجيه وصل قبول قبل Workspace مرفق إضافة،rollback،GitHub HMAC و body حد، اعتماد جولة تبديل و دقيق Loader تركيب. تجميع Web عرض مثال سوف نحو عزل ثاني مستمع إرسال توقيع ready-for-review تسليم، و سجل الذي نيل عادي Workspace محادثة.

حقيقي API e2e اختبار سوف عبر حمل webhook overlay و عزل مستمع بناء ناتج بدء `dsh web` CLI(أمر سطر واجهة) ، فقط دمج صار حمل توقيع دخول محطة GitHub تسليم، عبر عام Web API مراقبة Workspace مرفق إضافة و حمل دائم مصدر معلومة، و انتظار حقيقي DeepSeek استجابة. اختبار لن استخدام test double استبدال أي DSH خدمة، نموذج مهايئ أو مزود استدعاء.

شفرة المصدر مراجعة حساب سوف إبقاء تنفيذ سجل، إعادة محاولة timer، ذهاب إعادة map، إتمام حدث و Agent حالة مستمع لا وجود.

## Consequences

- مزود مهايئ إبقاء صغير بينما كما فقط يحتوي مزود منطق،Session إنشاء فقط لديه واحد owner.
- مستخدم في Web Workspace تحت نيل نيل عادي حمل عنوان Session، بينما لا هو ثاني طقم تلقائي تحويل UI.
- HTTP نجاح لحظة معنى لا شرح تحت تنقل مطابقة أو Agent نجاح.
- انهيار انهيار و تكرار تسليم إبقاء بسيط مفرد عملية دورة الحياة داخل دلالة؛ حاجة حمل دائم تلقائي تحويل نشر يجب زيادة مفرد وحيد تصميم فرعي نظام، بينما لا هو إعادة حل تفسير هذا runtime.
