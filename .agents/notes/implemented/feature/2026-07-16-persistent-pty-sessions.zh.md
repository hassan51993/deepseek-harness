# Agent Note: حفظ دائم PTY جلسة

Status: implemented

[English](2026-07-16-persistent-pty-sessions.md) | العربية

## مشكلة

harness يمكن تشغيل قبل منصة و خلفية أمر، تحرير ملف و تفويض إرسال عمل، لكن لا يمكن عبر أداة استدعاء تأخير متابعة مرة تفاعل صيغة طرفية محادثة. كل مرة `bash` قبل منصة تشغيل كل سوف بدء واحد جديد shell، لذلك shell داخل cwd، توجيه خروج متغير، وهمي محاكاة بيئة تنشيط حالة، دالة،job control حالة و تفاعل صيغة عملية فرعية كل سوف مع هذا مرة استدعاء انتهاء.

هذا عدد نقص فتحة ترتيب حذف حالة إقامة إبقاء في طرفية بينما لا هو ملف في سير العمل، مثال مثل مفرد خطوة ضبط تجربة `gdb`، في Python أو Node REPL في استكشاف، قيادة `ed` هذا صنف سطر صيغة تحرير جهاز، أو من في قطع قبل منصة أمر بعد عودة إلى أصل shell. عام [`ctx.jobs`](../../../../packages/jobs/README.zh.md) وقت التشغيل يمكن إبقاء خلفية عملية جملة مقبض و إخراج، لكن لا توفير تفاعل صيغة stdin أو طرفية دلالة.

قائم `bash`،`read`،`write` و `edit` أداة ما زال هو محدود، يمكن مراجعة حساب عملية يمكن اعتماد افتراضي خيار.PTY هو مقابل تأكيد فعلي حاجة طرفية حالة عمل تكملة ملء قدرة، لا شرح هذه أداة لديه نقص وقوع، أكثر لا معنى طعم حال يلزم إزالة هو جمع.

## قرار

اختياري `packages/terminal/` قدرة بيت عائلة توفير من agent(ذكي جسم) يملك، حفظ دائم كما موجه إلى سطر صيغة تفاعل PTY جلسة. هو التزام دوران مستودع [قدرة نمط](../../implemented/architecture/2026-06-13-capability-seams.zh.md) ، و قائم أمر و نظام الملفات أداة و تخزين، و كما لا تعديل `agent-loop`.

حالي تنفيذ في Linux و macOS فوق دعم حمل تفاعل صيغة shell و سطر صيغة REPL. كل شاشة طرفية تطبيق، حسب مفتاح تسلسل،BEL إطلاق تحكم تدفق، عملية فقد فقد بعد جلسة استعادة و عبر agent مشترك جلسة كل واضح دفع متأخر.

### حزمة توسيع اندفاع

| حزمة | زاوية لون | ctx key |
|---|---|---|
| `dsh-terminal` | `TerminalSessionService`،branded `TerminalSessionId`، خلفية سجل التسجيل، حسب owner عزل جلسة اتفاق و نتيجة نوع | `ctx.terminals` |
| `dsh-terminal-bash` | أساس في `ctx.subprocess.spawnTerminal()` حمل دائم shell خلفية: حينئذ خيط حالة، محدود طرفية مؤقت اندفاع، صندوق رملي تحليل و شعور معرفة owner جلسة دورة الحياة | في `ctx.terminals` فوق تسجيل خلفية |
| `dsh-tool-terminal` | 6 عدد موجه إلى نموذج أداة، خلفية إرسال task وقت التشغيل تجميع صار، استخدام إشارة جذب و UI تصيير معنى رسم | تسجيل إلى `ctx.tools` |

حينئذ خيط حكم تحديد ما زال يخص PTY خلفية سلوك، لا هو ثاني بند عام مشترك اتفاق. طرفية عملية مزود فقط توفير أساس قاع واقع، مثال مثل قبل منصة عملية مجموعة، و قدرة لا إثبات هذا مجموعة صحيح في انتظار إدخال؛`dsh-terminal-bash` سوف هذه واقع و تلميح رمز و ساكن صامت دليل تركيب صار موحد واحد إرسال نتيجة.

### agent كل حق و هوية

`TerminalSessionService` في عملية داخل حفظ نشط جلسة، لكن كل جلسة كل من أداة تنفيذ سياق نقل دخول تأكيد قطع `Agent` يملك. خدمة صب صنع لا نفاذ واضح `TerminalSessionId`؛ نموذج اختياري ملء `name` فقط هو عرض بيانات وصفية، فقط في هذا owner داخل وحيد. كل عملية كل بـ `sessionId` لـ هدف،`list`/`read`/`signal`/`kill` سوف رفض owner خارج استدعاء جهة.

تنفيذ لا توفير إضافة تحميل مدة auto-start جلسة.`terminal_open` فقط في agent أداة استدعاء خلال إنشاء جلسة، هذا وقت كل حق و الذي تابع حدث تتبع مصدر جلسة كل قد تحديد. لم قدوم إعلان صيغة بدء وظيفة يجب عبر بعد لم إصدار agent setup تركيب، بينما لا يستطيع إنشاء عام مشترك طرفية.

agent scope dispose(مورد تحرير) وقت أولا سحب إلغاء تسجيل، مجددا انتظار الكل الذي تابع PTY تماما توقف مستقر. لم إصدار خلفية setup نفس مثال هو تلقي تتبع أثر دورة الحياة عملية:owner أو خدمة dispose سوف في توقف خدمة ذاتي لديه signal، انتظار خلفية تسوية و تراجع إتمام بعد عندئذ إرجاع. أي جعل خلفية reject، أو إرجاع جلسة في تراجع close وقت فشل، استدعاء جهة إلغاء ما زال سوف أصل مثال إبقاء ذلك `AbortSignal.reason`؛ هذا تنظيف فشل لن استبدال استدعاء جهة سبب، بينما سوف متابعة تلقي تتبع أثر، إبقاء انتظار لاحق owner أو خدمة dispose معالجة. من lifecycle dispose إطلاق تراجع close فشل سوف جعل spawn و هذا lifecycle dispose كل reject، بينما `TerminalBackendCleanupError` يجعل خلفية في لا استبدال استدعاء جهة إلغاء قبل رفع تحت، لـ هذا lifecycle dispose إبقاء ذاته بدء تنظيف فشل. إذا استدعاء جهة إلغاء في dispose بدء قبل قد تسوية، هذا تنظيف فشل سوف متابعة بصفة تلقي تتبع أثر owner activity إبقاء، مباشر إلى لاحق owner أو خدمة dispose إزالة استهلاك و تقرير إبلاغ هو، لذلك صندوق رملي نمط سياسة لن يأخذ تنظيف فشل خطأ حكم لـ تماما توقف مستقر. خلفية أو أداة إضافة reload لن متروك إبقاء جلسة: كل حق حمل متابعة تخزين وضع في `TerminalSessionService` في، مباشر إلى agent انتهاء، و [`ctx.jobs`](../../../../packages/jobs/jobs/README.zh.md) خدمة يحتفظ سجل نمط متسق. خدمة سوف أولا تزامن يأخذ جلسة مسبق إبقاء إعطاء مرة نشط وثب إرسال، مجددا إرجاع هذا عملية؛ خلفية إرسال نفس مثال سوف في job id مقابل خارج مرئي قبل إتمام مسبق إبقاء. ثاني مرة إرسال سوف بـ `SEND_ACTIVE` فشل، لذلك إخراج و إلغاء لا يمكن عبر تجاوز عملية كل حق.

### أمان و عملية حد

تسجيل `shell` خلفية فقط قيد طرفية مثل أي بدء، لا قيد بدء بعد إدخال أمر. لذلك `dsh-terminal-bash` في spawn قبل تطبيق اثنان طبقة حفظ حماية:

- هو فقط توفير طرفية مخصص استخدام بيئة تغطية؛ تركيب عملية فرعية مزود أولا صاف حذف اسم شكل يشبه اعتماد بيئة متغير، مجددا دمج هذه تغطية.
- هو اشتراط مشترك `ctx.sandboxPolicy`. خلفية في spawn وقت، بـ نشر قيمة افتراضية لـ قاع طي owner صالح جلسة نمط؛`danger-full-access` سوف مباشر بدء shell، تلقي حد نمط فإن اشتراط نفس تنفيذ عالم حد في وجود `ctx.sandbox` مزود، و فقط حزمة تركيب مرة shell argv. هذا نمط و workspace root في PTY كامل دورة الحياة في ملء عند عملية حد. فقط يلزم owner لديه أي قد فتح PTY أو بعد لم إصدار spawn، أي سوف تغيير توليد فاعلية `sandbox/mode` كتابة كل سوف في إيداع قبل يتم رفض، و تلميح أولا انتظار إنشاء عملية تسوية، مجددا إغلاق هذه جلسة؛ لن تغيير توليد فاعلية نمط كتابة ما زال صالح. هذا بند إجراء في مسبق إبقاء من خلفية setup حمل متابعة إلى إصدار إتمام، لذلك لا وجود تخفيض بعد أيضا ظهور إذن أكثر عرض طرفية هذا واحد تنافس حالة.`danger-full-access` هو قائم صريح بلا قيد اختيار، لا آخر ضبط PTY خاص bypass.

صندوق رملي حد محلي عملية فرعي أثر، لكن لن يجعل مهمة معنى shell إدخال تلقائي أمان: شبكة شبكة استدعاء و أخرى خارجي فرعي أثر ما زال من نشر سياسة معالجة إدارة. أداة وصف سوف شرح PTY جلسة مقارنة مرة صفة أداة أكثر صعب مراجعة حساب، فقط ينبغي في تأكيد فعلي حاجة حمل دائم حالة أو تفاعل صيغة stdin وقت استخدام.

محلي عملية فرعية طرفية أصل لغة فقط استخدام `node-pty` عام قدرة: عملية فرعية PID،`data` و `exit` إشعار،`write` و `kill`. هو لا زائف ضبط قدرة وصول أصلي master fd، أيضا لا من TypeScript استدعاء `waitpid`. في تلقي دعم حمل Linux مضيف فوق،[أصلي استلام سعة owner](../architecture/2026-08-28-subprocess-native-containment.zh.md) سوف في user-systemd scope داخل بدء نفس بند PTY أمر، معا إبقاء PID،session، تحكم طرفية، قبل منصة عملية مجموعة و حينئذ خيط دلالة. هذا أصل لغة تحت منصة عملية فحص جهاز ما زال في Linux فوق عبر `/proc`، في macOS فوق عبر `ps` دفع توجيه قبل منصة عملية مجموعة و fallback أب عملية فرعية هوية.[يمكن نقل غرس تنفيذ بيئة قرار](../architecture/2026-07-28-portable-execution-world-consumers.zh.md) مسؤول تعريف هذا نوع عملية/مستهلك تفكيك قسم.

### 6 عدد موجه إلى نموذج أداة

| أداة | استخدام طريق | نتيجة |
|---|---|---|
| `terminal_open` | من قد تسجيل خلفية نوع إنشاء حسب owner عزل جلسة | `{ sessionId, name, type, motd }` |
| `terminal_send` | إرسال نص، اختياري إيداع Enter، و انتظار حينئذ خيط أو تسجيل واحد خلفية مهمة | محدود viewport، انتظار حالة و جلسة حالة؛ خلفية نمط أيضا إرجاع `jobId` |
| `terminal_read` | من إبقاء scrollback قراءة واحد محدود صفحة | `{ text, totalLines, lineBegin, lineEnd, truncated }` |
| `terminal_signal` | نحو حالي قبل منصة عملية مجموعة إرسال واحد نوع سماح إشارة | `{ delivered, targetPgid }` |
| `terminal_close` | إغلاق واحد جلسة و انتظار عملية شجرة تماما توقف مستقر | `{ killed }` |
| `terminal_list` | صف خروج استدعاء جهة نشط جلسة | حسب owner عزل جلسة ملخص |

UI تصيير اتفاق دقيق كما لا يحمل موضع معلومة.`terminal_send` فقط لـ قبل منصة إرسال استخدام terminal استدعاء بطاقة و نتيجة بطاقة؛ خلفية شكل صيغة استخدام عام `execute` بطاقة.`terminal_open`،`terminal_read`،`terminal_signal`،`terminal_close` و `terminal_list` قسم آخر استخدام عام `execute`،`read`،`execute`،`delete` و `read` بطاقة. كل PTY أداة كل لا إرسال خروج `locations`.

`terminal_send({ sessionId, text, submit?, run_in_background? })` سوف `text` نظر لـ UTF-8 بايت، و من أداة تنفيذ في تحليل مرحلة مقطع يأخذ `submit` افتراضي صار `true`.`submit` لـ true وقت أولا كتابة نص، مجددا كتابة منصة Enter تسلسل؛ لـ false وقت فقط كتابة نص، جعل تحكم محرف و REPL قطعة مقطع بلا حاجة إخفاء محتوى بدء إرسال صيغة يكفي إرسال. إلغاء سوف في نحو حقيقي قبل منصة عملية مجموعة إرسال إشارة قبل سوف ترتيب طابور إدخال علامة لـ قد إلغاء، لذلك أي جعل مختلف خطوة كتابة قبل فحص مع بعد عندئذ تسوية، هذا إدخال أيضا لا يمكن تنفيذ. يتم إلغاء إرسال سوف إبقاء ذلك مسبق إبقاء، مباشر حتى مختلف خطوة قبل منصة إشارة إرسال تسوية، لذلك لاحق إرسال لن يصبح هذا إشارة هدف.`enableRunInBackground` افتراضي لـ true؛ ضبط لـ false وقت،schema في سوف إزالة `run_in_background`، استدعاء جهة أي جعل قوي سطر يأخذ هذا عدد لم إعلان معامل نقل دخول تنفيذ مسار، أيضا سوف يتم رفض.

قبل منصة إرسال إرجاع محدود تصيير زيادة كمية و اثنان عدد مستقل واقع:`waitReason`(`stdin_read | inferred_idle | timeout | session_exit`) و `sessionStatus`(`running`، أو يحمل خروج رمز أو إشارة `exited`).`session_exit` إشارة PTY قمة طبقة shell عملية خروج، لا إشارة من shell إزالة استهلاك حالة مهمة معنى قبل منصة أمر.timeout من لا معنى طعم حال عملية قد خروج.`dsh-tool-terminal.maxResultBytes` افتراضي لـ 262144؛ منخفض في 64 قيمة سوف يتم رفض، بـ تأكيد حفظ إنشاء تأكيد إبقاء سجل التسجيل توقيع إرسال id؛ كل مفرد نص UTF-8 نتيجة في إضافة دخول مواصفة تحويل أداة أو خط الإنتاج خطأ، انتظار، جلسة، قسم صفحة، قطع قطع، عام task حالة حزمة تركيب، سياسة رفض أو قصير مسار و post-execute استبدال أو منع قطع بعد، ما زال تلقي هذا قيمة حد؛ طرفية تعريف ذاتي لديه نهاية طرف `finalizeContent` callback سوف أصل مثال إبقاء سياسة لحظة معنى إرجاع بنية تحويل كثير كتلة محتوى. مصير سوف لـ بعد لاحقة مسبق إبقاء فضاء و إبقاء شفرة نقطة حد، بينما لن يأخذ خلفية تحميل حمل حد أعلى عند عمل موجه إلى نموذج نتيجة نهائي حد أعلى.

عند `run_in_background: true` وقت،`dsh-tool-terminal` في `ctx.jobs` فوق تسجيل إجراء في إرسال، و قيام أي إرجاع `jobId`. إنتاج جهة يأخذ `maxResultBytes` كتابة task لقطة، جعل `job_output`،kill إرجاع نهاية حالة حالة و إتمام إشعار في إضافة فوق عام بيانات وصفية بعد، ما زال مقابل كامل نتيجة تنفيذ نفس حد أعلى.`job_output(wait: true)` مسؤول انتظار، قراءة زيادة كمية إخراج و سجل نهائي نتيجة؛`job_kill` سوف تحليل حالي قبل منصة PGID تزامن إرسال حق صحيح `SIGINT`، أي جعل تطبيق قد منع استخدام طرفية `ISIG` أيضا نفس مثال مثل هذا، كما لاحق ترقية ما زال فقط عبر PTY خلفية يملك teardown مسار إجراء. إذا task مقابل خارج واجهة لا وجود، خلفية نمط يجب في كتابة إدخال قبل فشل. تصميم لا إضافة جديدة PTY مخصص استخدام `sleep` أداة أو عام نداء تنبيه API.

`terminal_read` من الأكثر جديد إبقاء سطر نحو بعد قسم صفحة. خلفية معا مقابل إبقاء scrollback و إرجاع صفحة تحميل حمل تنفيذ سطر عدد و UTF-8 بايت حد أعلى، لذلك مفرد عدد تجاوز طويل سطر لا يمكن التفاف مرور خلفية حد أعلى؛ أداة مع بعد مجددا حد يتضمن قسم صفحة و قطع قطع بيانات وصفية كامل تصيير صفحة.`truncated` لأجل منطقة قسم إبقاء بيانات فقد فقد و عادي viewport زيادة كمية.

`terminal_signal` قبول إغلاق دمج تجميع `SIGINT | SIGTERM | SIGKILL | SIGTSTP | SIGHUP`. خلفية في تنفيذ وقت تحليل طرفية قبل منصة عملية مجموعة. عند هدف مجموعة هو قمة طبقة shell وقت رفض `SIGKILL`، و إشارة جذب استدعاء جهة استخدام `terminal_close`؛ عملية مجموعة تحليل فشل وقت عملية مباشر فشل، بينما لا هو نحو تخمين قياس PID إرسال إشارة.

### محلي حينئذ خيط فحص قياس

محلي خلفية أولا تعرف آخر تلقي تحكم bash بدء وقت إرسال خروج خاص OSC prompt marker، و كما فقط لديه في الأكثر قريب واحد marker بعد يمكن ضرب طبع ذيل جزء و تلقي تحكم `PS1` تماما متبادل انتظار وقت عندئذ إعلان prompt حينئذ خيط؛ حذف هذا خارج، هو أيضا تشغيل 3 عدد محدود fallback طبقة درجة. في data callback بين إبقاء هذا ذيل جزء، يمكن ملائم إعداد marker و prompt يتم قسم فتح تسليم حال حال؛ إذا عودة إظهار إدخال أو إخراج تتبع في تأخير متأخر وصول أولا قبل prompt بعد، اشتراط ذيل جزء تماما متبادل انتظار سوف رفض هذا prompt، جعل ذلك لا يمكن إتمام حالي send.marker في إخراج وصول نموذج قبل يتم إزالة، جعل اثنان عدد منصة فوق عادي shell أمر كل بلا حاجة ثابت انتظار ساكن صامت عتبة قيمة. بعد لم إصدار startup لن يأخذ صفر إخراج ساكن صامت نظر لـ حينئذ خيط؛timeout سوف رفض spawn. إذا استدعاء جهة إلغاء في startup خلال فوز خروج، خلفية سوف إغلاق خاص جلسة و أصل مثال رمي خروج `AbortSignal.reason`؛ بعد غير ممكن مراقبة قبل منصة PGID لن مجددا استخدام فحص بحث خطأ تغطية إلغاء سبب. كل وقت معامل كل هو مرور تحقق إعداد حقل:`pollIntervalMs`،`exactProbeAfterMs`،`idleSilenceMs`،`handoffGraceMs` و `timeoutMs`.

في Linux فوق، فحص جهاز من `/proc/<shellPid>/stat` قراءة shell طرفية قبل منصة PGID، قطعة رفع هذا عملية مجموعة في كل عملية و خط مسار، و فحص هو جمع حالي syscall.Tier 1 فقط لديه مراقبة إلى stdin انتظار عندئذ إرجاع صحيح نتيجة: مباشر `read(0)`، نيل دقيق قراءة كما يحتوي fd 0 `select`/`pselect6` أو `poll`/`ppoll` معامل، أو من يحتوي fd 0 epoll interest list. انتظار خط مسار `/proc/<pid>/task/<tid>/fd/0` أيضا يجب معرف shell تحكم طرفية ضبط تجهيز، لذلك خط مسار محلي fd جدول لا يمكن استخدام leader طرفية وصف رمز خطر ملء ذاته fd، منع سد في إدارة طريق خط الإنتاج قراءة طرف ما زال يخص صحيح في تشغيل أمر. مباشر PTY وصف رمز استخدام ذلك ضبط تجهيز رقم؛`/dev/tty` فإن استخدام الذي تابع عملية `tty_nr`، لأن `stat` تقرير إبلاغ هو آخر اسم ضبط تجهيز بينما غير اختيار تحديد PTY. طرفية إدخال قبل حينئذ قد وجود انتظار و لا بديل جدول كتابة بعد حينئذ خيط: يجب أولا مراقبة إلى نفس PGID انفصال مغادرة هذا انتظار، بعد مجددا مرة دخول انتظار عندئذ قدرة جعل هذا مرة send إتمام؛ قبل منصة PGID حدوث تغير فإن بنية صار جديد دليل. لا يمكن قراءة عملية داخل تخزين و لم تعرف آخر syscall كل هو miss، أبدا بصفة صحيح نحو تخمين قياس. مضيف سياسة (يشمل إضافة ثابت ptrace سياسة) إذا رفض قراءة `/proc/<pid>/task/<tid>/syscall`، نفس مثال سوف قفز مرور Tier 1 و إبقاء محدود Tier 2 idle دفع قطع؛ عملية راحة نوم حالة أبدا سوف بديل بديل غير ممكن وصول syscall دليل. هيكل بنية جدول فقط يتضمن مقابل Linux UAPI تعريف syscall number؛ فحص جهاز أولا دقيق دخول وقت التشغيل هيكل بنية، مجددا فحص كل تلقي دعم حمل داخل نواة ABI، لأن في مستخدم حالة نموذج محاكاة تحت،`/proc` ممكن تقرير إبلاغ مختلف ABI. لا تلقي دعم حمل وقت التشغيل هيكل بنية سوف قفز مرور Tier 1.

macOS لا يوجد دقيق syscall طبقة. أي قبل منصة عملية مجموعة إخراج ساكن صامت كل سوف إرجاع `inferred_idle`، يشمل Python و `gdb`؛ من `ps` دفع توجيه طرفية PGID فقط لأجل إرسال إشارة، لا بصفة «فقط لديه shell عندئذ قدرة idle» إثبات. صاف عملية فحص منطق يمكن حقن، و في Linux فوق مرور مرور اختبار وحدة، معا من macOS CI job قيادة حقيقي PTY و عملية جدول مسار.

Tier 2 في حمل متابعة `idleSilenceMs` لا يوجد إخراج بعد إرجاع `inferred_idle`، لذلك sleep أو شبكة شبكة منع سد أمر ممكن نظر يشبه ready. إذا هذا قبل قد رؤية مرور prompt marker،Tier 2 سوف مجددا انتظار `handoffGraceMs`، جعل تماما جيد سقوط في ساكن صامت حد فوق bash قبل منصة تسليم وصل ما زال بـ دقيق `stdin_read` عودة بسبب انتهاء، بينما لا هو تراجع إلى مقارنة ضعيف دفع قطع؛ هذا عرض حد هو من نشر جهة يملك إعداد حقل، و يتم تحقق لـ حتى قليل تغطية واحد `pollIntervalMs`——قصير في جولة استفسار دورة مدة عرض حد تركيب لا تحت مرة حينئذ خيط جولة استفسار، لذلك غير ممكن قدرة تغيير أي نتيجة. هو فقط قيد رؤية مرور marker send، بديل قيمة هو هذا واحد نوع حال حال تفاعل إرجاع تأخير متأخر، بينما لا هو كل مرة send.Tier 3 في `timeoutMs` بعد إرجاع `timeout`، تجنب تجنب قبل منصة أداة استدعاء بلا حد احتلال إقامة agent. نتيجة إبقاء هذه منطقة آخر؛ استدعاء جهة يمكن عبر `ctx.jobs` انتظار، نحو قبل منصة مجموعة إرسال إشارة، أو من آخر عدد جلسة ترتيب فحص.

مرة send في مهمة واحد طبقة درجة settle بعد،`TerminalSendOperation.append` حينئذ لم يعد قبول إخراج، هذا بعد عملية فرعية إخراج لن مجددا دخول ذلك عدد قد settle operation؛ هو ما زال سوف دخول scrollback، و هذا وقت تماما جيد موضع في نشط وثب حالة أي send. لذلك، انتظار ذاتي ذات الذي بدء operation فوق ظهور علامة اختبار، يجب يأخذ `idleSilenceMs` و `timeoutMs` ضبط نيل عال في عملية فرعية ذاته بدء استهلاك وقت؛ لا فإن في سالب تحميل مقارنة عال macOS runner فوق، حل تفسير جهاز بدء سوف في علامة ضرب طبع قبل حينئذ انتهاء هذا مرة send.

`node-pty` data إشعار دخول نفس عدد طرفية parser.parser carry state سوف معالجة عبر callback تحكم تسلسل و يقع في callback نهاية ذيل عودة عربة؛ لذلك، أي جعل CRLF يتم تفكيك فتح، أيضا فقط سوف توليد واحد تبديل سطر، بينما لن إنتاج تغيير قسم صفحة فارغ سطر. تنفيذ سوف مواصفة تحويل سطر صيغة إخراج، لكن لا تحمل وعد صحيح تأكيد عملية كل شاشة تطبيق.

### نموذج مرئي إخراج و حمل دائم صفة

قائم حفظ دائم `tool/call` و `tool/result` حدث هو نموذج إرسال نص و إرجاع إعطاء نموذج تصيير إخراج حق مصدر.`terminal_open` عبر قد سجل أداة نتيجة إرجاع MOTD؛ قبل منصة `send`/`read`/`list`/`signal`/`close` نتيجة مشي نفس مسار سجل.PTY حزمة لن يأخذ أصلي بايت تدفق تكرار كتابة ذاتي تعريف جلسة حدث.

خلفية إرسال إعادة استخدام قائم خلفية مهمة إتمام إشعار و `job_output` نتيجة مسار، لذلك دخول لاحق نموذج طلب أي إخراج نفس مثال حفظ دائم. أصلي طرفية بايت فقط بصفة محدود عملية داخل حالة وجود، حيث لا حفظ دائم أيضا غير ممكن استعادة. لم قدوم opt-in transcript(نص سجل)sink يجب يملك مستقل إبقاء، سند إثبات و خفي خاص اتفاق.

### عملية شجرة teardown

في تلقي دعم حمل Linux مضيف فوق،subprocess طرفية جملة مقبض سوف يأخذ قمة طبقة PTY عملية ربط إلى مؤقت user-systemd scope. بناء قيام قبل،close عبر direct PTY fallback إرسال `SIGTERM`، منع توقف bootstrap متابعة؛ بناء قيام بعد فقط نحو scope إرسال إشارة، و كما فقط في scope signalling فشل وقت استخدام direct fallback. مع بعد هو انتظار manager إثبات هذا range لـ فارغ، و في إعداد عرض حد مدة بعد ترقية إلى `SIGKILL`. استدعاء `setsid` أو حدوث reparent بعد بديل ما زال يخص scope، بينما PTY direct exit إشعار متابعة بصفة طرفية نتيجة.

fallback مضيف إبقاء مراقبة صيغة عملية session تنظيف. جملة مقبض سوف حسب أب PID بـ عملية فرعية أولوية ترتيب التقاط نقل تمرير بعد بديل، إرسال `SIGTERM` و انتظار، لكن بعد إعادة مسح صلة توقف خلال fork خروج عملية فرعية، نحو اثنان من و تجميع إرسال `SIGKILL`، و في إيقاف قمة طبقة عملية قبل تحقق كل غير جامد جثة بعد بديل كل قد مغادرة فتح عملية جدول. هوية مطابقة Linux جامد جثة عملية قد بلا يمكن تنفيذ عمل، لذلك نظر لـ تماما توقف مستقر. كل التقاط PID كل يتضمن عملية بدء هوية، تجنب تجنب PID إعادة استخدام يأخذ ترقية إشارة إرسال إعطاء غير متصل عملية.

teardown مستقل تقرير إبلاغ قمة طبقة عملية خروج و تخزين نشط عملية تنظيف.PTY جلسة لن فقط بسبب shell خروج حينئذ صوت تسمية نجاح: هو سوف استدعاء `SubprocessTerminalHandle.terminate()` و انتظار كامل جلسة تماما توقف مستقر، إذا تنظيف فشل فإن نحو خارج نقل بث و صف خروج تخزين نشط من. فشل close لن دائم دائم ذاكرة مؤقتة: سجل التسجيل و محلي جلسة كل منها فقط في إغلاق محيط شريط ما زال إشارة نحو هذا مرة فشل محاولة تجربة وقت عندئذ سوف ذلك صاف حذف، لذلك لاحق صريح close أو دورة الحياة close سوف إعادة محاولة، كما لن جاف إزعاج مقارنة جديد تزامن محاولة تجربة. أي جعل بعض عدد close فشل، خدمة dispose ما زال سوف صاف فارغ ذلك خلفية، مسبق إبقاء و owner detacher سجل التسجيل.

### تركيب و دفع سطر

عرض مثال تركيب إبقاء opt-in، و اعتماد أمان قيمة افتراضية:

```yaml
plugins:
  '@deepseek-ai/dsh-sandbox-local':
  '@deepseek-ai/dsh-sandbox-policy':
    config:
      mode: workspace-write
      workspaceRoot: .
  '@deepseek-ai/dsh-terminal':
  '@deepseek-ai/dsh-subprocess-local':
  '@deepseek-ai/dsh-terminal-bash':
    config:
      scrollbackLines: 10000
      scrollbackMaxBytes: 4194304
      maxReadBytes: 262144
      pollIntervalMs: 50
      exactProbeAfterMs: 150
      idleSilenceMs: 3000
      handoffGraceMs: 500
      timeoutMs: 30000
      disposeGraceMs: 3000
  '@deepseek-ai/dsh-tool-terminal':
    config:
      enableRunInBackground: true
      maxResultBytes: 262144
```

حزمة توفير بسيط نظيف أداة إشارة جذب، شرح حمل دائم حالة،owner عزل، لا تحديد idle نتيجة، تنظيف، و بلا حاجة تفاعل وقت أولوية استخدام قائم مرة صفة أداة. قد إصدار أساس أساس عرض مثال لا تركيب PTY:PTY فقط عبر مخصص استخدام تركيب opt-in، بينما ACP(Agent Client Protocol) و headless لقطة overlay سوف مقابل ذلك إجراء تحقق.`dsh-tool-terminal` نسخة واحد حالما تفعيل،6 عدد أداة و `run_in_background` حينئذ سوف افتراضي تفعيل؛ نشر يمكن عبر إعداد فقط منع استخدام خلفية معامل.

### دفع متأخر عمل

- كل شاشة TUI دعم حمل، تسمية حسب مفتاح تسلسل،BEL في قطع، طرفية resize أداة و alternate-screen لقطة حاجة آخر سطر تحقق موجه إلى نموذج اتفاق.
- إعلان صيغة per-agent بدء حاجة agent-setup تركيب نقطة؛ ما زال منع توقف إضافة تحميل مدة عام جلسة.
- harness عملية فقد فقد بعد جلسة استعادة حاجة عملية خارج owner و إصدار تحويل بروتوكول.
- شبكة شبكة خروج فتحة سياسة و خارجي فرعي أثر تراجع تجاوز خروج PTY نطاق، متابعة بصفة مستقل أمان عمل.
- Windows/ConPTY جلسة مرور من subprocess-local Windows inspector(Toolhelp32 هوية، زائف قبل منصة عملية مجموعة،taskkill تفكيك إزالة) و `pty-local` pwsh جهة قول تشغيل؛ رؤية [pwsh حمل دائم أداة note](../../archived/architecture/2026-08-11-pwsh-persistent-pty.md).

## تجهيز اختيار خطة

**استخدام PTY استبدال `bash`، نظام الملفات أداة أو task أداة.**رفض. مرة صفة أداة يملك أكثر قوي تحقق، مراجعة دفعة، صندوق رملي، إخراج حد أعلى و إعادة تشغيل اتفاق.PTY فقط خدمة تفاعل صيغة حالة.

**إعطاء `bash` زيادة حمل دائم نمط.**رفض. حسب حينئذ خيط بينما لا هو عملية خروج إرجاع، عبر استدعاء إبقاء عملية شجرة، كشف تفاعل صيغة stdin سوف شكل صار مختلف كل حق و فشل اتفاق.

**اشتراط من `node-pty` نيل أخذ أصلي master fd.**رفض. هو عام مشترك API لا كشف master fd. محلي عملية فرعية طرفية مهايئ تعديل لـ من تلقي دعم حمل OS عملية بيانات وصفية دفع توجيه قبل منصة مجموعة و فرعي حفيد عملية، و يأخذ غير ممكن قراءة بيانات وصفية نظر لـ detector miss.

**نحو أصل PID الذي تابع POSIX جلسة الكل عضو إرسال إشارة.**رفض.`node-pty` ممكن كشف يخص بدء جهاز جلسة helper PID، لذلك حسب SID تنظيف ممكن نحو غير متصل harness أو طاولة وجه عملية إرسال إشارة. حمل PID بدء هوية تحقق فرعي حفيد عملية شجرة نطاق أكثر ضيق، ذلك أمان حد من بنية حفظ إثبات.

**إصدار يمكن استبدال سجل التسجيل `TerminalIdleDetector`.**رفض. أساس قاع مخصص استخدام قبل منصة واقع قدوم ذاتي تركيب طرفية عملية أصل لغة، تلميح رمز/ساكن صامت حينئذ خيط حكم تحديد فإن ما زال هو `dsh-terminal-bash` داخلي واحد بند خاص سياسة. استبدال نظام الملفات/عملية فرعية تنفيذ بيئة حينئذ هو الذي يحتاج نقطة توسيع.

**إضافة جديدة PTY مخصص استخدام `sleep` أداة.**رفض.`ctx.jobs` قد يملك محدود انتظار، إلغاء، إتمام إشعار و موجه إلى نموذج استلام تجميع. ثاني طقم عام نداء تنبيه آلية سوف عبر تجاوز agent loop(ذكي جسم حلقة) حد و تكرار هذا اتفاق.

**يتضمن TUI sequence و BEL معالجة.**رفض. مصدر prototype سوف هذه مسار نظر لـ timing-sensitive، كما ما زال سجل لم حل قرار alternate-screen و تفاعل فشل. سطر صيغة PTY قد قدرة إثبات نواة قلب قيمة قيمة، بلا حاجة يأخذ لم مرور تحقق سلوك وضع دخول أساس أساس طبقة.

**قيام أي اعتماد عملية خارج daemon.**ابتدائي عملية داخل قدرة لا اعتماد، لأن حالي طويل إقامة تشغيل مدخل قد قدرة صيانة حمل Cordis سياق. عبر عملية استعادة أو كثير عميل مرفق إضافة سوف يجعل daemon تغيير نيل دمج إدارة، لكن اثنان من كل قد دفع متأخر.

## تحقق

- تدريجي ملف تغطية اختبار قفل تحديد owner عزل، تزامن مسبق إبقاء، كتابة قبل فحص خلال إلغاء، لم إصدار spawn إلغاء و انتظار صيغة teardown، صندوق رملي نمط تغيير رفض، يمكن إعادة محاولة دورة الحياة تنظيف، حينئذ خيط طبقة درجة، مقابل كتابة قبل stdin انتظار و تأخير متأخر وصول أولا قبل prompt رفض، إعداد تحويل تسليم وصل عرض حد يأخذ idle fallback قمة مرور مرة جولة استفسار و منخفض في `pollIntervalMs` وقت رفض،sanitizer carry state، كامل UTF-8 نتيجة حد أعلى،task تجميع صار،schema و دقيق render intent.
- عملية فرعية fixture(اختبار قبل وضع بيانات) تغطية غير leader و غير رئيسي خط مسار stdin انتظار، خط مسار محلي fd جدول،`/dev/tty` آخر اسم، مستخدم حالة نموذج محاكاة تحت تلقي دعم حمل داخل نواة ABI، رفض يأخذ إشارة نحو إدارة طريق fd 0 عند عمل طرفية إدخال، جامد جثة عملية تماما توقف مستقر، غير ممكن قراءة عملية حالة، لا دعم حمل هيكل بنية و أخرى خطأ تقرير رفض؛ نفس اختبار وحدة طقم عنصر عبر حقن تغطية macOS فحص جهاز منطق.
- حقيقي `node-pty` و PTY مستهلك اختبار مشترك نفس تغطية shell حالة، عبر `/dev/tty` قراءة تحكم طرفية إدخال، عملية syscall يمكن قراءة وقت دقيق عودة بسبب، مضيف سياسة رفض قراءة وقت محدود idle fallback، مشترك صندوق رملي سياسة، بيئة صاف غسل،raw mode قبل منصة `SIGINT`، تجاهل اختصار `SIGTERM` بعد بديل عملية، و dispose إرجاع بعد قيام أي تماما توقف مستقر.Linux native خطر دخان اختبار سوف في واحد reparent `setsid` بعد بديل ما زال من scope يملك وقت، إبقاء PTY PID،session leader، تحكم طرفية، قبل منصة `inputWaiting` و readiness؛fallback اختبار طقم عنصر متابعة تغطية حمل هوية محيط شريط مراقبة صيغة تنظيف.
- Loader قيادة `cordis.yml` اختبار تركيب حقيقي ثلاثة حزمة تركيب، و تحقق تأخير متأخر وصول خط الإنتاج إخراج مع قد إتمام أمر إرجاع، بينما لن يتم عودة صنف لـ طرفية إدخال حينئذ خيط.SDK minimal لقطة عبر حمل دائم Bash أداة ثابت هذا إخراج؛ACP و headless لقطة عبر opt-in overlay ثابت 6 عدد طرفية schema، محدود نتيجة و خطأ؛TUI لقطة ثابت terminal و generic بطاقة عرض.
- حزمة اتفاق، هيكل بنية رسم، فرعي نظام صفحة، توليد دليل و website API وصف نفس عدد قد إصدار واجهة.

## عاقبة

**بلا حاجة تقليل ضعيف مرة صفة أداة يكفي نيل نيل حمل دائم طرفية حالة.**Shell و REPL حالة يمكن عبر أداة استدعاء إبقاء، بينما `bash`،`read`،`write` و `edit` متابعة يملك أكثر ضيق تحقق، مراجعة دفعة و إعادة تشغيل اتفاق.

**Linux Tier 1 خارج idle كل هو بدء إرسال صيغة نتيجة.**إخراج ساكن صامت لا يمكن منطقة قسم prompt،sleep و شبكة شبكة I/O. نوع تحويل نتيجة إبقاء لا تحديد صفة، محدود timeout،task انتظار و إشارة يجعل نموذج ما زال قدرة كف إمساك تحكم حق.

**دقيق عودة بسبب و دفع قطع عودة بسبب حد هو تأخير متأخر أخذ ترك، لا هو يمكن إزالة حذف تنافس حالة.**عودة بسبب أخذ قرار في داخل نواة في ساكن صامت حد أعلى وصول قبل أيضا هو بعد إصدار قبل منصة تسليم وصل، لذلك أي ثابت عرض حد كل هو مرة ضبط درجة فوق مراهنة ملاحظة.`handoffGraceMs` يأخذ هذا عدد مراهنة ملاحظة تسليم إعطاء نشر إعداد: ضبط كبير هو يمكن في بطيء سرعة أو عال سالب تحميل رئيسي آلة فوق تبديل إلى دقيق `stdin_read` عودة بسبب، بديل قيمة هو رؤية مرور prompt marker بعد تفاعل إرجاع تأخير متأخر؛ ضبط صغير فإن متبادل عكس. لا ينبغي اعتماد فوز سالب نتيجة اختبار استخدام لن ظهور في إدخال عودة إظهار في token، تأكيد تحت مرة send في من عملية فرعية إنتاج إخراج، بينما لا هو تأكيد عودة بسبب مسار.

**حمل دائم حالة ممكن انحراف مغادرة نموذج إقرار معرفة.**نموذج ممكن نسيان تسجيل cwd أو نشط وثب REPL. جلسة ملخص و إبقاء إخراج لديه مساعدة استعادة، لكن أي نص التوجيه كل لا يمكن يجعل حالة حفظ دائم تغيير صار تحديد سلوك.

**Linux native ownership إزالة حذف عملية شجرة مراقبة نقص فتحة،fallback ownership لا يوجد.**تلقي دعم حمل user-systemd scope سوف حمل متابعة حفظ لديه daemonized أو reparent بعد بديل، مباشر إلى scope لـ فارغ. في macOS،Windows ConPTY، و لا يمكن بناء قيام scope Linux مضيف فوق، مراقبة صيغة teardown بدء قبل قد هروب هروب عملية ما زال ممكن تجنب فتح التقاط شجرة؛fallback قبول هذا عدد نقص فتحة، لا خطر خطر حسب SID نحو غير متصل عملية إرسال إشارة.

**Shell يمكن صنع صار خارجي فرعي أثر.**جلسة صندوق رملي و بيئة صاف غسل خفض منخفض محلي كشف، لكن لا يمكن سحب إلغاء push،API استدعاء أو رسالة إرسال. لا يمكن سعة تحمل هذه فرعي أثر نشر يجب حذف PTY أو زيادة شبكة شبكة سياسة.

**عملية فقد فقد سوف إلغاء تدمير طرفية حالة.**عملية داخل جلسة لا يمكن عبر harness crash أو restart تخزين نشط، أصلي scrollback أيضا لا حفظ دائم. إعادة يلزم عمل يجب إيداع إلى ملف أو أخرى حمل دائم نظام.

**`node-pty` هو `dsh-subprocess-local` أصلي اعتماد.**تثبيت، دعم حمل Node إصدار،prebuild متاح صفة و منصة سلوك كل حاجة في كل دعم حمل OS فوق تشغيل بناء ناتج خطر دخان اختبار.
