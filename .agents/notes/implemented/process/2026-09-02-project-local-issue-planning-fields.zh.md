# Agent Note: Project نطاق جزء Issue قاعدة تخطيط حقل

Status: implemented

[English](2026-09-02-project-local-issue-planning-fields.md) | العربية

## مشكلة

Issue دورة الحياة سير العمل حاجة بنية تحويل قاعدة تخطيط بيانات وصفية، لكن مجموعة نسج Issue حقل استخدام GitHub App إذن مستقل في مجموعة نسج Project إذن. أداة لديه Project كتابة إذن سير العمل token يمكن قراءة و تحديث Project custom field، بينما GitHub سوف رفض قراءة Issue حقل، لذلك معا استخدام اثنان طقم تخزين سوف يجعل نفس سياسة اعتماد اثنان مجموعة مستقل إدارة إذن.

Priority، أثر وجه، حل قرار بديل قيمة و يوم مدة لأجل في `DSH Issue Management` في قاعدة تخطيط عمل. يأخذ هذه قيمة حفظ في Issue فوق أيضا سوف يجعل هو جمع في هذا Project خارج مرئي، لكن مستودع لا يوجد حاجة عبر Project قيمة سير العمل.

## قرار

`DSH Issue Management` Project استخدام Project custom field تخزين `Priority`،`Severity`،`Cost`،`Start Date` و `Target Date`.`Severity` امتداد استخدام مجموعة نسج حقل `أثر وجه` خيار يحتوي معنى،`Cost` امتداد استخدام `حل قرار بديل قيمة` خيار يحتوي معنى.

مستودع سياسة من إعداد Project تحليل `Priority` و `Start Date`. سياسة رفض Issue حقل إسقاط أو خطأ بيانات نوع، من Project item قراءة Priority، و عبر `updateProjectV2ItemFieldValue` كتابة Start Date. مجموعة نسج Issue حقل فقط بصفة حمل لديه `Legacy ...` بادئة ترحيل مصدر إبقاء، مستودع سير العمل لن قراءة هو جمع.

PR سياسة سير العمل استخدام مستودع `GITHUB_TOKEN` تنفيذ REST Issue و PR قراءة، و استخدام فقط لديه مستودع Issues و مجموعة نسج Projects قراءة إذن GitHub App token تنفيذ ProjectV2 استعلام. دورة الحياة mutation متابعة استخدام لديه كتابة إذن App token.

Issue دورة الحياة سير العمل فقط في `pull_request.opened` وقت ابتدائي تحويل `Start Date`. سير العمل قراءة PR فوري متن، إبقاء كل قدرة تحليل لـ Issue نفس مستودع مرجع، يأخذ `created_at` حسب إعداد Project وقت منطقة تحويل لـ يوم تاريخ يوم مدة، تأكيد حفظ Issue هو Project item، و فقط في حالي Project قيمة لـ فارغ وقت كتابة يوم مدة.

[مجموعة نسج حقل تنفيذ](../../archived/process/2026-08-31-pr-opened-issue-start-dates.md) سجل قد يتم يحل محل عبر Project كل حق قرار و ذلك حدث وقت آلة اعتماد حسب. من حدث مباشر إشارة تحديد Status تحويل ما زال من[دورة الحياة قرار](2026-08-10-event-directed-pr-review-status.zh.md) مسؤول.

## تحقق

[Issue إدارة اختبار](../../../../.github/issue-management/policy.test.mjs) اشتراط Priority و Start Date استخدام Project custom field، إثبات مستودع قراءة و Project قراءة استخدام مختلف اعتماد، تغطية فوق بحر وقت منطقة يوم مدة حد، فقط opened قسم إرسال، فارغ قيمة كتابة، قد لديه قيمة إبقاء و Project item ناقص، و ثابت `updateProjectV2ItemFieldValue`. سير العمل اختبار ثابت Project token فقط قراءة إذن. حذف مجموعة نسج حقل قبل يجب تدريجي بند مقارنة مقارنة كل قديم حقل قيمة و Project قيمة، يشمل قد عودة ملف Project item.

## اعتبار مرور بديل خطة

**إبقاء مجموعة نسج Issue حقل.** هو جمع يمكن يجعل واحد قيمة في كثير عدد Project في مرئي، لكن سير العمل لا حاجة هذا نطاق، و كما GitHub App أيضا حاجة مفرد وحيد مجموعة نسج Issue Fields إذن.

**معا كتابة Issue و Project حقل.** مرآة مثل حقل إبقاء عبر Project مرئي صفة، لكن كل كتابة جهة و شخص عمل تحرير كل ممكن إنتاج انحراف فرق، و كما أيضا حاجة تنسيق ضبط سياسة.

**معالجة كل قد حجز قراءة PR حدث أو تغطية Start Date.** لاحق حدث يمكن إصلاح ناقص يوم مدة، لكن سوف في عمل بدء بعد عندئذ منح قيمة أو استبدال شخص عمل حساب تخطيط. لذلك ابتدائي تحويل جهاز إبقاء فقط opened، فقط فارغ قيمة سلوك.

## عاقبة

قاعدة تخطيط بيانات وصفية حد تحديد في واحد Project ملكية في. نفس عدد Issue يمكن في آخر عدد Project في استخدام مختلف قيمة،`DSH Issue Management` خارج Issue لا يوجد Project نطاق جزء قاعدة تخطيط قيمة.

GitHub App عبر Project إذن بينما لا هو مجموعة نسج Issue Fields إذن وصول سياسة بيانات وصفية. حقل تعديل اسم أو نوع تغير سوف يجعل سير العمل فشل، بينما لن رجوع إلى قديم حقل.

فارغ قيمة قراءة جعل عبر معتاد إعادة محاولة إبقاء قوة انتظار.Project حقل تحديث لا يوجد مقارنة مقارنة و ضبط قبل رفع، لذلك معا مرجع نفس عدد Issue PR ممكن كل سوف مراقبة إلى فارغ Start Date، الأكثر بعد مرة mutation ممكن فوز خروج.
