# Agent Note: Windows Python runtime CI إبقاء في GitHub حمل إدارة Windows فوق

Status: implemented

[English](2026-09-06-python-runtime-windows-hosted.md) | العربية

## مشكلة

عند #3629 إضافة دخول لذا عائق تبديل اختيار جهاز و عمل عمل خاص Windows أداة سلسلة بعد،[build-exe-for-python-sdk.yml](../../../../.github/workflows/build-exe-for-python-sdk.yml) في Windows x64 هدف بدء مقابل تلقي معلومة مهمة PR CI عبر `DSH_CI_FAILOVER_WINDOWS=selfhosted` تحليل تشغيل جهاز. مشترك `dsh-win-ci` حوض و لم يجعل هذا عبر طريق أكثر يمكن اعتماد.2026-09-06(كل وقت متساو لـ UTC؛ كل مرة تشغيل كل تنفيذ #3629 ترحيل سير العمل اختيار جهاز، هذا اختيار جهاز ذاتي 07:56 دمج بدء توليد فاعلية): تثبيت بعد wheel خطر دخان اختبار في 09:12 في `dsh-win-ci-16` فوق لـPR #3640(`ci/benchmark-standard-runner`) الأكثر أول فعلي قياس إصلاح حجز (run 34023970384) عبر، مع بعد 10:06 في `dsh-win-ci-21` فوق لـPR #3337(`feat/visualizer-host-plugin`) (run 34026500701) فشل،10:46 في `dsh-win-ci-04` فوق لـPR #3640 نهائي فعلي قياس إصلاح حجز (run 34028339888, job 101473395734) فشل——`smoke_sdk_profile_plugin` تحزيم `dsh plugin add` عملية فرعية بلا إخراج أي خروج، بينما هذا مرة تشغيل Linux و macOS وحدة متساو عبر؛11:29 عمل عمل إعادة محاولة مجددا مرة ظهور نفسه بلا صوت ميت هلاك. ترحيل رفع سجل (#3629) إبقاء `proposed`، لأن ذلك ابتلاع إخراج كمية و مشترك سالب تحميل تحقق استلام معيار من لم فعلي قياس.

## قرار

Windows x64 هدف بداية نهاية استخدام حمل إدارة `matrix.runner`——PR CI لـ `windows-2025`——إعداد بـ معيار setup-python أداة سلسلة،pnpm ذاكرة مؤقتة استعادة و pkg ذاكرة مؤقتة. قدوم ذاتي #3629 لذا عائق تبديل اختيار جهاز، عمل عمل خاص Python دقيق تجهيز خطوة، ذاتي حمل إدارة اعتماد تثبيت و بعد وضع تنظيف، خاص دقيق تجهيز نص برمجي و توجيه اختبار متساو يتم إزالة.`DSH_CI_FAILOVER_WINDOWS=selfhosted` مجددا مرة فقط إعادة تحديد نحو [ci.yml](../../../../.github/workflows/ci.yml) في أصلي Windows عمل عمل؛[لذا عائق تبديل يد سجل](2026-07-26-ci-failover-runbook.zh.md) و [python/development.zh.md](../../../../python/development.zh.md) وصف فقط حمل إدارة runtime بناء. ترحيل في UTF-8 نمط توجيه خروج لـ الذي بـ وجود، هو لأن حمل دائم رئيسي آلة استخدام GBK افتراضي شفرة صفحة؛ حمل إدارة مرآة مثل توفير هذا عبر طريق هذا قبل تشغيل منطقة مجال ضبط.

## قد اعتبار بديل خطة

**إبقاء لذا عائق تبديل توجيه.** لا اعتماد: مشترك حوض نفس يوم اثنان مرة تكرار الآن نفسه تثبيت بعد wheel عملية فرعية بلا صوت ميت هلاك، بينما ترحيل بيان ابتلاع إخراج كمية تحقق استلام ما زال معلق وضع؛ و كما يأخذ صحيح تأكيد صفة عبر طريق توجيه دخول لذا عائق تبديل حالة، سوف جعل ذلك اقتران دمج إلى غير متصل حوض لذا عائق فتح صلة.

**تعديل لـ إصلاح مشترك حوض.** تسليم من حوض تشغيل صيانة من معالجة: مراقبة قياس إلى فشل هو بلا إخراج أي خروج عملية فرعية، بينما غير مرآة مثل قبل وضع شرط ناقص؛ نفس مرآة مثل أيضا خدمة أصلي Windows لذا عائق تبديل عمل عمل.

**في حمل إدارة مرآة مثل فوق إبقاء عمل عمل خاص أداة سلسلة.** لا اعتماد: خاص uv/Python تحت تحميل وجود إدارة من هو لا تعديل حمل دائم مشترك رئيسي آلة؛ مرة صفة حمل إدارة مرآة مثل قد توفير ترحيل قبل عبر طريق استخدام قد تسجيل Python 3.10 أداة سلسلة.

## عاقبة

كل رمز دمج شرط سحب أخذ طلب مجددا مرة لـ runtime بناء دعم دفع GitHub حمل إدارة Windows سعة كمية، عمل عمل خاص دقيق تجهيز و تنظيف آلية (يشمل محدود نظام الملفات إعادة محاولة) مع عبر طريق واحد نفس إزالة. تسليم تبديل قدوم هو كل مرة بناء تشغيل في حمل معيار أداة سلسلة و حمل إدارة ذاكرة مؤقتة مرة صفة رئيسي آلة فوق، كما Windows لذا عائق تبديل فتح صلة فقط تغطية ترحيل قبل وثيقة الذي وصف أصلي Windows عمل عمل. لم قدوم ذاتي حمل إدارة محاولة تجربة يجب في أي توجيه تغيير قبل، مقابل فعلي حوض إعادة تحقق ابتلاع إخراج كمية و فشل يمكن تكرار الآن صفة، و كما يجب إعادة بناء قد تراجع دور #3629 رفع سجل سجل قيد:setup-python Windows تثبيت جهاز سوف حذف مطابقة آلة جهاز/حالي مستخدم تثبيت سجل و لـ كل مستخدم تثبيت (خاص أداة ذاكرة مؤقتة لا يمكن عزل هذه سجل التسجيل حالة) ، كل بناء ذاكرة مؤقتة و مؤقت اختبار أصل دليل يجب عمل عمل خاص و استخدام نسخ استيراد بينما غير مشترك store رابط، تنظيف يجب في نجاح، فشل و إلغاء مسار فوق بـ محدود Windows نظام الملفات إعادة محاولة تنفيذ، كما فقط لديه Windows x64 هدف يمكن نقل غرس——Linux هدف manylinux فحص حاجة Docker.
