# Agent Note: GitHub أصلي كومة تراكم و اختياري PR rebase

Status: implemented

[English](2026-08-02-native-github-stacks-and-optional-rebases.md) | العربية

## مشكلة

فقط بـ base فرع يمثل اعتماد PR(Pull Request) سلسلة لا يوجد رسمي جهة كومة تراكم هوية. يلزم يجعل هو سقوط أرض، حينئذ يجب تدريجي عدد يد حركة دمج PR، إبقاء في بين فرع، ضبط كامل كل فرعي PR base، و إعادة فحص إثبات هذا بند سلسلة هل ما زال كامل.GitHub أصلي كومة تراكم PR وظيفة فإن سوف تحمل تحميل ترتيب، مقابل كل واحد طبقة تطبيق trunk قاعدة و CI، و مسؤول ذاتي قاع نحو فوق دمج و base ضبط كامل.

واحد عام منع توقف تعديل كتابة قد مراجعة فرع، أيضا سوف ترتيب حذف أصلي `gh stack` تزامن سير العمل: هذا سير العمل عبر درجة ربط rebase تحديث كل نشط وثب طبقة، و في lease حفظ حماية تحت إصدار. إذا فقط في كومة تراكم خارج فعلي تطبيق هذا بند منع أمر، حينئذ سوف يجعل مستقل PR و كومة تراكم PR وجه قرب لا متسق تاريخ اختيار.

## قرار

نفس مستودع داخل من اثنان عدد أو أكثر كثير عدد متبادل متبادل اعتماد PR مجموعة صار كل بند سلسلة، في سقوط أرض قبل كل يجب استخدام GitHub رسمي جهة stack كائن. بـ فوري `PullRequest.stack` و `stackEntry.position` حقل لـ مرجعي اعتماد حسب. مقابل في بعد لم شكل صار رسمي جهة كومة تراكم كما كل PR عمل من نفسه سلسلة، نظام استخدام `gh stack link` حسب ذاتي قاع نحو فوق ترتيب تلقائي صلة ربط؛ عمل من لا واحد أو عمل من معلومة غير ممكن استخدام وقت، يجب أخذ نيل مستخدم تأكيد. نقص قليل أصلي دعم حمل أو عبر fork سلسلة سوف جعل مسار صلب صفة إيقاف. إذا قائم عضو يخص متبادل متبادل اندفاع مفاجئ كومة تراكم، أو من رسمي جهة ترتيب و فرع توسيع اندفاع لا متسق، فإن في حل تفرق أو إعادة بناء أي كومة تراكم قبل كل يجب أخذ نيل مستخدم إشارة عرض.

«سقوط أرض كومة تراكم» عبر `gh stack merge <stack-number> --yes --merge` دمج كامل رسمي جهة كومة تراكم. جزء سقوط أرض حاجة واضح إشارة تحديد حد PR، و دمج من قاع جزء إلى هذا PR بادئة. سير العمل أبدا رجوع إلى تدريجي عدد تنفيذ `gh pr merge` و يد حركة ضبط كامل base. أصلي مباشر دمج يلزم ما الكل نجاح، يلزم ما الكل لا دمج؛ دمج طابور صف ممكن قسم مجموعة معالجة الذي اختيار PR، لذلك فقط لديه كل الذي اختيار PR كل قسم آخر بلوغ إلى `MERGED`، سقوط أرض عندئذ حساب إتمام.

merge-forward و rebase كل يمكن بصفة مستقل PR و رسمي جهة كومة تراكم PR تاريخ تحديث جديد طريقة، يشمل مراجعة بعد. تعديل كتابة بعيد طرف تاريخ وقت، يجب استخدام دقيق lease أو تلقي lease حفظ حماية `gh stack` دفع إرسال مسار؛ إذا بعيد طرف قد حدوث تغير، عملية يجب في توقف. منع توقف مباشر استخدام `--force`.[زيادة كمية تحديث base قرار](../../archived/process/2026-07-26-incremental-pr-base-retargeting.md) ما زال مسؤول merge-forward خيار.

متبادل صلة فحص عبر معتاد في إصدار قبل تشغيل.`gh stack sync` هو واضح مثال خارج، لأن هو في مرة عملية في إتمام نيل أخذ، درجة ربط rebase و دفع إرسال: مع بعد قيام أي تحقق كل قد تعديل كتابة طبقة؛ هذه تحقق عبر قبل، لا نيل دمج أي تلقي أثر PR. كل مرة تعديل كتابة دفع إرسال بعد، كل يلزم إعادة مراجعة حساب حالي head، لم حل قرار مراجعة خط مسار، دفعة دقيق حالة، يمكن دمج صفة و فحص نتيجة، لأن أولا قبل commit OID و داخل ربط مرساة نقطة ممكن قد مرور وقت.

## تحقق

[كومة تراكم سقوط أرض skill(تقنية قدرة)](../../../skills/dsh-merging-stacked-prs/SKILL.md) تحقق أصلي دعم حمل، نفس مستودع فرع، فوري عمل من معلومة، رسمي جهة عضو علاقة و ترتيب، دمج نطاق و نهائي دمج حالة.[كومة تراكم مراجعة إشارة جنوب](../../../../docs/cookbook/responding-to-pr-review-on-a-stack.ar.md) يجعل إصلاح إبقاء في جذب دخول مشكلة طبقة، و شمول غطاء اثنان نوع لأجل نقل بث إصلاح تاريخ سياسة.[دفع إرسال قبل سير العمل](../../../skills/dsh-pre-push-checks/SKILL.md) مسؤول lease حفظ حماية و تزامن بعد قيام أي تحقق الذي نيل دليل.

## سبق اعتبار بديل خطة

**فقط بـ فرع سلسلة يمثل كومة تراكم.** هذا نوع فعل قاعدة إبقاء يد حركة مسار، لكن GitHub لا يوجد stack كائن متاح في عرض ترتيب، مقابل كل واحد طبقة تنفيذ trunk قاعدة أو بـ أصل فرعي عملية دمج كامل نطاق.

**اعتماد أصلي كومة تراكم، لكن منع توقف في مراجعة بعد استخدام ذلك rebase أمر.** هذا سوف إبقاء commit OID مستقر، لكن أيضا سوف في كومة تراكم صحيح في قبول مراجعة وقت منع استخدام رسمي جهة تزامن مسار، و يجعل مستقل PR التزام دوران مختلف سياسة سياسة.

**اشتراط كل مرة تحديث جديد PR كل استخدام rebase.** خط صفة تاريخ جدا لديه قيمة قيمة، لكن عند حفظ قد إتمام اندفاع مفاجئ حل قرار و ذلك استعادة نقطة مقارنة ضيق تجميع تاريخ أكثر إعادة يلزم وقت، دمج فحص نقطة ما زال هو صالح اختيار.

**تلقائي حل تفرق متبادل متبادل اندفاع مفاجئ كومة تراكم.** هذا سوف يجعل محلي فرع دفع قطع تجاوز قيادة في مشترك GitHub بيانات وصفية لـ فوق، و ممكن جاف إزعاج الذي طلب سلسلة خارج PR أو عمل من؛ قد دمج أو دخول طابور صف بند لا واحد تحديد كل قدرة إزالة.

## عاقبة

- مراجعة من و تلقائي تحويل سوف نيل نيل GitHub كومة تراكم رسم، تغطية كامل كومة تراكم قاعدة،CI و أصلي دمج حالة.
- نفس عمل من متروك إبقاء سلسلة بلا حاجة مقدار خارج استفسار سؤال يكفي يصبح رسمي جهة كومة تراكم؛ سلسلة من كثير اسم عمل من مشترك نفس يملك أو بيانات وصفية حدوث اندفاع مفاجئ وقت، ما زال إبقاء شخص عمل قرار حد.
- مراجعة بعد،rebase ممكن جعل commit hash، دفعة دقيق حالة أو تقييم نقاش مرساة نقطة بطلان، لذلك كل مرة تعديل كتابة دفع إرسال بعد كل يلزم مقابل فوري مراجعة حالة و فحص نتيجة إجراء مراجعة حساب.
- `gh stack sync` ممكن قصير مؤقت إصدار محلي تحقق ما زال انتظار إتمام شفرة؛ تلقي أثر PR في تزامن بعد قيام أي تحقق عبر قبل ما زال منع توقف دمج.
- merge-forward ما زال متاح، و بـ زيادة دمج إيداع لـ بديل قيمة إبقاء قد إتمام فحص نقطة.
