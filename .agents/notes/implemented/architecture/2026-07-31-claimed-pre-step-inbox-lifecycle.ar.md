# Agent Note: في مفرد واحد pre-step قرار قبل قيادة أخذ inbox إدخال

Status: implemented

[English](2026-07-31-claimed-pre-step-inbox-lifecycle.md) | العربية

## مشكلة

حلقة هذا قبل يأخذ واحد خطوة حد تفكيك صار نص التوجيه دقيق تجهيز، نص التوجيه دقيق دخول و سلسلة سطر خطوة خطاف. دقيق دخول نتيجة يمكن إبقاء أو إسقاط قد قيادة أخذ إدخال، فوري طابور صف حدث أيضا يحمل و حمل دائم inbox حالة تكرار بيانات بنية. إضافة لا نيل لا في تعديل inbox، تعديل كتابة قد إيداع دفعة مرة و مباشر إلحاق جلسة تاريخ بين اختيار، بينما مراقبة جهة لا يمكن اعتماد واحد طقم واضح ترتيب.

مفرد مرة ظهور مخصص تابع inbox حزمة تركيب طبقة أيضا تكرار كل `UserMessage` قد لديه معرف. هو يأخذ إدراج دخول، تحرير، قيادة أخذ، إلغاء، إعادة وصل إسقاط و خطوة دخول دمج صار واحد طقم بروتوكول، لكن فقط إلحاق جلسة هذا حينئذ يملك حمل دائم طابور صف إسقاط.

## قرار

كل محاكاة اقتراح خطوة قبل، حلقة حزمة داخلي `ReactLoopInbox` سوف أصل فرعي قيادة أخذ كامل دفعة مرة: الكل `next-step` رسالة، و جولة حد فوق واحد بند `next-turn` رسالة. في أول مرة حد، حلقة سوف أولا إيداع `turn/start`، جعل قيادة أخذ و ذلك وحيد مرة `agent/pre-step` قرار يملك حمل دائم جولة ملكية. قيادة أخذ سوف سجل مواصفة تحويل، لا حمل outcome صاف حذف `agent/inbox/spliced`، إبرة مقابل كل بند قد قيادة إلغاء خبر إرسال خروج مرة `agent/inbox/claimed { message, turn }`، و يأخذ وحيد احتلال دفعة مرة إرجاع إعطاء حلقة، من بعد من استخدام `{ turn, step, signal }` انتظار waterfall(شلال نشر صيغة حدث).

`PreStepDecision` لـ `{ kind: 'reject' } | { kind: 'enter'; messages: UserMessage[] }`.reject لن فتح خطوة، سوف يجعل قد قيادة أخذ دفعة مرة إبقاء قد حذف، و سوف جولة إغلاق لـ blocked، كما لا إنتاج أي خطوة حدث. فارغ enter، إلغاء و `step/start` قبل فشل نفس مثال سوف إغلاق واحد حد مستو توازن بلا خطوة جولة.enter توفير في `step/start` بعد بـ `user/message` إلحاق كامل دفعة مرة. حزمة تركيب `next()` مستمع سوف إبقاء تحت تنقل تغيير، حذف غير متعمد استبدال، لذلك الكل رسالة تعديل كتابة فقط في نهائي قيمة راجعة في مرة صفة تسوية. نظام لم يعد وجود `agent/prompt-prepare`،`agent/prompt-submit` أو `agent/step` نقطة توسيع.

حمل دائم inbox ما زال هو اثنان نسخة عبر `MessageId` بحث عنوان `UserMessage[]` قائمة.`append`،`prepend` و `splice` قبول target؛`replace(messageId, newMessage)` و `remove(messageId)` فإن في إيداع مواصفة تحويل splice قبل، عبر `MessageId` عبر اثنان نسخة قائمة تحديد موضع انتظار معالجة رسالة. استبدال يمكن تغيير معرف، و أولا سوف قديم رسالة بصفة discarded إصدار، مجددا سوف جديد رسالة بصفة inserted إصدار. كل مرة إدراج دخول إرسال خروج `agent/inbox/inserted { message }`؛ عادي حذف سجل `outcome: 'canceled'` تزامن خروج `agent/inbox/discarded { message }`. قيادة أخذ سجل لا حمل outcome صاف حذف، و من `ReactLoopInbox` إرسال خروج claimed حدث. هذه فوري حدث لا زيادة placement،outcome أو دفعة مرة حقل.

`Agent.inbox` فقط كشف لأجل قراءة و تغيير انتظار معالجة عمل بنية تحويل `Inbox` واجهة؛ فقط توفير حلقة استخدام `hasPending` و قيادة أخذ عملية لا في هذا عام واجهة فوق.dsh-agent-loop فقط بنية صنع واحد `ReactLoopInbox`، معا لأجل بنية تحويل أمر و مشغل عملية. أداة جسم بنية صنع دالة مباشر استقبال `SessionProjectionRegistry`، بينما لا هو أكثر عرض عام Cordis `Context`.`AgentLoop` في خدمة دورة الحياة داخل يحتفظ معيار إسقاط تسجيل، يجعل لا يوجد live Agent وقت بارد Inbox قراءة ما زال متاح؛`ReactLoopInbox` فقط قراءة و تغيير هذا مشترك حالة.

اثنان صنف حدث واجهة خدمة مختلف مستهلك. تتبع أثر مفرد بند رسالة مراقبة جهة استخدام `agent/inbox/inserted`،`claimed` و `discarded`.`AgentLoop` في حمل دائم `agent/inbox/spliced` تدفق فوق مساهمة معيار `inbox` إسقاط؛UI تحرير و إزالة عبر Inbox تغيير طريقة معالجة، من بينما يجعل نفس إسقاط سجل كل تغير. هذا إسقاط إعادة بناء حمل دائم تاريخ وقت، سوف رفض لا أمان أو تجاوز حد جلوس علامة، و عبر اثنان نسخة قائمة تكرار `MessageId`، و تقرير إبلاغ خروج خطأ حدث seq. كامل جسم طابور صف control مستهلك استخدام عام إسقاط تغيير تدفق، مباشر قراءة كامل Inbox قيمة.

يجب مقابل حالي خطوة إجراء أصل فرعي تعديل كتابة إضافة من `agent/pre-step` إرجاع رسالة. فقط حاجة قليلا بعد سياق إضافة يمكن مباشر تعديل `agent.inbox`.Workspace context معا استخدام اثنان بند مسار: مختلف خطوة نظام الملفات إسقاط سوف مؤقت تخزين واحد بند يمكن استبدال `next-step` رسالة، بينما تحت مرة دخول خطوة pre-step سوف يأخذ هذا رسالة أو جديد تركيب أساس خط طي دخول نهائي دفعة مرة، و إزالة ما زال انتظار معالجة فرعي هذا.reject سوف يجعل هذا بند متابعة ترتيب طابور.

قد عودة ملف[يمكن بحث عنوان طابور صف بند قرار](../../archived/feature/2026-07-29-addressable-queue-operations.md) وصف قد يتم يحل محل مفرد مرة ظهور حزمة تركيب طبقة تصميم.`MessageId` مسؤول بحث عنوان، بينما `AgentLoop` يأخذ `inbox` بصفة حمل دائم splice فوق معيار جلسة إسقاط مساهمة إعطاء إسقاط سجل التسجيل. عام إسقاط نقل طبقة سوف سوف هذا طي نتيجة لأجل فوري تحديث، تاريخ ذيل صفحة إعادة وصل أساس خط و بارد عملية إعادة بدء استعادة، بلا حاجة live Agent مرآة مثل.

## سبق اعتبار بديل خطة

**إبقاء قسم مغادرة prepare و admit خطاف.** هذا مثال دقيق تجهيز مرحلة مقطع يمكن في قيادة أخذ قبل تعديل inbox، دقيق دخول مرحلة مقطع يمكن في قيادة أخذ بعد تعديل كتابة، لكن نفس حد سوف ظهور اثنان عدد ترتيب جدول وجه، إلغاء ملكية أيضا سوف تغيير نيل نموذج غامض.

**reject وقت يأخذ قد قيادة أخذ دفعة مرة إعادة دخول طابور.** هذا نظر يشبه إبقاء إعادة محاولة سلوك، لكن سوف يجعل مرفوض خفي صيغة تعديل طابور صف؛ إذا لا لـ كل تنافس حالة إضافة محيط شريط، أيضا سوف نسخ لاحق عمل، و جعل claim لا يمكن يصبح أصل فرعي كل حق تحويل نقل.

**في كل فوري حدث فوق يحمل placement و outcome.** حمل دائم splice قد يملك هذه واقع. فوري إشعار تكرار هو جمع سوف بناء قيام ممكن عائم نقل ثاني نسخة اتفاق، بينما يحتفظ تأكيد قطع رسالة معرف مستهلك و لا حاجة هذه حقل.

## تحقق

agent loop(ذكي جسم حلقة) تغطية ثابت أولا `turn/start`، مجددا قيادة أخذ، بعد pre-step ترتيب، فوري حدث تأكيد قطع تحميل حمل، حد مستو توازن بلا خطوة reject، نهائي دفعة مرة تعديل كتابة، قيادة أخذ بعد إدراج دخول إدخال، مستمع فشل، إلغاء، وAgent إزالة بعد Inbox ما زال يمكن قراءة، و AgentLoop إزالة وقت إزالة إسقاط.Inbox و مستهلك اختبار ثابت صاف قيادة أخذ حذف، عادي حذف canceled نتيجة،agent-instructions مؤقت تخزين، استبدال و نفس خطوة دخول،plan/goal/خطاف سلوك،UI تنظيف، ضغط (compaction) ، فحص نقطة، استعادة بعد حمل دائم إسقاط، مقابل غير قاعدة حمل دائم جلوس علامة أو عبر قائمة تكرار معرف رفض، و controller مبكر في إسقاط سجل التسجيل تسجيل وقت ما زال استخدام طي بعد طابور صف قيمة. فقط لديه عند حمل دائم صفة لا يخص اختبار كائن وقت، مستهلك مجال اختبار عندئذ استخدام عملية داخل Inbox وتد؛ قيادة أخذ، حمل دائم إسقاط، استعادة، تحقق و فوري إشعار اختبار عبر إنتاج AgentLoop اختبار harness إنشاء Agent، لذلك اختبار دعم حمل شفرة لن إعادة تنفيذ هذا إسقاط. توليد حدث و نوع دليل فقط عام جديد waterfall و تحميل حمل.

## عاقبة

حلقة في كل خطوة قبل فقط لديه واحد يحتاج انتظار قرار، مقابل إدخال أيضا فقط لديه مرة كل حق تحويل نقل. قد قيادة إلغاء خبر لن خفي صيغة إرجاع inbox؛ لاحق إدراج دخول إبقاء مستقل. فوري حدث و أخرى inbox إشعار إبقاء مقابل تسمية، لكن لا مرآة مثل حمل دائم بيانات وصفية؛ إضافة يمكن صريح اختيار دقيق حالي خطوة تعديل كتابة، أو عادي لاحق inbox إلقاء تمرير.
