# Agent Note: أصلي owner استلام سعة هروب هروب subprocess بعد بديل

Status: implemented

[English](2026-08-28-subprocess-native-containment.md) | العربية

## Problem

detached POSIX عملية مجموعة،Windows direct-parent مرة تاريخ و PTY بعد بديل مسح فقط قدرة وصف ما زال يمكن عبر بعض نوع عملية علاقة مراقبة إلى عضو. عملية فرعية يمكن استدعاء `setsid`، حدوث reparent، أو مقارنة direct parent تخزين نشط أكثر دائم و مغادرة فتح هذه range، لذلك إنهاء جدول وجه عملية شجرة بعد، عمل، طرف فتحة أو ملف ما زال ممكن إبقاء نشط وثب.direct target result أيضا لا يستطيع إثبات الكل بعد بديل قد إيقاف.

عادي subprocess جملة مقبض لا يمكن عبر إصدار PID حل قرار هذا عدد نقص فتحة.Linux scope setup و Windows Job runner سوف مختلف خطوة بناء قيام target identity،PID لا يمثل كامل managed range، مستهلك أيضا سوف يتم إجبار دفع قطع startup هل قد إيداع. لذلك، عام مشترك نتيجة،range ownership، خاص بدء بروتوكول و تحزيم مدخل حاجة كل منها واضح owner.

## Decision

`LocalSubprocessRuntime` سوف في target تنفيذ قبل اختيار واحد provider خاص managed-range owner. رمز دمج شرط Linux عادي أمر و PTY دخول مؤقت user-systemd scope؛ رمز دمج شرط Windows عادي أمر دخول من خاص runner يملك unnamed kill-on-close Job. لا دعم حمل مضيف استخدام قائم مقارنة ضعيف fallback، و في provider دورة الحياة داخل فقط تحذير إبلاغ مرة. اختيار تحديد native مسار واحد حالما ممكن قد تنفيذ target،provider أبدا إعادة وضع target.

عادي `SubprocessHandle` لا يوجد PID أو عام مشترك startup حالة.`.done` تقرير إبلاغ direct target result أو startup/provider failure،`terminate()` نحو الذي اختيار range إرسال إشارة،`waitForExit()` فقط لديه في نفس range يتم إثبات لـ فارغ بعد عندئذ نجاح.`SubprocessTerminalHandle.pid` متابعة يخص طرفية اتفاق، لأن PTY identity و قبل منصة فحص حاجة هو.

### Linux scope و one-shot bootstrap

نفس runtime رقم مرة رمز دمج شرط Linux عادي أو PTY استدعاء سوف عميق دخول فحص دقيق تأكيد runner مدخل،libc `execve` و `fcntl` bindings، يمكن قراءة user manager و إبقاء literal argv transient-scope دعم حمل. فشل عميق درجة probe سوف إعادة محاولة، رقم مرة نجاح فإن سوف ذاكرة مؤقتة. بعد كل مرة رمز دمج شرط استدعاء ما زال سوف في target تنفيذ قبل خفيف كمية فحص user manager هل يمكن بلوغ.native مسار واحد حالما اختيار تحديد،scope، بروتوكول، حالة استعلام أو pre-exec failure كل من هذا مرة بدء تقرير إبلاغ، أبدا تبديل إلى fallback.

parent إنشاء واحد 0700 دليل، منها كامل 0600 `launch-request.json` حفظ نهائي target cwd و بيئة. خاص `DSH_SUBPROCESS_RUNNER` قيمة مسؤول تحديد موضع هذا request،runner فإن من provider cwd و bootstrap-safe بيئة بدء.`systemd-run --user --scope --quiet --collect --expand-environment=no` أولا يأخذ ذاته عملية تسجيل إلى scope، مجددا من one-shot bootstrap حذف و تحقق request، تبديل إلى target cwd، استعادة كامل target بيئة، حسب target PATH قاعدة تحليل عار يمكن تنفيذ ملف، صاف حذف fd 0 حتى fd 2 `FD_CLOEXEC`، و استخدام أصلي argv استدعاء libc `execve()`.bootstrap سوف أصل أرض يصبح target و إبقاء وراثة stdio، لا بصفة معتاد إقامة supervisor.

request يتم إزالة استهلاك أو manager قد مراقبة إلى loaded unit كل قدرة بناء قيام scope ownership. في هذا اثنان بند واقع ظهور قبل، فقط يلزم direct launcher ما زال في تشغيل،unit absence حينئذ إبقاء لم قرار. إذا launcher خروج وقت request ما زال لم إزالة استهلاك،direct result سوف بـ startup failure reject، حذف غير فعلي مراقبة إلى إشارة مطابقة launcher ما زال في وقت التشغيل طلب إنهاء إشارة. عادي عملية و PTY عملية لقاء إلى مطابقة إشارة وقت كل سوف إبقاء فعلي خروج نتيجة؛ قد سجل startup error بداية نهاية أولوية.launcher قد خروج كما unit لا وجود وقت،range observation سوف مستقل تسوية empty-range wait.parent كل 50 مللي ثانية فحص مرة هذا مقطع لم قرار منطقة بين؛ بناء قيام بعد، حالة استعلام حسب إشارة عدد زيادة طويل بين فصل تراجع تجنب، الأكثر كثير بلوغ إلى قائم 5 ثانية systemctl حد أعلى. كل مرة استعلام قراءة `LoadState`،`ActiveState` و `TasksCurrent`:loaded `inactive` أو `failed`، و قد بناء قيام unit تغيير لـ `not-found`/`inactive` أو يتم collect إزالة، كل قدرة إثبات range لـ فارغ.`active`،`activating`،`reloading` و `deactivating` ما زال هو غير نهاية حالة؛ مثال خارج هو: واحد حالما طلب مرور إنهاء، كما launcher قد خروج أو bootstrap قد إزالة استهلاك ذلك request، تقرير إبلاغ لا يوجد أي عملية لكن ما زال active unit حينئذ هو فارغ range.request إزالة استهلاك إثبات payload قد دخول scope، لذلك أي جعل Node بعد لم استلام إلى مباشر عملية خروج إشعار، صفر عضو أيضا قدرة إثبات تماما توقف مستقر.request لم إزالة استهلاك وقت ما زال يجب انتظار launcher خروج——manager فقط في مراقبة قياس إلى populated→empty تحويل تغيير وقت عندئذ انتهاء scope، لذلك دخول cgroup قبل حينئذ يتم قتل ميت payload دائم بعيد لن إطلاق هذا تحويل تغيير. هذا حكم تحديد سوف stop إسقاط هذا عدد متروك إبقاء unit، جعل transient unit لن تراكم تراكم؛ لم فوق تقرير أو لـ `[not set]` عملية عدد ما زال نظر لـ لم معرفة و متابعة انتظار. لم معرفة أو malformed تركيب و غير ممكن قراءة manager نتيجة سوف جعل `waitForExit()` reject، بينما لا هو إعلان تسمية تماما توقف مستقر.`terminate()` سوف نداء تنبيه جارٍ راحة نوم observer قيام أي تكرار فحص، تسوية وقت سوف إلغاء لم فوز خروج تراجع تجنب sleep. صارم إطار نفس دليل `startup-error.json` فقط تحمل تحميل request/bootstrap أو target pre-exec failure،parent سوف في يمكن مراقبة دورة الحياة إتمام وقت إزالة هذا مرة spawn خاص مسار.

عادي target result ما زال قدوم ذاتي نفس عدد child process.PTY مسار إعادة استخدام نفس request و bootstrap، لكن لا زيادة معتاد إقامة runner، لذلك `node-pty` PID، عملية مجموعة،session leader، تحكم طرفية، قبل منصة `inputWaiting`،`/dev/tty`،readiness و direct terminal outcome إبقاء قائم يحتوي معنى، معا scope membership تغطية `setsid` و reparent بعد بديل.

### Windows runner و Job

Windows parent من bootstrap cwd و بيئة بدء provider runner، يأخذ أصلي target argv وضع في خاص `--` قسم فصل رمز بعد، و انتظار Node runner `spawn` حدث بعد عندئذ إرسال تماما جيد واحد بند start request.runner في spawn قبل تقرير خطأ وقت،direct launch failure سوف أصل مثال إبقاء، معا إثبات Job range من لم وجود، لذلك empty-range wait نجاح؛spawn بعد infrastructure failure ما زال هو لا تحديد حالة، سوف جعل range settlement reject. حذف هذا خارج،Node IPC أيضا تحمل تحميل قوة انتظار terminate control و تماما جيد واحد result.runner fd 0 حتى fd 2 متبادل متبادل عزل،fd 3 تحمل تحميل IPC،fd 4 حتى fd 6 تحمل تحميل target stdin،stdout و stderr. تجاهل اختصار stdin وقت،fd 4 وراثة منصة null-device descriptor؛ أخرى نمط استخدام pipe. مشترك Win32 طبقة عبر Node تصدير `uv_get_osfhandle()` يأخذ fd 4 حتى fd 6 خريطة لـ OS handle، رفض null و Koffi كشف unsigned `UV_INVALID_OS_FILE_HANDLE` و `UV_INVALID_FILE_DESCRIPTOR` sentinel، مؤقت تفعيل صالح handle وراثة، و عبر `STARTF_USESTDHANDLES` نقل دخول.`spawnCurrentTokenJobProcess` اشتراط مفرد وحيد تحليل `applicationName` و كامل target بيئة، و استخدام `CREATE_UNICODE_ENVIRONMENT` نقل دخول ترتيب، مزدوج NUL ربط ذيل UTF-16LE كتلة، منها يشمل `=X:` مشغل بند، بينما لا تعديل runner بيئة.suspended target دخول Job و استعادة بعد،runner فقط إغلاق fd 4 حتى fd 6؛ هو أبدا تعديل كتابة أو إلغاء تدمير Node معيار تدفق.parent يأخذ pipe carrier stream بصفة عادي جملة مقبض stdio إرجاع، مستخدم بايت أبدا مرور مرور IPC.

runner هو target process handle و unnamed Job handle وحيد owner.`spawnCurrentTokenJobProcess` بـ suspended حالة إنشاء target، يأخذ هو قسم إعداد إعطاء لا سماح active breakaway kill-on-close Job، و فقط في قسم إعداد بعد استعادة.runner جولة استفسار direct process نيل أخذ target exit code، و جولة استفسار Job نيل أخذ active-process count. فقط لديه direct result قد عبر IPC send callback تسليم كما Job قد تقرير إبلاغ صفر active process بعد،runner عندئذ نجاح خروج؛parent فقط يأخذ هذا مرة clean exit خريطة صار نجاح `waitForExit()`.

parent سوف في استلام إلى مرور مرور تحقق، فقط يحتوي عدد حرف `target-exit` وقت قيام أي دائم دائم قفل تخزين هو، هذا وقت قائم stdout/stderr close أو محدود drain barrier ممكن بعد لم إتمام.`.done` فقط متابعة انتظار هذا stdio barrier، مع بعد إرجاع قد قفل تخزين نتيجة. لاحق Job query،range settlement failure،IPC loss أو runner استثناء خروج فقط سوف جعل `waitForExit()` reject، لا يستطيع استبدال direct result. في صالح target result وصول قبل حدوث infrastructure failure عندئذ سوف جعل `.done` reject، لكن هذا rejection لن شرح target هل قد بدء تنفيذ.disconnect أو result-send failure سوف يجعل runner إيقاف بروتوكول عمل، إنهاء و إغلاق ذاتي ذات وحيد Job handle، لكن بعد بـ غير صفر حالة خروج. الأكثر بعد واحد Job handle إغلاق سوف إنهاء باق بقية عضو، لكن لن يأخذ disconnected مسار تعديل كتابة صار نجاح تماما توقف مستقر إثبات.

### خاص قسم إرسال و بروتوكول

source بدء عبر TypeScript source launcher تنفيذ حزمة داخل runner مدخل،built بدء تحليل `@deepseek-ai/dsh-subprocess-local/runner` export،Python SDK مفرد ملف يمكن تنفيذ برنامج فإن من [`python/sdk-runtime/runtime-bootstrap.mjs`](../../../../python/sdk-runtime/runtime-bootstrap.mjs) دخول. هذا bootstrap من Python runtime يملك؛ خاص selector لا وجود وقت، هو استدعاء عام مشترك CLI export؛ لا فإن سوف حذف selector، و قسم إرسال إلى نفس subprocess runner core. عام مشترك `dsh` معامل محلل لا يوجد إخفاء runner mode،`apps/cli` فقط بناء عام مشترك مدخل، تحزيم أيضا لا توفير ثاني عدد Node يمكن تنفيذ برنامج.

selector هو per-spawn locator أو sentinel، لا هو اعتماد أو حمل دائم صيغة.Linux استخدام واحد صارم إطار request و واحد اختياري صارم إطار startup-error ملف.Windows استخدام واحد بند IPC channel، تحمل تحميل إغلاق تجميع `start` و `terminate` request، و تماما جيد اثنان عدد result فرع: فقط يحتوي عدد حرف `exitCode` `target-exit`، و لا بد يحتوي `name`،`message` كما فقط سماح اختياري `code`،`syscall`،`path` `error`؛parent سوف إرسال توليد `signal: null`. إيداع قبل إلغاء استخدام نفس نوع عادي `error` record. إلغاء reason لا عبر wire نقل تمرير، لذلك parent cancellation latch سوف أصل مثال استعادة رقم واحد محلي reason، يشمل `null` أو `undefined`. ناقص، مقدار خارج، نوع خطأ أو لم معرفة حقل كل سوف fail closed.target بيئة يمكن يتضمن selector اسم و ذلك Windows كبير صغير كتابة تغيير جسم، لأن provider سوف مفرد وحيد نقل تمرير target حالة، و كما فقط في خاص اختيار قيمة إزالة استهلاك بعد عندئذ استعادة هذا حالة.

### Fallback و cleanup

دقيق تأكيد bootstrap، الآن بديل كما يمكن قراءة user-systemd manager، أو إبقاء literal argv scope غير ممكن استخدام وقت،Linux سوف في target تنفيذ قبل دخول fallback.runner مدخل،Win32 bindings أو current-token Job probe غير ممكن استخدام وقت،Windows عادي بدء سوف دخول fallback.macOS عادي بدء،Windows ConPTY و أخرى لا تلقي دعم حمل مضيف إبقاء قائم PGID،`taskkill /T` أو حمل هوية محيط شريط PTY مراقبة آلية.warning سوف واضح شرح: هروب مغادرة هذه يمكن مراقبة علاقة بعد بديل لا حفظ إثبات يتم إنهاء، أيضا لا حفظ إثبات تأخير متأخر `waitForExit()`.

صحيح معتاد Cordis dispose سوف مستقل بدء direct-result و range observation، طلب إنهاء، و انتظار كل ذاتي لديه range. مستهلك teardown لا فحص عادي PID؛ هو سوف إبقاء أصلي operation أو startup error، معا محاولة تجربة terminate و final wait، و حسب مستهلك قائم خطأ ترتيب إبقاء cleanup failure.range واحد حالما يتم تأكيد لـ فارغ، حينئذ سوف دائم دائم منع توقف لاحق نحو قديم قديم identity إرسال إشارة.

في JavaScript يمكن مراقبة host exit خلال،`LocalSubprocessRuntime` سوف تزامن قوي صنع إنهاء كل ما زال تخزين نشط جملة مقبض، لا استخدام Promise أو timer.Linux سوف إرسال قائم direct fallback kill و دقيق تأكيد scope kill؛Windows سوف إنهاء runner، جعل ذلك وحيد Job handle إغلاق؛PTY fallback مسح ما زال هو best effort. كل جملة مقبض فشل متبادل متبادل عزل، أيضا لا تغيير مضيف خروج نتيجة.JavaScript لا يمكن تشغيل إنهاء شكل لا يخص هذا listener حفظ إثبات.

## Verification

مضيف خروج تنظيف fixture مقابل مقارنة provider في disposal قبل بعد مستمع هوية، و تحقق مستقل تسجيل خروج مستمع ما زال وجود. عملية مستمع مجموع عدد لا يمكن إثبات provider تنظيف إتمام، لأن أخرى عملية دورة الحياة معالج ممكن في provider بنية صنع بعد تسجيل.

- provider و Linux بروتوكول اختبار طقم عنصر ثابت تزامن NUL رفض حدوث في بدء فرعي أثر قبل، صارم إطار request/error حل رمز،target cwd و كامل بيئة استعادة، خاص متغير اصطدام اصطدام، إبقاء argv كما مقابل symlink حساس شعور PATH مرة تاريخ، لـ وراثة stdio صاف حذف close-on-exec،pre-exec error ownership، فشل عميق درجة probe إعادة محاولة و نجاح عميق درجة probe ذاكرة مؤقتة و تدريجي استدعاء manager فحص، ثلاثة نوع scope بناء قيام حالة (يشمل request لم إزالة استهلاك وقت طلب إنهاء و معنى خارج خروج) ،`LoadState`/`ActiveState`/`TasksCurrent` تحليل، تحرير يتم إبقاء في active كما لا يوجد أي عملية متروك إبقاء scope(وصل نفس client ما زال تخزين نشط، لم طلب إنهاء و عملية عدد لم فوق تقرير ثلاثة نوع حال شكل) ،`reloading`، حمل لم فوز خروج delay إلغاء terminate wake-up، بناء قيام بعد لديه حد أعلى تراجع تجنب، و PTY managed-owner تماما جيد مرة cleanup.
- Windows بروتوكول و Win32 اختبار طقم عنصر ثابت تماما جيد اثنان عدد result فرع، فقط يحتوي عدد حرف target exit، استخدام عادي error start cancellation و parent أصل مثال إبقاء محلي reason، تقليص نقص إلى `name`/`message`/`code`/`syscall`/`path` error record، ثابت `2`/`3`/`267` إلى `ENOENT`،`740` إلى `EACCES`،`5` إلى `EPERM`،`193` إلى `EFTYPE` و ذلك بقية code إلى `UNKNOWN` خريطة،runner spawn بعد عندئذ إرسال start،spawn قبل failure empty-range settlement، حسب ترتيب عدد صريح ترتيب target بيئة كتلة و `=C:` إبقاء و مزدوج NUL ربط ذيل،`uv_get_osfhandle()` carrier خريطة و unsigned invalid sentinel رفض،null-device ignored-stdin carrier و غير ignore stdin pipe،result-send و IPC-disconnect failure،stdio settlement قبل direct-result قفل تخزين،active-process تماما توقف مستقر، و وحيد handle cleanup.
- بلا حاجة مفتاح [`bash-startup-timeout`](../../../../snapshots/session/bash-startup-timeout/snapshot.yml) Session لقطة ثابت نموذج مرئي مهلة نتيجة.Linux user-systemd fixture عبر إدخال شاشة عائق إبقاء بدء طلب لم إزالة استهلاك، و تحقق إلغاء و range settlement.
- حقيقي Linux user-systemd اختبار سوف قسم آخر عبر إنتاج مدخل تشغيل واحد بند عادي أمر و واحد بند `node-pty` `setsid`/reparent مشهد. هو جمع إثبات scope signalling و collection، عار يمكن تنفيذ ملف فحص بحث، هروب هروب بعد بديل إنهاء،range settlement، و ثابت PTY PID،session، تحكم طرفية، قبل منصة إدخال،`/dev/tty`،readiness و startup-failure دلالة.
- native Windows اختبار إثبات suspended creation،resume قبل Job assignment، وراثة stdio، افتراضي بعد بديل وراثة،direct result،termination،active-process zero، استثناء/disconnected runner cleanup،kill-on-close و تزامن host-exit termination.source،built و Python packaged خطر دخان اختبار دخول نفس runner core.
- عام مشترك seam نوع،local provider،LSP و subagent مستهلك،shell fixture،README،Cordis catalog و keyless subprocess API snapshot كل لا يتضمن عادي PID؛terminal PID إبقاء.

## Alternatives considered

**إبقاء PID، يأخذ هو تعديل صار اختياري قيمة، أو زيادة عام مشترك `started` Promise.**لا إعطاء اعتماد، لأن هذه يمثل كل سوف كشف لا يمثل managed range مختلف خطوة provider identity، و إغراء توجيه مستهلك من خطأ واقع دفع قطع startup أو تماما توقف مستقر.

**توسيع عملية مجموعة،session،parent tree أو PID مسح.**لا إعطاء اعتماد، لأن عملية يمكن مغادرة فتح كل واحد نوع مراقبة علاقة؛ عند PTY helper و launcher مشترك استخدام session وقت، أكثر عرض SID signalling أيضا ممكن أمر في غير متصل عملية.native OS membership سوف حمل متابعة وجود، و كما يمكن مستقل استعلام.

**يجعل parent يملك أو إعادة فتح Windows Job.**لا إعطاء اعتماد، لأن نسخ handle،named Job،`OpenJobObject`،process-handle handoff و completion port سوف صنع صنع كثير عدد lifecycle owner، لكن لا يستطيع تعديل حسن direct-result اتفاق. واحد runner يمكن موحد واحد يملك target creation،Job membership،result production و نهائي handle closure.

**في Windows فوق عبر target stdio أو ملف نقل تمرير control/result.**لا إعطاء اعتماد، لأن مستخدم بايت و EOF يجب متابعة بـ قائم Node stream لـ مرجعي، بينما result file أو polling سوف صنع صنع ثاني عدد result owner. واحد بند IPC channel يمكن يأخذ control و target stdio قسم فتح.

**في عام مشترك CLI في تحليل إخفاء runner معامل، أو إصدار آخر عدد Node يمكن تنفيذ برنامج.**لا إعطاء اعتماد، لأن قبل من توسيع ورقة عام مشترك تطبيق لغة قاعدة، بعد من توسيع ورقة توزيع وجه.packaging-only bootstrap إبقاء واحد شيء إدارة يمكن تنفيذ برنامج و اثنان عدد خاص منطق مدخل.

**ذاكرة مؤقتة كامل Linux native اختيار نتيجة كما لم يعد فحص يمكن بلوغ صفة.**لا إعطاء اعتماد، لأن user-manager availability يمكن في اثنان مرة spawn بين تغير.runtime فقط ذاكرة مؤقتة رقم مرة نجاح bootstrap/scope عميق درجة probe، و في بعد كل مرة رمز دمج شرط استدعاء في خفيف كمية تكرار فحص manager reachability.

**في native launch فشل بعد إعادة وضع أمر.**لا إعطاء اعتماد، لأن يحتوي غامض failure ممكن حدوث في target قد تنفيذ بعد، إعادة وضع لذلك ممكن يأخذ أمر تنفيذ اثنان مرة.

**فقط من لم إزالة استهلاك request دفع قطع بدء فشل.** رفض، لأن abort،timeout أو dispose ممكن في request إزالة استهلاك قبل إنهاء launcher. سوف فعلي مراقبة إلى إشارة و owner طلب إنهاء إشارة مطابقة، حيث قدرة إبقاء إلغاء نتيجة، أيضا لن إخفاء غير متصل bootstrap خروج أو قد سجل pre-exec failure.

## Consequences

تلقي دعم حمل Linux عادي و PTY بدء،Windows عادي بدء سوف في بعد بديل هروب مغادرة عملية مجموعة أو direct parent خروج بعد متابعة يملك هو جمع، معا direct target result و range تماما توقف مستقر إبقاء مستقل. بديل قيمة هو كل مرة spawn كل حاجة مرة Linux manager فحص و scope/request، أو واحد طقم Windows runner/IPC/Job دورة الحياة، بينما كما الذي اختيار owner لا يمكن إثبات settlement وقت سوف صريح فشل.

fallback مضيف متابعة تشغيل أمر، لكن يحمل مرئي مقارنة ضعيف حفظ إثبات.Windows ConPTY،macOS native containment،active breakaway بعد بديل، قديم إصدار أو ناقص user-systemd بيئة،target replay، حمل دائم runner recovery، و JavaScript لا يمكن تنفيذ إنهاء مسار متساو لا يخص هذا قرار.
