# Agent Note: فقط في صريح ملاحظات بعد عبر OpenTelemetry فوق نقل

Status: implemented

[English](2026-09-05-nonofficial-feedback-otel.md) | العربية

## مشكلة

ملاحظات حاجة هو الذي وصف جلسة سياق، و لا اعتماد نموذج مزود أو لاحق نموذج طلب إلقاء تمرير مسار. عادي نشط حركة لا نيل تخويل فوق نقل. وراثة ملاحظات لا نيل نظر لـ فرعي Session نفس معنى.

## قرار

أساس أساس إعداد لـ كل مستخدم و مزود بـ `FEEDBACK_ONLY` تركيب OTel، يشمل `deepseek-official` و لا يوجد طلب رأس Session. فقط لديه جديد ذاته `feedback/record`،`feedback/message-put` و `feedback/message-delete` حدث تخويل التقاط، كما قطع توقف هذا تأكيد قطع مرجعي حدث. نص ملاحظات، تقييم قسم، فعلي جودة ملاحظة تحرير و سحب عودة متساو حساب عمل ملاحظات. بارد جلسة `feedback/committed` إشعار توفير قد إيداع لقطة، لا إصدار تخزين نشط Session أو Agent.

تخويل بادئة يتضمن من seq 0 إلى هذا ملاحظات كل بعد لم تسليم وصل مرجعي سياق، بينما غير فقط لديه ملاحظات تحميل حمل. فرعي جلسة حاجة جديد ذاته ملاحظات؛ بعد ذلك بادئة يتضمن وراثة تاريخ. لاحق سجل انتظار تحت مرة صريح ملاحظات. طلب نشط حركة، طلب رأس،Session إنشاء أو وصل قبول، استعادة، إضافة تركيب و HMR(حار وحدة استبدال) أبدا تخويل التقاط؛ فقط لديه تخزين ملاحظات لن إطلاق أي فوق نقل.

خلفية استخدام يتضمن كامل تاريخ حسب يحتاج التقاط و قائم انفصال حساس waterfall(شلال نشر صيغة حدث).`DISABLED` لا بنية صنع نقل.`FULL` يتم رفض، لا بصفة آخر اسم. مباشر استدعاء `ctx.sessionTelemetry.emit()` هو فارغ عملية، لذلك استدعاء جهة لا يستطيع التفاف مرور ملاحظات تخويل.SDK تحديد وقت تحديث جديد و إغلاق يمكن إتمام أولا قبل قد تخويل دفعة مرة، لكن أبدا التقاط جديد سجل. إيداع بعد إرسال بلا حاجة دخول واحد خطوة مستخدم تفاعل أو نموذج استدعاء.

[مرجعي ملاحظات قرار](2026-09-05-canonical-feedback-log.ar.md) مسؤول تخزين، إصدار، حذف و صاف أمر تأكيد.[افتراضي فتح بدء DeepSeek مساهمة](../../../../packages/session/session-log-deepseek/README.ar.md) إبقاء مستقل، إبقاء قائم هدف و قبول سلوك.

## اعتبار مرور بديل خطة

**حسب مزود أو طرف نقطة رئيسي آلة اسم مرور ترشيح.** ملاحظات لـ كل موضع مستخدم تخويل نفسه محدود سياق؛ مزود اختيار، شبكة صلة أو ناقص طلب رأس لا تغيير هذا تخويل.

**فقط استخدام لاحق DeepSeek طلب.** أخرى مزود لا يحمل `dsh_session_log`، بينما نهائي ملاحظات بعد ممكن لا يوجد طلب. قائم OTel خط الإنتاج يمكن مستقل إرسال، بلا حاجة ذاتي تعريف فوق نقل جهاز أو نموذج استدعاء.

**إبقاء حمل متابعة التقاط أو في دورة الحياة حدث فوق إعادة تشغيل تخزين ملاحظات.** نشر إعداد و قديم ملاحظات لا تخويل جديد التقاط. فقط لديه جديد صريح إيداع عندئذ تخويل. أب جلسة ملاحظات نفس مثال لا يستطيع تخويل فرعي جلسة فوق نقل.

## عاقبة

تسليم وصل كل قوة بينما لـ، لا بديل جدول أخذ تجميع طرف قبول. نفس كائن تنقل علامة كبح صنع تكرار التقاط، لكن جديد بارد لقطة و إعادة بدء بعد جديد ملاحظات ممكن تكرار بادئة؛ استقبال جهة حسب `(session.id, session.format_version, event.seq)` ذهاب إعادة. لا يوجد حفظ دائم OTel outbox، إلقاء تمرير ماء موضع أو harness HTTP إعادة محاولة تحمل وعد. دخول طابور بعد ملائم استخدام SDK دفعة معالجة و فقد فقد سلوك.OTel و افتراضي فتح بدء DeepSeek مسار ممكن إعادة تراكم. سحب عودة تصدير حذف حدث، لا هو بعيد طرف مسح حذف.

[OTel اختبار](../../../../packages/session/session-telemetry-otel/tests/otel.spec.ts) تغطية صريح ملاحظات التقاط، مزود غير متصل سلوك، دورة الحياة ساكن صامت،fork نفس معنى، بارد جلسة إيداع و مباشر استدعاء رفض.[تنسيق ضبط جهاز اختبار](../../../../packages/session/session-telemetry/tests/telemetry.spec.ts) تغطية تاريخ التقاط؛[أساس أساس إعداد اختبار](../../../../packages/bundle/base/tests/base.spec.ts) ثابت تركيب قيمة افتراضية.
