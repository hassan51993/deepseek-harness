# Agent Note: جانب شريط تخطيط حفظ دائم و provider استعادة

Status: implemented

[English](2026-09-14-sidebar-layout-provider-recovery.md) | العربية

## Problem

تحديث جديد متصفح سوف فقد فقد قد فتح ملف، قسم شريط موضع و اختيار في بند. يأخذ إبقاء طرفية إعادة فتح لـ جديد وسم لا يمكن أيضا أصل تخطيط، أيضا ممكن توسيع أصل هذا طي جانب شريط.

## Decision

جانب شريط حسب Session حفظ دائم مرور مرور تحقق حالي تخطيط لقطة و هوية حساب عدد،Client store سوف سحب إلغاء تاريخ إبقاء في داخل تخزين في. حفظ نوع أو تخطيط مرجع بلا فاعلية وقت، فقط تنظيف مقابل Session لقطة. تحديث جديد بعد سحب إلغاء تاريخ صاف فارغ، لذلك حفظ دائم بيانات لن مع مرور ذهاب عملية حمل متابعة زيادة طويل. هو في تصيير متن قبل استعادة تخطيط و وسم هوية، و بناء قيام مورد pin.provider استعادة ذاته محتوى؛ جانب شريط لا حفظ طرفية مخصص تابع حالة، أيضا لا مسؤول إعادة وصل. مؤقت تنقل معامل و مورد محتوى لا دخول تخطيط لقطة.

terminal provider قراءة قد اعتماد Session وسم سجل، أولا استعادة طرفية نموذج، مجددا استعلام بعد بلا عرض Host طرفية. ذلك Client controller في قسم إعداد قبل سوف عام وحيد محتوى و طرفية هوية صلة ربط حفظ لـ مستقل سجل، تحديث جديد بعد إعادة استخدام، و في سجل صريح إغلاق معنى رسم بعد حذف. تخطيط داخل tab id معرف مستقل نشط حركة عرض، لا يستطيع عبر نافذة معرف حفظ دائم عملية؛ تدريجي بند سجل كتابة و حذف تجنب تجنب تغطية غير متصل صلة ربط. استعادة هوية لا سماح إنشاء بديل عملية.Host مسؤول عملية تخزين نشط حالة، عنوان و شاشة ستار محتوى؛ حفظ صلة ربط فقط هو استعادة هدف. لا يوجد مقابل استعادة وسم صلة ربط لن منع توقف Host استكشاف قياس.

OpenCode `packages/app/src/context/layout.tsx` حفظ Session وسم،`context/terminal.tsx` مستقل حفظ طرفية هوية.DSH استخدام قائم Session أثر مجال store و provider خدمة تنفيذ نفسه مسؤولية تخطيط قسم، طرفية ما زال عودة Session كل.

هذا قرار جزء بديل [Web طرفية قرار](../feature/2026-09-09-web-sidebar-terminal.ar.md) في لا حفظ دائم حد تحديد. أصل سجل متابعة إبقاء، لأن عملية ملكية، تنظيف، تدفق نقل و إدخال تحكم قرار ما زال ملائم استخدام.

## Alternatives considered

**يأخذ كل إبقاء طرفية استعادة لـ جديد وسم.** Host استكشاف قياس لا يمكن أيضا أصل وسم موضع، اختيار في بند أو طي تخطيط، أيضا سوف تكرار إنشاء قد استعادة وسم.

**يجعل جانب شريط مسؤول طرفية استعادة.** تخطيط كل من سوف لذلك اعتماد خاص تحديد محتوى provider. توفير عام قد إيداع وسم استعلام يكفي يجعل كل provider استعادة ذاته حالة.

**حفظ دائم عملية بيانات وصفية و طرفية إخراج.** هذه قيمة سوف مستقل في متصفح تخطيط بطلان. إعادة اتصال Host قدرة أخذ نيل حالي بيانات وصفية و متسق شاشة ستار.

## Consequences

نفس متصفح محطة نقطة داخل تحديث جديد سوف إبقاء تخطيط، كل Session استخدام مستقل تخزين مفتاح. نافذة مشترك كل Session الأكثر بعد حفظ تخطيط؛ نشط حركة نافذة في تحديث جديد قبل إبقاء كل منها تخطيط. تخزين فشل وقت داخل تخزين حالة ما زال متاح. تحديث جديد لن إعادة بدء ناقص أو قد خروج عملية؛Host إعادة بدء ما زال لا يمكن استعادة shell.provider حالة حاجة ذاته دعم حمل استعادة، مؤقت ملف تنقل معامل لا استعادة.

store اختبار تغطية تخطيط قراءة كتابة، محدود حفظ دائم حالة، بلا فاعلية سجل،Session عزل و مورد اعتماد. طرفية اختبار تغطية هوية إعادة استخدام، هدف ناقص، لم تنشيط وسم إغلاق، و لا يوجد استعادة وسم وقت استكشاف قياس. كامل متصفح اختبار استخدام حقيقي طرفية عملية هوية، تحقق ملف معاينة، قسم شريط، اختيار في بند، كل شاشة و طي حالة تحت تحديث جديد.

[بلا شخص اتصال طرفية اثنان صغير وقت عودة استلام](../feature/2026-09-14-unattended-browser-terminal-reclamation.ar.md) لـ provider استعادة زيادة نافذة يحتفظ طرفية دورة الحياة، إبقاء هذا موضع تخطيط/محتوى مسؤولية تخطيط قسم.
