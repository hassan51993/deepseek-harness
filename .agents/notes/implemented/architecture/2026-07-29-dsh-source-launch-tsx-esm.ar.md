# Agent Note: dsh عبر tsx ESM خطاف شفرة المصدر بدء

Status: implemented

[English](2026-07-29-dsh-source-launch-tsx-esm.md) | العربية

> يحل محل[أصلي TypeScript شفرة المصدر بدء](../../archived/architecture/2026-07-28-dsh-native-typescript-source-launch.md):Node إزالة هذا قرار الذي اعتماد قدرة.

## مشكلة

[قد عودة ملف أصلي شفرة المصدر بدء قرار](../../archived/architecture/2026-07-28-dsh-native-typescript-source-launch.md) يجعل `apps/cli/src/bin.ts` في `node --experimental-transform-types` تحت تشغيل، إعداد دمج واحد فقط فعل تحليل paths loader، من Node مسؤول TypeScript تحويل.Node 26.0.0 إزالة `--experimental-transform-types`(عملية بـ `bad option` رفض هذا flag) ، فقط إبقاء strip نمط، بينما strip نمط لا يمكن قبول هذا عدد شفرة المصدر رسم مطلوب لغة قاعدة:vendor Cordis في معامل خاصية (`constructor(private ctx: Context)`) ،`vendor/hmr` في `@Inject` تركيب زينة جهاز، و مرة نشر `vendor/` و `packages/workflow` وقت التشغيل enum/namespace. مستودع engines نطاق (`^22.19.0 || >=24.0.0`) يتضمن Node 26، لذلك أصلي بدء سلسلة في ذلك فوق تماما لا يمكن بدء——كما لا يوجد أي CI مهمة تنفيذ مرور حقيقي بدء نحو كمية، هذا واحد لا توافق صامت لكن إصدار.

بدء تأخير متأخر نفس مثال هو مشكلة:off-thread `module.register()` خطاف عمل خط مسار يأخذ كل مرة تحليل كل عبر خط برنامج صف تحويل (TUI بدء خلال نحو 440ms `makeSyncRequest` انتظار) ، بينما كامل tsx افتراضي شكل (`--import tsx`) سوف بسبب ذلك CJS خطاف وضع كبير تحليل فتح إلغاء بينما كثير زهرة نحو 0.4s.

## قرار

`dsh` TUI،Web و بلا رأس شفرة المصدر بدء تشغيل `node --import tsx/esm`: من tsx ESM-only خطاف معا مسؤول TypeScript تحويل و tsconfig `paths` إسقاط. أصل دليل `dsh` نص برمجي مباشر من مستودع أصل دليل استخدام نفس بدء طريقة؛ ناتج توليد هو مستقل عملية، من[شفرة المصدر بدء و بناء قسم مغادرة قرار](../../archived/simplification/2026-08-12-separate-source-launch-from-build.md) قاعدة تحديد.CJS خطاف إبقاء إغلاق، لأن CLI(أمر سطر واجهة) شفرة المصدر رسم هو صاف ESM؛ فعلي قياس وقت التشغيل بدء حتى TUI banner استهلاك وقت نحو 0.7s، مقابل مقارنة كامل tsx افتراضي شكل نحو 1.1s، قد إزالة أصلي سلسلة نحو 0.75s.

`scripts/tspath-loader.ts` و `apps/cli/src/tsconfig-paths-loader.ts` قد حذف. مع لـ إزالة فقد أيضا لديه هذا loader«فقط لـ قد إعلان وقت التشغيل اعتماد خريطة workspace import» وقت التشغيل قاعدة——tsx بلا شرط تطبيق `paths` خريطة. إعلان كامل صفة الآن فقط من ساكن حالة بوابة حفظ عائق: إعداد عار إضافة مشي `verify-cordis-config`،manifest(بيانات وصفية بيان) مشي workspace constraints.(هذا وقت التشغيل قاعدة تأكيد فعلي اكتشاف مرور حقيقي نقص وقوع:`dsh-plan-mode` و `dsh-tool-jobs` استيراد `@deepseek-ai/dsh-llm` لكن فقط إعلان في devDependencies؛ بعد قد إصلاح.)

node-compat CI مستطيل دفعة (Node 22.19 و 26) إضافة جديدة `dsh-source-launch-smoke`(`apps/cli/tests/source-launch.compat.spec.ts`): بـ دقيق إنتاج وقت التشغيل بدء نحو كمية فعل keyless إدارة طريق stdio بدء، تأكيد عملية سوف بسبب TTY رفض بينما بـ غير صفر حالة خروج. لم قدوم Node مقابل وحدة خطاف أو TypeScript معالجة أي تعديل كل سوف يجعل هذا بوابة تغيير أحمر، بينما لا هو كسر تالف تطوير من `pnpm dsh`.

## تجهيز اختيار خطة

**في Node ≤25 إبقاء أصلي سلسلة و حسب إصدار قسم تقاطع.** رفض: اثنان طقم تحويل دلالة (amaro و esbuild) في حافة حافة لغة قاعدة فوق سوف قسم اختلاف، بدء جهاز يلزم إضافة إصدار استكشاف قياس،node-compat مستطيل دفعة يلزم تغطية اثنان بند مسار——لـ واحد قد تغيير حركة مرور experimental flag دفع خروج غرق إعادة صيانة. بينما كما amaro أيضا لا دعم حمل `vendor/hmr` استخدام `@Inject` تركيب زينة جهاز، أصلي مسار هذا قدوم حينئذ لا يمكن بدء مع مرفق افتراضي TUI إعداد.

**يأخذ شفرة المصدر رسم تعديل صار erasable-only بـ ملائم إعداد Node 26 strip نمط.** رفض: معامل خاصية و قيمة namespace مرة نشر vendor Cordis/cosmokit/loader/schemastery؛ تعديل كتابة هو بلا حد churn، كما كل مرة vendor sync كل يلزم إعادة فعل.

**مستودع ذاتي لديه نفس خط مسار loader(`module.registerHooks()` إضافة esbuild أو `@swc/core` تحويل).**غير مقبول: أصل نوع فعلي قياس نحو 0.45s، بينما esbuild مسار نقص قليل طرف إلى طرف تحقق،SWC في اثنان نوع تركيب زينة جهاز نمط تحت كل سوف بسبب `vendor/hmr` تركيب زينة جهاز و namespace دمج فشل. هذا خطة أيضا سوف يجعل مستودع مسؤول تحويل صحيح تأكيد صفة و tsx قد توفير تحليل خطاف. فقط عند فعلي قياس نحو 0.3s فرق مسافة يصبح فعلي جودة صار هذا وقت مجددا إعادة اعتبار.

**Node 26 تشغيل بناء ناتج `lib/`،24 إبقاء أصلي.** رفض: في الأكثر جديد Node إصدار خط فوق فقد ذهاب صفر بناء تطوير حلقة، كما خلط خلط شفرة المصدر وجه و ناتج وجه.

## نتيجة

- كامل engines نطاق (يشمل لم قدوم تغيير أصلي TypeScript دعم حمل Node إصدار خط) فقط لديه واحد بدء نحو كمية؛ خطر دخان بوابة حسب مستطيل دفعة سطر قوي صنع تنفيذ.
- TypeScript تحويل إعادة تفويض حمل إعطاء tsx/esbuild، عكس تحويل قبل واحد مقالة Agent Note«إثبات Node أصلي تحويل متاح» هدف؛ في vendor شفرة المصدر استخدام غير ممكن مسح حذف لغة قاعدة كما Node لم يعد توفير transform نمط حال حال تحت، هذا هدف غير ممكن بلوغ.
- شفرة المصدر بدء في وقت التشغيل اعتماد إعلان قوي صنع لا تكرار وجود؛ لم إعلان workspace import الآن فقط قدرة عبر ساكن حالة بوابة أو بناء نمط تحليل فشل كشف.
- وقت التشغيل بدء متبادل مقارنة كامل tsx افتراضي شكل سريع نحو 0.4s؛ACP(Agent Client Protocol) إبقاء `--import tsx`، لأن هو اعتماد رسم بعد لم حينئذ CJS خطاف اعتماد صفة فعل مراجعة حساب، كما ذلك بدء تأخير متأخر لا في تفاعل مسار فوق.
