# Agent Note: أساس في مزود توجيه LLM مهايئ و عام pi-ai خلفية

Status: implemented

[English](2026-07-14-provider-routed-llm-adapters.md) | العربية

## مشكلة

`dsh-llm` حسب دقيق نموذج اسم تسجيل مهايئ. إضافة في Cordis بدء وقت توفير نموذج قائمة،`LlmRuntime` لـ قائمة في كل نص حفظ واحد مهايئ،`GenerateOptions.model` معا اختيار مهايئ و مزود نموذج. اثنان عدد مع مرفق مهايئ كل فقط موجه إلى نفسه اثنان عدد DeepSeek نموذج وقت، هذا نوع طريقة يمكن عمل، لكن هو خلط خلط اثنان عدد مستقل قرار: من أي عدد فوق تنقل مزود تحمل وصل طلب، و هذا مزود ينبغي تشغيل أي عدد نموذج.

هذا نوع خلط خلط جعل مزود شبكة صلة لا يمكن توفير فتح وضع نموذج دليل. مثال مثل،OpenRouter هو واحد يتضمن كبير كمية نموذج ID مزود، خاص OpenAI توافق طرف نقطة أيضا ممكن في لا تعديل Harness إضافة شجرة حال حال تحت زيادة نموذج. هدف قبل، كل جديد اختيار نموذج كل يجب في إضافة بدء خلال إتمام تسجيل. نفس عدد نموذج ID أيضا ممكن وجود في كثير عدد مزود في، لذلك فقط حسب نموذج تسجيل لا يمكن جدول بلوغ استدعاء جهة مسبق مدة استخدام مزود.

`dsh-llm-pi-ai` لا يوجد كشف pi-ai مزود سحب كائن. هو بـ داخل ربط طريقة بنية صنع DeepSeek `openai-completions` نموذج، تطبيق DeepSeek مخصص استخدام payload رقعة، و سوف كل بند إعادة تشغيل مساعدة يد رسالة علامة لـ DeepSeek.pi-ai ذاته توفير مزود/نموذج دليل، قدرة كاف اختيار `openai-responses`،`anthropic-messages`،`google-generative-ai` انتظار API، و إبقاء مزود مخصص استخدام استجابة ID، و لاحق جولة الذي يحتاج دفع إدارة و أداة توقيع.Harness تحويل إسقاط مزود/نموذج توجيه و مزود استجابة حقل، لذلك فقط سوف داخل ربط نموذج استبدال لـ دليل استعلام، سوف توجيه يؤدي نفس نموذج إعادة تشغيل و عبر مزود نقل تسليم لا كامل.

مهايئ إعداد نفس مثال زائف تحديد فقط وجود واحد DeepSeek API مفتاح و طرف نقطة. عام خلفية حاجة لـ كل مزود قسم آخر إعداد اعتماد و طرف نقطة تغطية، معا متابعة من pi-ai معالجة AWS،Google ADC،OAuth انتظار بيئة إقرار إثبات آلية.

## قرار

### مزود بصفة مهايئ تسجيل مفتاح

`GenerateOptions` و `LlmCallConfig` في `model: string` خارج يحمل `provider: string`،`AgentOptions` فإن يحمل مقابل اختياري إنشاء حقل. فقط لديه اثنان عدد قيمة كل غير فارغ وقت،agent loop(ذكي جسم حلقة) طلب عندئذ صالح؛ اثنان عدد قيمة أيضا كل سوف كتابة طلب رأس سجل.`agent/request` يمكن في مهمة معنى خطوة إرجاع استبدال بعد حقل تركيب، لذلك جلسة يمكن تبديل مزود و نموذج، بلا حاجة تغيير Cordis إضافة دورة الحياة.

`LlmRuntime` حسب مزود تسجيل و تحليل مهايئ.`registerAdapter(providers, adapter)` في تعديل سجل التسجيل قبل فحص كامل مزود قائمة، لقاء إلى تكرار بند وقت إرجاع `DUPLICATE_ADAPTER`، و بـ واحد effect لـ مفرد موضع كامل جسم dispose(مورد تحرير). نموذج ID لا بصفة تسجيل مفتاح؛ ما زال من اختيار في مهايئ مسؤول تحقق أو تحويل إرسال. لاحق [LLM دليل و ACP نموذج اختيار Agent Note](../../archived/architecture/2026-07-15-llm-model-catalog-and-acp-selection.md) زيادة بناء اقتراح صفة `listProviders()` / `listModels()` اكتشاف واجهة، لكن لن يأخذ دليل عضو علاقة تغيير صار طلب تحقق قاعدة.

في واحد Cordis سياق في، واحد مزود فقط قدرة لديه واحد مهايئ كل من.`dsh-llm-deepseek` تسجيل `deepseek`؛`dsh-llm-pi-ai` أيضا يمكن تسجيل `deepseek`، لكن معا تحميل اثنان عدد كل من يخص إعداد خطأ، لا اعتماد ترتيب قاعدة أو رجوع سلوك. إذا نشر اختيار يد كتابة DeepSeek تنفيذ، يحتاج من pi-ai إعداد في ترتيب حذف `deepseek`؛ إذا نشر اختيار pi-ai DeepSeek تنفيذ، فإن لا تركيب `dsh-llm-deepseek`.

`dsh-llm-deepseek` إزالة نموذج تسجيل قائمة، قبول عبر `deepseek` مزود توجيه مهمة معنى نموذج نص. ذلك طلب تسلسل تحويل،`/chat/completions` طرف نقطة،thinking خيار،SSE(Server-Sent Events) تحليل و خطأ سلوك إبقاء ثابت؛`options.model` ما زال سوف أصل مثال إرسال.

### صريح pi-ai مزود إعداد

`dsh-llm-pi-ai` قبول واحد غير فارغ مزود إعداد قائمة. قائمة داخل مزود اسم يجب وحيد، و كما وجود في pi-ai `getProviders()` نتيجة في. كل بند إعداد يتضمن مزود اسم، و اختياري `apiKey`،`baseURL`،headers، دفع إدارة درجة آخر و ميزانية، ذاكرة مؤقتة إبقاء ضبط، نقل طريقة،SDK مهلة،Harness تدفق فارغ خامل مهلة، و من مزود يملك `retryPolicy`. مهايئ قوي صنع سوف pi-ai `maxRetries` ضبط لـ صفر، جعل مرة `stream()` استدعاء فقط إرسال بدء مرة مرئي مزود طلب؛`dsh-llm-retry` فإن في agent فشل خطوة نقطة توسيع فوق تنفيذ تحليل بعد سياسة. اعتماد لا ضبط عام قيمة: صريح مفتاح فقط مقابل الذي تابع إعداد توليد فاعلية؛ لم توفير مفتاح وقت،pi-ai استخدام معيار بيئة متغير،OAuth token،AWS اعتماد سلسلة،Google ADC أو أخرى مزود أصلي بيئة إقرار إثبات. صريح فارغ مفتاح يخص بلا فاعلية إعداد، لن رجوع إلى بيئة إقرار إثبات.

إضافة عبر مرة أصل فرعي استدعاء، سوف قد إعداد مزود اسم تسجيل إلى نفس عدد `PiAiAdapter`. كل غير ممكن تغيير طلب لقطة تركيب صالح profile و يمكن خدمة نموذج وصف رمز. دليل خارج نموذج حاجة صريح إشارة تحديد أو يمكن دفع قطع بروتوكول و طرف نقطة. أصل حسب[ضبط دليل استعادة قرار](../bug-fix/2026-09-07-pi-ai-settings-catalog-recovery.ar.md) ، قد تخزين دليل خطأ إبقاء مرئي، يمكن إصلاح، كتابة ما زال سوف تحقق قد تعديل مزود، طلب فإن في شبكة شبكة I/O قبل رفض الذي اختيار خطأ نموذج.

مهايئ استدعاء pi-ai `streamSimple()`، لذلك كل دليل نموذج سوف اختيار ذلك تسجيل API تنفيذ؛ وصف رمز لـ `openai-responses` وقت استخدام OpenAI Responses، بينما غير Chat Completions.Harness temperature، الأكثر كبير token عدد،signal،session ID، و مزود إعداد في عام تدفق خيار متساو مباشر نقل تمرير. إعداد headers و Harness قوي صنع عودة بسبب headers دمج؛ حدوث إبقاء اسم اندفاع مفاجئ وقت، بـ Harness عودة لأن دقيق. مهايئ لم يعد صيانة DeepSeek مخصص استخدام payload إعادة كتابة أو مزود بروتوكول مستطيل دفعة.

pi-ai عام تدفق خيار لا دعم حمل إيقاف تسلسل. إذا Harness `stop` خيار قد تعريف،`dsh-llm-pi-ai` سوف بـ `UNSUPPORTED_OPTION` رفض طلب، لن ساكن صامت تجاهل اختصار، أيضا لن زيادة ثاني طقم مزود مخصص استخدام payload تنفيذ.`dsh-llm-deepseek` متابعة عبر أصلي طلب تسلسل تحويل جهاز دعم حمل `stop`.

### قد سجل مساعدة يد توجيه و إعادة تشغيل حالة

مساعدة يد رسالة يحمل طلب `provider` و `model`، و اختياري JSON يمكن تسلسل تحويل مهايئ إعادة تشغيل حالة. نجاح `assistant/message` جلسة حدث سجل هذه حقل،`deriveMessages()` إرجاع مساعدة يد رسالة وقت أيضا سوف يتضمن هو جمع. مستخدم، نظام، سياق و أداة نتيجة رسالة لا يحمل مساعدة يد توجيه حقل. مزود/نموذج حقل هو agent loop مرجعي بيانات؛ مهايئ فقط يملك ذلك لا نفاذ واضح إعادة تشغيل حالة payload.

نجاح إنهاء `finish` قسم قطعة يمكن بـ `ReplayEnvelope` شكل صيغة يحمل إعادة تشغيل حالة: لا نفاذ واضح استجابة درجة بيانات وصفية، إضافة فوق و إرسال إطلاق كتلة تسلسل مقابل متساو اختياري تدريجي كتلة بند.`BlockAssembler` مقابل محتوى و بيانات وصفية فقط فعل مرة إبقاء/إسقاط قرار——max-token تجميع إسقاط أداة استدعاء وقت، بيانات نفس موضع بند واحد و إسقاط——لذلك agent loop مرفق إضافة إلى قد تجميع مساعدة يد رسالة نموذج مصدر في حالة بداية نهاية وصف تخزين كتلة، رؤية [max-token إعادة تشغيل حالة مقابل متساو قرار](../../archived/bug-fix/2026-08-15-max-token-replay-state-alignment.md).agent loop لا عام استجابة تعديل كتابة خطاف. خطأ أو في توقف استجابة لن توليد صحيح معتاد مساعدة يد رسالة، لذلك لن دخول لاحق نموذج تاريخ.

pi-ai إعادة تشغيل حالة استخدام ذلك نجاح `AssistantMessage` حمل إصدار الأكثر صغير إسقاط ملء ملء هذا بنية: واحد استجابة نصف منطقة (مصدر API/مزود/نموذج، استجابة ID/نموذج، اختياري مزود أصلي effort، إيقاف سبب) ، و تدريجي كتلة نص توقيع،thinking توقيع و أداة استدعاء توقيع.[pi-ai ترقية توافق صفة قرار](../bug-fix/2026-09-05-pi-ai-upgrade-compatibility.ar.md#decision) تعريف طلب نموذج و Anthropic أصلي نموذج هوية منطقة آخر، و effort إبقاء قاعدة. هو لن تكرار Harness محتوى كتلة في قد لديه نص أو أداة معامل، أيضا لا يتضمن تشخيص معلومة، ختم الوقت، استخدام كمية أو خطأ. لاحق طلب في، فقط لديه تاريخ مزود و هدف مزود حالي عودة نفس عدد مهايئ نسخة كل وقت،`LlmRuntime` عندئذ سوف يأخذ إعادة تشغيل حالة تسليم إعطاء هدف مهايئ. مهايئ في قدرة كاف استعادة تاريخ استجابة وقت، سوف Harness سجل محتوى و إعادة تشغيل حالة تركيب، و مسؤول الذي يحتاج عبر نموذج أو عبر مزود تحويل. حفظ دائم محتوى إبقاء مرجعي: مهايئ استلام إلى لا يمكن استخدام إعادة تشغيل حالة——لم معرفة kind أو إصدار، صيغة خطأ بيانات وصفية، أو و محتوى لم يعد مطابقة كتلة بنية——سوف يأخذ هذا رسالة تخفيض لـ مزود غير متصل تحويل و حمل خروج تشخيص؛ أخرى مهايئ فقط قدرة استلام إلى مزود غير متصل محتوى و مزود/نموذج حقل.

هذا حالة يخص نموذج مرئي إعادة تشغيل إدخال، لذلك التزام دوران قائم[طلب يمكن إعادة بناء قاعدة](2026-07-05-reconstructable-requests.ar.md): هو معا وجود في إنهاء `finish` قسم قطعة و قيادة إرسال توليد قد تجميع `assistant/message` نموذج مصدر في. استعادة و fork سوف أصل مثال إبقاء هذا حالة. ضغط (compaction) حجب حجب مساعدة يد رسالة وقت، أيضا سوف من نشط حركة surface في إزالة ذلك إعادة تشغيل حالة؛ ملخص يخص عادي مزود غير متصل محتوى.

### في كل طلب إنتاج جهة في نقل بث هدف

كل بند نموذج اختيار مسار كل معا يحمل provider و model: إعلان صيغة agent،ACP(Agent Client Protocol) و stdio تطبيق إعداد،JSON-RPC initialize طلب،subagent تغطية و وراثة، سير العمل فرعي agent تغطية، و مباشر ضغط ملخص.subagent أولا من أب agent وراثة اثنان عدد حقل، مجددا تطبيق طلب تغطية. توجيه النظام متغير تجميع دمج في `model` خارج زيادة `provider`.

ضغط إعداد في `summarizationModel` خارج زيادة `summarizationProvider`. اثنان عدد قيمة متساو لـ فارغ وقت وراثة، متساو غير فارغ وقت اختيار صريح هدف؛ فقط إعداد منها واحد سوف توجيه يؤدي تحميل فشل. وراثة أولوية استخدام الأكثر قريب مرة سجل طلب هدف، لا يوجد وقت رجوع إلى agent إنشاء خيار.`compaction/summary` استخدام قائم نموذج استدعاء envelope سجل اثنان عدد حقل.

JSON-RPC وقت التشغيل صريح استقبال مزود و نموذج. فقط عند `deepseek` مزود لا يوجد تسجيل كل من وقت، ذلك سهل فائدة رجوع عندئذ سوف تركيب `dsh-llm-deepseek`؛ أخرى ناقص مزود سوف مباشر فشل، لن تخمين قياس مهايئ.

حالي seed/load تحقق سوف رفض حذف مطلوب مزود/نموذج حقل طلب رأس و مساعدة يد رسالة. تجميد ربط v0-to-v1 ترحيل حافة اشتراط ترحيل قبل قد أداة تجهيز نفس طقم يمكن إعادة بناء توجيه هوية؛ هو أبدا سوف تخمين قياس ناقص مزود أو نموذج، شاذ شكل بنية سوف في إصدار قبل يتم رفض.

## اعتبار مرور بديل خطة

**متابعة بـ نموذج اسم بصفة سجل التسجيل مفتاح، و زيادة عبر إعداد مهايئ.** عبر إعداد آلية سوف في دقيق تسجيل و التقاط قاع إضافة بين جذب دخول رجوع ترتيب، جعل تكرار كل حق أخذ قرار في مستمع ترتيب؛ إذا لم يعد زيادة أخرى اتفاق، ما زال لا يمكن منطقة قسم مختلف مزود في نفسه نموذج ID.

**سوف مزود و نموذج تحرير رمز إلى واحد نص في.** OpenRouter `openai/gpt-*` انتظار قيمة قد يتضمن صنف يشبه مزود بادئة و مائل عمود. قسم فصل رمز اتفاق سوف يأخذ توجيه لغة قاعدة تسرب تسرب إلى كل نموذج اختيار جهاز، و حاجة تحويل معنى قاعدة؛ اثنان عدد صريح حقل أكثر صاف واضح، أيضا يمكن قسم آخر سجل سجل.

**زيادة `backend + provider + model`.** backend مفتاح يمكن يجعل `dsh-llm-deepseek` و pi-ai DeepSeek تنفيذ مشترك تخزين، و حسب طلب تبديل. نهائي اعتماد نشر قاعدة هو واحد مزود مقابل واحد مهايئ كل من: نفس فوق تنقل مختلف تنفيذ يخص من إضافة تركيب اختيار تحديد بديل بند. رقم ثلاثة عدد توجيه صيانة درجة سوف زيادة كل طلب و إعداد سالب تحمل، لكن لا يوجد حالي مستهلك.

**يجعل `dsh-llm-pi-ai` تلقائي تسجيل كل pi-ai مزود.** هذا نوع طريقة سوف احتلال استخدام نشر بلا معنى كشف بيئة اعتماد و مزود اسم، و و `dsh-llm-deepseek` انتظار أصلي مهايئ اندفاع مفاجئ. صريح إعداد يمكن مراجعة فحص قدرة و اعتماد نطاق.

**كل مزود تركيب واحد pi-ai إضافة نسخة.** مستقل نسخة يمكن عزل إعداد، لكن سوف تكرار إضافة إعلان، أيضا لا يمكن تنفيذ إعداد تسجيل أصل فرعي صفة. كل طلب هذا حينئذ نحو نفس عدد مهايئ توفير مزود، لذلك مرور مرور تحقق إعداد خريطة أداة لديه أكثر صغير دورة الحياة واجهة.

**قبول مهمة معنى داخل ربط pi-ai نموذج وصف رمز.** هذا نوع طريقة يمكن دعم حمل دليل خارج خاص نموذج ID، لكن سوف سوف pi-ai نموذج و توافق صفة schema كشف لـ Harness إعداد، و اشتراط مهايئ تحقق بروتوكول مخصص استخدام تركيب. حالي إصدار عبر تغطية دليل نموذج `baseURL` دعم حمل ذاتي تعريف طرف نقطة؛ فقط لديه فعلي ظهور دليل خارجي توقيع يحتاج طلب بعد، عندئذ سوف آخر سطر قرار هل دعم حمل ذاتي تعريف وصف رمز.

## أثر

- مزود اسم هو نشر نطاق داخل توجيه كل حق مفتاح: اثنان عدد مزود يمكن استخدام نفسه نموذج نص، لكن لـ نفس عدد مزود تركيب اثنان عدد مهايئ سوف في تحميل وقت فشل، لن شكل صار رجوع ترتيب.
- نموذج اختيار لم يعد تغيير Cordis إضافة رسم. دليل نوع مهايئ يمكن قبول بدء بعد اختيار مهمة معنى قد تثبيت دليل نموذج، أصلي DeepSeek مهايئ فإن سوف تحويل إرسال مهمة معنى DeepSeek نموذج ID.
- ذاتي تعريف `baseURL` سوف إبقاء الذي اختيار دليل نموذج بروتوكول و قدرة، لكن لن يجعل دليل خارج نموذج ID تغيير لـ صالح. خاص طرف نقطة يجب تنفيذ هذا دليل بند مقابل بروتوكول.
- pi-ai اعتماد، نقل خيار،SDK مهلة، و افتراضي خمسة قسم ساعة `streamIdleTimeoutMs` فارغ خامل مهلة آلية متساو حسب مزود إعداد عزل. نظام منع استخدام إخفاء مزود إعادة محاولة؛ محدود إعادة محاولة من مفرد وحيد تركيب agent استعادة سياسة مسؤول.
- pi-ai عام تدفق API لا يمكن جدول بلوغ إيقاف تسلسل، لذلك `dsh-llm-pi-ai` سوف رفض إيقاف تسلسل؛ أصلي DeepSeek مهايئ ما زال دعم حمل إيقاف تسلسل.
- فقط عند تاريخ مزود و هدف مزود عودة نفس عدد مهايئ نسخة كل وقت، إعادة تشغيل حالة عندئذ يمكن نقل غرس. مهايئ مسؤول عبر مزود و عبر نموذج استعادة؛ أخرى مهايئ فقط استقبال لا يحتوي لا نفاذ واضح حالة مزود غير متصل تاريخ.
- حالي Session JSONL اشتراط طلب رأس و مساعدة يد رسالة كل يتضمن مزود/نموذج.v0 حافة فقط ترحيل قد يحمل يمكن إعادة بناء طلب هوية تجميد ربط بنية.

## اختبار

- اختبار وحدة تغطية سجل التسجيل اندفاع مفاجئ، طلب إعادة بناء، جلسة تحقق، إعداد تحليل، مفرد مرة طلب خيار تحويل إرسال، يشمل OpenAI Responses في داخل أصلي API اختيار، تحويل، إعادة تشغيل تحقق، خطأ خريطة، استدعاء جهة إلغاء، فارغ خامل مهلة توجيه يؤدي نقل إنهاء، محتوى إعادة كتابة، و نفس نسخة و مختلف نسخة بين إعادة تشغيل توزيع.
- بلا مفتاح agent loop/جلسة اختبار و ACP لقطة تغطية حفظ دائم مزود/نموذج بيانات وصفية، استعادة و fork نقل بث، سير العمل/subagent تغطية، و ثابت مستخدم مرئي transcript(نص سجل) ؛ مفتاح باب تحكم DeepSeek e2e اختبار إبقاء حقيقي مزود تدفق صيغة إخراج و أداة لاحق استدعاء نسبة التغطية.
- عام مشترك JSDoc،package README، هيكل بنية و فرعي نظام وثيقة، توليد دليل، عرض مثال، جلسة fixture(اختبار قبل وضع بيانات) و Python SDK إعداد مقابل وثيقة موحد واحد استخدام مزود/نموذج هدف، و من مستودع وثيقة و نوع انتظار قيمة بوابة تحقق.

## ريح خطر

هذا بند تغيير في جذب دخول وقت هو تغطية كل مستودع API كسر تالف صفة تغيير: فقط نموذج طلب بنية صنع، مهايئ تسجيل، تطبيق بروتوكول،fixture، و حفظ دائم v0 حدث بنية معا تغير، لا توفير توافق آخر اسم. قد إصدار تاريخ استعادة الآن يخص متبادل مجاور Session صيغة حافة. مزود ترتيب هو قاعدة متعمد منع توقف نفس فوق تنقل اثنان عدد تنفيذ مشترك تخزين في نفس سياق.pi-ai اعتماد ترقية ممكن تغيير يمكن قبول مزود/نموذج دليل، لذلك قفل ملف و مهايئ e2e مستطيل دفعة تعريف قد تحقق تجميع دمج. ذاتي تعريف `baseURL` طرف نقطة سوف وراثة الذي اختيار دليل نموذج بروتوكول زائف ضبط، لا يمكن إصلاح لا توافق بديل إدارة. دليل خارج نموذج وصف رمز و كثير نموذج حالة محتوى ما زال لا تلقي دعم حمل.pi-ai إعادة تشغيل حالة ممكن يتضمن لا نفاذ واضح إضافة سري دفع إدارة توقيع؛ مزود حاجة هذا معلومة صيانة حمل وصل متابعة صفة، لذلك نظام سوف حفظ دائم هذا حالة، لكن لن في قائم جلسة سجل خارج تصيير أو سجل هو.
