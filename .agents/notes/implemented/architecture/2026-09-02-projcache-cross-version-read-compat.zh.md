# Agent Note: إسقاط ذاكرة مؤقتة قبل بديل استعادة و Session صيغة ربط (session_projcache v3-v6 → v7)

Status: implemented

[English](2026-09-02-projcache-cross-version-read-compat.md) | العربية

## مشكلة

`session_projcache` تخزين مجال عرض دخول مرور كثير بديل مغناطيس قرص بنية. ترقية بعد DSH_HOME كشف ثلاثة صنف ريح خطر:

- **v3 مفرد ملف home ترقية بعد بدء صلب فشل**:per-record تخطيط legacy bootstrap ترحيل قديم مفرد ملف وقت لا فحص ذلك `unit.version`، يأخذ قديم سجل أصل مثال ضرب فوق حالي إصدار ختم كتابة جديد شجرة؛domain طبقة فتح مجال وقت تدريجي بند zod تحقق، قديم سجل نقص إضافة جديدة لا بد ملء حقل → `invalid-record` → كامل مجال رفض فتح → إضافة شجرة تحميل فشل. كما bootstrap أولا كتابة قرص بعد تحقق،**أول مرة بدء أي يأخذ تالف وثيقة دائم دائم كتابة جديد شجرة**("إلقاء سم")——هذا بعد كل مرة بدء جديد شجرة غير فارغ، وصل legacy مسار كل لم يعد مشي،home حمل متابعة غير ممكن استخدام.
- **v4 per-record home ترقية بعد قائمة فقد عنوان**:v4 وثيقة يتم إصدار ختم فحص ساكن صامت إسقاط (per-record عقد نحو) ،SessionList هو صفر I/O صاف ذاكرة مؤقتة قراءة،miss بعد كامل سطر لا حمل إسقاط؛ عنوان يلزم انتظار كل جلسة يتم تدريجي عدد إعادة فتح بعد عندئذ استعادة.
- **Session صيغة تمرير زيادة ممكن إعادة استخدام حسب قديم حدث دلالة طي نتيجة**: إصدار 3 حتى 6 لا سجل Session صيغة بديل. إذا يأخذ ناقص بديل نظر لـ حالي بديل، ذاكرة مؤقتة سطر حينئذ قدرة التفاف مرور محدود تاريخ مواصفة تحويل أو تغيير أساس عدد ترحيل.

ذاكرة مؤقتة مجال ذاته عقد نحو هو"مرور مدة أو غير ممكن قراءة ذاكرة مؤقتة فقط دفع خروج أكثر طويل ذيل جزء إعادة وضع، أبدا إعطاء خروج خطأ قيمة، أبدا رفض تحميل"——صلب فشل و كامل جسم إسقاط كل مخالفة خلف هذا عقد نحو قبل نصف جملة أو منتج مسبق مدة.

## مغناطيس قرص بنية بديل حد

| domain version | يحمل إصدار | تخطيط | مغناطيس قرص شكل | identity حقل | سطر حقل |
|---|---|---|---|---|---|
| 3 | 0.1.1-rc.2 | single | مفرد ملف `storages/session_projcache.json`(`{unit:{name,version}, global, tables}`) | `createdAt`, `cwd?` | `ver`, `seq`, `val` |
| 4 | 0.1.2-alpha.3 | per-record | كل جلسة واحد نسخة `storages/session_projcache/sessions/<sessionId>.json`(`{version, record}`) | `createdAt`, `cwd?` | نفس فوق |
| 5 | 0.1.2-alpha.4 | per-record | نفس v4 | + `isSeeded`(v5 أول إرسال لا بد ملء؛ الآن لـ optional) ،`inheritedEventCount`(نفس قبل) | نفس فوق (`seq` عدد قيمة دلالة و v4 نفسه، فقط نوع إضافة brand) |
| 6 | v1 قبل mainline | per-record | نفس v5 | نفس v5 | نفس فوق |
| 7 | حالي إصدار | per-record | نفس v5 | + `formatVersion`؛ حالي كتابة أيضا اشتراط اثنان عدد lineage حقل | نفس فوق |

v4→v5 وحيد فعلي جودة فرق مختلف هو identity إضافة جديدة اثنان عدد lineage حقل؛v6 فقط تغيير كتابة إصدار ختم. هذه قبل بديل سطر داخل `ver/seq/val` يمثل متسق،`seq` عدد قيمة يحتوي معنى لم تغيير ([2026-08-31 seq/offset brands note](../../archived/architecture/2026-08-31-session-sequence-and-log-offset-brands.md) واضح on-disk عدد قيمة ثابت).v3→v4 هو تخطيط ترحيل، سجل محتوى بنية متسق.v7 يأخذ Session صيغة بديل إضافة دخول ذاكرة مؤقتة identity، لأن لا يمكن من domain إصدار ختم دفع توجيه سطر دلالة.

آخر لديه واحد نوع اشتقاق توليد شكل: ركض مرور مرة v5 إصدار v3 home(إلقاء سم حالة)——جديد شجرة داخل وجود**إصدار ختم لـ 5 لكن محتوى هو v3 سجل**(نقص lineage حقل) وثيقة.

## قرار

إعلان صيغة قراءة توافق——قراءة سعة تحمل owner خلف كتاب مرور قديم إصدار، كتابة ثابت ختم حالي إصدار:

1. **`DomainSpec.compatibleVersions`(إضافة جديدة، اختياري)**: مجال owner إعلان"هذه قديم إصدار تخزين كمية سجل في حالي سجل schema تحت أيضا يمكن قراءة"(قاموس نوع يد مقطع: إضافة جديدة حقل علامة optional).`defineDomain` تحقق كل بند لـ صغير في حالي version غير سالب كامل عدد؛`descriptorOf` نفاذ نقل إلى خلفية `KvUnitDescriptor`.
2. **json خلفية per-record قراءة**: قبول"حالي إصدار ∪ compatibleVersions"داخل إصدار ختم، تجميع دمج خارج وفق قديم نظر لـ foreign إسقاط؛**كتابة مسار دائم بعيد ختم حالي إصدار**(قراءة إلى قديم سجل بعد تحت مرة checkpoint ذاتي لكن يأخذ هو دفع دخول إلى حالي إصدار).single تخطيط صيانة حمل exact-version ثابت.
3. **legacy bootstrap إصدار يأخذ صلة (bug إصلاح هذا جسم)**: قديم مفرد ملف `unit.version` يجب سقوط في قبول تجميع دمج داخل عندئذ ترحيل، لا فإن نظر لـ فارغ unit إبقاء في أصل أرض——لـ owner لم خلف كتاب سجل ضرب حالي إصدار ختم، سوف يأخذ"يمكن إسقاط مرور مدة ذاكرة مؤقتة"تغيير صار domain طبقة schema صلب فشل.
4. **projcache مجال إعلان `version: 7, compatibleVersions: [3, 4, 5, 6]`**؛ تخزين schema في صيغة و lineage identity حقل متساو لـ optional، جعل owner خلف كتاب قبل بديل سجل يمكن فتح. حالي كتابة بداية نهاية يتضمن هذا ثلاثة عدد حقل.
5. **identity مطابقة مقارنة بنية دقيق دخول أكثر صارم إطار**: ناقص `formatVersion` سجل أبدا مطابقة حالي Session، لذلك قبل بديل سطر لا يستطيع بث نوع إسقاط، بينما سوف من مرجعي سجل إعادة طي. صيغة مطابقة بعد،`identityMatches` عندئذ يأخذ ناقص lineage عودة واحد تحويل لـ unseeded(`?? false` / `?? 0`): مقابل unseeded جلسة دقيق، مقابل seeded مدة نظر فإن مطابقة فشل.v5 إلقاء سم home بسبب بينما يمكن أمان بدء، لكن ذلك لم ربط سطر لن بصفة حالي قيمة كشف.
6. **schema تحقق التقاط قاع:`invalidRecords: 'backup-and-skip'`(فقط هذا مجال إعلان)**. قراءة توافق خارج ما زال تحليل فشل تخزين كمية سجل لم يعد يجعل كامل مجال رفض فتح:domain طبقة استدعاء خلفية `KvUnit.backupRecord`(json per-record تنفيذ=يأخذ وثيقة تعديل اسم لـ `<key>.json.bak.<YYYYMMDDHHmm>`، بايت إبقاء ملف، لم يعد يتم قراءة) ، استخدام `logger.error` ضرب طبع أداة جسم فشل معلومة (مجال اسم، جدول، مفتاح، نقل حركة ذهاب نحو،zod فشل سبب) ، مع بعد عند هذا سجل لا وجود متابعة بدء؛ تحت مرة بارد قراءة سوف إعادة بناء و إعادة كتابة هذا جلسة ذاكرة مؤقتة.**هذا سياسة هو مجال درجة صريح إعلان، نقص حذف ما زال لـ fail-loud**——أخرى عمل خدمة مجال تخزين كمية بيانات تحقق فشل وفق قديم كامل مجال رفض تحميل؛ خلفية لا يوجد `backupRecord` قدرة (single تخطيط، سطر تخزين) وقت أيضا رجوع fail-loud. تسمية امتداد تغيير:quarantine → backup-and-skip(مستخدم قطع قرار: كلمة يلزم معا يحتوي"تجهيز نسخة"و"قفز مرور"اثنان معنى، كما و `.bak` بعد لاحقة نفس مصدر؛skip-backup بسبب CLI `--skip-X` معتاد مثال وجود"لا تجهيز نسخة"عكس قراءة بينما ترك استخدام). مقابل هذا مجال بينما قول، هذا سياسة يحل محل [2026-07-28 تخزين استعادة رفع سجل](../../proposed/architecture/2026-07-28-storage-root-and-derived-medium-recovery.zh.md) في reset/destroy استعادة طريق مسار؛ هذا رفع سجل مقابل مرجعي وسيط جودة و كامل وسيط جودة ضرر تالف ما زال صالح.

7. **predecessor title هو قائمة hint، بينما لا هو fold shortcut**:Session list بدء إبقاء metadata/cache-only، أبدا فتح بارد log body.log header هو مرجعي مصدر؛ دورة الحياة مطابقة checkpoint هو durable prefix witness، يمكن سقوط بعد لكن لا يستطيع قيادة أولا سجل. لذلك `cachedPredecessorTitle` فقط عام ما زال عبر حالي title unit `stateVersion` و schema predecessor `title` row. اثنان بند متبادل مجاور Session format edge كل إبقاء title نص. هذا hint استخدام `asOfSeq: -1`، بينما لا استخدام تخزين row ترتيب رقم، لأن تغيير سجل حدث عدد كمية ترحيل سوف إعادة خريطة هذا جلوس علامة. أخرى predecessor row متابعة إخفاء،`hydratePrepared`/`coldSnapshot` ما زال اشتراط صارم إطار صيغة identity، لأن أي جعل شيء إدارة تخزين متسق،normalizer ما زال ممكن تغيير `blank` أو `lastPromptAt` انتظار قيمة.

### v3-v6 → v7 موضع وضع

إصدار 3 حتى 6 ما زال يمكن بنية تحويل قراءة، لأن هو جمع سجل و سطر يمثل هو حالي schema صالح إدخال. ذلك identity نقص قليل `formatVersion`، لذلك متعمد لا يستطيع بصفة حالي طي سريع مسار.unseeded كما دورة الحياة مطابقة سجل ما زال يمكن نحو صفر I/O قائمة توفير إصدار توافق title، لكن لا يستطيع توفير أي مرجعي seed. بارد قراءة أو فوري فحص نقطة سوف من ترحيل بعد Session سجل إعادة بناء قيمة، و كتابة حمل كامل صيغة و lineage identity v7 سجل. بدء وقت لا تشغيل eager قيمة ترحيل؛schema تحقق فشل قد قبول سجل تنفيذ `backup-and-skip`.

### ترقية مستطيل دفعة

| home شكل | إصلاح بعد سلوك |
|---|---|
| v3 مفرد ملف (لم إلقاء سم) | bootstrap ترحيل (3 ∈ قبول تجميع)→ بدء نجاح؛ توافق title في قائمة مرئي، لم ربط طي انتظار بارد إعادة بناء |
| v3 + إلقاء سم جديد شجرة | optional حقل يجعل جديد شجرة وثيقة يمكن تحليل → بدء استعادة؛ توافق title في قائمة مرئي، لم ربط طي انتظار بارد إعادة بناء |
| v4/v5/v6 per-record | وثيقة بنية تحويل قراءة دخول → نقص صيغة بديل بينما رفض fold shortcut؛ توافق title في قائمة مرئي؛ حالي فحص نقطة إعادة كتابة v7 |
| identity مطابقة v7 حالي سجل | صحيح معتاد خدمة ذاكرة مؤقتة قيمة |
| صيغة مطابقة لكن نقص lineage سجل | unseeded استدعاء جهة يمكن استخدام؛seeded استدعاء جهة رفض و عودة سقوط بارد طي |

## تجهيز اختيار خطة

- **في تخزين طبقة رفض قبل بديل إصدار ختم**: مقابل إسقاط أمان، لكن سوف منع توقف تلقي حفظ حماية legacy bootstrap، أيضا لا يمكن إبقاء بنية تمام جيد سجل مباشر إلى مرجعي إعادة طي استبدال هو. بنية دقيق دخول إضافة دلالة identity رفض حيث يجعل بدء يمكن استعادة، أيضا لا خدمة لم مرور إثبات قيمة.
- **في كل استخدام طريق في يأخذ ناقص صيغة بديل نظر لـ حالي بديل**: يمكن إبقاء ذاكرة مؤقتة قيمة، لكن يجعل ترحيل قبل طي التفاف مرور Session صيغة حافة. لا اعتماد، لأن v0→v1 يحتوي محدود تاريخ مواصفة تحويل، لاحق حافة أيضا ممكن تغيير حدث أساس عدد.title-only قائمة hint أكثر ضيق: هو لا بث نوع fold، بينما كما title نص في قد تثبيت edge بين إبقاء ثابت.
- **schema `.default()` ملء نقص حذف**: سلوك و optional+قراءة نقطة عودة واحد تحويل انتظار قيمة، لكن يأخذ"ناقص=unseeded"حل تفسير ثابت تحويل دخول durable schema إخراج نوع؛ التقاط لوح لـ optional——schema مثل فعلي وصف وسيط جودة فوق كل يتم قبول شكل، حل تفسير حق في إزالة استهلاك نقطة (2026-09-02 مستخدم قطع قرار).
- **مجال إصدار رجوع إلى 4**: تعديل جدا صغير، لكن كسر تالف إصدار مفرد ضبط صفة، اعتماد"bootstrap لا فحص إصدار"هذا عدد bug ذاته، كما إلقاء سم حالة و صحيح معتاد v5 home ذاكرة مؤقتة كل يتم إسقاط.

## أثر

- نشر جهة إذا يأخذ هذا مجال توجيه إلى sqlite خلفية، نيل لا إلى أي سعة تحمل قدرة:sqlite حيث لم تنفيذ `compatibleVersions` أيضا لا يوجد `backupRecord`، سلوك تراجع تحويل لـ أصل لديه صارم إطار إصدار دلالة (كامل unit إصدار لا مطابقة ما زال `version-mismatch` رفض فتح؛ لا وضع رخو، لا خروج خطأ قيمة).shipped تركيب ثابت توجيه json، هذا ريح خطر فقط وجود في نشر إعداد طبقة وجه.
- optional صيغة حقل سماح قبل بديل سجل عبر بنية تحقق، لكن ناقص صيغة بداية نهاية لا يمكن عبر حالي identity مطابقة. فقط لديه صيغة مطابقة بعد عندئذ عودة واحد تحويل optional lineage؛seeded استدعاء جهة ما زال رفض نقص lineage سجل. تدريجي سطر `ver` حراسة حماية متابعة غربلة فحص كل فعلي خدمة قيمة.
- `backupRecord` مقابل نفس مفتاح نفس قسم ساعة داخل تكرار تجهيز نسخة سوف تغطية قبل واحد نسخة (جديد بايت فوز خروج) ؛ مختلف قسم ساعة، مختلف مفتاح دائم لا اندفاع مفاجئ.

## اختبار

- `storage-json` مفرد قياس:compat إصدار ختم قراءة دخول/تجميع دمج خارج إسقاط/كتابة ثابت حالي إصدار؛legacy bootstrap فقط في إصدار يتم قبول وقت ترحيل (يحتوي ترحيل بعد وثيقة ختم حالي إصدار تأكيد) ؛`backupRecord` نقل ملف/قراءة نقص مقعد/إعادة كتابة/غلاف إغلاق حراسة حماية.
- `storage-domain` مفرد قياس:`compatibleVersions`/`invalidRecords` إعلان تحقق؛ خلفية بلا `backupRecord` وقت backup-and-skip رجوع fail-loud.
- `session-projection-cache` مفرد قياس: صيغة مطابقة كما نقص lineage سجل فقط خدمة unseeded Session؛ نقص صيغة بديل قبل بديل سجل لا يستطيع بث نوع fold، لكن فقط قدرة توفير ذلك توافق title hint.
- **عودة ملف fixtures مستقل استعادة اختبار**(`tests/fixtures.spec.ts` + `tests/fixtures/`): حقيقي إصدار شيء إنتاج خروج أربعة نسخة وسيط جودة تخزين ملف——`v3-single-unit.json`(0.1.1-rc.2 كامل مجال مفرد ملف) ،`v4-session-doc.json`(0.1.2-alpha.3) ،`v5-session-doc.json`(0.1.2-alpha.4) ،`v5-lineageless-doc.json`(بلا حراسة حماية bootstrap إلقاء سم شكل، من v3 سجل دمج صار)——تدريجي واحد مشي حقيقي تخزين مكدس فتح مجال، فقط خدمة ذلك توافق predecessor title، أبدا خدمة ذلك لم ربط طي، مع بعد من فوري كتابة استبدال صار حمل كامل identity و جديد قيمة v7 سجل. نفس طقم عنصر أيضا إثبات schema فشل سجل backup-and-skip: بدء لا فشل،`.bak` سقوط قرص، تشخيص نقطة اسم فشل، كما مجاور قريب قبل بديل سجل ما زال يمكن إعادة كتابة.

لم قدوم bump مسار: فقط لديه حالي تخزين schema قدرة تحليل قديم domain إصدار وقت، عندئذ يأخذ هو إضافة دخول `compatibleVersions`، مجددا من owner reader حكم قطع ذلك دلالة identity هل ملء قسم.Session صيغة تغير أبدا وراثة ناقص صيغة بديل. حزمة README اشتراط كل مرة bump كل مع مرفق عودة ملف fixture و اختبار، إثبات بنية دقيق دخول، دلالة استخدام أو رفض، و حالي إعادة كتابة.
