# Agent Note: Windows أصلي حمل دائم JSONL إصدار

Status: implemented

[English](2026-07-05-windows-jsonl-durable-publish.md) | العربية

## مشكلة

`dsh-session-persistence-jsonl` في أول مرة إلحاق وقت تأخير متأخر إصدار جلسة سجل.POSIX بروتوكول سوف كتابة مؤقت ملف، مقابل ذلك تنفيذ fsync، سوف ذلك رابط حتى نهائي اسم، مقابل أب دليل تنفيذ fsync، لكن بعد إزالة مؤقت رابط. مقابل أب دليل تنفيذ fsync هو حمل دائم صفة اتفاق واحد جزء: نطاق الأسماء تغيير بعد حدوث انهيار انهيار وقت، قد إيداع نهائي اسم لا يستطيع فقد فقد، لا فإن استدعاء جهة سوف خطأ بـ لـ جلسة سجل قد شيء تحويل.

Windows أداة تجهيز أصل فرعي نطاق الأسماء عملية، لكن Node لا يوجد كشف و POSIX انتظار قيمة أب دليل fsync اتفاق. إذا يأخذ Windows دليل تزامن فشل نظر لـ نجاح، حينئذ سوف في بلا تلميح حال حال تحت تقليل ضعيف حفظ دائم خلفية. لذلك،Windows مسار حاجة اعتماد مختلف إصدار أصل لغة، بينما لا هو في POSIX `syncDir` مساعد مساعدة دالة في إضافة شرط فرع.

## قرار

JSONL خلفية سوف في `materialize()` داخلي، أي نطاق الأسماء تغيير قبل قسم تدفق. مشترك شفرة حساب حساب جلسة دليل، نهائي سجل مسار، و تحرير رمز بعد header و ابتدائي حدث دفعة مرة؛ مع بعد POSIX و Windows قسم آخر تنفيذ كل منها إصدار بروتوكول.

POSIX إبقاء قائم بروتوكول: إنشاء أصل دليل، مشروع دليل و جلسة دليل، و مقابل ذلك أب دليل تنفيذ fsync؛ كتابة مؤقت ملف و مقابل ذلك تنفيذ fsync؛ استخدام `link()` إصدار، تأكيد حفظ أبدا تغطية قد لديه نهائي سجل؛ مقابل جلسة دليل تنفيذ fsync؛ الأكثر بعد إزالة كثير بقية مؤقت صلب رابط.

Windows عبر حمل دائم مؤقت تخزين إصدار قدوم إنشاء ناقص دليل: إنشاء واحد بـ ثابت `.dsh-mkdir-` لـ بادئة مع آلة نفس درجة دليل، ذلك اسم و هدف أساس هذا اسم غير متصل؛ مع بعد استخدام `MoveFileExW(..., MOVEFILE_WRITE_THROUGH)` سوف ذلك إصدار لـ نهائي دليل اسم، كما لا استخدام `MOVEFILE_REPLACE_EXISTING` أو `MOVEFILE_COPY_ALLOWED`. ملف شيء تحويل أولا كتابة مؤقت سجل و مقابل ذلك تنفيذ fsync، مجددا بـ نفس عدد تفعيل كتابة اختراق نفاذ `MoveFileExW` استدعاء سوف مؤقت ملف إصدار إلى نهائي مسار، و كما نفس مثال لا سماح استبدال.`koffi` هو تغطية هذا مجموعة API الذي يحتاج الأكثر صغير Win32 جسر وصل طبقة؛`pnpm-workspace.yaml` سماح تنفيذ هو تثبيت نص برمجي، لأن هذا حزمة سوف توزيع أصلي loader و مسبق بناء منصة وحدة.

## اعتبار مرور بديل خطة

**تجاهل اختصار Windows دليل تزامن فشل.** غير مقبول، لأن هذا سوف في لا يوجد قوي صنع سوف قد إصدار نطاق الأسماء بند كتابة مستقر تخزين وقت، حينئذ يأخذ أول مرة إلحاق تقرير إبلاغ لـ حفظ دائم نجاح.

**استخدام `CreateHardLinkW`.** غير مقبول، لأن صلب رابط اعتماد نظام الملفات، لا يستطيع إصدار دليل، و كما لا يوجد توفير كتابة اختراق نفاذ خيار.

**استخدام استبدال أو أمر خدمة نوع API.** `ReplaceFileW` استبدال دلالة و رفض نفس id اندفاع مفاجئ اشتراط متبادل تناقض، بينما جديد تطبيق تصميم لا ينبغي استخدام Transactional NTFS.

## أثر

هذا خلفية في كل منصة فوق صيانة حمل نفس بند خارجي اتفاق: أول مرة إلحاق يلزم ما يأخذ كامل سجل إصدار إلى نهائي اسم، يلزم ما فشل كما لا تغطية قد لديه سجل. منصة قسم تدفق فقط هو تنفيذ دقيق عقدة؛`SessionPersistence` API و JSONL منطق سجل صيغة متساو لا تغيير. لاحق [Zstandard تحرير رمز قرار](2026-07-19-zstandard-jsonl-session-logs.ar.md) سوف أولا أثر في لا نفاذ واضح بايت، لكن بعد عندئذ من مهمة واحد منصة تنفيذ إصدار.

Windows اختبار سوف في أصلي Windows فوق تنفيذ حقيقي Win32 إصدار مسار. قطع كهرباء سلوك يخص API اتفاق خاصية، اختبار وحدة لا يمكن إثبات؛ يمكن اختبار ثابت كمية يشمل:Windows شيء تحويل لن استدعاء دليل fsync، نهائي مسار اندفاع مفاجئ سوف فشل، بلوغ إلى الأكثر كبير طويل درجة هدف مسار مكون ما زال يمكن شيء تحويل، مؤقت سجل في إصدار قبل قد تنفيذ fsync، و كما توليد سجل يمكن صحيح معتاد تحميل.

اثنان عدد منصة إلحاق و إصلاح ما زال استخدام عادي ملف جملة مقبض fsync. إلحاق فشل بعد، نظام سوف إغلاق فقط إلحاق جملة مقبض، بـ قراءة كتابة نمط إعادة فتح سجل، سوف ملف مقتطع إلى إلحاق قبل كبير صغير، و مقابل تراجع نتيجة تنفيذ fsync، لأن Windows لا سماح في فقط إلحاق جملة مقبض فوق استدعاء `ftruncate`.
