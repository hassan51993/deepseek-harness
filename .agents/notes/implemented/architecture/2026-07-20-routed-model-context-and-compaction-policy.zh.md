# Agent Note: توجيه نموذج سياق و ضغط سياسة

Status: implemented

[English](2026-07-20-routed-model-context-and-compaction-policy.md) | العربية

## مشكلة

عند واحد عملية يأخذ طلب توجيه إلى مختلف سعة كمية نموذج وقت، ضغط (compaction) لا يستطيع أمان أرض تطبيق نفس عدد عام سياق نافذة. نفسه نموذج id أيضا ممكن وجود في كثير عدد مزود تحت، مهايئ أيضا ممكن قبول لا في بناء اقتراح دليل في حركة حالة id. خطأ سعة كمية يلزم ما يجعل ضغط إطلاق مرور متأخر و صنع صار أصل هذا يمكن تجنب تجنب فيض خروج، يلزم ما يجعل ضغط إطلاق مرور مبكر و إسقاط لديه استخدام سياق.

اثنان عدد مباشر مراقبة إعداد ملكية جهة كل لا يمكن مستقل حل قرار مشكلة.Compact-basic هو اختياري إضافة، لا معرفة طريق مهايئ قبول أي بعض نموذج.LLM(كبير لغة نموذج) مهايئ يملك نموذج توجيه، لكن لا يستطيع اعتماد اختياري ضغط إضافة، أيضا لا ينبغي امتصاص استلام مستهلك مخصص استخدام عتبة قيمة، إبقاء، ملخص جهاز و إعادة محاولة سياسة. هذا تصميم حيث حاجة مرجعي سعة كمية واقع و اختياري تدريجي هدف ضغط سياسة، أيضا لا يستطيع بناء قيام ثاني طقم نموذج سجل التسجيل.

## قرار

### مهايئ يملك دقيق توجيه سعة كمية

`LlmAdapter.resolveModel(provider, model, signal?)` إرجاع واحد بند دقيق توجيه تجمع دمج بيانات وصفية، منها اختياري `LlmModelContext` يقع في `context` حقل تحت.`LlmRuntime.resolveModelInfo()` اختيار قد تسجيل توجيه الذي تابع جهة، تحقق `contextWindow` لـ صحيح كامل عدد، و إرجاع و مهايئ داخلي حالة قسم مغادرة بيانات وصفية. هذا استعلام مستقل في `listModels()`: لا في دليل في حركة حالة نموذج أيضا يمكن يملك سعة كمية بيانات وصفية، بينما نقص قليل `context` فقط يمثل مهايئ لا يمكن وصف سعة كمية.

يد كتابة DeepSeek مهايئ سماح كل قد إعداد نموذج توفير اختياري `contextWindow`، و دعم حمل مهايئ درجة `defaultContextWindow`. دقيق نموذج سعة كمية أولوية؛ لم توفير سعة كمية نموذج بند و لم صف خروج نفاذ نقل id سوف وراثة مهايئ قيمة افتراضية، إذا قيمة افتراضية أيضا لا وجود فإن حذف `context`. اثنان عدد داخل وضع نموذج بند كل عام دقيق 256,000 token سعة كمية.pi-ai مهايئ من نفس عدد دليل وصف رمز تحليل سعة كمية، هذا وصف رمز أيضا لأجل مرجعي تحليل طلب نموذج.

### Token حساب كمية إبقاء نموذج غير متصل

`dsh-token-meter` لا يوجد إعداد، أيضا لا يوجد نموذج profile. هو يملك واحد ثابت إعادة تشغيل طي، و إرجاع قطعا مقابل تقدير حساب token ضغط قوة، و حسب موضع ترتيب صف جدول طبقة عقدة token تقدير قيمة. إزالة عام سعة كمية بعد، لم تحميل compaction-basic وقت ما زال يمكن إعادة استخدام حساب كمية، معا تجنب تجنب يجعل إعادة تشغيل نواة حساب تغيير صار آخر طقم نموذج سجل التسجيل.

### Compact-basic تحليل هدف قاعدة إطار

Compact-basic يملك مستهلك سياسة. قمة طبقة حقل تعريف قيمة افتراضية؛`modelPolicies` يتضمن بـ دقيق `{ provider, model }` تركيب لـ مفتاح جزء تغطية. تكرار هدف، لم معرفة حقل أو بلا فاعلية حقل كل سوف يجعل إضافة تحميل فشل.`thresholdRatio` افتراضي لـ `0.8`، إبقاء سياسة افتراضي لـ `retainRatio: 0.16`؛ استدعاء جهة أيضا يمكن تعديل استخدام قطعا مقابل `retainTokens`، لكن اثنان نوع إبقاء شكل صيغة متبادل رفض. إتمام وراثة بعد، إذا إبقاء مقارنة مثال لا صغير في عتبة قيمة مقارنة مثال، إضافة أيضا سوف تحميل فشل، لأن أي نموذج سعة كمية كل لا يمكن يجعل هذا سياسة صالح.

مقابل في رئيسي حركة ضغط قوة فحص،compaction-basic قراءة الأكثر جديد حمل دائم طلب توجيه، تحليل ذلك مهايئ سعة كمية و دقيق هدف سياسة، مجددا يأخذ مقارنة مثال تقليص وضع لـ `ResolvedCompactSpec`. كل مرة فحص كل سوف إعادة تحليل، لذلك نفس جلسة تبديل مزود أو نموذج بعد، سعة كمية و سياسة سوف قيام أي تغير. إذا قطعا مقابل إبقاء ميزانية لا صغير في تقليص وضع بعد عتبة قيمة، نظام سوف في هدف سعة كمية أول مرة سماح مقارنة مقارنة اثنان من وقت فشل.

نفس دقيق هدف تغطية أيضا يمكن اختيار ملخص مزود/نموذج، ملخص إخراج حد أعلى، استلام جمع إعادة محاولة مرة عدد و فيض خروج إعادة محاولة حد أعلى. هذه كل يخص ضغط مشكلة، لن دخول أي LLM مزود.

### هدف مخصص استخدام ضغط قوة خطأ ما زال إبقاء اختياري تركيب

نقص قليل سعة كمية بيانات وصفية مهايئ ما زال هو صالح LLM توجيه. يد حركة رئيسي حركة ضغط قوة فحص سوف إرجاع هدف مخصص استخدام إعداد خطأ؛ تلقائي مستمع حسب دقيق توجيه فقط تحذير إبلاغ مرة، و متابعة إبقاء كامل تاريخ. عند قد تحليل سعة كمية كشف خروج بلا فاعلية قطعا مقابل إبقاء ميزانية وقت، نظام أيضا حسب توجيه كبح صنع تكرار تحذير إبلاغ؛ أخرى تشغيل لذا عائق ما زال سوف كل منها مقابل خارج مرئي. مزود قد تأكيد مواصفة تحويل فيض خروج لا حاجة سعة كمية بيانات وصفية: هو التفاف مرور رئيسي حركة عتبة قيمة و عادي إبقاء ميزانية، محاولة تجربة مرة الأكثر كبير كما مستو توازن تقليص نقص، و في استبدال لا يمكن إثبات دخول عرض وقت إبقاء أصلي مزود خطأ.

## اختبار

خدمة اختبار تغطية و مهايئ داخلي حالة قسم مغادرة سياق بيانات وصفية، بلا فاعلية مهايئ إخراج، دليل مستقل صفة و افتراضي ناقص سلوك. مهايئ اختبار تغطية DeepSeek دقيق سعة كمية، افتراضي سعة كمية، لم صف خروج نموذج تحليل و بلا فاعلية سعة كمية، و pi-ai دقيق وصف رمز تحليل. ضغط اختبار تغطية مقارنة مثال تقليص وضع، دقيق مزود/نموذج تغطية، تحميل مدة رفض بلا فاعلية دمج مقارنة مثال، وقت التشغيل تحقق قطعا مقابل ميزانية، نفسه نموذج id مزود تبديل، هدف مخصص استخدام تحذير إبلاغ كبح صنع و لا اعتماد سعة كمية فيض خروج استعادة.Loader fixture(اختبار قبل وضع بيانات) سوف رفض قد إزالة token-meter سعة كمية ضبط، عرض مثال فإن في مهايئ فوق إعداد سعة كمية.

## اعتبار مرور بديل خطة

- **يأخذ سعة كمية و كل سياسة كل وضع دخول compaction-basic**——غير مقبول، لأن compaction-basic سوف نسخ مهايئ نموذج معرفة تعرف، لم صف خروج حركة حالة نموذج حاجة و سطر تسجيل، بينما كما لم تثبيت ضغط وقت سعة كمية أيضا سوف إزالة فقد.
- **يأخذ ضغط سياسة وضع دخول كل عدد LLM مهايئ**——غير مقبول، لأن مهايئ يجب مستقل في اختياري مستهلك، بينما ملخص و إعادة محاولة سياسة أيضا لا هو مزود واقع.
- **يجعل `listModels()` يصبح مرجعي مصدر**——غير مقبول، لأن اكتشاف قدرة فقط هو بناء اقتراح معلومة، واحد بعض مهايئ متعمد قبول حركة حالة id. صحيح تأكيد صفة بيانات وصفية لا يستطيع يأخذ اختيار جهاز عضو علاقة تغيير صار توجيه أبيض اسم مفرد.
- **إعطاء token-meter زيادة تدريجي نموذج طي**——غير مقبول، لأن إعادة تشغيل حساب قاعدة يمكن مشترك، تغير فقط لديه سعة كمية و مستهلك سياسة. كثير عدد طي سوف تكرار حالة، لكن لن تعديل حسن تقدير حساب.
- **بناء قيام مستقل نموذج سياق سجل التسجيل**——غير مقبول، لأن مهايئ قد يملك مرجعي توجيه تحليل. ثاني طقم سجل التسجيل سوف جذب دخول دورة الحياة ترتيب، تكرار مفتاح و عائم نقل مشكلة، لكن لا يوجد مستقل خلفية.

## عاقبة

- سعة كمية في مزود اتفاق فوق يملك وحيد مرجعي ملكية جهة، بينما ضغط سياسة إبقاء في اختياري إزالة استهلاك إضافة في.
- نفس عدد compaction-basic نسخة بلا حاجة استعلام اكتشاف بيانات وصفية، حينئذ قدرة أمان معالجة مختلف نافذة، مزود تبديل، و مختلف مزود تحت نفسه نموذج id.
- فقط LLM و فقط meter تركيب ما زال صالح؛ تحميل compaction-basic لن يجعل مهايئ إنتاج عكس نحو اعتماد.
- DeepSeek نشر يمكن ضبط دقيق تدريجي نموذج سعة كمية، أيضا يمكن يجعل لم توفير سعة كمية نموذج بند و لم صف خروج نفاذ نقل id استخدام `defaultContextWindow`.
- مقارنة مثال قيمة افتراضية سوف مع نموذج ذاتي لكن تقليص وضع، معا ما زال يمكن حسب دقيق هدف استخدام قطعا مقابل إبقاء قيمة، بـ ممتلئ كاف نشر مخصص استخدام سلوك.

هذا سجل يحل محل[إعادة تشغيل صيغة token حساب كمية خدمة Agent Note](../../archived/architecture/2026-07-15-replay-token-meter-service.md) في عام سعة كمية و بلا نموذج سياسة جزء، مفرد طي حساب كمية قرار إبقاء ثابت.
