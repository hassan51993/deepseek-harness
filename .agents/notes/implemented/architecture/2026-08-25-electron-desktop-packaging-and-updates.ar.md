# Agent Note: تحزيم و تحديث Electron طاولة وجه تطبيق

Status: implemented

[English](2026-08-25-electron-desktop-packaging-and-updates.md) | العربية

إضافة إدارة و أصلي استعادة التزام دوران[مشترك Web رقيق قشرة قرار](2026-09-10-desktop-web-wrapper.ar.md).

[Electron وقت التشغيل قرار](2026-09-11-desktop-electron-node-runtime.ar.md) بديل مستقل فوق تنقل Node يمكن تنفيذ ملف اختيار؛ هذا نص أخرى قرار ما زال ملائم استخدام.

## مشكلة

DeepSeek Harness حاجة واحد إعادة استخدام Web UI Electron طاولة وجه تطبيق. هذا تطبيق بلا حاجة نظام Node.js أو pnpm يكفي عمل، عبر تطبيق داخل وضع pnpm تثبيت dsh و طاولة وجه إضافة، و عبر واحد موجه إلى مستخدم مسار تحديث كامل طاولة وجه إصدار.

طاولة وجه تطبيق و عبر npm تثبيت dsh مشترك `.dsh` بيانات أصل دليل، لكن اثنان من ممكن استخدام مختلف dsh و إضافة إصدار. هو جمع يجب مشترك تلقي دعم حمل منتج بيانات، معا لا نيل مشترك يمكن تنفيذ حزمة،lockfile،`node_modules`، إضافة تنشيط حالة أو حزمة إدارة جهاز إعداد.

حالي GUI بروتوكول ربط Web عميل و خلفية إصدار.Electron ناتج و منها عبر داخل وضع dsh إذا مستقل تحديد إصدار، حينئذ سوف إنتاج لم مرور تحقق قشرة، عميل، خلفية و إضافة تركيب، أيضا لا يمكن واضح حكم قطع تحديث هل متاح.

## قرار

تسليم صغير نوع Electron قشرة و ثابت إصدار pnpm؛[وقت التشغيل قرار](2026-09-11-desktop-electron-node-runtime.ar.md) يحتفظ يمكن تنفيذ ملف اختيار.[رقيق قشرة قرار](2026-09-10-desktop-web-wrapper.ar.md) مسؤول Host بدء و نقل: خاص Host تشغيل مشترك Web profile runner،Electron تحميل ذلك إقرار إثبات HTTP URL، عملية فرعية IPC تحمل تحميل دورة الحياة رسالة.

Electron يملك `.dsh/profiles/desktop` إبقاء profile.[داخل وضع وقت التشغيل قرار](2026-09-08-desktop-bundled-runtime-and-external-plugins.ar.md) مسؤول نواة قلب مورد تخزين، خارجي إضافة اعتماد، مشترك حزمة رابط و profile تنسيق ضبط. خاص Desktop Host إبقاء مستقل في عام مشترك CLI حزمة، كما لن إصدار إلى npm.

واحد Desktop إصدار رقم معا معرف Electron ناتج و ذلك دقيق `@deepseek-ai/dsh` و `@deepseek-ai/dsh-desktop-host` اعتماد. إصدار لا يستطيع في بناء أو وقت التشغيل اختيار مختلف نواة قلب إصدار. لذلك، أي جعل قشرة شفرة لا يوجد تغير، تحديث dsh أيضا يجب إنتاج جديد Electron إصدار.

Desktop Host لـ إبقاء profile توفير مشترك Web إضافة إدارة جهاز، و عبر بدء جهاز معلومة توفير داخل وضع pnpm.CLI إبقاء `desktop` اسم كل كبير صغير كتابة تغيير جسم، و رفض إبرة مقابل هو بدء، إعداد dump و إضافة إدارة طلب.Electron في profile استعادة أو Host بدء قبل نيل أخذ عملية دورة الحياة مفرد نسخة قفل؛ لاحق بدء فقط سوف تجمع تركيز أو إعادة بناء رئيسي نافذة، لن وصل لمس profile حالة.

## ملكية

| Owner | مسؤولية |
|---|---|
| Electron قشرة | نافذة و عملية فرعية دورة الحياة، إبقاء desktop profile دقيق تجهيز، أصلي استعادة، تحديث تنسيق ضبط |
| Electron RunAsNode و pnpm | تنفيذ dsh و تثبيت طاولة وجه مشروع اعتماد، استخدام pnpm صحيح معتاد إعداد |
| Desktop profile | من داخل وضع وقت التشغيل قرار تعريف خارجي إضافة اعتماد، قد تفعيل bundle ترتيب و مشترك رابط |
| خاص Desktop Host حزمة | و dsh واحد بدء تثبيت، لكن لا دخول عام مشترك CLI حزمة أو npm إصدار Electron مخصص استخدام عملية فرعية مدخل و تركيب overlay |
| قد تثبيت dsh حزمة | خلفية، مطابقة Web UI، بدء manifest، عميل حزمة و منتج سلوك |
| مشترك `.dsh` owner | جلسة، ضبط، اعتماد، مساحة العمل و تخزين، من ذلك قائم قفل و صيغة إصدار حفظ حماية |
| عبر npm تثبيت dsh | ذاتي ذات يمكن تنفيذ تثبيت و مستخدم إدارة profile؛ لا يستطيع وصول إبقاء desktop profile أو حزمة حالة |

تصيير عملية استخدام `nodeIntegration: false`،`contextIsolation: true` و `sandbox: true`.Preload توفير بدء حينئذ خيط و فشل تقرير إبلاغ، أصلي دليل اختيار، رئيسي عنوان تزامن، و Windows قائمة مفرد و خارج مراقبة ملائم إعداد. هو لا كشف أصلي `ipcRenderer`، نظام الملفات وصول،shell أمر أو pnpm معامل.Electron قائمة مفرد و أصلي محادثة إطار استخدام نوع تحويل في إنجليزي نص نص سجل، و بـ إنجليزي نص رجوع؛Windows تتبع مع رئيسي وثيقة لغة. مشترك Web إضافة إدارة جهاز مسؤول ذاته عميل نص سجل.

## نظام الملفات تخطيط

```text
~/.dsh/
  profiles/
    desktop/
      package.json
      pnpm-lock.yaml
      lock
      pnpm-workspace.yaml
      node_modules/
  sessions/
  storages/
```

`.dsh/profiles/desktop` هو وحيد نشط حركة طاولة وجه profile. ذلك يمكن تنفيذ حزمة ملكية و سماح تحليل دليل التزام دوران[داخل وضع وقت التشغيل قرار](2026-09-08-desktop-bundled-runtime-and-external-plugins.ar.md).pnpm أصل حسب صحيح معتاد إعداد اختيار store و ذاكرة مؤقتة.

## تثبيت و تحليل

مشترك Web إضافة إدارة جهاز مسؤول profile حزمة عملية.Electron إبقاء بدء دقيق تجهيز و أصلي استعادة؛[Web رقيق قشرة قرار](2026-09-10-desktop-web-wrapper.ar.md) مسؤول هذا واحد مسؤولية تخطيط قسم.

Electron عملية دورة الحياة قفل هو Desktop مرجعي كل من.profile دقيق تجهيز و أصلي استعادة استخدام سجل Electron PID ترتيب هو قفل؛ تخزين نشط كل من منع توقف تنافس تنازع عملية، بطلان PID يمكن يتم عودة استلام.Web حزمة عملية استخدام مشترك إضافة إدارة جهاز قفل.

نواة قلب شيء تحويل، أول مرة بدء، إضافة تثبيت و مشترك وحدة تحليل التزام دوران[داخل وضع وقت التشغيل قرار](2026-09-08-desktop-bundled-runtime-and-external-plugins.ar.md). فعلي Host بدء وقت سوف تركيب قد تفعيل كما توفير `dsh.client` شفرة طاولة وجه إضافة.

## تحديث و استعادة

Electron تحديث فقط استخدام واحد `electron-updater` إصدار تدفق و توقيع `electron-builder` ناتج. هذا إصدار حينئذ هو Desktop إصدار إصدار؛ لا وجود مستقل dsh manifest، توافق نطاق أو فقط تحديث dsh عملية. قبل منصة تثبيت سوف انتظار صحيح في إجراء خلفية فحص، بينما لن يأخذ فحص نتيجة إعادة استخدام صار تثبيت نتيجة. تحديث نابض نافذة تحت تحميل و تثبيت Electron ناتج، لكن بعد إعادة بدء دخول جديد إصدار.

[قيام أي عرض نافذة قرار](2026-09-09-desktop-immediate-window-and-direct-start.ar.md) مسؤول محلي تحميل صفحة، مباشر بدء Host و رئيسي نافذة استعادة.profile تنسيق ضبط التزام دوران[داخل وضع وقت التشغيل قرار](2026-09-08-desktop-bundled-runtime-and-external-plugins.ar.md).

`DSH_DESKTOP_AUTO_UPDATE_ENV` افتراضي لـ اختبار نشر، أيضا يمكن اختيار إنتاج نشر، و معا قرار هدف مخصص استخدام generic-provider URL و COS هدف. إصدار تلقائي تحويل عبر `DOWNLOAD_TEST_ORIGIN` توفير اختبار HTTPS origin، و عبر `DOWNLOAD_TEST_COS_BUCKET` أو `DOWNLOAD_PROD_COS_BUCKET` توفير كل نشر bucket؛ متغير اختبار توجيه و COS تخزين هوية لا كتابة شفرة المصدر، نشر أساس أساس ضبط تطبيق تغيير وقت بلا حاجة إصدار جديد شفرة، بينما عام إنتاج origin ما زال ثابت. تحزيم فقط تحليل عام تحديث URL، منع توقف electron-builder إصدار، من عملية فرعية بيئة في حذف كل COS اعتماد حقل، و كما فقط لديه في electron-builder و كل توقيع أو عام إثبات hook نجاح بعد عندئذ كتابة إتمام سجل. هدف فوق نقل أيضا يجب توفير الذي اختيار bucket، مع بعد سوف أولا اشتراط إتمام سجل، أصل dsh إصدار،Desktop إصدار، أصل حسب إصدار نيل خروج تردد طريق بيانات وصفية، ناتج اسم، كبير صغير و SHA-512 الكل متسق، مجددا قراءة الذي اختيار اعتماد أو إرسال بيانات. هو أولا فوق نقل غير ممكن تغيير كما حمل إصدار تحديث تحميل حمل و كل مستقل blockmap، الأكثر بعد استبدال electron-builder توليد تردد طريق بيانات وصفية، و كما لن حذف تاريخ كائن. مستقر إصدار استخدام `latest` بيانات وصفية اسم، مسبق إصدار إصدار فإن استخدام دلالة تحويل إصدار رقم واحد مسبق إصدار معرف رمز.NSIS يأخذ blockmap تضمين دخول قد توقيع يمكن تنفيذ ملف،macOS ZIP فإن استخدام مستقل blockmap؛ اثنان من كل يجعل electron-updater في منصة دعم حمل وقت فقط تحت تحميل تغير بيانات كتلة، بينما تطبيق استبدال و محلي pnpm حزمة عملية ما زال هو اثنان عدد مستقل عملية.

## أمان و إصدار سياسة

نواة قلب dsh و خاص Desktop Host فقط قدوم ذاتي توقيع تطبيق مورد شجرة. إضافة تثبيت يأخذ حزمة قاعدة إطار تسليم إعطاء pnpm، يشمل محلي و بعيد مسار مصدر، لكن لا قبول أصلي pnpm أمر.pnpm مسؤول اعتماد تحليل و profile `allowBuilds` سياسة؛Host تحميل قد تفعيل bundle.

Electron إصدار ناتج يجب توقيع؛macOS ناتج يجب عام إثبات. تحزيم و فوق نقل أمر من Git تجاهل اختصار هدف `.env.windows` أو `.env.macos` قراءة إصدار إعداد، عملية فرعية عبر تحرير ترتيب جهاز اختيار بيئة حقل استقبال إعداد. هدف ملف هو إصدار حقل وحيد مصدر، تجنب تجنب قديم shell أو نظام اعتماد تغطية محلي اختيار؛ إعداد تحميل لا تعديل أب عملية بيئة. تحزيم في بناء، تحت تحميل أو تنظيف إصدار سجل قبل تحقق هذا نمط مطلوب تطبيق ID، تحديث عنوان، توقيع هوية و محلي ملف،macOS أيضا اشتراط واحد طقم كامل عام إثبات اعتماد. مفرد وحيد `check:package` تنفيذ نفس تحقق بينما لا وصول Token أو Apple؛ اعتماد حقيقي صفة ما زال من فعلي توقيع و عام إثبات تحقق. إعداد تحميل سوف رفض ناقص أو صيغة خطأ معرف رمز و لا كامل عام إثبات اعتماد،macOS تحزيم أيضا سوف قوي صنع توقيع، تجنب تجنب إثبات كتاب اكتشاف مرور مسار ساكن صامت اختيار أخرى قد تثبيت هوية أو توليد لم توقيع إصدار. وقت التشغيل دقيق تجهيز سوف تحقق كل داخل تضمين Mach-O ملف دقيق Authority و Team ID، و ختم الوقت و hardened-runtime علامة. توقيع بعد خطاف سوف تنفيذ Apple عميق درجة صارم إطار تطبيق تحقق، و اشتراط نفس ورقة إثبات كتاب Authority و Team ID تماما مطابقة، تحقق عبر بعد عندئذ متابعة توليد ناتج. ثابت هدف تثبيت حزمة أمر استخدام[عزل App فرعي هذا و سطر عام إثبات](../process/2026-09-09-parallel-macos-notarization.ar.md):ZIP يتضمن قد تثبيت بطاقة App، توقيع DMG فإن يحمل تغطية منها لم تثبيت بطاقة App بطاقة حسب.DMG artifact-completion hook اشتراط ذلك استخدام إعداد هوية، أداة تجهيز صالح بطاقة حسب و عبر Gatekeeper. فقط لديه اثنان بند ناتج تدفق كل نجاح، أمر عندئذ سوف نقل دخول ذلك إخراج و كتابة إصدار إتمام سجل؛ فقط توليد دليل أمر ما زال سوف عام إثبات App و تثبيت بطاقة.macOS تحديث استخدام توقيع ZIP، لذلك DMG لا توليد blockmap؛ لا فإن تثبيت بطاقة سوف يجعل قد توليد DMG blockmap بطلان.

[ثابت إصدار osx-sign رقعة](../../../../patches/@electron__osx-sign@1.3.3.patch) في اثنان نوع قد إصدار وحدة بناء في استخدام `lstat`، لذلك Framework ملف و دليل آخر اسم لن إطلاق تكرار توقيع. اختيار تحديد فوق تنقل إصدار قدرة كاف قفز مرور هذه آخر اسم قبل، ما زال يحتاج إبقاء هذا رقعة.PAK ملف من خارج طبقة bundle توقيع سجل كامل صفة؛ تدريجي عدد توقيع سوف زيادة سلسلة سطر ختم الوقت طلب، لكن لن زيادة مورد كامل صفة حفظ حماية.Desktop إبقاء الكل لغة ملف، فقط قفز مرور ذلك مفرد وحيد توقيع. يمكن تنفيذ شفرة ما زال استخدام Developer ID توقيع، أمان ختم الوقت و hardened runtime.[توقيع جهاز مرة تاريخ ارتداد اختبار](../../../../apps/desktop/tests/macos-signing-walk.spec.ts) استخدام حقيقي Framework آخر اسم تنفيذ قد تثبيت اعتماد؛ إصدار تحقق استلام ما زال اشتراط صارم إطار تطبيق تحقق، عام إثبات و بدء.

Windows إصدار تحزيم عبر `/f` نحو قد إعداد كما و SafeNet توافق SignTool توفير `DSH_DESKTOP_WINDOWS_CER_FILE` إشارة تحديد عام EV ورقة إثبات كتاب، و عبر مطلوب `DSH_DESKTOP_WINDOWS_KEY_CONTAINER` معرف مطابقة خاص مفتاح. إثبات كتاب ملف إبقاء في شفرة المصدر مستودع خارج، خاص مفتاح ما زال إبقاء في USB Token فوق.electron-builder hook يأخذ كل ناتج تسليم إعطاء اعتماد CRLF `windows-sign.cmd`؛ هذا CMD فقط استدعاء مرة SignTool، و إشارة تحديد SafeNet `/kc "[{{PIN}}]=حاوية"` قيمة و CSP،SHA-256 ملف ملخص و DigiCert SHA-256 RFC 3161 ختم الوقت.hook لن تعديل استخدام أخرى SignTool، أيضا لن إعادة محاولة فشل طلب. تحزيم تحرير ترتيب لن يأخذ أي `DSH_DESKTOP_WINDOWS_*` حقل نقل إعطاء بناء و وقت التشغيل دقيق تجهيز عملية فرعية، فقط سوف يأخذ إثبات كتاب مسار،SignTool مسار، مفتاح حاوية و PIN نقل دخول electron-builder. توقيع جهاز في قد تنظيف CMD بيئة في فقط توفير مرور مرور تحقق توقيع حقل؛CMD سوف منع استخدام تأخير متأخر توسيع، في SignTool بدء قبل صاف حذف هذه حقل، و فقط في SignTool مطلوب أمر سطر في إبقاء PIN. كل مقابل خارج تشخيص كل سوف استبدال PIN، بينما كما فقط قدرة سماح مخصص استخدام بناء حساب رقم و إدارة عضو فحص هذا runner. توقيع جهاز سوف في مؤسسة عمل Code Integrity فحص electron-builder مؤقت NSIS bootstrap قبل أولا لـ هذا يمكن تنفيذ ملف توقيع؛ مقابل في توليد يمكن تنفيذ ملف، فقط لديه إثبات كتاب جدول بند إشارة نحو ملف نهاية ذيل خارج وقت، عندئذ سوف في نهائي توقيع قبل صاف حذف هذا بند.SignTool، إثبات كتاب، حاوية،PIN،Token أو توقيع غير ممكن استخدام وقت، تحزيم سوف في إنتاج لم توقيع ناتج قبل فشل.

Windows تحزيم استدعاء قوي صنع ضبط `ELECTRON_BUILDER_7Z_FILTER=BCJ`. داخل وضع 7-Zip 24.09 تحرير رمز جهاز سوف لـ ARM64 PE ملف تلقائي اختيار ARM64 مرور ترشيح جهاز، لكن `nsis-resources-3.4.1` في NSIS حل رمز جهاز سوف في حل ضغط وقت متروك تسرب هذه بند. استخدام فعلي NSIS إضافة أصلي حل ضغط تحقق جدول واضح، تلقائي مرور ترشيح سوف فقد فقد اثنان عدد `node-pty` ARM64 اثنان دخول صنع ملف، بينما BCJ يمكن تدريجي بايت أيضا أصل اثنان من. استخدام توافق مرور ترشيح جهاز قدرة كاف إبقاء اعتماد محتوى و وقت التشغيل كامل صفة، بلا حاجة حذف خاص تحديد هيكل بنية ملف أو تقليل ضعيف تحقق.

محلي Windows تثبيت اختبار استخدام صريح `--unsigned` تحزيم استدعاء، و تنفيذ نفسه بناء و وقت التشغيل دقيق تجهيز. هو صاف حذف إثبات كتاب إدخال، سوف ناتج عزل إلى `unsigned-artifacts`، و حذف تحديث جهاز إعداد و إصدار إتمام سجل. أي جعل أب عملية بيئة طلب لم توقيع نمط، معتاد قاعدة تحزيم أمر أيضا سوف صريح اختيار توقيع نمط. هذا مثال حيث قدرة في لا يوجد EV Token وقت تشخيص تثبيت مشكلة، أيضا قدرة منع توقف محلي اختبار ناتج عبر إصدار فوق نقل تحقق.

Windows تطبيق استبدال التزام دوران[دليل تثبيت قرار](2026-09-11-windows-directory-installation.ar.md): استخدام قدرة إرجاع فشل حالة أمر سطر أداة حل ضغط إلى هدف جانب حافة، مجددا في نفس لفة داخل تعديل اسم استبدال كامل دليل. تثبيت جهاز في مؤقت تخزين خلال إبقاء قديم دليل، صحيح صيغة استبدال فشل وقت استعادة قديم دليل. تسجيل معلومة، سريع سريع طريقة و توقيع إزالة جهاز ما زال من electron-builder يحتفظ.

تحزيم تطبيق سوف تجاهل اختصار تطوير مورد و مشروع بيئة متغير تغطية. فقط لديه لم تحزيم Electron عملية يمكن استبدال pnpm مدخل،dsh مورد أو نشط وثب مشروع.

قسم هيكل بنية بناء تقرير إبلاغ فعلي مكون درجة ضغط جسم تراكم و تثبيت جسم تراكم.

## تنفيذ

| جدول وجه | تنفيذ |
|---|---|
| قشرة | `apps/desktop` مسؤول Electron نافذة، تلقي حد preload، ذاتي تعريف بروتوكول، عملية فرعية دورة الحياة،profile دقيق تجهيز، أصلي استعادة، تحديث تنسيق ضبط و electron-builder إعداد. |
| قد تثبيت وقت التشغيل | خاص `@deepseek-ai/dsh-desktop-host` استدعاء مشترك profile runner، و نحو Electron تقرير إبلاغ إقرار إثبات Web URL. |
| حزمة حالة | Electron RunAsNode تنفيذ غير ممكن تغيير نواة قلب مورد؛ داخل وضع pnpm فقط تعديل Desktop profile في خارجي إضافة اعتماد رسم. |
| مورد إطار تحقق | macOS تحزيم اشتراط قد إعداد عام شركة هوية و عام إثبات اعتماد متاح، في توليد بيان قبل تحقق كل أصلي وقت التشغيل ملف، تحقق كامل تطبيق توقيع، و اشتراط تطبيق و DMG كل إتمام عام إثبات كما عبر Gatekeeper.Windows تحزيم اشتراط قد إعداد عام إثبات كتاب،SafeNet خاص مفتاح حاوية،Token Password و SignTool، و تحقق توليد كل توقيع. تحديث حمل إدارة، عبر فوق واحد إصدار قد تثبيت ناتج اختبار و كل منصة GUI تسجيل صنع ما زال هو إصدار بيئة باب عتبة. |

`dev:desktop` سوف بناء حالي workspace، يأخذ قد بناء CLI حزمة، خاص Desktop Host حزمة و ذلك اعتماد رابط إسقاط لـ مرة صفة مشروع، استخدام عزل Harness home، فتح Main،Renderer و Host ضبط تجربة جهاز، و في لا دقيق تجهيز إصدار مورد حال حال تحت بدء لم تحزيم Electron. تطوير وقت التشغيل لـ مستقل إضافة profile توفير مساحة العمل رابط؛ إضافة إدارة و استعادة استخدام و تحزيم تطبيق نفسه مسار. ثابت macOS arm64،macOS x64 و Windows x64 تحزيم أمر سوف يأخذ نفس هدف نقل إعطاء وقت التشغيل دقيق تجهيز،dsh دقيق تجهيز و electron-builder؛ كل بند أمر أيضا توفير لم غلاف تركيب تثبيت جهاز تغيير جسم، لأجل في توليد تثبيت جهاز قبل تحقق إصدار مسار.

## اعتبار مرور بديل خطة

**استخدام Electron Node.js تنفيذ dsh.** هذا يمكن نقص صغير حزمة جسم تراكم، لكن سوف يجعل dsh اقتران دمج إلى Electron Node رقعة،fuse، أصلي ABI،TLS سلوك و عملية دورة الحياة. داخل وضع فوق تنقل Node.js يمكن يجعل dsh متابعة استخدام ذلك تلقي دعم حمل وقت التشغيل.

**عبر JSON IPC بـ Base64 تحمل تحميل Fetch رسالة جسم.** هذا سوف تمدد انتفاخ طلب و استجابة رسالة جسم، في اثنان عدد عملية في بنية صنع كبير نص، و في قسم إرسال قبل مؤقت اندفاع طلب. أصلي قسم لقطة إدارة طريق تجنب تجنب Base64 تمدد انتفاخ، لكن ما زال يحتاج صيانة ثاني طقم نقل؛[رقيق قشرة قرار](2026-09-10-desktop-web-wrapper.ar.md) اختيار قد لديه Web HTTP نقل.

**يأخذ منتج Web UI دائم دائم تحزيم دخول Electron.** مستقل UI و خلفية تحديث حاجة جديد إصدار تحويل توافق حساب تخطيط. من نفس عدد dsh حزمة تثبيت خلفية و Web UI يمكن إبقاء حالي إصدار ربط.

**صيانة Electron مخصص استخدام إضافة تثبيت جهاز.** مستقل صفحة،IPC API و حزمة خدمة سوف تكرار مشترك Web إدارة جهاز وظيفة. مشترك خدمة استخدام إبقاء Desktop profile و بدء جهاز توفير pnpm، معا متابعة منع توقف CLI وصول هذا profile.

**يجعل طاولة وجه profile استخدام CLI إدارة حزمة أو إضافة.** مهمة واحد منتج كل ممكن تغيير آخر منتج اعتماد رسم،Cordis إصدار، إضافة إصدار أو أصلي وحدة.Desktop رفض عبر CLI profile رجوع دليل تحليل حزمة.

**قسم مغادرة نواة قلب و إضافة تحليل، لكن لا توفير مشترك حزمة رابط.** pnpm لم تثبيت مضيف peer حزمة وقت، إضافة حاجة وصول داخل وضع وقت التشغيل.[داخل وضع وقت التشغيل قرار](2026-09-08-desktop-bundled-runtime-and-external-plugins.ar.md) عبر واضح رابط توفير profile ناقص حزمة، معا إبقاء pnpm تثبيت حزمة.

**من registry حزمة حذف غير هدف Mach-O ملف.** هيكل بنية قطع قص يمكن عقدة حذف قليل كمية وقت التشغيل فضاء، لكن حزمة ممكن متعمد مرفق حمل كثير عدد هيكل بنية تغيير جسم، استدعاء جهة أيضا يمكن مراقبة تثبيت بعد ملف تجميع. توقيع توقيع كل فعلي يحمل Mach-O كائن، بلا حاجة إرسال واضح Desktop مخصص تابع حزمة تخطيط حينئذ قدرة ممتلئ كاف عام إثبات اشتراط.

**يأخذ Windows EV خاص مفتاح توجيه خروج إلى PFX ملف.** خارجي توفير عام ورقة إثبات كتاب يجعل SignTool بنية صنع توقيع،`/csp` و `/kc` فإن تحديد موضع صلب عنصر مفتاح.EV خاص مفتاح إبقاء غير ممكن توجيه خروج، و إبقاء في Token فوق.

**يأخذ اعتماد كتابة دخول قد تتبع أثر نص برمجي أو نظام بيئة.** محلي منصة ملف يأخذ إعداد حد في مفرد عدد checkout، و جعل تحزيم إدخال واضح. بديل قيمة هو اعتماد بـ واضح نص سقوط قرص: بناء حساب رقم حاجة حد ملف وصول إذن،CI يجب تنظيف مؤقت إعداد،Git و إصدار ملف خريطة كل يجب ترتيب حذف حقيقي إعداد. قد إيداع نموذج لوح لا يحتوي اعتماد؛Windows CMD فقط يتضمن متغير مرجع، توقيع سلسلة سطر تنفيذ و في أول مرة فشل بعد إيقاف، ملف صيغة لن تجنب حذف Token خطأ PIN حساب عدد.

**يجعل electron-builder أو عام دليل تزامن مباشر إصدار.** مباشر إصدار ممكن في كل مرجع ناتج حينئذ خيط قبل كشف تردد طريق بيانات وصفية، ممكن يأخذ قديم قديم أو أخرى هدف ملف خلط دخول إصدار، أيضا لا يمكن إثبات قد إتمام توقيع بناء ما زال و حالي dsh إصدار متسق. هدف مخصص استخدام كما مرور مرور تحقق فوق نقل يمكن واضح تحكم إصدار ترتيب و إصدار هوية.

## نتيجة

- لا يوجد نظام Node.js أو pnpm جاف صاف مغادرة خط آلة جهاز قدرة كاف بدء داخل وضع dsh، بلا حاجة تثبيت نواة قلب اعتماد.
- توقيع تطبيق سجل نهائي وقت التشغيل ملف بيان؛ كل macOS أصلي ملف كل أداة لديه إصدار Developer ID، أمان ختم الوقت و hardened runtime، كل Windows ناتج كل أداة لديه إعداد صلب عنصر EV توقيع.
- `.dsh/profiles/desktop/node_modules` حفظ من مشترك Web إضافة إدارة جهاز إدارة خارجي إضافة.
- Desktop حزمة عملية استخدام بدء جهاز توفير داخل وضع pnpm، و مشترك إدارة جهاز عملية فرعية بيئة و profile إعداد.
- رئيسي تطبيق “إضافة” صفحة نحو مشترك Host خدمة إرسال بنية تحويل حزمة عملية و تنشيط طلب.
- مستقل CLI ما زال لا يستطيع وصول إبقاء Desktop profile.
- npm/CLI dsh و Electron أبدا من مقابل جهة `node_modules` تحليل أو تثبيت إضافة.
- في منتج UI تحميل قبل، نشط وثب خلفية و Web UI تقرير إبلاغ نفسه dsh إصدار و توافق قشرة API.
- مشترك إضافة إدارة جهاز مسؤول حزمة عملية فشل معالجة؛ أصلي استعادة مسؤول Host يؤدي أمر لذا عائق.
- واحد Desktop إصدار ربط Electron و dsh؛ كل مرة dsh تحديث كل عبر واحد Electron تحديث نابض نافذة تسليم، و إنتاج مرة مستخدم مرئي إعادة بدء.
- مشترك `.dsh` بيانات في ترحيل أو تعديل قبل رفض لا توافق قراءة جهة.
- Web تطبيق مسؤول HTTP إقرار إثبات و خدمة؛ صندوق رملي تصيير عملية لا يستطيع وصول مهمة معنى نظام الملفات أو Electron API.
- Workspace تطوير بلا حاجة تحت تحميل إصدار مورد يكفي تشغيل حالي قد بناء شفرة، لم غلاف تركيب تثبيت جهاز تطبيق تحقق ما زال إبقاء إنتاج تثبيت مسار.
- Windows إصدار تحزيم اشتراط قد تحقق SignTool،EV Token، مطابقة عام ورقة إثبات كتاب،Token Password و واضح مفتاح حاوية، أبدا سوف رجوع إلى لم توقيع ناتج أو يمكن توجيه خروج مفتاح ملف.
- هدف تحديث فقط لديه في قد إتمام توقيع بناء و ذلك مرجع كل ناتج عبر إصدار تحقق بعد عندئذ قدرة كشف جديد تردد طريق بيانات وصفية؛ إبقاء تاريخ ناتج متابعة توفير فرق قسم تحديث استخدام.
- كل إصدار منع قطع منصة فوق توقيع قد تثبيت ناتج متساو قدرة من فوق واحد تلقي دعم حمل إصدار نجاح تحديث.

## مراجعة قرار

| قرار | بناء اقتراح |
|---|---|
| أول مرة بدء | فحص داخل وضع إصدار بيانات وصفية و إنشاء profile رابط، لا تثبيت نواة قلب اعتماد |
| طاولة وجه profile | واحد من Electron يملك إبقاء profile، حفظ خارجي إضافة و مشترك حزمة رابط |
| إضافة إدارة | مشترك Web“إضافة” صفحة و Host خدمة، استخدام بدء جهاز توفير داخل وضع pnpm |
| تنشيط | تفعيل HMR وقت من مشترك إدارة جهاز تطبيق إعداد؛ لا فإن تغيير حاجة إعادة بدء |
| ابتدائي منصة | macOS arm64/x64 و Windows x64؛Linux بعد بلا تلقي دعم حمل إصدار هدف |
| تحديث سلوك | خلفية فحص، فرق قسم تحت تحميل و إعادة بدء قبل صريح تأكيد، بدء وقت تدقيق دقيق dsh |

## ريح خطر

إضافة دورة الحياة نص برمجي سوف تنفيذ رقم ثلاثة جهة شفرة.profile `allowBuilds` إعداد قرار أي بعض بناء نيل دقيق تنفيذ.

تحديث ربط dsh ممكن جعل إضافة peer اعتماد أو أصلي وحدة لا توافق. أصلي استعادة يمكن منع استخدام رقم ثلاثة جهة bundle و إعادة بدء تطبيق، بعد يمكن عبر مشترك “إضافة” صفحة إصلاح.

عبر npm تثبيت dsh و طاولة وجه dsh ممكن في مشترك حفظ دائم بيانات وقت استخدام مختلف إصدار. كل مشترك owner كل يجب في قراءة، ترحيل أو كتابة قبل تنفيذ صيغة إصدار و عملية قفل.

حزمة عملية فشل و إلغاء التزام دوران مشترك إضافة إدارة جهاز أيضا أصل قاعدة. أصلي استعادة لن إعادة تثبيت حزمة.

شفرة توقيع، عام إثبات و تحديث حمل إدارة حاجة إنتاج إصدار أساس أساس ضبط تطبيق. فقط تشغيل مستودع اختبار لا يستطيع إتمام هذه إقرار إثبات.
