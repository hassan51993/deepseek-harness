# Agent Note: Fork child إبقاء parent طلب بادئة

Status: implemented

[English](2026-08-10-fork-children-stay-one-shot.md) | العربية

## مشكلة

fork و spawn فرق مختلف في في:fork سوف استخدام parent اكتمل جولة بادئة بصفة child Session نوع فرعي. هذا نوع فرعي سوف إزالة استهلاك token، ذلك مسبق مدة استلام فائدة هو مزود جانب بادئة إعادة استخدام: استخدام نفسه مزود و نموذج وقت، إذا child طلب فتح رأس بايت و parent نفسه، مشترك منطقة مقطع حينئذ بلا حاجة مجددا مرة مسبق ملء ملء. أي يقع في وراثة تاريخ قبل، فقط يخص child توجيه النظام section أو أداة schema كل سوف كسر تالف هذا بند استلام فائدة.

أولا قبل مع مرفق تركيب عبر يأخذ fork child إبقاء لـ one-shot قدوم تجنب فتح هذا نوع لا مطابقة. هذا حد مصدر في أصل قدوم child-only إرجاع أداة، و غير يمكن متابعة fork ثابت لديه خاصية.

## قرار

موجه إلى نموذج `send_message` أداة في تركيب في كل Agent فوق عام تسجيل. لذلك، يمكن متابعة fork child نيل نيل و parent نفسه أداة اسم، وصف،schema و ترتيب. ذلك ابتدائي مهمة إلحاق في وراثة Session نوع فرعي بعد؛ عند child يمكن يرى هذا أداة وقت، مهمة أيضا سوف يتضمن مباشر parent id، و استخدام `send_message({ agent_id, message })` إرجاع نتيجة إشارة جذب.

base و headless تركيب إبقاء one-shot fork بصفة ذلك حفظ حراسة دورة الحياة سياسة.`cordis`،`standard` و `ptc` CLI preset يمكن يأخذ fork ربط لـ يمكن متابعة دورة الحياة، لأن هذا ربط لم يعد إدراج دخول child-only طلب رأس حقل.`ForkInProcessProvider.prepareContinuable()` و `ctx.subagents.startContinuable()` ما زال هو هذه preset استخدام تنفيذ seam.

تدريجي بايت نفسه بادئة إعادة استخدام تلقي صريح نشر اختيار قيد. إعداد child persona أو `toolFilter` fork تفويض إرسال ما زال ممكن تغيير طلب رأس. خاصة ذلك هو مرور ترشيح إسقاط `send_message` وقت،child سوف معا فقد ذهاب هذا schema و إرجاع إشارة جذب؛ وقت التشغيل لن التفاف مرور صريح allow-list.

## اعتبار مرور بديل خطة

**يجعل كل fork إبقاء one-shot.** هذا قدرة إبقاء بادئة، لكن child-only schema فرق مختلف إزالة فقد بعد، متابعة وضع ترك حمل دائم كما كثير جولة fork child قد بلا لا بد يلزم.

**تثبيت child-only إرجاع آخر اسم.** بلا حاجة ملء كتابة استقبال جهة آخر اسم يمكن تقليص قصير child استدعاء، لكن سوف في وراثة تاريخ قبل إعادة إنتاج أداة schema و نص التوجيه فرق مختلف، و تكرار متبادل مجاور Agent عملية.

**يأخذ إرجاع إشارة أمر وضع دخول توجيه النظام.** هذا سوف في وراثة رسالة قبل إضافة دخول child-only بايت. سوف ذلك إلحاق إلى ابتدائي مستخدم مهمة، يمكن إبقاء وراثة بادئة، و يجعل parent id ضيق مجاور حاجة هو مهمة.

**تجاهل اختصار صريح child `toolFilter`.** بنية صفة إرجاع أداة مرور ذهاب سوف التفاف مرور child allow-list. مرفوض هذا خطة، لأن إعلان أداة حد يجب معا قرار schema مرئي صفة و إشارة جذب؛ إخفاء إذن سوف يجعل موجه إلى نموذج أداة بيان فقد حق.

## عاقبة

- لم طلب persona أو أداة مرور ترشيح وقت،parent و يمكن متابعة fork child كشف تدريجي بايت نفسه كما ترتيب متسق أداة schema.
- وراثة Session نوع فرعي يقع في child ابتدائي مهمة و ذلك إرجاع إشارة جذب قبل.
- base و headless profile إبقاء one-shot fork؛ اختيار تحديد CLI preset سوف في لا يوجد child-only طلب رأس زيادة كمية قبل رفع تحت استخدام يمكن متابعة fork.
- child صريح نحو مباشر parent إرسال صفر بند أو كثير بند رسالة؛ نهائي عودة جواب لن يتم خفي صيغة نسخ. إدارة جهاز مسؤول تسوية إشعار ما زال بلا شرط تنفيذ، و كما و Agent رسالة قسم مغادرة.
- keyless snapshot و حزمة اختبار ثابت schema متبادل انتظار صفة، وراثة تاريخ ترتيب،parent-id إشارة جذب، و عبر نفس عدد `send_message` عملية إتمام child-to-parent إلقاء تمرير.

### قد قبول ريح خطر

مزود جانب بادئة إعادة استخدام ما زال أخذ قرار في اختيار تحديد مزود و نموذج، و هل لا وجود صريح persona أو أداة مرور ترشيح فرق مختلف.harness إثبات هو ذاتي ذات تجميع خروج طلب رأس إدخال متبادل انتظار، بينما لا هو مزود ذاكرة مؤقتة سلوك.
