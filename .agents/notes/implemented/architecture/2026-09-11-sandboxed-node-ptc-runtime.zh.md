# Agent Note: PTC صندوق رملي Node تنفيذ

Status: implemented

[English](2026-09-11-sandboxed-node-ptc-runtime.md) | العربية

## مشكلة

Node worker عزل JavaScript حالة، لكن لا تطبيق استدعاء Session OS صندوق رملي سياسة. نموذج شفرة يمكن مباشر استيراد نظام الملفات و عملية فرعية API، التفاف مرور أداة سياسة مسار، أي جعل تضمين طقم `tools.*` استدعاء تلقي إلى صحيح تأكيد فحص. إنهاء worker أيضا لا يستطيع إثبات ذلك عملية فرعية قد إيقاف.

[PTC أساس أساس](../feature/2026-06-15-ptc.zh.md) متابعة مسؤول سجل التسجيل عرض، توليد ربط، قسم إرسال سجل و مرة صفة تسوية. هذا قرار يحل محل منها أساس في worker تنفيذ، معلومة مهمة و ميزانية تنفيذ، معا إبقاء مستهلك قاعدة.

## قرار

`dsh-ptc-runtime-node` في واحد كل جديد Node عملية في تشغيل كل برنامج.Host تحليل تنفيذ اختيار، عبر و Bash نفسه `ctx.sandbox` مزود قيد بدء، و سوف عملية دورة الحياة تسليم إعطاء `ctx.subprocess`. عملية فرعية بـ مباشر Node API، فارغ نموذج بيئة و Host توفير مختلف خطوة ربط طلب قيمة يمكن مسح حذف TypeScript. هذا مزود لا إبقاء worker أو حمل دائم داخل نواة.

Host في عملية فرعية بدء وقت إبقاء `ELECTRON_RUN_AS_NODE`؛bootstrap في طلب قيمة قبل سوف ذلك من أصلي بيئة في حذف، نموذج مرئي `process.env` ما زال لـ فارغ. تضمين طقم بدء Electron حاجة ذاتي سطر صريح اختيار Node نمط. طاولة وجه طرف استخدام Electron بصفة Node يمكن تنفيذ ملف؛ حذف هذا اختيار متغير سوف بدء Electron تطبيق مسار، بينما لا هو PTC bootstrap. أكثر تعديل صندوق رملي إذن لا يمكن إصلاح هذا واحد بدء نمط لا مطابقة.macOS طاولة وجه طرف ارتداد اختبار استخدام حقيقي Electron تحقق ربط كتابة، مباشر مساحة العمل كتابة و تلقي حد سياسة مقابل مساحة العمل خارج كتابة رفض. هذا اختبار حاجة قد تثبيت Electron اثنان دخول صنع ملف؛ عادي وقت التشغيل اختبار بلا حاجة هذا اعتماد يكفي تغطية بيئة مرور ترشيح.

### قد تحليل إدخال و سياسة

`PtcRuntime.resolve(request)` تحقق دعم حمل خيار و تكملة كل `PtcRunSpec`؛`run(spec)` لا جذب دخول قيمة افتراضية.PTC نقل دخول استدعاء Session cwd و قد تحليل معتاد ضبط سياسة. مباشر وقت التشغيل استدعاء جهة عبر نفس محلل أخذ نيل نشر قيمة افتراضية. نظام الملفات و عملية فرعية مزود مشترك واحد تنفيذ عالم حد،bootstrap مسار عبر نظام الملفات صريح مضيف ملف خريطة أو إعداد مسبق تثبيت bootstrap نقل تمرير.

ملف نمط، مراقبة إلى رفض و قوي صنع كامل صفة عبر `PtcRunResult.sandbox` مستقل في برنامج نتيجة نقل تمرير. الذي يحتاج صندوق رملي خلفية لا يمكن بدء وقت، تلقي حد تنفيذ فشل. كامل وصول هو صريح سياسة نمط. برنامج نجاح لا إثبات كامل قوي صنع قدرة،`process` وصف رمز و مقدار خارج تحكم إدارة طريق أيضا لا إعلان كثير إيجار مستخدم عزل.

خاص Python مزود إبقاء قائم تنفيذ تنفيذ و إعداد مرور مرور وقت قطع توقف. ذلك محلل قبول cwd، لكن رفض صريح ملف سياسة أو مفرد مرة timeout تغطية؛ قدرة وصف رمز لن ساكن صامت منح إعطاء لا تلقي دعم حمل حفظ حماية.

### تحكم و دورة الحياة

عملية فرعية كل من توفير مخصص استخدام وراثة صيغة اثنان دخول صنع تحكم عبر طريق، و برنامج stdout/stderr و launcher دورة الحياة IPC قسم فتح.Host حد لقطة، ترتيب طابور كتابة، انتظار معالجة استدعاء و لم إتمام معامل بايت، لكن بعد في قسم إرسال قبل تحقق استدعاء هوية و ربط سماح قائمة. نموذج شفرة يمكن كتابة هذا عبر طريق، لذلك منها بايت ما زال غير ممكن معلومة.

برنامج إتمام، مهلة، إلغاء و بروتوكول فشل كل عبر تلقي إدارة عملية كل من إغلاق تنفيذ. اختيار نتيجة بعد إيقاف تنفيذ حساب وقت جهاز؛ تنظيف مع بعد انتظار مباشر نتيجة و تلقي إدارة نطاق توقف مستقر.PTC جسر وصل في خارج طبقة أداة نتيجة تسوية قبل، آخر سطر إلغاء و ترتيب فارغ تضمين طقم أداة قسم إرسال. رفض أو نقل فشل أبدا تلقائي إعادة وضع ممكن قد إنتاج فرعي أثر برنامج.

### مورد حد

افتراضي مرور مرور وقت قطع توقف لـ 120 ثانية، افتراضي حد أعلى لـ 600 ثانية. يمكن معلومة خدمة مستهلك يمكن طلب `timeoutMs: null` قدوم منع استخدام هذا تحديد وقت جهاز؛[سير العمل صندوق رملي إعادة استخدام](2026-09-13-workflow-ptc-sandbox-reuse.zh.md) مسؤول هذا نوع من استدعاء جهة تحكم دورة الحياة. حذف timeout أو استخدام عدد قيمة طلب (يشمل موجه إلى نموذج `run_code`) إبقاء عدد قيمة قيمة افتراضية و حد أعلى. تفعيل قطع توقف يشمل وقت التشغيل دقيق تجهيز و تضمين طقم أداة أو مراجعة دفعة انتظار.V8 قديم توليد بديل داخل تخزين، تسلسل تحويل خارج طبقة إخراج و تحكم عبر معلومة أداة لديه مستقل إعداد حد أعلى. كومة حد لا يتضمن أصلي قسم إعداد و بعد بديل داخل تخزين، مرور مرور وقت أيضا لا هو عملية شجرة CPU ميزانية.

## اعتبار مرور بديل خطة

**إبقاء worker و زيادة أداة فحص.** أداة فحص لا يستطيع اعتراض قطع مباشر Node استيراد، أيضا لا يستطيع بناء قيام OS قيد. في تلقي حد مراقبة إشراف عملية في إبقاء worker يمكن إبقاء worker حساب كمية، لكن سوف زيادة واحد طبقة تنفيذ دورة الحياة، ما زال لا يستطيع توفير عملية شجرة CPU حد.

**استخدام نفس عملية JavaScript realm.** لغة درجة realm لا قوي صنع مباشر Node API الذي يحتاج نظام الملفات و عملية سياسة. الذي يحتاج حفظ حماية هو OS قيد و Host يملك عملية دورة الحياة.

**نسخ Codex Code Mode تنفيذ نموذج.** [Codex Code Mode](https://github.com/openai/codex/blob/02a8f038b87ad34d4a1dc5058eda26972ed7aa6c/codex-rs/code-mode-protocol/src/description.rs) توفير كل جديد أصلي JavaScript isolate و Host أداة عودة ضبط،yield/wait مراقبة و تنفيذ دورة الحياة قسم فتح. إزالة Node API أو زيادة يمكن استعادة وحدة سوف تغيير PTC تحرير مسار و سجل نموذج. إبقاء تصميم في OS سياسة تحت توفير مباشر Node وصول، و إرجاع مرة صفة نتيجة.

**يأخذ worker active time عند عمل CPU حد.** حدث حلقة احتلال استخدام معدل حساب كمية مفرد عدد worker نشط وثب مرور مرور وقت، لا هو Node و ذلك بعد بديل إزالة استهلاك CPU. عملية مزود استخدام Host يملك مرور مرور وقت قطع توقف، لا عمل أكثر قوي إعلان.

## عاقبة

كل مرة `run_code` كل تحمل تحمل Node عملية بدء و OS صندوق رملي دقيق تجهيز صار هذا. مقارنة طويل تضمين طقم أداة و مراجعة دفعة إزالة استهلاك و مباشر برنامج عمل نفسه مرور مرور وقت ميزانية. تنظيف ممكن يجعل استدعاء جهة في قطع توقف بعد متابعة انتظار. أكثر قوي بعد بديل قيد ما زال أخذ قرار في الذي اختيار عملية فرعية خلفية؛ ذلك fallback حد إبقاء مرئي، لن يتم وقت التشغيل وسم رفع رفع.

`run_code` اشتراط برنامج و ذلك وصف. خدمة استدعاء جهة يمكن تحليل دعم حمل تنفيذ اختيار؛ موجه إلى نموذج timeout و مراجعة دفعة تحكم من مستقل مستهلك مسؤول. كل تضمين طقم أداة ما زال مرور مرور صحيح معتاد سياسة و سجل مسار.

## تأخير بعد تقييم تقدير timeout تصميم

مرور مرور وقت قيمة افتراضية هو يمكن إعادة تقييم تقدير نشر اختيار. لاحق تصميم يجب سوف استجابة و وقت صفة و إنهاء قسم فتح: نحو نموذج تسليم خروج إخراج ذاته لن إيقاف برنامج؛ زيادة يمكن انتظار وحدة سوف جذب دخول كل حق، إلغاء، جزء إخراج سجل، جولة انتهاء و استعادة معنى خدمة.

فتح وضع مشكلة يشمل مراجعة دفعة انتظار هل إزالة استهلاك برنامج ميزانية، ترتيب تنفيذ طويل مهمة أداة مثل أي تركيب، هل حاجة مستقل مجموع دورة الحياة التقاط قاع، و أي بعض عملية شجرة CPU/RSS حد أعلى يمكن متسق قوي صنع تنفيذ. حمل دائم داخل نواة أيضا حاجة في Session سجل في يمثل إبقاء حالة. هذه مشكلة لن ساكن صامت مؤقت توقف أو تأخير طويل قد إصدار مرور مرور وقت حساب وقت جهاز.
