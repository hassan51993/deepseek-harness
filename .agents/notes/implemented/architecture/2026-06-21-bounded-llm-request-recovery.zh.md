# Agent Note: LLM مؤقت وقت صفة طلب فشل محدود استعادة

Status: implemented

[English](2026-06-21-bounded-llm-request-recovery.md) | العربية

[حسب مزود إعداد طلب إعادة محاولة سياسة](../../archived/feature/2026-07-24-provider-retry-policies.md) في هذا أساس أساس فوق زيادة تأكيد قطع مزود إعداد و صريح بلا حد mode. هذا شرح متابعة مسؤول بنية تحويل فشل واقع، فشل محاولة تجربة استعادة حد،normal mode مؤقت وقت صفة قيمة افتراضية، مرئي مفرد مرة محاولة تجربة و حمل دائم إعادة محاولة حالة.[LLM(كبير لغة نموذج) تدفق إنهاء فشل](2026-07-29-terminal-llm-stream-failures.zh.md) يحل محل منها صلة في رمي خروج خطأ هوية و تدفق sidecar آلية.

## مشكلة

مزود مهايئ ممكن في توزيع أو تكرار بديل وقت رمي خروج استثناء، أيضا ممكن بـ `finish { kind: 'error' | 'aborted' }` انتهاء. نهائي مهايئ حد سوف في `dsh-agent-loop` استقبال قبل يأخذ رمي خروج قيمة مواصفة تحويل لـ هذا إنهاء finish بروتوكول؛middleware و نتيجة معالجة نقص وقوع ما زال سوف رمي خروج.loop سوف سوف إنهاء نموذج طلب فشل تسليم إعطاء `agent/request-error`. لم يتم معالجة فشل هو نهاية حالة؛ معالجة فشل مستمع إصلاح سياسة ذاتي لديه حالة، إرجاع `{ kind: 'retry' }`، و إيقاف waterfall(شلال نشر صيغة حدث) تفويض حمل.[إعادة محاولة حركة عمل قرار](../simplification/2026-07-27-request-error-retry-action.zh.md) قاعدة تحديد هذا واحد إرجاع اتفاق.

هذا حد قد قدرة أمان أرض مجددا مرة إرسال بدء طلب. كل فشل stream سوف إيداع واحد يتضمن دقيق ضيق تجميع stream فقط سجل `assistant/attempt`،message derivation سوف تجاهل اختصار هو؛ نظام فقط سوف في terminal finish نجاح و تجميع `assistant/message` بعد قسم إرسال أداة استدعاء، إعادة محاولة فإن من حمل دائم surface إعادة بناء تحت مرة attempt. لذلك،harness بلا حاجة جذب دخول ثاني طقم استجابة دورة الحياة أو مؤقت تحديد إخراج بروتوكول، يكفي قسم فصل اثنان مرة attempt.

هذا قبل حد أيضا إبقاء لديه ثلاثة عدد مقارنة ضيق نقص فتحة.

- مزود فشل فقط إبقاء رسالة، عبر معتاد أيضا سوف إبقاء واحد code.HTTP حالة، إعادة محاولة تأخير متأخر و مزود طلب id سوف يتم إسقاط، أو من فقط قدرة عبر مزود مخصص استخدام خطأ كائن استعادة، لذلك عام استعادة آلية إذا لا تحليل نص، سهل لا يمكن عمل خروج قرار أو حل تفسير قرار.
- إعادة محاولة ملكية بسبب مهايئ بينما مختلف. يد كتابة DeepSeek مهايئ فقط محاولة تجربة مرة،pi-ai profile فإن يمكن تفعيل مكتبة داخلي لا نفاذ واضح إعادة محاولة. إذا يأخذ إخفاء نقل إعادة محاولة و `agent/request-error` مستمع ربط دمج، محاولة تجربة مرة عدد سوف صار ضعف زيادة، في بين فشل أيضا لن تسجيل دخول جلسة سجل.
- استعادة بعد فشل لا يوجد حمل دائم حالة واقع. فشل خطوة و قسم قطعة ما زال يمكن إعادة بناء، لكن مراقبة من لا يمكن نيل معرفة agent(ذكي جسم) هل في متعمد تراجع تجنب، سوف انتظار كثير دائم، و انتظار سبب. طويل وقت ساكن صامت انتظار نظر بدء قدوم و حلقة توقف ركود بلا مختلف.

افتراضي سياسة هدف هو من نفس عدد صريح مزود/نموذج طلب مؤقت وقت صفة فشل في إجراء محدود استعادة. مزود أو نموذج لذا عائق تحويل نقل، استجابة تجميع وصل و دلالة إخراج إصلاح كل يخص أخرى مشكلة، هدف قبل لا يوجد مستهلك.

## قرار

### إبقاء فشل واقع، لا تضمين دخول سياسة

`@deepseek-ai/dsh-llm` توجيه خروج وحيد يمكن JSON تسلسل تحويل `LlmFailure` تحميل حمل:

```ts ignore-check
type ProviderRequestId = Branded<'ProviderRequestId'>

interface LlmFailure {
  message: string
  code: string
  status?: number
  providerRetryAfterMs?: number
  requestId?: ProviderRequestId
}
```

`code` ما زال هو `HarnessError` بناء قيام provider-neutral آلة جهاز توجيه تصنيف؛ جديد حقل هو في provider حد مراقبة قياس إلى واقع.`ProviderRequestId` من `dsh-llm` يملك و بنية صنع، تسلسل تحويل بعد هو provider إرسال وضع نص. هذا payload متعمد لا يتضمن `retryable`،`failover`،`partialOutput`،provider،model،phase أو route id. هل يمكن إعادة محاولة يخص policy،provider/model قد يقع في حمل دائم request header في، جزء إخراج من فشل attempt تضمين دخول صيغة stream إبقاء.

`LlmError` يحمل `failure: LlmFailure`، و إبقاء `failure.code === error.code`.`FinishReasonMap.error` و `FinishReasonMap.aborted` يحمل نفس تحميل حمل، بينما لا هو و سطر فشل شكل حالة. نهائي مهايئ حد سوف من مهايئ رمي خروج قيمة في قسم مغادرة هذه واقع، تزامن خروج متبادل ينبغي إنهاء finish؛ لم معرفة SDK استثناء سوف نيل نيل `UNKNOWN` تحميل حمل. دقيق رمي خروج كائن هوية لن عبر تجاوز LLM تدفق seam.

agent loop(ذكي جسم حلقة) سوف سوف إنهاء finish `LlmFailure` نقل إعطاء `agent/request-error`، و في سجل لم استعادة `turn/end.reason` وقت استخدام نفس تحميل حمل.

مهايئ سوف أولا رفع أخذ بنية تحويل واقع، مجددا رجوع إلى رسالة فحص. هو جمع سوف تحقق HTTP حالة، سوف `Retry-After` ثانية عدد أو يوم مدة تحليل لـ صحيح لديه حد جزء ثانية تأخير متأخر، في مزود عام طلب id وقت سوف ذلك صنف لوحة تحويل، و منطقة قسم ذاته مهلة و استدعاء جهة في توقف. مزود مخصص استخدام code و رسالة يمكن دقيق تحويل خريطة، لكن استعادة مستمع لن تحليل هو جمع.

مشترك مؤقت وقت صفة code تجميع متعمد إبقاء جدا صغير: مهايئ إبرة مقابل `RATE_LIMIT` و `SERVER` خريطة، بعيد مسار فشل استخدام صريح `TIMEOUT` و `TRANSPORT` code، و مزود استجابة قد إتمام لكن لا يوجد محتوى كتلة وقت استخدام `EMPTY_RESPONSE`. اثنان عدد مهايئ كل سوف يأخذ الأكثر بعد واحد نوع حال حال عودة صنف لـ خطأ finish؛ تفصيل رؤية[فارغ نموذج استجابة يمكن إعادة محاولة](../../archived/bug-fix/2026-07-24-empty-model-response-is-retryable.md). هوية تحقق، إعداد مقدار، بلا فاعلية طلب، سياق فيض خروج، بروتوكول، في توقف و لم معرفة فشل كل إبقاء مختلف مستقر code، كما افتراضي لا يخص مؤقت وقت صفة فشل. إضافة جديدة code حاجة مهايئ fixture(اختبار قبل وضع بيانات) و قد سجل سياسة قرار؛ بلا حاجة توسيع ثاني عدد فشل صنف قطعة رفع.

### سوف إعادة محاولة سياسة وضع في قائم فشل خطوة نقطة توسيع فوق

`@deepseek-ai/dsh-llm-retry` هو استماع `agent/request-error` دالة إضافة. هو لا جذب دخول خدمة أو جديد حلقة فرع؛agent-loop حزمة فقط سوف أكثر تعديل عبر قائم فشل خطوة استعادة تحكم تدفق يحمل بيانات.

`agent/request-error` waterfall يحمل حالي `LlmFailure`، في وصل متابعة استعادة تسلسل في تخويل إعادة محاولة غير ممكن تغيير أولا قبل فشل قائمة، و توفير خدمة تسجيل بند الذي يحمل غير ممكن تغيير إعادة محاولة سياسة. حلقة فقط نقل تمرير بينما لا حل تفسير هذا سياسة؛ هو يملك وصل متابعة فشل تاريخ، و في نموذج طلب نجاح بعد صاف حذف.`dsh-llm-retry` normal سياسة موحد حساب من نفس بند تأكيد قطع مزود سياسة أمان ترتيب حمل دائم إعادة محاولة سجل،`dsh-compaction-basic` فإن صيانة ذاتي ذات سياق فيض خروج ميزانية. لذلك، مؤقت وقت صفة فشل و سياق فيض خروج تسليم بديل ظهور وقت، سوف كل منها مستقل إزالة استهلاك ذلك لديه حد ميزانية؛ الأكثر كبير طلب عدد انتظار في 1 إضافة فوق كل قد تحميل لديه حد ميزانية لـ و.

حالي إعداد شكل حالة رؤية [llm-retry README](../../../../packages/llm/llm-retry/README.zh.md). مزود مهايئ سوف تسجيل تضمين طقم `retryPolicy`؛ حذف وقت استخدام normal قيمة افتراضية: اثنان مرة مؤقت وقت صفة إعادة محاولة،500 جزء ثانية ابتدائي تأخير متأخر،10 ثانية تأخير متأخر حد أعلى،10% اهتزاز حركة، و فوق وصف خمسة عدد مؤقت وقت صفة code. حساب عدد و تأخير متأخر حد مشاركة اعتبار الذي ضبط فحص تنفيذ في مقارنة حفظ حراسة واحد طرف:[OpenCode استخدام اثنان مرة طلب إعادة محاولة، تأخير متأخر حد لـ 500 جزء ثانية/10 ثانية](https://github.com/anomalyco/opencode/blob/9976269ab1accfc9f9dc98a4a688c516934de422/%70ackages/llm/src/route/executor.ts#L36-L39) ؛[Pi سوف ثلاثة مرة agent درجة إعادة محاولة و مزود إعادة محاولة قسم فتح، كما مزود إعادة محاولة افتراضي لـ صفر](https://github.com/earendil-works/pi/blob/3da591ab74ab9ab407e72ed882600b2c851fae21/%70ackages/coding-agent/docs/settings.md#L139-L147) ؛[Codex استخدام لديه حد طلب/تدفق ميزانية و خمسة قسم ساعة فارغ خامل مهلة](https://github.com/openai/codex/blob/0fb559f0f6e231a88ac02ea002d3ecd248e2b515/codex-rs/model-provider-info/src/lib.rs#L25-L33).10% اهتزاز حركة مشاركة اعتبار [Codex محدود اهتزاز حركة](https://github.com/openai/codex/blob/0fb559f0f6e231a88ac02ea002d3ecd248e2b515/codex-rs/codex-client/src/retry.rs#L40-L47).

مقابل في ميزانية لم استهلاك كل دمج إطار فشل، من 1 بدء مؤقت وقت صفة إعادة محاولة حساب عدد استخدام محدود إشارة عدد تراجع تجنب. صالح `providerRetryAfterMs` فقط لديه في لا تجاوز مرور `maxDelayMs` وقت عندئذ سوف يحل محل إشارة عدد تراجع تجنب؛ مزود تأخير متأخر أكثر طويل وقت، نظام سوف تفويض حمل إعطاء تحت واحد مستمع، بينما لن مخالفة عكس مزود إشارة أمر رفع قبل إعادة محاولة. محلي تراجع تجنب ركوب بـ `[1 - jitterRatio, 1 + jitterRatio]` داخل حقن مع آلة بسبب فرعي، و سوف نهائي قيمة حد إلى `maxDelayMs`؛ مزود تأخير متأخر لا إضافة اهتزاز حركة.

إضافة يملك واحد تغطية ذلك كامل دورة الحياة `AbortController`، و تتبع أثر كل نشط وثب استعادة عودة ضبط، يشمل تفويض حمل waterfall عمل و تراجع تجنب.effect dispose(مورد تحرير) سوف أولا ملاحظة إلغاء مستمع، مجددا في توقف و انتظار نشط وثب عودة ضبط؛ في توقف سوف فوز مرور مقارنة متأخر وصول تفويض حمل إعادة محاولة قرار، يتم التقاط عودة ضبط في إضافة dispose بعد حيث لا يستطيع إعادة محاولة، أيضا لا يستطيع دخول ذلك waterfall باق بقية جزء. كل إدارة Cordis قد التقاط هذا مستمع، هذا تصميم ما زال قدرة جعل HMR(حار وحدة استبدال) dispose بلوغ إلى تماما توقف مستقر.

راحة نوم قبل،`dsh-llm-retry` سوف إلحاق واحد بند لا دخول جدول طبقة `llm/retry` جلسة حدث، منها يتضمن جولة، فشل خطوة، مزود، سياسة mode، كامل تحليل بعد سياسة key، مزود سياسة إعادة محاولة تحرير رقم، خاص تحديد في mode لديه حد حد أعلى (مثل لديه) ، حساب تخطيط تأخير متأخر و `LlmFailure`. هذا key سوف مقابل code تجميع ترتيب ترتيب، و في مزود توجيه يتم سلوك مختلف لكن mode نفسه سياسة استبدال وقت قسم فصل إعادة محاولة تاريخ. هذا إضافة يملك `SessionEventMap` إعلان دمج، و عبر ذلك متصفح أمان `./types` فرعي مسار توجيه خروج تحميل حمل؛`dsh-session` متابعة مسؤول عام حفظ دائم، لن امتصاص استلام اختياري سياسة مفردات. حدث سجل قد أمان ترتيب محتوى، بينما لا هو تحت واحد طلب قد إتمام؛ تأخير متأخر خلال إلغاء مع بعد سوف في `turn/end` في مرئي. لأن هذا حدث هدف هو يمثل تشغيل حالة، بينما لا هو استلام تجميع تتبع أثر بيانات، الذي بـ هو سوف و إنتاج مصير و إعادة تشغيل/لقطة تغطية واحد بدء تسليم.

مقابل غير مؤقت وقت صفة code، استهلاك كل سياسة ميزانية أو تجاوز خروج حد أعلى مزود تأخير متأخر، مستمع سوف استدعاء `next()`. هذا إبقاء و سياق فيض خروج استعادة و لاحق سياسة إضافة تركيب قدرة. مقابل ذاته معالجة فشل، هو سوف سجل و انتظار تأخير متأخر، لكن بعد في لا تفويض حمل حال حال تحت إرجاع `{ kind: 'retry' }`. جولة إلغاء و إضافة dispose سوف انتهاء انتظار كما لا إرجاع إعادة محاولة حركة عمل، هذا بعد ما زال بـ حلقة إلغاء/dispose فحص لـ دقيق.

`dsh-base` و `dsh-sdk-minimal` patch سوف هذا إضافة بصفة صريح إعداد سطر تحميل، لذلك أساس في base profile و مستقل SDK profile استخدام نفس طقم حسب مزود توجيه سياسة. مكتبة مستهلك ما زال يحتاج صريح تركيب إضافة: حذف هذا إضافة وقت، طلب فشل إبقاء نهاية حالة.

### من مفرد واحد طبقة مسؤول مرئي محاولة تجربة

مهايئ كل مرة استدعاء `stream()` فقط تنفيذ مرة مزود طلب.pi-ai مهايئ إزالة عام `maxRetries` و `maxRetryDelayMs` profile حقل، و منع استخدام مكتبة داخلي إعادة محاولة؛ يد كتابة مهايئ إبقاء قائم مفرد مرة محاولة تجربة سلوك. هذا مثال حيث تجنب تجنب SDK ميزانية صار ضعف وضع كبير agent ميزانية، أيضا قدرة تأكيد حفظ كل مرة مؤقت وقت صفة إعادة محاولة كل من ذلك سجل في سجل فشل محاولة تجربة إضافة `llm/retry` يمثل.

`ctx.llm.stream()` ما زال هو أصلي مفرد مرة محاولة تجربة waterfall. ضغط (compaction) ملخص انتظار مباشر استدعاء جهة سوف استلام إلى بنية تحويل فشل، لكن لن تلقائي نيل نيل إعادة محاولة، لأن هو جمع لا يوجد agent خطوة حد، أيضا لا يوجد يمكن توفير قسم فصل محاولة تجربة عام حمل دائم موضع. لم قدوم مباشر استدعاء مستهلك ممكن سوف حاجة واحد مؤقت اندفاع مساعد مساعدة دالة، فقط في بعد لم إرسال خروج أي قسم قطعة وقت إعادة محاولة؛ هذا قرار لا زيادة هذا صنف مساعد مساعدة دالة.

### في قدرة كاف إنهاء توقف ركود تدفق موضع تطبيق إضافة حد

كل مهايئ كل عام واحد مرور مرور تحقق `streamIdleTimeoutMs` إعداد حقل، قيمة افتراضية اعتماد فوق نص مرجع خمسة قسم ساعة أولا مثال. هذا بين فصل لا تجاوز مرور Node الأكثر كبير تحديد وقت جهاز تأخير متأخر، لذلك لن يتم ملقط صنع لـ 1 جزء ثانية. هو تغطية كل بعد لم إتمام مكرر `next()`: من مستهلك طلب تحت واحد بند بدء، إلى مهايئ تعرف آخر إلى مزود نشط حركة لـ توقف؛ مستهلك في اثنان مرة `next()` استدعاء بين زهرة استهلاك وقت لا يخص مزود فارغ خامل وقت.DeepSeek SSE(Server-Sent Events) ملاحظة تفسير حساب لـ نقل نشط حركة، لكن أبدا سوف يصبح `StreamChunk` قيمة أو جلسة سجل حدث.

`@deepseek-ai/dsh-timeout` عام واحد يمكن إعادة نشر منع فارغ خامل نظر باب كلب أصل لغة. واحد مستقر نطاق جزء `AbortController` سوف و استدعاء جهة إشارة دمج دمج، و في كامل مهايئ استدعاء خلال نقل إعطاء نقل طبقة؛ كل بعد لم إتمام `next()` كل سوف نشر منع نظر باب كلب، هذا استدعاء إتمام وقت حل حذف نشر منع، تحت مرة طلب بيانات وقت مجددا إعادة نشر منع. حمل خارج نقل نشط حركة سوف استدعاء `pulse()`، في لا إنتاج قيمة حال حال تحت لـ بعد لم إتمام يحتاج طلب إعادة نشر منع. مهلة سوف استخدام قدرة ذاته يملك `TimeoutReason` في توقف هذا عدد مستقر تحكم جهاز،`finally` فإن سوف صاف حذف تحديد وقت جهاز. مهايئ سوف ذاته نظر باب كلب عودة صنف لـ `TIMEOUT`، سوف أكثر مبكر حدوث فوق تنقل في توقف عودة صنف لـ `ABORTED`. قائم مرة صفة `deadline()` لن يتم وصف لـ انزلاق حركة حساب وقت جهاز.

حد اختبار إثبات اثنان عدد فعلي نقل طبقة كل قدرة إنهاء. يد كتابة مهايئ سوف في توقف ذلك fetch/reader،pi-ai مهايئ سوف يأخذ مستقر إشارة خريطة إلى SDK، و إثبات SDK سوف إغلاق استجابة. إذا تحديد وقت جهاز فقط رفض مستهلك promise، لكن يجعل طلب متابعة تشغيل، حينئذ لا ممتلئ كاف هذا اتفاق.

### في قائم سجل في قسم فصل محاولة تجربة

فشل attempt سوف إلحاق حمل تضمين دخول صيغة stream `assistant/attempt`، لكن أبدا إلحاق surface `assistant/message` أو قسم إرسال أداة. إعادة محاولة في فشل turn و step داخل متابعة، من حمل دائم surface إعادة بناء طلب، و إنتاج ذاتي ذات settlement؛ فقط لديه نهائي نتيجة عندئذ سوف إغلاق turn.step فتح وقت،UI يمكن تصيير لحظة حالة `assistant/live-chunk` update؛ عند `llm/retry` معرف فشل attempt أو `turn/end` سجل فشل وقت،UI مجددا تسوية هو.Web سوف تحقق كامل retry payload contract، يأخذ كل بند producer-correlated `retryId` chain إسقاط لـ مستقر واحد سطر و تحديث إلى الأكثر جديد attempt، مجددا من `llm/retry-started` و الذي تابع turn،step boundary إغلاق إرسال توليد scheduled،started أو cancelled حالة. قلب حساب وقت بـ متصفح استلام إلى event وقت لحظة لـ حساب تخطيط تأخير متأخر بدء نقطة، بينما لا هو Host event clock؛ هو حسب نحو فوق أخذ كامل كما لا منخفض في 1 ثانية ثانية عدد عرض، فقط في لم تسوية وقت حركة رسم، و يأخذ الأكثر جديد فشل تفصيل حال طي في هذا سطر بعد. أي جعل فشل attempt لا يوجد surface Assistant node،retry node أيضا سوف مرساة تحديد ذاتي ذات trajectory turn.Message derivation سوف تجاهل اختصار `assistant/attempt`،Web في تاريخ إعادة بناء وقت تطبيق نفس إسقاط، لذلك تحديث جديد لن يأخذ فشل partial رفع رفع دخول نموذج تاريخ، أيضا لن توليد تكرار retry row.

إذا استعادة ميزانية استهلاك كل، نهائي فشل سوف وصل نفس بنية تحويل واقع في `turn/end.reason` في تخزين مرة.Web سوف في هذا تسلسل موضع إرسال توليد واحد `turn-error` عقدة، و داخل ربط تصيير ملائم دمج عرض رسالة و اختياري رمز خطأ؛AUTH إسقاط سوف يأخذ ممكن عودة إظهار اعتماد قطعة مقطع مزود نص سجل استبدال لـ `API key is invalid`، أصلي تشخيص ما زال إبقاء في جلسة سجل في. فوري حدث و تاريخ إعادة تشغيل استخدام نفس طقم طي منطق. مؤقت وقت صفة استعادة متابعة خلال،`llm/retry` هو كل مرة في بين فشل و تأخير متأخر حمل دائم ملكية موضع؛ نهاية حالة خطأ سطر فقط في `turn/end` سجل خطأ بعد عندئذ وجود، بينما من في استهلاك كل استعادة و فشل مشترك نفس جولة، هذا جولة إعادة محاولة تاريخ أبدا سوف كبح صنع هذا واحد سطر——تحديد إطار إعادة محاولة سلسلة و نهاية حالة خطأ و صف تصيير. هذا قرار لا زيادة مستقل نهائي خطأ حدث أو استجابة id مفردات.

## لا في نطاق داخل

- تلقائي مزود أو نموذج لذا عائق تحويل نقل. طلب قد صريح اختيار واحد مزود و نموذج، مزود سجل التسجيل أيضا متعمد قاعدة تحديد كل مزود فقط من واحد مهايئ مسؤول.
- في نجاح إنهاء صفة finish بعد إعادة محاولة أو متابعة، أو سوف اثنان مرة محاولة تجربة قسم قطعة تجميع وصل صار واحد بند assistant رسالة.
- إصلاح صيغة خطأ أداة معامل، رفض جواب، محتوى مرور ترشيح أو أخرى دلالة نموذج إخراج.
- صهر قطع جهاز، مشترك مزود سليم سليم حالة أو عبر agent إعادة محاولة ميزانية.
- في لا يوجد إنتاج مستهلك حال حال تحت، يأخذ `llm/stream` تعديل صنع صار استجابة دورة الحياة أو زيادة سهل فائدة توليد API.

## اعتبار مرور بديل خطة

- **في `llm/stream` أو مزود SDK داخلي إعادة محاولة**: رفض اعتماد، لأن أصلي تدفق واحد حالما إرسال خروج قسم قطعة سهل لا يوجد حمل دائم محاولة تجربة حد، إخفاء SDK إعادة محاولة سوف صار ضعف وضع كبير ميزانية، بينما كما اثنان بند مسار كل لا يمكن متسق أرض سجل كل مرة فشل محاولة تجربة.
- **نحو `dsh-llm` زيادة استجابة بدء، في قطع، إسقاط، فشل و إيداع حدث**: رفض اعتماد، لأن agent سجل قد قسم فصل أصلي قسم قطعة، نجاح رسالة و تحرير رقم محاولة تجربة. ثاني طقم حالة آلة سوف تكرار ملكية علاقة، أيضا لا يستطيع دعم يحتفظ حد نفس توجيه إعادة محاولة.
- **زيادة منطق توجيه، قدرة مستطيل دفعة و لذا عائق تحويل نقل اختيار**: رفض اعتماد، لأن حالي طلب قد صريح إشارة تحديد مزود و نموذج، كل مزود من واحد مهايئ مسؤول، بينما كما لا يوجد حالي مستهلك اشتراط تلقائي رجوع أو قدرة كاف إثبات دلالة توافق صفة.
- **يأخذ `retryable` أو `failover` وضع في `LlmFailure` فوق**: رفض اعتماد، لأن مهايئ تقرير إبلاغ واقع، نشر سياسة قرار حركة عمل. نفس عدد 429 يمكن في تفاعل صيغة تركيب حزمة في إعادة محاولة، أيضا يمكن في صار هذا تلقي حد دفعة معالجة في يتم رفض.
- **فقط يلزم استدعاء جهة ما زال موضع في نشط وثب حالة حينئذ بلا حد إعادة محاولة**:[حسب مزود إعداد سياسة](../../archived/feature/2026-07-24-provider-retry-policies.md) مقابل صريح `always` بند إعداد دفع قلب هذا بند رفض، معا إبقاء محدود normal mode بصفة قيمة افتراضية.
- **فقط عبر عملية logger سجل إعادة محاولة حالة**: رفض اعتماد، لأن عملية سجل لا يمكن إعادة بناء جلسة سلوك، أيضا لا يستطيع قيادة إعادة تشغيل بعد UI حالة.
- **فقط إبقاء مسطح مستو code**: رفض اعتماد، لأن إعادة محاولة تأخير متأخر و مزود طلب id هو بنية تحويل مزود واقع، بينما عند مختلف بروتوكول فشل مشترك استخدام واحد مستقر code وقت، تشخيص أيضا حاجة HTTP حالة.

## تحقق

- `LlmFailure` هو مهايئ رمي خروج، خطأ finish و في توقف finish استخدام وحيد يمكن تسلسل تحويل تحميل حمل؛ في متاح وقت، مواصفة تحويل إبقاء مستقر code، حالة، إعادة محاولة تأخير متأخر، صنف لوحة تحويل مزود طلب id، و استدعاء جهة في توقف و مهايئ مهلة بين تصنيف.
- مهايئ رمي خروج قيمة سوف في مقاومة بلوغ مستهلك قبل يصبح إنهاء فشل قسم قطعة؛middleware و مستهلك استثناء ما زال في نموذج طلب استعادة خارج رمي خروج.
- DeepSeek و pi-ai مهايئ اختبار تغطية أداة لديه بديل جدول صفة 400،401/403،429،5xx، اتصال، صيغة خطأ/قطع قطع تدفق، مهلة، في توقف،Retry-After ثانية عدد/يوم مدة، طلب id و لم معرفة SDK خطأ مسار، استعادة سياسة بلا حاجة تحليل رسالة نص.
- pi-ai سوف SDK خيار ثابت لـ صفر مرة إعادة محاولة، و إبرة مقابل يمكن إعادة محاولة مزود استجابة تنفيذ مرة يمكن مراقبة قياس خط مسار طلب محاولة تجربة؛ مستقل اختبار تأكيد حفظ إزالة مهمة واحد حد كل سوف فشل.
- `agent/request-error` يحمل حالي فشل واقع، غير ممكن تغيير أولا قبل قد إعادة محاولة فشل واقع، و توفير خدمة تسجيل بند الذي يحمل غير ممكن تغيير إعادة محاولة سياسة؛ نجاح سوف صاف حذف تاريخ، مؤقت وقت صفة فشل/سياق فيض خروج تسليم بديل حدوث اختبار تكامل إثبات اثنان نوع سياسة فقط إزالة استهلاك كل منها لديه حد ميزانية.
- كل مزود مهايئ كل في Loader بدء وقت تحقق ذلك تضمين طقم إعادة محاولة سياسة،`ctx.llm` فإن سوف هذا سياسة و توجيه واحد نفس التقاط؛normal mode سوف تفويض حمل لا دمج إطار مسار، بينما كما في لا يوجد أخرى سياسة وقت الأكثر كثير إرسال بدء `maxRetries + 1` مرة مزود طلب.
- تراجع تجنب خلال تنفيذ HMR اختبار إثبات:dispose مرور مسار سوف ملاحظة إلغاء مستمع، في توقف و انتظار ذلك التقاط عودة ضبط،dispose بعد لا إرسال خروج إعادة محاولة قرار، أيضا لا إبقاء تحت تخزين نشط تحديد وقت جهاز أو promise.
- صاف اختبار وحدة تغطية مؤقت وقت صفة code اختيار، إشارة عدد تراجع تجنب و اهتزاز حركة حد، صالح و تجاوز خروج حد أعلى `Retry-After`، استهلاك كل ميزانية، تحديد صفة تحديد وقت جهاز/مع آلة عدد خطاف، و تراجع تجنب خلال في توقف.
- حقيقي agent-loop اختبار تغطية قسم قطعة قبل فشل، جزء قسم قطعة بعد فشل، رمي خروج و حمل داخل فشل، في نفس جولة داخل إعادة محاولة حتى نجاح، استهلاك كل بعد كتابة بنية تحويل `turn/end.reason`، و و `dsh-compaction-basic` سياق فيض خروج استعادة تركيب.
- جزء قسم قطعة اختبار تكامل إثبات: فشل قسم قطعة ما زال ملكية في فشل خطوة، هذا خطوة لن إيداع assistant رسالة أو أداة فرعي أثر، نجاح إعادة محاولة سوف سجل ذاتي ذات قسم قطعة seq و مزود/نموذج توجيه.
- إضافة يملك لا دخول جدول طبقة `llm/retry` حدث يمكن في JSONL نحو إرجاع بعد إبقاء، يتم رسالة إرسال توليد تجاهل اختصار، و قيادة TUI و Web سحب عودة و حساب تخطيط إعادة محاولة تصيير. عميل اختبار تغطية كامل wire تحقق، مستقل في وقت ساعة قلب حساب وقت، قد إلغاء و قد إتمام إعادة محاولة وسم منطقة آخر و مسار أثر ملكية؛ بلا مفتاح UI لقطة تغطية Web ضبط درجة و نجاح، حقيقي Web تركيب اختبار تغطية جزء نقل فشل مباشر حتى استعادة، و استهلاك كل بعد نهاية حالة خطأ سطر و تحديد إطار إعادة محاولة سلسلة و صف رسم وجه،ACP تلقائي تحويل لقطة تأكيد، يتم إسقاط محاولة تجربة لن عبر بروتوكول إرسال خروج، بينما استعادة بعد عودة تكرار سوف صحيح معتاد إرسال خروج.
- فارغ خامل نظر باب كلب اختبار إثبات: فقط لديه `next()` بعد لم إتمام وقت عندئذ سوف إعادة نشر منع مستقر إشارة؛ في مستهلك تفكير اعتبار خلال و `finally` في سوف حل حذف نشر منع؛ هو و مجموع استدعاء deadline و أكثر مبكر حدوث استدعاء جهة في توقف قسم فتح تصنيف. مهايئ اختبار إثبات هذا إشارة سوف إنهاء قاع طبقة طلب، بينما لا فقط هو و ذلك انفصال مغادرة.
- `ctx.llm.stream()` مباشر استدعاء جهة ما زال فقط محاولة تجربة مرة، و استلام إلى نفسه بنية تحويل فشل واقع.

## عاقبة

- كل مرة إعادة محاولة محاولة تجربة كل في ذلك الذي تابع جولة داخل بـ فشل محاولة تجربة قسم قطعة إضافة `llm/retry` شكل صيغة مرئي، مهايئ درجة مفرد مرة محاولة تجربة سلوك سوف منع توقف إخفاء SDK إعادة محاولة صار ضعف زيادة سياسة قرار. أي جعل لا يوجد قسم قطعة وصول، إعادة محاولة ما زال ممكن صنع صار مزود تكرار حساب استهلاك؛normal mode سوف حد هذا ريح خطر، بينما صريح always mode سوف قبول هو، مباشر حتى إلغاء أو نجاح.
- مزود SDK ممكن إخفاء حالة أو إعادة محاولة علامة رأس. مهايئ سوف إبقاء SDK عام مستقر واقع، لا فإن استخدام خشن حبة درجة code، بينما لن يجعل استعادة سياسة تحليل هش ضعيف نص.
- حمل دائم إعادة محاولة حدث توسيع جلسة بروتوكول و UI حالة آلة. حدث و ذلك مستهلك واحد نفس تسليم، يمكن تجنب تجنب إنتاج بلا شخص استخدام بعيد قياس مفردات؛ لكن بـ بعد أكثر تعديل schema ما زال حاجة تزامن إتمام حفظ دائم و إعادة تشغيل عمل.
- صاف حذف فشل خطوة فوري قسم قطعة ممكن سوف واضح إظهار سحب عودة إخراج. و يأخذ إسقاط نص أو لا كامل أداة JSON عرض لـ قد إيداع تاريخ متبادل مقارنة، هذا هو أكثر جيد اختيار؛ لقطة ثابت هذا واحد تحويل.
- مهايئ نطاق جزء فارغ خامل قوي صنع آلية يمكن إنهاء توقف ركود نقل، بينما لن حساب دخول مستهلك تفكير اعتبار وقت. كل نقل حد اتفاق اختبار سوف منع توقف SDK عائم نقل.
- كثير عدد normal استعادة إضافة سوف تراكم إضافة كل منها لديه حد ميزانية.always mode سوف أولا تفويض حمل، مجددا توفير بلا حد رجوع؛ إعادة تراكم تصنيف جهاز ما زال سوف شكل صار اعتماد تسجيل ترتيب سياسة، يجب من جذب دخول هو جمع إضافة سجل و اختبار.
