# طويل جلسة متصفح أساس دقيق

[English](README.md) | العربية

[long-session.bench.ts](long-session.bench.ts) في مطلوب Chromium سير العمل قياس كمية فتح يتضمن 240 عدد جولة دمج صار جلسة، تحميل كل مقارنة مبكر صفحة، وصول Trajectory، و في لديه عقدة عزف تدفق صيغة عودة تكرار خلال إدخال تحت واحد بند مسودة مسودة. مع منتج صيانة Web scaffold يملك عزل رئيسي دليل، حفظ دائم، إعادة تشغيل مهايئ و عودة حلقة مستمع؛Chromium تحميل بناء بعد Web ناتج، بينما غير بديل تطوير خادم.

## تشغيل

`pnpm run test:bench` أولا بناء library،worker و Web ناتج، مجددا سلسلة سطر تشغيل أساس دقيق بيان. ناتج قد بناء وقت، عبر `pnpm exec vitest run --config vitest.bench.config.ts benchmarks/long-session-browser` اختيار هذا دليل. أول مرة تشغيل قبل، عبر benchmark workspace تثبيت Chromium.

## قياس كمية

ثلاثة عدد كل جديد متصفح عملية و scaffold بيئة إنتاج أصلي مثال هذا و في موضع عدد حكم تحديد. فتح و قسم صفحة في مسبق مدة transcript(نص سجل) حالة ظهور كما مرور مرور اثنان مرة حركة رسم لقطة بعد انتهاء؛ هذا يتضمن مرة تصيير آلة سوف، بينما غير صلب عنصر عرض ختم الوقت. قسم صفحة تقرير إبلاغ كل واحد صفحة، و مقابل كل مثال هذا الأكثر بطيء قسم صفحة وقت في موضع عدد تنفيذ ميزانية فحص. تدفق صيغة تقرير إبلاغ أول مرة مرئي عودة تكرار، تلقي معلومة مهمة مسودة مسودة مفتاح دخول، كامل عودة تكرار جدار ساعة وقت و Chromium رئيسي خط مسار مهمة وقت.Enter من قد تجمع تركيز إدخال إطار إيداع؛ مسودة مسودة مفتاح دخول إبقاء هذا تركيز نقطة، لا تنفيذ فأرة علامة نقر. عودة تكرار علامة فحص بحث و إدخال حدث نص مراقبة جهاز فقط قراءة الأكثر جديد Assistant خطوة، تجنب تجنب تكرار إجراء كل كمية تاريخ نص مسح و بلا عائق عائق مسح. إدخال حدث نص مراقبة جهاز في إيداع قبل تثبيت، أول عدد علامة مرئي بعد قيام أي بدء مسودة مسودة مفتاح دخول، لا مقدار خارج انتظار إدخال قبل حركة رسم لقطة. عودة تكرار علامة في حركة رسم لقطة فوق أخذ مثال، اشتراط نص في الأكثر جديد خطوة داخل مرئي. أول مرة مراقبة في متصفح داخل سجل علامة حالة و تركيز نقطة؛ تشخيص في مفتاح دخول بعد أخذ عودة، لا زيادة إدخال قبل عبر معلومة نحو إرجاع. تشخيص أيضا يتضمن أول عدد إدخال حدث متصفح وقت ساعة ختم الوقت و تركيز نقطة. تشخيص لن مؤقت توقف إعادة تشغيل؛ أول مرة مراقبة أو إدخال تأخير متأخر ما زال ممكن توجيه يؤدي إعادة تراكم فشل. فعلي أول عدد إدخال حدث يجب مراقبة إلى لم إتمام عودة تكرار؛ كامل عودة تكرار قياس كمية سوف في Host تسوية بعد انتظار جديد turn-tail تصيير إتمام. قياس كمية بعد، في DONE بعد إرسال تلقي معلومة مهمة حسب مفتاح يجب لا يمكن عبر نفس عدد إعادة تراكم تأكيد. فتح، الأكثر بطيء مقارنة مبكر صفحة و أول مرة Trajectory استخدام معيار حمل إدارة مسبق مدة 900/700/520 ms. مشترك 1.25× بقية كمية قسم آخر إنتاج 1125/875/650 ms حد أعلى؛ تدفق صيغة نهاية نقطة مقدار خارج فتح إلغاء ميزانية ثابت. قوي صنع GC بعد heap و DOM عدد كمية فقط توفير تشخيص، لا بصفة تسرب تسرب ميزانية.

fixture(اختبار قبل وضع بيانات) في أول بند مستخدم رسالة قبل إبقاء فارغ system رأس عقدة، كل بند مستخدم رسالة كل يقع في ذلك خطوة داخل. هو يتضمن خلط دمج لغة نص التوجيه، متن، دفع إدارة (reasoning) ،20 عدد محيط شريط شفرة كتلة و 40 عدد دمج صار أداة نتيجة. كل بند تاريخ Assistant كل يحتوي ضيق تجميع تدفق، من إنتاج accumulator من مطابقة دفع إدارة، نص، أداة معامل،usage و finish قسم قطعة بناء. ذلك محتوى لا قدوم ذاتي نموذج، أداة، خارجي شبكة، تسجيل صنع جلسة أو خاص Harness رئيسي دليل. تدفق صيغة عودة تكرار بـ 16 ms إعادة تشغيل بين فصل إرسال 120 عدد نص delta، مرور مرور حقيقي إدخال إطار،agent loop(ذكي جسم حلقة) ، نقل و حفظ دائم.
