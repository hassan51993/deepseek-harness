# @deepseek-ai/dsh-api-workspace-files

[English](README.md) | العربية

## عام وصف

استخدام هذه الحزمة يمكن من Web Client معاينة Session نظام الملفات سماح قراءة ملف. هو حسب صفحة قراءة UTF-8 نص، حسب محدود نافذة أو كامل ملف قراءة أصلي بايت، من أساس ملف دليل تحليل صلة ربط ملف، و تقرير إبلاغ ملف بيانات وصفية. ملف قراءة يمكن إشارة نحو مساحة العمل خارج مسار؛ دليل صف رفع و قد دفن نقطة نظام الملفات مراقبة ما زال حد تحديد في مساحة العمل. هذا خدمة لا توفير تعديل عملية.

## استخدام هذه الحزمة

يأخذ هذه الحزمة و `dsh-fs`،`dsh-sandbox-policy`،Session store و Typert Gateway واحد بدء تركيب؛bundle يأخذ هو ضيق مع Session Controller بعد تركيب. كل طريقة كل في خط مسار فوق يحمل Session هوية،Client استدعاء `remote.workspaceFiles.read(sessionId, path, range, signal)`،`stat(sessionId, path, signal)`،`readBytes(sessionId, path, range, signal)`،`list(sessionId, path, signal)` أو `changes(sessionId, signal)`، من لا ذاتي ذات إشارة تحديد أصل.Host قراءة live Session header،cold Session فإن استخدام حمل دائم طبقة `stat`؛ هو لن تنشيط Agent، قراءة حدث متن أو استعارة استخدام أب Session أصل.live قراءة لا اشتراط تركيب Session persistence؛ لم تركيب وقت cold Session لا يمكن تحليل،Gateway إرجاع `gateway/lookup-not-found`.

| طريقة | إرجاع | استخدام طريق |
|---|---|---|
| `stat(path)` | `WorkspaceFileStat { absolutePath, version, bytes? }` | واحد عادي ملف هوية، إصدار و كبير صغير، لا يحتوي محتوى |
| `read(path, { offset?, limit? })` | `WorkspaceFileText` = stat + `{ offset, text, lines, eof }` | UTF-8 نص ملف واحد سطر نافذة؛`lines` حساب سطر عدد، جعل مفرد عدد فارغ سطر و تجاوز مرور ملف نهاية ذيل صفحة يمكن منطقة قسم |
| `readBytes(path, { offset?, length? })` | `WorkspaceFileBytes` = stat + `{ offset, data, eof }` | مهمة معنى عادي ملف واحد أصلي بايت نافذة،base64 تحرير رمز |
| `readAll(path)` | `WorkspaceFileBytes`، منها `offset: 0`،`eof: true` | `maxFileBytes` داخل كامل أصلي بايت؛ تجاوز كبير ملف فشل، لا قطع قطع |
| `readRelated(path, relativePath)` | `WorkspaceFileBytes` | Host من أساس ملف دليل تحليل خروج ملف كامل بايت |
| `list(path)` | `WorkspaceDirectoryListing { path, entries, truncated }` | واحد دليل مباشر فرعي بند |
| `changes()` | `WorkspaceFileWatchFrame` تدفق | حجز قراءة حينئذ خيط تأكيد، مع بعد لـ مساحة العمل أصل داخل نظام الملفات مراقبة |

### بحث عنوان و مسار

`read`،`readBytes`،`readAll`،`readRelated` و `stat` قبول قطعا مقابل مسار أو متبادل مقابل في الذي اختيار Session مساحة العمل أصل مسار. تركيب نظام الملفات قرار مسار هل يمكن قراءة؛ هذا خدمة لا مقدار خارج اشتراط ملف قراءة حد تحديد في مساحة العمل.`readRelated` من أساس ملف الذي في دليل تحليل متبادل مقابل نظام الملفات مسار، أساس ملف أو هدف ملف يقع في مساحة العمل خارج وقت نفس مثال ملائم استخدام. هذه طريقة بـ نظام الملفات تنفيذ بيئة في قطعا مقابل مسار تقرير إبلاغ ملف.`list` ما زال حد تحديد في مساحة العمل، و بـ متبادل مقابل في هذا أصل مسار تقرير إبلاغ يتم صف رفع دليل.`changes` نفس مثال فقط تقرير إبلاغ مساحة العمل أصل داخل قد دفن نقطة نظام الملفات مراقبة.

### قسم صفحة

`read` إرجاع واحد سطر نافذة، أبدا إرجاع كامل ملف.`range.offset` هو 1 بدء حساب أول سطر، نقص حذف لـ 1؛`range.limit` هو هذا صفحة الأكثر كثير سطر عدد، نقص حذف لـ `maxLines` كما لا نيل تجاوز مرور هو——أكثر كبير limit، أو لا هو صحيح كامل عدد offset / limit، كل هو `gateway/bad-request`. سطر بـ `\n` انتهاء، نهاية ذيل `\n` هو الأكثر بعد واحد سطر إنهاء رمز بينما لا هو مجددا بدء واحد فارغ سطر، الذي بـ اثنان سطر ملف حينئذ هو اثنان سطر. صفحة `text` بـ `\n` اتصال كل سطر، الأكثر بعد واحد سطر بعد لا حمل إنهاء رمز؛`eof` في هذا صفحة يحتوي ملف الأكثر بعد واحد سطر وقت لـ true،offset تجاوز مرور نهاية ذيل فإن إرجاع فارغ صفحة كما `eof` لـ true. كل صفحة أيضا حمل فوق قبل وضع stat نيل إلى ملف `version`، مستهلك حسب هذا قسم تمييز جديد صفحة و قديم صفحة، و `bytes`——خلفية قدرة تقرير إبلاغ وقت كامل ملف كبير صغير. خدمة فقط يأخذ ملف قراءة إلى هذا صفحة بعد رقم واحد محرف لـ توقف، الذي بـ مجددا كبير ملف كل مرة طلب أيضا فقط احتلال واحد صفحة داخل تخزين.

### بايت نافذة

`read` حسب سطر قسم صفحة، أبدا حسب بايت؛ بايت نافذة مشي `readBytes`.`range.offset` هو 0 بدء حساب أول بايت، نقص حذف لـ 0؛`range.length` هو نافذة الأكثر كثير بايت عدد، نقص حذف لـ `maxBytes` كما لا نيل تجاوز مرور هو——أكثر طويل نافذة بـ `too-large` فشل بينما لا هو يتم قطع قصير، لا هو كامل عدد أو تجاوز حد offset / length فإن هو `gateway/bad-request`. نافذة بـ base64 `data` إرجاع، إلى ملف نهاية ذيل وقت قصير في `length`، يقع في أو تجاوز مرور نهاية ذيل وقت لـ فارغ؛ نافذة يحتوي ملف الأكثر بعد واحد بايت وقت `eof` لـ true. لا فعل أي حل رمز، أيضا لا حسب اثنان دخول صنع رفض، لذلك صورة أو يحتوي NUL ملف في `read` بـ `not-text` فشل لـ موضع ما زال يمكن قراءة خروج. و صفحة واحد مثال مرفق حمل نفس `version` و `bytes`.

### ملف قراءة و دليل فحص

كل بند عملية كل أولا عبر `lstat` رفض لا وجود مسار، نهاية طرف رمز رقم رابط أو خطأ ملف نوع. ملف عملية مع بعد عبر تركيب نظام الملفات تحليل و قراءة، لا فعل مقدار خارج مساحة العمل يتضمن فحص. فقط لديه `list` اشتراط تحليل بعد دليل ما زال يقع في مساحة العمل داخل. إعداد قسم صفحة، نافذة، كامل ملف و دليل صف رفع حد أعلى ما زال ملائم استخدام. نص صفحة أيضا رفض بلا فاعلية UTF-8 و NUL بايت؛ بايت قراءة لا حل رمز محتوى. فارغ مسار هو `gateway/bad-request`.

### تغيير تدفق

`changes` هو `stream` نمط Remote. واحد بديل تدفق تسجيل مراقبة طابور صف و تحليل Session مساحة العمل أصل بعد، عندئذ إنتاج خروج `{ kind: 'ready' }`. مع بعد إنتاج خروج `{ kind: 'change', change }`، منها `change` مقابل وجود ملف لـ `{ absolutePath, version }`، مقابل يتم مراقبة إلى قد إزالة فقد ملف لـ `{ absolutePath, absent: true }`. مصدر هو حسب هذا أصل داخل هدف مرور ترشيح `fs/observed`؛ عملية نظام و لم يتم مراقبة نظر. واحد بديل تدفق أول مرة سحب أخذ بعد مراقبة كل سوف ترتيب طابور، يشمل تحليل أصل خلال مراقبة. تدفق في إلغاء أو إضافة تحرير وقت انتهاء.

### إعداد

| حقل | قيمة افتراضية | يحتوي معنى |
|---|---|---|
| `maxBytes` | `2097152`(2 MiB) | مفرد صفحة نص و مفرد عدد بايت نافذة بايت حد أعلى (يحتوي) ؛ أكثر كبير صفحة أو نافذة فشل |
| `maxFileBytes` | `33554432`(32 MiB) | `readAll` و `readRelated` كامل ملف بايت حد أعلى (يحتوي) ؛ أكثر كبير ملف بـ `too-large` فشل |
| `maxLines` | `5000` | صفحة كبير صغير نقص حذف قيمة و حد أعلى (سطر) ؛ أكثر كبير `limit` يتم رفض |
| `maxEntries` | `2000` | إرجاع دليل بند عدد حد أعلى؛ ذلك بقية إسقاط و تقرير إبلاغ قطع قطع |

توليد[إعداد دليل](../../../docs/config-catalog.zh.md#deepseek-aidsh-api-workspace-files) هو كل يمكن قبول حقل و ذلك JSDoc تمام تجهيز مصدر.

### فشل

كل نوع فشل كل هو واحد حمل نوع تحويل details `RemoteError` شفرة، إعلان في [`src/types.ts`](src/types.ts):`workspace-file/not-found`،`workspace-file/outside-workspace`(فقط دليل صف رفع) ،`workspace-file/too-large`(حمل `limit`، أي ملائم استخدام صفحة، نافذة أو كامل ملف حد أعلى) ،`workspace-file/not-text`،`workspace-file/not-regular-file`(`kind` لـ `directory`،`symlink` أو `other`) و `workspace-file/not-directory`(`kind` لـ `file`،`symlink` أو `other`). استدعاء جهة حسب شفرة فرع، أبدا حسب رسالة نص.

### Client ملف مورد

متصفح توجيه خروج نحو `ctx.resources` تسجيل `file` مزود، اشتراط `resources`،`remote` و `remote.workspaceFiles` في ساحة.bundle في مفرد عدد `workspace-files` بند توفير ينبغي اثنان وجه؛Client لا يوجد مفرد وحيد إعداد. مكون عبر `useResource<'file'>(address)` قراءة `WorkspaceFileStat { absolutePath, version, bytes? }` بيانات وصفية، محتوى آخر مرور Remote قراءة. أي UI(يشمل Global) وصول نفس كامل عنوان كل مشترك مراقبة.

`session/<sessionId>/<path>` عنوان يحمل تخويل Session، و متبادل مقابل أو قطعا مقابل مسار؛ قبل توجيه مائل عمود إبقاء، مثال مثل `dsh-resource://file/session/s//etc/hosts`.Host أصل مثال استقبال مسار، مسؤول تحليل و إذن فحص؛Client لا حاجة Session `cwd`.`absolute/<path>` ما زال يمكن تحليل، لكن لا يوجد تخويل Session، بـ `workspace-file/unknown-workspace` فشل، لا استعارة استخدام حالي أو Tab Session. لا دعم حمل عنوان بـ `workspace-file/unsupported-address` فشل. لغة قاعدة من [workspace-path](../../util/workspace-path/README.zh.md) تعريف؛Resource عام نوع طبقة فقط إقرار عنوان و `signal`.

مزود انتظار إلى Host `ready` لقطة بعد عندئذ إرسال أول مرة `stat`، قراءة خلال سوف تغيير ترتيب طابور، مع بعد سوف تتبع مع من ربط إلى `stat.absolutePath`. ترتيب طابور و فوري تغيير كل حسب هذا Host إرجاع مسار مطابقة. جديد كتابة إصدار تحديث بيانات وصفية و إبقاء الأكثر قريب بايت كبير صغير؛ تكرار إصدار يتم تجاهل اختصار. إزالة فقد إشعار سوف إعادة stat ملف.stat فشل بعد ما زال تتبع مع عنوان، لاحق كتابة يمكن جعل ذلك استعادة؛ أول مرة نجاح ربط مسار قبل،Session داخل أي كتابة كل يمكن إطلاق إعادة محاولة. لقطة هو `RemoteResult` قيمة، تحرير مسار استثناء لا يتم التقاط.

كل Session كل يتم تتبع مع ملف مشترك استخدام واحد بند تلقي مراقبة إشراف `changes` تدفق. تتبع مع من حسب عكس مائل عمود عودة واحد لـ مائل عمود قطعا مقابل مسار مطابقة. تحميل جسم إسقاط خط من Gateway مراقبة إشراف جهاز إعادة وصل؛Host انتهاء أو نهاية حالة فشل تدفق سوف انتهاء ذلك تتبع مع من، الأكثر بعد بيانات وصفية ما زال يمكن قراءة، مباشر إلى إعادة فتح. الأكثر بعد واحد تتبع مع من مغادرة فتح وقت تحرير تدفق، بعد استمرار تدفق انتظار هذا تحرير إتمام، إضافة تفكيك حذف انتظار كل في طريق إغلاق. توفير من إعلان `ResourceProtocolMap.file`؛ نص معاينة إعلان ذلك Sidebar سطر رقم تنقل معامل.

### تصميم عام فكرة

مرور `ctx.fs` قراءة استخدام خلفية قراءة إذن؛ صندوق رملي خلفية حد كتابة و تحرير، بينما لا حد قراءة.Typert lookup من live Session header أو حمل دائم طبقة header-only `stat` توجيه خروج `WorkspaceFileScope`، الذي بـ cold subagent Session لا حاجة تنشيط Agent أو قراءة حدث متن. هذا خدمة زيادة عادي ملف فحص و محدود نقل، مساحة العمل يتضمن اشتراط فقط يخص دليل صف رفع و تغيير مراقبة. صفحة من `streamText` قطع خروج، بعد من تدريجي كتلة حل رمز و رفض غير UTF-8: قطع صفحة جهاز مقابل نافذة قبل سطر فقط حساب عدد لا إبقاء، مقابل نافذة داخل كل قطعة مقطع أولا حسب بايت حد أعلى تحقق استلام مجددا مؤقت اندفاع، و في نافذة بعد رقم واحد محرف موضع إرجاع. تدفق قبل مرة `stat` إعطاء خروج صفحة الذي تقرير إبلاغ إصدار و كبير صغير.

كامل ملف قراءة سوف كبير صغير حد أعلى فحص تسليم إعطاء `fs.readBytes`، و سوف إرجاع بايت تحرير رمز لـ base64، توفير Remote استجابة استخدام.

## حدود معروفة وعمل مؤجل

<a id="known-limitations-and-deferred-work"></a>

- **فقط تغطية قد دفن نقطة عملية**——`changes` تحويل إرسال `fs/observed` إرسال إطلاق؛ عملية فرعية،shell أمر أو مستخدم تحرير جهاز تعديل ملف لا إنتاج أي لقطة.
- **فقط دليل تلقي حد**——كل إدارة ملف معاينة يمكن قراءة نظام الملفات خلفية سماح مهمة معنى مسار،`list` و `changes` ما زال حد تحديد في Session مساحة العمل داخل.
- **لا يوجد مجموع سطر عدد**——صفحة فقط تقرير إبلاغ `eof`، لا تقرير إبلاغ بعد وجه أيضا لديه كثير قليل سطر؛ حاجة مجموع عدد مستهلك يلزم قلب إلى نهاية ذيل أو حسب `bytes` تقدير حساب.
- **تجاوز طويل مفرد سطر لا يوجد صفحة**——تجاوز مرور `maxBytes` مفرد سطر في يتضمن هو كل نافذة كل بـ `too-large` فشل، لأن صفحة حسب سطر بينما غير حسب بايت قطع.
- **قراءة لا أداة تجهيز أمر خدمة صفة**——نتيجة بيانات وصفية قدوم ذاتي محتوى قراءة قبل stat؛ تزامن كتابة ممكن جعل تقرير إبلاغ إصدار و إرجاع محتوى لا متسق.
- **generation طابور صف بلا حد**——واحد `changes` generation سوف مؤقت اندفاع كل واحد بند يتم يتضمن مراقبة مباشر إلى مستهلك pull؛ توقف ركود مستهلك سوف في تدفق توليد أمر مدة داخل حمل متابعة زيادة طويل Host داخل تخزين.
- **`maxEntries` حد هو جواب سجل، لا هو صف رفع**——`list` يجعل `ctx.fs.listDir` صف خروج الكل فرعي بند بعد مجددا قطع قطع عدد مجموعة، بعيد تجاوز حد أعلى دليل ما زال يجعل Host دفع خروج كامل صف رفع بديل قيمة (`fs-local` فوق كل فرعي بند مرة stat) ؛ يلزم حد هذا نسخة عمل، حاجة نظام الملفات seam `listDir` دعم حمل حد أعلى.
- **بطلان تدفق إبقاء بيانات وصفية**——Host انتهاء `changes` أو تدفق نهاية حالة فشل بعد، قد فتح قيمة إبقاء الأكثر بعد معروف حالة، مباشر إلى إعادة فتح.
