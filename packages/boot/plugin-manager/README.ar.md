# @deepseek-ai/dsh-plugin-manager

[English](README.md) | العربية

تطبيق يملك profile عبر بدء جهاز معلومة توفير داخل وضع حزمة إدارة جهاز استدعاء طريقة. هو في حزمة عملية و registry فحص في أولوية في `pnpmCommand`؛ ذلك بيئة فقط تطبيق في هذه عملية فرعية.

## عام وصف

إدارة حالي profile إضافة، بلا حاجة يد حركة تحرير إعداد. بدء توقف مفرد عدد إضافة بند، اختيار قد تثبيت تركيب حزمة، و تثبيت أو حذف خارجي تركيب حزمة. في YAML في تفعيل HMR وقت، إعداد تغير قيام أي توليد فاعلية؛ لم تفعيل HMR وقت، تشغيل في تركيب إبقاء إلى إعادة بدء. تعديل أثر استخدام هذا profile الكل جلسة.

<a id="use-this-package"></a>
## استخدام هذه الحزمة

أساس في base profile توفير إدارة خدمة. في Web في، جانب حافة شريط**إضافة**صفحة ([ui-plugin-manager](../../client/ui-plugin-manager/README.ar.md)) إدارة profile تركيب حزمة و ذلك قدرة وحيد تحديد موضع سطر؛ ضبط صفحة إضافة قائمة إبقاء فقط قراءة.Agent مسبق ضبط بند إبقاء فقط قراءة.`plugin_manager` أداة توفير نفسه عملية، في Creator نمط في تفعيل. أخرى مسبق ضبط ما زال افتراضي منع استخدام. كل أداة عملية كل اشتراط `danger-full-access` أو هذا مرة استدعاء دفعة دقيق. في مقارنة منخفض صندوق رملي نمط تحت،`ask` سوف طلب مراجعة دفعة؛`never`، رفض، إلغاء أو مراجعة دفعة قناة طريق غير ممكن استخدام وقت متساو لا تنفيذ. دفعة دقيق لا تغيير جلسة إذن نمط.profile تغيير عبر جلسة حفظ دائم، قد تثبيت Host شفرة في مضيف عملية داخل تشغيل، لا تلقي مساحة العمل صندوق رملي حد. اعتماد بناء نص برمجي ما زال يحتاج مفرد وحيد دفعة دقيق.

لم استخدام Agent مسبق ضبط نشر في profile patch في تفعيل أداة؛ استخدام مسبق ضبط جلسة من ذلك مسبق ضبط في `tool-plugin-manager` بند تحكم.

```yaml
- id: tool-plugin-manager
  disabled: false
```

إضافة فتح صلة فقط تحديث profile `cordis.patch.yml` في الأكثر بعد واحد بند مطابقة تغطية بند `disabled`؛ لا يوجد مطابقة بند وقت إلحاق. مطابقة اعتماد حسب هو بند id، و تغطية بند إعلان وحدة اسم. تركيب حزمة فتح صلة تعديل `package.json` لديه ترتيب `dsh.profile.bundles` قائمة. إغلاق إبقاء اعتماد؛ فتح بدء إلحاق إلى قائمة نهاية ذيل، ممكن تغيير إعداد أولوية درجة. تثبيت جديد تركيب حزمة افتراضي تفعيل.home و مفرد مرة بدء patch إبقاء أكثر عال أولوية درجة.

`inspect(spec)` في أي شرق غرب تثبيت قبل قراءة خروج spec إشارة نحو ماذا: سجل التسجيل حزمة اسم عبر `pnpm view` استفسار سؤال سجل التسجيل، في profile دليل في تشغيل، بسبب بينما و تثبيت استخدام نفس مثال سجل التسجيل و بديل إدارة ضبط؛ قطعا مقابل مسار قراءة ذلك `package.json`؛git عنوان أو tarball فقط جواب تكرار ذاتي ذات شكل صيغة. جواب تكرار يحمل اسم، إصدار، وصف و هذا حزمة هل إعلان تركيب حزمة، لا فإن إعطاء خروج `problem`:`invalid-spec`،`already-installed`،`not-found`،`not-a-package`،`not-a-bundle`،`network` أو `unknown`. استدعاء جهة `signal` أو `inspectTimeoutMs` سوف انتهاء استعلام.

`installBundle` قبول استدعاء جهة توليد `requestId`،`plugin-manager/install-log` في ذلك تحت تدفق صيغة تحويل إرسال كل مرة pnpm تشغيل إخراج،`plugin-manager/install-state` عبر إبلاغ `installing`،`cancelling` و `applying`.`cancelInstall(requestId)` إيقاف تشغيل، فقط في pnpm خروج كما ملف استعادة بعد جواب تكرار `cancelled`، تركيب حزمة قد في تطبيق وقت جواب تكرار `too-late`، أخرى id جواب تكرار `not-running`؛ تثبيت استدعاء مع بعد تقرير إبلاغ `application: 'cancelled'`. فشل، يتم إلغاء أو تركيب دخول لا يوجد تركيب حزمة patch حزمة تشغيل، سوف يأخذ `package.json` و `pnpm-lock.yaml` استعادة أصل مثال؛`packageResult.kind` حسب خروج طريقة و إخراج مقابل فشل تشغيل تصنيف،`bundle` إعطاء خروج إتمام تشغيل إضافة جديدة حزمة.`listBundles` يحمل كل تركيب حزمة واحد جملة كلام بسيط وسيط (حزمة `description`) ، ذلك patch إعلان سطر و ذلك تخزين نشط بند، و هو تغطية داخل وضع سطر؛ هو صف خروج profile ذاتي ذات تركيب حزمة، تثبيت توفير تركيب حزمة، و يتم اختيار في لكن لا يوجد تركيب حزمة patch اسم حرف (بصفة `not-bundle` مشكلة) ، لم اختيار في عادي اعتماد لا صف خروج. بدء جهاز `OPTIONAL_BUNDLES` نقطة اسم تركيب حزمة هو `optional`: مع تثبيت توفير، افتراضي إغلاق، من مستخدم فتح بدء، دائم غير ممكن إزالة، أيضا لا يتم أي مع مرفق نموذج لوح اختيار في ([إدارة من](../../../.agents/notes/implemented/process/2026-09-15-shipped-optional-bundles.ar.md)). كل إتمام عملية كل سوف إرسال خروج `plugin-manager/changed`؛ في إدارة جهاز خارج تطبيق واحد بديل patch(HMR مراقبة نظر إلى CLI أو يد عمل تحرير بعد) لا إرسال إشعار، صفحة يلزم إلى تحت مرة قراءة عندئذ معرفة طريق.

pnpm 11 اعتراض تحت اعتماد نص برمجي وقت، فشل تثبيت في `pendingBuilds` داخل تقرير إبلاغ profile في كل انتظار قرار حزمة اسم، يشمل أولا قبل محاولة تجربة إبقاء تحت؛ فشل تشغيل سوف استعادة `package.json` و `pnpm-lock.yaml`، لكن متعمد لا استعادة pnpm سجل هذه اسم حرف `pnpm-workspace.yaml`.Web إضافة صفحة توفير**سماح هذه نص برمجي و إعادة محاولة**؛ أداة يمكن في مستخدم في محادثة في دفعة دقيق هذه نص برمجي بعد، عبر `install_bundle` `approvedBuilds` بديل لـ تخويل. خدمة فقط تحقق انتظار قرار اسم حرف، لا نواة فعلي محادثة في دفعة دقيق. تخويل حسب حزمة اسم حفظ في حالي profile، سماح بـ مضيف مستخدم إذن تنفيذ أمر، و في مجددا مرة تثبيت فشل بعد إبقاء. فقط قدرة دفعة دقيق حالي لم قرار اسم حرف؛ قد لديه رفض و عبر إعداد قاعدة لا يستطيع عبر هذا عملية تغطية.`allowBuilds` داخل ظهور YAML مرساة نقطة أو آخر اسم وقت رفض تخويل. إعادة محاولة إبقاء أصل قدوم تفعيل اختيار.

### إعداد

| حقل | قيمة افتراضية | يحتوي معنى |
|---|---|---|
| `pnpmCommand` | `pnpm` | pnpm يمكن تنفيذ ملف اسم أو مسار، و `dsh plugin` أمر واحد مثال عبر `PATH` تحليل. |
| `inspectTimeoutMs` | `20000` | مفرد مرة فحص الذي فعل سجل التسجيل استعلام حد أعلى، مفرد موضع جزء ثانية. |
| `outputBytes` | `16384` | كل مرة عملية إرجاع pnpm تشخيص بايت حد أعلى؛ كامل إخراج إبقاء في إرجاع سجل مسار في. |
| `lockWaitMs` | `120000` | نيل أخذ profile كتابة قفل الأكثر طويل انتظار جزء ثانية عدد. |

## فهم التنفيذ

<details>
<summary>تنفيذ دقيق عقدة——انقر للتوسيع</summary>

خدمة و `dsh plugin` مشترك استخدام [operations.ts](src/operations.ts) في حزمة إدارة عملية. بدء جهاز توفير حالي profile؛[DSH HMR](../hmr/README.ar.md) سلسلة سطر تنفيذ وحدة إعادة تحميل، ملف استماع و إدارة كتابة. كل مرة تحديث جديد إعادة قراءة تركيب حزمة اختيار و patch طبقة، تحديث أصل لديه أصل Include، و انتظار قد إزالة إضافة تحرير مورد و باق بقية Loader شجرة مستقر.CLI و service عملية مشترك استخدام profile manifest كتابة قفل، منع توقف تزامن حزمة عملية و manifest كتابة.HMR لا نيل أخذ هذا قفل.pnpm في HMR طابور صف خارج تنفيذ؛ تثبيت في pnpm نجاح بعد اختيار دخول تركيب حزمة، حذف فإن في تنفيذ pnpm قبل إلغاء اختيار دخول و إتمام إزالة. فقط اعتماد حقل تغير لن إطلاق إعداد إعادة تحميل.

نتيجة يتضمن الأكثر بعد محاولة تجربة مرحلة مقطع، هدف، مغناطيس قرص تغير، تطبيق حالة و رمز خطأ.Web كلمة قاموس عرض إدارة نص سجل؛pnpm و Loader تشخيص إبقاء أصل مثال. غير متصل قد لديه لذا عائق بصفة تحذير إبلاغ إرجاع؛ جديد ظهور، إعداد تغير بعد لذا عائق، و صريح تفعيل هدف لم تنشيط، كل سوف جعل عملية فشل. فشل أو يتم إلغاء تثبيت سوف استعادة pnpm تشغيل قبل لقطة manifest و lockfile([إدارة من](../../../.agents/notes/implemented/architecture/2026-09-15-guided-plugin-installation.ar.md)) ؛ فشل حذف إبقاء جزء تعديل و تشخيص. تثبيت حسب request id تتبع أثر إلى استدعاء انتهاء، لذلك إلغاء فقط إبرة مقابل مرة تشغيل، و كما لا أخذ profile قفل حينئذ قدرة انتظار هو انتهاء.CLI وراثة إقرار إثبات بيئة و طرفية وصف رمز؛service استخدام تنظيف بعد بيئة و التقاط إخراج. إدارة جهاز مباشر قراءة ملف و Loader حالة، لا صيانة ثاني نسخة هدف حالة سجل التسجيل، لذلك لا إصدار مفرد وحيد وقت التشغيل ثابت صيغة مرافق توليد مدخل.

</details>

## تجربة النموذج

### إدارة أداة

#### نموذج يرى ماذا

[`plugin_manager` أداة](../../../docs/tool-catalog.ar.md#deepseek-aidsh-plugin-manager) صف خروج إضافة بند و تركيب حزمة، و تنفيذ أثر كامل profile تعديل. نتيجة يتضمن حفظ حالة تغير، تطبيق حالة و حزمة إدارة تشخيص. إدارة عملية لن نحو Agent حقن رسالة.

#### Token أثر

تركيب إعداد أداة إزالة استهلاك من وقت توفير أداة إعلان؛ كل مرة استدعاء إلحاق إرجاع بيان أو تعديل نتيجة.

#### KV Cache أثر

أداة نتيجة إلحاق إلى محادثة في. بدء توقف أخرى أداة ممكن تغيير لاحق أداة إعلان و ذلك ذاكرة مؤقتة إعادة استخدام.

## حدود معروفة وعمل مؤجل

<a id="known-limitations-and-deferred-work"></a>

- Web مرة دفعة دقيق عرض خروج قدوم كامل مجموعة انتظار قرار حزمة، لا يوجد تدريجي حزمة اختيار.
- استبدال قد لديه حزمة بعد حاجة إعادة بدء عملية، بـ تحميل جديد JavaScript وحدة إصدار.
- فقط بدء وقت تحميل profile لا يستطيع حذف حالي عملية بدء وقت استخدام حزمة؛ إيقاف عملية بعد استخدام `dsh plugin`.
- إدارة جهاز لا يستطيع إغلاق ذاته الذي يحتاج إدارة مكون، تعديل أخرى profile أو تحرير agent مسبق ضبط تركيب.
- فشل حذف ممكن إبقاء تحت جزء اعتماد تعديل، فشل أو يتم إلغاء تثبيت ممكن في `node_modules` أو pnpm ذاكرة مؤقتة في إبقاء تحت قد تحت تحميل ملف. ملف ناقص لم تفعيل اعتماد ما زال يمكن حذف. تشخيص سجل إبقاء في profile `.plugin-manager/logs` دليل في.
- إدارة نتيجة وصف Host تنشيط حالة. متصفح تزامن فشل سوف في ضبط إضافة قائمة في مفرد وحيد عرض.
- Desktop حزمة إدارة عملية ما زال من Desktop shell مسؤول.

<a id="failure-behavior"></a>
### فشل سلوك

فشل إبقاء قد إتمام خطوة، و تقرير إبلاغ فعلي ناقص إبقاء حالة. لا يوجد صالح تركيب حزمة إعلان profile اعتماد ما زال مرئي، يمكن حذف، لكن لا يستطيع تفعيل.

| فشل عملية | معالجة طريقة |
|---|---|
| تثبيت:pnpm تنفيذ أو تركيب حزمة تحقق فشل | استعادة pnpm تشغيل قبل لقطة `package.json` و `pnpm-lock.yaml`؛pnpm قد تحت تحميل ملف ممكن إبقاء. تقرير إبلاغ تثبيت فشل. |
| تفعيل: حفظ اختيار بند أو تحميل فشل | إبقاء قد تثبيت اعتماد و قد حفظ اختيار بند. تقرير إبلاغ تفعيل فشل، سماح إصلاح صحيح، توقف استخدام أو إزالة. |
| إزالة: مهمة واحد خطوة فشل | توقف في فشل خطوة، إبقاء قد إتمام تعديل و انتظار إعادة محاولة حذف اعتماد، تقرير إبلاغ إزالة فشل. لا إعادة تفعيل تركيب حزمة. |

pnpm تنفيذ و تركيب حزمة تحقق نجاح أي إتمام تثبيت، لاحق تفعيل فشل لا سحب إلغاء تثبيت. إزالة اعتماد مرة تنفيذ: من `dsh.profile.bundles` إزالة تركيب حزمة، إزالة وقت التشغيل مساهمة، تنفيذ `pnpm remove`. مهمة واحد خطوة فشل كل لا متابعة تنفيذ لاحق خطوة.

استعادة فقط إعادة كتابة هذا اثنان نسخة لقطة ملف؛ مستخدم تحرير كتابة patch إعداد، تطبيق بيانات، تشخيص سجل و pnpm قد تحت تحميل ملف إبقاء أصل مثال، لا يوجد manifest مرجع حزمة من تحت مرة حزمة عملية تنظيف.
