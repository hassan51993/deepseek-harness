# @deepseek-ai/dsh-agent-loop

[English](README.md) | العربية

## عام وصف

`dsh-agent-loop` إنشاء كل جديد agent أو استعادة حفظ دائم جلسة، مع بعد عبر نموذج طلب، تدفق صيغة استجابة، أداة تنفيذ و حمل دائم جلسة تاريخ قيادة كل جولة. معيار agent تركيب ينبغي تركيب هذه الحزمة؛ إعلان صيغة بند سوف في بدء وقت بدء agent، عام `ctx.agents` API فإن دعم حمل بـ تحرير مسار طريقة إنشاء و استعادة agent.`maxParallelToolCalls` حد معا تشغيل و سطر أمان استدعاء عدد كمية، وحيد احتلال استدعاء إبقاء ترتيب. إلغاء سوف إبقاء قد تدفق صيغة تسليم إعطاء مستخدم نص. فقط لديه معيار «استدعاء نموذج، تشغيل أداة، تكرار» دورة الحياة لا يمكن ممتلئ كاف يحتاج طلب وقت، عندئذ ينبغي اختيار ذاتي تعريف `Agent` تنفيذ.

## استخدام هذه الحزمة

في أي ينبغي تشغيل agent تركيب في تركيب `dsh-agent-loop`. هو توفير `ctx.agents` خلف بعد مشغل، و بدء أنت في إعداد في إعلان agent؛[`dsh-base`](../../bundle/base/README.ar.md) و [`dsh-sdk-minimal`](../../bundle/sdk-minimal/README.ar.md) كل سوف هو بصفة صريح إعداد سطر تركيب.

### إعداد إعلان صيغة agent

إعداد في إعلان agent سوف في إضافة تحميل وقت تلقائي بدء. كل بند حاجة واحد `id` وسم؛ نموذج استدعاء أيضا معا حاجة `provider` و `model`(`agent/request` يمكن في توزيع قبل تكملة متساو ناقص هذا واحد مقابل قيمة).

```yaml
- name: '@deepseek-ai/dsh-agent-loop'
  config:
    maxParallelToolCalls: 10
    agents:
      - id: 'main'
        provider: deepseek
        model: deepseek-chat
        reasoningEffort: high
        cwd: /workspace
```

| حقل | قيمة افتراضية | يحتوي معنى |
|---|---|---|
| `maxParallelToolCalls` | `10` | كل خطوة معا في طريق و سطر أمان أداة استدعاء عدد؛`1` لـ سلسلة سطر |
| `agents[].id` | لا بد ملء | مستقر وسم؛ لم ضبط `sessionId` وقت، كل جديد جلسة سوف توليد `${id}-session-<uuid>` |
| `agents[].provider` / `agents[].model` | — | نموذج توجيه؛ توزيع قبل اثنان من كل يجب وجود |
| `agents[].reasoningEffort` | — | غير فارغ ابتدائي دفع إدارة قوي درجة؛`agent/request` يمكن تغطية هو |
| `agents[].maxTokens` | — | صحيح عدد تدريجي طلب إخراج token حد أعلى |
| `agents[].cwd` | — | كل جديد جلسة عمل دليل |
| `agents[].sessionId` | — | تأكيد قطع هوية: أول مرة استخدام إنشاء، إعادة تركيب وقت استعادة قد فعلي جسم تحويل تاريخ |
| `agents[].resumeSessionId` | — | تحميل هذا عدد حفظ دائم جلسة بينما لا هو إنشاء جديد جلسة؛ و `sessionId` متبادل رفض |

توليد[إعداد دليل](../../../docs/config-catalog.ar.md#deepseek-aidsh-agent-loop) هو كل تلقي دعم حمل حقل نفاد كل صيغة حق مصدر. مهايئ سوف تحقق صالح دفع إدارة قوي درجة، حلقة فإن يأخذ هو سجل في طلب رأس في.`maxParallelToolCalls` أيضا هو كامل `agent-loop` ضبط قسم عقدة، لذلك تراكم إضافة في هذا بند لـ فوق مستخدم طبقة بلا حاجة إعادة بدء يكفي حد تحت واحد مجموعة أداة استدعاء.

### بـ تحرير مسار طريقة إنشاء أو استعادة agent

إضافة و مضيف عبر `ctx.agents.create()` إنشاء agent، عبر `ctx.agents.resume()` استعادة حفظ دائم جلسة؛ اثنان من كل إرجاع `AgentHandle`، ذلك `dispose()`(مورد تحرير) مسؤول دقيق تفكيك حذف مقابل agent. حلقة سوف يأخذ كل إنشاء agent تشغيل إلى إتمام——فقط لديه استدعاء جهة حاجة ذاتي سطر تفكيك حذف agent وقت عندئذ حاجة جملة مقبض.

```text
const handle = await ctx.agents.create({
  sessionId,
  agentOptions: { provider: 'deepseek', model: 'deepseek-chat' },
  setup: (agentCtx, agent) => { /* scoped registrations plus explicit unpublished Agent */ },
})
```

كل مرة inbox تغيير كل سوف إيداع واحد بند مواصفة تحويل `agent/inbox/spliced` حدث. إسقاط سجل التسجيل سوف تزامن طي هذا حدث، لذلك `Session.append()` إرجاع وقت، فوري إسقاط قد عكس عكس هذا splice. إدراج دخول، تحرير، إزالة، قيادة أخذ و إلغاء كل عبر نفس مجموعة معيار splice جلوس علامة إعادة تشغيل. عادي حذف يحمل `outcome: 'canceled'` تزامن خروج `agent/inbox/discarded { message }`؛ قيادة أخذ استخدام لا حمل outcome صاف حذف، تزامن خروج `agent/inbox/claimed`. كل مرة إدراج دخول كل سوف إرسال خروج `agent/inbox/inserted { message }`.`MessageId` في اثنان عدد انتظار معالجة قائمة بين إبقاء وحيد. حاجة يتم إزالة رسالة مستهلك ينبغي استخدام claimed أو discarded إشعار، بينما لا اعتماد splice قبل `session/event` إسقاط عرض.

### واحد خطوة فعل ماذا

كل خطوة كل سوف إرسال جلسة إرسال توليد تاريخ——الأكثر جديد غير فارغ `system/message` عقدة هو صالح نص التوجيه، تصيير نص التوجيه لـ فارغ وقت فإن لا يوجد نظام رسالة——و ذلك مرئي أداة schema؛ نموذج أداة استدعاء مرور مرور تلقي حراسة حماية أداة خط الإنتاج، كل يتم وصل قبول واقع كل سوف في تحت واحد خطوة حسب هذا إرسال توليد قبل إلحاق إلى جلسة سجل. و سطر أمان استدعاء الأكثر كثير يمكن إعادة تراكم `maxParallelToolCalls` عدد؛ وحيد احتلال استدعاء مفرد وحيد تشغيل و بنية صار ترتيب ترتيب شاشة عائق. إلغاء هو تنسيق عمل صيغة:`agent.cancel()` في توقف حالي نشط حركة، و في لم ضبط `keepInbox` وقت صاف حذف انتظار معالجة عمل؛ يتم إلغاء تدفق سوف نهاية ربط قد إرسال بلوغ مستخدم نص.

## فهم التنفيذ

<details>
<summary>تنفيذ دقيق عقدة——انقر للتوسيع</summary>

هذا عقدة حل تفسير هذا حزمة مثل أي تنفيذ فوق وصف سلوك؛ يمكن مراقبة اتفاق قد في[استخدام هذه الحزمة](#use-this-package) في كامل شرح.

### تصميم إدارة فكرة

هذا حزمة هو عام `Agent` اتفاق وحيد أداة كائن تنفيذ. هو في `ctx.agents` فوق يأخذ ذاته تسجيل لـ `AgentFactory`، لذلك مستهلك من لا استيراد هذه الحزمة؛ كل إنشاء agent كل حق ملكية في استدعاء جهة fiber و حلقة مزود، و تجميع دمج إلى نفس عدد تسجيل ذاكرة تحويل تماما توقف مستقر حد. كل يمكن مراقبة فاعلية نتيجة كل عبر جلسة حدث و `agent/*` تصنيف جسم نظام حدوث——حزمة داخلي تنفيذ أبدا يخص عام واجهة.

### طلب header و مهايئ قيمة افتراضية

`agent/request` إرجاع بعد،`ctx.llm.prepareCall()` سوف في نشط وثب جولة إشارة تحت تحقق مهايئ يحتفظ حقل، و تحليل دفع إدارة قوي درجة و إخراج token قيمة افتراضية. حلقة سوف في تحليل،`request/header` سجل و قسم إرسال خلال إبقاء نفس عدد مهايئ. حلقة سوف لـ أول مرة طلب، تغير envelope(إعداد أو أداة——نص التوجيه لا يخص header) ، صريح رسالة تسلسل بدء نقطة،surface استبدال أو صورة حذف قرار بعد طلب و استعادة كتابة كامل header؛ نفس تسلسل داخل محتوى لم تغيير خطوة، إعادة محاولة و عادي لاحق جولة وراثة الأكثر جديد header، تاريخ داخل إلحاق نص التوجيه لا هو استبدال، لذلك ضيق مع ذلك بعد طلب نفس مثال وراثة header. في header خارج، حلقة أيضا سوف سجل `request/context`——مزود، نموذج،`contextWindow` و قدوم ذاتي `prepareCall()` توجيه `systemPromptUpdate` نمط——كما فقط في منها أي واحد بند و الأكثر جديد لقطة مختلف وقت سجل. تحت مرة waterfall توزيع قبل، حلقة إزالة مهايئ افتراضي حقل، جعل حالي توجيه إعادة تحليل هو جمع؛ صريح ضبط فإن إبقاء. لم معالجة توجيه ما زال بـ `NO_ADAPTER` فشل.

حلقة في كل إرسال توليد رسالة كائن أول مرة دخول طلب وقت تنفيذ عميق تجميد ربط، و كما فقط في نفس agent داخل إعادة استخدام هذا إثبات. استعادة رسالة إبقاء كائن هوية؛ بنية صنع طلب لن تجميد ربط يتضمن رسالة حدث حزمة تركيب كائن. كل طلب كل سوف تجميد ربط محلي مواصفة تحويل header، جديد رسالة عدد مجموعة و طلب غلاف تركيب، معا إبقاء إلغاء إشارة متغير صفة.[طلب تجميد ربط قرار](../../../.agents/notes/implemented/simplification/2026-09-06-agent-request-freeze-evidence.ar.md) حل تفسير كل حق و قياس كمية اعتماد حسب.

### إنشاء و تفكيك حذف

إنشاء هو نفس عدد تلقي تراجع حفظ حماية أمر خدمة: بنية صنع خاص جلسة، أداة كائن agent و حمل أثر مجال سياق؛ انتظار اختياري setup؛ دخول اثنان عدد سجل التسجيل؛ إعلان إبلاغ `session/created`؛ انتظار سلسلة سطر `agent/created` مستمع؛ مع بعد تحرير قد ترتيب طابور إدخال. إنشاء وقت التشغيل فرعي Agent استدعاء جهة ضبط `options.parentAgent`؛ استدعاء جهة Context فإن مفرد وحيد يملك أمر خدمة و تخزين نشط جملة مقبض.Setup،commit، مستمع فشل أو كل من dispose كل سوف تراجع قد دقيق تجهيز مورد. قد إرسال بلوغ إعلان إبلاغ ما زال يمكن يتم مراقبة، و لديه إعداد مقابل إلغاء تدمير إشعار.Teardown إيقاف و ترتيب فارغ مشغل، سحب إلغاء أثر مجال، إغلاق جلسة كتابة مسار،detach agent، مجددا detach جلسة. كل مرة detach كل ربط إلى تأكيد قطع دخول كائن، لذلك قديم قديم disposer لا يمكن إزالة بعد ظهور نفس id بديل بند.

### حفظ دائم تجميع صار

حلقة هو جلسة كتابة جملة مقبض في إنتاج بيئة في نيل أخذ نقطة. تركيب `ctx.sessionPersistence` بعد،`create`/`createAgent` استدعاء `persistence.create(header)`——في إصدار قبل تخزين حمل دائم هوية و أخذ نيل كتابة كل حق——و عبر جملة مقبض إلحاق بنية صنع seed؛`resume` أولا استدعاء `persistence.open(id, 'write')`(ترتيب حذف نفس id تزامن استعادة) ، عبر جملة مقبض قراءة شيء إدارة فوق صالح سجل، و لـ في جولة في طريق انهيار انهيار سجل يأخذ `interruptedTurnClosers` بصفة عادي دفعة مرة إلحاق——دلالة انهيار انهيار إصلاح هو agent طبقة مسؤولية، بينما غير تخزين مدخل. إصدار قبل الأكثر بعد واحد لحظة،`appendUnstoredSuffix` تخزين setup نافذة خلال إلحاق حدث (seed علامة، تفويض إرسال سياسة سجل) ، هو جمع أبدا سوف مرور من `session/event` إعادة إرسال خروج. إصدار بعد، تركيب خلفية حسب جلسة id يأخذ هذا جلسة `session/event` دفعة مرة،`session/flush` شاشة عائق و `session/disposed` تراجع دور توجيه دخول نشط وثب كتابة جملة مقبض؛ حلقة فقط عبر هو يملك جملة مقبض لمس اصطدام تخزين. تسجيل ذاكرة تحويل teardown في حلقة إيداع جلسة استلام ذيل حدث بعد إغلاق جملة مقبض——close سوف ترتيب فارغ أي قد توجيه مؤقت اندفاع——يمكن إثبات أرض تحرير كتابة كل حق. لا يوجد خلفية وقت، جلسة فقط وجود في داخل تخزين في، ذلك بقية واحد قطع ثابت.

### جولة و خطوة مسار

مشغل في ذلك كامل دورة الحياة داخل يملك واحد agent، و في `ctx.agents.withInitiator(agent, ...)` داخل تشغيل.`AgentLoop` في خدمة دورة الحياة داخل تسجيل معيار `inbox` إسقاط، لذلك بارد قراءة في لا يوجد Agent و كل Agent إزالة بعد كل متاح. ذلك حزمة داخلي `ReactLoopInbox` استخدام هذا مشترك إسقاط تنفيذ بنية تحويل أمر و فقط توفير loop استخدام قيادة أخذ عملية. في جولة حد، هو أولا فتح حمل دائم جولة، مجددا أصل فرعي قيادة أخذ انتظار معالجة next-step إدخال و واحد بند ترتيب طابور نص التوجيه؛ في خطوة بين فإن فقط قيادة أخذ next-step إدخال. مشغل تجميع نص التوجيه و أداة، إسقاط وقت التشغيل سياق، و تشغيل `agent/pre-step`. يتم رفض قرار أو فارغ أول دفعة إدخال لا فتح خطوة. وصل قبول بعد أول مرة محاولة تجربة أولا سجل `step/start`، مجددا تشغيل `agent/request` waterfall و `prepareCall()`؛ هذا اثنان عدد مختلف خطوة مرحلة مقطع كل نظر لا إلى انتظار إيداع توجيه النظام و قد وصل قبول مستخدم رسالة دخول تاريخ، في مهمة واحد مرحلة مقطع إلغاء كل لن إيداع هذا اثنان من. كل مرة محاولة تجربة وقت، حلقة مع بعد اعتماد حسب قد دقيق تجهيز استدعاء قدرة، تزامن سوف تصيير بعد نص التوجيه و تخزين نشط `system/message` عقدة تنسيق ضبط متسق، فقط في أول مرة محاولة تجربة إلحاق قد وصل قبول `user/message` دفعة مرة، حسب يحتاج سجل header و context، مجددا إرسال توليد و تجميد ربط طلب، عبر هذا ربط قد دقيق تجهيز استدعاء إرسال بدء تدفق صيغة طلب. إعادة محاولة إعادة استخدام نفس نسخة قد تصيير تجميع نتيجة، لا تكرار تجميع،`agent/pre-step` أو مستخدم رسالة دقيق دخول. تنسيق ضبط مرور مسار مرئي pre-step و إعادة محاولة في ضغط؛ تسلسل في قطع وقت سوف نص التوجيه عودة و إلى رأس جزء، بينما غير في قد إيداع مستخدم رسالة بعد إلحاق تحديث. طلب من `header.config`،`deriveMessages()` و `header.tools` بنية صار، لا يحمل `system` حقل. كل مرة نموذج محاولة تجربة سوف إرسال خروج واحد عملية محلي `start`، فقط في مطابقة حمل دائم assistant-frame تسوية بعد إرسال خروج كل عدد `chunk`، و تماما جيد إرسال خروج واحد نهاية حالة `end`؛ نهائي تجميع أو رسالة إلحاق فشل وقت بـ `aborted` تسوية،`committed` فإن ظهور في حمل دائم `assistant/message` بعد. كل مرة نجاح نموذج استدعاء كل تماما جيد إلحاق واحد message مرساة نقطة، يتم إلغاء تدفق فإن إلحاق حمل `interrupted: true` مرساة نقطة و يحمل قد تسليم بادئة، جعل تحت مرة طلب يتضمن مستخدم يرى محتوى. في خطوة داخل، وحيد احتلال استدعاء شكل صار شاشة عائق، و سطر أمان استدعاء استخدام محدود تمرير حوض؛ سياسة، حمل دائم نتيجة و نتيجة سياق إبقاء نموذج ترتيب.

نص التوجيه دقيق دخول اعتماد حسب فعلي `prepareCall()` نتيجة، بينما غير أولا قبل `request/context`. لا يوجد نظام عقدة وقت، أي جعل نص التوجيه لـ فارغ أيضا إلحاق (مسبق إبقاء رقم 0 رقم عقدة، لكن لا إنتاج بروتوكول رسالة). في لا أداة تجهيز قدرة توجيه فوق أو جديد طلب تسلسل بدء وقت، غير فارغ تصيير نص عودة و إلى أول عدد نظام عقدة: كل غير فارغ لاحق نظام عقدة قسم آخر استلام إلى لديه سجل سجل فارغ محتوى استبدال، مع بعد حسب يحتاج إعادة كتابة رأس عقدة. لم توليد فاعلية فارغ ذيل عقدة بلا حاجة استبدال، أيضا لا قرار صالح نص. أي جعل الأكثر جديد صالح نص لم تغيير، أيضا تنفيذ عودة و. تأخير متابعة في `in-history` تسلسل في صالح نص التوجيه ثابت وقت لا إنتاج حدث، غير فارغ تغيير فإن إلحاق. بلا نقاش توجيه أو تسلسل حالة مثل أي، فارغ تصيير نص كل سوف عبر لديه سجل سجل تدريجي عقدة فارغ محتوى استبدال صاف حذف كل غير فارغ لاحق نظام عقدة، مجددا حسب يحتاج صاف فارغ رأس عقدة. نموذج لن متابعة يرى قديم إشارة أمر. فارغ رأس عقدة كما لا يوجد توليد فاعلية لاحق نظام عقدة يمثل لا يوجد نص التوجيه؛ تكرار صاف حذف و استعادة جلسة كل إبقاء لـ فارغ. إعادة توفير غير فارغ نص التوجيه التزام دوران نفس توجيه/تسلسل قاعدة: تأخير متابعة في أداة تجهيز قدرة توجيه يمكن إلحاق هو، لا أداة تجهيز قدرة توجيه أو جديد تسلسل فإن إعادة ملء ملء رأس عقدة. التالي حال حال فتح بدء تسلسل:pre-step قرار إعلان `startsRequestSeries`،`session.surface.contentGeneration` ذاتي مرفق وصل أو فوق مرة طلب بـ قدوم حدوث تغير (استبدال أو صورة حذف قرار) ، مرئي أداة schema تغير. استعادة و مفرد صاف مزود أو نموذج تبديل كل تأخير متابعة تسلسل؛ دقيق دخول ما زال من قد دقيق تجهيز توجيه قرار. تدريجي عقدة فارغ محتوى استبدال إبقاء ذلك بين تاريخ، بلا حاجة surface حذف عملية.

### فشل و إلغاء

نهائي مهايئ اختيار، توزيع و تكرار بديل فشل بـ إنهاء انتهاء شكل صيغة وصول و دخول `agent/request-error`؛ معالجة هذا فشل مستمع إرجاع `{ kind: 'retry' }` كما لا استدعاء `next()`، لم يتم معالجة فشل فإن هو نهاية حالة.Middleware، نتيجة معالجة، أداة و أخرى توسيع فشل ما زال سوف رمي خروج و مباشر إغلاق جولة——إضافة فشل انتهاء هو جولة، لا هو حلقة. إلغاء بعد لم توزيع نموذج أداة استدعاء سوف استلام إلى دمج صار `tool/call` إضافة `ABORTED_BEFORE_DISPATCH` نتيجة مقابل.[صريح إلغاء قرار](../../../.agents/notes/implemented/architecture/2026-07-16-explicit-turn-cancellation.ar.md) يملك إشارة دورة الحياة.

<a id="model-experience"></a>
## تجربة النموذج

### كامل محادثة طلب

#### نموذج يرى ماذا

كل خطوة في، حلقة سوف إرسال جلسة إرسال توليد رسالة و مرئي أداة schema. غير فارغ `system/message` عقدة تحمل تحميل نص التوجيه، الأكثر جديد واحد بند هو صالح إصدار؛ فارغ تصيير نص سوف من إرسال توليد تاريخ في صاف حذف كل نص التوجيه إصدار. هو توفير `provider`،`model` و `cwd` متغير قيمة، لكن لا إضافة ثابت نص سجل.

#### Token أثر

نظام نص و schema في كل خطوة كل سوف مجددا مرة حساب دخول، في `in-history` توجيه فوق، كل إبقاء نص التوجيه إصدار كل سوف حمل متابعة حساب دخول، مباشر إلى ضغط سوف ذلك حجب حجب أو نص التوجيه تنسيق ضبط سوف ذلك صاف فارغ. تدريجي agent أثر مجال قرار مساهمة، بينما مرجعي تجميع waterfall يمكن تغيير نهائي طلب، و جعل ذلك مستمع مسؤول إبقاء بروتوكول وصل اختراق.

#### KV Cache أثر

فقط لديه في نفس مزود و نموذج توجيه تحت، كما نظام نص،schema و هذا قبل تاريخ كل إبقاء تدريجي بايت متسق وقت، طلب عندئذ إبقاء فقط إلحاق. تصيير بعد نص التوجيه لم تغيير وقت، ذاكرة مؤقتة بادئة نيل بـ إبقاء، حذف غير لا أداة تجهيز قدرة توجيه أو جديد طلب تسلسل يجب عودة و إبقاء تاريخ داخل نظام عقدة. أصل أرض استبدال بعض عدد نظام عقدة نص التوجيه تغيير سوف جعل طلب من هذا عقدة رقم واحد token بدء حينئذ مختلف——هذا عقدة هو رقم 0 رقم عقدة وقت فإن كامل طلب كل مختلف——لذلك مزود بادئة ذاكرة مؤقتة من ذلك داخل بدء لم أمر في؛ عند قد دقيق تجهيز استدعاء إعلان `systemPromptUpdate: 'in-history'` وقت، نفس طلب تسلسل تأخير متابعة خلال غير فارغ نص التوجيه تغيير سوف إلحاق إلى قد ذاكرة مؤقتة تاريخ بعد، لذلك مباشر إلى هذا تاريخ نهاية ذيل بادئة ما زال يمكن إعادة استخدام.schema أو تركيب تغيير فإن من رقم واحد تغيير طلب token بدء جعل إعادة استخدام بطلان.

### إبقاء رسالة تاريخ

#### نموذج يرى ماذا

قد وصل قبول user رسالة،assistant رسالة، أداة استدعاء و نتيجة، حقن سياق و steering(في طريق جذب توجيه) كل سوف سجل، و في لاحق خطوة في إرسال. أصلي تدفق قسم قطعة، دورة الحياة حد و أخرى فقط كتابة سجل حدث سوف يتم ترتيب حذف.

#### Token أثر

إدخال سوف مع كل بند جدول طبقة رسالة زيادة طويل، مباشر إلى ضغط استبدال حجب حجب مقارنة قديم عقدة؛ يتضمن كثير عدد خطوة أداة جولة سوف في كل خطوة إعادة إرسال تراكم تراكم تاريخ.

#### KV Cache أثر

عادي تاريخ زيادة طويل فقط إلحاق، و إبقاء يمكن إعادة استخدام بند. جدول طبقة استبدال أو ضغط سوف من رقم واحد يتم حجب حجب تاريخ token بدء جعل إعادة استخدام بطلان.

### إلغاء بعد لم توزيع استدعاء

#### نموذج يرى ماذا

إذا لاحق طلب إعادة تشغيل واحد في توقف خطوة، إلغاء الذي منع توقف توزيع كل أداة استدعاء كل لديه رمز خطأ `ABORTED_BEFORE_DISPATCH`، نتيجة نص لـ `Error: tool call aborted before dispatch`.

#### Token أثر

كل قفز مرور استدعاء كل سوف في تاريخ في إبقاء واحد ثابت خطأ نتيجة، مباشر إلى ضغط سوف ذلك حجب حجب.

#### KV Cache أثر

فقط إلحاق؛ كل دمج صار نتيجة كل يقع في يمكن إعادة استخدام طلب بادئة بعد، لن جعل قائم KV Cache بند بطلان.

## حدود معروفة وعمل مؤجل

<a id="known-limitations-and-deferred-work"></a>


هذه حد شرح حلقة أي وقت حاجة خاص آخر إبقاء معنى. هو جمع هو حالي حزمة قيد، لا هو مهمة تراكم ضغط.

- **تصنيف هو واحد عنصر**: أمان صفة أخذ قرار في مقارنة مقارنة نفس درجة استدعاء أو مورد استدعاء يجب إبقاء وحيد احتلال ([أصل إدارة](../../../.agents/notes/implemented/feature/2026-07-10-parallel-tool-call-execution.ar.md)).
- **إعداد وسم افتراضي مقابل جديد جلسة**: حذف `sessionId` وقت، كل مرة بدء كل سوف إنشاء جديد `${id}-session-<uuid>`؛ مثل يحتاج تأكيد قطع استعادة أو إنشاء سلوك، يجب صريح توفير مستقر `sessionId`، بينما `resumeSessionId` اشتراط قد لديه حفظ دائم تاريخ.
- **إعداد agent لا يوجد تدريجي agent persona حقل أو setup خطاف**: هو جمع استخدام نشر persona؛ فقط لديه تحرير مسار صيغة `ctx.agents.create()` / `resume()` عمل مصنع خيار دعم حمل حمل أثر مجال persona و أداة تركيب.
- **لا يوجد داخل وضع جولة ميزانية**: أداة استدعاء أو steering سوف يجعل حالي جولة متابعة؛ حد فقد تحكم جولة سياسة يجب من قائم دورة الحياة نقطة توسيع (مثل `agent/turn-stopping`) تنفيذ إلغاء.
