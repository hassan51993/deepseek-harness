# @deepseek-ai/dsh-typert-registry

[English](README.md) | العربية

## عام وصف

`dsh-typert-registry` يجعل توليد Typert ناتج في وقت التشغيل يمكن حسب يحتاج استعلام: كل حزمة عكس إطلاق، كسول صفة Zod schema factory و Remote استدعاء وصف رمز كل حفظ في مستقر مفتاح تحت. مستهلك أول مرة طلب schema وقت عندئذ سوف شيء تحويل و ذاكرة مؤقتة هو. تسجيل هو أصل فرعي كما حسب fiber أثر مجال: مساهمة يلزم ما كامل جسم سقوط أرض يلزم ما تماما لا سقوط أرض، و في تسجيل مكون إزالة وقت تلقائي سحب إلغاء. نفس خدمة أيضا حمل إدارة Remote استدعاء الذي مرور من lookup و أثر مجال Context مزود سجل التسجيل. هو لا تنفيذ TypeScript قسم تحليل، أيضا لا توليد schema؛ هذه من توليد جهاز و loader مسؤول.

<a id="use-this-package"></a>
## استخدام هذه الحزمة

في تخزين أو إزالة استهلاك توليد Typert ناتج أي Host أو Client تركيب في تركيب هذا سجل التسجيل؛ هو توفير `ctx.typert`. لا يوجد إعداد.

### الأكثر صغير ضبط

تحميل سجل التسجيل إضافة؛Client face من Client وقت التشغيل ذاته بيانات وصفية بـ نفس مثال طريقة تثبيت، اثنان عدد face تشغيل نفس تنفيذ:

```yaml
- name: '@deepseek-ai/dsh-typert-registry'
```

### استعلام schema و عكس إطلاق

مستهلك استخدام `get(key)`،`resolve(key)` أو `list(filter?)` قراءة schema، استخدام `getPackage(name, face?)` أو `listPackages(filter?)` قراءة حزمة عكس إطلاق. أول مرة قراءة سوف شيء تحويل واحد عملية realm داخل schema نسخة، لاحق قراءة إعادة استخدام هذا نسخة.`resolve()` قدرة منطقة قسم صيغة خطأ مفتاح، لم تسجيل حزمة، و قد تسجيل لكن لم بـ هذا اسم توفير schema حزمة، كل منها إعطاء خروج مختلف خطأ.`toJSONSchema(key)` يأخذ قد شيء تحويل Zod schema إسقاط لـ JSON Schema، لكن لا ذاكرة مؤقتة هذا إسقاط.

### تسجيل مساهمة

توليد ناتج في Loader تركيب في عبر [loader](../loader/README.zh.md) تسجيل؛ أخرى كل من مباشر استدعاء `ctx.typert.register(contribution)`، و نيل نيل سحب إلغاء هو نفس مورد تحرير دالة. تكرار حزمة و face تركيب مفتاح،schema مفتاح، استدعاء id أو طرف نقطة سوف في إيداع أي محتوى قبل رفض كامل دفعة مرة.

### Lookup و Context مزود

Remote استدعاء عبر `ctx.typert.lookups` و `ctx.typert.contexts` تحليل Host كائن و أثر مجال Context.`registerHost()` تثبيت Host wire إعلان و ذلك wire إلى Context resolver،`configureHost()` فقط استبدال هذا resolver.`registerClient()` لـ نفس عدد merge-declared kind تثبيت مزدوج نحو Client adapter.Host إلى Client حدث مصدر صريح يحمل مجال identity، بينما لا من Context عكس نحو إسقاط.

<a id="understand-the-implementation"></a>
## فهم التنفيذ

<details>
<summary>تنفيذ دقيق عقدة——انقر للتوسيع</summary>

هذا عقدة حل تفسير سجل التسجيل مثل أي تخزين و يملك مساهمة؛ مستهلك API قد في[استخدام هذه الحزمة](#use-this-package) في شرح.

### تصميم إدارة فكرة

سجل التسجيل بناء قيام في واحد أصل فإن لـ فوق: مساهمة هو مرة أصل فرعي، من fiber يملك إيداع.`register()` أولا تحقق حزمة و face تركيب مفتاح،schema و استدعاء وصف رمز، مجددا في مفرد عدد Cordis effect تحت إيداع الكل محتوى، هذا effect مورد تحرير دالة دقيق سحب إلغاء هذا واحد مساهمة. تكرار معرف في يملك هذا عملية كل حق حد فشل، هذا وقت أي حالة كل لم تغيير.

### فرعي سجل التسجيل

- `ctx.typert.local`——حالي بيئة استدعاء تعريف، يحتوي توفير شفرة المصدر نمط رجوع استخدام `hasSeen()` تاريخ.
- `ctx.typert.remotes`——في استدعاء جهة fiber في تركيب، من مستهلك اختيار في مساهمة.
- `ctx.typert.lookups`——lookup مزود، و حسب مفتاح إعداد تركيب جهة محلل تغطية.
- `ctx.typert.contexts`——حسب أثر مجال مفتاح إعداد Host Context مزود و Client Context ربط جهاز.

كل فرعي سجل التسجيل كل سوف نحو قد حجز قراءة مستمع إصدار `TypertRegistryChange` حدث؛ رمي استثناء مستمع سوف يتم سجل سجل، كما لن منع توقف لاحق مستمع.

### معرف و تحقق

مفتاح هو مستقر: عكس إطلاق استخدام `<package>#<face>`،schema استخدام `<package>#<name>`، طرف نقطة استخدام `<namespace>/<method>`. تحقق سوف رفض يحتوي `#` اسم، تجاوز خروج RPC طرف نقطة مقطع نص قاعدة wire اسم، تكرار مفتاح، و في ذلك سجل التسجيل دورة الحياة داخل تغيير wire إعلان lookup تعريف؛schema بند و صارم إطار تحرير حل رمز جهاز يجب يحمل factory.

### شفرة المصدر أرض رسم

| ملف | مسؤولية |
|---|---|

## حدود معروفة وعمل مؤجل

<a id="known-limitations-and-deferred-work"></a>


هذه حد شرح سجل التسجيل تخزين و رفض ماذا؛ هو جمع هو حالي حزمة قيد، لا هو مهمة تراكم ضغط.

- **لا دمج رسم**——سجل التسجيل حسب face تخزين توليد عكس إطلاق، لكن لا دمج مضيف جانب و عميل جانب رسم، أيضا لا تحليل TypeScript مرجع؛ هذه هو قسم تحليل جهاز و توليد جهاز أمر.
- **schema مفتاح لا يحتوي face**——مضيف جانب و عميل جانب في مختلف سياق في تشغيل، لذلك في نفس سياق في تسجيل قدوم ذاتي اثنان عدد face نفس اسم schema سوف يتم بصفة تكرار بند رفض.
- **JSON Schema إسقاط لا ذاكرة مؤقتة**——`toJSONSchema()` كل مرة استدعاء كل إرجاع كل جديد وثيقة؛ حاجة تكرار إسقاط مستهلك ذاتي سطر مسؤول ذاكرة مؤقتة.
