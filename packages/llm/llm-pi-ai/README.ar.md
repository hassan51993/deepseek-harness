# @deepseek-ai/dsh-llm-pi-ai

[English](README.md) | العربية

## عام وصف

`@deepseek-ai/dsh-llm-pi-ai` عبر واحد نسخة إعداد يأخذ نموذج طلب توجيه إلى كثير عدد pi-ai مزود،OpenAI توافق شبكة صلة أو ذاتي حمل إدارة خادم. قد تثبيت pi-ai مزود سوف توفير طرف نقطة، بروتوكول و نموذج دليل قيمة افتراضية؛ ذاتي تعريف توجيه يمكن مباشر إعلان هذه قيمة، بلا حاجة تعديل شفرة.profile و اعتماد حسب طلب تحليل، لذلك ضبط تغيير سوف في تحت واحد طلب توليد فاعلية، بلا حاجة إعادة بدء. تلقي دعم حمل مزود يمكن استخدام قد تخزين OAuth أو تفاعل صيغة مفتاح تسجيل تسجيل، و عبر عبر عملية قفل تحديث جديد اعتماد. هذه الحزمة يمكن في لا يوجد توجيه وقت بدء، و في مستخدم ضبط إضافة توجيه بعد سوف ذلك تنشيط.

## استخدام هذه الحزمة

عند تركيب حاجة عبر pi-ai مزود دليل، أو عبر pi-ai قد تثبيت دليل لم وصف شبكة صلة توجيه نموذج طلب وقت تركيب هذا إضافة.`providers` حرف قاموس حينئذ هو كامل إعداد وجه: كل مفتاح كل هو طلب استخدام `GenerateOptions.provider` اختيار مزود توجيه اسم.

### أي وقت اختيار

عند نفس تركيب خدمة كثير عدد مزود، بعض بند توجيه حاجة pi-ai دليل قيمة افتراضية و إصلاح صحيح قليل عدد حقل، أو يجب عبر ذاتي لديه طرف نقطة و بروتوكول وصول يد عمل إعلان شبكة صلة وقت، اختيار هذا مهايئ. عند نشر لا حاجة أخرى مزود وقت، اختيار `dsh-llm-deepseek` مباشر وصل DeepSeek توجيه. اثنان عدد مهايئ يمكن معا تركيب، لأن هو جمع توجيه اسم لا اندفاع مفاجئ؛ تسجيل أخرى مهايئ قد يملك توجيه سوف توجيه يؤدي إضافة تحميل فشل.

### إعداد مزود توجيه

كل profile كل يمكن ضبط `retryPolicy`؛ حذف وقت استخدام normal mode، الأكثر كثير إعادة محاولة خمسة مرة.`apiKeyEnv` هو حسب طلب مرور harness اعتماد seam تحليل اعتماد مرجع، لذلك ملف إعداد أبدا يتضمن مفتاح؛ تحليل لـ فارغ مرجع سوف يجعل طلب بـ `MISSING_CREDENTIAL` فشل. حذف هو سوف يجعل توجيه إبقاء قد إعداد لكن بلا مفتاح (configured-but-keyless) حالة، مقابل قد تثبيت دليل توجيه بينما قول أي تسليم من pi-ai مزود أصلي بيئة اكتشاف.

```yaml
- name: '@deepseek-ai/dsh-llm-pi-ai'
  config:
    providers:
      openai:
        apiKeyEnv: OPENAI_API_KEY
        baseURL: https://proxy.example.com:8443
        reasoning: high
        requestImagePixelBudget: 4194304 # total pixels; 2048 by 2048 default
        requestImageMaxBytes: 1048576    # raw bytes before base64 expansion
        maxRequestImageBytes: 20971520   # accumulated base64 payload
        retryPolicy:
          mode: normal
          maxRetries: 3
      anthropic:
        apiKeyEnv: ANTHROPIC_API_KEY
        models:
          - id: claude-sonnet-4-5
            contextWindow: 200000
      acme-gateway:
        displayName: Acme Gateway
        apiKeyEnv: ACME_GATEWAY_API_KEY
        api: openai-completions
        baseURL: https://gateway.acme.example/v1
        compat:
          thinkingFormat: deepseek
        models:
          - id: acme-think
            name: Acme Think
            contextWindow: 262144
            reasoningEfforts:
              off:
              high: high
```

| حقل | قيمة افتراضية | يحتوي معنى |
|---|---|---|
| `apiKeyEnv` | بلا | حسب طلب تحليل اعتماد مرجع؛ حذف وقت تسليم من pi-ai بيئة اكتشاف |
| `displayName` | مزود اسم | اختيار جهاز واجهة عرض وسم |
| `api` | دليل بروتوكول | بروتوكول صيغة؛ فقط دليل لا توفير توجيه حاجة |
| `baseURL` | دليل طرف نقطة | توجيه فوق كل نموذج طرف نقطة |
| `models` | قد تثبيت دليل | كامل جسم استبدال توجيه دليل؛ كل بند من قد تثبيت نموذج أخذ قيمة افتراضية |
| `modelOverrides` | بلا | إعادة تشكيل عدد آخر قد تثبيت دليل نموذج، بينما لا استبدال ذلك بقية نموذج |
| `compat` | دليل فحص قياس | لا يمكن تعرف آخر طرف نقطة بروتوكول توافق فتح صلة |
| `defaultContextWindow` | `262,144` | لم وصف نموذج سعة كمية رجوع |
| `defaultMaxTokens` | `32,768` | لم وصف نموذج إخراج حد أعلى رجوع |
| `requestImagePixelBudget` | `4,194,304` | كل ورقة تحديد صفة طلب صورة مجموع مثل عنصر ميزانية |
| `requestImageMaxBytes` | `1 MiB` | كل ورقة طلب صورة في base64 توسيع قبل تحرير رمز بايت هدف |
| `maxRequestImageBytes` | `20 MiB` | base64 صورة تحميل حمل مجموع حد أعلى، إبقاء صورة تجاوز مرور وقت طلب بـ `IMAGE_OFFLOAD_REQUIRED` فشل |
| `retryPolicy` | normal،5 مرة إعادة محاولة | من `dsh-llm-retry` تنفيذ مزود ذاتي لديه إعادة محاولة سياسة |

توليد[إعداد دليل](../../../docs/config-catalog.ar.md#deepseek-aidsh-llm-pi-ai) هو كل تلقي دعم حمل حقل و ذلك JSDoc نفاد كل صيغة حق مصدر.

### تسجيل تسجيل مزود

pi-ai توفير تسجيل تسجيل مزود يمكن عبر harness تخويل seam تسجيل تسجيل: مسار توفير OAuth أو تفاعل صيغة مفتاح تلميح (مفتاح مفتاح دخول pi-ai ذاتي ذات تسجيل تسجيل تلميح، بينما غير ضبط جدول مفرد) ، نيل إلى اعتماد تخزين في harness اعتماد تخزين `llm-pi-ai/<provider id>` سجل في. تخزين تسجيل تسجيل في ذلك توجيه `apiKeyEnv` تغطية لـ تحت إتمام إقرار إثبات، و في تخزين عبر عملية قفل تحت ذاتي سطر تحديث جديد؛ خروج تسجيل تسجيل أي حذف تخزين سجل. سقوط في سجل نص قاعدة خارج——صغير كتابة وصل محرف معرف رمز——يد عمل إعلان توجيه مفتاح لا يمكن تسجيل تسجيل، لأن مقابل هو سجل كتابة سوف بـ `LlmError('UNSTORABLE_PROVIDER_ID')` رفض؛ هذا صنف توجيه تعديل استخدام `apiKeyEnv` أو مزود ambient ضبط إقرار إثبات.

### تحليل نموذج دليل

profile `models` قائمة سوف استبدال بينما غير توسيع توجيه قد تثبيت دليل؛ كل بند من نفس id قد تثبيت نموذج أخذ لم ضبط حقل قيمة افتراضية، لذلك يأخذ توجيه استلام ضيق إلى اثنان عدد نموذج، إصلاح صحيح واحد سعة كمية أو إضافة مقارنة قد تثبيت دليل تحديث نموذج كل هو واحد سطر تحرير.`modelOverrides` بلا حاجة هذا بديل قيمة يكفي إعادة تشكيل عدد آخر قد تثبيت دليل نموذج——إصلاح صحيح واحد نموذج، إبقاء ذلك بقية ثلاثة عشرة سبعة عدد——عند هو و `models` قائمة و تخزين، يقع في يد عمل إعلان توجيه فوق، أو نقطة اسم دليل لم وصف نموذج وقت سوف يتم رفض، لأن ساكن صامت ثابت نموذج سوف يصبح آخر شخص يوم بعد بحث بحث تجميع كتابة خطأ.

### حمل دفع إدارة (reasoning) و بروتوكول توافق تشغيل

`reasoningEfforts` إعلان نموذج اختياري اختيار thinking انتظار درجة: كل مفتاح كل هو اختيار جهاز توفير انتظار درجة، ذلك قيمة هو قسم إرسال وقت في بروتوكول في إرسال تجميع كتابة، لذلك `max: ultra` يمكن لـ يملك ذاتي لديه مفردات شبكة صلة إعادة تسمية انتظار درجة. حذف هذا حقل وقت إبقاء قد تثبيت دليل بند قدرة؛`false` إعلان غير دفع إدارة نموذج. مقابل في pi-ai لا يمكن تعرف آخر طرف نقطة،`compat` فتح صلة إعادة تشكيل طلب——أي عدد زاوية لون يحمل توجيه النظام، أي عدد حقل حد إخراج،thinking انتظار درجة مثل أي نقل تمرير——يمكن تدريجي توجيه، تدريجي نموذج إعداد. بند و قد تثبيت دليل كل لا يوجد مقياس قياس نموذج، سوف اعتماد توجيه `defaultContextWindow` و `defaultMaxTokens` رجوع قيمة.

مقابل في ذاتي حمل إدارة Chat Completions طرف نقطة،`thinkingTokenBudgetField` اختيار دفع إدارة ميزانية معامل،`vllmPriority` في خدمة طرف تفعيل أولوية درجة ضبط درجة وقت ضبط كامل عدد ضبط درجة أولوية درجة. نموذج لوح معامل قبول `$var: thinking.budget`.`openai-responses` شبكة صلة يمكن ضبط `supportsMaxOutputTokens: false` قدوم حذف `max_output_tokens`؛Azure و Codex نقل سوف تجاهل اختصار هذا عدد مشترك توافق حقل. هذه تحكم متساو يحتاج صريح تفعيل؛ دليل يملك Anthropic effort و رجوع قدرة لا هو يمكن إعداد فتح صلة.

### وقت التشغيل أكثر تعديل إعداد

profile عبر اختياري settings seam كل مرة عملية إعادة قراءة:base و مستخدم `llm-pi-ai:` ضبط قسم عقدة حسب مزود دمج، لذلك مستخدم يمكن إضافة جديدة توجيه، تغطية تركيب توجيه واحد حقل أو يأخذ توجيه إشارة نحو آخر عدد بديل إدارة، الكل في تحت واحد طلب توليد فاعلية، بلا حاجة إعادة بدء. مهايئ لا يمكن خدمة قسم عقدة سوف في كتابة موضع يتم رفض——`settings.mutate` عودة جواب `settings-rejected`——بعد بطلان قد تخزين قسم عقدة سوف إبقاء namespace الأكثر بعد صالح قيمة. عند توجيه تجميع دمج أو بعض توجيه إعادة محاولة سياسة تغير وقت، إضافة سوف أصل فرعي أرض إعادة تسجيل: اندفاع مفاجئ توجيه سوف يجعل هذا قبل توجيه متابعة خدمة.

### من طرف نقطة اكتشاف نموذج

إضافة سوف عودة جواب «هذا مزود يمكن توفير أي بعض نموذج؟» ، توفير إعداد واجهة جارٍ تحرير أو بدء مسودة توجيه استخدام. قد تثبيت دليل توفير توجيه مباشر من دليل عودة جواب، لا إرسال شبكة طلب، و سوف ذلك `input` عدد مجموعة إبقاء لـ اكتشاف نتيجة `inputModalities`؛ فقط لديه دليل لم وصف توجيه عندئذ سوف مرور شبكة استفسار سؤال.`openai-completions` و `openai-responses` استخدام حمل bearer تمييز حق `GET {baseURL}/models`،`anthropic-messages` فإن بـ `x-api-key` و `anthropic-version` استخدام أصلي `GET /v1/models?limit=1000` دلالة؛ ذلك قائمة URL قبول حمل أو لا حمل نهاية ذيل `/v1` API أصل عنوان، لأن شبكة صلة وثيقة اثنان نوع كتابة قاعدة كل سوف إصدار، كما فقط لديه هذا قائمة URL سوف عودة واحد تحويل هذا واحد مقطع، نموذج طلب استلام إلى ما زال هو إعداد أصل مثال `baseURL`. قد إعداد كما أداة اسم توجيه سوف في Host داخلي توفير قد تخزين اعتماد و profile `headers`، لذلك عبر `settings.yaml` أو Cordis إعداد ضبط نشر علامة رأس يمكن وصول نموذج اكتشاف طلب، لكن لن يصبح اكتشاف طلب أو Models صفحة حقل؛ جدول مفرد في جديد مفتاح دخول مفتاح ما زال أولوية في قد تخزين اعتماد. محلل قبول معيار `data` عدد مجموعة أو غني معلومة `models` كائن، و عودة واحد تحويل كل مرشح id، عرض اسم، سياق نافذة و الأكثر كبير إخراج token عدد؛Anthropic `max_input_tokens` و `max_tokens` سوف دخول نفسه سعة كمية حقل، أي جعل كائن بند نقطة اسم آخر عدد مواصفة id، كائن مفتاح ما زال هو طلب id، أصلي نوع كائن خاصية سوف يتم تجاهل اختصار، ناقص عرض اسم فإن رجوع إلى هذا طلب id. عودة جواب هو واجهة يمكن توفير إعطاء مستخدم قبول مرشح بيانات وصفية——لا تخزين أي محتوى،`settings.yaml` ما زال هو قرار توجيه خدمة محتوى وحيد واقع.

### فشل و استعادة

pi-ai لا توفير توجيه حاجة `api`،`baseURL` و غير فارغ `models` قائمة؛ لا يمكن خدمة profile سوف في كتابة موضع يتم رفض، و نقطة اسم توجيه و نموذج. فشل يحمل مستقر code: لا يمكن استخدام اعتماد بـ `INVALID_CREDENTIAL` فشل و نقطة اسم توجيه و مرجع،`apiKeyEnv` مرجع تحليل لـ فارغ توجيه بـ `MISSING_CREDENTIAL` فشل، لم إعداد نموذج بـ `UNKNOWN_MODEL` فشل، إنهاء صفة مزود فشل فإن منطقة قسم `QUOTA` و مؤقت وقت صفة `RATE_LIMIT`.`GenerateOptions.stop` بـ `UNSUPPORTED_OPTION` يتم رفض، لأن pi-ai عام تدفق صيغة UI لا يمكن عبر مزود حفظ إثبات هو.

Settings كتابة سوف في دمج تركيب طبقة و مستخدم طبقة بعد صارم إطار تحقق كل إضافة جديدة أو تعديل مزود. نطاق الأسماء تسجيل وقت، قد تخزين إعداد دليل تحليل خطأ سوف إبقاء نطاق الأسماء و مزود سطر، و عبر `LlmConfigurableProvider.error` أولوية إرجاع أول عدد نموذج تشخيص، بلا نموذج تشخيص وقت إرجاع توجيه خطأ؛ لم تعديل خطأ مزود لن منع توقف أخرى تحرير. يمكن تحليل نموذج ما زال اختياري اختيار، لا يمكن تحليل نموذج إبقاء في يمكن تحرير إعداد في، مباشر طلب وقت سوف في شبكة I/O قبل بـ `INVALID_CONFIG` فشل. إصلاح أو حذف خطأ إعداد سوف صاف حذف تشخيص.Schema و profile ذاته قيد خطأ ما زال سوف رفض تحميل. لاحق خارجي ملف تحرير سوف تحقق تغير مزود، فشل وقت إبقاء الأكثر بعد مرة قبول قسم عقدة.

فقط تعديل `displayName`،`apiKeyEnv` أو `baseURL` بينما لم حل قرار مزود نموذج إعداد خطأ وقت، حفظ ما زال سوف يتم رفض. مثال مثل،OpenRouter توجيه نموذج `111` نقص قليل `api` وقت، لا يستطيع مفرد وحيد حفظ توجيه اسم تعديل: حاجة في نفس نسخة تحرير مسودة مسودة في إصلاح أو حذف هذا نموذج، مجددا حفظ كامل مزود إعداد. في بين إصلاح حالة إبقاء في مسودة مسودة في، مباشر إلى كامل بند مزود إعداد عبر تحقق؛ أخرى مزود يمكن مستقل حفظ.

## فهم التنفيذ

<details>
<summary>تنفيذ دقيق عقدة——انقر للتوسيع</summary>

هذا عقدة حل تفسير مهايئ خلف بعد تصميم؛ يمكن مراقبة سلوك قد في[استخدام هذه الحزمة](#use-this-package) في كامل شرح.

### تصميم إدارة فكرة

مهايئ بناء قيام في غير ممكن تغيير لقطة و حسب عملية تحليل لـ فوق. كل عملية كل سوف في رقم مرة `await` قبل التقاط كامل لقطة——profile إضافة واحد يحتفظ كل بند توجيه الذي بناء `Provider` `createModels()` تجميع دمج——إعداد تغيير سوف بناء جديد تجميع دمج بينما غير تعديل استخدام في تجميع دمج، لذلك في واحد إعداد تحت بدء طلب أبدا سوف في آخر عدد إعداد تحت انتهاء. توجيه ذاتي ذات اعتماد مرجع مرور harness seam تحليل، و بـ طلب `apiKey` خيار نقل دخول،pi-ai سوف ذلك نظر لـ أولوية درجة الأكثر عال auth تغطية——هذا صحيح هو واضح فشل مرجع دلالة الذي في. هذا تغطية لم تغطية واحد قطع كل مرور تجميع دمج ذاته auth وصول pi-ai: اعتماد تخزين يحتفظ تسجيل تسجيل كتابة، تحديث جديد جولة تبديل سجل (بـ `llm-pi-ai/<provider id>` بحث عنوان) ،auth context عودة جواب مزود تحليل وقت رفع خروج ambient مشكلة. اثنان من عبر لقطة إبقاء مستقر، لذلك إعداد تغيير إعادة بناء تجميع دمج وقت لن نسيان تسجيل من قد تسجيل تسجيل. وقت التشغيل import استخدام pi-ai provider،API و utility مدخل؛`src/models.ts` توفير هذا مهايئ الذي يحتاج قليل كمية model helper، بينما لن طلب قيمة pi-ai تجمع دمج مدخل.

### تسجيل و دليل

إضافة سوف في يمكن إعداد مزود دليل في إعلان هو قدرة إقرار إثبات كل قد تثبيت دليل مزود، و إضافة دخول حالي profile إعلان كل بند توجيه، لذلك إعداد واجهة يمكن في أي توجيه وجود قبل توفير كامل دليل. كل بند كل يحمل `declared`——pi-ai هل في هذا مفتاح تحت لا توفير أي محتوى——لأن فقط لديه مهايئ قدرة منطقة قسم يد عمل إعلان توجيه و استلام ضيق دليل توجيه. توجيه تسجيل أداة لديه أصل فرعي صفة: و أخرى مهايئ اندفاع مفاجئ مرشح تجميع دمج سوف يجعل هذا قبل توجيه متابعة خدمة. صفر توجيه عار تركيب أي راحة نوم وضع حالة:settings قسم عقدة توفير profile قبل لا تسجيل أي محتوى، قسم عقدة صاف فارغ وقت توجيه مع لـ إزالة فقد.

### إعادة تشغيل و مفردات

نجاح assistant استجابة سوف تخزين حمل إصدار، بلا ضرر JSON إعادة تشغيل حالة، و إنتاج هو جمع مزود و نموذج وضع في واحد بدء——استجابة درجة واقع إضافة كل تدفق صيغة كتلة واحد بند تدريجي كتلة بند. طلب وقت،`LlmRuntime` فقط عند نفس مهايئ نسخة يملك اثنان بند توجيه وقت عندئذ نقل تمرير إعادة تشغيل حالة؛ مهايئ تحقق هو و استعادة أصلي استجابة id، مزود توقيع و اختياري `providerThinkingLevel` effort بيانات وصفية، ناقص effort بيانات وصفية ما زال إبقاء ناقص. إعادة تشغيل سوف مقابل وفق assistant مصدر تحقق طلب نموذج هوية، و في مزود تحليل آخر اسم أو رجوع وقت مفرد وحيد استعادة Anthropic استجابة نموذج. لا يمكن استخدام حالة سوف تخفيض لـ مزود غير متصل محتوى بينما لا هو يجعل طلب فشل.pi-ai استدعاء الأداة معامل هو تحليل بعد كائن، لذلك مهايئ تحليل إدخال و إعادة نص تحويل إخراج، بـ رمز دمج harness أصلي JSON اتفاق؛pi-ai تدفق داخل خطأ حدث خريطة لـ إنهاء `finish` قسم قطعة.

</details>

<a id="model-experience"></a>
## تجربة النموذج

### مرور pi-ai مزود طلب

#### نموذج يرى ماذا

الذي اختيار دليل نموذج سوف استلام إلى واحد بند توجيه النظام (`GenerateOptions.system`، لا فإن أخذ تاريخ في أول بند `system` رسالة نص؛ أول بند system رسالة نص لـ فارغ وقت لا إرسال توجيه النظام) ، ذلك بقية تاريخ، أداة و pi-ai عام تدفق صيغة API دعم حمل أخذ مثال حقل. كل ورقة إبقاء صورة قبل كل سوف لديه نص، ملاحظة واضح ذلك كامل مرفق عنصر id و فعلي طلب مقياس قياس. حالي تنفيذ نظام الملفات يمكن خريطة مرفق عنصر مزود مضيف كائن وقت، هذا نص أيضا سوف يحمل فقط قراءة مواصفة تحويل كائن مسار، و تحذير إبلاغ مواصفة تحويل أو طلب إسقاط ممكن تقليص وضع أو إعادة تحرير رمز فوق نقل محتوى. سجل في صورة حذف قرار اختيار في كل ظهور موضع كل سوف في استبدال نص في إبقاء ذاتي ذات هوية و حالي قد تحليل وصول طريقة، ذلك مواصفة تحويل مرفق عنصر لن قراءة أو تغيير تبديل. عند إبقاء ظهور موضع حسب دقيق base64 تحميل حمل ما زال تجاوز مرور توجيه `maxRequestImageBytes` وقت، استدعاء بـ `IMAGE_OFFLOAD_REQUIRED` فشل، من `dsh-compaction-image-offload` استخدام `image/offload` حدث سجل الذي اختيار موضع و إعادة محاولة خطوة. مزود أصلي إعادة تشغيل بيانات وصفية فقط في مهايئ إبرة مقابل تاريخ محتوى تحقق عبر بعد استعادة.

#### Token أثر

مزود قسم كلمة قرار دقيق إدخال. إبقاء صورة سوف إضافة مستقر مرفق عنصر و جلوس علامة وصف رمز؛ إزالة احتلال موضع رمز سوف بديل حذف صورة نظر شعور token. إعادة تشغيل بيانات وصفية ممكن يجعل أصلي API إعادة استخدام مزود جانب حالة.

#### KV Cache أثر

تحويل إبقاء منطق طلب ترتيب، صورة جملة مقبض و إزالة احتلال موضع رمز فإن سوف إضافة نموذج مرئي نص. أي جعل مرفق عنصر هوية و طلب بايت إبقاء مستقر، تنفيذ عالم حد مسار تغير أيضا سوف تعديل كتابة تاريخ جملة مقبض، و ممكن من هذا صورة بدء منع توقف إعادة استخدام. أكثر تبديل مهايئ نسخة، مزود، نموذج أو أخرى فوق تنقل token أداة لديه نفسه بعد لاحقة أثر. مرة حذف قرار سوف يأخذ مقارنة مبكر صورة تبديل صار احتلال موضع نص، لذلك إعادة استخدام في هذا رسالة موضع انتهاء؛ حذف دائم لا رجوع، هذا بعد بادئة إبقاء مستقر.

### مزود استجابة

#### نموذج يرى ماذا

pi-ai حدث تغيير صار harness دفع إدارة، نص، استدعاء الأداة، استخدام كمية و finish قسم قطعة. مهايئ يأخذ تحليل بعد أداة معامل بـ أصلي JSON نص نقل إعطاء harness.

#### Token أثر

توليد محتوى فقط في loop سجل بعد عندئذ أثر لاحق إدخال. مزود لم مفرد وحيد تقرير إبلاغ دفع إدارة token وقت،pi-ai سوف يأخذ دفع إدارة token و دخول إخراج استخدام كمية، و أصل مثال إبقاء ذلك دقيق `totalTokens` قيمة.

#### KV Cache أثر

قد سجل استجابة محتوى سوف إلحاق إلى تحت واحد طلب، لن جعل ذلك أكثر مبكر يمكن إعادة استخدام بادئة بطلان. لم سجل نقل بيانات وصفية و استخدام كمية حساب كمية لا أثر ذاكرة مؤقتة معرف.

## حدود معروفة وعمل مؤجل

<a id="known-limitations-and-deferred-work"></a>


هذه حد شرح مهايئ في أي داخل إيقاف، من لم قدوم عمل وصل متابعة. هو جمع هو حالي حزمة قيد، لا هو عام pi-ai مقابل مقارنة أو مهمة تراكم ضغط.

- **`maxRequestImageBytes` فقط حساب حساب base64 صورة تحميل حمل**، نص، أداة، وصف رمز و JSON بنية في هذا حد أعلى خارج، لذلك هو يجب إبقاء لديه بقية كمية أرض منخفض في شبكة صلة طلب جسم حد أعلى.
- **تسجيل تسجيل فقط وجود في إرسال بدء هو عملية في**——تخويل محاولة تجربة لا حمل دائم، لذلك تسجيل تسجيل في طريق تحديث جديد صفحة سوف وضع ترك هو، مستخدم حاجة إعادة بدء. خروج تسجيل تسجيل هو مقابل قد تخزين سجل تنفيذ `deleteRecord`، فقط في محلي نسيان تسجيل هو، لن إبلاغ معرفة توقيع إرسال جهة.
- **مزود أصلي اكتشاف مرور هذا إضافة ambient context عودة جواب**——لا نقطة اسم اعتماد توجيه تسليم من دليل مزود ذاته تحليل، هو سوف استفسار سؤال بيئة قيمة (`AZURE_OPENAI_API_KEY`،`AWS_PROFILE` و كل مزود ذاتي لديه تجميع دمج) و محلي اعتماد ملف. اثنان عدد مشكلة كل في هذا داخل نيل إلى عودة جواب: اعتماد seam أولا في عملية بيئة يتم استعلام، ملف وجود فإن إبرة مقابل مضيف عملية نظام الملفات بـ `~` توسيع بعد فحص. هو فعل لا إلى هو*قراءة*اعتماد ملف محتوى——ذاتي سطر تحليل `~/.aws/credentials` مزود سوف مباشر قراءة، لا مرور هذا seam.
- **ضبط يمكن إضافة جديدة أو تغطية توجيه، لا يستطيع إزالة تركيب توجيه**——مستخدم طبقة تغطية تركيب base، لذلك حذف `cordis.yml` توفير مزود يخص تركيب تغيير.
- **قسم طبقة دمج مقابل حرف قاموس مفتاح لا يوجد حذف**——base إعلان `reasoningEfforts` انتظار درجة،`modelOverrides` بند أو `compat` حقل يمكن يتم مستخدم طبقة تغطية، لكن لا يستطيع يتم إزالة.
- **`headers` يمكن يحمل redactor دائم بعيد نظر لا إلى اعتماد**——profile تحليل سوف رفض Fetch لا يمكن يمثل اسم و قيمة، لكن هذا حرف قاموس ما زال هو صاف نص؛ بـ `apiKeyEnv` مرجع تخزين اعتماد.
- **توجيه دليل لن ذاتي سطر تحديث جديد**——دليل حينئذ هو `settings.yaml` محتوى؛ هذا داخل لا يوجد أي آلية نحو مزود استعلام هو توفير نموذج.
- **Anthropic نموذج اكتشاف الأكثر كثير قراءة 1,000 عدد نموذج**——طلب استخدام API الأكثر كبير صفحة كبير صغير، لكن لن مرة تاريخ `has_more`؛ رقم واحد صفحة خارج بند حاجة يد عمل إضافة.
- **كل بند توجيه واحد نوع بروتوكول صيغة**——خلط دمج بروتوكول دليل توجيه لا يمكن تحمل تحميل آخر بروتوكول صيغة نموذج؛ يأخذ مزود تفكيك إلى اثنان عدد توجيه مفتاح هو تغيير عبر إنجاز قاعدة.
- **نموذج حالة إعلان لا تلقي تحقق**——إعلان `image` بينما ذلك شبكة صلة لا دعم حمل نموذج سوف في نص التوجيه دقيق دخول بعد يتم مزود رفض. حمل دائم صورة ما زال إبقاء في تاريخ في، نفس خطأ إعلان نموذج ممكن مجددا مرة فشل؛ تبديل إلى صاف نص نموذج ما زال يمكن سطر، لأن مشترك LLM وقت التشغيل سوف إبرة مقابل هذا طلب يأخذ صورة مرجع إسقاط لـ مستقر نص.
- **لم إقرار إثبات توجيه أخذ قرار في ذلك بروتوكول**——لا نقطة اسم اعتماد توجيه تحليل لـ قد إعداد لكن بلا مفتاح، لكن pi-ai OpenAI توافق تنفيذ ما زال اشتراط API مفتاح أو `Authorization` علامة رأس، لذلك بلا مفتاح محلي خادم حاجة من `apiKeyEnv` مرجع أو `headers` في `Authorization` بند توفير احتلال موضع اعتماد.
- **لا دعم حمل `GenerateOptions.stop`**——pi-ai عام تدفق صيغة خيار لا يمكن عبر مزود حفظ إثبات إيقاف تسلسل سلوك.
- **فقط لديه تاريخ في أول بند `system` رسالة سوف يصبح pi-ai `systemPrompt`**——pi-ai فقط لديه واحد نظام مجرى موضع، لذلك لاحق `system` رسالة، أو في معا ضبط `GenerateOptions.system` وقت أول بند رسالة، سوف في أصل موضع طي لـ `user` رسالة؛ توجيه النظام مزود مخصص تابع وضع وضع التزام دوران pi-ai، بينما غير harness ذاتي لديه بروتوكول تغطية.system أو assistant تاريخ في صورة (يشمل أول بند نظام رسالة في صورة) في اثنان بند تحويل مسار فوق كل سوف بـ `UNSUPPORTED_CONTENT` فشل.
- **مزود HTTP حالة غير ممكن استخدام**——pi-ai خطأ حدث لا عبر مزود كشف مستقر HTTP حالة.
- **إعادة محاولة سياسة من مزود ذاتي لديه، بينما غير SDK إعادة محاولة**——pi-ai SDK إعادة محاولة إبقاء منع استخدام، لذلك حمل دائم agent(ذكي جسم) خطوة و `llm/retry` حدث يملك كل مرئي محاولة تجربة، مباشر `ctx.llm.stream()` استدعاء ما زال هو مفرد مرة محاولة تجربة.

### ملاحظة تطوير

</details>
