# @deepseek-ai/dsh-llm-retry

[English](README.md) | العربية

## عام وصف

تركيب `@deepseek-ai/dsh-llm-retry`، يمكن في حمل دائم agent خطوة حد إعادة محاولة فشل نموذج طلب. مزود `retryPolicy` ضبط اختياري اختيار محدود normal mode إعادة محاولة أو بلا حد أعلى always mode إعادة محاولة؛ خطة محاولة تجربة سوف في تراجع تجنب قبل كتابة جلسة سجل، إلغاء بعد تاريخ ما زال إبقاء متسق. إعادة محاولة سوف في نفس عدد فتح جولة داخل إعادة ركض فشل خطوة، بينما مباشر `ctx.llm.stream()` استدعاء ما زال فقط محاولة تجربة مرة. كل مرة إعادة محاولة كل سوف إنتاج آخر مرة مزود طلب حساب استهلاك،always mode سوف حمل متابعة إلى نجاح، إلغاء أو تحرير.

## استخدام هذه الحزمة

عند agent تشغيل ينبغي من مؤقت وقت صفة نموذج طلب فشل——سرعة معدل حد، خدمة طرف خطأ، مهلة، نقل خطأ——في استعادة بينما لا هو انتهاء جولة وقت، تركيب هذا إضافة. هو هو منفذ: إعادة محاولة سياسة ذاته يقع في كل مزود مهايئ إعداد فوق، هذه الحزمة لا يوجد أي ذاتي ذات إعداد.

### أي وقت اختيار

عند تركيب تشغيل agent loop(ذكي جسم حلقة) و حاجة حمل دائم طلب استعادة وقت اختيار هو. هذا إضافة هو بلا إعداد دالة إضافة؛`dsh-llm-deepseek` و `dsh-llm-pi-ai` انتظار مزود مهايئ يملك كل منها توجيه `retryPolicy`، كثير مزود مهايئ يأخذ هو وضع دخول كل provider profile. عند استدعاء لا مرور agent loop، مباشر مشي `ctx.llm.stream()` وقت قفز مرور هو: هذه مستهلك ما زال هو مفرد مرة محاولة تجربة، لأن أصلي تدفق لا يمكن حمل دائم أرض منطقة قسم قد إرسال خروج قسم قطعة.

### الأكثر صغير إعداد

```yaml
- name: '@deepseek-ai/dsh-llm-deepseek'
  config:
    apiKeyEnv: DEEPSEEK_API_KEY
    retryPolicy:
      mode: always
      backoff:
        initialDelayMs: 1000
        maxDelayMs: 30000
        jitterRatio: 0.2

- name: '@deepseek-ai/dsh-llm-retry'
```

حذف `retryPolicy` وقت استخدام normal mode: مقابل `EMPTY_RESPONSE`،`RATE_LIMIT`،`SERVER`،`TIMEOUT` و `TRANSPORT` الأكثر كثير إعادة محاولة خمسة مرة، تراجع تجنب من 500 مللي ثانية إلى 10 ثانية، حمل 10% اهتزاز حركة.normal mode يمكن أكثر تعديل ذلك محدود ميزانية، دمج إطار code و تراجع تجنب؛always mode أولا استفسار سؤال تحت تنقل استعادة، لكن بعد بلا محاولة تجربة حد أعلى أرض إعادة محاولة كل نموذج طلب فشل، فقط في نجاح، إلغاء أو إضافة تحرير وقت إيقاف.

### أنت يمكن مراقبة إلى ماذا

كل مرة خطة إعادة محاولة في انتظار قبل حينئذ هو حمل دائم: إضافة سوف أولا إلحاق يحمل إعادة محاولة id، مزود، نمط، سياسة مفتاح، فشل و خطة تأخير متأخر غير جدول طبقة `llm/retry` حدث، لكن بعد في إعادة محاولة بدء قبل قيام أي إلحاق `llm/retry-started` حدث. مزود إعطاء خروج كما رمز دمج سياسة حد صالح `Retry-After` سوف استبدال محلي تراجع تجنب. انتظار إتمام بعد،loop سوف في نفس عدد فتح جولة داخل إعادة ركض فشل خطوة، ما زال أساس في نفس نسخة حمل دائم تاريخ، لذلك إعادة محاولة طلب و أصلي طلب واحد مثال يمكن من جلسة سجل إعادة بناء. إلغاء أو إضافة تحرير سوف في توقف إجراء في تراجع تجنب، انتظار نشط وثب تفويض إرسال استعادة تسوية، و جعل تحرير قبل التقاط عودة ضبط فقط قدرة بـ فشل انتهاء.

### فشل و استعادة

في أي نهائي مهايئ يتم اختيار في قبل حدوث فشل لا يوجد مزود سياسة، أصل مثال تفويض إرسال تحت تنقل.normal mode في، لا في دمج إطار تجميع دمج داخل فشل code أو قد استهلاك كل ميزانية سوف تفويض إرسال؛always mode في، تجاوز حد أعلى مزود تأخير متأخر استخدام إعداد محلي تراجع تجنب، لذلك سياسة لن بسبب هذا إشارة أمر إنهاء. هذا داخل لا يوجد أي نموذج مرئي محتوى: إعادة محاولة حدث، تأخير متأخر، مزود خطأ أو فشل جزء إخراج كل لن وصول نموذج أو إرسال توليد رسالة.

## فهم التنفيذ

<details>
<summary>تنفيذ دقيق عقدة——انقر للتوسيع</summary>

هذا عقدة حل تفسير منفذ خلف بعد تصميم؛ يمكن مراقبة سلوك قد في[استخدام هذه الحزمة](#use-this-package) في كامل شرح.

### تصميم إدارة فكرة

منفذ بناء قيام في واحد بند قاعدة تحديد لـ فوق:**أولا حمل دائم، بعد انتظار، فتح خطوة حد.** أي تحديد وقت جهاز بدء قبل، إعادة محاولة حينئذ قد عبر جلسة سجل خطة، لذلك انهيار انهيار أو إلغاء دائم بعيد لن إبقاء تحت غير ممكن رؤية انتظار معالجة إعادة محاولة. استعادة تشغيل في agent loop `agent/request-error` waterfall(شلال نشر صيغة حدث) ، أي فتح خطوة نقطة توسيع فوق، بينما لا هو حزمة تركيب `ctx.llm.stream()`——أصلي تدفق لا يمكن حمل دائم أرض منطقة قسم قد إرسال خروج قسم قطعة، بينما loop يمكن في نفس عدد فتح جولة داخل إعادة ركض فشل خطوة.

### شفرة المصدر أرض رسم

| ملف | مسؤولية |
|---|---|
| [`src/index.ts`](src/index.ts) | دالة إضافة:waterfall مستمع، سياسة فحص بحث، تراجع تجنب، حمل دائم حدث إلحاق |
| [`src/history.ts`](src/history.ts) | من جلسة سجل فحص بحث حمل دائم إعادة محاولة تاريخ |

### استعادة مسار

فشل خطوة وصل نفس ذلك مزود و تحليل بعد سياسة واحد بدء وصول waterfall.always mode أولا تسوية تحت تنقل استعادة، و التزام دوران تحت تنقل `retry` قرار؛normal mode أولا فحص فشل code هل دمج إطار، ميزانية هل لم استهلاك كل. إضافة حساب حساب تأخير متأخر——صالح كما في حد داخل مزود `Retry-After`، لا فإن حمل مقابل تسمية اهتزاز حركة محلي محدود إشارة عدد تراجع تجنب——إلحاق `llm/retry` حدث، في يمكن إلغاء تحديد وقت جهاز فوق انتظار، إلحاق `llm/retry-started`، لكن بعد إرجاع `{ kind: 'retry' }`.loop مع بعد في نفس عدد فتح جولة داخل إعادة ركض فشل خطوة (ما زال أساس في نفس نسخة حمل دائم تاريخ).

### Waterfall تركيب

هذا إضافة هو `agent/request-error` waterfall في واحد مستمع.always mode "تحت تنقل أولوية"وضع حالة معنى طعم حال، بعد تجاهل اختصار إلغاء كما دائم لا تسوية سياسة أيضا سوف منع توقف رجوع، جولة تماما توقف مستقر و إضافة تحرير إتمام؛ نجاح، إلغاء أو تحرير سوف في نشط حركة تفويض إرسال استعادة بلوغ إلى تماما توقف مستقر بعد إيقاف always mode.

## بحث إضافي

عند حزمة درجة اتفاق لا كاف استخدام وقت قراءة قراءة التالي صفحة. هو جمع من خدمة اتفاق تدريجي خطوة دخول يملك إعادة محاولة سياسة مهايئ.

- [llm-pi-ai مهايئ](../llm-pi-ai/README.ar.md)——حمل تدريجي profile `retryPolicy` كثير مزود مهايئ.

<a id="model-experience"></a>
## تجربة النموذج

### نموذج طلب استعادة

#### نموذج يرى ماذا

إعادة محاولة حدث، تأخير متأخر، مزود خطأ أو فشل جزء إخراج كل لن مقابل نموذج مرئي. حذف غير تحت تنقل استعادة سياسة لحظة معنى تغيير هذا جدول طبقة، إعادة محاولة خطوة سوف من حمل دائم جدول طبقة تاريخ في إعادة بناء نفسه صريح مزود/نموذج طلب؛ فشل قسم قطعة أبدا دخول إرسال توليد رسالة.

#### Token أثر

كل مرة إعادة محاولة كل هو مرة جديد مزود طلب، ممكن تكرار إدخال token حساب استهلاك.normal mode لديه محدود ميزانية؛always mode في نجاح أو إلغاء قبل ممكن إزالة استهلاك بلا حد أعلى طلب.`llm/retry` ذاته لا مساهمة أي token.

#### KV Cache أثر

إعادة بناء طلب إبقاء هذا قبل بادئة، لديه مورد إطار حسب هذا مزود قاعدة إعادة استخدام مزود ذاكرة مؤقتة. غير جدول طبقة إعادة محاولة حدث لا تغيير ذاكرة مؤقتة معرف.

## حدود معروفة وعمل مؤجل

<a id="known-limitations-and-deferred-work"></a>


هذه حد شرح منفذ في أي داخل إيقاف، من لم قدوم عمل وصل متابعة. هو جمع هو حالي حزمة قيد، لا هو عام إعادة محاولة مقابل مقارنة أو مهمة تراكم ضغط.

- **agent جولة هو وحيد إعادة محاولة حد**——مباشر `ctx.llm.stream()` مستهلك ما زال هو مفرد مرة محاولة تجربة، لأن أصلي تدفق لا يمكن حمل دائم أرض منطقة قسم قد إرسال خروج قسم قطعة.
- **always mode سوف إعادة محاولة دائم دائم صفة فشل**——إقرار إثبات، إعداد مقدار، بلا فاعلية طلب، بروتوكول و غير ممكن استعادة سياق خطأ سوف حمل متابعة إلى نجاح، إلغاء أو تحرير؛ نشر جهة مسؤول مزود مخصص تابع صار هذا و تأخير متأخر تحكم.
- **محدود إضافة ميزانية متبادل إضافة**——normal mode فقط موحد حساب ذلك إعداد code و دقيق مزود سياسة، بينما سياق فيض خروج ضغط (compaction) يملك مستقل ميزانية. أي إعادة تراكم سياسة كل يجب تعريف تسجيل ترتيب سلوك.
- **استعادة سياسة حسب waterfall ترتيب تركيب**——always mode أولا قبول تحت تنقل إعادة محاولة، مجددا تطبيق ذلك رجوع. بعد تجاهل اختصار إلغاء كما دائم لا تسوية سياسة أيضا سوف منع توقف رجوع، جولة تماما توقف مستقر و إضافة تحرير إتمام.
- **`llm/retry` سجل ضبط درجة، بينما غير إتمام**——لاحق خطوة و جولة حدث عندئذ تأكيد قيام نجاح، استهلاك كل أو إلغاء.

### ملاحظة تطوير

<details>
<summary>صيانة من عمل سياق——انقر للتوسيع</summary>

هذا ملاحظة تطوير هو لا أداة مرجعي صفة عمل سياق: صيانة من ملاحظة و فتح وضع مشكلة. قد تسليم سلوك و حيث تحديد إدارة من بـ فوق نص، حزمة شفرة و متبادل صلة Agent Note لـ دقيق.

- إعادة محاولة تحرير رقم فقط في نفس مزود و كامل سياسة مفتاح حدث بين تأخير متابعة، لذلك حد مقدار،code عضو أو تراجع تجنب مختلف توجيه استبدال سوف فتح بدء ذاتي ذات تاريخ؛ هذا مفتاح يتضمن كل أثر سلوك حقل، و بسبب مورد إطار حكم قطع استخدام تجميع دمج عضو بينما مقابل normal mode code ترتيب.
- مفرد وحيد إصدار `./invariant` مرافق توليد إضافة سوف مقابل وفق جلسة سجل تحقق كل مرة خطة إعادة محاولة——نقطة اسم حالي فتح جولة و الأكثر جديد إغلاق دمج خطوة، مطابقة فشل طلب حمل دائم مزود، و اشتراط كل `llm/retry-started` حدث نقطة اسم مرة حمل نفسه إعادة محاولة id، جولة، خطوة و إعادة محاولة تحرير رقم أولا قبل خطة محاولة تجربة.
