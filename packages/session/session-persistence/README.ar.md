# @deepseek-ai/dsh-session-persistence

[English](README.md) | العربية

## عام وصف

هذه الحزمة يجعل تطبيق عبر خلفية غير متصل API حمل دائم تخزين و استعادة جلسة حدث سجل. قراءة من يمكن إنشاء، فتح، فحص، صف خروج، إلحاق، قراءة، تحديث جديد و إغلاق قد تخزين جلسة، معا إبقاء وصل متابعة كما فقط إلحاق تاريخ سجل. فقط لديه إتمام flush عندئذ بنية صار حمل دائم صفة شاشة عائق؛ قراءة جهة لن استلام إلى تمزيق شق ذيل جزء أو بلا فاعلية سجل، و كما كل خلفية نسخة داخل كل جلسة فقط سماح واحد كتابة جهة. إذا أمل نظر كل جلسة استخدام واحد نسخة ضغط سجل، اختياري استخدام مع منتج تسليم [JSONL خلفية](../session-persistence-jsonl/README.ar.md) ؛ أيضا يمكن تنفيذ أداة تجهيز نفسه يمكن مراقبة حفظ إثبات أخرى خلفية.

## استخدام هذه الحزمة

تركيب واحد حفظ دائم خلفية يكفي يجعل جلسة حفظ دائم. خلفية يأخذ ذاتي ذات تسجيل لـ `ctx.sessionPersistence`، و يأخذ كل قد إصدار جلسة فوري حدث توجيه دخول هذا جلسة نشط وثب كتابة جملة مقبض؛agent-loop——جلسة في إنتاج بيئة في إصدار نقطة——في إصدار قبل نيل أخذ كل جلسة كتابة جملة مقبض، لذلك تركيب في أخرى جزء ثابت.

### اختيار خلفية

seam مع منتج تسليم [JSONL](../session-persistence-jsonl/README.ar.md) خلفية. هو لـ كل جلسة تخزين واحد نسخة فقط إلحاق `.jsonl.zstd` سجل. رقم ثلاثة جهة خلفية يمكن مباشر تنفيذ هذا خدمة؛ يجب التزام حراسة[خلفية اتفاق](#understand-the-implementation) رؤية تحت نص.

### خدمة توفير ماذا

تركيب خلفية بعد، خمسة عدد خدمة طريقة بحث عنوان قد تخزين جلسة:

```text
const handle = await ctx.sessionPersistence.create(header)     // store a new session, take write ownership
const handle = await ctx.sessionPersistence.open(id, 'write')  // claim single-writer ownership of an existing session
const reader = await ctx.sessionPersistence.open(id, 'read')   // observe without ownership
const snap = await ctx.sessionPersistence.stat(id)             // header + revision (+ eventCount / sizeBytes) without a log read
const all = await ctx.sessionPersistence.list()                // one snapshot per visible stored session
await ctx.sessionPersistence.flush()                           // backend-wide durability barrier over every active write handle
```

خدمة درجة `flush()` ترتيب فارغ كل نشط وثب كتابة جملة مقبض قد توجيه حدث و يأخذ ذلك جلسة فعلي جسم تحويل، فاعلية نتيجة و كل جملة مقبض ذاتي ذات `flush` تماما نفسه؛ فشل حسب جلسة تجمع دمج لـ واحد `AggregateError` بينما لا في طريق وضع ترك صاف مسح، صاف مسح طريق في يتم إغلاق جملة مقبض نظر نفس قد flush، لأن close ذاته سوف حمل دائم ترتيب فارغ.

كل مرة سجل قراءة كتابة كل تدفق مرور إرجاع `SessionHandle`؛ لا وجود حسب id بحث عنوان append أو load طريقة.`handle.read(offset?, length?)` إرجاع `{ eventState, events }`: خارج طبقة slice يخص استدعاء جهة،`eventState` فإن منطقة قسم من استدعاء جهة وحيد احتلال `detached` حدث رسم و ممكن معا يقع في خلفية ذاكرة مؤقتة في `shared-frozen` حدث رسم. هذا حالة من توليد جهة تحديد، أي جعل قطع قطعة لـ فارغ أيضا سوف إبقاء. اثنان نوع حالة كل قدرة مباشر وصل إدارة بينما بلا حاجة نسخ؛ حاجة متغير حدث مستهلك يجب أولا تغلب ضخم حدث. قراءة أبدا يتضمن تمزيق شق ذيل جزء، نفس جملة مقبض فوق تكرار قراءة أبدا سوف مراقبة إلى مقارنة أولا قبل قراءة أكثر قديم حالة، كتابة جملة مقبض أيضا قدرة قراءة إلى ذاتي ذات نجاح append.`handle.append(events)` إلحاق واحد وصل متابعة دفعة مرة، ذلك رقم واحد `seq` انتظار في قد تخزين next-seq؛ إتمام وقت حفظ دائم هو كل قوة بينما لـ——دفعة مرة يتم قبول، لديه ترتيب، و مقابل نفس خلفية نسخة فوق قراءة مرئي، فقط لديه إتمام `flush` عندئذ تحمل وعد هو في انهيار انهيار بعد اعتماد لكن وجود (تسليم JSONL خلفية تماما جيد سوف قيام أي حفظ دائم كل دفعة مرة).`handle.flush()` هو حمل دائم صفة شاشة عائق، معا يأخذ فارغ قد إنشاء جلسة فعلي جسم تحويل، جعل ذلك يمكن يتم حمل دائم صف خروج.`handle.close()` قوة انتظار كما غير ممكن إلغاء: قراءة جملة مقبض تحرير محلي مورد؛ كتابة جملة مقبض إتمام انتظار معالجة حفظ دائم و تحرير كتابة كل حق. واحد حالما بعض مرة `append` أو `flush` إتمام، ذلك بعد في نفس خلفية نسخة فوق بدء قراءة——بلا نقاش مرور من أي جملة مقبض، أيضا هو مرور من `stat`/`list`——حتى قليل قدرة مراقبة إلى هذا بادئة.

### كل حق و مرئي صفة

`create` و `open(id, 'write')` أخذ نيل عملية داخل مفرد كتابة من كل حق: في يحتفظ من نشط وثب خلال ثاني مرة بـ كتابة نمط فتح سوف بـ `SessionAlreadyOwnedError` رفض، مقابل قد احتلال استخدام id تنفيذ `create` سوف بـ `SessionAlreadyExistsError` رفض، في `read` جملة مقبض فوق تنفيذ تعديل سوف بـ `SessionReadOnlyError` رفض——واحد نوع جملة مقبض نوع، وقت التشغيل رفض. مقابل قد إغلاق جملة مقبض أي عملية سوف بـ `SessionHandleClosedError` رفض،`SessionOwnershipLostError` علامة كتابة كل حق قد دائم دائم فقد فقد كتابة جملة مقبض (إغلاق و إعادة فتح). قد إنشاء جلسة ذاتي `create` إتمام لـ لحظة بدء يكفي في هذا عملية داخل يتم مراقبة إلى، بينما خلفية يمكن يأخذ شيء إدارة فعلي جسم تحويل دفع متأخر إلى رقم مرة `append` أو `flush`؛ أخرى عملية فقط قدرة يرى قد فعلي جسم تحويل جلسة، واحد في انهيار انهيار قبل من لم فعلي جسم تحويل جلسة انتظار في من لم وجود.

### فوري كتابة مسار و إغلاق ترتيب فارغ

فوري كتابة مسار من خلفية ذاتي حمل: هو مرة صفة تثبيت جلسة مستمع، يأخذ كل قد إصدار جلسة حدث حسب id توجيه إلى هذا جلسة نشط وثب كتابة جملة مقبض——`session/event` نسخ دخول محدود داخلي دفعة معالجة نافذة،`session/flush` هو أي وقت حمل دائم صفة و خطأ مراقبة شاشة عائق،`session/disposed` تنفيذ نهائي ترتيب فارغ و إغلاق جملة مقبض. لا يوجد نشط وثب كتابة جملة مقبض قد إصدار جلسة لا فعل أي حفظ دائم. خلفية كتابة فشل وقت حسب ترتيب إبقاء ذلك حدث، مؤقت توقف تلقائي مسار و تسجيل دخول سجل؛ تحت مرة صريح flush سوف إعادة محاولة، و في مجددا مرة فشل وقت واضح إرجاع رفض.`close()` ذاته سوف أولا مرور من ما زال فتح تخزين ترتيب فارغ توجيه مؤقت اندفاع منطقة مجددا تحرير كل حق، لذلك أي سهل أصل fiber dispose(مورد تحرير) تزامن تشغيل كل fiber disposer، خلفية تفكيك إزالة وقت إغلاق صاف مسح أيضا قدرة حفظ إثبات تطبيق إغلاق لا فقد بيانات.

### استعادة و انهيار انهيار استعادة

حفظ دائم إرجاع شيء إدارة فوق صالح سجل؛ دلالة إصلاح يخص قراءة جهة. في طريق انهيار انهيار جلسة إبقاء ذلك لم إغلاق دمج نهائي جولة——مفرد عدد جولة ممكن جدا كبير، بينما هذه حدث في انهيار انهيار قبل قد حمل دائم إلحاق؛ فقط لديه من لم تأكيد تمزيق شق ذيل جزء في لا كامل تفتيت قطعة سوف يتم إسقاط——من في استعادة كامل سجل من كتابة مسار في جملة مقبض رقم مرة جديد append قبل حمل دائم إعادة كتابة. استعادة (agent-loop) عبر ذلك كتابة جملة مقبض قراءة قد تخزين سجل، حساب حساب `interruptedTurnClosers`——دمج صار `tool/result` خطأ، أي لم إغلاق دمج `step/end`، و `turn/end {interrupted}`——و يأخذ هو جمع بصفة عادي دفعة مرة عبر نفس جملة مقبض إلحاق. فقط قراءة مراقبة جهة (session-query) فقط في داخل تخزين في استخدام نفس مثال closer إعداد مستو يتم في قطع بارد سجل.

### فشل و استعادة

حالي بناء لا يمكن وفي فعلي حل قراءة تخزين سجل سوف يتم رفض، و إرجاع إشارة واضح رفض جهة نحو خطأ، أبدا سوف يتم خطأ قراءة.`SessionHandle` فقط كشف من `SESSION_FORMAT_VERSION` معرف حالي منطق سجل؛ مزود يجب في إرجاع جملة مقبض قبل تحويل أي تلقي دعم حمل تاريخ تخزين، مع منتج تسليم JSONL مزود سوف عبر ساكن حالة catalog ترحيل تلقي دعم حمل تاريخ بديل حد. تحديث صيغة سوف اشتراط عملية من ترقية harness. هذا بناء لا إقرار تعرف حدث نوع سوف يتم رفض، حذف غير ذلك معلومة غلاف علامة لـ `ignorable`؛ قد إيداع بادئة في ضرر تالف بـ `SessionPersistenceCorruptionError` رفض.

## فهم التنفيذ

<details>
<summary>تنفيذ دقيق عقدة——انقر للتوسيع</summary>

هذا عقدة شرح seam مثل أي تنفيذ حمل دائم تخزين و خلفية مثل أي وصل دخول؛ يمكن مراقبة اتفاق رؤية[استخدام هذه الحزمة](#use-this-package) و توليد [Cordis API](../../../docs/subsystems/persistence.ar.md#cordis-surface).

### تصميم إدارة فكرة

هذه الحزمة هو seam، بينما لا هو خلفية إطار هيكل: هو فقط توجيه خروج سحب كائن `SessionPersistence` خدمة،`SessionHandle` اتفاق، مستهلك التقاط مستقر خطأ صنف، صاف دالة تخزين سجل تحقق مساعد مساعدة (`storage-contract`) و حمل صنف لوحة نوع إصلاح حجز قيمة——مجددا بلا أخرى. كل مزود يملك ذاتي ذات كامل تخزين وقت التشغيل (جملة مقبض صنف، تعديل ترتيب ترتيب، مفرد كتابة من تسجيل حساب، فوري حدث توجيه، تفكيك إزالة) ،`tests/` تحت اثنان طقم مشترك اختبار طقم عنصر——`runPersistenceContract` و `runLiveWritePathContract`——ثابت كل مزود كل يجب متسق يمكن مراقبة سلوك. متعمد لـ لـ عاقبة: كل مزود في تخزين تماما جيد متبادل يشبه لـ موضع يمكن ذاك هذا متبادل مثل، لكن لا يوجد أي تنفيذ آلية عبر تجاوز حزمة حد.

### كل خلفية يجب التزام حراسة ثابت كمية

- **فقط إلحاق، وصل متابعة `seq`.** قد إيداع حدث أبدا إعادة كتابة؛`append` رقم واحد `seq` يجب انتظار في قد تخزين next-seq، نقص فتحة سوف يتم رفض.
- **تمزيق شق شيء إدارة ذيل جزء أبدا وصول قراءة جهة.** هو يخص مرة من لم إتمام append؛ كتابة مسار في رقم مرة جديد append قبل سوف ذلك حمل دائم قطع قطع.
- **بلا ضرر JSON بيانات.** دفعة مرة و header مرور مرور مشترك مفرد مرة تحقق و لقطة حد (`materializeAppendBatch`/`materializeCreateHeader`) ؛ لا يمكن تسلسل تحويل تحميل حمل في استدعاء موضع يتم رفض.
- **حمل دائم صفة.** `append` كل قوة بينما لـ أرض حفظ دائم؛`flush`——تدريجي جملة مقبض أو خدمة درجة——هو تحمل وعد تخزين و معا يأخذ فارغ جلسة فعلي جسم تحويل شاشة عائق.
- **لقاء إلى لم معرفة أو بلا فاعلية صيغة وقت رفض قراءة.** `validateStoredEvents` رفض لم معرفة حدث مفردات و قد ملغى ترك مسبق إصدار شكل؛`assertVersion` رفض خارج قدوم صيغة إصدار.
- **كل خلفية نسخة مفرد كتابة من.** مزود عملية داخل إقرار قيادة في `create`/`open('write')` وقت أخذ نيل، في جملة مقبض إغلاق وقت تحرير.

### كتابة مسار عام تصفح

كتابة جهاز جلسة كل `session/event` كل نسخ دخول هذا جملة مقبض داخلي مؤقت اندفاع. رقم واحد انتظار معالجة حدث فتح بدء ثابت دفعة معالجة نافذة؛ لاحق حدث إضافة دخول لكن لا إعادة وضع قطع توقف وقت. نافذة إلى مدة بعد مرور من جملة مقبض تعديل سلسلة ترتيب فارغ انتظار معالجة بادئة؛ ترتيب فارغ خلال وصل قبول حدث حسب ترتيب دمج دخول تحت واحد سلسلة فوق دفعة مرة.`session/flush` إلغاء انتظار و ترتيب فارغ حتى تماما توقف مستقر، مع بعد تشغيل `handle.flush()`، لذلك loop في تحت واحد جولة قبل يأخذ هو استخدام عمل ترتيب ترتيب و خطأ مراقبة فحص نقطة. فشل خلفية ترتيب فارغ إبقاء ذلك حدث و مؤقت توقف تلقائي حساب وقت جهاز؛ صريح flush، كتابة جهاز close أو خلفية تفكيك إزالة سوف قيام أي إعادة محاولة، و في مجددا مرة فشل وقت واضح إرجاع رفض. بنية صنع seed حدث أبدا إرسال خروج `session/event`، لذلك إصدار قبل عبر جملة مقبض إلحاق seed أبدا سوف يتم إعادة دخول طابور.

### تخزين سجل تحقق

seam مشترك مساعد مساعدة دالة تحقق من `SESSION_FORMAT_VERSION` معرف حالي منطق سجل،append فقط كتابة حالي صيغة ([إدارة من](../../../.agents/notes/implemented/architecture/2026-08-31-released-session-format-migrations.ar.md)). تاريخ حل رمز و غير ممكن تغيير بعد استمرار إصدار يخص كل مزود داخلي، و في ذلك إرجاع جملة مقبض قبل إتمام. كل خلفية كل في جملة مقبض قراءة و كتابة open مسبق حار وقت تشغيل `storage-contract` تحقق، يأخذ لم معرفة حدث نوع بصفة `SessionFormatUnsupportedError` رفض، يأخذ صيغة خطأ حالي سجل بصفة `SessionPersistenceCorruptionError` رفض، و في خلفية لـ كل جلسة إبقاء واحد نسخة ناتج وقت مرفق فوق أصلي سجل `SessionLocation`.

- [جلسة فحص نقطة سياسة](../session-checkpoint-policy/README.ar.md)——في دلالة حد فوق مرور من `session/flush` تحديث جديد إضافة.
- [جلسة حزمة خريطة](../README.ar.md)——متبادل مجاور حفظ دائم، إسقاط، عنوان و بعيد قياس حزمة.

### استعادة محادثة تاريخ

#### نموذج يرى ماذا

seam لا إضافة نص التوجيه أو schema. استعادة سوف سوف قد تخزين جدول طبقة حدث أيضا أصل لـ رسالة تاريخ؛ قد تخزين طلب header إعادة بناء مقارنة مبكر استدعاء، جديد loop فإن لـ تحت مرة طلب تركيب حالي توجيه النظام، أداة و جلسة بادئة. انهيار انهيار إصلاح سوف لا يوجد حمل دائم استدعاء assistant طلب علامة لـ `TOOL_NOT_STARTED`؛ لديه حمل دائم استدعاء لكن بلا نتيجة وقت تغيير لـ `TOOL_OUTCOME_UNKNOWN`، ذلك نص سماح نموذج إعادة محاولة فقط قراءة أو قوة انتظار عمل، لكن اشتراط تحقق فرعي أثر أو استفسار سؤال مستخدم، بينما لا هو أعمى هدف إعادة محاولة.

#### Token أثر

عادي حفظ دائم خلال لـ صفر token. استعادة بعد سوف إعادة حساب دخول إبقاء تاريخ token استخدام كمية، و وفق معتاد حساب دخول حالي طلب envelope token استخدام كمية؛ كل قد إصلاح استدعاء كل سوف زيادة واحد مقطع بـ مرجع شكل صيغة إبقاء خطأ نص.

#### KV Cache أثر

حفظ دائم لا تعديل حالي طلب بادئة. فقط لديه عند إعادة بناء تاريخ، حالي envelope و نموذج توجيه مطابقة وقت، استعادة loop عندئذ قدرة إعادة استخدام مزود ذاكرة مؤقتة؛ انهيار انهيار إصلاح نتيجة فقط إلحاق، لا إعادة كتابة مقارنة مبكر تاريخ.

## حدود معروفة وعمل مؤجل

<a id="known-limitations-and-deferred-work"></a>


هذه حد حد تحديد seam حفظ إثبات نهاية نقطة. هو جمع هو حالي حزمة قيد، لا هو انتظار إنجاز أمر بند.

- **seam فقط حفظ إثبات مفرد عدد خلفية نسخة داخل كتابة كل حق**——عبر عملية ترتيب هو من أداة جسم مزود مسؤول. مع منتج تسليم JSONL مزود عبر داخل نواة قفل في مختلف نسخة و عملية بين توفير إيجار نحو؛ أخرى مزود يجب سجل انتظار فاعلية حفظ إثبات، أو اشتراط نشر جهة منع توقف تزامن كتابة.
- **في لديه نشط وثب جلسة وقت إعادة تحميل خلفية إضافة سوف جعل ذلك كتابة جهاز واضح تقرير خطأ**——إعادة تحميل بعد خلفية لا يمكن خدمة قديم نسخة توقيع إرسال جملة مقبض؛ كتابة سوف حمل متابعة فشل مباشر إلى جلسة إعادة بدء، لا يوجد أي آلية ساكن صامت إعادة وصل إدارة سجل.
- **فقط لديه عبر جملة مقبض نيل أخذ جلسة عندئذ سوف حفظ دائم**——فقط اعتماد `ctx.sessions.create` + `session/flush` لا تخزين أي محتوى؛agent-loop هو إنتاج بيئة نيل أخذ نقطة، اختبار عبر `create`/`append`/`close` كتابة ابتدائي تخزين بيانات.
- **بلا حذف أو إبقاء واجهة**——قص غصن قد تخزين جلسة يخص حمل خارج خلفية صيانة.
- **`list()` بلا قسم صفحة كما بلا مرور ترشيح**——هو إرجاع كل قد تخزين جلسة لقطة؛ ملائم دمج محلي تخزين، كبير قاعدة نموذج وقت بلا بحث جذب.
- **دمج صار closer هو وحيد انهيار انهيار خطة**——استعادة عبر كتابة جملة مقبض إلحاق `interruptedTurnClosers`؛ لا يوجد متابعة في قطع جولة بينما لا أولا إغلاق هو جزء جولة استعادة.
