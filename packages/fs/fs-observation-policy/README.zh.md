# @deepseek-ai/dsh-fs-observation-policy

[English](README.md) | العربية

## عام وصف

`dsh-fs-observation-policy` اشتراط agent(ذكي جسم) أولا قراءة ملف، نظام الملفات أداة عندئذ يمكن تغطية أو تحرير هو. إذا ملف ذاتي قراءة بعد حدوث تغير، هو أيضا سوف رفض تغيير، و صاف واضح تلميح إعادة قراءة بعد إعادة محاولة. قراءة ناقص مسار سوف تخويل حمل منع حماية إنشاء، معا ما زال منع توقف تغطية تزامن إنشاء ملف. حاجة تحرير قبل قراءة أمان صفة نشر طلب اختيار هو؛ من في مراقبة سجل لا حفظ دائم، استعادة جلسة يجب إعادة قراءة هدف.

<a id="use-this-package"></a>
## استخدام هذه الحزمة

عند نشر أمل نظر نموذج في تغطية أو تحرير ملف قبل أولا قراءة هذا ملف وقت، يأخذ هذا إضافة و `ctx.fs` خلفية و `dsh-tool-fs` أداة واحد بدء تحميل. إضافة بلا حاجة إعداد، أيضا لا حقن أي خدمة؛ هو فقط استماع أداة قسم إرسال `fs/*` حدث.

### الأكثر صغير تركيب

أولا تحميل خلفية، مجددا تحميل هذا إضافة، الأكثر بعد تحميل أداة. سياسة مستمع ينبغي عند هو `fs/*` معنى رسم slot فوق رقم واحد تسجيل قرار جهاز.

```yaml
- name: '@deepseek-ai/dsh-fs-local'
- name: '@deepseek-ai/dsh-fs-observation-policy'
- name: '@deepseek-ai/dsh-tool-fs'
```

### مقابل نموذج بينما قول تغير

تركيب سياسة بعد،`write` يمكن إنشاء جديد ملف، لكن رفض تغطية جلسة لم قراءة مرور قائم ملف؛`edit` اشتراط أولا قراءة هدف؛ ذاتي قراءة بـ قدوم حدوث تغير (يشمل ناقص) ملف بـ `FS_STALE_VERSION` فشل. ناقص أيضا سوف يتم سجل: قراءة ناقص ملف سوف يأخذ هو علامة لـ تأكيد ناقص، لذلك مع بعد `write` يمكن عبر منع حماية إنشاء مسار إعادة إنشاء هو. جلسة استعادة بعد لا يحمل أي قد مراقبة حالة، لذلك يجب إعادة قراءة ملف، منع حماية تغيير عندئذ قدرة مجددا مرة نجاح.

### فشل و استعادة

لا يوجد أولا قبل مراقبة قياس تحرير بـ شفرة `FS_NOT_OBSERVED` و سياسة سبب `edit requires reading "<path>" first` فشل؛ تحرير يتم مراقبة قياس لـ ناقص هدف بـ `FS_NOT_FOUND` فشل. أداة يأخذ سياسة و مزود لم قراءة فشل موحد واحد لـ `cannot modify "<path>": file has not been read — read the file, then retry`، معا إبقاء رمز خطأ و أصلي سبب. في خارجي حذف ملف فوق التزام دوران هذا استعادة إشارة أمر سوف سجل ناقص، لذلك تحت مرة منع حماية كتابة يمكن إعادة إنشاء هو، بينما لن تغطية تزامن إنشاء من.

<a id="understand-the-implementation"></a>
## فهم التنفيذ

<details>
<summary>تنفيذ دقيق عقدة——انقر للتوسيع</summary>

هذا عقدة حل تفسير سياسة إضافة خلف بعد تصميم قرار، و إشارة خروج تنفيذ هو جمع شفرة موضع؛ يمكن مراقبة سلوك قد في[استخدام هذه الحزمة](#use-this-package) في كامل شرح.

### تصميم إدارة فكرة

إضافة بناء قيام في اثنان عدد تفكير قاعدة لـ فوق:

- **حدث بوابة، بينما غير طريقة خدمة.** إضافة فقط عبر `fs/*` حدث أثر خارجي عالم حد، لذلك لا تسجيل `ctx.fsPolicy` خدمة، أيضا لا يوجد عام طريقة. إزالة هو لن في خدمة حقن حد كسر تالف `dsh-tool-fs`——أداة سوف مباشر سقوط إلى عار مزود.
- **قد مراقبة حالة هو أولا قبل مراقبة سجل.** واحد ورقة بـ كل من لـ ضعيف مفتاح، سجل كل هدف خريطة جدول يحتفظ ثلاثة نوع منطق حالة——لم رؤية، تأكيد ناقص، وجود في بعض عدد إصدار. إضافة ذاته لا تنفيذ أي نظام الملفات I/O؛ هو يأخذ سجل حالة تحويل لـ مزود اختياري منع حماية، من مزود تنفيذ أصل فرعي جديد طازج درجة فحص.

### شفرة المصدر أرض رسم

| ملف | مسؤولية |
|---|---|
| [`src/index.ts`](src/index.ts) | ثلاثة عدد `fs/*` مستمع و قد مراقبة حالة بوابة |
| [`src/types.ts`](src/types.ts) | لا نفاذ واضح حدث مشاركة و من شكل، من في إرسال توليد كل من جلسة |

### قرار مسار

`fs/write-intent` يأخذ لم رؤية أو تأكيد ناقص تحليل لـ `{ kind: 'createIfAbsent' }`، يأخذ قد مراقبة قياس وجود تحليل لـ `{ kind: 'replaceIfVersion', version: vObserved }`.`fs/edit-intent` بـ `FS_NOT_OBSERVED` رفض لم رؤية هدف، بـ `FS_NOT_FOUND` رفض تأكيد ناقص هدف، لا فإن توفير مراقبة إلى إصدار بصفة مقارنة مقارنة و تسليم تبديل أساس أساس.`fs/observed` لـ هذا كل من و هدف سجل `{ kind: 'present', version }` أو `{ kind: 'absent' }`——تزامن، فقط لديه فرعي أثر `WeakMap.set`، لأن نجاح تغيير قد إيداع.

### مفرد slot، أولا إلى من فوز

كل معنى رسم slot فقط سعة قبول واحد قرار جهاز: هذا إضافة سوف كامل قرار، أبدا استدعاء `next()`.slot حسب تسجيل ترتيب أولا إلى من فوز——من هذا إضافة يملك slot فقط هو افتراضي نشر اتفاق، لا هو حدث قوي صنع ثابت صيغة. قسم طبقة إذن، مراجعة حساب أو صندوق رملي اعتراض قطع يخص `tools/execute` waterfall(شلال نشر صيغة حدث).

### دورة الحياة

قد مراقبة حالة في إضافة dispose(مورد تحرير) وقت إسقاط، بـ تأكيد حفظ HMR(حار وحدة استبدال) أمان، كما أبدا عبر جلسة حفظ دائم——استعادة جلسة من بلا مراقبة حالة بدء.

</details>

## بحث إضافي

عند حزمة درجة اتفاق لا كاف استخدام وقت قراءة قراءة التالي صفحة. هو جمع من سياسة تدريجي خطوة دخول هو الذي تركيب اتفاق، أداة و خلفية.

- [نظام الملفات فرعي نظام](../../../docs/subsystems/filesystem.zh.md)——نفاد كل صيغة مزود اتفاق، سياسة حدث و خطأ تصنيف جسم نظام.
- [dsh-fs](../fs/README.zh.md)——`ctx.fs` اتفاق و `fs/*` حدث مفردات.
- [tool-fs](../tool-fs/README.zh.md)——قسم إرسال `fs/*` حدث موجه إلى نموذج أداة.
- [fs-local](../fs-local/README.zh.md)——هذا سياسة الذي منع حماية مضيف نظام الملفات خلفية.
- [fs-sandbox](../fs-sandbox/README.zh.md)——و هذا سياسة تركيب صندوق رملي قوي صنع خلفية.
- [Fsspec ريح إطار seam تفكيك قسم Agent Note](../../../.agents/notes/implemented/simplification/2026-06-26-fsspec-style-fs-seam.zh.md)——سياسة لـ أي هو حدث إضافة بينما غير مزود طريقة.

<a id="model-experience"></a>
## تجربة النموذج

### نظام الملفات أداة نتيجة

#### نموذج يرى محتوى

هذا إضافة لا إضافة نص التوجيه أو schema. لا يوجد أولا قبل مراقبة قياس وقت، هو سوف بـ شفرة `FS_NOT_OBSERVED` و سياسة سبب `edit requires reading "<path>" first` رفض تحرير؛ تحرير يتم مراقبة قياس لـ ناقص هدف إرجاع `FS_NOT_FOUND`. صحيح نحو مراقبة قياس قديم قديم وقت، حمل منع حماية تغيير سوف نقل بث من مزود يملك `FS_STALE_VERSION` خطأ.[`dsh-tool-fs`](../tool-fs/README.zh.md) يملك نموذج جانب خطأ حزمة تركيب: هو يأخذ كل `FS_NOT_OBSERVED` مصدر مواصفة تحويل لـ `cannot modify "<path>": file has not been read — read the file, then retry`، بينما `FS_STALE_VERSION` إبقاء مزود سبب و إلحاق `— re-read the file, then retry`؛ اثنان من كل إبقاء رمز خطأ و أصلي سبب. خارجي حذف هدف بعد، التزام دوران قديم قديم استعادة إشارة أمر سوف سجل ناقص: تحت مرة حمل منع حماية كتابة يمكن عبر `createIfAbsent` إعادة إنشاء هذا هدف، بينما مزود سوف بـ أصل فرعي طريقة إبقاء أي تزامن إنشاء من كتابة ملف.

#### Token أثر

سماح عملية حذف عادي أداة نتيجة خارج لا زيادة token. رفض سوف إضافة قليل كمية إبقاء خطأ نتيجة، و تجنب تجنب إنتاج نجاح payload.

#### KV Cache أثر

فقط إلحاق؛ إضافة جديدة مرئي محتوى يقع في يمكن إعادة استخدام طلب بادئة بعد، لن جعل قائم KV Cache بند بطلان.

## حدود معروفة وعمل مؤجل

<a id="known-limitations-and-deferred-work"></a>


هذه حد شرح هذا سياسة أي وقت لا دمج ملائم، أو أي وقت حاجة خاص آخر تشغيل صيانة ملاحظة معنى. هو جمع هو حالي حزمة قيد، لا هو عام نظام الملفات مقابل مقارنة أو مهمة تراكم ضغط.

- **قد مراقبة حالة لا يمكن في جلسة استعادة بعد إبقاء**: هذا سجل حفظ دائم عمل تأجيل معالجة، لذلك استعادة جلسة يجب إعادة قراءة ملف، عندئذ قدرة تنفيذ منع حماية كتابة و تحرير.
- **لا يوجد agent جلسة مشاركة و من قطعا لا يمكن ممتلئ كاف سياسة**: هو جمع تحرير سوف رمي خروج `FS_NOT_OBSERVED`، كتابة مجموع سوف تحليل لـ `createIfAbsent`، لذلك غير agent استدعاء جهة لا يمكن عبر بوابة تغطية قائم ملف.
- **مباشر `ctx.fs` قراءة لن إرسال خروج `fs/observed`**: في `read` أداة خارج قراءة ملف ما زال لم مراقبة؛ لاحق منع حماية تحرير سوف بـ `FS_NOT_OBSERVED` رفض، مباشر إلى أداة قراءة هذا ملف.
- **تخويل اعتماد حسب هو إصدار جديد طازج درجة، بينما غير عرض كامل صفة**: أي نافذة قراءة كل سوف تخويل مقابل لم تغيير ملف تنفيذ كل ملف تغطية، هذا متعمد ضعيف في كامل عرض قاعدة (رؤية[seam تفكيك قسم Agent Note](../../../.agents/notes/implemented/simplification/2026-06-26-fsspec-style-fs-seam.zh.md)).
