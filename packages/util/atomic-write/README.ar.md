# @deepseek-ai/dsh-atomic-write

[English](README.md) | العربية

## عام وصف

استخدام `dsh-atomic-write` استبدال ملف وقت، لن كشف جزء محتوى، أيضا لن تتبع مع مؤقت مسار فوق رمز رقم رابط. هو كتابة قفل سوف عبر عملية سلسلة سطر تحويل قراءة-تعديل-كتابة حلقة، لذلك تزامن كتابة جهة لن استخدام قديم قديم حالة متبادل متبادل تغطية. كل مرة استبدال كل سوف في كل جديد inode فوق استخدام استدعاء جهة اختيار إذن موضع، من بينما أمان أرض استلام ضيق قائم ملف إذن. هذا عدد صفر اعتماد مكتبة فقط قبول نص؛ هو لا توفير `cordis.yml` إضافة، أيضا لا حفظ إثبات انهيار انهيار حمل دائم صفة، لأن هو لا استدعاء `fsync`.

## استخدام هذه الحزمة

عند ملف نوع تخزين يجب استبدال واحد نسخة قد تصيير جيد نص، كما أبدا سماح كشف جزء كتابة، رمز رقم رابط خطف حمل أو إذن مرور عرض حالة وقت، استخدام `writeFileAtomic`؛ عند كثير عدد عملية مقابل نفس ملف تنفيذ قراءة-تعديل-كتابة حلقة وقت، استخدام `withFileLock`. الأكثر صغير مسار هو مرة استدعاء، نقل دخول نهائي محتوى و استبدال inode إذن موضع.

### أصل فرعي كتابة ملف

```ts
import { writeFileAtomic } from '@deepseek-ai/dsh-atomic-write'

declare const text: string
await writeFileAtomic('/home/u/.dsh/settings.yaml', text, { mode: 0o600 })
```

أب دليل سوف حسب يحتاج إنشاء، قراءة جهة فقط سوف مراقبة إلى قديم محتوى أو كامل جديد محتوى. في Windows فوق، تقرير إبلاغ لـ `EACCES`،`EBUSY` أو `EPERM` لحظة وقت استبدال جاف إزعاج سوف في محدود وقت داخل إعادة محاولة؛ أي باق بقية فشل كل سوف إزالة مؤقت ملف، و إبقاء هدف ملف ثابت.

### تنسيق ضبط كتابة جهة

مقابل في مفرد اعتماد أصل فرعي إيداع لا يمكن حفظ إثبات أمان قراءة-تصيير-إيداع حلقة، طلب في عملية خلال يحتفظ كتابة قفل:

```text
import { withFileLock, writeFileAtomic } from '@deepseek-ai/dsh-atomic-write'

declare const render: (previous: string) => string
declare const readCurrent: () => Promise<string>

await withFileLock('/home/u/.dsh/settings.yaml', async () => {
  const previous = await readCurrent()
  await writeFileAtomic('/home/u/.dsh/settings.yaml', render(previous), { mode: 0o600 })
})
```

فقط لديه كتابة جهة سوف تنافس تنازع——قراءة جهة من لا أخذ قفل——تنافس تنازع من حسب إشارة عدد تراجع تجنب، مهلة بعد تقرير خطأ، بينما لا هو بلا حد منع سد. تنافس تنازع من انتظار كثير دائم من كل مرة استدعاء مرور `waitMs` إعلان: قيمة افتراضية فقط حسب صاف ملف عمل كمية درجة اختيار تحديد، لذلك حمل قفل جهة حلقة إذا يتضمن مرة شبكة شبكة نحو إرجاع——مثال مثل تحديث جديد مرور مدة token اعتماد تغيير——حينئذ ينبغي إعلان أكثر طويل قيمة، لا فإن هذا ملف أخرى كتابة جهة في هذا مقطع وقت داخل كل سوف فشل. تراجع تجنب عقدة عزف إبقاء ثابت. تنافس تنازع من أبدا إزالة قد لديه قفل، لأن ملف تخزين متابعة وقت لا يمكن إثبات ذلك يحتفظ من قد إيقاف.

### حاجة قاعدة تخطيط فشل

Windows في لا يمكن مراقبة إلى قفل وقت سوف مقابل `EPERM` إعادة محاولة مرة، لأن حمل قفل جهة ممكن في وحيد احتلال إنشاء و وجود فحص بين تحرير قفل. مجددا مرة ظهور لا يمكن تأكيد قفل وجود `EPERM` وقت، سوف إعادة رمي خروج خطأ كما لا تشغيل عملية.

قفل أب دليل يجب قد وجود، لذلك `withFileLock` سوف في تشغيل عملية قبل رفض بلا فاعلية أب دليل طبقة درجة. حمل قفل عملية خروج وقت سوف يأخذ قفل ملف إبقاء في أصل أرض؛ لاحق كتابة جهة مهلة فشل، عملية من فقط لديه في تأكيد لا يوجد كتابة جهة ما زال يحتفظ هذا قفل بعد عندئذ سوف إزالة هو.

### كتابة مسار

`writeFileAtomic` أولا بـ وحيد احتلال إنشاء (`wx`) فتح واحد مع آلة بعد لاحقة نفس درجة ملف و كتابة محتوى، لكن بعد rename إلى هدف فوق. وحيد احتلال فتح رفض تتبع مع مسبق أولا دفن في يمكن تخمين قياس مؤقت مسار فوق رمز رقم رابط؛ نفس دليل أخ أخ ملف حفظ إثبات rename سقوط في نفس نظام الملفات فوق؛rename استبدال هو هدف موضع رمز رقم رابط ذاته، أبدا كتابة اختراق إلى هذا رابط إشارة نحو ملف.Windows إعادة محاولة سوف إبقاء نفس نسخة كامل أخ أخ ملف، و اعتماد محدود إشارة عدد تراجع تجنب، لذلك تنسيق عمل صيغة كتابة قفل خارج لين عنصر لحظة وقت احتلال استخدام هدف وقت، لن يجعل أمان استبدال قيام أي فشل؛ قد عودة ملف[إعادة محاولة قرار سجل](../../../.agents/notes/archived/bug-fix/2026-08-29-windows-atomic-replace-retry.md) سجل الأكثر أول إدارة من و يتم رفض بديل خطة.

`withFileLock` بـ `wx` إنشاء `<filename>.lock` نفس درجة ملف.`EEXIST` مباشر يمثل تنافس تنازع؛ فقط لديه مرة جديد `lstat` تأكيد قفل مسار وجود وقت،`EPERM` عندئذ يمثل تنافس تنازع، من بينما توافق Windows وحيد احتلال إنشاء سلوك، أيضا لا إخفاء غطاء غير متصل إذن لذا عائق. قفل سجل إنشاء من PID، من يحتفظ من في `finally` في إزالة؛ تنافس تنازع حسب إشارة عدد تراجع تجنب، في كل مرة استدعاء إعلان `waitMs` مدة حد (افتراضي اثنان ثانية) مرور بعد فشل.

### تسليم تبديل لـ أي أمان

- **كل جديد inode، استدعاء جهة إعلان إذن موضع**——مؤقت ملف حمل حال `mode` مشي تمام rename، لذلك استلام ضيق إذن مرور عرض ملف لا يوجد chmod تنافس حالة.`mode` لـ لا بد ملء، يجعل إذن قرار بداية نهاية مرئي في كل استدعاء نقطة.
- **قراءة جهة من لا تنافس تنازع**——rename إيداع هو أصل فرعي، قراءة جهة بلا حاجة إضافة قفل.
- **تنافس تنازع من أبدا إزالة قفل**——ملف تخزين متابعة وقت لا يمكن منطقة قسم قد انهيار انهيار كل من و مؤقت توقف لكن ما زال تخزين نشط كتابة جهة؛ استعادة هو عملية من حركة عمل.

## حدود معروفة وعمل مؤجل

<a id="known-limitations-and-deferred-work"></a>


هذه حد شرح هذه الحزمة أي وقت لا هو دمج ملائم أداة. هو جمع هو حالي حزمة قيد، لا هو مهمة تراكم ضغط.

- **أصل فرعي لكن لا حفظ إثبات حمل دائم**——لا مقابل ملف أو ذلك الذي في دليل فعل `fsync`، لذلك انهيار انهيار بعد ممكن مراقبة إلى rename يتم رجوع. هذا موضع ملف نوع تخزين في بدء وقت إعادة قراءة و إعادة إصدار، يأخذ حمل دائم صفة إبقاء عمل استدعاء جهة سياسة.
- **فقط دعم حمل نص محتوى**——في لديه مستهلك حاجة قبل، لا توفير `Buffer` أو تدفق صيغة شكل.
- **متروك إبقاء قفل حاجة عملية من استعادة**——حمل قفل عملية خروج وقت ممكن إبقاء تحت نفس درجة قفل ملف؛ لاحق كتابة جهة مهلة أيضا لن حذف هو.
