# @deepseek-ai/dsh-authorization

[English](README.md) | العربية

## عام وصف

`dsh-authorization` يجعل إعداد UI أو أخرى استدعاء جهة عبر شخص جذب توجيه تسجيل تسجيل، إدخال رمز أو عودة جواب مشكلة قدوم نيل أخذ اعتماد. كل مرة محاولة تجربة فقط يأخذ notice و prompt إرسال إلى إرسال بدء هو واجهة. فقط لديه جديد اعتماد قد تخزين وقت، هو عندئذ تقرير إبلاغ `authorized`؛ رفض أو سحب إلغاء سوف تقرير إبلاغ `cancelled`، بينما لذا عائق ما زال بصفة خطأ. عند اعتماد لا يمكن عبر إعداد توفير وقت اختيار هو. هو حاجة اعتماد تخزين و واحد تعريف متاح تخويل طريقة تجميع صار؛ هذه الحزمة ذاته لا توفير خاص تحديد مزود تخويل طريقة.

## استخدام هذه الحزمة

هذه الحزمة هو منتج في مسؤول نيل أخذ «يجب من شخص تسليم خروج قدوم» اعتماد جزء: إضافة تسجيل واحد معرفة طريق مثل أي أخذ نيل ذاتي ذات ذلك نسخة اعتماد flow، أي واجهة كل قدرة إرسال بدء محاولة تجربة و نحو شخص عرض هذا فعل ماذا. معتاد استخدام مسار هو صريح——لـ أنت إضافة يحتفظ كل اعتماد تسجيل واحد flow، لكن بعد من شخص صحيح نظر حال ذلك عدد واجهة إرسال بدء محاولة تجربة.

### أي وقت استخدام

فقط يلزم اعتماد فقط قدرة عبر و شخص محادثة نيل نيل——OAuth صيغة تسجيل تسجيل، مرة صفة رمز، اختيار واحد حساب رقم——كما لا يمكن تخزين دخول إعداد، حينئذ استخدام هو. إذا اعتماد هو نشر جهة يمكن توفير واحد ثابت مفتاح، طلب تعديل استخدام اعتماد seam تخزين هو. بلا رأس أو ACP(Agent Client Protocol) تركيب أيضا يمكن أمان تركيب هذه الحزمة: هو ذاته لا توفير أي flow، لذلك حذف غير إضافة تسجيل flow، لا فإن لن اشتراط شخص تسجيل تسجيل.

### تسجيل flow

أنت إضافة لـ هو يحتفظ كل اعتماد إعلان واحد flow، بـ هذا flow كتابة `<scope>/<id>` اعتماد سجل لـ مفتاح——scope نقطة اسم أنت إضافة،id نقطة اسم هو يملك واحد بند اعتماد:

```ts
import type { Context } from '@deepseek-ai/cordis'
import type { AuthorizationSession } from '@deepseek-ai/dsh-authorization'
import { credentialKey } from '@deepseek-ai/dsh-credentials'

declare const ctx: Context
declare const exchangeCode: (code: string, signal: AbortSignal) => Promise<{ token: string }>

const key = credentialKey('llm-pi-ai', 'openai-codex') // <scope>/<id> — your plugin / this credential

const dispose = ctx.authorization.registerFlow({
  key,
  label: 'ChatGPT (Codex)',
  methods: [{ id: 'oauth', label: 'Sign in with ChatGPT' }, { id: 'api-key', label: 'Paste a key' }],
  async run(session: AuthorizationSession) {
    session.notify({ message: 'Continue in your browser', url: 'https://auth.example/start' })
    const code = await session.prompt({ kind: 'text', message: 'Paste the code' })
    const { token } = await exchangeCode(code, session.signal)
    await ctx.credentials.modifyRecord(key, () => Promise.resolve({ kind: 'grant', payload: { token } }))
  },
})

ctx.authorization.list()          // every registered flow, with inFlight
ctx.authorization.describe(key)   // the entry above, or undefined
dispose()                         // unregister; withdraws any running attempt
```

flow إعلان هو كتابة اعتماد سجل، موجه إلى مستخدم وسم و هو توفير تسجيل تسجيل طريقة، الأكثر أولوية من في قبل.`run()` عبر جلسة و شخص محادثة——مفرد نحو notice و flow لا يمكن ذاتي سطر عودة جواب مشكلة——و كما يجب في إرجاع قبل عبر `ctx.credentials` إيداع سجل:seam سوف رفض لم إيداع حينئذ إرجاع flow.`list()` و `describe()` يجعل واجهة عرض يمكن تخويل محتوى و هل لديه محاولة تجربة في تشغيل؛`dispose()` ملاحظة إلغاء هذا flow و سحب إلغاء ما زال في تشغيل في محاولة تجربة.

### إرسال بدء مرة محاولة تجربة

كل اعتماد معا فقط سماح مرة محاولة تجربة. تفاعل مع طلب نقل دخول بينما غير تخزين وضع في سجل التسجيل في، لذلك رفع سؤال تماما جيد مقاومة بلوغ إرسال سؤال ذلك عدد صفحة؛ بلا رأس استدعاء جهة نقل دخول واحد مباشر رفض تفاعل تنفيذ. عند سجل في محاولة تجربة خلال يتم إيداع و يتم مراقبة إلى وقت،`begin()` تقرير إبلاغ `{ status: 'authorized' }`؛ عند شخص رفض أو استدعاء جهة سحب إلغاء وقت، تقرير إبلاغ `{ status: 'cancelled' }`.`cancel(key)` من ثاني مرة استدعاء سحب إلغاء جارٍ تشغيل محاولة تجربة، خدمة في ذلك نوع استخدام ثاني مرة استدعاء قدوم استجابة «إلغاء» حسب زر، لكن لا يحتفظ رقم مرة استدعاء signal طلب/استجابة صيغة نقل.

### ممكن خروج خطأ أرض جهة

- **لا يوجد flow اعتماد هو كسول صفة**——مقابل لا يوجد أي flow إقرار قيادة مفتاح استدعاء `begin()` سوف رمي خروج `NO_FLOW`؛ يتم إزالة إضافة متروك إبقاء سجل يمكن حذف، لكن لا يمكن إعادة تخويل.
- **كل اعتماد معا فقط سماح مرة محاولة تجربة**——قد لديه محاولة تجربة في وقت التشغيل مجددا مرة `begin()` سوف رمي خروج `ALREADY_IN_FLIGHT`؛entry فوق `inFlight` يجعل واجهة مسبق أولا منع استخدام حسب زر.
- **لم إيداع حينئذ إرجاع flow سوف يتم رفض**——رمي خروج `NOT_COMMITTED`، لذلك `authorized` دائم بعيد معنى طعم حال سجل حق قد تخزين.
- **نقطة اسم flow لم توفير طريقة سوف رمي خروج `UNKNOWN_METHOD`**——لا نقطة اسم فإن تشغيل flow رقم واحد طريقة.
- **«لا» هو واحد نوع نتيجة، لا هو لذا عائق**——يتم رفض prompt يجعل محاولة تجربة بـ `cancelled` تسوية، و سحب إلغاء signal تماما متسق؛ ذلك بقية أي فشل كل بـ رمي خروج خطأ مقاومة بلوغ استدعاء جهة.

<a id="understand-the-implementation"></a>
## فهم التنفيذ

<details>
<summary>تنفيذ دقيق عقدة——انقر للتوسيع</summary>

هذا عقدة حل تفسير هذا seam خلف بعد تصميم قرار، و إشارة خروج تنفيذ هو جمع شفرة موضع؛ يمكن مراقبة سلوك قد في[استخدام هذه الحزمة](#use-this-package) في كامل شرح.

### تصميم إدارة فكرة

- **seam يملك محادثة، من لا يملك بروتوكول.** معرفة طريق مثل أي أخذ نيل ذاتي ذات ذلك نسخة اعتماد إضافة، بـ هو كتابة سجل لـ مفتاح تسجيل واحد flow؛ ثاني نوع تخويل بروتوكول بـ آخر عدد flow شكل صيغة إلى قدوم، بينما لا هو آخر عدد seam، قدرة تصيير واحد flow واجهة حينئذ قدرة تصيير الكل flow.
- **كتابة من flow يملك.** `run()` إرجاع أي يمثل سجل قد عبر `ctx.credentials` إيداع؛seam نواة فعلي هو هو في محاولة تجربة خلال مراقبة إلى إيداع——فقط نظر سجل وجود و لا، سوف يجعل إعادة تخويل يأخذ قديم قديم سجل خطر ملء صار جديد طازج——و رفض لم إيداع حينئذ إرجاع flow. يجعل إيداع حدوث في flow داخلي، عندئذ قدرة جعل واحد عبر ذاتي لديه تخزين مهايئ حفظ دائم مكتبة إبقاء لـ وحيد كتابة جهة، بينما لا هو يأخذ اعتماد نسخ خروج قدوم مجددا كتابة ثاني مرة.
- **تفاعل مع طلب نقل دخول، بينما غير سجل التسجيل.** إرسال بدء تخويل واحد جهة عندئذ هو قدرة و شخص محادثة واحد جهة، لذلك رفع سؤال تماما جيد مقاومة بلوغ إرسال سؤال ذلك عدد واجهة، بلا رأس استدعاء جهة فإن نقل دخول واحد مباشر رفض تفاعل تنفيذ. هذا مثال حيث لا وجود «بيئة مزود نقص مقعد» مشكلة، أيضا لن لديه بعض عدد رفع سؤال هذا عودة اثنان عدد قد فتح صفحة في أي واحد شك سؤال.
- **شخص «لا» هو واحد نوع نتيجة، لا هو لذا عائق.** اختيار رفض تفاعل تنفيذ بـ `AuthorizationDeclinedError` رفض ذلك prompt، محاولة تجربة بـ `cancelled` تسوية، و سحب إلغاء signal تماما متسق؛ ذلك بقية أي prompt رفض ما زال هو مقاومة بلوغ استدعاء جهة flow لذا عائق.

### شفرة المصدر أرض رسم

| ملف | مسؤولية |
|---|---|
| [`src/index.ts`](src/index.ts) | Service Definition:flow سجل التسجيل، كل مفتاح مفرد محاولة تجربة دورة الحياة، تفاعل توجيه، إيداع تأكيد |
| [`src/types.ts`](src/types.ts) | عبر عملية أمان مفردات: طريقة،notice،prompt، نتيجة،entry |
| [`src/invariant.ts`](src/invariant.ts) | ثابت صيغة مرافق توليد إضافة:`authorization/settled` نقطة اسم مفتاح لا بد قد تحرير |

### دورة الحياة

كل مفتاح معا فقط سماح مرة محاولة تجربة.`begin()` تحقق مفتاح و طريقة، رفض كثيف مشغول مفتاح ثاني مرة محاولة تجربة، و استخدام واحد `AuthorizationSession` تشغيل flow——هو يحمل الذي اختيار طريقة، إلغاء signal و توجيه إلى طلب تفاعل `notify`/`prompt` عودة ضبط. يتم سحب إلغاء محاولة تجربة سوف قيام أي تسوية، أي جعل flow من لم استجابة هو signal——يتم متروك ترك تشغيل مهمة ذلك ذاتي سطر انتهاء، بينما هو إذا ما زال ضبط قاعدة إيداع واحد بند سجل، ذلك أيضا هو واحد بند شخص تأكيد فعلي تخويل مرور سجل. مفتاح في `authorization/settled` إطلاق قبل تحرير، لذلك بـ بدء تحت مرة محاولة تجربة قدوم استجابة مستمع لن يتم رفض؛ مستمع فشل حسب اعتماد seam قاعدة حينئذ أرض كبح صنع.

### تفاعل مفردات

notice هو مفرد نحو، كما من لا يحمل آلة سري: واحد بند رسالة، و اختياري «شخص حاجة فتح صفحة» و «حاجة في هذا صفحة إدخال رمز».prompt هو flow لا يمكن ذاتي سطر عودة جواب مشكلة——`text`،`secret` أو `select`——منها `secret` و `text` فرق آخر فقط في عرض طريقة.prompt ذاتي حمل signal، جعل نيل يجعل يد نقل رمز و متصفح عودة ضبط سباق ركض flow يمكن في محاولة تجربة متابعة معا سحب تحت سقوط فشل ذلك عدد مشكلة؛ سحب إلغاء كامل مرة محاولة تجربة فإن استخدام طلب signal. هذا طقم مفردات لحظة معنى صغير في أي مفرد عدد مزود مفردات: هو وصف هو واجهة يجب تصيير ماذا، لذلك قدرة تصيير واحد flow واجهة حينئذ قدرة تصيير الكل flow.

### إيداع تأكيد

محاولة تجربة خلال،seam استماع هذا flow مفتاح فوق `credentials/record-updated`،`run()` إرجاع بعد مجددا إعادة قراءة `describeRecord`——تأكيد إيداع تأكيد فعلي حدوث في عند تحت، لأن في إعادة تخويل وقت سجل مبكر قد وجود، فقط نظر وجود و لا سوف يجعل قديم قديم اعتماد خطر ملء جديد طازج تخويل. لم إيداع حينئذ إرجاع flow، أو حذف سجل بينما غير إيداع flow، سوف رمي خروج `NOT_COMMITTED`.

## حدود معروفة وعمل مؤجل

<a id="known-limitations-and-deferred-work"></a>


هذه حد شرح هذه الحزمة أي وقت لا دمج ملائم أو حاجة خاص آخر ملاحظة معنى. هو جمع هو حالي حزمة قيد، لا هو مهمة تراكم ضغط.

- **flow غير ممكن استعادة**——مرة محاولة تجربة فقط تخزين نشط في إرسال بدء هو عملية في، لذلك تسجيل تسجيل طريق في تحديث جديد متصفح سوف إسقاط هو، شخص حاجة إعادة قدوم؛ يمكن حمل دائم محاولة تجربة حاجة واحد هذا seam و لا أداة تجهيز تخزين.
- **لا يوجد تعليق إلغاء**——تسجيل خروج أي `ctx.credentials.deleteRecord(key)`، هو فقط متروك نسيان محلي سجل بينما لا إشعار توقيع إرسال جهة؛ حاجة خدمة طرف تعليق إلغاء مزود لا يوجد يمكن إعلان لـ موضع.
- **لا يوجد flow مفتاح هو كسول صفة**——seam فقط تقرير إبلاغ قد تسجيل محتوى، لذلك يتم إزالة إضافة متروك إبقاء سجل يمكن حذف لكن لا يمكن إعادة تخويل؛ تعرف آخر هذا نوع منعزل طفل سجل من استدعاء جهة مسؤول، و `listRecords()` حال حال نفسه.

<a id="dev-note"></a>
### ملاحظة تطوير

<details>
<summary>صيانة من عمل سياق——انقر للتوسيع</summary>

هذا ملاحظة تطوير هو صيانة من عمل سياق: فتح وضع مشكلة و بعد لم قرار استكشاف جهة نحو. هو واضح لا أداة مرجعي صفة——قد تسليم سلوك، حد و حيث تحديد إدارة من بـ فوق نص، حزمة شفرة و متبادل صلة Agent Note لـ دقيق.

فوق نص حد نقطة اسم فتح وضع جهة نحو——يمكن استعادة محاولة تجربة، خدمة طرف تعليق إلغاء، منعزل طفل سجل اكتشاف——كل واحد بند سقوط أرض قبل كل حاجة كل منها تصميم و تخزين. ثابت صيغة مرافق توليد إضافة هو وحيد تحمل إعادة وقت التشغيل فحص: تسوية وقت مفتاح يجب قد تحرير، لأن بطاقة ميت مفتاح و كثيف مشغول مفتاح لا يمكن منطقة قسم، فقط لديه إعادة بدء عندئذ قدرة تحرير هو.

</details>
